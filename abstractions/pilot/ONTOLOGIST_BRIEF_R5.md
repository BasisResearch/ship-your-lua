## The project

The project proves in Lean 4 (v4.34, no Mathlib) that the RISC-V machine code of `luaV_execute` (Lua 5.4.7 compiled by GCC for rv64i, with no FPU) refines a bytecode semantics on the Sail model.
- Floats were just added to the semantics. Values hold core Lean's transparent IEEE model `Float.Model` (`Init/Data/Float/Model/`), plus a NaN sign bit.
- The ELF computes floats with libgcc's soft-float routines (`__adddf3`, `__subdf3`, `__muldf3`, `__divdf3`, `__floatdidf`, `__fixdfdi`, `__eqdf2`/`__ledf2`/`__gedf2`, …) and libm's `floor`/`fmod`/`pow`.

The obligation for each opcode's float paths is a field of `FloatArms` (`Lua/Vm/Sim/Fold.lean`, 39 fields). Quoted exactly:

```
structure FloatArms : Prop where
  LOADF : SimArm .LOADF
  DIV : SimArm .DIV   DIVK : SimArm .DIVK   POW : SimArm .POW   POWK : SimArm .POWK
  ADD : SimArmOn .ADD FltBC   SUB …  MUL …  MOD …  IDIV …  BAND …  BOR …  BXOR …  SHL …  SHR … (FltBC)
  ADDK … SUBK … MULK … MODK … IDIVK … (FltBK)   BANDK … BORK … BXORK … ADDI … SHRI … SHLI … UNM … BNOT … (FltB)
  EQ … LT … LE … (FltAB)   EQK … (FltAKb)   EQI … LTI … LEI … GTI … GEI … (FltA)
  FORPREP : SimArmOn .FORPREP ForCoerce   FORLOOP : SimArmOn .FORLOOP FltStep
```

`SimArmOn o Q` is `SimArm o` (`sim_ADD`'s shape, below) restricted to steps where predicate `Q` holds, e.g. "B or C holds a float":

```
SimArm o := ∀ p, Supported p → ∀ c s s', VmRel p c s → fetch/opcode = o → Step p s s'
            → ∃ c' n, 0 < n ∧ StepsN n c c' ∧ VmRel p c' s'
```

The soft-float routines are summarised in two levels:
- **(a) machine code = a lifted Lean function,** generated by `scripts/gen_lua_fn.py` and proved (`Lua/Vm/Fn/*`).
- **(b) lifted function = the `F64` spec op,** with `F64` proved bit-equal to `Float.Model` (`Lua/Num/F64.lean`). NONE of the (b) equations closed; they are one named premise, `SoftFloatSpec` (`Lua/Vm/Fn/Spec.lean`).

## What is costly (census, ROUND-5.md §1)

1. **Float arm paths.**
   - FORLOOP costs 29 hand lines, 10–14× an int arm. 48% of it reads three float registers, while the machine tests only one tag; the other two come from the kernel.
   - 33 fields remain: 3 GEI-like, 8 ADDI-like (register or K partner), 4 all-float, 16 FORLOOP-like or worse (4–24 float paths each, forking on soft-float answers), and 2 where the float handling is inside a callee.
   - 93 comparison-call sites use 17 result idioms. 22 `floor` sites include 20 inlined `luaV_flttointeger` chains in 6 layouts.
   - Heartbeats go to wrong-polarity closers (10.3k of 59.1k) and to replaying the shared machine prefix per kernel outcome (8.3k). Forecast: some arms exceed the 200k budget.
2. **Level (b).**
   - `__adddf3` lifts to 133 nodes, 497 paths, 42 variable shifts and 14 spill reloads. Rounding is inlined 6×, the sticky shift 5× and pack 4×.
   - Nothing names the sign/exponent/fraction stages, and `omega` can't handle the variable shifts.
