- **N4. F1 forbids open calls.** The kernel row is

  F1 CALL is `B ≠ 0 ∧ C ≠ 0`.
- **N5. `ValRepr` has slack in its tags.**
  - `ValRepr.nil` accepts any `t % 16 = 0` (0, 16, 32, …).
  - `ValRepr.str` accepts `vShrStr ∨ vLngStr` whatever the header says.
  - `TStringRepr` is functional in its content: the length and the bytes are
    pinned. So a pointer determines the string.

## 1. One close, read off the final memory. The seven close proposals are one mechanism, and only the cheapest should be built

**Acts on:** (b) merges R3-R1-5 #2 (`bleach`) with R3-R1-1 #1's `apply_final`
(R1.3). It then (c) objects to R3-R1-2 #3 (`StoreLog`) and R3-R1-3 #3 (store
patches) as duplicate machinery with a hidden cost.

### Idea

Seven round-1 proposals are the same rule under different names. Each says:
"state the close over the arm's final memory, so store order and store shape
disappear".

- R1-1 #1: the lens, `apply_final`;
- R1-2 #1: `put_get`;
- R1-2 #3: `StoreLog`/`commit`;
- R1-3 #3: patches with a normaliser;
- R1-4 #1: `dec_image`;
- R1-5 #1: `decode_store_other`;
- R1-5 #2: `bleach`.

They differ only in *what object carries the final memory*: a log, a patch,
an image or a view. The executor (the incumbent's runs or SymExec) already
produces `c'.σ.mem` as a nested chain of inserts. **That term is the log.** A
separate `WriteLog` fold (150–220 lines) or a patch normaliser with
representation quotients (300–400 lines) would recompute what the run has
already computed. That is paying for the same bill twice.

**Build only `bleach`, generalised to any edge.** It needs three premises:

- **(i) Frame, byte-wise.** For every `a ∉ Win' ∪ Slots(e.defs ∪ kills e)`,
  `c'.mem[a]? = c.mem[a]?`.
- **(ii) Defs.** For every `j ∈ e.defs`,
  `ValRepr w (slotTag c'.mem (w.slot j)) (slotVal c'.mem (w.slot j)) (vals j)`.
- **(iii) Pins and `RegsOk`.**

Premise (i) is discharged by a single simp set
(`getElem?_insert_ne`/`writeMap8` read-over-write, plus `omega` on offsets).
Premise (ii) is discharged by simp reading the final bytes.

Three things then need no lemma at all:

- **Tag-only stores** (LOADTRUE and friends): the payload is read back
  unchanged and ignored by `ValRepr.true_ {x}`.
- **Payload-only stores** (FORLOOP): the tag byte is read back through (i)
  as the old tag, which is 3.
- **Store order:** the insert chain is simply read.

This removes R1-3 #3's "tag irrelevance under a precondition" and its
state-indexed `≈[repr w s]` entirely.

**The part no one in round 1 said.** The `vals` in (ii) are exactly the
`vals` that `kstep` evaluation produces (idea 3). So `bleach` should be
stated with `(e, o) := kstep` output, not with kernel-inversion output. The
close then consumes the evaluator's result directly, with no glue lemma
between "which edge" and "which bytes".

### Core rules

- **L-C6′ → `bleach_edge`**, one theorem for every combinator, including
  `callK`'s kill range.
- **Store shapes → nothing.** They are no longer a concept.

### What it makes free

- **Cluster (c):** 28 declarations and 245 lines, plus 9–39 lines per future
  close shape.
- **The `*_of` transports:** these become premise (i).
- **The store-order row of L-C6′.**

### What it costs

- `bleach_edge` is about 50 lines. `Complement.dead_congr` is about 40 (R1-5
  #2's estimate, which I accept).
- **Harder:** premise (i) quantifies over all addresses. It must be discharged
  by *one* generic lemma, "an insert at `x ∈ S` leaves `a ∉ S` unchanged",
  iterated by simp. If simp needs a per-store `omega` call, the cost becomes
  linear in stores (MOD has 4 stores, and CALL's copy loop far more). This is
  the thing to measure.

### Objections, concrete

- **To R1-2 #3 (`StoreLog`).** Its fold lemma
  `mem_after_stores = mem ⊕ log` must re-derive little-endian `sd`/`sw`
  decomposition, which `SlotStore` and the insert chain already give.
  Its own "harder" item (read-after-write inside an arm) is a *non-problem*
  for the final-memory form: a read inside the run sees the partial insert
  chain as it stands. The log form is the only one that forgets it.
- **To R1-3 #3 (patches).** Its normaliser "must fail loudly on partial
  overlaps", which is extra code for a case the final-read form handles
  silently and soundly.

### Theories

- *Known:* Burstall's and Bornat's component-as-array memory model and
  read-over-write axioms (McCarthy's `select`/`store` theory, 1962; Bornat,
  MPC 2000). Recalled; check the citations.
- *Known, distant (forensic fire investigation):* burn-pattern analysis reads
  the *final* char pattern, and the order of ignition is not recoverable and
  not needed for the conclusion. Recalled (NFPA 921); check it.
- *Novel:* feeding `kstep`'s output edge directly into a final-memory close,
  so that the kernel side and the memory side share one `vals` term.

### Pilot

- **Build:** `bleach_edge` and the read-over-write simp set.
- **Refactor `sim_ADD`:** it is tag-first; replace its `Core.write` and
  `slotStore_sb`/`_sd_sb` uses.
- **MUL:** payload-first, and the same call works unchanged.
- **MOD, EQ:** the `Protect` stores land in `Dead`, which is premise (i)'s
  `Win'`.
- **Measure:** close lines per leaf. The prediction is at most 2.

### Seed

**singey**, **rearwardness**: look rearward at the singe mark (the final
memory), not at the order of the flames (the stores). **rediscount** and
**bill**, as a warning: the run already discounted the store list once, so do
not build a second instrument (a log or a patch) to discount it again.

## 2. Chaptalized `ValRepr`: make the tag a function of the value, and hold short strings through a lifeholder intern map in the witness

**Acts on:**

- (c) objects to R3-R1-5 #1's `decode_canon` ("short strings are unique per
  content" as an `Inv`) and to R3-R1-2 #1/#2's global interning invariant;
- (d) goes where none of round 1 went: a *definitional* fix, not an invariant.

It is the coordinator's soundness gaps 2 and 3, fixed with no new relation
field.

### Objection first (a counterexample to the round-1 fix)

A heap invariant "no two TStrings in memory have equal short contents" is
**false** whenever the GC has run.

- `luaC_fullgc`/`sweeplist` frees a dead short string, but dlmalloc's `free`
  does not zero the bytes.
- A later `luaS_newlstr` of the same content allocates a new block.
- Memory now holds two byte-exact `TStringRepr`s of the same content. Only
  one of them is in `strt`.

F1's CALL print reaches `luaL_tolstring` → `lua_pushfstring` → string
creation and `luaC_checkGC`. So a long enough F1 loop that prints triggers
this. Any invariant quantified over raw `mo` (R1-5 #1, R1-2 #2's
`Factors_I`) is therefore unprovable after the first collection. It could be
restricted to "reachable" strings, but reachability is a heap-graph notion
that costs far more than the fix below.

### Idea

Add sugar before fermentation. **Strengthen `ValRepr` itself**, so that the
properties EQ needs are *definitional*, and preservation is automatic for
every arm that copies or writes a slot.

1. **Tag-functional.** Define `tagOf : Value → w → BitVec 8`:
   - `nil ↦ 0`;
   - `false ↦ 1`, `true ↦ 17`, `int ↦ 3`, `print ↦ 22`;
   - `str s ↦ 0x44` if `|s| ≤ 40`, else `0x54`.

   Replace the `t % 16 = 0` and `vShrStr ∨ vLngStr` slack with
   `t = tagOf v` (for strings, "tag agrees with length" is the same thing as
   agreeing with the header, because `TStringRepr` pins `short ↔ |s| ≤ 40`).
2. **Lifeholder intern map in the witness.** Add
   `intern : List UInt8 → Option Nat` to `RelPtrs`. The short-string case of
   `ValRepr` requires `w.intern s = some x`, plus `TStringRepr w.mo x s`.
   Because `VmRel` is `∃ w` at each head, the map is re-chosen at every head.
   It only has to cover strings *currently referenced* from `R[]` or `K`, so
   GC can drop entries freely.

Two things follow:

- **Pointer equality ↔ content equality** is a two-line lemma. `intern` is a
  function, which gives ←. `TStringRepr` is functional in its content, which
  gives →.
- **Tag equality between two slots ↔ same variant** is `congrArg tagOf`.

### Why this is cheap

- **Producers already write canonical tags.**
  - `setnilvalue` writes `LUA_VNIL = 0`.
  - The main-chunk stack is nil-initialised by `stack_init` with tag 0.
  - `luaV_finishget` writes `setnilvalue`, not `VEMPTY`.
  - MOVE/LOADK copy tags bytewise from slots or `K`, which are canonical.

  So the 25 proved arms *produce* the strong form with no new facts. Only
  places that *construct* a `ValRepr.nil` with a symbolic `t` change. (Check:
  I have not read the arm proofs.)
- **Consumers get stronger.** Every guard on a tag byte becomes a rewrite by
  `t = tagOf v` (idea 3 uses this).
- **Preservation of interning costs 0 per arm.** A slot that satisfies
  `ValRepr w` carries its intern fact with it, and copies carry the source's.

### Core rules

- **Soundness gaps 2 and 3 → definitional.** No `VmRel` field is added, and
  there is no preservation lemma per arm.
- **L-C4 is unchanged.** The decoder can now be *total and injective* on
  `(tag, payload)` for non-long strings, which is R1-5 #1's `decode_canon`
  for free.

### What it makes free

- **EQ/EQK's `luaV_equalobj` value**, on nil, bool, int, print and short
  strings.
- **`Factors` over pairs of slots** (R1-2 #2's "second instance family" for
  `beq tagA, tagB`): this is `congrArg`.
- **The long-string/short-string variant mismatch** (`ttypetag` compares
  `& 0x3F`, so a short-tagged long string would compare unequal). It is
  excluded by construction.

### What it costs

- **Changing `ValRepr mo` to `ValRepr w`** touches every statement that
  mentions it: a mechanical signature ripple. Budget about 40 lines.
- **`vmRel_entry`** must build `intern` from the constant table. Every F1
  string at entry is a `K` constant, and `luaY_parser` interned them. That
  needs about 30 lines, plus an entry fact that `K`'s short strings are
  distinct pointers per content. The loaded image gives this; check it.
- **Harder:** long strings (`luaS_eqlngstr` → `memcmp`) still need a loop in
  the helper. In F1 they occur only as constants longer than 40 bytes.
- **Harder:** later fragments that *create* strings (CONCAT, or `tostring`
  results stored into registers) need `luaS_newlstr`'s runtime contract to
  return `w'.intern s`. That is a clause the runtime shape needs anyway.

### Theories

- *Known (programming languages):* hash-consing. Ershov 1958; Goto 1974;
  Filliâtre and Conchon, "Type-safe modular hash-consing", ML Workshop 2006.
  With it, physical equality is structural equality by construction.
  Recalled; check.
- *Known, distant (oenology):* chaptalization: adjusting the must *before*
  fermentation, instead of fortifying the finished wine. Chaptal, *L'art de
  faire le vin*, 1801. Recalled; check. Strengthen the representation up
  front, instead of adding an invariant later.
- *Known, distant (law):* a life estate. The holder's interest lasts only as
  long as the measuring life. This is the intern entry that lives exactly as
  long as some register or constant refers to it.
- *Novel:* putting the intern map in the *existential witness* of a
  simulation relation. GC safety then comes from re-choosing the witness at
  each head, not from a reachability invariant.

### Pilot

- **Build:** `tagOf`, the tightened `ValRepr`, `RelPtrs.intern`, and
  `ptr_eq_iff_content_eq`.
- **Refactor `sim_ADD`:** it must still go through with no change beyond the
  signature ripple. This is the control that the tightening costs nothing.
- **EQ:** `luaV_equalobj`'s value lemma for F1 tags.
- **MUL, MOD:** unaffected (controls).

### Falsifier (cheap, before any Lean)

Extend the L-C4 checker. At every one of the 1,424 head crossings, assert:

1. every slot decoding to nil has tag byte exactly 0;
2. every string slot's tag agrees with its header;
3. no two registers or `K` entries hold different pointers to equal short
   contents.

Separately, scan the whole memory for byte-identical `TStringRepr`s at two
addresses after a run long enough to trigger GC. This confirms or refutes
the objection above.

### Seed

- **chaptalization:** strengthen before, not after.
- **lifeholder:** the intern entry lives as long as its referent.
- **lissotrichan** (straight-haired): one canonical form per value, with no
  curl of 16 alternative nil tags.

## 3. Evaluate the kernel forward; delete `knf`, `KTree` and reconciliation; with idea 2, guards become one rewrite

**Acts on:**

- (c) objects to R3-R1-1 #4's `knf`/`knf_sound`/`refines` (R4.2, R4.3) and to
  R3-R1-4 #4's `KTree`/`ktree_eq`/`reconcile_sound`, as redundant with
  `kstep`;
- (b) combines R3-R1-3 #5 (forward evaluation) with idea 2;
- (c) also objects to R3-R1-2 #2's per-shape `Factors` instances as
  unnecessary once tags are functional.

### Objection

`knf` (about 150 lines) and `KTree` with 7 `ktree_eq` lemmas and
`reconcile_sound` (about 220 lines) each build a *second* decision-tree form
of the kernel. The first form already exists and is executable: `opKernel p
pc w` is a `Kernel` whose `body` is a Lean `match` on the read values.

With symbolic fields `w.a`, `w.b`, `w.c`, simp reduces:

- `reads.mapM s.regs`: a literal two-element list for `opArith`;
- `Opnd.fill`;
- the `match [.int x, .int y]`.

Once the leaf's path condition says both reads are `.int`, the whole kernel
is a normal form. The machine-to-kernel correspondence that reconciliation
labels as "speciation" or "duplication" is simply this: *simp closes the
leaf, or leaves a residue*.

- **Duplications** (MOD's `y ∈ {0, −1}` test, the sign fix-up) surface as
  residues about `BinOp.int .mod`. These are exactly the δ value lemmas that
  reconciliation also needs.
- **Losses** (EQ's `valEq` computed inside the callee) surface as the call
  node's `a0` fact.

Nothing is gained by naming the events.

### Idea

The leaf obligation is `kstep s = some (e, o)` with `(e, o)` read off the
machine leaf (its target pc, and its final slot bytes via idea 1). It is
closed by `simp [kstep_iff, opKernel, arithRR, opArith, Opnd.fill, δ]`,
together with the leaf's path facts.

The path facts come from the machine branches. **Under idea 2 they are not
lemmas.**

- Branches on a tag byte: after `lbu t,8(slot)`, `t = tagOf v`, so
  `beq t, s2` with `s2 = 3` becomes `tagOf v = 3`. That is `v.isInt` by
  `decide` over 7 constructors.
- Nil tests `andi t,15`: `tagOf v &&& 15 = 0 ↔ v = nil`, by `decide`.
- The pair test in `luaV_equalobj`: `(tagOf v₁ ^^^ tagOf v₂) &&& 63 = 0`.
  This is `decide` over 7 × 7 constructor pairs.

So the census's (a4) cluster (40 declarations) becomes **one** `simp` lemma,
`ValRepr.tag_eq : ValRepr w t x v → t = tagOf v`, plus `decide`. R1-2 #2
needed about 8 `Factors` instances, each deciding over 256 tags. R1-5 #1
needed 7 `decode_tag` lemmas. Both were needed only *because* the tag was
not a function of the value.

Payload tests (`slt`, `bgeu 1, n+1`) remain `BitVec` facts, one simp lemma
each: `BitVec.slt_iff`, and `n + 1 ≤u 1 ↔ n = 0 ∨ n = −1`. Round 1 already
listed these.

### Core rules

- **(a5) → `kstep_iff`**, which exists: zero new declarations per tree.
- **(a4) → `ValRepr.tag_eq` + `decide`**: one declaration, total.
- **L-C2′ → nothing to key.** Arms whose trees agree produce the same simp
  residue.

### What it makes free

- (a4): 40 declarations and 191 lines, and every future guard pair.
- (a5): 19 declarations and 209 lines, and every future inversion.
- **Most of the setup of three round-1 proposals:** R1-1 #4 (its R4.1 and
  R4.2), R1-4 #4 (all of it), and R1-2 #2 (all of it except the payload
  lemmas).

### What it costs

- A simp set that evaluates `opKernel` without unfolding `Proto.fetch` or
  `nextJump` wholesale. EQ's `docondjump` needs `nextJump p pc` as a
  hypothesis (`Complement.code_word` gives it).
- **Harder:** a leaf residue is less readable than a named reconciliation
  failure, as R1-3 #5 already noted. Mitigation: state one leaf per
  `have`, so a failure names its leaf.

### Theories

- *Known:* proof by reflection and evaluation (Boutin 1997; the `decide`
  lineage). Recalled; check.
- *Known, distant (psychology):* Gestalt configurationism (Wertheimer 1923):
  the whole is perceived directly, and it is not reconstructed from
  part-features. Here, the kernel is evaluated whole instead of being
  re-assembled as a feature tree (`KTree`). Recalled; check.
- *Novel:* the observation that the guard family exists only because of
  representation slack. With a tag-functional representation, every
  tag-byte guard is a rewrite.

### Pilot

- **Refactor `sim_ADD`:** delete `step_opArith` and its guard pairs. The
  leaves are two uses of `tag_eq`, one `simp [kstep…]` and one
  `bleach_edge`.
- **MUL:** the same, plus the call node (idea 4).
- **MOD:** four live leaves.
  - The `y = 0` leaf is vacuous: `kstep = none` contradicts `Step`
    (R1-3 #4, R1-5 F-f).
  - The `y = −1` leaf uses `imod x (−1) = 0`.
  - The two `__moddi3` leaves use one δ lemma,
    `imod_eq_srem_fix : y ∉ {0,−1} → imod x y = let r := x.srem y; if r ≠ 0 ∧ (r ^^^ y).msb then r + y else r`,
    shared with MODK.
- **EQ:** two leaves on `k = a0`.
- **Measure:** lines per leaf. The prediction is at most 3 (guard rewrite,
  kernel simp, close). This is the number that decides idea 5's
  "under 10 per arm".

### Seed

- **configurationism:** perceive the whole kernel, not a rebuilt tree.
- **assever:** assert forward (`kstep s = some …`); do not invert backward.

## 4. Relocate leaves only, and execute wrappers: the actual cost of reusing the WHILE helper specs

**Acts on:**

- (c) objects to R3-R1-1 #3's R3.2 ("`jal`/branch offsets are relative, so
  they are equivariant"; "`ret`/`jalr` are equivariant because they go
  through `ra`") and to R3-R1-2 #4's byte-equality transport;
- (b) combines both with R3-R1-5 #3's class R;
- (a) extends the coordinator's fact that the five soft-int helpers are
  instruction-identical after address normalisation.

### Objections, from N1 and N2

1. **`jal` is not translation-equivariant.** It writes `rd := pc + 4`, so after
   `__moddi3`'s inner `jal __hidden___udivdi3`, `ra` holds `0x8002f7c0` in the
   Lua ELF and a different value in WHILE. A relation of the form "all
   registers equal, pc shifted by d" breaks at the first internal `jal`. The
   real relation must track a *set of code-pointer registers* that differ by
   d (`ra` after `jal`, and `t0` after `mv t0,ra` holds the *caller's*
   `ra`, which is not shifted). That set is flow-sensitive: a small typing
   pass, not one equivariance lemma. R1-2 #4 estimated 200–400 lines for the
   whole thing; the flow-sensitive part is what makes it risky.
2. **The WHILE specs cannot be instantiated on a Lua state.** Their
   precondition includes `__muldi3Loaded c.σ.mem`, which is about the bytes
   at `0x80004640…`, and those are Lua code in the Lua image. Relocation
   alone does not help. You also need **memory independence**: the run
   depends on memory only through fetched words. That holds only for code
   with no loads or stores, which is R1-5 #3's class R.

### Idea

Split the helpers by N2's structure.

- **Leaves** (`__muldi3`: 9 instructions; `__hidden___udivdi3`: 18) are class
  R. They have no load, store, `jal`, `auipc` or csr, and they exit by
  `ret`. Prove **one** theorem, `reloc_R`. For class-R code with byte
  content `b`:

  ```
  Triple (St@a b …) Q  →  Triple (St@a' b …) (Q shifted by a' − a)
  ```

  It holds for *any* surrounding memory: the simulation relation is "pc
  shifted, every GPR equal, memory arbitrary but equal on both sides except
  the two code windows". This needs no code-pointer typing, because leaves
  have no `jal`. `ra` is the spec's parameter `r` and is never written.
- **Wrappers** (`__moddi3`, `__divdi3`, `__umoddi3`: 6–8 straight-line
  instructions around one `jal` each) are **not relocated**. They are
  *executed* at their Lua address by the same executor as the arms, with the
  relocated leaf spec as a call node. Their `jal` is then an ordinary call
  node, and the `ra`/`t0` juggling is ordinary register state. The wrapper's
  value lemma is `__moddi3 x y = x.srem y`, which is about 10 lines of
  `BitVec` (sign cases, including `x = INT_MIN`). It is written once and
  shared by MOD/MODK, with IDIV/IDIVK using `__divdi3`.

### Core rules

- **L-C3′ pure, register-only → `reloc_R` + `call_R`.** `call_R` is R1-5 #3's
  frame rule; with `muldi3_post`'s `mem = m0` and `hframe`, it is nearly a
  restatement.
- **L-C2′ for helpers:** MUL and MULK share the relocated `muldi3_spec`.
  MOD, MODK, IDIV and IDIVK share the relocated `udivdi3_spec` through two
  executed wrappers.

### What it makes free

- **Cluster (b)'s soft-int part.** `Muldi3Spec` (about 930 lines, per-site
  style) and `DivLoops` are reused, not redone. The "sites only, no spec"
  `__divdi3`/`__moddi3` become executor runs plus a `srem`/`sdiv` value
  lemma each.
- **No position-dependent reasoning anywhere in the arm layer.**

### What it costs

- `reloc_R`: about 120–180 lines, by induction on `StepsN`, with one case per
  instruction *class* (ALU, branch, `jalr x0`). It is not per-pc. It also
  needs Sail's fetch to read only `[pc, pc+4)`, and `GoodState`, `tick` and
  `minstret` to be pc-independent; check both.
- **Harder:** the tick model. `St.tick < 2` and `muldi3_spec`'s triple are
  over `Steps`, and the arm needs `StepsN` with `0 < n`. `TripleN` exists in
  `Vsa/Triple.lean`, so the bridge should be small; check it.

### Theories

- *Known, distant (finance):* rediscounting. A central bank accepts a bill
  already discounted by a commercial bank on the strength of the first
  endorsement, and does not re-examine the underlying trade. See Bagehot,
  *Lombard Street*, 1873 (recalled; check). The WHILE proof is the first
  endorsement.
- *Known, distant (marine biology):* plankton drift. A planktont's identity
  is independent of where the current puts it, but only for organisms that
  do not anchor. The anchored ones (`auipc`, internal `jal`) must be
  re-examined in place.
- *Known (systems):* position-independent code (Levine, *Linkers and
  Loaders*, 1999). The novelty here is splitting callees into PIC leaves
  (relocated) and non-PIC wrappers (re-executed), instead of proving
  equivariance for everything.

### Pilot

- **Build:** `reloc_R` for the instruction classes of `__muldi3`, and
  `call_R`.
- **MUL:** a call node with the relocated `muldi3_spec`.
- **MOD:** the relocated `udivdi3_spec` plus an executed `__moddi3` run, plus
  `moddi3_eq_srem`.
- **EQ, ADD:** unaffected (controls).
- **Measure:** lines of `reloc_R` against R1-2 #4's 200–400. Check that no
  per-site lemma is written.

### Falsifier (an hour, no Lean)

Scan the two leaves' bytes for `auipc`, `jal` with `rd ≠ x0`, loads, stores
and csr. N2 says this passes for `__hidden___udivdi3` and `__muldi3`. If a
leaf fails the scan, `reloc_R` needs the code-pointer typing, and this idea
collapses into R1-1 #3's cost.

### Seed

**rediscount** and **bill** (reuse the first endorsement); **planktont**
(identity under drift, for unanchored code only).

## 5. Callee shape is a property of the *pruned* callee tree, not of the helper

**Acts on:**

- (c) objects to R3-R1-5 #3's syntactic effect-class scanner, and to R1-1 #3
  R3.3, R1-2 #4 and R1-3 #4, which all classify `luaV_equalobj` as pure;
- (a) extends R3-R1-5 #3's "camera square applied to the helper" and R1-3
  #4's "one judgement reused for the callee".

### Objection (N3)

A syntactic scanner over `luaV_equalobj`'s static closure classifies it as
**U (runtime)**, for three reasons:

- **A metamethod call is in its closure.** The table and userdata cases reach
  `luaT_callTMres` (`lvm.c:614ff`), and that reaches `luaD_call` and all
  of Lua.
- **It dispatches through `jr a5` on a jump table** built by `auipc`, which
  R1-5 #3 itself says forces class U.
- **It saves `ra` on the stack**, so it is at best RO, never R.

So the scanner loses exactly the helper that EQ, EQK, LT and LE need. The
round-1 answers that call it "pure" are right *only on F1 argument tags*. In
a later fragment with tables, EQ on two tables with `__eq` is a runtime call
that can print, allocate and error.

### Idea

Classify a callee **per call node, under the caller's path facts**.

- Run the helper through the same executor as the arms, with its entry state
  built from the call node's arguments: `a1`/`a2` point to slots whose
  decoded values have tags known from Φ (idea 3 gives them from `tagOf`).
- The jump table's index is then concrete per path. `jr a5` resolves by
  reading the table word from `.rodata`, which is image-constant
  (`Complement`).
- The pruned tree never reaches `luaT_callTMres`.
- The shape is **derived**, not declared:
  - no stores above entry `sp` on any live path, so RO;
  - no `jal` to a U callee on any live path;
  - the value at every leaf is `a0 = decide (v₁ = v₂)`, with the int leaf
    `sub; seqz` and the short-string leaf a pointer compare that idea 2 turns
    into content equality.

The table row becomes `(luaV_equalobj, δ .eq, tags ∈ F1)`. For fragments
with tables, the *same* helper gets a second row,
`(luaV_equalobj, runtime(Φ_TM), tags = table)`. Shape is a function of
(helper, argument tag class), and L-C3′'s three shapes are assigned *per
row*.

### Core rules

- **L-C3′ → `shape_of_pruned_run`.** If every live path of the helper's
  executor run from an RO-entry state stays RO, then `call_RO` applies
  to that call node. This is one theorem. It replaces the scanner's soundness
  proof, which would have been about 150 lines, with the executor's own
  soundness.
- **L-C2′ for helpers:** EQ/EQK share `luaV_equalobj`'s pruned run, and LT/LE
  share `l_strcmp`'s.

### What it makes free

- The scanner, and its soundness proof (R1-5 #3's 80 + 150 lines).
- **Indirect jumps inside helpers.** The 21 unresolved `jalr` sites cost
  nothing when their index is path-constant.
- **Future-proofing.** The table/userdata `__eq` path arrives as a new row,
  not as a reclassification of an old helper.

### What it costs

- The executor must handle `auipc` (a pc-relative constant) and an indirect
  `jr` whose target is a loaded image word. Both are ordinary once the image
  is in `Complement`, but check that SymExec's decoder accepts `jr a5` with
  a symbolic-free target.
- `luaS_eqlngstr` → `memcmp` is a loop, so it needs a loop node (R1-2 #5's
  LOADNIL loop node, reused). F1 only reaches it for long constants.
- **Harder:** the helper's own C frame (`sd ra,40(sp)`) is below the
  caller's `sp`, so it falls in `Dead` (idea 1). The helper's run must prove
  it restores `sp` and `ra`, which is ordinary executor output.

### Theories

- *Known, distant (epidemiology):* an **enthetic** disease is introduced from
  outside. Whether a host is infectious depends on exposure, not on the
  species. A helper is "runtime" only on paths exposed to a metamethod.
- *Known (program analysis):* context-sensitive effect analysis. Call-string
  and functional approaches: Sharir and Pnueli, 1981 (recalled; check). The
  context here is the argument tag class.
- *Known, distant (pharmacology, answering R1-5 #3 on its own ground):* a
  BCS class can depend on the dose (the dose number Do), not only on the
  drug. The same molecule can be class I at a low dose and class II at a
  high one (Amidon et al. 1995; recalled; check). Shape per (helper, dose),
  that is, per (helper, tag class).
- *Novel:* deriving a callee's effect class from its *pruned* executor run
  under caller path facts, so that one helper carries several shape rows.

### Pilot

- **EQ:** run `luaV_equalobj` pruned by F1 tags. Check three things:
  - the live leaves are
    `{tag-mismatch → 0, nil/bool/print → 1, int → seqz, shrstr → ptr-eq}`;
  - no live path reaches `0x8001b86c` (the metatable load);
  - the result is RO.
- **MUL, MOD:** controls. Their callees are class R, handled by idea 4.
- **Measure:** helper lines for `luaV_equalobj` (the prediction is about 20,
  mostly the value lemma), and EQK's added cost (the prediction is 0 beyond
  its row).

### Seed

- **enthetic:** the risk comes from outside, on exposed paths only.
- **impotence**, **desperacy**: the error and metamethod paths that are
  powerless under F1's facts are pruned, not classified.

## Answers to the three pressing questions

### Which round-1 ideas are the same mechanism, and which merge is cheapest

| mechanism | round-1 names | cheapest form |
|---|---|---|

| unconstrained cells (`savedpc`, `L->top`, below `sp`) | R1-1 #2 (gauge), R1-2 #1 (Δ `protect`), R1-3 #2 (owners, phase invariant), R1-4 #1 (`supp Inv`), R1-4 #3 (`RtOk`), R1-4 #5 (ring 2), R1-5 #2 (`Dead`) | R1-5 #2's `Dead` plus one `LuaStateAt.top` edit. **Refinement:** make the exclusion of `L->top` keyed by a *static* predicate, `topLive p pc := (pc = 0) ∨ prev instruction has an open result`. Under N4 it is `pc = 0` in F1 at no cost. It stays correct when CALL `B = 0` after CALL `C = 0` arrives (the next instruction reads `L->top` as an input), which a plain "dead at head" would silently break. |
| tag guard as a value predicate | R1-1 #4 R4.1, R1-2 #2, R1-3 #1, R1-4 #4 `Obs`, R1-5 #1 `decode_tag` | `ValRepr.tag_eq` after idea 2's tightening: one lemma (idea 3) |

### The smallest combination that brings MUL, EQ and MOD under about 10 hand lines each, and shrinks `sim_ADD`

`bleach_edge` + `Dead` (with `topLive`) + tightened `ValRepr` + `kstep_iff`
evaluation + `call_R`/`reloc_R`, **carried by an executor** (SymExec with call
nodes; no `knf`, no reconciliation).

- **One-time setup:** about 50 + 70 + 110 + 20 + 180 lines, roughly 430,
  plus the executor's call node.
- **Per arm:** a row, plus leaf residues.
  - MUL: about 3 lines.
  - MOD: about 5 lines, plus shared δ lemmas (`imod_eq_srem_fix`,
    `imod_neg1`, `moddi3_eq_srem`), about 25 lines reused by MODK.
  - EQ: about 4 lines, plus `luaV_equalobj`'s pruned run and value lemma,
    about 20 lines reused by EQK.
  - `sim_ADD`: loses `step_opArith`, its guard pairs and its `slotStore`
    uses. Target: under 20 lines, against 61.

**Without an executor** (the incumbent's generated runs, with the same
lemmas), the cost is linear in *leaves*: about 3 lines per leaf. That gives
MUL ≈ 9 and EQ ≈ 6, but **MOD ≈ 14** (four live leaves and one vacuous).
So MOD is the arm that decides whether the executor is needed at all.

### What would falsify the leading combination cheaply, before a bake-off

1. **Leaf cost, in half a day.** Hand-refactor *one* leaf of `sim_ADD` (the
   int × int leaf) with `bleach_edge` + `tag_eq` + `simp [kstep_iff…]`.
   - More than 3 lines: "under 10 per arm" fails for MOD without an
     executor.
   - More than 5 lines: it fails even with an executor, because MOD has five
     leaves' worth of residues.
2. **Tag canonicity, with the checker only.** Run idea 2's three assertions
   over the 1,424 head crossings.
   - Any nil tag other than 0, or any string tag disagreeing with its header,
     kills the tightening. EQ then needs R1-5 #1's invariant, and pays for
     it on every arm.
3. **Relocatability, with objdump only.** Run idea 4's scan of
   `__muldi3`/`__hidden___udivdi3`.
   - Any `auipc`, linking `jal`, load or store means `reloc_R` must become
     the flow-sensitive version, and the setup doubles.
4. **The `Dead` set, with a trace.** Check "no read of `ci->savedpc`,
   `L->top`, or `[sp − K, sp)` before a write in the same head interval" on
   the 1,424 steps.
   - Any read (for example `luaG_traceexec` on a trap path) shows which
     cell needs `topLive`-style phase keying.
5. **The EQ helper's pruned run, by reading.** Confirm from the disassembly
   that, with both tags in `{0, 1, 17, 3, 0x44, 0x54, 22}`, no path reaches
   `0x8001b86c`.
   - If the tag-mismatch path for int against a float-looking tag (the
     `andi 15; li 3; beq` at `0x8001b7ac`) is live under F1, idea 5's row
     needs the float case, which is pruned only by `Supported`.
