## 1. Port-typed kernels ("the opcode is its functional role")

**Idea.** The pattern is already there in `arith` + `intArith`/`arithShape`;
this idea applies it to every opcode and makes it the only way to state a
rule. An opcode's meaning becomes one value of a structure. Its *ports* are
fixed by the instruction word alone, never by register contents:

```lean
structure Edge' where tgt : Nat; wr : List Nat          -- static in (p, pc, w)
structure OpSpec where
  ins   : Proto → Nat → Word → List Nat                  -- registers read (in order)
  outs  : Proto → Nat → Word → List Edge'                -- edges with their write lists
  kern  : Proto → Nat → Word → (vals : List Value) →     -- pure, on the read values only
          Option (Σ e : Fin (outs ..).length, Vector Value (outs ..)[e].wr.length × String)
```

The kernel receives *only* the values read. It returns an edge index, one value
for each register that edge writes, and the text it emits. It cannot write
anywhere else, and it cannot land anywhere else, **by typing**. `spec : OpCode →
Option OpSpec` is the whole F1 instruction set. Everything else is a projection
of `spec`:

- `Step s s'` := `∃ w sp r, fetch = some w ∧ spec w.op = some sp ∧
  sp.kern … (sp.ins … |>.map s.regs) = some r ∧ s' = apply r s`;
- `step?` is the same expression read as an `Option`;
- `reads`, `edgesOf`, `regTop` are `ins`, `outs` and the max over both.

The old named constructors (`move`, `testsetJump`, …) are kept as derived
*lemmas* so that the semantics stays readable (pedomorphism: the adult keeps
the juvenile's shape). They are no longer the definition.

**Core rules.**

- **L-B1 → `footprint`** (one theorem, by unfolding):
  `agree (sp.ins p pc w) s t → s.pc = t.pc → s.out = t.out → (Step s s₁ → ∃ t₁, Step t t₁ ∧ …)`.
  - Equal reads give equal kernel inputs, so the kernel output is the same.
  - `apply` writes exactly `outs[e].wr` and lands at `outs[e].tgt`.
  - "*some* edge with that target" (the TESTSET refinement) holds because the
    kernel returns the edge *index*, not the target.
- **L-B2 → `Step_iff_step?`**: `Iff.rfl` up to the `Option.bind` normal form.
  Both are one definition read two ways.
- **L-C1 (partial).** An arm splits into three parts:
  - port-fetch: one lemma, generic in the register index;
  - kernel refinement: per opcode, but on pure `BitVec`/`List UInt8` values,
    with no state;
  - write-back and dispatch: one lemma.

**What it makes free.**

- **All 75 `bc-rule-fanout` cases** (`step?_sound`, `step?_complete`,
  `Step.sim` arms). They become the two generic theorems.
- **Four of the five definition sites per rule.** `edgesOf`, `reads`, `regTop`
  and the `step?` arm are projections, so they can no longer drift apart. The
  "some edge, not the edge" and "edges exist" refinements are built into the
  types.
- **What a new opcode costs:** one `OpSpec` value, about 3–8 lines.

**What it costs.**

- **The TCB changes.** `Semantics.lean` is rewritten as a table of kernels, so
  the reviewer's check that it matches `lvm.c` moves from inductive rules to
  kernels. The kernels read close to `lvm.c` (compare `intArith`), but a
  human has to re-review them.
- **Dependent types.** The output (`Σ e, Vector …`) is awkward in Lean. The
  alternative is `List Value` plus a length check inside `apply`, which makes
  a wrong length stuck, and costs a small lemma.
- **Forward proofs change.** The compiler's translation validation now meets
  `∃ sp r, …` where it used to meet a constructor. The derived lemmas make up
  for that.
- **Setup:** about 150 lines (structure, `apply`, the two theorems, the 39
  derived lemmas stated as one-line `⟨_, rfl, …⟩` proofs).

**Theories.**

- *Known.* **Wiring diagrams / operads** (category theory): a box with typed
  input and output ports, composed only through the ports. D. Spivak, "The
  operad of wiring diagrams", arXiv:1305.0297 (2013). Footprint is the fact
  that a box sees only its inputs.
- *Known.* **ISA specification languages with one source and several readings**
  (computer architecture): Sail produces both an executable emulator and
  theorem-prover definitions from one specification. A. Armstrong et al.,
  "ISA Semantics for ARMv8-A, RISC-V, and CHERI-MIPS", POPL 2019. This
  project already trusts Sail for the same reason.
- *Known, applied here in a novel way.* **Bluespec guarded atomic rules** (hardware synthesis): a rule reads
  and writes declared registers, and a guard selects whether it fires. J. Hoe
  and Arvind, "Hardware synthesis from term rewriting systems", VLSI 1999.
  (Recalled from memory: check the venue.) Here the edge index plays the
  guard's part.

**Pilot.**

- **H1** (`LOADK` of a string): drop the `| _ => none` for `.str` in the
  `LOADK` spec's `outs`, since the kernel is `c.toValue?`. About 1 line.
- **H2** (`CONCAT A B`):
  - `ins = range A B`;
  - `outs = [(pc+1, [A])]`;
  - `kern` = a right fold with `tostr : Value → Option (List UInt8)`, where
    an int becomes its `%d` digits and anything else gives `none`.
  - About 8 lines. No metatheory.
- **H3** (`LEN`): `ins [B]`, one edge writing `[A]`, and a kernel `str s ↦ .int s.length`.
- **H4** (`LT`/`LE`): generalise `intCmp` to `valLt : Value → Value → Option Bool`,
  with byte-lexicographic order on `.str`. The conditional-jump spec already
  picks the edge from a `Bool`.
- **R1:** replace `Step.sim` and `step?_sound`/`complete` with the two
  theorems, then measure the lines.
- **Smallest build:** the `OpSpec` machinery plus MOVE, the `arith` family,
  TESTSET (two edges with the same target) and CALL print (range read and
  range write). If those four go through, the rest is transcription.

**Seed.** *functionalism* (an opcode is identified by its input/output role),
*pedomorphism* (the constructors are kept as derived juvenile forms),
*unwasting* (no write outside a port).

## 2. Poisoned stores and query certificates (footprint as monotonicity in the information order)

**Idea.** Change the register domain instead of the rules. A generic
`step?` is written once, over a *register algebra* `σ` that only has
`query : σ → Nat → Option Value` (a query may *fail*). It has two instances:

- **Total:** `Nat → Value`, where a query never fails. This is the semantics.
- **Poisoned:** `Nat → Option Value`, where `none` is ⊥ ("stale, unknown").
  A query on ⊥ aborts the step.

The poisoned file is ordered by information (`ŝ ⊑ s` iff they agree wherever
`ŝ` is defined): the inspissator thickens a partial file into a total one.
`step?` is written in a *query monad*: a decision tree whose internal nodes
query a register index computed from `w` alone and whose leaves are pure.
Two facts about the query monad are proved once, for all trees:

- **Certificate lemma** (decision-tree theory). If run(T, s) = r with query
  log Q, then run(T, t) = r and its log is Q, for every t that agrees with s
  on Q.
- **Monotone extension.** If the poisoned run on ŝ succeeds, then every total
  s ⊒ ŝ gives the same result.

**Core rules.**

- **L-B1 → the certificate lemma, plus `log ⊆ labels(T w)`.** The static set of
  query labels in the tree is *computed from the tree*. `reads w := labels (T w)`
  is a projection, not a table. The write and edge half of L-B1 comes from
  the leaves, whose write indices are also static.
- **Definite-initialisation soundness** (`bcSemFrom_iff`, `cbcSem_iff`),
  currently proved through `Step.sim`, → **one rule, `poison_run`**:
  - Take a program with `Supported p`, and give it the poisoned state whose
    defined registers are exactly the must-mask at each pc.
  - Its run never queries ⊥, because `reads w ⊆ mask pc` is what `Supported`
    checks.
  - By monotone extension, the runs from any two total completions coincide.
  - The stale values a `CALL` leaves above its base, and the registers at
    entry, are just two ways a register can be ⊥.
- **L-B2:** the total instance of the generic stepper, with `Step` defined as
  its graph. This part coincides with abstraction 1 and is not the novelty.

**What it makes free.**

- **Every `Step.sim` arm** (27 now, 39+ later), including the costliest
  (`forloopAgain`, 13 lines).
- **The per-rule reasoning inside `bcSemFrom_iff`.** The two
  definite-initialisation theorems become two instantiations of `poison_run`.
- **The `reads` table**: it is `labels`.

**What it costs.**

- `step?` has to be rewritten in the query monad, as a free monad over `query`
  with pure leaves. About 60 lines of monad and proofs, and an F1 stepper of
  about the same size as today's.
- `Step` must be tied to it: either by definition, or by the existing
  `step?_sound`/`complete`, which abstraction 1 or 4 would collapse.
- It does **not** by itself give L-B2. It is best paired with abstraction 1,
  whose `ins` become the tree's query labels.

**Theories.**

- *Known.* **Concrete data structures and sequential algorithms**
  (domain theory): a sequential function on a concrete domain is described by
  the cells it queries, and it is monotone in the information order.
  - G. Kahn and G. Plotkin, "Concrete domains", TCS 121 (1993), originally an
    IRIA report from 1978.
  - G. Berry and P.-L. Curien, "Sequential algorithms on concrete data
    structures", TCS 20 (1982).
- *Known.* **Certificates in query complexity** (complexity theory): a
  certificate is a set of queried coordinates that fixes the value. H.
  Buhrman and R. de Wolf, "Complexity measures and decision tree complexity:
  a survey", TCS 288 (2002). The certificate lemma is their Definition of
  C(f) read as a theorem about one run.
- *Known.* **Poison semantics in compilers**: `poison` propagates and only
  becomes UB when it is observed. J. Lee et al., "Taming undefined behavior
  in LLVM", PLDI 2017. ⊥ plays the role of a stale register, and `Supported`
  guarantees it is never observed.

**Pilot.**

- **H2** (`CONCAT`): the tree queries `A … A+B-1` in turn, from the rightmost,
  and its leaf folds. The footprint for H2 is 0 lines, since the labels are
  `range A B` by computation.
- **H1, H3, H4:** 0 footprint lines each. The only per-case work is the
  kernel, as in abstraction 1.
- **R1:** delete `Step.sim` and reprove `bcSemFrom_iff` through `poison_run`.
- **Smallest build:**
  - the query monad;
  - the certificate lemma and monotone extension, about 40 lines together;
  - a stepper for MOVE, ADD and FORLOOP in the monad;
  - `bcSemFrom_iff` restricted to programs made only of those three opcodes.

**Seed.** *baleise* (a baleen filter restricts the store to what is queried),
*inspissator* (thickening, ⊑), *unloosable* (monotone: once defined, a register
stays defined in every extension), *preopinionated* (the ⊥-mask is decided
before the run).

## 3. A determinism rule format ("the synod decides ahead which rule speaks")

**Idea.**

- **Rules as data.** `LuaSem`'s mutual relations are presented as a *rule
  system*: a finite list of rules. Each rule has three parts:
  - a conclusion pattern: the head constructor, plus static side conditions on
    constructor fields such as `op.arith = some f`;
  - an *ordered* premise list: `Eval e ⇒ x`, `Exec b ⇒ (ρ, o, sg)`, and so on;
  - *guards* on premise outputs: `v.isFalse = true`, `sg = .normal`,
    `v = .int x`, `v = .str s`.
- **The determinism format.** This is the metatheory result of SOS rule
  formats. Take any two rules whose conclusions can unify. Their premises must
  share a common prefix (the same premise on the same inputs), followed by a
  point where their guards are *disjoint*. This is a decidable check on the
  rule data.
- **Pretty-big-step form.** The intermediate forms `while₁ v`, `whileBody sg`
  are the "rebirths" that make the shared prefix syntactic.
- **One generic theorem.** A system in deterministic format, whose premise
  relations are deterministic, denotes a partial function. The fuel-indexed
  evaluator `evalSys sys` is *derived from the rule data*, never hand-written.
  It is sound and complete for `Derivable sys`.

This is not "an interpreter plus a separately proved soundness". The
evaluator is a single generic function over all rule systems, proved once. The
Lua-specific content is only the rule list, plus `decide` for the format check.

**Core rules.**

- **L-A1 → `graph_of_format`**:
  `DetFormat sys = true → (Derivable sys j out ↔ ∃ fuel, evalSys sys fuel j = some out)`.
  - Its corollaries are determinism, interpreter soundness and interpreter
    completeness for every construct.
  - `whileT`/`whileF`/`whileX` illustrate the format:
    - they share the prefix `Eval ρ c v`;
    - `whileF` splits off on `isFalse = true` against `false`;
    - `whileT`/`whileX` share `ExecB … sg` and split on `sg = .normal`
      against `sg ≠ .normal`.

  The format check finds exactly the exclusivity arguments that the
  determinism arms re-derive by hand, today with quadratic pairwise
  inversion.

**What it makes free.**

- **All 187 `ast-construct-fanout` cases.** The 50 arms of `Eval.det`, the 53
  of `ExecS.det`, and the `execSound` arms (`while_` 19, `if_` 16,
  `fornum` 15) become one theorem, plus one `decide` of `DetFormat luaRules`.
- **No more quadratic growth.** The format check is linear in the number of
  rule pairs that share a head, and the kernel does it.

**What it costs.**

- **The biggest setup of the five**, about 400–700 lines:
  - the rule-system syntax for a *mutual, many-sorted* family (Eval,
    EvalList, ExecS, ExecL, ExecBF, ExecB, ForIter): a sort index plus
    per-sort judgment shapes;
  - `Derivable`, `evalSys` and the generic proof.
- **Readability.** `Lua/Ast/Semantics.lean` becomes a data table, and the
  guards need a small predicate language: equality to constructors, `isFalse`,
  Sig tests.
- **Fixed-point side conditions** (`scope`, `jumpEnv`, `findLabel`,
  `forCount`) are pure functions in conclusions. The format must allow pure
  "let" nodes.
- **The goto recursion** (`ExecBF.jump` re-entering the same block) is
  determined by `sg.target`. That is one more guard (`target = none` against
  `some`), so it fits.
- **Evaluation.** `evalSys` is slower than a hand-written interpreter for
  `decide`-based testing, but that does not matter for proofs.

**Theories.**

- *Known.* **SOS rule formats for determinism** (process algebra).
  - L. Aceto, A. Birgisson, A. Ingólfsdóttir, M. R. Mousavi, M. A. Reniers,
    "Rule formats for determinism and idempotence", Science of Computer
    Programming 77 (2012). Recalled from memory: check the volume. It gives
    a syntactic format guaranteeing that a transition relation is
    deterministic.
  - General background: Aceto, Fokkink, Verhoef, "Structural operational
    semantics", Handbook of Process Algebra, 2001.
- *Known.* **LL(1) / deterministic parsing** (linguistics, formal languages).
  - View derivation trees of the big-step system as parse trees of an
    attribute grammar. D. Knuth, "Semantics of context-free languages",
    Math. Systems Theory 2 (1968).
  - Determinism then means that the rule for a head is predicted by bounded
    lookahead on already-computed attributes: an LL(1)-style disjointness of
    "FIRST guards". P. M. Lewis and R. E. Stearns, "Syntax-directed
    transduction", JACM 15 (1968).
  - *Novel* here: reading big-step determinism as the LL(1) condition on the
    attribute grammar of derivations.
- *Known.* **Pretty-big-step semantics** (PL): A. Charguéraud, ESOP 2013.
  **Functional big-step semantics**: S. Owens, M. Myreen, R. Kumar, Y. K.
  Tan, ESOP 2016. The first supplies the intermediate forms. The second shows
  that the functional reading carries soundness.

**Pilot.**

- **H1:** add the rule `Eval ρ (.string s) (.str s)`. It has a new head, so
  the format check passes by `decide` and determinism costs 0 lines.
  `supE` gains `.string _ => true`.
- **H2:** add the rule
  `Eval a va → Eval b vb → concatV va vb = some r ⊢ Eval (binop .concat a b) (.str r)`.
  - Against `arith`, `cmp`, `eq`, … the split is a static side condition:
    `.concat.arith = none` and `.concat.cmp = none`.
  - `BinOp` is a finite enum, so `decide` covers it.
- **H3:** `Eval a (.str s) ⊢ Eval (unop .len a) (.int s.length)`.
- **H4:** the rule `cmpStr`. It shares the prefix `Eval ρ a v` with `cmp`, and
  the two split on the guard `v = .int _` against `v = .str _`.
- **Measure:** each H case costs its rule line, plus the `AstSupported` line.
  The interpreter, soundness and determinism cost 0 lines.
- **R2:** replace `Determinism.lean` and `execSound` with `graph_of_format`
  and one `decide`.
- **Smallest build:** the format and the generic theorem for a *single-sorted*
  toy (Eval only, with `and`/`or` short-circuit, which have guard splits).
  Extend to many sorts only if it holds.

**Seed.** *synodally* (a council of rules where exactly one may speak, agreed
ahead), *preopinionated* (the rule is predicted before the premises
finish), *rebirth* and *mesolecithal* (the partial-cleavage intermediate forms
of pretty-big-step).

## 4. Actinomorphic orbits (prove one petal, transport it round the flower)

**Idea.** Opcodes fall into *orbits* under a group action. The action has two
parts:

- **Kernel substitution.** Swap the pure operation in a shape: `+` for `-`
  for `&` for `<<`, `<` for `≤`, `blt` for `bge`.
- **Renaming** machine registers that are dead at the dispatch head.

The proof object is the orbit's *shape*, a rule or an arm with a hole for the
kernel. One theorem per shape covers every member. Membership is a decidable
equation: `rule_o = fill shape κ_o`, or on the machine side
`arm_o = σ(fill shapeArm alu_o)`. This is one `decide` per opcode, not a lemma
battery.

- **On the bytecode side** the orbits already partly exist. `arith` covers 24
  opcodes, through `intArith`/`arithShape`. The census cost is concentrated in
  rules that were *not* merged into orbits: `EQK`, `TESTSET`, `FORLOOP`.
  - *Load orbit:* move, loadi, loadk, loadfalse, loadtrue, gettabupPrint, and
    lfalseskip (the last with pc+2).
  - *Conditional-jump orbit:* eq, eqk, eqi, cmpRR, cmpRI, test. All are
    `Step s (s.goto t)` with `condJump p s.pc b w.k`, and differ only in how
    `b` is computed.
  - *Unary orbit:* unm, bnot, not.
  - *Singletons:* for, call, jmp, testset, varargprep.
  - The result is about 8 shapes instead of 39 rules.
- **On the machine side (L-C1).** `lvm.c` generates the arms from macros:
  `op_arith(L, l_addi, luai_numadd)`, `op_arithK`, `op_bitwise`, `op_order`,
  `op_orderI`. *Recalled from memory: check `lvm.c` 5.4.7.* So gcc's code for
  `ADD`, `SUB`, `MUL`, `BAND`, `BOR` and `BXOR` should be the same instruction
  sequence up to one ALU instruction and register allocation.
  - The orbit theorem: `Sim shapeArm[f] rule[f]` for all `f` with an ALU
    refinement `alu ⊨ f`.
  - Any tail that gcc shares between arms (`vmbreak` → dispatch) is proved
    once as part of the shape.

**Core rules.**

- **L-C1 → `orbit_transport`**: `Sim armShape rule κ → (∀ o ∈ orbit, arm_o = σ_o (fill armShape alu_o) ∧ alu_o ⊨ κ_o) → ∀ o ∈ orbit, Sim arm_o rule_o`.
  One proof per orbit. Renaming invariance (σ) is proved once: the
  representation relation mentions no temporaries at the dispatch head.
- **L-B1/L-B2 → one theorem per shape**, not per rule: 8 instead of 39. This
  is weaker than abstraction 1's single theorem, but it keeps the inductive
  `Step` as the TCB.

**What it makes free.**

- **Bytecode side:** most `bc-rule-fanout` arms go. The marginal cost of a new
  member of an existing orbit is ≈0, as `ADDK` was once `intArith`
  existed.
- **The A1 arms (L-C1):** the forecast `a1-arm-sim` cost falls from one
  arm per opcode (54) to one per orbit (about 12–15 on the machine side,
  because MOD/IDIV/SHL/SHR call helpers).

**What it costs.**

- **It depends on gcc.** The payoff exists only if gcc really emits
  isomorphic arms, which is an empirical question about the ELF. If gcc
  specialises (for example `ADDI` with an immediate folded in), the orbit
  splits.
- **Kernel refinement.** Each orbit needs one generic "ALU instruction refines
  κ" relation.
- **Moving the TCB rules into orbits** is itself a refactor of `Step`: rules
  are grouped with a shape-parameter table *inside* the relation, like
  `intArith`.

**Theories.**

- *Known.* **Symmetry reduction** (verification of concurrent systems): quotient
  the state space by a symmetry group and check one orbit representative.
  - E. A. Emerson and A. P. Sistla, "Symmetry and model checking", FMSD 9 (1996).
  - C. N. Ip and D. L. Dill, "Better verification through symmetry", FMSD 9
    (1996).
  - I use only the quotient principle (orbit invariance of the property), not
    model checking.
- *Known.* **Orbit–stabiliser and Burnside's lemma** (group theory): obligations
  are counted per orbit. The number of distinct proofs is the number of
  orbits of the opcode set under the action.
- *Known.* **Serial homology** (developmental biology): repeated body parts built
  by one developmental program with local parameters, like radial petals or
  vertebrae. The analogy is the macro in `lvm.c`: one generator, several
  instantiations. This is a heuristic, not a result I would cite.

**Pilot.**

- **Bytecode side:**
  - H4 (string `LT`/`LE`) joins the conditional-jump orbit, since only the
    computation of `b` changes.
  - H3 (`LEN`) joins the unary orbit.
  - H1 joins the load orbit.
  - H2 (`CONCAT`) is a new singleton, with a range read.
  - Measure: the H cost is about one kernel each, plus CONCAT's full shape.
- **A1 arms:** the pilot's three (`ADD`, `EQI`, `FORLOOP`) are each orbit
  representatives, so they show only setup cost. To show the effect, add
  `SUB` and `BAND` as the "second petal" and report their *marginal* cost.
- **Smallest build:**
  - an `objdump` diff of the `ADD`/`SUB`/`BAND` arms of the ELF's
    `luaV_execute`, to test the premise before writing any Lean;
  - then the `condJump`-orbit theorem on the bytecode side (six rules into
    one).

**Seed.** *actinomorphy* (radial symmetry: one petal, rotated),
*silversides* (a school of identical fish), *sexennial* (periodic
recurrence, one period proved), *Sialis* (a genus: one type, many
individuals).

## 5. Tethered separation (the footprint triple as the joint between VM and machine)

**Idea.**

- **The VM semantics as small triples.** The VM semantics is *presented* in a
  separation logic over the abstract VM state. The resources are the
  register cells `R[i] ↦ v`, `pc ↦ n`, and an append-only `out` history.
  - Each rule is a small triple over its ports (abstraction 1's `ins`/`outs`):
    `{pc ↦ n ∗ ⊛_{i∈ins} R[i] ↦ vᵢ ∗ ⊛_{j∈wr} R[j] ↦ _} step {pc ↦ tgt ∗ ⊛ R[i] ↦ vᵢ ∗ ⊛ R[j] ↦ v'ⱼ}`.
  - The triples are built from two *local primitives* (read a cell, write a
    cell), so locality is compositional and proved once.
- **The tether.** The representation of VM states in machine memory is a
  **separation-algebra morphism** `τ`:
  - `R[i] ↦ v` goes to the 16-byte `TValue` at `base + 16·i` holding
    `encode v`;
  - disjoint cells go to disjoint memory, and `∗` goes to `∗`.

  *Recalled from memory: check the `StackValue`/`TValue` size and layout in
  Lua 5.4.7.*
- **The joint.** Frames transport along `τ`, so a machine-arm proof only has
  to establish the *image of the small triple*. The other 255 registers, the
  output and the heap come free by the frame rule on both sides.

**Core rules.**

- **L-B1 → the frame rule** of the VM logic. It is sound because every action
  is local by construction.
  - Footprint is exactly "the triple's precondition owns `ins`, and the
    postcondition changes only `wr`".
  - The "some edge" refinement: each edge is its own triple.
- **Definite initialisation → ownership.**
  - `Supported`'s must-mask at a pc is the set of register cells *owned* there.
  - Reading requires ownership.
  - "Stale entry values are unobservable" is the frame rule applied to cells
    no triple ever owns.
  - The dataflow fixpoint is frame inference over the CFG.
- **L-C1 → `tether_adequacy`** (one theorem):
  `(∀ o, ArmTriple o (τ (smallTriple o))) → VmSim Lay`.
  - It is proved once. It uses `τ`'s morphism property and the existing
    `Refine.Sim` pattern (`vm_refinement_of_sim`).
  - Per arm, what remains is an Iris or SL proof about *only* the arm's own
    footprint. The machine-level framework (`VsaIris`) is presumably already
    there, though I have not read it.

**What it makes free.**

- **The frame half of every A1 arm.** In the predecessor project,
  "everything else is unchanged" facts were a large share of the per-site
  work.
- **All `Step.sim` arms**, through the VM frame rule.
- **The definite-initialisation soundness proofs**, which become one frame
  argument.
- **Strings in the pilot suite:** the heap part of `τ` (a `TString` object for
  a `.str` value) is framed away in every arm that does not touch strings.

**What it costs.**

- **Two-level logic.** A VM-level separation algebra must be set up next to
  the machine-level one.
- **`τ` is only a partial morphism for strings.** Under Lua's string
  interning, two registers can share one `TString`, so the heap part is
  *shared*, not disjoint. It needs fractional or persistent ownership of
  string objects. This is the hard part, and exactly what H1–H4 exercise.
- **Output is a history.** The output resource must be append-only, a
  monotone resource, for `print`/`emit`.
- **Setup:** VM logic and frame rule, about 150 lines; `τ` and the morphism
  lemma, about 150; `tether_adequacy`, about 100.

**Theories.**

- *Known.* **Local actions and abstract separation logic** (PL): the frame
  rule is sound for any command that is a local action on a separation
  algebra. C. Calcagno, P. O'Hearn, H. Yang, "Local action and abstract
  separation logic", LICS 2007.
- *Known.* **Views** (concurrency): compositional reasoning is transported
  along a morphism from an abstract separation algebra to the concrete state.
  T. Dinsdale-Young, L. Birkedal, P. Gardner, M. Parkinson, H. Yang, "Views:
  compositional reasoning for concurrent programs", POPL 2013. `τ` is a view
  morphism.
- *Known.* **Shared read-only ownership for interned strings**: fractional
  permissions. J. Boyland, "Checking interference with fractional
  permissions", SAS 2003.
- *Novel*: using `Supported`'s must-analysis masks *as* ownership assertions,
  so that the dataflow fixpoint is an SL frame-inference certificate.

**Pilot.**

- **H1–H4 on the bytecode side:** each is one small triple, derived from the
  ports as in abstraction 1. The footprint cost is 0.
- **A1 arms `ADD`, `EQI`, `FORLOOP`:** measure each arm's proof with only its
  footprint cells in scope.
  - `ADD` owns 3 cells.
  - `EQI` owns 1 cell plus the next word (for the jump).
  - `FORLOOP` owns 4 cells.
  - Compare against the lines the incumbent spends on unchanged registers.
- **Smallest build:**
  - the VM-level separation algebra over `Nat ⇀ Value`, with the frame rule
    for read and write primitives;
  - `τ` restricted to integer and boolean values, where it is a true disjoint
    morphism;
  - `tether_adequacy` for a two-opcode toy (MOVE, ADD).

  Strings, where `τ` needs fractions, come second. They are the real test.

**Seed.** *teather* (the representation as a tether, where a pull on the VM
side is a pull on the machine side), *overmount* (the abstract heap mounted on
the concrete one), *ischiofemoral* (a joint that transmits motion between two
bodies: the triple is the joint), *unloosable* (the frame, which cannot be
touched).

## How the five relate

- **Stacking.** Abstraction 1 (ports) is the base layer.
  - 2 (poisoned stores) and 5 (tethered separation) both consume its static
    ports.
  - 2 turns them into a domain-theoretic monotonicity argument.
  - 5 turns them into a frame rule that transports to the machine.
- **3 is independent.** It addresses only the source-side cluster (L-A1).
- **4 is the fallback** if the TCB may not be restructured. It keeps an
  inductive `Step` and gets most of the savings through orbits, and it is the
  only one that also attacks L-C1 by counting orbits rather than by locality.
