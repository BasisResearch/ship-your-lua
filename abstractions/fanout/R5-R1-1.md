## A1. Odd collapse: the sticky shift as a monoid action, with round-to-odd invariance

### 1. Name
**OddCollapse** (`Lua/Num/Odd.lean`): the sticky right shift as an action of `(ℕ, +)` on `ℕ`, and rounding as a function that cannot see past an odd collapse.

### 2. The idea
`_FP_FRAC_SRS` is the only place a variable shift loses information. Give it one name and one closed form, with no `BitVec` and no shifts:

```
odd (k x : Nat) : Nat := x / 2^k ||| (if x % 2^k = 0 then 0 else 1)
```

This is **round to odd** at `k` dropped bits. Its low bit is a flag saying "inexact". With that name, the per-routine core needs only four algebraic facts, each proved once over `Nat`:

- collapses compose;
- adding an exact even value commutes with a collapse;
- a collapse over zero work bits is exact;
- rounding to nearest-even at precision `p` cannot tell `odd k x` from `x` if at least 2 bits stay below `p`.

The fourth is the round's open hand-off: "rounding after the sticky collapse equals rounding the exact value". It is a known theorem about round-to-odd, so it needs no per-routine proof. All 42 of `__adddf3`'s variable shifts become `odd k` or `<<< k` atoms. No rule is applied inside `omega`. The rules are rewrites, and their side conditions are linear once `Nat.log2 n` is generalised to an atom.

### 3. Core rules

**`round_odd` is the heart.** It is Boldo–Melquiond's round-to-odd theorem specialised to the project's `F64.round`. Proof sketch, once:
- `F64.shr n false false s` returns `(n / 2^s, bit, rest ≠ 0)`.
- `shr (odd k n) false false (s - k)` returns the same triple, given `s - k ≥ 2`.
- The quotient agrees by `Nat.div_div_eq_div_mul`.
- The round bit agrees because bit `s-1` of `odd k n` is bit `s-1` of `n` (`s - 1 ≥ k + 1`, so the OR'd low bit is below it).
- The sticky agrees because `odd k n % 2^(s-1-k) ≠ 0 ↔ n % 2^(s-1) ≠ 0`: the odd flag is set exactly when `n`'s lost bits were nonzero.
- `target (odd k n) (e+k) = target n e` because `log2 (odd k n) = log2 n - k` when `log2 n ≥ k + 1` (`Nat.log2_div_pow` plus the OR of a lower bit).

That makes 5 lemmas, all over `Nat` `/`, `%` and `2^`, with no variable `BitVec` shift.

### 6. Theories

- **Coarse-graining in statistical physics / the renormalisation group** (novel as an application): integrate out the low bits, keeping one "relevant" parity variable. `round_odd` says the rounding observable is a *fixed point* of the coarse-graining as long as the coarse scale is ≥ 2 below the observation scale. That suggests the right generalisation for the margin: a coarse-graining is admissible if it commutes with the observable.
- **Rounding hypotheses in numerical analysis**, e.g. Sterbenz's lemma (known: P. Sterbenz, *Floating-Point Computation*, 1974). `cancel_le_one` and `odd_exact` are its cousins: they mark where subtraction is exact.

## A2. Conjugate routines: a symmetry group acting on (routine, operand order, idiom), proved once per orbit

### 1. Name
**Orbits** (`Lua/Num/Sym.lean`, `Lua/Vm/Sim/Orbit.lean`): a finite group `G` of operand and result symmetries, its action on soft-float calls, comparison idioms and kernel leaves, and "prove the orbit representative".

### 2. The idea
L5-comm found four bit-exact symmetries:
- `add` commutes;
- `sub = add ∘ (flip b)`;
- `le(a,b) = −ge(b,a)` with unordered `2 ↦ −2`;
- `eq` commutes.

Treat them as one object, not four lemmas. The group has these generators:
- `swap`: `(a, b) ↦ (b, a)`;
- `flipB`: `b ↦ b ^^ 2^63`;
- `negR`: on comparison results, `r ↦ −r` with the unordered code relabelled.

Every soft-float call site, every comparison idiom and every kernel order leaf (`lt l i`, `le idx l`, `le l idx`) carries a `G` element as **data**, an element of a small closed type `Sym := Fin 8` **[size to fix: ⟨swap, flipB, negR⟩ has 8 elements]**.

Each routine has a stabiliser (add: `{1, swap}`) and a conjugator (`sub ↦ add` by `flipB`). Each comparison routine is `ι ∘ R.S` with `R.S` a function of `compare`. So one equation per orbit representative (`__adddf3`, `__ledf2`, `__eqdf2`) plus the action table gives every member's equation.

At level (b) this halves the add/sub pair. It also kills the `__ledf2`/`__gedf2` pair (67 paths each), *if* the machine-side conjugacy is supplied, as described next.

**The machine-side conjugacy is the hard part, and this abstraction names it honestly.** `Subdf3.F a b = Adddf3.F a (flipB b)` relates two *different* lifted DAGs (142 vs 133 nodes). Its proof is not free. It comes from both DAGs entering the *same* `_FP_ADD_INTERNAL` stage term after unpack: soft-fp's `_FP_SUB` flips `Y`'s sign (unless `Y` is NaN) and then runs the same macro **[recall: check `op-common.h` `_FP_SUB`; the semiraw form tests `Y_e == EXPMAX && frac ≠ 0`]**. So the conjugacy is stated at the *stage* level:

```
Adddf3.F = core ∘ unpack₂            (stage cut, A1/A4)
Subdf3.F = core ∘ (id × flipB') ∘ unpack₂
flipB' (NaN) = NaN ;  F64.add a NaN = qnan = F64.sub a NaN
```

The per-routine work is then only "this DAG is `core` after this unpack", a stage match. The semantic proof of `core` happens once.

### 3. Core rules

| law | rule | decided at a use site by |
|---|---|---|
| L5-comm (spec) | **`F64.act_spec`**: `∀ g : Sym, ∀ R ∈ {add, compare-family}, R.S (g • (a,b)) = g • R.S (a,b)`, from `F64.add_comm`, `F64.compare_swap` and a new `F64.sub_eq_add_neg` (one lemma; NaN case by `cls` of `neg`). | **computation**: `g` is a closed `Fin 8` literal, `decide` picks the table row |

### 4. What it makes free

### 6. Theories

- **Gauge fixing in physics** (novel as an application): choose one representative per orbit, here "lvm.c's operand order", so that the comparison (the observable) is computed only in that gauge. `idiom_act` is the gauge transformation of the observable.

## A3. Answer-deferred runs: run the shared prefix once over symbolic compare answers, then reconcile the machine's fork tree with the kernel's outcome tree

### 1. Name
**AnswerTree** (`Lua/Vm/Sim/AnswerTree.lean`): an arm's float path is a *decision tree over compare variables* `o₁ … oₙ : Option Ordering` (one per comparison call, plus one `Bool` per inline tag test). A *reconciliation* maps its leaves onto the kernel's outcome tree. The map and its correctness are checked by one closed `decide`.

### 2. The idea
Today the arm splits on the kernel outcome first and then runs the machine once per outcome. That causes both the 8.3k replay and the 10.3k wrong-polarity trial.

Invert it:
1. Run the machine prefix **once**, with each comparison call's result kept as the opaque `R.S a b`. By `SoftFloatSpec` plus L5-idiom, that is `enc_R (compare a b)`.
2. Name `oᵢ := compare aᵢ bᵢ` with `generalize`. Every machine fork then tests `ιᵢ(oᵢ)`, a closed function of a *finite* variable.
3. The machine path is a tree `T` over `o₁ … oₙ`. Each leaf has a straight-line suffix (generated segments) and lands in some state.
4. The kernel's float clause is also a function of the same comparisons. `forloopK`'s `Float.Model.le idx l` is `(compare idx l).any isLE` by the existing bridges, and `Float.Model.lt 0 st` is a function of `compare 0 st`. So the kernel is a function `K : Option Ordering^n → Outcome`.
5. **Reconciliation** is a closed statement: `∀ o ∈ (Option Ordering)^n, class (T.leaf o) = K o`. It is decided by `decide +kernel` over at most 4ⁿ points (FORLOOP: n = 2, 16 points; LT's longest path, n ≤ 4 or so: 256).

The fork polarity is never tried. At each machine fork, the run lemma for `beqz`/`bnez` on `ι(o)` goes *both* ways symbolically, as the tree's two children. The proof only `cases` the variable `oᵢ` when a fork needs it, so no closer of the wrong polarity is ever attempted.

When the f2i chain makes the machine fork 3–4 times where the kernel's `tointegerns` has one `Option`, the reconciliation map is many-to-one. The theory below names exactly that.

### 3. Core rules

| law | rule | decided at a use site by |
|---|---|---|
| L5-fork | **`run_tree`**: given `prefix : at_run s₀ ↦ s₁` (once), `T : Tree n`, and for every leaf `ℓ` a suffix run from `s₁[o ↦ ℓ]` to `s_ℓ` with `VmRel p c' (out (class ℓ))`, plus `recon : ∀ o, class (T.leaf o) = K o` → `SimArmOn o Q` on the float path. | the prefix: the existing kit run. `recon`: **computation** (`decide +kernel` over the closed product of `Option Ordering`, after the kernel's float leaves have been rewritten to functions of `o` by A2's `leaf_act`). Suffixes: the existing kit, one per *machine* leaf. |
| L5-idiom | each fork's guard is `ιᵢ (enc_R oᵢ)`, reduced by the closed idiom table (A2's or L5-idiom's) to `gᵢ oᵢ : Bool` | computation |

### 4. What it makes free
- **FORLOOP:** the 8.3k replay, the 10.3k polarity trial, and the 4 lines "kernel outcomes: step sign × bound (`rcases … <;> split <;> rename_i`)". `recon` replaces them over 16 points.
- **The 16 FORLOOP-like fields**, where §1.3 forecasts the budget overflow: SHL/SHR (22 paths), LT/LE (24), MOD (15), bitwise (13). Cost grows with machine leaves, not with leaves × kernel outcomes.
- **C5-f2i's many-to-one leaves** (L5-fork's refinement): handled by construction. The map `class` is not required to be injective.
- **LT/LE's error class** (non-number partner): one leaf class, and the order error is a leaf with no suffix (a stuck/error exit).

### 5. What it costs
- `run_tree` (≈60 lines) plus a `Tree` datatype whose leaves carry kit-run obligations.
- The kit's `at_run` must be able to **stop at a fork with a symbolic guard** and hand back both children, instead of choosing a polarity. That is a new kit entry point. It may be the bulk of the work, and I have not read the kit (forbidden), so its feasibility is unverified.
- The `generalize` of `compare a b` must happen *before* the prefix reaches the first fork, so the prefix must expose the call's result as `R.S a b` (it does through `f<k>_eq`, per round 5 §1.4).
- **What gets harder:** reading a failing `recon` (a `decide` that says `false`). It needs a counterexample printer, an `#eval` over the product, as a debugging tool.

### 6. Theories
- **Reduced ordered binary decision diagrams** (known): R. E. Bryant, "Graph-based algorithms for Boolean function manipulation", *IEEE Trans. Computers* C-35(8), 1986. The machine tree and the kernel are two diagrams over the same variables. Reconciliation is equivalence of the induced functions to `Outcome`, checked here by enumeration because the domain is tiny.
- **Gene-tree/species-tree reconciliation in phylogenetics** (known): M. Goodman et al., "Fitting the gene lineage into its species lineage", *Syst. Zool.* 28, 1979; R. D. M. Page, "Maps between trees and cladistic analysis", *Syst. Biol.* 43, 1994. The machine fork tree is the gene tree and the kernel outcome tree is the species tree. A machine fork mapped to no kernel fork is a "duplication" (the f2i chain's extra `__eqdf2`/`__gedf2`/`__ledf2` forks). The LCA mapping is exactly the `class` data. The duplication count gives a measure of how far an arm's machine and kernel trees diverge, usable by the gate.
- **Staged computation / partial evaluation** (known): run the static part (the prefix) once, and residualise on the dynamic part (the answers). N. D. Jones, C. K. Gomard, P. Sestoft, *Partial Evaluation and Automatic Program Generation*, 1993.

## A4. Layout quotient: one summary per chain *modulo* code layout, with a closed CFG certificate per site

### 1. Name
**LayoutQuotient** (`Lua/Vm/Sim/Layout.lean`): a canonical, polarity-free control-flow graph for an inlined chain, and the theorem that any site whose machine CFG is isomorphic to it, up to branch polarity and fall-through placement, inherits the chain's summary.

### 2. The idea
- L5-chain's 20 `luaV_flttointeger` sites come in 6 layouts. They differ only in:
  - `beqz`/`bnez` and `bgez`/`bltz` polarity, so which successor is the fall-through;
  - where the unconditional `j` sits.
- GCC's block placement did this, not the C source.
- Prove the chain summary **once**, over a canonical graph `G_chain(mode)`. That graph has:
  - nodes: call nodes (`floor`, `__eqdf2`, `__gedf2`, `__ledf2`, `__fixdfdi`, and `__adddf3` in the `F2Iceil` mode);
  - two-armed *test* nodes `test ι succ_true succ_false`, with `ι` from the closed idiom table;
  - exit nodes `some n` / `none`.
- Per site, the generator emits **data**, not a proof: a node map from canonical nodes to machine addresses. For each test node it also emits one polarity bit, saying whether `bnez` means "true" or "false".
- One closed `decide +kernel` checks the certificate against the fixed image bytes. The words at those addresses are ground (`Lua/Vm/Image.lean`).
- The theorem `summary_of_iso` then transports the chain summary to the site.

Each site gives a lemma "from the chain entry at `addr`, with float `f` in `fa0`, the machine reaches `exit_some` with `a0 = n` iff `tointegerns mode f = some n`, else `exit_none`". It is used at the arm like a callee summary keyed by entry pc (an existing concept). It also composes with A3: the whole chain becomes **one** leaf class in the arm's tree, not 3–4 forks. That collapses A3's many-to-one map back to one-to-one.

### 3. Core rules

| law | rule | decided at a use site by |
|---|---|---|
| L5-chain | **`chain_summary (mode)`**: over the canonical graph, proved once per mode (`F2Ieq`, `F2Ifloor`, `F2Iceil`) from `Floor.S` (a new named premise beside `SoftFloatSpec`), `Eqdf2.S`, `Gedf2.S`, `Ledf2.S`, `Fixdfdi.S`, the closed idiom table, and the range constants `-2^63 ≤ f < 2^63` as `F64` literals. | proved once; its internal case split is an A3 `recon` over the 3–4 compare answers (`decide`) |
| (new) layout invariance | **`summary_of_iso`**: if `Cert.check img site = true` then the site's machine run refines the canonical graph's run, hence `chain_summary` holds at `site.entry`. `Cert.check` decodes each mapped address (`decodeW`), checks the opcode class (`jal floor`, `beqz`/`bnez` on `a0`, `j`), and checks that successors match up to the polarity bit. | **computation**: closed `decide +kernel` over the certificate and the ground image bytes. No symbolic data enters `check`. |
| L5-idiom (polarity) | the polarity bit flips `ι` to `¬ι`, which is in the closed idiom table | computation |
| (new) register discipline | the certificate also lists the register carrying `f` across calls (`s`-register spills, the 7 spilled/moved sites). `check` verifies the move/spill instruction words, and the canonical graph's `Loc` is renamed. | computation; spills in the frame use the existing memory-frame tools (`FrameMeta.memFrame_of_chain`) |

**Symbolic data.** `f` stays symbolic in `chain_summary`. `Cert.check` sees only addresses and ground words.

### 4. What it makes free
- **C5-f2i:** all 20 sites in 13 fields (bitwise 11, LT/LE), one certificate each (generated data), with 3 mode theorems total.
- The bitwise family's (BAND…SHRI, BNOT) 13–22 float paths shrink to "chain leaf + MMBIN leaf + int-ALU leaf". That brings SHL/SHR (22 paths) back under the budget by structure, not by heartbeat tuning.
- **FORPREP's `forlimit`:** it uses `luaV_tointegerns(lim, F2Ifloor/F2Iceil)` (inlined or called **[recall: check whether `forlimit`'s call is inlined in this build]**). If inlined, it is one more certificate.
- **The 2 non-chain `floor` sites** (`luai_numidiv`, `luai_nummod`) are a single-node certificate on the same mechanism, so they come free.

### 5. What it costs
- `Cert`, `Cert.check` and `summary_of_iso` (≈150 lines). The simulation proof of `summary_of_iso` is a generic "block graph homomorphism preserves runs" lemma. That is general but non-trivial: each edge needs the per-block segment lemma, which already exists generated (`Lua.Vm.Arms.seg_*`).
- `chain_summary` per mode (≈30 lines each, using A3's `recon`).
- `Floor.S` premise plus its level (b) (libm `s_floor.c`, bit masks) **[recall: newlib's `s_floor.c` is fdlibm's, integer masking on the high/low words]**.
- **Risk:** the 6 layouts may differ in more than polarity and placement, e.g. a shared tail merged into a neighbour's block (cross-jumping). A cross-jumped tail breaks the 1-1 node map. The fix is a node map that is a graph *homomorphism* onto the canonical graph, not an isomorphism. That is still decidable, but `summary_of_iso` must then be stated for homomorphisms (harder simulation proof).

### 6. Theories
- **Dependency grammar and linearisation** (known): L. Tesnière, *Éléments de syntaxe structurale*, 1959. A sentence's meaning lives in its dependency tree; word order is a linearisation, freer in some languages. The chain is the dependency tree and the 6 layouts are its linearisations. Polarity flips are like active/passive alternations: one meaning, the arguments in the other slots.
- **Binary diffing by CFG isomorphism** (known): T. Dullien, R. Rolles, "Graph-based comparison of executable objects", SSTIC 2005. Functions are matched across builds by CFG structure, regardless of layout.
- **Pettis–Hansen code positioning** (known, the cause): K. Pettis, R. Hansen, "Profile guided code positioning", PLDI 1990. The quotient undoes exactly this transformation family.
- **Translation validation** (known): A. Pnueli, M. Siegel, E. Singerman, "Translation validation", TACAS 1998. The certificate is a per-instance witness checked by a fixed checker, not a per-instance proof.

### 7. Pilot
- **Held-out LT:**
  - `LTintfloat`/`LTfloatint` call `luaV_flttointeger(f, &fi, F2Iceil/F2Ifloor)` in the `!l_intfitsf(i)` branch;
  - if inlined in `luaV_execute` (`idioms.out` counts LT/LE among the 13 fields), that is 2–4 certificates in LT;
  - measure that LT's proof refers to the chain as one leaf.
- **Held-out SUB, FORPREP:** SUB has no chain (the control). FORPREP has one only if `forlimit` is inlined.
- **Refactor FORLOOP:** none (no chain).
- **Smallest thing to build:**
  - `Cert` plus `Cert.check` for a *single* site;
  - `chain_summary .eq` for that site's mode;
  - `summary_of_iso` for isomorphisms only.
  - Then a second site in a *different* layout reuses `chain_summary` with only a new certificate. That is the cost test: the second site costs 0 hand lines.

### 8. Seed
The repeat `6lD6` (at `…1lDyHD6Vo…` and again at `…Vl6lD6bm…`): the same short word in two places and two framings. That is the 6 layouts of one chain, the same meaning in different linear positions.

## A5. Domain-parametric class views: one arm template per kernel combinator, instantiated at a number domain, with classes as named views

### 1. Name
**ClassViews** (`Lua/Vm/Sim/Views.lean`): for each kernel combinator `κ` and operand predicate `Q`, a computed inductive `κ.Class Q regs` whose constructors are L5-read′'s classes. Each constructor's fields are **views**, named-field structures that bundle a register's kernel value, machine tag and machine payload. A *number domain* record `NumDom` (int, float) parameterises the arm template, so the `opArith`/`docondjump` hand-off is written once (L5-share′).

### 2. The idea
FORLOOP's 48% (14 of 29 lines) are:
- refuting non-float constructors on registers the machine never tests;
- bundling the tag and model per register.

Both are the same missing concept: *what a kernel class says about the registers*.

**Views.** A view is the projection of `VmRel` onto one register under a known class:

```
structure FltView (c : Config) (r : Nat) (x : Float.Model) : Prop where
  kern  : regs r = .flt x _
  tag   : readByte c (base c + 16*r + 8) = 19      -- LUA_VNUMFLT, from Layout.lean
  bits  : readU64 c (base c + 16*r) = F64.ofModel x
```

with `IntView` alike. (Offsets come from `Lua/Vm/Layout.lean`, never hand-written; the `16*r+8` above is schematic.)

**Classes.** The classes are computed from the kernel's clause list. `κ.classify : Q regs → κ.body regs = some o → κ.Class Q regs` is proved **once per combinator**, by the combinator's definition, not per arm. Each constructor carries views for exactly the registers that class reads. FORLOOP's `back`/`exit` constructors carry three `FltView`s. That is the kernel inversion L5-read′ asks for, so the two untested registers' tags come from `kern` plus `VmRel`, not from the machine.

**Domains.**

```
structure NumDom where
  V    : Type            -- Int64 / Float.Model
  View : Config → Nat → V → Prop
  tag  : UInt8           -- 3 / 19
  leaf : BinOp → V → V → Option V   -- fastArith / δ's float leaf
  call : MachineLeaf     -- inline ALU segment / call node + R.spec
```

`arm_opArith (D : NumDom)` is the arm template over `D`, proved once. `D := intDom` reproduces the existing int arms, as a regression check. `D := fltDom` gives the float arms. Mixed int/float partners are a `conv` edge in `NumDom` (`__floatdidf`/`__floatsidf` with their `spec`).

### 3. Core rules

| law | rule | decided at a use site by |
|---|---|---|
| L5-read′ | **`κ.classify`**, one per combinator (`opArith`, `docondjump`, unary/`setR`, `bitwiseRK`, `forloopK`, `forprepK`): from `Q` and `body = some o` to a `Class` constructor with views | **syntactic**: `cases (κ.classify hQ hb)`, one `cases` with one goal per class. The constructors' set is fixed by the combinator, so no `cases v0 <;> cases v1`. |
| L5-read′ (views) | **`VmRel.view`**: `VmRel p c s → regs r = .flt x n → FltView c r x` (and `IntView`), one lemma for all registers and arms | syntactic (applied by `classify` itself) |
| L5-share′ | **`arm_opArith D`**, **`arm_docondjump D`**: the arm template over a number domain. The per-arm content is the `MachineLeaf` (which segment/call) and the class-to-leaf table. | syntactic instantiation; the machine leaf is generated data (call node address plus `spec` name) |
| L5-comm, L5-idiom | consumed through `NumDom.call`'s statement in lvm.c's order (A2's table, if adopted) | computation |

**Symbolic data.** All values are symbolic. The classes are finite, fixed per combinator, and independent of the values.

### 4. What it makes free
- **The 14 of FORLOOP's 29 lines** (reads, refutation, bundle) become one `cases` with views.
- **O-pay** (9/10 of the sample) and **O-inv** (4/10) everywhere.
- **C5-handoff:** the ≈10 forecast per-shape hand-offs become ≈6 combinator templates. Since the int arms instantiate the same template, `at_fcond`/`at_farith` are deleted, not joined.
- **The 8 ADDI-like and 4 all-float fields:** `opArith fltDom` with partner classes `{flt, int (conv), MMBIN}`.
- **The 3 GEI-like fields:** `docondjump fltDom` with an immediate (one class).

### 5. What it costs
- `NumDom`, the views, and 6 `classify` lemmas (≈25 lines each; the kernel's clause list is the proof).
- The template proofs (≈40 lines per combinator) and the **re-proof of the int arms through the template**. That could be skipped, keeping them as they are, at the price of two parallel routes, which violates "duplication is a signal".
- **Harder:** the int arms' inline ALU segments and the float arms' call nodes differ in shape (straight-line versus a `jal` plus summary). `MachineLeaf` must be a sum type, and the template must handle both in one proof. The run lemma per alternative is where it could break.
- FORLOOP and FORPREP do **not** share with their int clauses (L5-share false). They get their own `classify` but no domain parametricity.

### 6. Theories
- **Relational parametricity** (known): J. C. Reynolds, "Types, abstraction and parametric polymorphism", IFIP 1983; P. Wadler, "Theorems for free!", FPCA 1989. Each template is stated over an abstract number domain, and its correctness for each instance comes from one proof.
- **Typed assembly language** (known): G. Morrisett, D. Walker, K. Crary, N. Glew, "From System F to typed assembly language", TOPLAS 21(3), 1999. The machine reads the untagged payloads because the *type* (here the kernel class) is known. The view is that type's interpretation.
- **Bioisosteric replacement in medicinal chemistry** (known: G. A. Patani, E. J. LaVoie, "Bioisosterism: a rational approach in drug design", *Chem. Rev.* 96, 1996). Swap a functional group (inline integer ALU) for another (soft-float call) that keeps the scaffold's binding shape (the dispatch prefix and the store/jump tail). The `NumDom` interface is the pharmacophore, the shape that must be preserved.
- **Updatable database views** (known: F. Bancilhon, N. Spyratos, "Update semantics of relational views", TODS 6(4), 1981): a view is a named projection with a fixed complement. Here the complement is the rest of `VmRel`, carried untouched.

### 7. Pilot
- **Held-out SUB** (`FltBC`):
  - `cases (opArith.classify …)` gives 4 classes: flt/flt, flt/int, int/flt, MMBIN;
  - each is `arm_opArith fltDom` with `call := __subdf3` and `conv := __floatdidf` on the int side.
  - Target ≤ 6 lines, no new hand-off.
- **Held-out LT** (`FltAB`):
  - `docondjump.classify` gives bool with partner ∈ {flt, int} plus the order error;
  - the int partner's machine leaf is itself a tree (`l_intfitsf` and the f2i chain), so LT also needs A3/A4. ClassViews handles only the register side.
- **Held-out FORPREP** (`ForCoerce`):
  - `forprepK.classify` gives `float-loop-enter`, `float-loop-skip`, `step-zero error`, `coerced int limit` (from `forLimit`'s `tointegerns`), and `tonumber` failure.
  - The `tonumber?` of a string partner is the callee (`luaV_tonumber_` → `strtod`). Its view is a callee summary, not a register view.
- **Refactor FORLOOP:** `forloopK.classify` gives `back x₀ x₁ x₂ (3 FltViews)`, `exit (3 FltViews)`. Lines 1–14 become one `cases`. Target 29 → 15 alone, ≤ 10 with A3.
- **Smallest thing to build:** `FltView`, `VmRel.view`, `forloopK.classify`. Refactor FORLOOP with only those, and measure the 48%.

### 8. Seed
The doubled `JJ` in `GwdzJJios` (one shape, two letters: the int and float instances of one template) and the digit cluster `N43U4X7` (3 and 4: FORLOOP's 3 classes and `opArith`'s 4).

## Composition and an order of building

These compose:
- **A5** (views and classes) gives the leaves.
- **A3** (answer trees) gives the forks between them.
- **A4** (layout quotient) folds the f2i chain into one leaf.
- **A2** gives the operand-order and idiom normalisation, used by A3's `recon` and by level (b).
- **A1** closes the level-(b) core.

The smallest combined pilot, with the largest measured win: **A5's `forloopK.classify` plus A3's `run_tree` on FORLOOP** (the 48% of lines and the 31% of heartbeats). It needs no generator change and no level (b). After that, A1's `round_odd` over `Nat` alone, as the cheapest test of whether level (b) is tractable.
