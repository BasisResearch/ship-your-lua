## 1. Scan folds with prefix acceleration (cursor loops as list catamorphisms)

### Idea

Every loop that the remaining arms and their callees meet (ROUND-4 §1b.2) moves one or two **cursors** over a list of fixed-width chunks. At each chunk it either continues with an updated accumulator or exits.
- The nil fill and the slot copy are *write* scans: cursor `a5`, stride 16, one store per element.
- `memcmp`, `strlen` and `strcmp` are *read* scans: cursors `a0`/`a1`, stride 1 or 8, no stores.
- `l_strcmp` is a scan over the `'\0'`-separated pieces of two strings, and its body contains calls.

The kit's loops index the induction by a ghost `Nat`. This proposal makes the ghost the **consumed prefix of a list**. The invariant is then always the same sentence: "the cursors are at `base + stride·k`, and the accumulator is `foldUntil f init (take k xs)`". A loop supplies no invariant, only its *step function* `f : α → Chunk → Next α X`.

The loop's post is a pure fold over the list, so loops compose by list algebra rather than by Hoare logic:
- a loop that exits into another loop (`memcmp`'s word loop into its byte loop) is `foldUntil` over `xs ++ ys`;
- a word-at-a-time loop is the byte loop *accelerated*: it skips 8-byte chunks on which the byte step would only have continued.

### Core rules

Let a cursor loop be `CLoop := { head : Nat, stride : Nat, cursors : List (Reg × Nat), endReg? , pins : α → Pins, mem : α → Mem }`. Here `pins` and `mem` are read off `(k, acc)`, as in L4-loop′. One proved rule turns each law into a theorem.

**L4-loop′ → `cloop_fold`, proved once over `SegSt`.**

```
theorem cloop_fold (L : CLoop) (xs : List Chunk) (f : α → Chunk → Next α X)
    (body : ∀ k acc, k < xs.length →
      Triple (SegSt L.head (L.pins k acc) (L.mem k acc))
        (fun c => match f acc xs[k] with
          | .cont acc' => SegSt L.head (L.pins (k+1) acc') (L.mem (k+1) acc') c
          | .exit x    => L.Exit x c))
    (hend : ∀ acc, Triple (SegSt L.head (L.pins xs.length acc) …) (L.Exit (L.atEnd acc))) :
    Triple (SegSt L.head (L.pins 0 init) (L.mem 0 init))
      (L.Exit (foldUntil f init xs))
```

- The measure is `xs.length − k`. It is internal to the rule, so no loop names it.
- A rotated loop is covered because `L.head` is the DFS head, not the source-order top. `memcmp`'s byte loop is entered by `j 0x800361c0` into the middle.
- A mid-body exit is covered because `body`'s post is a match on `f`. `udiv_norm` fits this way.
- The body Triple is a *single* `kit_run` over the generated body segments at a symbolic `k`. It is the one proof obligation a loop has. The current per-loop invariant plus recursion is gone.
- **Write scans** are the case `α = Unit` with `mem k = foldl (store at cursor) M0 (range k)`.
  - The nil fill is one instance, parametric in the head pc, the cursor/end registers and the store offset (−8 or 0). That one instance covers all five occurrences (LOADNIL, RETURN0, RETURN1, `luaD_precall`, `luaD_poscall`).
  - The slot copy is the same with `mem k = foldl copy …`.

**Loop-to-loop → `foldUntil_append`, a pure list lemma.** It states:

`foldUntil f a (xs ++ ys) = match foldUntil' f a xs with | .exit x => x | .cont a' => foldUntil f a' ys`.

`memcmp`'s word loop reaches `0x800361ac` on a mismatch or on a remainder below 8. That re-enters the byte loop on the rest of the list, so the two loops compose through this lemma and `Triple.seq`.

**Word-at-a-time → `accel_sound`, proved once per *kind* of scan, not per loop.** If the word step `g` on a chunk `w = b₀…b₇` satisfies `g a w = .cont a ↔ ∀ i, f a bᵢ = .cont a`, and on `.exit` it hands the same 8 bytes to the byte loop, then:

`byteFold f a (w ++ rest) = (if g a w = .cont a then byteFold f a rest else byteFold f a (w ++ rest))`.

There are three kinds, each with one bit-level lemma:
- **equality** (`memcmp`: `ld; ld; bne`): `x = y ↔ ∀ i, byte i x = byte i y`;
- **has-zero** (`strlen` mask `0x7f7f…7f` built at `0x8003b77c`, `strcmp` mask loaded from `mask` at `0x8005c620`):
  `((x & m) + m) | x | m = −1 ↔ ∀ i < 8, byte i x ≠ 0`.
  This is the one hard bit lemma: by hand, no `bv_decide`, 64-bit, per byte lane. **[check: that the carry argument closes per lane without blowing up]**;
- **both**, for `strcmp`'s aligned loop: equal and has no zero.

**Trailing garbage → `scan_prefix_only`.** `strcmp` and `strlen` read whole words past the terminator (the model's `readByte` is total, `getD 0`). The step functions are defined on *memory chunks*, not on `s`. The lemma `foldUntil f a (chunks m p) = foldUntil f a (chunks (s ++ [0]))` holds whenever `f` exits at the first zero and `BytesAt m p (s ++ [0])`. It is proved once for the zero-exit kinds. This is what C-str needs from `TStringRepr`: the bytes and the terminator, nothing more.

**`l_strcmp`'s chunk loop (`0x8001a760`) → `lexLt_splitOn`.** It is `cloop_fold` with a body that contains two `strlen` calls and one `strcoll` (= `j strcmp` at `0x80036374`). The list is `splitOn 0 s` zipped with `splitOn 0 t`, and the fold law is the pure lemma

`lexLt a b ↔ lexChunks (splitOn 0 a) (splitOn 0 b)`,

proved once on lists, against `lexLt` in `Semantics.lean`. The exits correspond to the code as follows:
- `strcoll ≠ 0` is the exit at `0x8001a7a8`;
- `len = strlen` is `snez (s2 − s4)` at `0x8001a7cc`;
- `s2 = s4` is `−1` at `0x8001a7d8`.

### What it makes free

- **C-loop.** The four hand inductions go: `muldi3_loop`, `loadnil_loop`, `udiv_norm` and `udiv_div` each become a `cloop_fold` instance with a body `kit_run`.
  - The 5 nil fills and the 2 slot copies become one parametric instance each.
  - Every read-only scan (`memcmp` ×2, `strlen` ×2, `strcmp` ×2, `l_strcmp` ×1) becomes an instance plus at most one `accel_sound` kind.
- **C-str, the callee half.**
  - `memcmp`'s summary: `a0 = 0 ↔ take n s = take n t`.
  - `l_strcmp`'s summary: `sign = lexLt`.
  - Both follow from `BytesAt (s ++ [0])` alone, and neither needs a hand invariant.
- **Most of the stdio chain's 33 bottom-tested, single-exit loops.** The other 60 need multi-exit `Next`, which `cloop_fold` has.

### What it costs

- **Setup.** `CLoop`, `cloop_fold`, `foldUntil` and its append lemma come to about 120 lines. Then `accel_sound` with the three bit kinds, about 150, most of it the has-zero lemma, and `lexLt_splitOn` at about 60. These are estimates.
- **What gets harder.**
  - `pins : α → Pins` must evaluate under `kit_run` with a symbolic `k`. Cursor values such as `p + 8*k` need the `pins_of` fallback (`pin_eq … (by kit_val)`). That is obstruction 3 of KIT.md again, now on every iteration.
  - Unrolled bodies, such as `strcmp`'s 3 words per iteration (`0x8003b938..0x8003b99c`), need a step function over a 24-byte chunk with 6 exits. That is mechanical but long.
  - Alignment: `strcmp` takes the word path only if `(a0|a1)&7 = 0`. Strings at `ts+24` are aligned if `ts` is 8-aligned, and nothing in `ValRepr` says that today. Without it, both paths are proved, which `cloop_fold` makes cheap but not free.

### Theories

- **Catamorphisms and fusion**: Bird, *An introduction to the theory of lists* (1987); Meijer, Fokkinga and Paterson, *Functional programming with bananas, lenses, envelopes and barbed wire* (FPCA 1991). Known. The loop's post is a fold, and composition is fusion and append.
- **The third homomorphism theorem**: Gibbons, JFP 1996. Known **[check: exact venue]**. A word step and a byte step agree because the function is a list homomorphism over chunk boundaries.
- **SWAR, "multiple byte processing with full-word instructions"**: Lamport, CACM 1975. Known **[check: year and venue]**. This is the has-zero mask trick, as a lemma instead of a folklore identity.
- **Novel here:** stating the loop rule over `SegSt` families indexed by a list prefix, and treating word-at-a-time scanning as *acceleration of a stuttering simulation* (`accel_sound`) instead of as a separate loop.

### Pilot

The smallest thing to build:
1. `cloop_fold` plus `foldUntil_append`.
2. Refactor `loadnil_loop` as a write-scan instance. The target is the 25 lines down to ≤ 8, and the nil-fill instance should state RETURN0's loop at `0x8001c2f4` for free.
3. `memcmp_sum` from two instances, `foldUntil_append` and the equality `accel_sound`.

That is enough for **EQ on two long strings** once abstraction 5 supplies `BytesAt` on the machine memory. **LT on strings** adds the has-zero kind, the `strlen`/`strcmp` instances and `lexLt_splitOn`. FORPREP, IDIV and MODK are untouched; they have no loops.

### Seed

The doubled letters (`TT`×2, `xx`, `qq`, `AA`, `QQ`) gave two cursors in lockstep over equal-width chunks. The repeated `28` gave a pattern recurring at a larger stride, which became word-at-a-time scanning as acceleration of the byte scan.

## 2. Callee-saved parametricity: summaries quantified over the untouched frame

### Idea

A helper summary today is stated against a frame pin list (`HFrame`, `KFrame`) that names the caller's registers. Typed assembly language solves the same problem with polymorphism. The callee's type is `∀ρ. {s0..s11 : ρ, ra : ret} → {s0..s11 : ρ, a0 : result}`. Because the callee cannot inspect ρ, it must return it unchanged, and the caller instantiates ρ with whatever it holds, so no frame is ever written.

Here that becomes:
- every summary is **∀ ρ : PinList with `ρ.regs ⊆ calleeSaved ∪ {sp, gp, tp}`**;
- every memory frame is **∀ M, outside the callee's footprint**;
- the footprint is the ABI's (`[sp − frame, sp)`) plus any out-parameter pointed to by an argument register, for example `a1 = sp+40` for `luaV_tointeger`.

At a call site, ρ is *computed*: `pins.filter (·.reg ∈ calleeSaved)`. That filter reduces by `decide` on register names, and the live set never has to be compared with it. Dead pins (`s6`/`s10` at MUL and FORPREP) simply ride along.

### Core rules

**L4-call → `SegSt.callABI`, proved once.**

```
theorem SegSt.callABI (S : HelperSum f)        -- args ↦ results, footprint fp
    (hjal : jalAt pc f.entry) :
    ∀ pins M, Triple (SegSt pc pins M)
      (fun c => ∃ r M', S.post (pins.args) r ∧
         M' =[¬ S.fp (pins.args)] M ∧
         SegSt (pc+4) (S.results r ++ pins.filter calleeSaved?) M' c)
```

**Per-helper proof of the ∀ρ summary → `HelperSum.of_wrChain`.**
- The ∀ρ form is obtained *once per helper* from its generated segments with `FrameMeta.abiFrame_of_wrChain`. CLAUDE.md lists that as "ABI register frame … one `decide`". Its memory side comes from `FrameMeta.memFrame_of_chain`.
- So the parametric part of each summary costs one `decide` over the helper's write chain, not a pin list.
- Nested calls (`__moddi3 → __udivdi3`, returning through `t0`) compose by `callABI` inside `callABI`: ρ for the inner call is the outer callee's own saved set.

**L4-split (the frame half) → `ArmPre := ∃ ρ, …`.** A split at a return is stated as `∀ ρ M', SegSt ret (results ++ ρ) M' → …`, with the needed values pulled by `pins_of` lookups on ρ. The *register set* is never written. (The *values* still need naming at a split; abstractions 3 and 4 remove the split itself.)

### What it makes free

- **C-call, as measured in §1b.4.**
  - `divFrame` goes, together with the `s3`/`s4`/`s10` parameters it takes only to be MOD-shaped.
  - IDIV reuses `s3`/`s4` as operand temporaries (`ld s4,0(s10)`; `ld s3,0(a5)` at `0x8001f720`). Under ∀ρ that reuse is invisible, because the summary never asks what `s3` means.
  - The second helper in IDIV, `__moddi3` at `0x8001f964` on the sign-mismatch path after `__divdi3`, is a second `callABI` with no new statement.
- **FORPREP's two calls.** `luaV_tointeger` writes its out-parameter at `sp+40`, which `fp (a1)` names, so `bleachF`'s C-frame write is the footprint, not a special case. `__udivdi3` follows at `0x8001f86c`.
- **Future runtime-shape callees.** Their summaries get the same ∀ρ head. Only the footprint grows.

### What it costs

- **Setup.** `HelperSum`, `callABI`, and an `of_wrChain` bridge from the copied `FrameMeta`, about 100 lines. The four existing helper summaries must be restated ∀ρ: a refactor of `muldi3_sum`, `udivdi3_sum`, `moddi3_sum`, `equalobj_sum` and `toint_sum`, each a few lines if `abiFrame_of_wrChain` fits the generated helper segments. **[check: those segments' write chains are first-order enough for that `decide`]**
- **What gets harder.**
  - The generator's liveness fixpoint for helpers (`HELPERS`, `SUMMARISED`) becomes redundant on the register side, though it is still useful as a check.
  - Footprints that depend on arguments (out-parameters) need the footprint to be a function of `args`, which is one more field of `HelperSum`. That is still one rule, not one contract per helper.
  - `EqCtx`, the callee's *precondition* (9 address facts), is untouched by this abstraction. Abstraction 3 closes those facts by label.

### Theories

- **Typed assembly language**: Morrisett, Walker, Crary and Glew, *From System F to typed assembly language* (TOPLAS 1999). Known. Callee-saved registers are type variables of the code pointer's type.
- **Parametricity**: Reynolds 1983; Wadler, *Theorems for free!* (FPCA 1989). Known. The frame lemma is the free theorem of the ∀ρ summary.
- **Databases, the view update problem with constant complement**: Bancilhon and Spyratos, TODS 1981. Known **[check: year]**. A call is an update through a view (args to results). The complement (ρ, `M` outside `fp`) is constant, and the caller's state is reassembled from the view and the complement. That is the frame rule without naming the frame.
- **Novel here:** deriving the ∀ρ form of each summary by one `decide` on the generated write chain, so polymorphism costs nothing per helper.

### Pilot

The smallest thing to build:
1. `HelperSum`, `callABI`, and `udivdi3_sum` restated ∀ρ.
2. Refactor `modk_call`. The target is 6 lines down to 2: no `divFrame`.
3. **IDIV**'s `__divdi3` path and its `__moddi3` correction, with no frame lines.

**FORPREP** needs `toint_sum` restated with the `sp+40` footprint. It still exceeds the budget without abstraction 3 or 4.

### Seed

The mirrored ends (`MtJ9G…da9N`) and the near-palindrome `IaKGak` gave the idea of a call and its return mirroring each other, with what passes through the middle coming back unchanged.

## 3. Labelled regions, separated by reflection (Burstall–Bornat memory for the kit)

### Idea

The budget is spent on **arithmetic proofs that two addresses differ** (ROUND-4 §1b.3):
- 341 slow `omega` runs for 27 instructions, about 60% of tactic time;
- the cost multiplies by about 4 per disjunctive `Ranges` fact;
- the rest is whnf of `writeMap8` chains over `Nat` addresses.

Each such fact is re-proved at each read, but it is really a fact about **which object** the two addresses belong to, and there are about 10 kinds of object. The proposal is to give every address a **region label** and to prove disjointness once, as a table over labels. The labels are:
- `slot j`, `kslot i`, `cframe o`, `savedpc`, `ltop`, `ciF o`, `LF o`, `cstack`, `strObj x`, `text`, `rodata`.

Separation then becomes `decide` on a finite label pair, not `omega` on `Nat`. Memory inside a run becomes a **first-order log** `List (Rgn × off × width × val)` over `mo`, not a `writeMap8` chain. Read-over-write then reduces by label comparison, `List.find?` over decidable label inequality, which CLAUDE.md's law 1 asks for in "reflect on the first-order write log; never whnf the Sail state".

The disjunctive facts (`ci_sep`, `L_sep`, `k_sep`, `L_sep_ci`) are consumed **once**, inside the soundness proof of the label table. A use site never sees a disjunction.

### Core rules

**L4-split's cost precondition → `Rgn.sep_sound`, proved once from `Ranges`.**

```
inductive Rgn | slot (j : Nat) | kslot (i : Nat) | cframe | savedpc | ltop
              | ciF | LF | cstack | strObj (x : Nat) | text | rodata
def Rgn.addr (w : RelPtrs) : Rgn → Nat        -- base address
def Rgn.size (p) : Rgn → Nat
def Rgn.sep : Rgn → Rgn → Bool                -- the table; slot j vs slot j' is j != j'
theorem Rgn.sep_sound (hr : Ranges p w) (h : r.sep r' = true)
    (ho : o < r.size p) (ho' : o' < r'.size p) : r.addr w + o ≠ r'.addr w + o'
```

There is one `omega` per pair of *kinds* (about 50), inside one proof. The case split on each disjunctive `Ranges` field happens there, once.

**Read-over-write → `rd_log`.**

`rdN (applyLog mo log) (addr r o) = (log.find? (overlaps r o)).elim (rdN mo (addr r o)) val`, with `overlaps` decided by `Rgn.sep` and offsets.

**Address recognition → `addrOf`.** A reflective recogniser `addrOf : AddrExpr → Option (Rgn × Nat)` sends the generated segments' address terms to labels. Its forms are `w.base + 16*j + o`, `w.sp + o` and `w.ci + o`. It is proved sound once.

`kit_disch`'s separation goals become `Rgn.sep_sound hr (by decide) (by decide) (by decide)`.

**L4-str's precondition → `strObj x` is `sep` from every `Win` label by the table.** Its soundness needs one fact per represented string: the footprint is outside `Win` (abstraction 5).

### What it makes free

- **C-budget, at the root.**
  - A guarded load through `savestate` is predicted to drop from 15–20k to the order of a `j` (6k) **[estimate, to measure]**, because its separation goals become `decide`.
  - At that cost, MODK's whole path (198k today) and FORPREP's integer path, which reads `R[A]`/`R[A+1]`/`R[A+2]` after `savestate` and calls twice, fit one declaration.
  - With no split, there is no hand-chosen split point and no `ArmPre`.
- **The 557k fallback unification** (KIT-1). It cannot happen: memories are logs compared by label, never `writeMap8` chains unified against `mo`.
- **`Ranges.k_*_wm8` and `slotVal_wm8`.** They become instances of `rd_log`. The raw `bytesT8 (writeMap8 …)` versus normalised `slotVal` mismatch in L4-call′ disappears, because `rd_log` *is* the normaliser.
- **`EqCtx`'s 9 address facts.** Each is a label fact, closed by `decide`.

### What it costs

- **Setup.** `Rgn`, `sep`, `sep_sound` (the big one, about 150 lines), `applyLog`, `rd_log`, `addrOf` and its soundness. That is 300 or more lines **[estimate]**.
- **What gets harder.**
  - The generated segments' post memories are `writeMap8` chains today. Either the generator emits them as logs, which is a change to the generator and not to its output, or one bridge lemma `writeMap8 chain = applyLog mo (logOf chain)` is applied after each segment. The second is cheaper to pilot.
  - Addresses that are not affine in one base, such as a table walk `node + 40*i` with a run-time `i`, need a label with a symbolic index. `slot j` already is one, so it is the same pattern.
  - A label table is closed: a new object kind is a new constructor, so `sep_sound` grows by a row.

### Theories

- **Burstall's memory model and the Burstall–Bornat "component as array" encoding**: Burstall 1972; Bornat, *Proving pointer programs in Hoare logic* (MPC 2000). Known. Aliasing between different field kinds disappears by construction.
- **Region inference**: Tofte and Talpin (POPL 1994). Known. Objects partitioned into named regions whose disjointness is static.
- **Value-set analysis**: Balakrishnan and Reps (CC 2004). Known. Machine addresses abstracted to (memory region, offset), which is exactly `addrOf`.
- **Proof by reflection**: Boutin, TACS 1997. Known. `decide` on label data instead of tactic search on arithmetic.
- **Distant, from compilers**: Chaitin's interference graph (1982). Known. Disjointness as a precomputed non-interference relation over a finite set of names, consulted rather than re-derived.

### Pilot

The smallest thing to build:
1. `Rgn` with the six labels MODK touches (`slot`, `kslot`, `savedpc`, `ltop`, `cframe`, `cstack`), plus `sep_sound` for those.
2. Route `kit_disch`'s separation goals through it via the existing `kit_side_pre` hook.
3. Re-profile MODK with `ProfModk.lean`'s per-segment heartbeat log, then merge `ArmPre` and `ArmPost` into one declaration.

The measurement is whether the merged path stays under 200k. Then do **FORPREP** in one declaration (it adds `ciF`, `LF` and the `sp+40` `cframe` offset), and **IDIV**.

### Seed

The digit clusters (`194`, `96`, `285`, `61`, `39`, and `28` twice) read as small fixed offsets in a finite table, labels rather than arithmetic.

## 4. Path certificates: an arm path as data, checked by a verified symbolic evaluator

### Idea

L4-split′ says a split is free exactly when the boundary state is *emitted*, not stated. The deepest way to emit it is to make the whole path a **value**:

`π : List (SegName × Polarity)`, the sequence of generated segments and branch outcomes from the arm's jump-table target back to the head.

A **symbolic state** `Σ = { pc, regs : List (Reg × Expr), log : List (Rgn × off × width × Expr) }` lives in a small first-order expression language:
- `Expr` takes fetch-head variables (`w.base`, the instruction fields, `ldSlot j`, `ldK i`), constants, `add`, `sub`, `shl`, `and`, `xor`, `slt`, `sltu`, …, and a `call f args` node for summarised helpers.
- `Path.post : Path → Σ → Option Σ` composes the segments' effects by a total function, and returns the residual guards as data.

There is one soundness theorem:

```
theorem Path.sound (hwf : π.check σ₀ = some (σ, guards)) :
    (guards.All (·.holds ⟦·⟧)) → Triple (SegSt⟦σ₀⟧) (SegSt⟦σ⟧)
```

An arm proof is then `Path.sound π (by decide) ⟨guard proofs⟩` followed by the close. A split, if ever needed, is `Path.post (π₁ ++ π₂) = Path.post π₂ ∘ Path.post π₁`, which holds by `rfl`. The boundary state *is* `π₁.post σ₀`, a term nobody writes.

### Core rules

**L4-split → `Path.post_append`.** `Path.post_append` (by definition) together with `Path.sound_append` (once) makes cutting anywhere free at the statement level. Each half is a `decide +kernel`, which is outside tactic elaboration **[check: how Lean's kernel counts heartbeats for `decide +kernel`, against `maxHeartbeats`]**.

**Per-segment effect → `SegData.eff_sound`.** The generator emits each segment's effect as *data* (`SegData`: the register updates and the log entries as `Expr`) next to its existing lemma. A generated `rfl` lemma, one per *segment* and not per arm, equates the data's denotation with the lemma's post. Emitting data and per-segment `rfl` facts is changing the generator's output kind, not emitting per-arm proofs.

**L4-call → `Expr.call`.** A call node `call f args` denotes through `HelperSum` (abstraction 2), and its register frame is `Σ.regs.filter calleeSaved?` inside `Path.post`.

**Guards → `Guard.holds`.** Each branch polarity in π contributes `cmp e₁ e₂ = b` to `guards`. These are discharged by the kit's tag lemmas (M2) exactly as `kit_guard` does now, but as a list of named facts. They are *the* per-path content: the path condition.

### What it makes free

- **C-budget.** Elaboration of a path is a kernel evaluation of `check` plus `|guards|` small proofs. The 341 `omega` runs per 27 instructions do not happen in the elaborator, provided the separation inside `check` is the label `decide` of abstraction 3.
- **L4-split's statement cost.** It drops to zero: boundary states are `π₁.post σ₀`.
- **The frame half of C-call.** It is computed inside `Path.post` and never stated.
- **The path skeleton per arm**, the `kit_run` sequence. It becomes a list literal, and the generator's path enumeration already has it.

### What it costs

- **This is the most expensive candidate.** It needs an `Expr` language with a sound simplifier, enough that the guard polarities and the final register file reduce to kernel values (`imodC_eq` shapes, the `bgeu` bridges). That is estimated at 600–900 lines.
- **Overlap with existing machinery.** It overlaps the copied `SWP`/step-table machinery (`VsaIris/Vsa/SymRun.lean`) and `FnSummary.seq`. **[check whether `SWP`'s state is already first-order enough to be `Σ`.]** If it is, A4 shrinks to an arm front end for it.
- **What gets harder.**
  - The value-level facts the close needs, such as `slotVal` of the final log equalling the kernel's `out` value, are now about the *denotation of `Expr`*. The kit's `simp` lemmas must be restated on `Expr`.
  - Error messages become "`check` returned `none`", so debugging moves into the evaluator.

### Theories

- **Translation validation with a verified checker**: Pnueli, Siegel and Singerman (TACAS 1998); Necula (PLDI 2000). Known. A checker over symbolic states, proved once, instead of per-instance proofs.
- **Symbolic execution as a certified evaluator**: King, CACM 1976. Known. The `Expr` store is King's symbolic store, and `guards` is his path condition.
- **Distant, from logic**: Gentzen's cut restricted to *analytic* cut formulas. Known (Gentzen 1935; analytic cut in, for example, Smullyan's tableaux). The only cut formulas are segment posts `π₁.post σ₀`, which are subformulas of the path, so cutting never introduces a new statement.
- **Distant, from biology**: the reading frame of a genome. A path is a word over a finite alphabet (the segment names), and its meaning is computed by a fixed decoder rather than reasoned about per word. This is an analogy, not a citation; novel as a framing.

The long letters-only stretches between the digit clusters, read as words over a finite alphabet. A path is such a word, and the seed itself is data that a fixed procedure reads.

## 5. Persistent outside-window facts (immutable string footprints as a stable modality)

### Idea

C-str is not a missing summary; it is a missing **transfer**.
- `TStringRepr` is stated over `w.mo`, and the machine memory equals `w.mo` only outside `Win`.
- Nothing says a register's string lies outside `Win`.
- L4-str′ checked on every trace that it does, and that no F1 store touches any byte of a reachable string object.

The proposal is to make this *one* modality instead of a premise per arm. A memory fact `P : Mem → Prop` is **outside-stable** for `w` if it depends only on bytes outside `Win`:

`□w P := ∀ m m', (∀ a, ¬ Win p w a → m[a]? = m'[a]?) → P m → P m'`.

The relation gains *one* field, generic over values rather than per resource:

`Core.owned : ∀ j v, s.regs j = some v → ∀ a ∈ fp mo v, ¬ Win p w a`,

and the same for the constants, where `fp` is a value's heap footprint (`[ts, ts+24+len]` for a string, `∅` for an immediate).

With `Core.frame`, this gives a `BytesAt` fact on the *machine* memory at any point of an F1 run. Every store of an F1 run is to `Win ∪ Scratch`, and `Scratch ⊆ Win`. That is exactly what `memcmp`, `strcmp` and `strlen` read. It is the Iris idea of a **persistent points-to**: a cell nobody holds write permission to, so its points-to fact is duplicable and survives every step.

### Core rules

**L4-str → `stable_transfer`, proved once.**

```
theorem Core.str_live (hc : Core p c s w) (hj : s.regs j = some (.str t))
    (hx : stackPayload c j = x) : TStringRepr c.σ.mem x.toNat t
-- via: TStringRepr mo x t ∧ fp ⊆ ¬Win  ⇒  □w (TStringRepr · x t)  ⇒ transfer along frame
```

**Along a run → `stable_run`.** Any `SegSt` run whose writes are all in `Win`, which `Rgn.sep` (abstraction 3) or `kit_frame` decides, preserves every `□w` fact. This covers the C stack below `sp`, which `memcmp`'s caller `luaS_eqlngstr` pushes (`sd ra,8(sp)`). That address is `Scratch`, so it is in `Win`.

**L4-str′, preservation of `Core.owned` by the arms → `owned_step`, proved once.** A def port's value is either a copy of a register or constant, which has the same footprint, or an immediate, which has `∅`. So `owned` is preserved by every F1 arm generically, from `footprint` in `Kernel.lean`.
- CONCAT and CALL will later need a *footprint-frame* variant. GC and `luaS_resize` write only `next` +0, `marked` +9 and `hnext` +16, which are outside `TStringRepr`'s footprint.

**Boot → one more check in `gen_lua_boot_witness.py`.** It confirms `fp ⊆ ¬Win` for every boot-reachable string. The trace check of §2b already found 0 overlaps.

### What it makes free

- **The C-str premises.** `sim_EQ_of_long`, `sim_EQK_of_long`, `sim_LT_of_str` and `sim_LE_of_str` lose their premise. With abstraction 1's summaries, they become ordinary call paths. KIT.md's obstruction 1 (two equal long strings, one inside `Win`) is excluded by `owned`.
- **UNM's numeric-string path, the input half.** The bytes are known on the machine memory. The path still leaves F1 through `luaO_str2num`'s four loops, which abstraction 1 covers.
- **Every later string library call, LEN and CONCAT's reads.** The same lemma serves them.

### What it costs

- **A relation widening.** It is one field, but `vmRel_entry` must discharge it, and every arm's close must re-establish it.
  - `owned_step` makes the close generic for F1.
  - VARARGPREP and CALL, which move `func` and thus `Win`, need a re-proof: the new `Win` must still avoid footprints. For CALL, the heap grows, and newly created strings must land outside the new `Win`.
- **The definition of `fp` must match `TStringRepr` exactly.** Header bytes `next`/`marked`/`hash`/`extra`/`hnext` are deliberately *outside* `fp`. Otherwise GC writes (§2b, 41 and 35 header stores) break stability at CALL and CONCAT.
- **Alignment.** If abstraction 1 wants the aligned `strcmp` path only, `fp` should also carry `ts % 8 = 0`. That is a fact about the allocator, which the boot witness can check.

### Theories

- **Dynamic frames**: Kassios (FM 2006); Leino's `reads`/`modifies` in Dafny. Known. A value carries its footprint, and a fact is preserved by any write disjoint from it.
- **Persistent ("discarded") points-to in Iris**: Vindum and Birkedal, CPP 2021. Known **[check: the paper that introduced `l ↦□ v`]**. Immutable cells as a persistent resource.
- **Distant, from databases and functional data structures**: hash-consing and interning (Filliâtre and Conchon, *Type-safe modular hash-consing*, ML Workshop 2006 **[check]**). The intern map `ι` *is* a hash-cons table, and its soundness, pointer equality being structural equality, already needs immutability of the consed objects. This abstraction states the immutability that `ι` silently assumes.
- **Distant, reference immutability**: Tschantz and Ernst, *Javari* (OOPSLA 2005). Known. Immutability as a type-level property of a reference, checked once, not per use.

### Pilot

The smallest thing to build:
1. `□w`, `stable_transfer` and `Core.owned`.
2. Extend `ValRepr.str`'s use sites only through `Core.str_live`.
3. Add the boot-witness check, then `owned_step` for MOVE/LOADK.

Then **EQ on two long strings**: `luaS_eqlngstr` is loop-free up to `memcmp` (`0x80017184..0x800171c4`, a length test then `jal memcmp`), with `memcmp_sum` from abstraction 1. **LT** follows with the `l_strcmp` instance.

### Seed

The `Q` that recurs unchanged from near the start (`udQ0w`, `cQq`) to the end (`xQQmda9N`) suggested content invariant along the whole run, which became a fact that survives every step.
