## 1. Chunked-fold scans (list homomorphisms for read-only loops)

**Seed.** `qrry … BsRR` (two tapes in lockstep) and `mUl4eq8` (an 8-byte
equality chunk).

### The idea

A read-only scan loop (`memcmp`, `strlen`, `strcmp`, `l_strcmp`'s chunk loop,
`luaO_str2num`'s digit loops) is not a loop with an invariant. It is a
**fold over one or two byte streams, cut into chunks**:

- the word loop eats 8 bytes per pass, and the byte loop eats 1;
- `l_strcmp`'s outer loop eats one `'\0'`-terminated piece (`strlen + 1`
  bytes) per pass.

The specification is a byte-level fold:
- `cmpStep : Ord → UInt8 → UInt8 → Ord ⊕ Verdict` for `memcmp`/`lexLt`;
- `zStep` for `strlen`.

The list-homomorphism property says that folding a concatenation equals
folding the chunks in order. So **the invariant is not written per loop: the
rule fixes it** as "tape pointers = base + k, the fold of `take k` has not
exited". The only per-loop content is a per-chunk lemma, and the chunks come
from a handful of idioms:
- the 8-byte `ld; ld; bne` equality chunk;
- the 1-byte `lbu; lbu; beq` chunk;
- the SWAR has-zero-byte word test `(x & m) + m | x | m = -1` (used by both
  `strlen` and `strcmp`);
- the "call returns a chunk length" chunk, for `l_strcmp`'s outer loop.

Each idiom is proved once, over bytes.

### Core rules

**L4-loop′, read-only exits.** The loop shapes are rotated, have several
exits, and chain loop to loop. All of them become one rule, `scan_chunked`:

```lean
structure Fold2 (σ ρ : Type) where
  step : σ → UInt8 → UInt8 → σ ⊕ ρ        -- per byte pair: continue or verdict

def Fold2.run (F : Fold2 σ ρ) : σ → List UInt8 → List UInt8 → σ ⊕ ρ   -- left fold

/-- A cut state of the scan: tape pointers advanced by the ghost `k`, the
fold state after `take k`, memory unchanged. Generic: fixed by the rule. -/
def ScanAt (h : Pc) (regs : TapeRegs) (A B : Nat) (k : Nat) (st : σ) (m : Mem) : Config → Prop

/-- A chunk at cut `h`: from `ScanAt … k st`, the generated segments reach
`ScanAt h' … (k + c) st'` with `F.run st (bytes A k c) (bytes B k c) = .inl st'`
(c may be 0: a word mismatch that hands over to the byte loop), or an exit
whose post is `F.run st (bytes …) = .inr r`. -/
def Chunk (F) (h h' : Pc) (c : Nat) …

theorem scan_chunked (F : Fold2 σ ρ) (G : CutGraph) (μ : lex (loopIdx, n - k))
    (hchunks : ∀ e ∈ G.edges, Chunk F e.src e.dst e.width) :
    Triple (ScanAt G.entry regs A B 0 F.init m)
           (fun c => ∃ r, F.run F.init (bytes A 0 n) (bytes B 0 n) = .inr r ∧ Exit r c)
```

- The proof of `scan_chunked` is `Triple.loop` over `∃ k st, ScanAt …`, plus
  `Fold2.run_append` (the homomorphism lemma), proved once.
- The rotated byte loop of `memcmp` (entered by `j` at `0x800361c0`) is just
  a cut graph whose entry is not the DFS head.
- `memcmp`'s word loop exiting *into* the byte loop is an edge of width 0
  that changes `loopIdx`. That is why the measure is lexicographic.

**The idiom lemmas** (once each; these are the only arithmetic):

- `chunk_ld_eq` (8-byte equality chunk): `bytesT8 m a = bytesT8 m b ↔ bytes a 8 = bytes b 8`.
- `chunk_lbu`: `beq` on two `lbu`s is `cmpStep`.
- `swar_haszero`: for the mask `0x7f7f…7f`, `((x & m) + m | x | m) = -1 ↔ ∀ i < 8, byte i x ≠ 0`.
  This is Mycroft's has-zero-byte trick **(recalled; check: Mycroft 1987,
  Warren *Hacker's Delight* §6-1)**.
- `overread_irrelevant`. `strcmp`'s and `strlen`'s aligned word loops read up
  to 7 bytes past the terminator, and those bytes are not in `TStringRepr`.
  - The verdict never depends on them. A word with a zero either compares
    equal as a whole (then the two prefixes up to `'\0'` are equal), or goes
    to the byte loop, which stops at the terminator.
  - So the chunk is stated as "verdict = `F.run` up to the first zero, for
    any value of the trailing bytes".
  - This needs only total `getD 0` reads, never presence (CLAUDE.md's
    `RamRead*` row).

**L4-str** is consumed, not proved, here. The scan needs `BytesAt c.σ.mem`
of both strings, and §5 supplies it.

### What it makes free

- **EQ and EQK on long strings.** `memcmp`'s two loops are one
  `scan_chunked` instance with `F := eqFold`. `luaS_eqlngstr`'s
  pointer-equality and length-test paths are loop-free kit runs.
- **LT and LE on strings.**
  - `strcmp` (aligned loop with 6 exits, plus the byte loop) and `strlen`
    (word then byte) are two instances.
  - `l_strcmp`'s chunk loop is a third, *at a coarser grain*: one chunk is a
    C-string piece. The same `lexLt` fold is consumed by `strcoll` and
    `strlen` call nodes inside the chunk.
  - So the nesting is the homomorphism applied twice, not a new invariant.
- **UNM on numeric strings (later).** `luaO_str2num`'s 4 loops are folds of
  `str2int`'s digit step (`Semantics.lean:177`).
- **Later arms.** CONCAT's `memcpy`, LEN, and the string library get read
  scans for free (a single-tape `Fold1`).

Census instances removed: every read-only scan in ROUND-4 §1b.2 (`memcmp`
×2, `strlen` ×2, `strcmp` ×2, `l_strcmp` ×1, `strchr` ×6 on the print
chain), with no invariant written for any of them.

### What it costs

- **Setup, forecast:** about 120 lines.
  - `Fold2`/`Fold1`, `run_append`, `ScanAt`, `scan_chunked`: about 60.
  - The four idiom lemmas: about 50; `swar_haszero` is the only hard one,
    one `bv_decide`-free proof by byte decomposition.
  - The generator must emit the cut graph, which `loops.py` already
    computes. This is data, not proof.
- **What gets harder.** `ScanAt` fixes the register shape "tape pointer =
  base + k". `strlen`'s byte prelude, which aligns first, uses `a4` and `a0`
  differently. It needs `TapeRegs` to allow a pointer that is `base + k` and
  an unrelated start register: one more field.

### Theories

- **Known: list homomorphisms and the third homomorphism theorem.** A
  function that is both a leftwards and a rightwards fold is a homomorphism,
  so it can be evaluated on any chunking. **(recalled; check: Bird 1987, "An
  introduction to the theory of lists"; Gibbons 1996, "The third
  homomorphism theorem", JFP)**
- **Known: SWAR / bit-parallel byte tests.** Word-at-a-time string
  functions as lifted byte predicates. **(recalled; check: Mycroft's 1987
  `haszero` post; Warren, *Hacker's Delight*)**
- **Known, distant: two-tape (multi-tape) finite automata.** `memcmp` and
  `strcmp` are deterministic 2-tape automata reading synchronously, and
  chunking is a block homomorphism of the input alphabet. **(recalled; check:
  Rabin & Scott 1959)**
- **Novel here.** "Over-read irrelevance" as a property of the chunk lemma
  (the verdict is invariant under bytes past the first zero), instead of a
  memory-safety side condition.

### Pilot

- **Build:** `Fold2`, `scan_chunked`, `chunk_ld_eq`, `chunk_lbu`, then
  `memcmp_sum` as one instance (`F := eqFold`).
- **Measure:**
  - hand lines for `memcmp_sum` (forecast: under 15, against the KIT.md
    estimate of about 150);
  - then `sim_EQ` on two long strings, with §5's transfer.
- **LT:** add `swar_haszero`, `overread_irrelevant`, `strlen_sum`,
  `strcmp_sum`, and `l_strcmp_sum` as the nested instance.
- **Refactor:** none of the refactor cases has a read-only loop. LOADNIL is
  §2's.

## 2. Cyclic loops over `SegSt` families, with lattice acceleration for store loops

**Seed.** The palindromes `JAJ`, `3z3`, `hBh`: a cycle reads the same from
any rotation, so a cut point can sit anywhere. The runs `mm` and `nn`: one
unit cell, repeated.

### The idea

There are two layers.

**(a) A cyclic proof over `SegSt` families.** A loop is a cyclic proof
graph:
- the nodes are *cut points*: a pc with a pin family `pins : α → List Pin`
  and memory `mem : α → Mem`;
- the edges are generated segment lemmas;
- one global condition holds: every cycle passes a back edge on which a
  measure `μ : α → Nat` strictly falls.

Soundness is proved once, by well-founded induction on `μ`. Exits sit on any
edge, so bottom-tested, mid-exit (`udiv_norm`) and rotated loops are all the
same object. This is L4-loop′ with the exit placed anywhere. What it removes
is the `| 0 => absurd | n+1 => …` recursion and the `∃`-packing that kept
the kit away from `loopFromBody` (ROUND-4 §1b.1, reasons 2–3).

**(b) Lattice acceleration**, for store loops whose pointer is an
induction variable. In the nil fill (×5) and the slot copy (×2), one
register moves by a constant stride `s`, and each pass writes a fixed *unit
cell*: a list of (offset, value source) pairs.

So the whole loop is a crystal: a cell translated along a lattice vector.
For such loops **the invariant is not supplied at all**. It is the closed
form:
- pointer `= p₀ + s·k`;
- memory `= tile m p₀ s cell k` (the cell written at `p₀ + s·i` for
  `i < k`).

The pass count `n` is the unique solution of `p₀ + s·n = e`, under a
`Ranges`-supplied no-wrap fact.

### Core rules

**L4-loop′ (general).** `cyclic_run` is proved once:

```lean
structure CutPt where pc : Nat; α : Type; pins : α → List Pin; mem : α → Mem
theorem cyclic_run (G : LoopGraph) (μ : ∀ v, (G.cut v).α → Nat)
    (hedge : ∀ e ∈ G.edges, EdgeTriple e)        -- each a generated segment chain
    (hdesc : G.backEdgesDecrease μ)              -- one `decide` on the graph + per-edge `μ a' < μ a`
    : ∀ a, Triple (CutSt (G.cut G.entry) a) (fun c => ∃ x ∈ G.exits, ExitPost x c)
```

**L4-loop′ (parametric summaries), as one rule.** The census asked for "one
parametric nil-fill summary + one slot-copy summary". Both are one theorem
over the cell:

```lean
inductive Src | const (b : BitVec 64) (width) | load (srcReg) (off) (width)   -- nil: const 0, width 1; copy: load
structure Cell where stride : Int; writes : List (Int × Src); bumpFirst : Bool

def tile (m : Mem) (p₀ : Nat) (C : Cell) : Nat → Mem          -- foldl over i < k of C.writes at p₀ + s·i
theorem tile_rd : rd (tile m p₀ C k) a = if a ∈ lattice p₀ C k then cellVal … else rd m a  -- once

theorem accel (C : Cell) (hpass : PassLemma C head)   -- the generated one-pass segment, symbolic in the pin value
    (hnowrap : p₀ + C.stride * n = e ∧ no overflow) :
    Triple (SegSt head [ptr ↦ p₀, end ↦ e] (ArmPay m o))
           (SegSt exit [ptr ↦ e, end ↦ e] (ArmPay (tile m p₀ C n) o))
```

- `accel` is `cyclic_run` with the `α`, `pins` and `mem` above: one proof.
- The close is `Core.bleach_tile`, proved once: a tile whose lattice lies in
  `Slots` and whose values are nil tags keeps `Core.frame` and makes
  `Core.stack` hold of `upd^n`. This also replaces the multi-slot close that
  KIT.md forecast (an `upd` fold over `bleach`, about 20 lines).

### What it makes free

- `loadnil_loop` (25 lines) goes to 0. `sim_LOADNIL` (22) becomes a kit run
  with one `accel` call node plus `bleach_tile`: forecast 3–5 lines.
- RETURN0, RETURN1 (store before the bump: `bumpFirst := false`),
  `luaD_precall` and `luaD_poscall` need no loop lines at all.
- The slot copy (`luaD_poscall`, `luaT_adjustvarargs`) uses the same rule,
  with `Src.load`.
- `muldi3_loop`, `udiv_norm` and `udiv_div` move onto `cyclic_run`.
  - Each keeps its `I` and `μ` (a ghost `Nat` is allowed: `α` carries it).
  - Each loses the recursion skeleton and the packing.
  - Forecast: 25 → about 12 lines each.

### What it costs

- **Setup, forecast:** about 150 lines.
  - `LoopGraph` and `cyclic_run`: about 60.
  - `Cell`/`tile`/`tile_rd`/`accel`: about 70.
  - `bleach_tile`: about 20.
- **Generator:** must emit the one-pass segment *symbolic in the pointer
  value*. Today a segment's pins are values in the `SegSt`, so this is
  already true. It must also emit the cell (offsets and widths), which is
  data read off the body's stores.
- **What gets harder.**
  - The no-wrap fact must come from `Ranges` (`base_hi`), plus a
    `stride ∣ (e − p₀)` fact, which LOADNIL's `field_b_shl` already
    computes.
  - Conditional cells (a store under a guard) are not lattices. They fall
    back to `cyclic_run`.

### Theories

- **Known: chains of recurrences / scalar evolution.** Closed forms for
  induction variables, used by LLVM's SCEV. **(recalled; check: Bachmann,
  Wang & Zima 1994, "Chains of recurrences — a method to expedite the
  evaluation of closed-form functions", ISSAC)**
- **Known: loop acceleration in counter-system verification.** The
  transitive closure of an affine or octagonal transition is computed
  exactly, not by an invariant. **(recalled; check: Boigelot 1998 thesis;
  Bozga, Iosif & Konečný 2010, "Fast acceleration of ultimately periodic
  relations", CAV)**
- **Known: cyclic proofs.** Induction discharged by a global trace condition
  on a proof graph. **(recalled; check: Brotherston 2005, "Cyclic proofs for
  first-order logic with inductive definitions", TABLEAUX)**
- **Distant, known: crystallography.** A Bravais lattice plus a basis (the
  unit cell) determines the whole crystal, and `tile_rd` is "which cell, and
  which basis atom, does a point fall in". The analogy is novel here; the
  mathematics is standard.

### Pilot

- **Refactor LOADNIL:** build `accel` and `bleach_tile`, then re-prove
  `sim_LOADNIL` with no `loadnil_loop`.
  - Success: under 6 hand lines, at no more than today's 7.0 s CPU.
- **Cross-check:** instantiate the same `accel` at RETURN1's
  store-before-bump cell with zero new lemmas.
  - This tests whether the rule is parametric or LOADNIL-shaped.
- **Held-out cases:** no loops in FORPREP or IDIV. EQ and LT use §1, which
  could be stated on `cyclic_run` as its read-only specialisation.

## 3. Region-typed disambiguation, reflected over the write log

**Seed.** The zeros `0dqFMb0GwuY0nOx`, three fences between named regions.
Also the many distinct capitals, read as region tags.

### The idea

C-budget is mostly `kit_disch` re-proving the same address separations with
`omega`: 341 slow calls for 27 instructions, and the disjunctions multiply
that by 4. The repeated question is always the same one: "does this load at
`slot j + 8` see through `savestate`'s stores to `savedpc` and `L->top`?"

Compilers answer it with **type-based alias analysis**. Give every address a
*region tag* (`slot j`, `kslot i`, `savedpc`, `Ltop`, `cframe off`,
`cstack`, `ciField off`, `LField off`, `code`, `heap`). Disjointness of two
regions is a fixed **table** `Rgn.disj : Rgn → Rgn → Bool`. It is proved
sound *once* from `Ranges`, so the disjunctions `ci_sep`, `L_sep`, `k_sep`
and `L_sep_ci` are consumed in that single proof. A read through a store
chain is then:
1. reify the chain as a first-order log of tagged writes (by `rfl` from the
   `writeMap8` nest);
2. `decide` that the read's tag is disjoint from every write's tag, or that
   the address is syntactically equal to it.

`omega` runs only to place an address in its region: `a ∈ (slot j).span w`
holds by definition, so even that is `rfl` for generated addresses.

This is CLAUDE.md law 1 taken literally: "reflect on the first-order write
log; never whnf the Sail state", plus "use one small `decide` per fact".

### Core rules

**L4-split** (the cost part) and the budget:

```lean
inductive Rgn | slot (j : Nat) | kslot (i : Nat) | savedpc | Ltop | ciField (o : Nat)
              | LField (o : Nat) | cframe (o : Nat) | cstack | code | heap
def Rgn.span (p : Proto) (w : RelPtrs) : Rgn → Set Nat
def Rgn.disj : Rgn → Rgn → Bool                                 -- a finite table, `decide`-able

theorem Rgn.disj_sound (hr : Ranges p w) : r₁.disj r₂ = true →
    ∀ a ∈ r₁.span p w, ∀ b ∈ r₂.span p w, a ≠ b                -- the ONLY place the disjunctions are split

structure TWrite where rgn : Rgn; addr : Nat; width : Nat; val : BitVec 64
def WLog.apply : List TWrite → Mem → Mem
theorem WLog.rd_through (hr : Ranges p w) (L : List TWrite) (hL : ∀ x ∈ L, x.addr ∈ x.rgn.span p w)
    (ha : a ∈ r.span p w) (hc : (L.all fun x => x.rgn.disj r) = true) :
    bytesT8 (L.apply m) a = bytesT8 m a
```

- `kit_side_pre` gets a single closer, `rd_through … (by decide)`. It
  subsumes `Ranges.k_{getElem,bytesT1,bytesT8}_wm8` and `slotVal_wm8`
  (KIT-1's hand-made special cases of exactly this).
- **Write-side frame.** `kit_frame`'s goal ("this chain touches only `Win ∪
  Scratch`") becomes `L.all (·.rgn ∈ WinRgns) = true` by `decide`.

### What it makes free

- **Budget, forecast.** The cost of a guarded load through `savestate`
  falls from 15–20k heartbeats toward the 6k of a straight-line `j`. The
  measured gap between seg3 (6k) and seg2/seg4 (38–42k) is the target.
  - MODK's whole path would then be about 151 − 2·32 + 2·10 ≈ 110k pre-half,
    and the whole path fits without a split.
  - FORPREP's three tag and three payload loads through `savestate`, at
    about 10k each, fit in one declaration (forecast).
- **The ×4 disjunction penalty** is gone. The disjunctions are never in an
  arm's context.
- **Read-through lemmas** of every future shape (C-frame spills
  `sd a5,16(sp)`, `luaV_tointeger`'s out-parameter at `sp+40`, `L->top`
  writes) need no new lemma: a new region constructor and a table row.

### What it costs

- **Setup, forecast:** about 140 lines.
  - `Rgn`, `span`, the table, `disj_sound`: about 90. `disj_sound` is the one
    big `omega` proof, a case per table row, run once.
  - `WLog`, `rd_through`, and reification from `writeMap8`: about 50.
- **What gets harder.**
  - Two addresses in the same region (two slots, `slot j` against
    `slot j'`) still need `j ≠ j'`. The tag carries `j`, so it is `decide`
    on concrete `j` and one `omega` on symbolic `j` (instruction fields).
    That is still one call, not twelve.
  - The table must grow with each new runtime object. A wrong row is caught
    by `disj_sound` failing to build, which is the right failure mode.

### Theories

- **Known, compilers: type-based alias analysis.** Disjoint types cannot
  alias. **(recalled; check: Diwan, McKinley & Moss 1998, "Type-based alias
  analysis", PLDI)**
- **Known: region calculus / effect systems.** Effects tagged by region,
  and commutation of effects on disjoint regions. **(recalled; check: Tofte &
  Talpin 1997, "Region-based memory management", I&C; Lucassen & Gifford
  1988, "Polymorphic effect systems", POPL)**
- **Distant, known: memory disambiguation in out-of-order CPUs.** A load may
  bypass earlier stores when an address-tag comparison proves no overlap,
  using a small fixed comparator per store rather than general arithmetic.
  **(recalled; check: Moshovos et al. 1997, "Dynamic speculation and
  synchronization of data dependences", ISCA)**
- **Known: proof by reflection.** **(recalled; check: Boutin 1997, TACS)**

### Pilot

- **Build:** `Rgn` with the regions MODK and FORPREP touch, `disj_sound`,
  `rd_through`, and `kit_side_pre := rd_through`.
- **Refactor MODK as ONE declaration** (no `armBody_split`) and measure the
  heartbeats per segment with the `ProfModk` harness.
  - Success: seg2/seg4 under 15k each, and the whole path under 170k.
- **FORPREP:** one `ArmBody` per exit (up/down × run/skip) with no split, and
  no `FpMem`.
- **IDIV:** whole paths with two helper calls, no split.
- **If the forecast fails, report the residual cost** (whnf of concrete
  memory) as the obstruction. Then §4 is the fallback.

## 4. Retimed cuts: the cut state is a computed strongest postcondition

**Seed.** `4mH2mmUl4`: a 4…4 bracket split by a lone `2` into halves around
`mmUl` (MUL/MOD: the split arm). The digit clusters `52`, `95`, `43` read as
weights: `52 + 95 = 147` stays under a cap of 150, and `+ 43` passes it, so
cut there.

### The idea

Read a path as a combinational circuit:
- segments are gates with known delays (6–42k heartbeats, set by the loads);
- the 200k budget is the clock period;
- a split is a pipeline register.

In hardware, nobody writes the register's contents by hand. It latches
whatever the logic computes, and **retiming** moves registers along the path
without changing behaviour.

Here the latched value is the **strongest postcondition of the segment
prefix**, and it is *already determined* by the generated segments. So it is
a Lean **function** of the path, not a statement:
- `CutSt path k` is the `SegSt` at the k-th boundary;
- its pins are the composed post-pins, *expressed in a tiny first-order
  expression language over the entry*: `Ex := slotTag j | slotPay j | kPay i
  | entryPin r | const | op Ex Ex`;
- its memory is a tagged write log over the entry memory (§3's `WLog`).

The frame at a call is the `CutSt` at the call's return, restricted to the
generator's live set (L4-call′). The values of `Ex` evaluate to the
normalised `slotVal` form by definition, so L4-split′'s "normaliser" is
`Ex.eval`'s defining equations.

### Core rules

**L4-split′ and L4-call′:**

```lean
inductive Ex | slotTag (j : Nat) | slotPay (j : Nat) | kPay (i : Nat) | entryPin (r : Reg)
             | lit (b : BitVec 64) | add (a b : Ex) | … | ret (h : Helper) (args : List Ex)
def Ex.eval (p w s) : Ex → BitVec 64        -- `ret` evaluates by the helper's spec function (moddi3 → srem …)

structure PathTable where                  -- DATA from the generator (arms.tsv-like), not proof
  segs : List SegName; cuts : List (Nat × Pc × List (Reg × Ex) × List TWrite)

def CutSt (T : PathTable) (k : Nat) (p w s) : Config → Prop :=
  SegSt (T.pcAt k) ((T.livePins k).map fun (r, e) => (r, e.eval p w s)) (ArmPay ((T.log k).apply w.mo') o)

theorem cut_compose (T) (k₁ < k₂) :
    Triple (CutSt T k₁) (CutSt T k₂) → Triple (CutSt T k₂) Post → Triple (CutSt T k₁) Post
theorem cut_sound (T) (k) : T.WellFormed = true → Triple (CutSt T k) (CutSt T (k+1))   -- per piece: kit_run
```

- **Correctness never depends on where the cuts are.** `cut_compose` holds
  for any `k`. So the generator's choice of cut indices is untrusted data,
  and a wrong choice only costs heartbeats.
- **Cut placement:**
  - is a greedy linear partition over per-segment weights;
  - uses the profile's model: loads through a store at about 18k, others
    at 6k, plus about 5k per piece of setup;
  - cuts before the running sum passes about 150k.
- **`T.WellFormed`** is a `decide` check: each cut's live set ⊆ the next
  segment's demanded pins, the `Ex` of each pin matches the segment's post
  under substitution. `lcall_frames.py` already does this composition; this
  moves the check into Lean.

### What it makes free

- **MODK.** `ArmPre`/`AtRet`/`divFrame`, and `modk_call`'s 4 frame lines, go
  to 0. `armBody_split` becomes `cut_compose`.
- **FORPREP.** The uncommitted `fp_pre`/`FpInts`/`fpFrame`/`FpMem` become
  `CutSt T 1` and `CutSt T 2`, at the returns of `luaV_tointeger` and
  `__udivdi3`. Nothing is stated.
- **IDIV/IDIVK.** `s3` and `s4` holding operand payloads instead of
  fetch-head values is just `Ex.slotPay b`/`Ex.slotPay c` in the table. The
  MOD-shaped `divFrame` doc problem (ROUND-4 §1b.4) disappears, because no
  frame is named.
- **Every future call node.** CALL's runtime summaries, VARARGPREP, and the
  `l_strcmp`/`luaS_eqlngstr` call frames in §1's pilot.

### What it costs

- **Setup, forecast:** about 160 lines.
  - `Ex` and `eval` with its `ret` cases: about 50, one equation per helper
    spec in use (`srem`, `sdiv`, `udiv`, `toint`, `equalobj`).
  - `CutSt`, `cut_compose`, `WellFormed`: about 60.
  - The bridge "kit_run from a `CutSt`": about 50.
  - Generator: emits `PathTable` rows, about 80 Python lines.
- **What gets harder.**
  - `Ex.ret` needs each helper's result as a *function*. The summaries
    already give equations (`a0 = srem …`), but a helper whose result is a
    relation would need a ghost.
  - Path tables are per path, so path enumeration must be emitted. The
    generator already walks every path from the jump-table target.

### Theories

- **Known, distant: retiming in synchronous circuits.** Register placement
  is driven by a clock period, and behaviour is preserved. **(recalled;
  check: Leiserson & Saxe 1991, "Retiming synchronous circuitry",
  Algorithmica)**
- **Known: strongest postconditions / symbolic execution summaries.** The
  cut state as `sp(prefix, pre)`. **(recalled; check: Floyd 1967; Dijkstra &
  Scholten 1990)**
- **Known: A-normal form.** Every intermediate is named by the compiler,
  never by the programmer. **(recalled; check: Flanagan, Sabry, Duba &
  Felleisen 1993, PLDI)**
- **Distant, known: checkpointing for reverse-mode differentiation.**
  Checkpoints are placed by a cost model, and any placement is correct.
  **(recalled; check: Griewank 1992 / Griewank & Walther 2000, "Revolve",
  ACM TOMS)**

### Pilot

- **Refactor MODK.** Delete `ArmPre`/`divFrame` and state `modk_*` from
  `CutSt T_modk 1`.
  - Success: 0 frame lines, the per-path lemmas unchanged or shorter, each
    piece under 200k with no hand split index.
- **FORPREP:** the four exits from a three-piece table (forecast:
  2–3 hand lines per exit).
- **IDIV:** both helpers, with the `s3`/`s4` reuse as `Ex` rows.
- **Combined with §3:** fewer cuts, and the two are measured separately.

## 5. The holed complement: the window as a hole in the context

**Seed.** `KQTK` and `KmENGK`, K…K brackets around content: a context with
a hole, as in a zipper. `RZPR` (a near-palindrome) read as the read-only
mirror: what is read is what was there.

### The idea

KIT.md obstruction 1: `ValRepr.str` gives `TStringRepr w.mo x s`, but
`Core.frame` relates `c.σ.mem` to `w.mo` only *off* `Win`. Nothing puts the
string off `Win`.

Adding a field "strings are outside `Win`" is forbidden ("one relation field
per resource"), and it would be followed by fields for tables, closures,
upvalues and so on. Instead, **change the representation of the
complement**:
- `w.mo` becomes a *partial* memory that is **undefined on `Win`** (and on
  the GC header bytes `next` +0, `marked` +9, `hnext` +16 of every object);
- the machine memory is the disjoint union `window ⊎ w.mo`.

Every `Repr` predicate built on `w.mo` with presence (`BytesAt m a s` is
`m[a]? = some`, and `rd8`/`rd64` are `some`) then *implies by itself* that
its footprint is off `Win`. So it transfers to `c.σ.mem` by `Core.frame`.

The one structural fact is `hole : ∀ a, Win p w a → w.mo[a]? = none`. It
replaces existing fields rather than adding per-resource ones:
`Ranges.code_out`, `k_out` and `ci_out` become theorems, since `code_word`,
`kconst` and `trap_word` are presence facts on `w.mo`.

### Core rules

**L4-str** (and L4-str′ for CALL/CONCAT's header writes):

```lean
-- Complement gains `hole`; `code_out`, `k_out`, `ci_out` are deleted (derived).
theorem Complement.off_win (hc : Complement p w) (h : w.mo[a]? = some b) : ¬ Win p w a
theorem Core.read_mo (hc : Core p c s w) (h : w.mo[a]? = some b) : bytesT1 c.σ.mem a = b
theorem TStringRepr.transfer (hc : Core p c s w) (h : TStringRepr w.mo ts s) :
    BytesAtT c.σ.mem (ts + tstringContentsOff) s ∧ bytesT1 c.σ.mem (ts + 24 + s.length) = 0
    ∧ lenField c.σ.mem ts = s.length          -- everything §1's scan_chunked consumes
```

- **Preservation along F1 runs is free.** `Core.frame` is already
  re-established by every close (`bleach`), and `w.mo` never changes.
- **CALL/CONCAT** (L4-str′) may write `next`/`marked`/`hnext`. These are
  already holes in `w.mo`, so those writes are invisible to every `Repr`.
  The CALL arm's runtime summary needs only "writes ⊆ heap headers ∪ new
  objects".

### What it makes free

- **The 4 named premises** `sim_EQ_of_long`, `sim_EQK_of_long`,
  `sim_LT_of_str` and `sim_LE_of_str` go, once §1 provides the scans.
- **UNM's numeric-string path:** its blocker was the same.
- **Ranges fields.** `code_out`, `k_out` and `ci_out` (three ∀-fields that
  `omega` cannot use anyway) are derived.

### What it costs

- **Boot.** `vmRel_entry` must build `w.mo := m₀.erase (Win ∪ headers)`, and
  every `Complement` fact must hold on the erased memory. The boot witness
  script checks this footprint disjointness. That is a law check, allowed;
  ROUND-4 §2b found 0 overlaps over 6,254 heads.
- **Total reads.** The `getD 0` total-read view must not leak into `w.mo`
  facts. `w.mo` is a ghost, so presence there is fine. CLAUDE.md's rule
  concerns demanding presence of the *machine* memory, which this never
  does.
- **Setup, forecast:** about 60 lines Lean (`hole`, the three derived
  lemmas, `transfer`) plus boot-witness changes.
- **What gets harder.**
  - Anything that genuinely reads `Win` through `w.mo` breaks, by design.
    Today, `Core.stack` reads slots through `c.σ.mem` and `kptr` reads
    `sp`, so nothing does (to check).
  - CONCAT must allocate new strings into the hole's complement: its
    witness grows `w.mo` (a `w'` with a disjoint extension). That is
    L-C3′'s runtime shape anyway.

### Theories

- **Known: separation logic's disjoint union of heaps.** The frame rule.
  `Core.frame` becomes the separating conjunction `window ∗ mo`.
  **(recalled; check: Reynolds 2002, "Separation logic: a logic for shared
  mutable data structures", LICS)**
- **Known, distant: Huet's zipper.** A data structure as a focus plus a
  context with a hole. The window is the focus. **(recalled; check: Huet
  1997, "The zipper", JFP)**
- **Known, distant: snapshot isolation in databases.** Read-only
  transactions read a snapshot, valid when no concurrent write set meets
  the read set. Here, string reads see the entry snapshot `w.mo`, valid
  because writes hit only the hole. **(recalled; check: Berenson et al.
  1995, "A critique of ANSI SQL isolation levels", SIGMOD)**
- **Novel here:** making the GC header bytes holes, so that L4-str′'s
  CALL/CONCAT refinement needs no footprint lemma.

### Pilot

- **Build:** `hole`, `off_win`, `read_mo`, `TStringRepr.transfer`, and the
  boot-witness check.
  - Does `vmRel_entry` still build? That is the cost to measure.
- **EQ on two long strings:** `transfer` (×2) + §1's `memcmp_sum` +
  `luaS_eqlngstr`'s loop-free runs ⇒ `sim_EQ` with no `_of_long` premise.
- **LT:** `transfer` + `strcmp`/`strlen` scans + `l_strcmp`'s nested fold ⇒
  `sim_LT`.
- **Refactor:** none (LOADNIL and MODK do not read strings). The check is
  that `sim_ADD`/`sim_MODK` still build after the `Complement` change, with
  0 edits beyond the deleted `*_out` uses.
