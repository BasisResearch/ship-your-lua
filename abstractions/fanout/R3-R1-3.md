## 1. Occurrence-typed machine registers (value-projection types for arm code)

### The idea

Give every machine register and spill slot along an arm a **type that says
which projection of which VM value it holds**, and let branches **refine** those
types, as occurrence typing does in Typed Racket. A small syntax of
denotations:

```
Den ::= tagOf j | payOf j            -- the tag byte / 8-byte payload of R[j]'s slot
      | kTag i  | kPay i             -- the same for K[i]
      | slotAddr j | pcAddr k        -- base+16j ; code+4(pc+k)
      | field f (Den)                -- a bit field of the instruction word (A, B, C, k, sJ …)
      | lit n | alu op Den Den       -- constants, pure ALU terms
      | ret f [Den]                  -- the a0 of a pure callee on these arguments (links to #4)
      | pin r                        -- a head-pinned register (s0, s2, s7, s9, s11, …)
```

A typing context is `Γ : MReg ⊕ SpillSlot → Den`, plus a path condition
`Φ : List Atom` over **VM-level atoms**, not machine atoms:

```
Atom ::= isInt j | isFalse j | tagIs j t | kIs i v | ieq (Den) (Den) | islt (Den) (Den) | …
```

The judgement is `Γ; Φ ⊢ pc ⇒ Leaves`. There is one rule **per RISC-V mnemonic**,
universally quantified over the pc, the registers and the offsets. The arms use
about 20 mnemonics (`lbu ld lw sd sb add addi slli srliw zext.b sext.w andi xor
li mv beq bne bltz bgeu bltu j jal`). Each rule is proved once against the Sail
model. For example:

- `lbu rd, 8(rs)` with `Γ rs = slotAddr j` gives `Γ[rd ↦ tagOf j]`;
- `beq rs1, rs2, L` with `Γ rs1 = tagOf j`, `Γ rs2 = pin s2` (= 3): the
  then-branch adds `isInt j` to Φ, the else-branch adds `¬ isInt j`.

**The pruning rule.** If Φ is unsatisfiable against `ValRepr`, the branch is
dead. One lemma: `ValRepr` has no constructor with tag 19, so `tagIs j 19` is
`False` for any represented register. This derives L-C2′'s "P" pruning (the float
paths drop) as typing, instead of it being a property of the generator.

### Core rules

- **L-C4 at the arm level** becomes `arm_typed`: if `Γ₀; Φ₀ ⊢ armTarget op ⇒ Leaves`,
  where Γ₀ is read off `ArmAt` (s4 = the word, s9 = base, …), and every live leaf
  `ℓ` discharges `leafOK ℓ (decide? s)` (#5), then `sim_op`.
- **(a4) guards, one rule per (mnemonic × denotation class)**:
  `branch_tag` (tag vs literal/pin), `branch_konst` (constant vs literal),
  `branch_slt` (two payloads, `slt`/`bltz` vs `BitVec.slt`, i.e. `x.toInt < y.toInt`),
  `branch_ult`. That is about 4 × 6 = 24 small lemmas in total, **fixed for all
  arms**. Today it is a `_t`/`_f` pair per branch *shape*, added with each new
  tree (+81, +44, +59 …). These are occurrence typing's then/else propositions,
  and the doubled-letter seed is this pair made one rule.
- **(d2) field arithmetic**: `srliw k; zext.b; slli 4; add s9` normalises to
  `slotAddr (field B)` by **one** rewrite set over `Den`, not per operand form.
  `sbraw_eq`, `kraw_eq` and `slot_addr` become instances.

### What it makes free

- (a4): 40 declarations and 191 lines stop growing. A new tree adds 0 guard lemmas.
- (d2): stops growing (30 declarations).
- (a6) ALU value lemmas: `alu op (payOf b) (payOf c)` *is* the value, and
  `alu_val` becomes the denotation's definition.
- L-C2′ rows and layouts cost nothing. Types are invariant under branch polarity
  and scheduling, because the leaf set is a set of (Φ, Γ) pairs.

### What it costs

- **Setup:** the `Den`/`Atom` syntax, their evaluation in `(Mem, MState, State)`,
  about 20 mnemonic rules, and the pruning lemma (estimate: 450–600 Lean lines).
  The rules are exactly the Sail step semantics of each mnemonic, lifted once.
  They are *not* per-pc step lemmas: each is ∀ pc.
- **What gets harder:** loops. LOADNIL and the helper bodies need a loop
  rule with an invariant, which a straight-line type system lacks. Spills
  (`sd a1,16(sp); … ld a1,16(sp)`) need `SpillSlot` typing across `jal`, which
  depends on #4's frame law (memory at ≥ sp is unchanged by pure callees).

### Theories

- **Occurrence typing** (known): Tobin-Hochstadt & Felleisen, "Logical types for
  untyped languages", ICFP 2010 *(recalled, check)*. Branch-refined
  propositions are exactly the guard pairs.
- **Typed assembly language** (known): Morrisett, Walker, Crary, Glew, "From
  System F to Typed Assembly Language", TOPLAS 1999 *(recalled, check)*.
  Registers typed at each label.
- **Data provenance semirings** (distant field, databases; known): Green,
  Karvounarakis, Tannen, "Provenance semirings", PODS 2007 *(recalled, check)*.
  A `Den` is the provenance annotation of a machine value: "this a0 is
  pay(R[B]) ⊗ pay(R[C]) through `__muldi3`".
- **Units of measure / dimensional types** (distant field, physics; known):
  Kennedy, "Relational parametricity and units of measure", POPL 1997
  *(recalled, check)*. A tag, a payload and an address are different
  dimensions. Adding a tag to an address is ill-typed, and that is why the
  denotation rewrite set stays small.
- **Novel:** refinement atoms that are **`ValRepr` constructor cases of the
  target VM's values**. Unsatisfiability against the representation relation
  is the pruning rule, so L-C2′'s P3p canonical tree *is* the typing
  derivation's shape.

### Pilot

- **Build:** `Den`, `Atom`, the rules for the 14 mnemonics the three held-out
  arms use (`lbu ld lw sd sb add slli srliw zext.b andi xor li mv beq bne bgeu
  bltz j jal`), the four branch classes, and the pruning lemma. Leave the rest
  of the ISA out.
- **MUL:** the typing derivation has 3 live leaves:
  - int × int: `jal` into #4's pure call rule;
  - `¬isInt B`: pc+1, via `0x8001c1e4`;
  - `isInt B ∧ ¬isInt C`: pc+1, via `0x8001e43c`.

  Tag 19 is dead by pruning.
- **MOD:** 4 live leaves: y ∉ {0,−1} with and without the sign fix-up; y = −1
  (result 0); pc+1. y = 0 is dead, because `imod x 0 = none` contradicts the
  `Step` premise (see #5).
- **EQ:** 2 leaves, `a0 ≠ k` and `a0 = k`, over `ret luaV_equalobj [slotAddr A,
  slotAddr B]`.
- **Refactor `sim_ADD`:** it becomes `arm_typed` plus leaf obligations. Measure
  the guard-lemma count, which should be 0 new.

### Seed

`dd`, `99`, `tt`: twins → the `_t`/`_f` guard pair as the then/else of one
occurrence rule.

## 2. Self-framing relation over owner-tagged memory (dynamic frames for `VmRel`)

### The idea

Stop growing `VmRel` one field at a time with every arm re-closing all
fields. Instead:

1. **Every address has an owner.** `own : RelPtrs → Nat → Option Owner` with
   ```
   Owner ::= slot j | cframe | calleeStack | ciF f | LF f | GF f | kArr | code
           | text | rodata | heap (chunk) | stdio
   ```
   Here `f` ranges over named struct fields (`ci.savedpc`, `ci.top`, `L.top`,
   `L.stack_last`, …). The owner map is computed from `RelPtrs` and the layout
   offsets that already exist in `Runtime.lean`.
2. **Every invariant is a self-framing record:**
   ```lean
   structure Inv (w : RelPtrs) where
     reads  : Owner → Prop               -- its frame
     holds  : Mem → Prop
     stable : ∀ m m', (∀ a o, own w a = some o → reads o → m[a]? = m'[a]?) → holds m → holds m'
   ```
   `Complement`, `RuntimeMem`/`LuaStateAt`, `Ranges` and the `kconst` field
   become a **list of `Inv`s**, one per conjunct, each with its frame. `stable`
   is proved once per invariant, and is usually `by congr` on `rd64`/`bytesT*`.
3. **Every edge has a write set of owners** (this is L-C6′):
   ```
   edgeWrites e protect callee :=
     slot '' (e.defs ∪ kills e) ∪ {cframe}
     ∪ (if protect then {ciF savedpc, LF top} ∪ {calleeStack} else ∅)
     ∪ (runtime footprint of callee, from #4)
   ```
4. **One rule, `frame_all`:** after an arm whose stores lie in
   `edgeWrites e …`, every `Inv` whose `reads` misses the write set holds
   unchanged. Only invariants that intersect the write set need a proof, and
   there are few such intersections, each reused by every arm with the same
   write shape.

**Relocation.** For VARARGPREP and the reallocating CALL, owners are
*relative*: `slot j` is `ci->func + 16 + 16j` read through the current `func`.
A relocation is a **permutation of addresses that preserves owners**. An `Inv`
stated only through owners is *equivariant*, so one rule `reloc_inv` carries
every such invariant across `func` moving. This is the nominal-sets move, with
addresses as atoms.

### Core rules

- **L-C6′** becomes `frame_all` plus `edgeWrites`. There is one rule for all arms.
- **L-C3′ runtime** becomes a callee's declared owner set, an element of
  `Owner → Prop` (`{LF top, LF ci, ciF next.*, slot ≥ A, heap, GF gcdebt, stdio,
  …}`). The same `frame_all` applies, so there is no per-callee close.
- **Relocation** ("func may move", L-C3′ runtime) becomes `reloc_inv`, one
  equivariance lemma.
- **The `Protect` split, and the concrete fix for MOD/EQ.** `LuaStateAt.top :
  L->top = func+16` is an invariant whose frame is `{LF top}`. `Protect` writes
  it. Restate it as a **phase invariant**:

  > `L->top = func + 16 ∨ L->top = ci->top`

  - The first disjunct holds from entry until VARARGPREP.
  - The second holds after any `Protect`, since `ci->top` is exactly what MOD
    and EQ store.

  Then one lemma, `protect_ok`, re-proves this single invariant, and all nine
  `Protect` opcodes reuse it. `ci.savedpc` is **not read by any invariant**
  (no conjunct constrains it), so writing it is free.

### What it makes free

- **(d1) relation widening falls from 100–250 lines per resource** to one `Inv`
  (the predicate, its `reads` and `stable`, typically 10–30 lines). Arms never
  re-close it unless their write set touches its frame. This addresses the four
  blocked widenings:
  - `savedpc`/`L->top`: two owners, one phase invariant;
  - `func` moving: `reloc_inv`;
  - heap/`G`: the owners `heap` and `GF *`;
  - console: the owner `stdio`.
- **(c) the `Core.frame_of`/`text_of`/`kptr_of`/`fetch_of` family** (each is a
  "survives writes outside X" lemma) collapses into `frame_all` instances.
- **(c) the `*_of` transports** go the same way.

### What it costs

- **Setup:** the `Owner` type and `own`, splitting `Complement`, `RuntimeMem`
  and `Ranges` into `Inv`s, and proving `own` well-defined (disjointness of
  regions, which is today's `Ranges` `*_out`/`*_sep` facts restated). Estimate:
  350–500 lines, once. `vmRel_entry` must be re-targeted to the list form.
- **What gets harder:**
  - The owner map must be *total enough*. Heap chunks are dynamic (malloc), so
    `heap` has to be one coarse owner with a `DlHeap` invariant that is itself
    re-proved by the allocator's contract.
  - Invariants that read many owners (`DlHeap`) get re-proved on every write
    set that touches the heap: CALL print, VARARGPREP and growth. That is the
    runtime-shape price, paid once per shape, not per arm.

### Theories

- **Dynamic frames** (known): Kassios, "Dynamic frames: support for framing,
  dependencies and sharing without restrictions", FM 2006; implicit dynamic
  frames, Smans, Jacobs, Piessens, ECOOP 2009 / TOPLAS 2012 *(recalled, check)*.
  **Region logic**, Banerjee, Naumann, Rosenberg, ECOOP 2008 *(recalled,
  check)*.
- **Build systems** (distant field, build engineering; known): Mokhov, Mitchell,
  Peyton Jones, "Build systems à la carte", ICFP 2018 *(recalled, check)*. An
  `Inv` is a build target with declared dependencies, and an arm's write set
  "dirties" only the targets that depend on it. Minimality is the same
  theorem.
- **Incremental view maintenance** (distant field, databases; known): Gupta &
  Mumick, "Maintenance of materialized views", IEEE Data Eng. Bull. 1995
  *(recalled, check)*. An update is *irrelevant* to a view whose query reads
  disjoint relations.
- **Nominal sets** (distant field, the metatheory of binding; known): Gabbay &
  Pitts, LICS 1999; Pitts, *Nominal Sets*, CUP 2013 *(recalled, check)*.
  Relocation is an atom permutation, and owner-stated invariants are
  equivariant.
- **Novel:** phase invariants over an owner's value (`L->top ∈ {func+16,
  ci->top}`), which let `Protect` writes enter without widening, and
  equivariance as the stack-relocation rule for a decoded VM.

### Pilot

- **Build:** `Owner`, `own`, `Inv`, `frame_all`, and `Complement` split into
  `Inv`s. `LuaStateAt.top` gets its phase form, with `protect_ok`. Skip
  `reloc_inv` (none of MUL, EQ, MOD relocates).
- **MUL:** the write set is `{slot A, cframe, calleeStack}`. No invariant
  besides `stack` has a frame intersecting it, so the close is `frame_all`
  plus #3's slot rule.
- **MOD, EQ:** add `{ciF savedpc, LF top}`, discharged by `protect_ok`. Measure
  that this costs no new `VmRel` field.
- **Refactor `sim_ADD`:** replace `Core.write`'s body with `frame_all`, and
  measure lines in `Rel.lean`.

### Seed

`lDpLDh`, a near-palindrome around `p`, and the recurring `pL`: what sits on
both sides of the write is preserved, framing. "pL" read as "preserved
L-fields" pointed at `LuaStateAt`.

## 3. Store patches modulo representation (one close rule for every store shape)

### The idea

Record an arm's memory effect as a **patch**, a list of `(addr, width, bytes)`,
and treat patches in an algebra:

- **commutation:** disjoint writes commute;
- **absorption:** a later write covering an earlier one absorbs it;
- **junk:** writes into owners no invariant reads (`cframe`, `calleeStack`,
  `ciF savedpc`; from #2) are quotiented out.

On top of this, quotient further by **representation**: two patches are
*equivalent* if the resulting memories decode (`ValRepr`) to the same VM
registers. Then **every** store shape is equivalent to one canonical patch:

```
canon (defs, vals) := ⊕_{(j,v)} [slot j + 8 ↦ tagByte v (1)] ⊕ [slot j ↦ payload v (8)]
```

The four shapes of L-C6′ then follow:

- **tag+payload in either order:** commutation. ADD is tag-first; MUL and MOD
  are payload-first.
- **tag-only** (LOADTRUE/LOADFALSE/LFALSESKIP/NOT/LOADNIL): *payload
  irrelevance*. `ValRepr.false_ {x}`, `true_ {x}` and `nil {t x}` quantify over
  any payload, so the missing `sd` is equivalent to writing whatever was there.
- **payload-only** (FORLOOP): *tag irrelevance under a precondition*. The slot
  already has tag 3, so the missing `sb` is equivalent to writing 3.
- **CALL's 16-byte copy:** one `sd`+`sd` equals `canon` of the copied value, by
  `ValRepr` of the source.

### Core rules

**L-C6′** ("after the arm the slot's 9 bytes represent v and nothing else in the
window changed") becomes **one theorem**:

```lean
theorem close (hc : Core p c s w) (hΔ : Δ ≈[repr w s] canon e.defs o.vals ⊕ junk)
    (hpc : …) : Core p (c.withMem (c.σ.mem.patch Δ)) (s.apply e o) w'
```

- `≈[repr w s]` is decided leaf-by-leaf by a normaliser: commute into address
  order, absorb, drop junk, then compare with `canon` using the
  irrelevance lemmas.
- The normaliser is a *definition* with a soundness proof. It is not search.

### What it makes free

- (c): every `slotStore_*` variant (`_sb`, `_sd_sb`, `_copy`, `_copy_tv`),
  `ForStore`, `Core.write`, `Core.forloop` and `Core.jump` become instances of
  `close`, with 0 lines per new store shape.
- New close shapes stop costing 9–39 lines. The census's "a new case with
  most new trees" row goes flat at zero.
- `insert_frame`, the step that failed a build in truth (d5), is subsumed by
  commutation.

### What it costs

- **Setup:** the patch type, the `patch` function on `Mem`, and the
  commutation, absorption and junk lemmas (byte-level, on the Sail `Mem` map).
  Then the `≈[repr]` relation with its two irrelevance lemmas, and the
  normaliser plus its soundness. Estimate: 300–400 lines.
- **What gets harder:**
  - Partially overlapping writes (an `sd` over the byte an `sb` wrote) need
    byte-splitting. The arms never do this in a slot (L-C6′'s shapes), but the
    normaliser must fail loudly on it.
  - The repr-quotient depends on the *pre*-state (tag irrelevance needs "tag
    was already 3"), so `≈` is indexed by a state, and the precondition must be
    available at the leaf, via #1's Φ.

### Theories

- **Patch theory** (distant field, version control; known): Darcs' patch
  commutation (Roundy, 2005); Mimram & Di Giusto, "A categorical theory of
  patches", ENTCS 2013 *(recalled, check)*.
- **Mazurkiewicz traces** (known): Mazurkiewicz 1977, trace equivalence under
  an independence relation *(recalled)*. Round 1 used them for instruction
  order. Here they apply to *stores only*, which is what L-C6′ says matters.
- **CRDTs / operational transformation** (distant field, distributed systems;
  known): Shapiro, Preguiça, Baquero, Zawirski, SSS 2011; Ellis & Gibbs, SIGMOD
  1989 *(recalled, check)*. Commuting operations converge regardless of
  delivery order. Here, compiler order vs kernel order.
- **Novel:** quotienting patches by the **representation relation's kernel**,
  so that "the compiler did not bother to write the payload of `false`" is
  patch equivalence and not a separate store shape.

### Pilot

- **Build:** the patch, `close`, and a normaliser handling `sb`/`sd` at slot
  offsets, `sd` into `cframe`/`calleeStack`, and `Protect`'s two `sd`s as junk
  (#2 supplies which owners are junk).
- **MUL:** Δ = `[slot A ↦ a0 (8)] ⊕ [slot A+8 ↦ 3 (1)]` ⊕ `__muldi3`'s frame
  junk. `close` applies after one commutation.
- **MOD:** Δ = `[ci+32 ↦ pc+1] ⊕ [L+16 ↦ ci->top]` ⊕ payload ⊕ tag. The first
  two are junk or phase invariant (#2).
- **EQ:** Δ = the `Protect` pair ⊕ the `luaV_equalobj` frame. `close` is
  reached with `e.defs = []`.
- **Refactor `sim_ADD`:** it is tag-first, so the same `close` applies. The
  measure is that `slotStore_sb`/`_sd_sb` can be deleted.

### Seed

`1O`/`O1` and `H8`/`8H`: the same pair in opposite orders, i.e. stores in
compiler order vs kernel order, and commutation making them one.

## 4. One simulation judgement with a call rule, reused for the callee: effect-signature contracts

### The idea

Define a single judgement over code regions:

```lean
def Sim (P : Config → Prop) (Q : Config → Prop) : Prop :=
  ∀ c, P c → ∃ c' n, 0 < n ∧ StepsN n c c' ∧ Q c'
```

- **An arm:** `P = ArmAt p · s w ins`, `Q = VmRel p · s'`.
- **A callee:** `P = AbiEntry f args ra sp mem`, `Q = AbiReturn …`.

These are the *same* judgement, which is the seed's "AZh twice". One **call rule**
is proved once, in three versions, one per L-C3′ shape:

- **`call_pure`**, for the signature `Pure F reads outs`. At `jal f` from a
  state whose Γ gives the `a0..a7` arguments, continue at `pc+4` with:
  - `a0 := F (args, bytes read at the argument pointers)`;
  - the callee-saved registers (`s0–s11`, `sp`, `gp`) unchanged. This is the
    ABI law, and it is what keeps `Pins` true across the call;
  - memory at ≥ `sp` unchanged except `outs`, and memory below `sp` havocked.
- **`call_runtime`**, for the signature `Runtime O R`, where `O` is an owner
  set from #2 and `R` a relation on decoded VM states. The same, but memory in
  `O` goes to any state satisfying `R` with the pre-state, and `func` may move
  under #2's equivariance.
- **`call_noreturn`**, for the signature `NoReturn`. The leaf is closed with no
  continuation: the path is either *infeasible* (below) or discharged on the
  `stuck_sim` side.

A helper enters the system as a **table row** `(symbol, shape, F/R/O,
arg-reads, outs)`, plus **one proof that its body satisfies the row**. That
proof uses the same `Sim` machinery (#1's typing, #5's leaf evaluation) with
`P = AbiEntry`. So there are **no hand-written contracts**: the row's `F` is a
Lean function already in the semantics:

- `__muldi3`: `(· * ·)`;
- `__moddi3`: `BitVec.srem`, the truncated remainder;
- `luaV_equalobj`: `fun v₁ v₂ => decide (v₁ = v₂)` lifted through `ValRepr`.

Proving the helper is simulating a very small "arm" whose "VM" is its
arguments.

**noreturn is not needed by `sim_X` at all.** `sim_X`'s premise is `Step p s s'`.
Every error path in MOD, MODK, IDIV, IDIVK and FORPREP corresponds to `δ …
= none` (`imod x 0 = none`, `idiv x 0 = none`, `forprepK` with `st = 0`), so
`Step` is impossible on it. The leaf's Φ plus `kstep_iff` gives `False`. The
81-function error chains are therefore **off the `sim_X` critical path
entirely**. They matter only for `stuck_sim`. *This should be checked against
how `Supported`/`stuck_sim` are stated; I did not read those proofs.*

### Core rules

- **L-C3′ pure** becomes `call_pure`.
- **L-C3′ runtime** becomes `call_runtime` (with #2's `frame_all`).
- **L-C3′ noreturn** becomes `call_noreturn`, plus the infeasibility lemma
  `leaf_dead_of_delta_none` for the `sim_X` side.
- **The ABI callee-saved law** is one lemma per call shape. It is the reason
  `Pins` survives, and it replaces per-site pin re-establishment.

### What it makes free

- **(b) for the 11 normal-path helpers:** each costs a row plus a body proof
  in the shared machinery.
  - Soft-int loops still need one **counted-loop rule** (below).
  - `luaV_equalobj` on F1 values is branchy but loop-free on non-strings.
- **The error chains (81 functions)** become unnecessary for `sim_X`.
- **Spills across calls** (`sd a1,16(sp); jal; ld a1,16(sp)`) are free, because
  memory at ≥ sp is unchanged by `call_pure`.
- MUL, MULK and UNM (proved trees that only lack a callee) unblock
  immediately.

### What it costs

- **Setup:** `Sim`, `AbiEntry`/`AbiReturn`, the three call rules and the ABI
  law. Estimate: 300 lines. On top of that, a **counted-loop rule**: an
  invariant indexed by an iteration count, with the loop body in `Sim`.
  libgcc's rv64i `__muldi3` is a shift-and-add loop and `__udivdi3` a long
  division *(recalled; check the disassembly)*, so each needs a loop
  invariant. That is real per-helper thinking, 30–60 lines each for 4
  soft-int helpers. This is the honest residue.
- **CALL `print` (runtime, 81 functions)** is still large: the rule shape
  exists, but proving `luaD_precall → luaB_print → … → HTIF` satisfies
  `Runtime O R` is the stdio port (A0.2). This proposal fixes the *interface*
  so that CALL's arm proof is the same size as MUL's. It does not make the
  chain's body proof small.
- **What gets harder:** `luaV_equalobj` on strings. δ `.eq` compares
  byte-lists, while the machine compares short strings by pointer. The row's
  `F` is only correct under an **interning invariant**: equal short-string
  contents imply equal addresses. That is a `heap`-owned `Inv` (#2) and is not
  in `TStringRepr` today *(check whether F1 ever has two live strings)*.

### Theories

- **Procedure-call rules** (known): Hoare, "Procedures and parameters: an
  axiomatic approach", 1971 *(recalled, check)*; the **frame rule** of
  separation logic, O'Hearn, Reynolds, Yang, CSL 2001 *(recalled, check)*.
- **Algebraic effects and handlers** (known): Plotkin & Pretnar, ESOP 2009
  *(recalled, check)*. The three shapes are effect signatures, and the call
  rule is their handler into the machine semantics.
- **Language interfaces for open compilation** (known): Koenig & Shao,
  "CompCertO", PLDI 2021 *(recalled, check)*. The "C calling convention"
  interface between components is `AbiEntry`/`AbiReturn`.
- **Transaction-level modelling** (distant field, hardware design; known): Cai
  & Gajski, "Transaction level modeling: an overview", CODES+ISSS 2003
  *(recalled, check)*. Bus transactions are abstracted into function calls
  with declared effects, and the helper call is the "transaction".
- **Interface automata** (distant field, component-based design; known): de
  Alfaro & Henzinger, FSE 2001 *(recalled, check)*.
- **Novel:** reusing *the arm judgement itself* to prove helper rows, so that a
  "contract" is just a Lean function already in δ, and the δ-`none`
  infeasibility argument that removes noreturn from `sim_X`.

### Pilot

- **Build:** `Sim`, `call_pure`, the ABI law, `leaf_dead_of_delta_none`, and
  three rows:
  - `__muldi3 ↦ Pure (·*·)`;
  - `__moddi3 ↦ Pure BitVec.srem`;
  - `luaV_equalobj ↦ Pure (eq on decoded values)`.

  **Assume** the rows' body proofs for the pilot, which is allowed if the
  bake-off separately measures one of them (`__muldi3` with the loop rule).
- **MUL:** the `jal` node is `call_pure`, and `ld a1,16(sp)` spill-reloads
  survive.
- **MOD:** `call_pure __moddi3`, then the sign fix-up leaf needs one δ lemma:
  `imod x y = some (let r := x.srem y; if r ≠ 0 ∧ (r ^^^ y).msb then r + y
  else r)` for y ∉ {0,−1}, plus `imod x (−1) = some 0`. The y = 0 leaf is dead
  by `leaf_dead_of_delta_none`.
- **EQ:** `call_pure luaV_equalobj` with pointer arguments, whose reads are
  `slot A`, `slot B`, plus the string heap if any. Then the `bne k,a0` leaf
  matches `docondjump`'s `edge := if (!c.isFalse) = k then 1 else 0`.
- **Refactor `sim_ADD`:** ADD has no call on the int path, so this measures the
  cost of `Sim` as the carrier. It should be neutral.

### Seed

`AZh` occurring twice in different contexts (`9AZhch`, `FuAZhgH`): one
judgement, instantiated twice, with the callee as a nested arm.

## 5. Forward kernel evaluation: `decide?` is the spec, no inversions (SymExec v3)

### The idea

Invert nothing. `kstep_iff` and `decide?_eq_some` already say that `Step` is the
graph of a function, and the palindrome `686` reads the same both ways. The arm
theorem is therefore restated in the **forward, computational direction**:

```lean
theorem sim_of_leaves (hk : kernelAt p s.pc = some K)
    (hleaves : ∀ ℓ ∈ armLeaves op, Φ ℓ (decode c) →
       ∃ vs, K.reads.mapM s.regs = some vs ∧
             K.body vs = some ⟨ℓ.edge, ℓ.vals.map (eval c), ℓ.print⟩ ∧ …) :
    sim_op
```

- Each machine leaf states *what edge index and what values the machine
  produced* (from #1's Γ at the leaf).
- The obligation is that **`K.body` computes the same thing**. `K` is a concrete
  `opKernel` term once the word's fields are fixed, so the goal is closed by
  **evaluation**: `simp only [opKernel, arithRR, opArith, Opnd.fill, δ,
  BinOp.int]` plus Φ.
- There is no per-combinator `step_opArith`, `step_forloop` or `step_testset`.
  The generic `decide?_eq_some` is the only inversion, and it already exists.

**The carrier is SymExec, fixed on its three losses:**

1. **Hand lines 2–4×.** The per-arm input becomes **nothing but the opcode**.
   - #1's typing computes the leaves.
   - #5's evaluation closes the kernel side.
   - #3's `close` closes the memory side.
   - #2's `frame_all` closes the rest.

   The hand residue per arm is only genuinely new δ facts (MOD's sign fix-up),
   which are δ lemmas reusable by MODK, not arm lemmas.
2. **No call nodes.** Add #4's `call_pure`/`call_runtime`/`call_noreturn` as
   executor nodes at `jal`, looked up in the row table.
3. **Weaker theorem (`SymOk`, `VmRelZ`).** `2332c06` already moved `Core.frame`
   to total reads and put `RegsOk` in `Core` (ROUND-2's two on-our-side fixes).
   So `VmRelZ = VmRel` and `SymOk` follows from `Core.ok`. The conclusion is
   stated exactly as `VmRel p c' s'`. *Check that `2332c06` really covers both.*

**Path merging.** Every leaf that returns to the head passes through the same
`close ∘ frame_all`, so proof size is linear in leaves, not in paths × depth.
That is (d4)'s growth with branchiness.

### Core rules

- **L-C4 at the arm level** becomes `sim_of_leaves`: one theorem for all
  opcodes.
- **(a5) kernel inversions** become `decide?_eq_some` (exists) plus
  evaluation, with no per-combinator lemma.
- **L-C2′** becomes redundant. Arms sharing a tree share the *leaf set*
  automatically, since leaves are computed and no template is keyed.

### What it makes free

- (a5): 19 declarations and 209 lines, rising, go to 0 new per tree.
- (a1) new-tree cost: the 19 remaining trees need no template, no inversion
  and no guards (#1). Their cost is only new δ lemmas and new helper rows.
- Generated volume (d4) goes to 0 (the SymExec measurement had 0 generated
  lines), and the ledger's "table row" becomes the only per-arm artifact.

### What it costs

- **Setup:** it composes #1 + #3 + #4, plus `sim_of_leaves` and the
  leaf-evaluation simp set. If SymExec (syi `exponentiate`) is copied, its
  decoder and instruction rules are reused, and only the Γ/Φ layer, call
  nodes and leaf closing are new. Estimate: 400 lines on top of #1/#3/#4.
- **What gets harder:**
  - **CPU.** Evaluation of `opKernel` inside `simp` on symbolic values must not
    unfold `Proto.fetch`/`nextJump` wholesale. `docondjump` needs `nextJump p
    pc` as a hypothesis-carried constant (the `JMP` at pc+1).
  - **Kernel reads through memory.** `Opnd.fill` with `.imm (kval …)` needs
    `Complement.kconst` at the leaf, via Φ `kIs i v`.
  - **Errors in the leaf.** If a leaf's machine result disagrees with `K.body`,
    the failure is a `simp` residue, not a named lemma. It is harder to read
    than a template mismatch.

### Theories

- **Translation validation** (known): Pnueli, Siegel, Singerman, TACAS 1998;
  Necula, PLDI 2000 *(recalled, check)*. Each arm is validated against its
  source kernel, not proved by a compiler-generic argument.
- **Partial evaluation / the first Futamura projection** (known): Futamura 1971;
  Jones, Gomard, Sestoft, *Partial Evaluation and Automatic Program Generation*,
  1993 *(recalled, check)*. `opKernel p pc w` specialised to a word is the
  residual program that the arm is compared against.
- **Double-entry reconciliation** (distant field, accounting; novel as a proof
  frame). Two ledgers, the machine's leaves and the kernel's `body`, are
  reconciled entry-by-entry. A mismatch is a named unreconciled entry, the
  path's `(Φ, edge, vals)`. The design principle taken from it: the check
  should report the *entry* that fails, which argues for leaf-indexed
  obligations over one monolithic `decide`.
- **Poincaré return map** (known, from round 1's R1-2 #5). The head is the
  section. The novelty here is closing the section map by *forward kernel
  evaluation* instead of per-kind inversion.

### Pilot

- **Build:** `sim_of_leaves`, the leaf-evaluation simp set, and SymExec
  extended with #1's Γ/Φ, #4's `call_pure` node and #3's `close`.
- **MUL:** 3 leaves. Evaluation gives `opArith … [.int x, .int y] → edge 0,
  [x*y]`, and `call_pure __muldi3` gives `a0 = x*y`, so they match. The two
  non-int leaves give edge 1 with `vals = []`.
- **EQ:** 2 leaves. `docondjump`'s body with `test = δ .eq` evaluates to
  `if (!(.bool (x=y)).isFalse) = k then 1 else 0` against the machine's `bne
  k,a0`.
- **MOD:** 4 live leaves plus 1 dead (y = 0) by δ = none. The sign fix-up needs
  one new δ lemma, which MODK reuses.
- **Refactor `sim_ADD`:** its hand input is the opcode name. Delete
  `step_opArith` and measure.
- **The bake-off numbers to watch:**
  - hand lines per held-out arm (target: below the incumbent's 61);
  - new declarations per new tree (target: only δ lemmas);
  - CPU per arm against the incumbent's 6.5–6.9 s.

### Seed

`686` (with `bub` and `wmW`), a digit palindrome: reading `Step` forwards
(`kstep`) equals reading it backwards (inversion), so evaluate instead of
invert.
