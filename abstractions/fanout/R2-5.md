## Positions on the two hard questions

**1. Should `Step`/`LuaSem` be redefined as data (a TCB change), or should the
readable inductive stay, with the derived form proved equal once?**

- The one-time equality is cheap in *lines*. Every `Step` constructor already
  has the shape `fetch → op → premises → Step s (f s)`, so
  `Step ↔ kernelStep` closes with one `cases h <;> exact ⟨_, rfl, …⟩` plus one
  `simp [kernel]` in the other direction. That is O(1) lines and O(rules) kernel
  time. R1-4 #1 calls it "a per-rule proof in disguise", and that overstates the
  cost.
- The real cost is **two transcriptions per rule, forever**. Every future
  opcode is written as a constructor *and* as a kernel entry, and each one is
  reviewed against `lvm.c`. The census counts "5 places per rule" as the
  disease, and keeping both leaves 2.
- My recommendation: redefine, with the constructors kept as derived one-line
  lemmas (R1-5 #1, "pedomorphism"). But **fix the kernel type for F2 now**.
  Every converged kernel type (R1-1 #1 `μ R W E`, R1-2 #2 `View R`, R1-3 #1
  `List Value → …`, R1-4 #1 `δ`, R1-6 #1 `Micro`) makes the footprint *static
  in the word*, and F2's heap breaks that (idea 1 below). Nondeterminism (`next`
  order, allocation addresses) would break `step?` being a function. Idea 4
  below keeps every converged theorem unchanged by making the choice an input.
- Under closures (F3), both forms need a frame stack. That cost is neutral
  between the two options.

**2. Which idea actually reduces A1, and what is the cheapest falsifier?**

- None of the converged metatheory ideas (kernels, rulebooks, δ) reduces A1
  directly. They give each arm a smaller *contract*: reads, an edge, writes.
- Only four round-1 families touch the arm proofs themselves:
  1. symbolic summaries: R1-1 #5, R1-2 #5;
  2. templates or idiom grammars: R1-3 #2, R1-4 #4;
  3. orbits: R1-5 #4, R1-6 #4;
  4. frames and lenses: R1-3 #5, R1-5 #5, R1-6 #5.
- The coordinator's ELF check already damages families 2 and 3 *as stated*:
  - ADD and SUB differ in a branch sense;
  - MUL and MULK differ by register allocation and scheduling;
  - text templates and `Relabel = shift + positional substitution` cannot
    absorb either.

  Idea 3 below is the repair. Idea 2 below reduces the frame cost of the arms
  that clobber (`CALL`, `CONCAT`).
- **The cheapest falsifier for families 1–3 together is one unverified script
  over the ELF, with no Lean.** It does four things:
  1. extract the 54 arms through the jump table;
  2. convert each to SSA and build its dependence graph;
  3. canonicalise the graphs and count the classes modulo ALU labels (idea 3);
  4. symbolically evaluate each arm to a summary and diff it against its kernel
     spec (family 1).

  The decision rule, fixed before running:
  - at most about 20 classes: build the orbit route;
  - summaries match kernel specs on at least 80% of arms with at most about 25
    idioms: build the verified symbolic evaluator;
  - otherwise: the incumbent plus the frame route (ideas 2 and 5).

## 1. Unanchored footprints: register ports stay static, the heap is read through an adaptive query tree

**Acts on:**
- **(c)** R1-4 #1 (RCW), R1-3 #1 (Kernel), R1-6 #1 (Micro), R1-2 #2 (`View R`).
- **(b)** R1-5 #2 (the query-monad certificate lemma).

**The objection.** All four converged kernel types assume that *every location an
opcode reads is named by the instruction word*. That is what lets a type index
(`μ R W E`, `View R`, `Vector Value (wr e).length`) carry the footprint. It is
true of F1 and of H1–H4, because strings are values in `BcSem`. It is false from
F2 on. Three counterexamples:

- **`GETFIELD A B C`** reads `R[B]`, then the table object *at the address
  carried by the value* `R[B]`. With F4 metatables, `luaV_finishget` follows
  `__index` up to `MAXTAGLOOP` times **[check the name and the value, 2000]**.
  How many cells it reads, and which, depends on the values it reads.
- **`SETTABLE`/`SETFIELD`** can rehash (`luaH_resize`). That allocates and
  rewrites the node array, so the write set is value-dependent and unbounded.
- **`CLOSURE`, `NEWTABLE`, `CONCAT`** allocate, and `checkGC` may then run a GC
  step that frees objects and flips mark bits in reachable objects' headers.
  Those cells are outside any footprint the opcode declares.

The body type `List Value → Option (…)` cannot even *see* the heap. R1-6 #1
names the break ("the applicative part breaks and monadic appears") for
`CALL B=0`, but leaves it unsolved. The idea is to solve it now, at no cost to
F1, rather than migrate every kernel at F2.

**The idea.** Two strata, bolted together:

```lean
-- stratum 1: registers, static in the word (unchanged: Supported's analysis consumes it)
-- stratum 2: an object-granular abstract heap, queried adaptively
inductive HQ (α : Type) where
  | pure  (a : α)
  | load  (ℓ : Loc) (k : Option Obj → HQ α)   -- which ℓ may depend on earlier answers
  | fail
structure Kernel where
  rd    : List Nat                            -- static register reads
  edges : List (Nat × Mask)                   -- static register writes per edge
  body  : List Value → HQ (Σ e : Fin edges.length,
            Vector Value (edges[e].2.popCount) × HeapDelta × String)
-- HeapDelta: a list of (ℓ, Obj) writes plus fresh allocations
```

- The abstract heap is **object-granular**: `Loc ⇀ Obj`, where a table is one
  `Obj` holding a finite map, its metatable and its array/hash hint. So a rehash
  is one abstract write of one cell, and the physical node array exists only in
  the A1 representation.
- **GC is invisible in the spec.** The machine representation relates the
  abstract heap to the *reachable* physical heap, modulo GC header bits. So a
  collection step is the identity on the abstract side.

**Core rules.**

- **L-B1, static half:** unchanged. Register agreement on `rd` gives the same
  `body` input, exactly as in RCW.
- **L-B1, dynamic half: the certificate lemma, proved once by induction on `HQ`:**
  ```lean
  theorem HQ.cert (t : HQ α) (h h' : Heap) :
      t.run h = some (a, log) → (∀ ℓ ∈ log, h ℓ = h' ℓ) → t.run h' = some (a, log)
  ```
  The footprint is the *log*, which is computed. It is not a type index. Heap
  frame: every `ℓ` outside the delta is unchanged, by the definition of
  `applyDelta`.
- **L-B2:** `Step := graph of step?`, `Iff.rfl`, as in every converged idea.

**What it makes free.**

- At F2–F4, per-opcode heap footprint lemmas are free: the `GET*`/`SET*` families
  (8 opcodes), `NEWTABLE`, `SETLIST`, `LEN` on tables, `TFOR*`, `GETUPVAL`/
  `SETUPVAL` and `CLOSURE`. Each is a kernel whose heap reads are `load` nodes,
  and each costs 0 footprint lines.
- The kernel type does not have to change at F2, so R1's refactor is paid once.
- `Supported`'s register analysis never learns about the heap. That is correct,
  since definite initialisation is a register property.

**What it costs.**

- About 60 lines for `HQ`, `run`, `cert` and `applyDelta`'s frame lemma.
- In F1 every body is `pure …`, so there are about 39 extra `pure` wrappers.
- Harder: the value domain grows `Loc`s. **Observable addresses**
  (`tostring({})` prints `table: 0x…`) make allocation a *choice* the spec cannot
  make. That is idea 4.
- A1 gains a real obligation: the physical heap represents the abstract one
  *modulo GC metadata*. The frame of every heap-reading arm has to be stated
  modulo mark bits. This is the honest cost, and it exists under any
  abstraction.

**Theories.**

- *Known, domain theory:* Berry and Curien, "Sequential algorithms on concrete
  data structures", TCS 20 (1982). A sequential algorithm is an adaptive query
  tree: the next cell it asks for depends on earlier answers. It is determined
  by the cells it actually queried. `HQ.cert` is the one-run version.
- *Known, program verification:* Kassios, "Dynamic frames: support for framing,
  dependencies and sharing without restrictions", FM 2006. Frames are *sets
  computed from the state*, not declared statically. The log is a dynamic frame.
- *Known, databases:* Rajaraman, Sagiv and Ullman, "Answering queries using
  templates with binding patterns", PODS 1995 **[check]**. A source can be
  accessed only once some attributes are bound, so plans are adaptive. The
  register ports are the bound attributes, and the heap is the source with an
  access pattern.
- *Novel, ethology as analogy:* a philanthid wasp does not scan the field. It
  follows its prey, and where it looks next depends on what it saw. That is
  the monadic heap stratum. The static register stratum is the nest it always
  returns to.

**Pilot.**

- **H1–H4:** bodies are `pure`, so the held-out cost equals RCW's (0 metatheory
  lines). The measurement that matters is *regression*: the extra lines and
  kernel-check time of the `pure` wrappers.
- **Discriminating check:** a toy F2 slice with 2–3 abstract objects and three
  kernels:
  - `NEWTABLE`;
  - `SETFIELD`, which may "resize", so one abstract write;
  - `GETFIELD` with a 2-hop `__index` chain.

  L-B1-dyn must be `HQ.cert` applied, with 0 per-opcode lines.
- **Smallest falsifier:** `HQ` plus `cert` plus the `GETFIELD`-with-chain
  kernel, about 80 lines. If the chain's footprint needs a per-opcode lemma, or
  `cert`'s log forces a physical-heap granularity, the idea fails.

**Seed.** *unanchored* (heap locations are not anchored to word fields),
*philanthid* (adaptive pursuit), *handbolt* (two strata bolted into one
kernel).

## 2. Kill sets: edges carry (target, def, kill), and one don't-care theorem replaces `keepMask` and CONCAT's garbage

**Acts on:**
- **(c)** R1-5 #1: `outs = [(pc+1, [A])]` for CONCAT, which SUITE H2 says is
  unfaithful.
- **(c)** R1-3 #1, R1-4 #1, R1-6 #1: their types force a *value* for every
  written slot.
- **(b)** R1-6 #5 (`havoc_ni`) and R1-1 #3 (X-values), done without changing
  `Value`.

**The objection, with a concrete counterexample.** SUITE H2 fixes CONCAT's write
set as the whole range `R[A..A+B-1]`. A kernel whose type is
`Vector Value (wr e).length` must then say *what* ends up in `R[A+1..]`. That
depends on `luaV_concat`'s pass structure.

Take `"a" .. 1 .. ""`: `CONCAT A 3` with `R[A]="a"`, `R[A+1]=1`, `R[A+2]=""`.
Pass 1 sees an empty string on top, so it only runs `tostring(top-2)`, and
`R[A+1]` becomes the string `"1"`. Pass 2 concatenates into `R[A]`. The final
state is `R[A]="a1"`, `R[A+1]="1"`, `R[A+2]=""`. **[check against
`lvm.c` `luaV_concat`, the `isemptystr` branch]**

So every RCW, Kernel or Micro kernel has two choices:

- replicate `luaV_concat`'s passes, including the empty-string special cases,
  inside the kernel, which ties the trusted spec to lvm internals;
- or be wrong at L-C1.

Writing `{A}` alone (R1-5 #1) makes L-B1 true for the spec but false for the
machine.

The same problem exists already, handled ad hoc. `CALL` clobbers everything
above its results. `Step.callPrint` pretends it does not, and `keepMask`
special-cases `CALL` inside `sweep`. After that, `cbcSem_iff` proves it does not
matter.

**The idea.** One edge schema for both, and for everything F3 adds (Lua calls,
`VARARG`, `TFORCALL`'s copies):

```lean
structure Edge where
  tgt  : Nat
  def_ : Mask     -- the spec writes these (L-B1's write set)
  kill : Mask     -- the machine may leave anything here; the spec leaves them unchanged
-- sweep:  st[t] ⊇ ((st[pc] \ kill) ∪ def)     -- keepMask disappears
```

- `CONCAT A B`: `def = {A}`, `kill = rmask (A+1) (B-1)`. The kernel computes
  only the right fold into `R[A]`.
- `CALL print`: `def = results`, `kill = everything ≥ A outside the results`.
- The spec is still deterministic, `step?` is still a function, and L-B1 holds
  with write set `def`.
- The SUITE's "whole range" is honoured as `def ∪ kill`.

**Core rules.**

- **The don't-care theorem, proved once, replacing `cbcSem_iff`'s CALL-specific
  argument:**
  ```lean
  -- StepH γ: take Step, then overwrite each killed slot with γ (any function of the run so far)
  theorem dontCare (hs : Supported p) (γ : Havoc) : BcSemH γ p out ↔ BcSem p out
  ```
  The proof is one induction on `Steps`. The invariant is agreement on the
  must-mask, and each step uses L-B1 with `reads w ⊆ st[pc]` and
  `st[t] ⊆ (st[pc] \ kill) ∪ def`. There is no per-opcode content, because
  kills enter only through the edge.
- **L-C1's representation relation becomes must-mask agreement.** A machine
  state represents `s` at `pc` if it agrees on `st[pc]` (R1-6 #5's LowEq, with
  the mask *computed from kill sets*). The CONCAT arm then needs to establish
  only `R[A]`. The CALL arm needs to establish nothing above its results.

**What it makes free.**

- H2's garbage question disappears from the trusted spec. CONCAT's kernel is
  the fold, about 5 lines.
- `keepMask` and the CALL case of `cbcSem_iff` become instances of `dontCare`.
- At A1, the "which garbage did `luaV_concat`/`luaD_call` leave" clauses of the
  CONCAT and CALL arms go away. Among the arms, those clauses are the likeliest
  to need unbounded reasoning, because `luaV_concat` loops.
- At F3, `OP_CALL` of a Lua function (callee frames overwrite everything above
  the base) is one more kill set, with no new theorem.

**What it costs.**

- Rewiring `Edge`, `sweep` and `edgesOf` (about 30 definition lines), and
  re-proving `dontCare` in place of the existing definite-initialisation
  lifting. That is R1's measure.
- The analysis gets slightly *stricter*: a program that reads `R[A+1]` after a
  CONCAT is rejected. `luac` never does this, because CONCAT's operands are
  temporaries freed by `freeexps` **[check `lcode.c`]**, but it has to be
  measured.
- The theorem is only as good as `Supported`. The spec now *licenses* garbage,
  so a bug in the must-analysis becomes a soundness hole rather than an
  incompleteness. Mitigation: `dontCare` is kernel-checked, so the hole cannot
  hide.

**Theories.**

- *Known, hardware logic synthesis:* observability don't-cares. Where an output
  of a sub-circuit is not observable, the synthesiser may implement any value
  there. Bartlett, Brayton, Hachtel, Jacoby, Morrison, Rudell,
  Sangiovanni-Vincentelli, Wang, "Multilevel logic minimization using implicit
  don't cares", IEEE TCAD 7(6), 1988 **[check]**. `kill` is the ODC set of an
  instruction, and `dontCare` is the theorem that the implementation may fill
  it freely.
- *Known, molecular evolution:* Kimura, "Evolutionary rate at the molecular
  level", Nature 217 (1968). Mutations at sites that do not affect the
  phenotype are neutral and drift freely. Killed slots are neutral sites, and
  the must-mask is the phenotype.
- *Known, compilers:* Kildall, POPL 1973. The transfer function
  `(st \ kill) ∪ gen` is the gen/kill form of the monotone framework. The
  vocabulary is borrowed literally, and `keepMask` was a hand-inlined kill.

**Pilot.**

- **H2:** a CONCAT kernel with `def = {A}` and `kill = rmask (A+1) (B-1)`. Count
  kernel lines plus the `edgesOf` line, with 0 metatheory lines.
- **R1:** `cbcSem_iff` and `bcSemFrom_iff` become `dontCare` instances. Measure
  those files before and after.
- **Smallest falsifier, two checks with no Lean proof:**
  1. Run the kill-set must-analysis over the difftest corpus and
     `f4_strlite.lua`'s `luac` output. Any rejection falsifies the claim that
     luac never reads killed slots.
  2. Extend `abstractions/checks/FootprintLaw.lean`'s random runs with a havoc
     step on kill sets, and check that `BcSem` outputs are unchanged on
     supported programs.

**Seed.** *abstersive* and *unmoiled* (the spec is cleansed of garbage it
would otherwise have to describe), *logroll* (`CALL` and `CONCAT` trade support
for one kill mechanism, instead of each keeping its own special case).

## 3. Orbits of dependence graphs, not of instruction text (L-C1 by canonical forms)

**Acts on:**
- **(c)** R1-5 #4 and R1-6 #4: text orbits. `Relabel = shift + positional
  instruction substitution` cannot absorb the coordinator's findings: ADD vs SUB
  differ in a branch sense, and MUL vs MULK differ in register allocation and
  scheduling.
- **(c)** R1-3 #2: anti-unified templates, for the same reason.
- **(b)** R1-1 #5: Mazurkiewicz independence, generalised to whole dependence
  graphs.

**The objection.** The coordinator's check found:

- BAND, BOR and BXOR are instruction-identical on their opening code, and so
  are LTI/LEI/GTI/GEI, ADDK/SUBK and LT/LE. The orbits are real.
- ADD vs SUB differ in *one branch sense*. gcc laid the fast path on the other
  side of a `beq`/`bne`.
- MUL vs MULK differ in *register allocation and scheduling*.

All three are *presentation* differences: block layout, register names, and a
topological order. They are not *dependence* differences. A quotient taken on
the text sees three orbits where there is one, so it degrades toward the
incumbent exactly on the arithmetic family, which is the largest.

**The idea.** Quotient each arm by its **program dependence graph (PDG)**:

- **Nodes** are the arm's instructions from dispatch head to dispatch head. The
  arms are acyclic except inside callees, which are opaque nodes carrying a
  contract.
- **Data edges** follow SSA def-use, so register allocation vanishes.
- **Memory edges** order every pair of accesses that may alias. Two accesses
  off the same base register at different constant offsets are independent;
  everything else is ordered. This is conservative about symbolic register
  indices (`R[A]` vs `R[B]` may alias), which is where R1-1 #5's plain
  "independent writes commute" needed a qualifier.
- **Control edges** are labelled by a normalised predicate: `bne x y →T L` is
  written `beq x y →F L`, so branch sense vanishes. Scheduling vanishes because
  a PDG has no order beyond its edges.

An orbit is a class of arms whose **canonical PDG** is equal, up to a hole set
of ALU node labels (`add sub and or xor mul sll srl`).

**Core rules.**

- **L-C1 through one adequacy theorem, proved once for the RV64 subset:**
  ```lean
  theorem pdg_adequate (a b : Arm) (π : PDGIso a b) :
      ∀ m, AtHead m → runHead a m ≈ runHead b m    -- same live-out registers and memory
  ```
  The proof has three parts:
  - any two linearisations of one DAG agree: Mazurkiewicz commutation of
    independent nodes;
  - SSA renaming is invisible after the arm, because only live-outs count;
  - a normalised branch is the same branch.
- **Transport:** `ArmSim rep → PDGIso(arm_o, rep)[hole ↦ op_o] → Alu op_o ⊨ κ_o → ArmSim o`.
  Per member, the obligation is a *certificate* (a node bijection) checked by
  `decide`, plus one ALU refinement lemma such as `sub ⊨ (· - ·)` on
  `BitVec 64`, which the Sail semantics nearly gives for free.
- The representative of each orbit is proved in the incumbent style, or by
  ideas 2 and 5's smaller contract.

**What it makes free.** The A1 cost becomes
`#orbits × incumbent-arm + #arms × (certificate + ALU lemma)`. My forecast
**[check with the script]**:

- arith rr (ADD SUB MUL BAND BOR BXOR SHL SHR);
- arith rk (ADDK SUBK MULK BANDK BORK BXORK);
- arith ri (ADDI);
- SHRI and SHLI;
- MOD and IDIV (both call helpers);
- order rr;
- order ri;
- EQ;
- EQK and EQI;
- TEST and TESTSET;
- the loads;
- FORPREP;
- FORLOOP;
- CALL;
- JMP;
- the RETURNs.

That is about 17 orbits for 54 arms. The saving is in the arithmetic family,
which is exactly where the text orbits fail.

**What it costs.**

- `pdg_adequate` over RV64 with memory. I estimate 500–900 lines: SSA over
  machine registers, an alias rule for base+offset, and the commutation
  argument. That is less than a verified symbolic evaluator (R1-2 #5) because
  the check never interprets ALU semantics: it compares arm against arm, never
  arm against spec.
- Canonical labelling has to be *computed* inside Lean if the certificate is
  checked by `decide`. Checking a given bijection is enough, and that is cheap.
  Finding it can be done outside Lean.
- **It does nothing for the three held-out A1 arms.** ADD, EQI and FORLOOP are
  representatives of three different orbits, so the held-out A1 cost is
  unchanged. Honestly, the win shows only in the *marginal* cost of SUB, BAND,
  MUL and MULK.
- It is the "contumacious" arms that decide. If gcc chose a different
  *instruction selection* for one member (for example strength-reducing a MUL
  by a constant K), that member is its own orbit. The cost is never above the
  incumbent's.

**Theories.**

- *Known, programming languages:* Horwitz, Prins and Reps, "On the adequacy of
  program dependence graphs for representing programs", POPL 1988. Programs
  with isomorphic PDGs are equivalent. Also Ferrante, Ottenstein and Warren,
  "The program dependence graph and its use in optimization", TOPLAS 9(3)
  (1987). `pdg_adequate` is their theorem, specialised to acyclic machine code
  with a base+offset alias rule.
- *Known, chemistry:* canonical labelling of molecular graphs. H. L. Morgan,
  "The generation of a unique machine description for chemical structures", J.
  Chem. Doc. 5(2) (1965). Weininger, Weininger and Weininger, "SMILES. 2.
  Algorithm for generation of unique SMILES notation", J. Chem. Inf. Comput.
  Sci. 29 (1989). Isomers written in different atom orders get one canonical
  string. That is the same move as scheduling and renaming variants of one arm
  getting one canonical PDG.
- *Known, mineralogy:* Mitscherlich's law of isomorphism (1819) **[check the
  date]**. Substances of analogous composition crystallise in the same form. An
  orbit is a crystal form, and the ALU op is the substituted cation.
- *Known, algorithms:* McKay, "Practical graph isomorphism", Congressus
  Numerantium 30 (1981). This is the tool for the outside-Lean canonicaliser.

**Pilot.**

- **Falsifier first:** the ELF script from "Positions" above, with no Lean.
  Report:
  - the class count;
  - whether ADD≅SUB, MUL≅ADD and MULK≅ADDK modulo the hole;
  - which arms are singletons.

  If there are more than about 30 classes, abandon the idea.
- **Then** the incumbent ADD proof (the held-out A1 arm), plus `pdg_adequate`
  for the instruction subset that ADD, SUB and MUL use. Report the marginal
  lines of SUB, MUL, BAND, BOR and BXOR (target: under 10 each).
- **EQI and FORLOOP** are measured as orbit setup only.

**Seed.** *globosite* (a mineral, so crystal forms and Mitscherlich
isomorphism), *contumacity* (MUL/MULK stubbornly refusing the text orbit),
*seriality* (the serial order of a schedule is not the thing), *pharyngology*
(the dispatch head is the throat that bounds every arm).

## 4. Oracle ports: implementation-defined choice as an input, so every converged theorem survives F2 unchanged

**Acts on:**
- **(c)** R1-3 #3: the rulebook grows a `choose` node for F2 non-determinism and
  gives up `Graph.det` for the arms that use it.
- **(a)** R1-4 #1 and R1-4 #2 (RCW and construct trees), extended to
  non-determinism.
- **(c)** the silent assumption in all six round-1 answers that `step?` stays a
  function.

**The objection.** F2 and F4 bring choices the spec must not make:

- `next` order depends on the hash layout. The layout depends on insertion
  history, resizes, and the string-hash **seed** `luai_makeseed`, which Lua
  5.4 mixes from addresses and `time` **[check `lstate.c`]**. Bare metal may fix
  it, but the spec should not bake that in.
- `tostring` of a table or closure prints its **address**.
- `Host.showBuiltin` already parameterises one such rendering. It is the
  degenerate case of this idea.

If the choices are modelled *relationally* (a `choose` node, or several `Step`
rules), five things break together:

- L-B2: `step?` is no longer a function;
- L-A1: the graph becomes set-valued;
- BcSem determinism, which Layer B's backward TV needs;
- LuaSem determinism, which forward TV needs;
- per-program TV by evaluation, because both sides now denote *sets*.

**The idea.** Every implementation-defined choice is a read from an **oracle
port**. The oracle is a global parameter `O : Nat → Answer`, indexed by a
*choice cursor* `κ` that lives in the state next to `pc` and `out`:

```lean
structure State where pc : Nat; regs : Nat → Value; out : String; κ : Nat   -- κ: choices consumed
-- a kernel that chooses reads O κ as one more input and bumps κ
variable (O : Nat → Answer)
def step? (O) … ; inductive Step (O) … ; def BcSem (O) … ; def LuaSem (O) …
```

For fixed `O`, both semantics are functions again, so **every converged theorem
holds verbatim with an extra parameter**:

- RCW footprint, with `κ` in the agreement set beside `pc` and `out`;
- `Graph_iff_run`;
- `holds_det`;
- the kill-set `dontCare` of idea 2.

**Core rules.**

- **Determinism per oracle:** `Sem O c out₁ → Sem O c out₂ → out₁ = out₂`. No
  new proof: it is the old one under `variable (O)`.
- **The layers meet at the same oracle.**
  - *Layer B* (compile refinement) becomes `∀ O, Valid O → (LuaSem O s out ↔ BcSem O p out)`.
    Its simulation invariant gains one conjunct: equal cursors. Source `pairs`
    iterations and `TFORCALL`s, and constructors and `NEWTABLE`s, consume
    choices in the same order.
  - *Layer A* (the machine refines bytecode) picks the machine's own answers as
    a **prophecy**: `O_c n :=` the answer the Sail run from `c` gives at its
    `n`-th choice event. This is well defined because Sail is deterministic,
    and it is classical, which the axiom policy allows. The statement is
    `BcSem O_c p out ↔ Halts c out`, plus `Valid O_c`.
  - **End to end:** `LuaSem O_c s out ↔ Halts c out`.
- **`Valid O`** keeps the spec non-vacuous. For example, the answers of `next`
  over one traversal enumerate each key of the table exactly once. `Valid O_c`
  is *one* callee contract at A1, about `luaH_next`, proved once.

**What it makes free.**

- Every metatheory theorem of the converged ideas carries over to F2–F4
  unchanged. Non-determinism costs a parameter, not a new logic.
- No `choose` node, no set-valued interpreter, no loss of `Graph.det`.
- Host renderings (`function: 0x…`, `table: 0x…`) become oracle answers, with
  no new `Host` fields per fragment.

**What it costs.**

- **Per-program TV by evaluation stops working for programs whose output
  depends on a choice.** With `O` a variable, `luaRun O` gets stuck at
  `match O κ with`. A `pairs` loop over k keys has k! valid orders. This cost
  belongs to *any* treatment of `next` order. The oracle form makes it
  explicit and turns it into a simulation invariant (equal cursors), which a
  real compiler-correctness proof, the planned later instance of Layer B,
  discharges once.
- Tape alignment is a real assumption about `luac`: it must never introduce or
  reorder a choice event. That holds for F2's `NEWTABLE`/`TFORCALL`/`tostring`.
  At F4, `__gc` finalisers run at GC-determined times, and that breaks it. They
  need their own oracle (when finalisers run), which is again an input.
- Threading `O` through the section variables costs about 10 lines.

**Theories.**

- *Known, concurrency and refinement:* Abadi and Lamport, "The existence of
  refinement mappings", TCS 82(2) (1991). Prophecy variables make a
  specification's future choices available now. `O_c` is a prophecy extracted
  from the implementation's run.
- *Known, complexity theory:* the random-tape formulation of probabilistic
  computation. A probabilistic machine is a deterministic machine reading an
  extra tape (e.g. Arora and Barak, *Computational Complexity: A Modern
  Approach*, 2009, ch. 7). Here the tape is adversarial rather than random,
  and determinism is recovered per tape.
- *Known, physics, as a design principle:* hidden-variable interpretations
  (Bohm, "A suggested interpretation of the quantum theory in terms of
  'hidden' variables", Phys. Rev. 85, 1952). Apparent indeterminism is a
  deterministic evolution with an unobserved parameter. The spec is
  deterministic in `(program, O)`.
- *Known, nearest precedent (not distant):* CompCert's `determinate` semantics
  with external calls answered by the environment **[check `Smallstep.v`]**.

**Pilot.**

- **H1–H4** have no choices. Measure the *regression* of threading `O` and `κ`:
  the target is under 15 lines and no change to any held-out proof.
- **Discriminating check (F2-forward):** a two-key
  `for k in pairs{a=1,b=2} do print(k) end`. It needs:
  - one source rule and one `TFORCALL` kernel reading `O κ`;
  - the cursor-alignment invariant;
  - `Valid` for a two-element table.

  The number to watch is the per-program TV lines under `∀ O, Valid O`. If they
  exceed about 30 for this toy, per-program TV is dead for F2 *under any
  abstraction*, and Layer B's compiler-correctness instance has to move
  earlier. That is worth knowing before F2 starts.

**Seed.** *starward* (steer by an outside reference: the oracle),
*Susuhunan* and *unauthoritativeness* (a sovereign that decides, and a spec
that declines to), *reasoned* (the choice is still reasoned about, as an
input).

## 5. Content-named strings: an authoritative intern map makes the representation sort-erased and EQ-by-pointer a lemma

**Acts on:**
- **(c)** R1-5 #5: fractional permissions for interned strings.
- **(a)** R1-1 #5, which listed "equal short strings ⇒ same object" as a
  cost; here it becomes the abstraction.
- **(b)** R1-4 #5 (the sort-erased core) combined with R1-3 #5 (lens view).

**The objection.** R1-5 #5 proposes fractional (shared read-only) ownership of
`TString` objects, because interning makes the heap shared. That gives
*sharing* but not *injectivity*, and the machine's `EQ` on short strings needs
injectivity. `EQ` compares short strings **by pointer** (`eqshrstr`) and long
ones with `memcmp` **[check `lstring.h`/`lvm.c`]**. So the representation must
guarantee:

> equal contents ⇔ equal pointers, for live short strings.

That is a global invariant, not a permission. It also has to survive GC. A
dead short string is swept, and its address can later hold a different string.
Any *persistent* points-to `ptr ↦ "abc"` then becomes false. Persistence plus
address reuse is unsound, which is the quillet reallocated to a new holder.

**The idea.** Name strings by **content**, never by address, on the spec side,
which `Value.str (List UInt8)` already does. Put the address link in one ghost
object:

- `Σ : List UInt8 ⇀ Addr`, an authoritative, **injective** partial map for live
  short strings.
- The machine's `G->strt` hash table represents `Σ` exactly.
- The value encoding is parameterised by `Σ`:
  `enc Σ (.str s) = (tag short, Σ s)` for `|s| ≤ 40` **[check
  `LUAI_MAXSHORTLEN`]**, and `(tag long, p)` with `p ↦ s` for long strings.
  Integers, booleans and nil ignore `Σ`.

At every moment the representation reads the *current* `Σ`. It never
remembers an address. So a swept address that gets reused confuses nothing:
the spec never knew it.

**Core rules.**

- **`enc_inj`:** `enc Σ (.str s) = enc Σ (.str t) → s = t` for short `s, t`,
  from `Σ`'s injectivity. Proved once. The EQ arm's string case is this lemma.
- **Sort-erased moves:** `Rep Σ` relates a 16-byte `TValue` to a `Value`
  uniformly, so *copying* a `TValue` preserves `Rep` for every sort. The
  lemma is proved once. MOVE, LOADK, TESTSET's copy and CALL's argument copies
  are then sort-parametric: their existing integer proofs, stated over `Rep Σ`,
  cover strings with no new line.
- **GC stability:** a sweep removes `Σ` entries only for contents unreachable
  from the roots. The register window and the constants are roots, so `Rep Σ`
  on live slots is preserved. This is one lemma about the sweep contract.
- **Allocation:** `luaS_newlstr` for short `s` either returns `Σ s` or extends
  `Σ` with a fresh address. One callee contract covers CONCAT's result and
  `tostring`'s result.

**What it makes free.**

- **H1 at the machine level.** LOADK of a string constant is a `TValue` copy
  from `k[]`. The constants were interned at load by `luaU_undump` →
  `luaS_newlstr` **[check]**, so the existing LOADK arm proof covers it with 0
  lines, once `Rep` is stated over `Σ`.
- **String EQ at the machine level** is `enc_inj`. There is one lemma, and no
  per-arm reasoning about pointers.
- **H4 at the machine level** is one callee contract on `l_strcmp`: under the C
  locale, `strcoll` is byte order **[check the libc in the ELF]**.
- **Later sorts:** tables and closures are *address*-named, with identity as
  the pointer. They get a trivially injective `Σ`, so the same `Rep`
  parameterisation serves them.

**What it costs.**

- Defining `Σ`'s representation against `G->strt` (bucket array, chaining,
  resize) is the one real setup. It is a data-structure proof, done once, with
  the resize inside `luaS_resize`'s contract.
- GC contracts are unavoidable once strings allocate. This idea only makes sure
  they are stated *once*, on `Σ`, instead of inside each arm.
- It is not in the held-out A1 arms (ADD, EQI and FORLOOP never see a string).
  It pays off on `f4_strlite`'s end-to-end kernel validation and on the F4 arms.

**Theories.**

- *Known, functional programming:* hash consing. Structurally equal values
  share one representative, so equality is pointer equality. Filliâtre and
  Conchon, "Type-safe modular hash-consing", ML Workshop 2006. The origin is
  usually credited to Ershov (1958) **[check]**. `Σ` is the hash-cons table as
  a ghost.
- *Known, philosophy of language:* Peirce's type/token distinction **[check the
  Collected Papers reference, 4.537]**. The spec speaks of types (contents) and
  the machine holds tokens (addresses). Interning is the invariant that, for
  short strings, type determines token *at each moment*.
- *Known, databases:* natural keys against surrogate keys. Codd, "Extending the
  database relational model to capture more meaning", ACM TODS 4(4) (1979).
  Contents are the natural key and addresses the surrogate. The spec keys by
  the natural key, so surrogate reuse after deletion is harmless.
- *Known, separation logic:* the authoritative resource algebra. Jung, Krebbers,
  Jourdan, Bizjak, Birkedal, Dreyer, "Iris from the ground up", JFP 28 (2018).
  `Σ` is `Auth` over an injective map, and fragments are handed to arms only as
  "`s` is live".
- *Novel, land tenure as analogy:* runrig and quillet strips. The field is
  reallocated each season, so a claim must name the holder by lineage, not by
  strip. That is the reason content-naming survives address reuse.

**Pilot.**

- **H cases (bytecode side):** no change; 0 lines, since strings are already
  content-named values.
- **The smallest machine-side build:**
  - `enc Σ` for nil, bool, int and short strings;
  - `enc_inj`;
  - the existing LOADK arm proof, restated over `Rep Σ`, with the line delta
    measured (target 0 new lines);
  - the EQ arm's string case from `enc_inj`.
- **Falsifier:** confirm in the ELF that `luaS_newlstr` interns every string of
  at most `LUAI_MAXSHORTLEN` bytes created by CONCAT and by `lundump`, and that
  `EQ` on two short strings is a pointer compare with no fallback. If CONCAT
  results of 40 bytes or fewer are *not* interned, `enc_inj` is false for
  them. **[check the `luaV_concat` short-buffer path]**

**Seed.** *quillet* and *carse* (strips of common land reallocated, so address
reuse), *Nishada* and *Motozintleca* (peoples named by who they are, not where
they live: content-naming), *unlensed* (the representation reads the current
`Σ` directly, with no cached view of an old address).

## How the five fit

- **Ideas 1 and 4** are what the converged kernel and rulebook family needs to
  survive F2. Idea 1 handles the heap footprint and idea 4 non-determinism.
  Both cost almost nothing on H1–H4. They are measured as *regression* now and
  as savings later.
- **Idea 2** is the one that changes the held-out H2 *spec*, and it simplifies
  it. It also removes the garbage clauses from the CONCAT and CALL arms at A1.
- **Idea 3** is the only one here that cuts the *count* of A1 arm proofs. Its
  falsifier is a script. It does not help the three held-out A1 arms, and that
  should be stated in the bake-off.

  strings exist. It is the machine-side twin of R1-4 #5's sort-erased core.
