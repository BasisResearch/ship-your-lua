## 1. Re-witness, don't widen: the `∃ w` in `VmRel` is already the gauge

**Acts on:**

- **(b)** It merges six round-1 ideas that are the same mechanism under different names:
  - R3-R1-1 #2 (gauge set Γ);
  - R3-R1-5 #2 (`Dead`, `Win'`);
  - R3-R1-4 #5 (ring 2);
  - R3-R1-3 #2 (owner frames and the phase invariant);
  - R3-R1-2 #1 (the `protect` Δ-generator);
  - R3-R1-4 #1 R3 (`supp Inv`).

  All six say: *the complement's support excludes a set D*.
- **(c)** It objects to how two of them place D.

### The idea

`VmRel p c s := ∃ w, VmRelAt p c s w`, and `Core.frame` compares memory outside `Win` with **`w.mo`**. So an arm that stores into D does not need D to enter `Win`, a Γ, a ring or an owner map. It closes with a **new witness**:

```
w' := { w with mo := rebase w.mo c'.σ.mem D }
rebase mo m D a := if a ∈ D then m[a]? else mo[a]?
```

`Core.frame` for `w'` then holds by definition on D, and unchanged off D. The one generic obligation is that the complement survives the change of `mo` on D.

**The objections.**

- **To R3-R1-5 #2 (`Win' = Win ∪ Dead`).**
  - `Ranges.ci_out` states `∀ a ∈ [ci, ci+ciSize), ¬ Win p w a`. Adding `ci+32` (savedpc) to the window falsifies `ci_out` as written.
  - Every use of `ci_out`, such as `Core.trap` reading `ci+40` through `frame`, would have to be re-proved against a window with a hole in `ci`.
  - Re-witnessing changes neither `Win` nor `Ranges`.
- **To R3-R1-1 #2's phase gauge ("`L->top` is gauge at pc ≠ 0").**
  - This is false beyond F1. OP_CALL with `C = 0` (and VARARG with `C = 0`) leaves `L->top` pointing past the results. The next CALL, RETURN or SETLIST with `B = 0` reads it (see the `if (b != 0)` guard at lvm.c:1678, 1697).
  - So `L->top` is live across a head at pc ≠ 0. D must be keyed by the *incoming kernel edge* (did the last instruction's edge declare open results?), not by pc.
  - F1 is safe only because `opKernel` requires `w.b ≠ 0 ∧ w.c ≠ 0` for CALL.
- **To "dead cells absorb the widening" (R3-R1-5 #2, R3-R1-1 #2).** By N6, `ci->next` is broken by the first CALL and is *read* afterwards, so it cannot be dead. It needs a disjunctive **phase fact**, `ci->next = 0 ∨ CIAt ci->next`.
  - R3-R1-3 #2's phase invariant (`L->top = func+16 ∨ L->top = ci->top`) is therefore the general form.
  - A dead cell is the special case whose phase fact is `True`.
  - So the rule below takes a `PhaseOk` premise instead of a dead set.

### Core rules

- **L-C6′ (non-def part) becomes `Complement.rebase`.** One theorem:

  ```
  Complement.rebase :
    Complement p w → (∀ a ∉ D w, m'[a]? = w.mo[a]?) → PhaseOk p w m' →
    Complement p { w with mo := m' }
  ```

  - `D w = [ci+savedpcOff, +8) ∪ [L+topOff, +8) ∪ [sp − Kc, sp)` in F1. `ci+nextOff` joins D at CALL.
  - `PhaseOk` is a list of per-field disjunctions:
    - `L->top ∈ {func+16, ci->top}`;
    - `ci->next = 0 ∨ …`.
  - `LuaStateAt.top` and `LuaStateAt.next` become those disjunctions. That is one edit, and entry still takes the left disjunct.
- **The same rule absorbs the `func` move (extending R3-R1-5 #4 and R3-R1-3 #2 `reloc_inv`).**
  - VARARGPREP's `luaT_adjustvarargs` moves `ci->func`. VARARGPREP is the one F1 relocating arm.
  - Because `w.func` is also a component of the existential, the arm closes with `w' := {w with func := func', mo := …}`.
  - The cost is re-proving `Ranges` at the new base: `base_lo`, `base_hi`, `frame_sep`, and `*_out` because `Slots` moved. That is one lemma, `Ranges.shift`.
  - No `decode_reloc` is needed, because nothing decodes. The witness moves.
- **L-C3′ runtime becomes:** a runtime callee's footprint is D plus `Slots ≥ A`. Its effect on `PhaseOk` is one disjunct per field.

### What it makes free

- **(d1) `savedpc`/`L->top`:** 0 lines per arm (MOD, MODK, IDIV, IDIVK, EQ, EQK, LT, LE, FORPREP, MMBIN*). No `VmRel` field is added.
- **Callee frames below `sp`.** `luaV_equalobj` has a 48-byte frame; the soft-int helpers have none (R3-R1-5 F-a).
- **VARARGPREP's relocation:** one `Ranges.shift`, instead of a new field.
- **No change to `Win`, `Ranges` or `Core.frame`,** so all 25 proved arms are untouched.

### What it costs

- `Complement.rebase`, about 60–100 lines. There is one case per `Complement`, `LuaStateAt`, `HeapAt` and `ErrorJmpAt` field, each by address disjointness from D.
- **The real risk.** `L` and `ci` are heap objects: `lua_newstate` allocates through `l_alloc`, and `luaE_extendCI` mallocs the `ci`.
  - If `DlHeap.HeapAt` constrains chunk *payload* bytes, and not only headers and bins, then D overlaps its support. `rebase` then needs a payload-frame lemma for `HeapAt`.
  - That is a one-time cost, but it could double the setup. This is falsifier F2 below.
- **Harder:** `PhaseOk` grows one disjunct per runtime-evolving field (`next`, later `nci`, `GCdebt`, …). That growth is additive, but it is real.

### Theories

- **Known, distant (economics):** chain-linked price indices. The base period is re-chosen at every link, so drift never accumulates against a fixed base. (Recalled: ILO/IMF *Consumer Price Index Manual*, 2004; check.) `w.mo` is the base period, and an arm is one link.
- **Known (program logic):** frame-preserving updates of ghost state. `mo` is ghost state, and re-witnessing is an update that no assertion outside D observes. (Recalled: Jung et al., "Iris from the ground up", JFP 2018; check.)
- **Known (rely-guarantee):** stability of an assertion under a rely (Jones 1983). `rebase` is `Complement`'s stability proof under "writes to D that satisfy `PhaseOk`".
- **Novel:** using the relation's existing existential as the gauge, so that neither the window nor the ranges change. Also: phase disjunctions as the general case, with dead cells as the trivial disjunct.

### Pilot

- **Build first:** `rebase`, `Complement.rebase` restricted to the fields that D can touch, and the `LuaStateAt.top` disjunction.
- **MOD:** the close is `⟨w', hc.comp.rebase (by simp [D]; omega) phase_protect⟩`, about 2 lines. Both edges carry it, because the Protect stores come before the tag test.
- **EQ:** the same, with the frame of `luaV_equalobj` inside D.
- **MUL:** nothing, since `__muldi3` touches no memory. **ADD:** nothing, so it is the control.
- **Measure:** Protect lines in MOD and EQ, against the forecast widening of 100–250.

### Seed

`BSq` is the only exact repeat in the string, and `SqS` follows it: the same record comes back with one letter moved. The witness `w` recurs, with only `mo` (or `func`) changed. It is not widened.

## 2. Canonical roots: make `ValRepr` equality-reflecting on the view, not the heap

**Acts on:**

- **(a)** It extends R3-R1-5 #1 (`decode_canon`), with a sharper condition from N2.
- **(c)** It objects to R3-R1-2 #2 (FactorGuard) and R3-R1-1 #4 (α-guard), which treat EQ's test as a guard that factors through `ValRepr`: as `ValRepr` stands, the test does not factor.
- **(b)** It combines with the pure call rule of R3-R1-3 #4.

### The idea

The EQ callee tests `ttypetag` first (N1). For `luaV_equalobj(x, y) = [δ.eq x y]` to hold, `ValRepr` must be **functional on tags** for every value that can meet another in a comparison. Pointers must also determine string contents. The coordinator already flagged the nil tag and interning. This idea adds the variant-by-length rule, and places interning where it is cheapest.

- **Canonical tags, as a tightening of `ValRepr`'s constructors** (not a new relation field):
  - `nil`: `t = 0`, instead of `t % 16 = 0`;
  - `str`: `t = if len s ≤ 40 then vShrStr else vLngStr` (N2);
  - bool, int and `print` are already exact.
- **Interning, stated pairwise on the roots.** Round 1 proposed a heap-wide "short strings are unique in the heap". Instead, state it only for the roots, the register slots and `K`:

  ```
  RootsCanon : ∀ r₁ r₂ ∈ roots, str₁ = str₂ ∧ len ≤ 40 → ptr r₁ = ptr r₂
  ```

  EQ compares roots only. The heap-wide fact is needed only where a *new* short string enters the roots, and that is CONCAT: `luaS_newlstr` → `internshrstr`, whose contract is the string-table lookup CONCAT needs anyway.

### Core rules

- **L-C3′ pure (for `luaV_equalobj`) becomes `eq_canon`:**

  ```
  eq_canon : ValReprC t₁ x₁ v₁ → ValReprC t₂ x₂ v₂ → RootsCanon … →
    ((t₁ ^^^ t₂) &&& 63 = 0 ∧ payloadEq t₁ x₁ x₂)  ↔  v₁ = v₂
  ```

  It is proved once, by the ≤ 7 F1 variant cases. This is the whole value half of the EQ summary (#4).
- **Preservation is a def-port obligation.**
  - Every arm whose def value is not a `.str` preserves `RootsCanon` by `simp`.
  - MOVE and TESTSET copy pointers.
  - LOADK takes a `K` pointer; `K` is in the roots already.
  - CONCAT is the only arm that pays.

### What it makes free

- The soundness gap is closed at EQ, EQK, LT and LE: `l_strcmp` also branches on variant for short strings.
- There is no heap-wide interning invariant in `Complement`, so `HeapAt` is untouched.
- Guards: FactorGuard's `Factors` instance for EQ's `xor`/`andi 63` test becomes `decide` over the 7 canonical tags.

### What it costs

- **Tightening `ValRepr.nil` touches every arm that *produces* nil** (LOADNIL and CALL's nil results). The producers store the literal 0, so each needs one extra `rfl`.
  - Arms that *consume* nil get a stronger hypothesis for free.
  - Constants: `kconst` must show that `K`'s nil has tag 0, which is true of the parser's `setnilvalue`.
- **`TStringRepr` must expose `len`.** R3-R1-4 recalled that it pins the length. Check this.
- **`RootsCanon` at entry.** At entry the roots are just `K`. The parser deduplicates constants (`addk` keys by value), and short constants are interned. So entry needs "`K`'s short strings are pairwise distinct in content, or equal in pointer". It should be decidable on the loaded image, but it is one lemma.
- **Harder:** long strings. `luaS_eqlngstr` → `memcmp` is a loop, so EQ on long strings needs a loop summary (#4). Two different constants with the same long content can exist, so the long case must go through content, which is correct.

### Theories

- **Known (programming languages):** hash-consing. Ershov 1958; Filliâtre and Conchon, "Type-safe modular hash-consing", ML Workshop 2006 (recalled; check). Interning is hash-consing, and pointer equality equals structural equality on the consed set.
- **Known, distant (library science):** authority control. Each entity has exactly one authorised heading, so string match on headings is identity. The rule is enforced at *cataloguing time* (the new record), not by re-scanning the catalogue, which is the analogue of CONCAT paying. (Recalled: the Library of Congress Name Authority File practice; check.)
- **Known (nominal techniques):** atoms are compared by identity (Pitts, *Nominal Sets*, 2013). A root is an atom.
- **Novel:** interning stated only on the *view's roots*, which are finitely many and already decoded, instead of on the heap. Also: the variant-by-length canonical tag, which δ's `Value.str` hides.

### Pilot

- **EQ:** `eq_canon` supplies `a0 = decide (v₁ = v₂)` as bit 0 or 1. Together with #4's summary, EQ's leaf is `docondjump`'s `edge := if (!c.isFalse) = k …` by `simp`.
- **Build first:**
  - the `ValRepr` tightening, and re-running the 25 proved arms (expect `rfl` fixes only);
  - `RootsCanon`;
  - `eq_canon` for nil, bool, int, `print` and short strings. Long strings are left as a hypothesis in the pilot and reported.
- **MUL, MOD, ADD:** these are unaffected, and measure the regression from the `ValRepr` edit (expected 0).

### Seed

`vCH`/`VCH`: the same letters, equal only after case folding. That is the exact failure: two values that are equal only after normalisation, where the machine compares *before* normalising. The clusters `90` and `01` are the canonical nil tag 0 and the `seqz` bit.

## 3. Tablebase tails: simulation up to proved continuations (join points as φ-annotated cut points)

**Acts on:**

- **(d)** No round-1 idea used the machine's *join* structure.
- **(c)** It objects to R3-R1-3 #5's "path merging: proof size is linear in leaves", and to the path-enumerating executors of R3-R1-2 #5 (KProd) and R3-R1-1 #4. Linear in leaves still means re-running the shared tail on every leaf.
- **(a)** It extends R3-R1-4 #4's "duplication" events: a duplication is exactly an in-edge of a join.

### The idea

GCC's arms share tails heavily (N5):

- the head, with 145 in-edges;
- the pc+1 tail `mv s11,s3; j head`, whose copies have more than 64 in-edges;
- two k-compare tails, with 8 in-edges each;
- two `donextjump` copies;
- MOD's store join at `0x8001f80c`, with 4 in-paths.

Prove **once per tail content** a *continuation lemma* whose precondition is a **kernel-level φ-annotation** on the tail's live registers. Then stop each arm proof as soon as it reaches a tail: this is simulation *up to* proved continuations.

```
tail_pc1   : fetch pc = mv s11,s3 ∧ fetch (pc+4) = j head → Core p c s w → s' = s.apply {pc+1} →
             ∃ c' n, StepsN n c c' ∧ VmRel p c' s'
tail_store : fetch window = [sd a5,0(s6); li a5,3; addi s11,s11,8; sb a5,8(s6); j head] →
             s6 = slot A ∧ a5 = v ∧ … → VmRel p c' (s.apply {pc+2, defs [A], vals [.int v]})
tail_kcmp  : [srliw a5,s4,15; andi 1; bne a5,a0 …] → a0 = [c.isFalse = false] → docondjump edges
```

- Each lemma is stated **for all pcs** with a code premise, and keyed by decoded content, not by address. The five copies of the pc+1 tail are then one lemma with five instances.
  - The `j head` offset differs per copy, which is why the key is *decoded* content (the resolved target) and not the bytes.
- An arm proof ends at a tail with the φ-value, for example `a5 = imod x n` at `0x8001f80c`.
- Each in-edge proves its φ-value from its own path condition. That proof is pure BitVec work, with no machine and no `VmRel`.

### Core rules

- **L-C4 at the arm level becomes `sim_upto`.**
  - If every path of the arm from `ArmAt` reaches (a) a tail whose continuation lemma has its precondition met, or (b) a vacuous leaf (N7), then `sim_X` holds.
  - This is a compatible up-to function over `VmRel`, proved once.
- **L-C2′ becomes a statement about tails.** Arms share *tails*, not trees. MUL's store tail is its own; MOD and MODK plausibly share `0x8001f80c`'s shape. Tails are keyed by content, which is the right key; L-C2 found `opKernel` combinator to be the wrong one.
- **L-C6′ becomes part of the tail lemma.** The store shapes live inside the tail lemma: `tail_store` is proved once, with R3-R1-5 #2's `bleach` inside it. The arm never sees a store.

### What it makes free

- **(c) closes:** every arm with the same tail reuses its close.
  - The pc+1 exit of every opArith, compare and test arm is one lemma, where today each template carries its own pc+1 close.
- **(a5) partly:** the tail lemma is stated against the kernel edge (`{pc+2, [A]}`), so each in-edge only proves a value.
- **Duplication value lemmas.** MOD's four in-edges become four *δ-level* facts:
  - `r = 0 → 0 = imod x n`;
  - `¬(r ^^^ n).msb → r = imod x n`;
  - `(r ^^^ n).msb → r + n = imod x n`;
  - `n = −1 → 0 = imod x n`.

  With `r = x.srem n` and `n ∉ {0, −1}`. These are one lemma, `imodC_eq`, which MODK and IDIV/IDIVK (with `idivC`) reuse.

### What it costs

- **Setup:**
  - `sim_upto`, about 60 lines;
  - three tail lemmas, about 30 each, mostly the current closes moved into place.
- **The φ-annotation is chosen by hand** for each *new* join (for MOD, `a5 = imod x n`). That is one line of data, but it is per join.
- **Harder:**
  - Joins whose live state includes spilled registers, which need a stack slot in the annotation.
  - Tails that read memory an arm just wrote. None exist in the pilot arms.

### Theories

- **Known (concurrency):** bisimulation up-to techniques. Sangiorgi, "On the bisimulation proof method", MSCS 1998; Pous, "Coinduction all the way up", LICS 2016 (recalled; check). A tail lemma is a compatible function.
- **Known, distant (game playing):** endgame tablebases. K. Thompson, "Retrograde analysis of certain endgames", ICCA Journal 1986 (recalled; check). Search stops the moment it reaches a solved position. Tails are the solved positions, and arms only need to reach one.
- **Known (compilers):** SSA φ-functions (Cytron et al., TOPLAS 1991). Floyd's cut-point assertions (1967). State merging in symbolic execution: Kuznetsov, Kinder, Bucur, Candea, PLDI 2012 (recalled; check).
- **Novel:** φ-annotations that are *kernel values* (δ-terms), so that a machine join is exactly where compiler-introduced splits reconverge on one δ value. Also: tail lemmas keyed by decoded content with a ∀-pc code premise.

### Pilot

- **Refactor `sim_ADD`.** Its two exits become `tail_pc1` and ADD's own store tail. ADD's tail stores the tag first and is inline, so it gets its own `tail_store` instance through `bleach`. The guard pairs become the tag lemma of R3-R1-2 #2, and the step inversion becomes `kstep_iff` evaluation (R3-R1-3 #5).
- **MOD.** Seven path ends:
  - two go to `tail_pc1` (via `0x8001c1e4` and `0x8001e43c`);
  - one is vacuous (`n = 0`);
  - four reach `0x8001f80c` with `imodC_eq`'s four facts;
  - plus #1's rebase.
- **MUL.** Two ends at `tail_pc1`, and one inline store tail with `a0 = x*y` from #4.
- **EQ.** Its inline k-compare copy is one more instance of `tail_kcmp`, plus `donextjump` (`tail_jmp`).
- **Measure:** hand lines per arm excluding the shared tails and `imodC_eq`. Report those two separately.

### Seed

`HTH` is head, tail, head. The cluster `483` is `lw` (4 bytes), `sd` (8 bytes) and `li 3` (the int tag), which is exactly the store tail's content. `63`, right after it, is bit 63, the `bltz (r xor n)` sign test that picks MOD's fix-up in-edge.

## 4. Pruned call summaries: classify callees after F1 pruning, and return to `ra₀`

**Acts on:**

- **(c)** It objects to R3-R1-5 #3's static-closure scanner, using N1.
- **(c)** It objects to the call rules of R3-R1-2 #4 and R3-R1-1 R3.1, using N3.
- **(c)** It names a hidden cost of relocation (R3-R1-1 #3 R3.2, R3-R1-2 #4).
- **(a)** It extends R3-R1-4 #2 (abstract `f`, with the residual as a table row).

### The objections, concretely

- **R3-R1-5 #3 classifies `luaV_equalobj` as U, so its EQ pilot cannot run as stated.**
  - Its criteria are "`jalr` in the closure forces U" and "a static call closure".
  - `luaV_equalobj` has `jr a5` through a `.rodata` table, and its static closure reaches `luaT_callTMres`, which runs arbitrary Lua.
  - The class of a helper must be computed on the *value-pruned* callee:
    - under canonical F1 tags (#2), the table and userdata cases (the TM path) and `__eqdf2` are dead;
    - the jump-table target is a function of `t &&& 63`, which is known per case.
- **"`ra` is preserved" is false for `__moddi3`.** It returns by `jr t0` with `ra` clobbered (N3). The rule's postcondition must be `pc' = ra₀` (the value of `ra` at the `jal`), with `ra` and `t0` havocked.
  - R3-R1-2 #4 writes `pc c' = ra` in the post-state, which is ambiguous; it must mean `ra₀`.
  - R3-R1-1 R3.1 lists `ra = ret` in the *pre*-state, which is fine. Say it explicitly.
- **Relocation's hidden cost.** The coordinator confirmed the five soft-int helpers are instruction-identical once addresses are normalised.
  - Transport by R3.2 still needs each WHILE spec's *precondition* to be **window-local**: `CodeAt a bytes` for the helper's own bytes (and `__udivdi3`'s, for the wrappers), not the whole WHILE image.
  - If the existing statements assume the whole-image `TextLoaded`, they must first be narrowed. That is a per-battery restatement, done before the one translation theorem can apply.
  - **Check the statements** (not the proofs) of `Muldi3Spec` and `udivdi3_spec` first. This is falsifier F4.

### The idea

A **call summary** is a pair `(P, Q)` over the callee's *pruned* paths, proved once per helper, with three shapes, and used by one rule:

```
call_summary : Summary h P Q →
  (at jal h: P (a0..a7, bytes at arg pointers)) →
  ∃ c' n, StepsN n c c' ∧ pc' = ra₀ ∧ Q (a0') ∧ s0–s11, sp, gp unchanged ∧
          mem =_{≥ sp} mem ∧ (below sp ⊆ D of #1)
```

- `P` carries the pruning:
  - for `luaV_equalobj`, "both argument pointers are root slots with `ValReprC` + `RootsCanon`" (#2);
  - for `__moddi3`, `n ∉ {0, −1}`.
- `Q` is a δ-term:
  - `a0 = x.srem n` for `__moddi3` (check: C `%` truncates, and `srem` is the truncating remainder);
  - `a0 = x * y` for `__muldi3`;
  - `a0 = [v₁ = v₂]` for `luaV_equalobj`.
- Inside a summary proof, calls are summaries too:
  - `__moddi3` uses `__udivdi3`'s summary;
  - `luaV_equalobj`'s long-string case uses `luaS_eqlngstr`'s summary.

  The rule is recursive, as R3-R1-3 #4 proposed.

### Core rules

- **L-C3′ pure becomes `call_summary`,** with shapes:
  - leaf: registers only, `mem` unchanged;
  - framed: stores only below `sp`, absorbed by #1's D;
  - composed: summaries nested inside.

  The shape is a proved fact about the *pruned* helper, not the output of a syntactic scan.
- **L-C3′ noreturn:** a pruned path that reaches `luaG_*error` has `P` false, or is vacuous at the arm (N7). No summary is written for it.

### What it makes free

- **(b) for the pilot's three helpers.** Each needs one summary. Arms cite it by name; there are no per-site lemmas.
  - The summaries of MUL/MULK, MOD/MODK/IDIV/IDIVK and EQ/EQK/LT/LE are shared.
- **The static-closure explosion (131 helpers reached dynamically).** Pruning cuts `luaV_equalobj`'s closure from TM, float and userdata down to the F1 cases.

### What it costs

- `call_summary` with the ABI facts: about 80 lines.
- **Summaries:**
  - `__muldi3`: relocated from WHILE if F4 passes; otherwise about 40 lines for a loop invariant.
  - `__udivdi3`: relocated or about 60 lines.
  - `__moddi3`: about 20 lines on top of `__udivdi3`.
  - `luaV_equalobj`, F1-pruned: 7 cases, a jump-table read (from `RodataLoaded`) and a `luaS_eqlngstr` hypothesis. About 80 lines.
- **Harder:** stating `P` so that pruning is *checked*, not assumed. Each dead case must show that `P` contradicts its branch condition.

### Theories

- **Known (testing and program analysis):** function summaries in compositional symbolic execution. Godefroid, "Compositional dynamic test generation", POPL 2007 (recalled; check). Conditioned program slicing: Canfora, Cimitile, De Lucia, IST 1998 (recalled; check). The summary is taken over the slice conditioned on `P`.
- **Known, distant (molecular genetics):** conditional (tissue-specific) gene knockout, Cre-lox. A gene's role is assayed only in the tissue where it is expressed, because a whole-organism knockout is lethal and uninformative. (Recalled: Gu et al., *Science* 1994; check.) A whole-closure scan of `luaV_equalobj` is the lethal knockout; the F1-conditioned summary is the tissue-specific one.
- **Novel:** a helper's shape class obtained *after* value pruning by the relation's own canonical representation (#2), and summaries whose `Q` is a δ-term, so an arm's leaf closes by `rfl` against `opKernel`.

### Pilot

### Seed

`TT` and `BB`, two doubled runs nine characters apart: one value held twice, as in `mv t0,ra` … `jr t0`, where `t0` is a second copy of `ra`. `IjI`: an indirect jump (`jr a5`) in the middle of the callee.
