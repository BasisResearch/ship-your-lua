## Seven facts from the binary that round 1 did not use

1. **FORPREP repurposes `s11` across its first call.** After `savestate` (`0x8001c0f8–0x8001c110`), the code runs `addi s11,a5,16` (`0x8001c118`), so `s11` holds `plimit`, not the cached pc. `luaV_tointeger` is then called with `a0 = s11` (`0x8001e1f8`). The pc lives in `s3` until `mv s11,s3` (`0x8001f884`) or `add s11,s3,a7` (`0x8001e224`) puts it back. So **at both call returns the head pins are permuted**. Any cut state shaped like "`VmRel` minus a few fields" is wrong there.
2. **FORPREP forwards a store to a load across a call.**
   - Before the call: `sd a5,16(sp)` (`0x8001e1e0`).
   - After it: `ld a5,16(sp)` (`0x8001e200`) and `ld a0,40(sp)` (`0x8001e20c`). The second reads the out-parameter that the callee wrote through `a1 = sp+40`.
   - The same pattern appears around `__udivdi3`: spill at `0x8001f868`, reload at `0x8001f870`.
   - So one path has a load that must **hit** the caller's own store and a load that must hit the **callee's** store.
3. **FORPREP's slot accesses all hang off one symbolic base `A`.** It writes `R[A+3]` with `sb s2,56(a5)` and `sd s10,48(a5)`, then later writes `R[A+1]` with `sd a4,16(a5)` and `sb a4,24(a5)` (`0x8001f878`). The separations are `A+3` against `A+1`: same atom, different literal.
4. **IDIV's two-helper path rejoins the one-helper path.**
   - `__divdi3` is called at `0x8001f73c`.
   - If the signs differ, it goes to `0x8001f95c`: `jal __moddi3`, `snez`, `sub s10,s10,a5`, `j 0x8001f74c`.
   - `0x8001f74c` is the same store-and-dispatch suffix that the same-sign path reaches. FORPREP's ascending and descending paths also join, at `0x8001f878`.
5. **`memset` has no back edge in its tail.**
   - The tail is `jr 12(a3)`, with `a3 = 4·(15 − a2) + pc` (`0x8003b5a8–0x8003b5b8`), into 15 unrolled `sb a1,k(a4)`. That is Duff's device.
   - Its alignment prologue makes a local call `jalr -104(a3)` with `ra` parked in `t0` (`0x8003b628–0x8003b630`).
   - `memset` is called from `_write` (`0x80000c74`, which is on CALL print's stdout chain), from `luaH_newkey` and `tablerehash` (F2 tables), from `luaF_newLclosure`, from `lua_newstate`, and from five sites in `_svfprintf_r`.
   - `luaV_equalobj`, on EQ's path, also has an indirect `jr`, a switch on the tag.
6. **Freeing a string overwrites its tag.** dlmalloc's free chunk keeps `fd` at payload+0 and `bk` at payload+8 (`DlHeap.BinChain` reads `q+16` and `q+24` of the chunk `q`, and the payload starts at `q+16`).
   - A `TString` has `next` at +0 and `tt`/`marked`/`extra`/`shrlen`/`hash` at +8..+15.
   - So once the GC frees a string, `_free_r` writes over its **tag, length byte and hash**.
   - Round 1's claim that "GC writes only `next` +0, `marked` +9, `hnext` +16" (R4-R1-1 #5, R4-R1-5 #2, R4-R1-3 #5) holds only for **live** strings.
7. **The window can move to a different allocation.**
   - VARARGPREP calls `luaD_checkstack(L, p->maxstacksize + 1)` inside `luaT_adjustvarargs`, which may reallocate the stack.
   - CALL reaches `checkstackGCp`, which runs `luaC_checkGC`. In atomic, the GC's `traversethread` can shrink the stack (`luaD_shrinkstack`) **(recall: check the 5.4.7 `lgc.c` guard)**.
   - The freed old stack is then heap that a new string may occupy.

## 1. Chunk-keyed ownership: a string is outside the window because it is a different allocation

**Acts on:** R4-R1-2 #1 (the `ValRepr.str` footprint conjunct), extended (a). It also objects (c) to R4-R1-1 #5, R4-R1-5 #2 and R4-R1-3 #5.

### The idea

Round 1 reached M-str five ways. Four of them are the same statement under different names, a per-value "footprint ∩ `Win` = ∅":
- R4-R1-1 #5 `Core.owned`;
- R4-R1-4 #1 `ValRepr … W`;
- R4-R1-5 #2 `Core.bastion`;
- R4-R1-2 #1's `ValRepr.str` conjunct.

The fifth, R4-R1-3 #5's holed complement, is a representation change.

For the F1 held-out cases, all five cost the same, because `w` is constant along an F1 arm. **The cheapest is R4-R1-2 #1's conjunct inside the existing `ValRepr.str` constructor**: no new field, threaded by `Core.write` for free.

The objection is to the *form* of the fact. "Footprint ∩ `Win` = ∅" mentions `Win`, and `Win` moves (fact 7). Each time it moves, the fact must be re-proved for every live register and every `K[i]`. The holed complement is worse: the hole itself moves, so `w.mo` must be erased in one place and refilled in another.

So state the fact about the **allocator's partition**, which the relation already carries: `Complement → RuntimeMem → DlHeap.HeapAt … chunks`, with a `ChunkWalk` over contiguous, non-overlapping chunks. The conjunct becomes:

```lean
/-- `x` is the payload of an in-use chunk that is not the Lua stack's, the
`lua_State`'s or the current `CallInfo`'s, and it is large enough for the string. -/
structure HeapObj (rt : RtPtrs) (w : RelPtrs) (x n : Nat) : Prop where
  chunk  : ∃ c ∈ rt.chunks, c.inuse ∧ c.addr + 16 = x ∧ x + 24 + n + 1 ≤ c.addr + c.size
  notWin : x - 16 ∉ [w.stackChunk, w.lxChunk, w.ciChunk]
```

`ValRepr.str` gains `HeapObj rt w x.toNat s.length`. The window gets **one** `Ranges` fact, `Win ⊆ stackChunk ∪ lxChunk ∪ ciChunk ∪ CStack`. Note that `Slots` lie in the stack chunk because `ci->top ≤ stack_last`.

### Core rules

- **L4-str → `HeapObj.off_win`**, proved once:
  `ChunkWalk` disjointness + `HeapObj` + the `Win ⊆ …` fact ⇒ `∀ a ∈ tsFoot x s, ¬ Win p w a`.
  It then composes with `Core.frame` into R4-R1-2 #1's `Core.strTape` (`BytesAt c.σ.mem (x+24) (s ++ [0])`). That is the fact the scans need.
- **Window moves → `HeapObj.rewindow`**, proved once. If the stack is reallocated, the old stack chunk becomes free and the new one comes from `_malloc_r`, which returns a chunk that was not in use. Every `HeapObj` was in use before, so its chunk differs from the new stack chunk.
  - The cost is one fact about the allocator summary, the existing `SWP` run of `_malloc_r`. It is not one re-proof per live register.
  - VARARGPREP with no reallocation keeps the same stack chunk, so the cost is zero.
- **GC → `HeapObj` exists only for live registers.** A freed string fails `c.inuse`, so its `ValRepr` cannot be claimed. Fact 6 then needs no special case. The kernel's kill ports must cover every register the GC can free. CALL's `killLo := w.a + w.c − 1` (`Semantics.lean:403`) does cover everything above `L->top` after the call.
  - The one check is that no live register is above `L->top` at a GC point. That is the CALL arm's obligation, and it is real.

### What it makes free

- **The same four premises as round 1:** `sim_EQ_of_long`, `sim_EQK_of_long`, `sim_LT_of_str`, `sim_LE_of_str`, given the scan summaries.
- **The re-proof at every window move**, which round 1 deferred (VARARGPREP, CALL's stack reallocation, the GC's stack shrink): one allocator fact each.
- **F2 tables**, through the `F2` that follows `OAh` in the seed. A `Table`, its array part and its node part are three chunks, so they get `HeapObj` with their own footprint. One structure serves every heap object, and none needs a new relation field. This is the "one value-generic field" of M-str, keyed to something that does not move.

### What it costs

- **The chunk lookup.** `HeapObj.chunk` is an `∃ c ∈ rt.chunks`. `rt.chunks` is ground at boot, so the boot witness gives the index by `decide`. CONCAT's strings get their chunk from the `_malloc_r` summary.
- **Three named chunks in `RelPtrs`:** `stackChunk`, `lxChunk`, `ciChunk`. The boot witness reads them off the heap walk.
- **What gets harder.** A string inside a chunk at an offset other than +16 would not fit `c.addr + 16 = x`. Strings created by `lua_pushexternalstring`/`luaS_newextlstr` are the case to check; I believe 5.4.7 has none **(recall)**.
- **For the F1 pilot alone this is more work than the bare conjunct.** The bare conjunct is the cheapest thing that discharges EQ and LT. Build `HeapObj` only if the bake-off includes a window move.

### Theories

- **Ownership types** (Clarke, Potter and Noble, OOPSLA 1998) **(recall)**: known. The owner here is the allocation, not the type.
- **Allocation as the source of separation:** Reynolds' `x ↦ –` produced by `cons`, LICS 2002 **(recall)**: known. Disjointness comes from the allocator's history, not from address arithmetic.
- **Cadastral land registries (property law; distant).** Title attaches to the parcel, not to the tenant, so when a tenant moves (the window), the other parcels' titles do not need re-registering: novel as an analogy.
- **Root sets in tracing GC** (Jones and Lins, *Garbage Collection*, 1996) **(recall)**: known. The kill ports must equal the non-roots.

### Pilot

1. **Smallest build:** R4-R1-2 #1's bare conjunct ("`tsFoot` ∉ `Win`") in `ValRepr.str`, `Core.strTape`, and the boot-witness check.
2. Then discharge `sim_EQ_of_long`'s premise with a `memcmp` summary (idea 5).
3. `HeapObj` is the refactor for the first arm that moves `Win`. If VARARGPREP enters the bake-off, its relocation is the measurement: with `HeapObj`, 0 lines per live register.

### Seed

`OAh` repeats at offsets 7 and 100, followed once by `F2` and once by `2`. It is the same heap object, once in an F2 (table) context and once bare, so one ownership rule should serve both.

## 2. Indexed-entry blocks: Duff's device and the jump table are one rule

**Acts on:** objects (c) to M-loop as "a cycle with a back edge": R4-R1-3 #2 (`LoopGraph`/`tile`), R4-R1-2 #4 (orbits), R4-R1-1 #1 (`cloop_fold`), R4-R1-5 #3 (`CursorShape`). Combines it (b) with the kit's existing `dispatch` (`Lua/Vm/Sim/Dispatch.lean`).

### The idea

Every M-loop variant assumes that repetition is a back edge, so that a measure falls on a cycle. The stdout chain contradicts this (fact 5). `memset`'s tail is a **computed entry** into an unrolled straight-line block, `jr 12(a3)` with the target affine in `a2`, so nothing is a loop. `cloop_fold`, `tile` and `orbit_loop` have no instance for it. `gen_fn.py`'s CFG must also either enumerate 16 targets (16 paths) or fail.

`memset` lies under `_write` on CALL print's path and under `luaH_newkey`/`tablerehash` in F2. The other indirect jumps in that code are switch tables: `luaV_equalobj`, `mainpositionTV`, `luaO_pushvfstring`.

The kit already has one rule for an indexed entry, the `dispatch` of `luaV_execute`'s jump table, proved "once for all opcodes". Duff's device is the same shape with the table removed: the target is `pc₀ + stride·k` instead of `table[k]`. So generalise `dispatch` instead of extending the loop rule:

```lean
/-- A uniform block: `N` copies of one instruction template at stride 4,
the i-th with displacement `d i` (`sb a1,(N-1-i)(a4)`). -/
structure UBlock where base : Nat; N : Nat; tmpl : Nat → Instr; exitPc : Nat

theorem ublock_suffix (B : UBlock) (hseg : ∀ i < B.N, Triple (SegSt (B.base+4i) …) (SegSt (B.base+4(i+1)) …)) :
  ∀ k ≤ B.N, Triple (SegSt (B.base + 4k) pins (P m))
                    (SegSt B.exitPc pins (P (tile m (B.cellsFrom k))))

theorem indexed_entry (hjr : jr target = B.base + 4·f(r)) (hk : f r ≤ B.N) : …  -- one rule
```

`indexed_entry` is `dispatch` with `table[k]` replaced by an affine target. The body memory is R4-R1-3 #2's `tile`, restricted to a suffix `[k, N)`. Nothing is iterated, because the "iteration count" is the entry offset.

### Core rules

- **L4-loop′ (computed entry) → `ublock_suffix`**, proved once by induction on `N − k`. Each block instruction is one generated segment, already emitted.
- **The jump → `indexed_entry`.** A generalisation of `dispatch`, proved once. `luaV_equalobj`'s switch (on EQ's path) and the stdio switches become instances of it, not per-site case splits.
- **A local call with the link in a temporary** (`mv t0,ra; jalr …; mv ra,t0` at `0x8003b628`) is not an ABI call. It is a `tailJump` into a `UBlock` and back, so `FnSummary.tailJump` covers it. No `HelperSum`/∀ρ applies (R4-R1-1 #2's `callABI` would wrongly assume `ra` survives the `jalr`).

### What it makes free

- **`memset`'s three exits** (short tail, alignment head, 16-byte loop + tail) and its two indirect jumps: one `ublock_suffix` instance plus one `cloop_fold` instance for the `sd;sd` loop at `0x8003b590`.
- **The per-target case split** that `gen_fn.py` would otherwise emit for each `jr`. That is 16 for `memset`, and one per tag for `luaV_equalobj`.
- **Not the held-out cases.** It is a falsifier of M-loop's coverage claim for CALL print: of the "93 loops" count, at least `memset` is not a loop at all, and the census should count indirect jumps separately.

### What it costs

- `UBlock`, `ublock_suffix`, and generalising `dispatch`: about 80 lines (est.).
- The generator must recognise a uniform block, meaning N consecutive words that decode to the same template up to the immediate. That is data, checked by `decide` on the decoded words (`decodeW`).
- **What gets harder.** The `jr` target's affine form needs `auipc` + `add` + immediate folding, three instructions, before the rule applies. Any indirect jump that is not affine (a loaded table entry) goes back to `dispatch`, which already handles it.

### Theories

- **Duff's device** (T. Duff, Usenet, 1983) **(recall)**: known.
- **Jump-table lowering of `switch`** (R. L. Bernstein, "Producing good code for the case statement", SP&E 1985) **(recall)**: known.
- **Dal segno in music notation (distant).** A score says "go to the sign at bar k and play to Fine". The suffix of a fixed passage is played; no repeat is involved: known as notation, novel as a proof rule.

### Pilot

- **Not in the held-out set.** The smallest check is to run `memset` through `gen_fn.py` and see whether it rejects the `jr` or explodes it into 16 arms. That is a free check of round 1's loop-coverage claim.
- **Smallest build:** `ublock_suffix` for `memset`'s 15-store block, then `luaV_equalobj`'s switch as an `indexed_entry` instance. That second instance is on EQ-long's path, so it is the held-out tie-in.

### Seed

`7Q` appears twice (`7Q2d58`, `7Q1Ds`): the same block entered with a different index digit. The `77` run gave a uniform template repeated.

## 3. Join-and-return cuts with kernel-valued joins

**Acts on:** combines (b) R4-R1-4 #5 (`Ckpt`) with R4-R1-3 #4 (retimed cuts) and R4-R1-5 #1 (location lists). Objects (c) to per-path tables (R4-R1-3 #4's `PathTable`, R4-R1-4 #5's per-path `π`) and to heartbeat-placed cuts.

### The idea

Round 1's cut proposals are the same mechanism under different names:
- R4-R1-2 #3 residuals;
- R4-R1-3 #4 `CutSt`;
- R4-R1-4 #5 `Ckpt`;
- R4-R1-5 #1 `At`/`Loc`;
- R4-R1-1 #4 path certificates.

In each, the boundary state is a term computed from the path. They differ in two choices:
- **the term language:** raw pins (#5 of R4-R1-4), `Ex` (R4-R1-3), `Loc` (R4-R1-5), or a full `Expr` with a verified evaluator (R4-R1-1);
- **where the cuts go:** per path at the generator's heartbeat sum.

I object to both choices, with facts 1 and 4.

**Where.** Per-path tables duplicate shared suffixes. IDIV's mismatch path and same-sign path share `0x8001f74c → head`, and FORPREP's two directions share `0x8001f878 → head`. Heartbeat-placed cuts move whenever a cost changes, so a proof can break when the cost model changes. Instead, **cut at a canonical set read off the CFG**: every call return, and every join (a pc with two or more predecessors on the arm's paths). This is not a hand choice, and it does not depend on heartbeats. Each piece then contains **at most one call** and **no join**.

**What the state is at a join.** At `0x8001f74c`, `s10` is `q` on one incoming path and `q − (r ≠ 0)` on the other. Per-path `Ex` terms differ, so a join cut has no single term. The common description is at the **spec level**: `s10 = idiv m n`, the kernel's δ output. So a join's state is named by the kernel. The language needs one constructor, `Loc.out i` ("the kernel body's i-th value", from `Kernel.body`), and each incoming piece proves its own expression equals it, the arithmetic the kit already does per path. The suffix after the join (store, tag, `pc+8`, `j head`, close) is then proved **once per arm, not once per path**.

**What the state is at a return.** Fact 1 shows FORPREP's return state has `s11 ↦ ptr base (16(A+1))` and `s3 ↦ pc`. A `Loc`-style table expresses that directly. An `ArmPre`-like named structure cannot do so without a FORPREP-only variant. So **the term language should be R4-R1-5 #1's `Loc` plus `out`**. It is cheaper than R4-R1-1 #4's full `Expr` evaluator (no verified symbolic evaluator, about 600–900 lines) and more expressive than raw pins.

### Core rules

- **L4-split′ → `cut_seq`** (R4-R1-4's `split_at` / R4-R1-3's `cut_compose`, unchanged). The cut set is `returns ∪ joins`, emitted as data by the generator's CFG walk.
- **Join → `join_by_kernel`:**
  `(∀ incoming piece π, Triple Pre_π (At (locs J)))` + `(Triple (At (locs J)) Post)` ⇒ `∀ π, Triple Pre_π Post`.
  `locs J` mentions only `Loc.out`, `Loc.slot*` and pins that agree on all incoming paths. The generator checks this agreement by evaluating `Loc` composition per incoming path. That is a `decide` on data, not a proof.
- **L4-call′ → R4-R1-1 #2's `callABI` at each return cut.** ρ is `locs.filter calleeSaved`, which is computed. It is not written.

### What it makes free

- **If M-log's heartbeat claim is false, this carries the budget.** Each piece is at most one inter-call span with no join, so the budget only has to cover the largest such span.
  - **FORPREP's largest piece** runs from the head through `savestate` to `jal luaV_tointeger`: 4 guarded loads (init tag `0x8001c114`, step tag `0x8001e1c0`, step `0x8001e1cc`, init `0x8001e1d8`) and 3 stores. At §1b.3's 15–20k per guarded load plus about 30k setup, that is about 100–110k (est.), under 200k. The pieces after the returns have no guarded slot loads, only frame loads.
  - **IDIV's largest piece**, head to `jal __divdi3`, is similar: two tag loads and two payload loads after `savestate`.
  - **MODK** is cut at `0x8001f7bc` by rule, not by `armBody_split`'s hand choice, and `ArmPre` is generated.
- **The duplicated post-join proofs:** one suffix proof per join, not per path. IDIV: 1, not 2. FORPREP: 1, not 2.
- **FORPREP's `fp_pre`/`FpInts`/`fpFrame`/`FpMem`:** `At (locs 0x8001e200)` and `At (locs 0x8001f870)`.

### What it costs

- **`Loc` with `out`, `At`, `join_by_kernel`, `cut_seq`:** about 200 lines (est.). That is R4-R1-5 #1's figure without `locXfer`: the pieces are kit runs that *end* in `At` via one `At.of_seg` closing lemma, as R4-R1-5 #1's smallest build suggests.
- **The generator emits `locs` at cut pcs only**, not at every boundary, so it emits fewer rows than R4-R1-5 #1.
- **What gets harder.**
  - A join whose incoming paths disagree on a value the kernel does not name (a spilled temporary) needs a `Loc.ghost`. I found none on IDIV, MODK or FORPREP, but this needs checking per arm.
  - Loops are joins too. A loop head is a cut, which is where idea 5's fold rule enters, consistently.

### Theories

- **SSA φ-nodes at joins** (Cytron et al., TOPLAS 1991) **(recall)**: known. The join's `s10` is a φ, and naming it by the kernel output is φ-elimination into the spec.
- **Floyd's cut-points** (1967) **(recall)**: known. Floyd's cuts must break every loop. Here they break every join and every call.
- **Craig interpolants at joins** (McMillan, CAV 2003) **(recall)**: known. The join state is an interpolant between the incoming paths and the suffix, chosen here as the kernel's value rather than searched for.
- **Hydrology (distant).** Gauging stations sit at confluences, where tributaries merge, and downstream flow is measured once: novel as an analogy.

### Pilot

- **IDIV** is the smallest decisive case, because it has the only nontrivial join among the held-out arms. Build `Loc` (const, ptr, slot, out, dead), `At`, `At.of_seg`, `join_by_kernel` and `callABI`. Prove IDIV's three pieces with no hand split and no hand frame.
- **FORPREP:** four pieces (two returns, one join, the skip exit), with no `FpMem`.
- **MODK refactor:** `modk_call` 6 → 1 line, `ArmPre` deleted.
- **Cheapest falsifier, before any build.** Sum the existing per-segment heartbeat profile (`ProfModk`-style) over FORPREP's head→`jal luaV_tointeger` span. If it exceeds about 180k, return-and-join cuts are not enough, and M-log (idea 4) becomes mandatory rather than an accelerator.

### Seed

The width-3 palindromes `j9j`, `RkR`, `bmb`, `fwf`, `2g2` gave two arms meeting at a centre, cut at the centre. `pc` appearing twice gave the idea of a pc reached twice, which is a join.

## 4. Atom-indexed region labels, with forwarding across calls

**Acts on:** extends (a) R4-R1-5 #4 (store-forwarding log), R4-R1-1 #3 (`Rgn`) and R4-R1-3 #3 (`WLog`). Objects (c) to their "resolved by `decide`" claim for symbolic slot indices. Combines (b) with R4-R1-5 #5 (derived callee footprints).

### The idea

M-log's promise is that a read through a store chain resolves by `decide`. Fact 3 breaks it as stated. With labels `slot (A+3)` against `slot (A+1)`, where `A` is a free variable (the instruction's field), `decide` cannot reduce `A+3 ≠ A+1`, because `Nat.decEq` gets stuck on a free variable. R4-R1-3 #3 and R4-R1-1 #3 fall back to "one `omega` on symbolic `j`". R4-R1-5 #4 notes an "`a ≠ b` hypothesis atom", which is the right instinct but is not built.

Every slot access in FORPREP, IDIV, MODK and LOADNIL is `R[F + lit]` for a field `F ∈ {A, B, C}` and a small literal. So reflect the indices: a label is `slot ⟨atom, lit⟩`, with `atom : Fin 3` (into an environment `[A, B, C]`) and `lit : Nat`.
- `sep` compares `(atom, lit)` pairs **as data**: the same atom with different literals is disjoint, decided.
- Different atoms are `stuck`, and the forwarder falls back to one `omega` with only `A, B, C` in context. That case does not occur on FORPREP (a single atom).

This is the standard trick of reflective `ring`/`omega`: atoms are indices, never terms.

Fact 2 adds the call. After `jal luaV_tointeger`, the log is the caller's entries `++` the callee's footprint entries. The callee's write set, derived as in R4-R1-5 #5 and parametric in `a1`'s label (`a1 = cframe 40`), contributes `havoc cstack` and `w8 (cframe 40) ⟨res⟩`. Then:
- `ld a5,16(sp)` is `fwd = hit (spilled a5)`, because `cframe 16 ≠ cframe 40` and `cframe ≠ cstack`, by data;
- `ld a0,40(sp)` is `hit res`.

No frame is stated, and no memory frame lemma is threaded at the call.

### Core rules

- **C-budget → `fwd_sound`** (R4-R1-5 #4), with labels `Rgn := slot (Fin 3 × Nat) | kslot (Fin 3 × Nat) | cframe Nat | cstack | savedpc | ltop | …` and a denotation under `env : Fin 3 → Nat`. `sep` is a total `Bool` function on labels. It is proved sound once from `Ranges`, which is the only place the disjunctions `ci_sep`/`L_sep`/`k_sep` appear (as in R4-R1-1 #3).
- **L4-call′ (memory half) → `log_call`:**
  `log' = log ++ (Fp f).entries (labelsOf args)`, with `Fp f` derived as in R4-R1-5 #5.
  It is proved once over `HelperSum`. The register half is R4-R1-1 #2's ∀ρ.

### What it makes free

- **FORPREP's 3 slot separations** (`A+3` vs `A+1`, tag and payload) and its 2 frame forwards across calls, all by `decide`.
- **LOADNIL's `slot (A+i)` vs `slot (A+j)`** inside the fill: the same atom. With idea 5's ledger, the loop body's reads, if any, never need `omega`.
- **`bleachF` vs `bleach`** (KIT-2): the close takes the label set, so `cframe 40` in the log is one more allowed label (as in R4-R1-2 #5's `close_of_ledger`).

### What it costs

- An atom environment in every log, and `addrOf` reflection that recognises `w.base + 16*(A + lit) + o`. That is about 40 lines on top of R4-R1-5 #4's estimate (est.).
- The generator emits addresses in field-plus-literal form. It already knows the field each `slli`/`add` came from.

### If M-log's heartbeat claim is false

The falsifier being run measures one number, a guarded load from 15–20k to under 10k. Split it into **three** numbers, each in its own declaration:
1. the cost of reifying the `writeMap8` chain into a log by `rfl`;
2. the cost of `decide` on `fwd`;
3. the cost of the rewrite.

- **If (1) dominates**, the claim fails only because of the bridge. The fix is R4-R1-5 #4's boundary format (`"boundary": "log"`): the generator never builds `writeMap8` terms, so the claim is re-tested with the bridge cost at zero.
- **If (2) or (3) dominates**, labels do not help, and idea 3's cuts carry the budget alone.

Either way the result is a number, not an argument.

## 5. One fold for scans and store loops, with a ledger as the accumulator

**Acts on:** combines (b) R4-R1-1 #1 (`cloop_fold`) with R4-R1-2 #5 (the write ledger) and R4-R1-3 #2 (`tile`). Objects (c) to per-class closed-form theorems: R4-R1-2 #4's `iterate_affine`/`iterate_shiftAdd` and R4-R1-4 #3's `nilFill`/`slotCopy`.

### The idea

Round 1's loop proposals reduce to two equivalence classes.

**Read-only scans (one mechanism, five names):**
- R4-R1-1 #1 `cloop_fold`;
- R4-R1-2 #1 `firstEvent_chunked`;
- R4-R1-3 #1 `scan_chunked`;
- R4-R1-4 #2 `scan_loop`;
- R4-R1-5 #3 `cursor_loop` with its exit oracle `σ`.

**Strided store loops (one mechanism, four names):**
- R4-R1-2 #4 `iterate_affine`;
- R4-R1-3 #2 `accel`/`tile`;
- R4-R1-4 #3 `nilFill`;
- R4-R1-5 #3's `eff`.

The cheapest single variant is **R4-R1-1 #1's `cloop_fold`**, because it already covers both classes: `α = Unit` with `mem k = foldl …` is the write scan.

The objection is to the store-loop half's closed forms. Each class theorem (`iterate_affine`, `nilFill`, `tile_rd`) proves a read-over-`foldl` lemma about memory. That is exactly the M-log work, done again per class. Instead, make the fold's accumulator the **ledger itself**:
- a store loop's accumulator after `k` steps is the list of log entries `(range k).map (fun i => w1 (slot ⟨A, 1+i⟩) nilTag)`;
- that list is the definition of the fold, so the closed form holds by `rfl`.

The memory is `applyLog m₀ env (pre ++ acc)` throughout, so:
- reads *inside* the body (the slot copy reads `src+i` after writing `dst+j`) go through idea 4's `fwd`;
- the **close** is R4-R1-2 #5's `close_of_ledger`, which needs only "every entry's label ∈ allowed", a `List.all` over a `map`. That reduces to one `∀ i < k` fact about the entry template, by the library lemma `List.all_map`/`List.all_range`.

So there is one rule and two accumulators:
- **verdict** (scans: `memcmp`, `strlen`, `strcmp`, `l_strcmp`);
- **ledger** (nil fill ×5, slot copy ×2, `memset`'s `sd;sd` loop).

`__muldi3` and `__udivdi3` use a third accumulator, the arithmetic state (`α = BitVec 64 × BitVec 64 × …`), with the existing copied lemmas.

### Core rules

- **L4-loop′ → `cloop_fold`** (R4-R1-1 #1, unchanged), its accumulator generalised to `α`. The cursor pins stay affine in `k`, which idea 4's atom labels decide.
- **Store loops → `ledger_fold`:**
  `foldUntil (fun acc _ => .cont (acc ++ [tmpl k])) [] (range n) = (range n).map tmpl`.
  This is a pure `List` lemma, proved once. It replaces `iterate_affine`, `tile_rd`, `nilFill`'s closed form, and `Core.writeNils`.
- **Close → `close_of_ledger`** (R4-R1-2 #5), with an allowed-label set.

### What it makes free

- **LOADNIL:** `loadnil_loop` (25 lines) becomes one `cloop_fold` instance whose body is a 2-segment kit run, plus `close_of_ledger`. Target: ≤ 5 lines (est.).
- **The RETURN0/RETURN1/`luaD_precall`/`luaD_poscall` fills:** the same instance with a different template. That covers R4-R1-4 #3's "affixes" (offset −8/0, bump order), since the template is `fun i => w1 (slot ⟨atom, off(i)⟩) 0`.
- **The scans** (EQ-long, LT-str): unchanged from R4-R1-1 #1/R4-R1-2 #1, with the verdict accumulator, plus the lane lemmas (`word_eq_iff_lanes`, `hasZero_iff_lanes`) and `lexLt_split0`.
- **No per-class closed-form theorem**, so CALL print's loops outside the three classes (R4-R1-2 #4's acknowledged fallback) cost an instance, not a new class theorem, as long as the body's effect is a ledger extension. `_svfprintf_r`'s buffer fills are.

### What it costs

- `ledger_fold` is a few lines. The cost sits in idea 4: the ledger must be the memory representation of the loop's segments. Without it, the body's post is a `writeMap8` term, and the accumulator would have to be bridged on every iteration.
- **What gets harder.** A loop whose stores depend on earlier loads of the same region (an in-place `memmove`) makes `fwd` return `stuck` on symbolic overlap. Such a loop needs an invariant again. None of the census loops do this; `luaT_adjustvarargs` copies upward into disjoint slots.

### Theories

- **The writer monad** (Wadler, "The essence of functional programming", POPL 1992) **(recall)**: known. A store loop is a computation that only emits, and its result is the concatenated output.
- **Event sourcing (software architecture; distant).** State is a fold over an append-only event log, and projections read the log (Fowler, 2005, **(recall)**). Known.
- **Fold fusion** (Bird 1987; Meijer, Fokkinga and Paterson 1991) **(recall)**: known. The `map` closed form is the fusion of the fold with the append.

### Pilot

- **LOADNIL refactor (smallest):** `cloop_fold` over a ledger accumulator, `ledger_fold`, and `close_of_ledger` with labels `{slot}`. Cross-check RETURN1's fill with 0 new lemmas.
- **EQ-long:** `memcmp_sum` = `cloop_fold` (word, verdict) ; `foldUntil_append` ; `cloop_fold` (byte), plus idea 1's conjunct.
- **LT-str:** add `strlen`, `strcmp` (6-exit unrolled body as one `Next` with 6 `.exit`s) and `l_strcmp` (body with call nodes), plus `lexLt_split0`.

### Seed

`2b` appears three times after different prefixes (`K2b`, `492b`, `te2b`): one rule, three uses. These are scans, store loops and arithmetic loops, which differ only in what accumulates.

### What is the smallest combination?

The coordinator asks for the smallest combination that:

### Which variants are the same?

- **Cuts:** R4-R1-2 #3 ≡ R4-R1-3 #4 ≡ R4-R1-4 #5 ≡ R4-R1-5 #1. R4-R1-1 #4 is the same with a verified evaluator, and it is the most expensive. They differ only in the term language. The cheapest adequate one is `Loc`, because FORPREP's permuted `s11`/`s3` (fact 1) rules out raw head-shaped pins.
- **Strings:** R4-R1-1 #5 ≡ R4-R1-4 #1 ≡ R4-R1-5 #2 ≡ R4-R1-2 #1 (a per-value fact). R4-R1-3 #5 is a different representation, costlier at window moves.
- **Labels:** R4-R1-1 #3 ≡ R4-R1-2 #2 ≡ R4-R1-3 #3 ≡ R4-R1-4 #4 (a disjointness table). R4-R1-5 #4 and R4-R1-2 #5 add the log. All of them need idea 4's atoms for FORPREP.
- **Loops:** see idea 5.
