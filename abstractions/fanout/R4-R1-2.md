## 1. Frozen tapes and first-event scans

### The idea

Every string loop the remaining arms meet is read-only (§1b.2: `memcmp`, `strlen`, `strcmp`, and the chunk loop of `l_strcmp`). So stop treating these loops as machine loops over memory. Treat them as **searches for the first event on an immutable tape**. The idea has two parts.

**(a) The tape is frozen by the relation, not by a premise.**
- KIT.md's obstruction 1 is fixed once, inside the existing `ValRepr.str` constructor. Its `TStringRepr` gains a footprint conjunct: the object `[x, x+24+len]` is disjoint from `Win`. This is not a new relation field. It is the d1 widening KIT.md asks for. The boot witness supplies it (`check_tstring` already reads the object), and so does CONCAT's allocation.
- Then `Core.frame` (outside `Win`, `c.σ.mem = w.mo`) gives the string's bytes and `'\0'` in the machine memory at every head. That is L4-str′ as a theorem, `Core.strTape`, not as an invariant to carry. No per-step argument is needed, because `Core.frame` is already re-established by every close.

**(b) The loop is a chunked first-event search.** Fix two tapes `t₁ t₂ : Nat → UInt8`. The machine reads them through total reads (`getD 0`), so padding past the terminator is a value, just an unknown one. Fix an event predicate `P : Nat → Bool`:
- mismatch for `memcmp`;
- zero for `strlen`;
- mismatch ∨ zero for `strcmp`.

A loop iteration of width `k` (k = 1 for a byte loop, 8 for a word loop, 8/16/24 for `strcmp`'s 3× unrolled body) does one of two things:
- it certifies `∀ j ∈ [i, i+k), ¬P j` and moves the cursor to `i+k`; or
- it certifies `∃ j ∈ [i, i+k), P j` and leaves to a **resolver** that returns `g (t₁ j*) (t₂ j*)` at the least such `j*`.

One rule says that any program built from such chunks and resolvers computes `g` at `firstEvent P i`. This holds whatever the widths, whatever the order of chunk loops (word loop, then byte loop), and whatever the entry point (rotated loops). Every helper's specification then collapses to a pure list identity:
- `luaS_eqlngstr` is `firstEvent mismatch 0 len = none ↔ s₁ = s₂` (the lengths were already compared at `0x80017194`);
- `l_strcmp` is `sign = lexLt` via one lemma that splits `lexLt` at embedded zeros (`lexLt_split0`).

**Word chunks are certified by lane decomposition, not by bit-blasting.**
- `bytesT8` is the little-endian concatenation of 8 bytes. So `ld a4; ld a5; bne a4,a5` certifies "8 equal bytes" by `word_eq_iff_lanes`.
- `strlen`'s and `strcmp`'s has-zero test `((x & m) + m) | x | m = -1`, with `m = 0x7f7f…7f`, has no carry between lanes: `0x7f + 0x7f = 0xfe < 0x100`. So the test splits into 8 independent 8-bit facts. Each lane is `decide` over 256 cases.
- Nothing about 2⁶⁴ is ever decided, and no `bv_decide` is used.

### Core rules

| law | rule (proved once) |
|---|---|
| L4-str′ (bytes and terminator) | `Core.strTape : Core p c s w → s.regs j = some (.str s) → slot j holds x → BytesAt c.σ.mem (x+24) (s ++ [0])`. This is `Core.frame` composed with the footprint conjunct of `ValRepr.str`. |
| L4-loop′, read-only shape | `firstEvent_chunked`. Let a `SegSt` family be indexed by a cursor `i` (pins = base pointers + `i`, memory constant: the segments' `ArmPay m` is unchanged, which the generator already shows). Suppose every body path either advances with a "no event in `[i, i+k)`" certificate or exits with "an event in `[i, i+k)`" plus a resolver. Then the loop's exit post is `g` at `firstEvent P i`, and the measure is `len − i`, fixed by the rule. The per-loop content is the chunk certificates, and those are the two lane lemmas. |
| (word-width certificates) | `word_eq_iff_lanes`, `hasZero_iff_lanes` (lane split + 256-case `decide`). |
| (string order) | `lexLt_split0 : lexLt (a ++ 0 :: a') (b ++ 0 :: b') = …`, the pure counterpart of `l_strcmp`'s loop over `'\0'`s at `0x8001a760–0x8001a7a4`. |

### What it makes free

- **The four C-str premises:** `sim_EQ_of_long`, `sim_EQK_of_long`, `sim_LT_of_str`, `sim_LE_of_str`. Each becomes the general path plus the derived helper summary.
- **The C-loop instances in the string helpers:**
  - `memcmp`'s 2 loops: the word loop `0x800361dc–0x800361f4`, and the byte loop at head `0x800361c0`, entered by `j` from `0x800361b8`, with exits at the mismatch `0x800361d4` and the count `0x800361fc`;
  - `strlen`'s 2 loops (word scan `0x8003b790–0x8003b7a8`, rotated byte scan `0x8003b7f4–0x8003b804`);
  - `strcmp`'s 2 loops (the 3× unrolled word loop with 6 exits, and the byte loop `0x8003ba04–0x8003ba18`).
  - Each one is chunks plus resolvers. There is no induction, no invariant and no measure.
- **`strcmp`'s 6 word-loop exits and the padding.** None of them needs an argument about the padding bytes past the terminator, which the aligned `ld`s read. The chunk rule only asks for "no event in the chunk" when the chunk is passed. When the chunk contains the terminator, the exit's resolver stops at the first zero, so the padding is universally quantified and never constrains anything.
- **Later loops:** every future read-only scan (`strchr`'s 6, LEN on strings, the `l_str2int` prefix of UNM's numeric-string path). The last one is a scan with an accumulator, i.e. a fold, so it needs the rule's Mealy-output generalisation `g := fold`. That is a second rule of the same shape.

### What it costs

- **Setup:**
  - the `ValRepr.str` footprint conjunct, with its two obligations (`gen_lua_boot_witness.py`'s `check_tstring` gets one extra disjointness check; CONCAT's allocation gets one, deferred with CONCAT);

  - the lane lemmas, about 50 lines (est.);
  - `lexLt_split0`, about 30 lines (est.).
- **Resolvers stay per exit.** `strcmp`'s byte-in-word resolution (`slli 48/32/16`, `srli 48`, `sub`, `zext.b`, `0x8003b9a0–0x8003b9fc`) is a pure `BitVec` fact per exit, discharged by the same lane split. That is about 6 small lemmas, and they are not a contract.
- **Two paths for `l_strcmp`.**
  - TString contents start at `ts+24`. They are 8-aligned when `ts` is, so the first `strcoll` (`j strcmp`) takes the word path.
  - After an embedded `'\0'`, `l_strcmp` advances by `len+1` (`0x8001a784`, `0x8001a788`), and the pointers lose alignment. The byte path at `0x8003ba04` is then taken.
  - So both paths are needed, but only for strings with embedded zeros. Both are instances of the same chunk rule.
- **What gets harder.** Every helper's segment state must expose the cursor as `base + i`, an affine pin. The generated pins are raw `BitVec` sums today, so one `pin_affine` normaliser is needed.

3. **SWAR null-byte detection.** Warren, *Hacker's Delight*, 2nd ed., 2012, §6-1 "Find first 0-byte" **(recall; check)**. Known; the lane-decomposition proof is novel here.
4. **Symbolic automata** (the resolver as a transducer output). Veanes et al., "Symbolic finite state transducers", POPL 2012 **(recall; check)**. Known.

## 2. Address atlas: charts with ground offsets, one disjointness theorem

### The idea

C-budget is ≈60% `omega` in `kit_disch`: 341 slow calls for 27 instructions, re-proving the same separation facts for each read and each pin (§1b.3). The disjunctive `Ranges` facts multiply that by about 4. The fix is a change of representation: **an address is not a `Nat` but a point on a chart**, `⟨ρ, o⟩`.
- `ρ : Chart` is a finite enum: `slot`, `cframe`, `savedpc`, `ltop`, `cstack`, `k`, `code`, `ci`, `L`, `str x`, `text`, `rodata`.
- `o` is an offset. It is a literal, or `16·j + lit` for slots and constants.
- `w.at : Chart → Nat` gives each chart's origin, read off `RelPtrs` (`w.base`, `w.sp`, `w.ci + ciSavedpcOff`, …).

One theorem, `Ranges.atlas : Ranges p w → Atlas w`, states that distinct charts are disjoint on their extents. It is the only place where `omega` ever meets `ci_sep`, `L_sep`, `k_sep` and `L_sep_ci`: each disjunction is case-split once, there, and never again.

After that, read-through-store is a `decide`:

```
rd_wr_chart : Atlas w → (ρ ≠ ρ' ∨ disjointOff o n o' n' = true) →
    rd n' (wr n m (w.at ρ + o) v) (w.at ρ' + o') = rd n' m (w.at ρ' + o')
```

The side condition is decided on tags (`Chart` has `DecidableEq`) and ground offsets. For slots, `16·j + c` vs `16·j' + c'` is decided as `j ≠ j' ∨ intervals of c, c' disjoint`, and that `j ≠ j'` is the only fact left for `omega`, once per pair. Since every pin the kit tracks is `BitVec.ofNat 64 (w.at ρ + o)`, `pins_of` charts them by a table `pinChart : Reg → Option (Chart × Off)`. That table is the existing `Pins` structure read as data: `s0 ↦ L`, `s7 ↦ ci`, `s9 ↦ base` (x25), `sp ↦ cframe`, …

L4-str′ becomes a typing fact. For every store in an F1 segment, `chart ∈ {slot, savedpc, ltop, cstack, cframe}`. That is `decide` per segment once the store addresses are charted, so `str x` is never written. Calls follow the same pattern: a summarised callee's writes are in `cstack` (below `sp`) or a named out-parameter chart (`luaV_tointeger`'s `sp+40` ∈ `cframe`). The caller's other charts are untouched, by one rule.

### Core rules

| law | rule |
|---|---|
| L4-split′ (budget part) | `Ranges.atlas` (once) + `rd_wr_chart` (once). Each guarded load through `savestate`'s stores costs one `decide` on charts instead of ~12 `omega` runs. |
| L4-str′ | `store_chart_ne_str`: a segment whose store charts are all ≠ `str _` preserves `TStringRepr` of every `str x`. `decide` on the segment's chart list. |
| L4-call′ (memory frame) | `call_chart_frame`: if a callee's write set is ⊆ `{cstack} ∪ outs`, then every other chart reads the same after the call. This is the chart-level form of the existing `FrameMeta.memFrame_of_chain` ("one `decide`", CLAUDE.md), reused, not re-derived. |

### What it makes free

- **The ×4 disjunction blow-up** (KIT-1, KIT ledger obstruction 2).
- **`Ranges.k_getElem_wm8`, `k_bytesT1_wm8`, `k_bytesT8_wm8`.** They collapse to `rd_wr_chart` with `ρ = k`.
- **The 557k fallback unification.** That was `omega` failing on a read the unifier then forced through whnf.
- **The `L_sep_ci` "add it only where EQ needs it" dance.** It lives in `atlas` and costs nothing per arm.
- **The budget (est.).** If a guarded load drops from 15–20k to ~5k heartbeats, MODK's whole path (198k measured) drops to ~100k, and FORPREP's ~6 guarded loads + 2 call nodes fits in one declaration.

### What it costs

- **Setup:**
  - the `Chart` enum, `w.at`, `Atlas`, `Ranges.atlas` (one big `omega` proof per chart pair, ≈ 12² / 2 pairs; split per row to stay in budget), about 120 lines (est.);
  - `rd_wr_chart` for widths 1/8, about 40 lines;
  - a charting pass in `pins_of` / `kit_side_pre`.
- **What gets harder:**
  - Computed addresses whose chart is not syntactic: `R[B]`'s string payload pointer, and `K[C]` loaded through `ld k,0(sp)`. These need the value-level fact that charts the pointer (`ValRepr.str` gives `str x`; `Core.kptr` gives `k`).
  - Callee frames at negative `sp` offsets need `cstack` with offset `sp − d`, which is affine, not ground. So `cstack` has to be charted from `RuntimeData.spEntry - cStackBudget`, and the callee offset becomes ground relative to `w.sp`. That holds because `Ranges.sp_eq` fixes `w.sp`, a literal.

### Theories

1. **CompCert's block/offset memory model.** Pointers are `(block, offset)`, distinct blocks never alias, and loads after stores to another block commute by definition. Leroy & Blazy, "Formal verification of a C-like memory model and its uses for verifying program transformations", JAR 41(1), 2008 **(recall; check)**. Known.
2. **Atlases in differential geometry.** A manifold is covered by charts with local coordinates, and facts are local to a chart; the transition maps are the only global content. Here the only "transition map" fact is `atlas` (disjointness). Known mathematics; the application is novel.
3. **Burstall's component-as-array model.** Each record field is its own array, so updates to one field leave the others syntactically unchanged. Burstall, "Some techniques for proving correctness of programs which alter data structures", Machine Intelligence 7, 1972; re-used by Bornat, MPC 2000 **(recall; check)**. Known.
4. **Type-based alias analysis.** Diwan, McKinley, Moss, PLDI 1998 **(recall; check)**. Known.

- **LOADNIL refactor.** The slot-store separation `slot (a+i)` vs `slot (a+j)` becomes `decide` on `i ≠ j`.
- **EQ/LT on strings.** The `str x` chart is what makes abstraction 1's footprint conjunct checkable.

## 3. Boundaries as terms: residual transformers and lenses

### The idea

The statement cost of a split or a call is that the boundary state must be *written* (`AtRet`, `divFrame`, FORPREP's `FpMem`, IDIV's `ArmPre` holding `s3`/`s4` loaded values). §2b found the reason: the generated post-state is raw (`bytesT8 (writeMap8 (writeMap8 m0 …))`) and the halves need it normalised.

Make each generated segment export, besides its `SegSt` lemma, a **residual transformer**: a plain Lean function `post : Env → Env` on a symbolic environment `Env := ⟨pins : Reg → Term, mem : MemTerm⟩`. Its lemma takes the form

```
seg_ok : SegSt pc (⟦e.pins⟧) (P ⟦e.mem⟧) c → Reach c (SegSt pc' ⟦(post e).pins⟧ (P ⟦(post e).mem⟧))
```

A path's state at any boundary is then the *term* `(postₖ ∘ … ∘ post₁) e₀`. It is never a statement: a split lemma's statement is a `def` application.

The normaliser of L4-call′ (`slotVal_wm8`, `k_*_wm8`) becomes a **lens** `view : Env → ArmView`. `ArmView` is a named-field structure (law 6): the slot values read, the operand payloads, `savedpc`, the frame registers. Its `get` is proved once against the raw form, `view_sound : ⟦e⟧ satisfies view e`. A call's frame at return address `r` is `frameAt r e := restrict (live r) e.pins`, where `live r : List Reg` is the generator's liveness set emitted as *data* next to the segments. §1b.4 found that this set covers the kit's hand frame at 14/14 sites.

### Core rules

| law | rule |
|---|---|
| L4-call′ | `call_residual : SegSt jal ⟦e⟧ → Summary f → SegSt r ⟦frameAt r e ⊕ results (f (args e))⟧`. The frame is the term `frameAt r e`. The callee's precondition (`EqCtx`'s address facts) is read off `view e` and discharged by abstraction 2. |
| L4-split′ | `split_at (chain₁ chain₂) : (∀ e₀, Pre e₀ → Run chain₁ e₀) → (∀ e₀, Pre e₀ → Close (view (chain₂.post (chain₁.post e₀)))) → …`. Each half is its own declaration (its own budget). The boundary appears only as `chain₁.post e₀`, which elaborates by δ-reduction of a `def`, not by whnf of memory. Cost ≈ one setup, the 5k measured in §1b.3, and zero statement lines. |

### What it makes free

- `modk_call`'s 4-line `divFrame`, and the `ArmPre` statements for IDIV/IDIVK (whose `s3`/`s4` are loaded values, which a hand frame keeps getting wrong: §1b.4, "`divFrame` holds only because it takes `s3`/`s4`/`s10` as parameters").
- FORPREP's uncommitted `fp_pre`/`FpInts`/`fpFrame`/`FpMem`: all four become `view (chain.post e₀)`.
- The 6 dead-pin frames (`s10` at MUL/MULK/IDIV, `s6`/`s10` at FORPREP). `live r` is exact by construction.
- Any future split forced by the budget. The generator can cut "where the running sum passes ~150k" (§2b) with no proof-side consequence.

### What it costs

- **Setup:**
  - `Env`, `Term`, `MemTerm` with their denotations;
  - the generator emits `post` per segment (it already composes post-pins in `lcall_frames.py`, so this is printing what it computes) and `live r` per return address;
  - `ArmView` + `view_sound`, about 100 lines (est.);
  - `split_at`, `call_residual`, about 60 lines (est.).
- **What gets harder:**
  - `kit_run` fills values with `_` today. With residuals, the environment must stay explicit through the run.
  - `MemTerm` must stay a first-order term (not `writeMap8` applications), or the `post` composition will unfold into exactly the whnf blow-up it was meant to hide. So this abstraction wants abstraction 5's ledger as `MemTerm`.
- **The forbidden-vocabulary risk is low.** The generator emits *definitions* (data), the same status as the generated `SegSt` lemmas today, and no per-arm proof.

### Theories

1. **Partial evaluation / the Futamura projections.** The boundary is the residual of the first half specialised to a symbolic input. Jones, Gomard, Sestoft, *Partial Evaluation and Automatic Program Generation*, 1993 **(recall; check)**. Known.
2. **The transfer-matrix method in thin-film optics.** Each layer is a 2×2 matrix, and the field at any interface is the product of the matrices before it. It is computed and never posited. Born & Wolf, *Principles of Optics*, ch. 1.6 **(recall; check)**. Known physics, from a distant field; the use for proof boundaries is novel.
3. **Bidirectional lenses** for raw ↔ normalised. Foster, Greenwald, Moore, Pierce, Schmitt, "Combinators for bidirectional tree transformations", TOPLAS 29(3), 2007 **(recall; check)**. Known.
4. **Symbolic execution summaries.** King, "Symbolic execution and program testing", CACM 1976 **(recall; check)**. Known.

## 4. Orbit summaries: a loop is the iterate of its body transformer

### The idea

L4-loop′ still asks each loop for an invariant `I`, a pin family and a measure (§2b: "what is left per loop is `I`, `μ` and the body's arithmetic, about 15 of `loadnil_loop`'s 25 lines"). Given abstraction 3's residual `post`, the invariant need not be stated at all. Let `f := bodyChain.post : Env → Env` be the body's transformer at the DFS head. The state after `i` iterations is *by construction* `SegSt h ⟦f^[i] e₀⟧`. The invariant is the orbit `{f^[i] e₀}`.

The exits are a function `ex : Env → Option ExitId`, read off the body's branch guards (bottom test, middle exit, or several exits; a rotated loop is a phase shift of the head). The rule `orbit_loop` says: if the measure decreases, `∀ e, ex e = none → μ (f e) < μ e`, then the run reaches `SegSt (exitPc x) ⟦exitPost x (f^[N] e₀)⟧`, where `N := Nat.find (∃ i, ex (f^[i] e₀) ≠ none)`.

What a loop still owes is the **closed form of its orbit**, `f^[k] e₀ = cf k e₀`. Here the census helps: the loops come in very few *transformer classes*, and each class gets one generic closed-form theorem, not one per loop:

| class | members | `f`'s action | generic theorem |
|---|---|---|---|
| **affine walk with strided stores** | slot nil fill ×5 (LOADNIL `0x8001d2a8`, RETURN0 `0x8001c2f4`, RETURN1 `0x8001ed74`, `luaD_precall` `0x8000ab70`, `luaD_poscall` `0x8000a4a4`), slot copy ×2 | pointer `x ↦ x + c`; memory `↦ wr (x + d) v(x)` | `iterate_affine : f^[k] (x, M) = (x + c·k, foldWrites (fun i => (x + c·i + d, v(x + c·i))) k M)` |
| **bit-serial shift register** | `__muldi3` `0x8002f6d0`, `__udivdi3` ×2 | `a ↦ a >>> 1`, `b ↦ b <<< 1`, accumulate on the low bit | `iterate_shiftAdd`: the closed form by binary expansion (reuses `invmul_bv`, `shr_lt`, `shl_double` from the copied `Muldi3Spec`/`DivLoops`) |
| **read-only cursor** | the string scans of abstraction 1 | cursor `i ↦ i + k`, memory fixed | `firstEvent_chunked` (abstraction 1 is this class's theorem) |

The class of a loop is recognised by **anti-unifying two consecutive iterates**, `f e` and `f (f e)`. The positions that differ become the loop's state, and their difference gives the stride. This is a deterministic term computation, not a search, so it stays within "tools may only check laws". What the anti-unifier proposes is checked by the class theorem's hypotheses (`f`'s action), which are `rfl`/`decide` on the residual term.

### Core rules

| law | rule |
|---|---|
| L4-loop′ | `orbit_loop` (once; it is `Triple.loop` with `I := fun c => ∃ i, SegSt h ⟦f^[i] e₀⟧ c ∧ ∀ j < i, ex (f^[j] e₀) = none`). Exits anywhere, several exits, loop-to-loop by `seq` on the exit post. |
| L4-loop′'s "parametric summaries" | `iterate_affine` and `iterate_shiftAdd`: one theorem per *class*, not per shape instance. The 5 nil fills and 2 slot copies (different head pcs, registers, store offsets `−8`/`0`, store before or after the bump) differ only in `(c, d, v)`. |

### What it makes free

- `loadnil_loop` (25 lines), and the 4 other nil fills.
- The 2 slot copies (`luaD_poscall` `0x8000a464`, `luaT_adjustvarargs` `0x80019874`, needed by VARARGPREP).
- `muldi3_loop`, `udiv_norm` (its mid-body exit is just `ex` on the first half of `f` split as `g ∘ h`), and `udiv_div`, if refactored.
- The `| 0 => absurd | n+1 => …` recursion everywhere.
- The kit's ghost measures (`k` slots left, `2⁶⁴ − a2`). `μ` is now a function of `Env`, and for the affine class it is the generic `(end − x)/c`.

### What it costs

- **Setup:**
  - `orbit_loop`, about 50 lines (est.);
  - `iterate_affine` with the `foldWrites` normal form, about 60 lines (est.). That normal form must be exactly what the multi-slot close consumes, which is KIT.md's forecast "`upd` fold over `bleach`, about 20 lines once";
  - `iterate_shiftAdd`, about 60 lines (est.), mostly the existing copied lemmas.
- **What gets harder:**
  - The rule depends on abstraction 3's residuals. Without `post` as a function, `f` does not exist.
  - Loops whose body calls a function (`l_strcmp`'s chunk loop calls `strcoll` + `strlen` ×2) need `f` to include a `call_residual` node. That is fine in principle, but the transformer then mentions the callee's summary.
  - Loops outside the three classes (the 93 back edges of the print chain: `_svfprintf_r`'s 20, `_malloc_r`'s 8) fall back to `orbit_loop` with a hand closed form. That is still no hand invariant, but a hand `cf`.

### Theories

1. **Kleene algebra with tests.** `while b do p = (b;p)*;¬b`, and the star's unfolding is the orbit. Kozen, "Kleene algebra with tests", TOPLAS 19(3), 1997 **(recall; check)**. Known.
2. **Compositional recurrence analysis.** Loop summaries come from closed forms of the body's transition recurrences. Farzan & Kincaid, FMCAD 2015; Kincaid, Breck, Boroujeni, Reps, PLDI 2017 **(recall; check)**. Known.
3. **Orbits of discrete dynamical systems**, and **C-finite sequences in combinatorics**: a sequence fixed by a linear recurrence has a closed form, which here are the affine class and the shift class. Kauers & Paule, *The Concrete Tetrahedron*, 2011 **(recall; check)**. Known math, from a distant field.
4. **Anti-unification**: the least general generalisation of two terms. Plotkin, "A note on inductive generalization", Machine Intelligence 5, 1970; Reynolds, same volume **(recall; check)**. Known; using it to recognise a loop's class from two iterates is novel.

Then RETURN0's and RETURN1's fills reuse the same theorem with no new lemma; this is the held-out check of the class claim.
- **EQ long strings.** `memcmp`'s two loops as orbits in the read-only class, together with abstraction 1.
- **FORPREP, IDIV, MODK:** no inline loops (§1b.2). Their helper loops (`__udivdi3`'s) are already proved and are only a refactor option.

## 5. Write ledger: memory as entry ⊕ a reflected delta

### The idea

The other third of C-budget is whnf and type checking of concrete memory terms. Every failure seen is a `timeout at whnf` in a close or a fallback unification. The 24k close in MODK's post half is `bleach_store` + `kit_frame` over a `writeMap8` tower. CLAUDE.md's law 1 already says "reflect on the first-order write log; never whnf the Sail state". The kit does not do so in its arm memory.

Represent the memory along an arm path as `apply Δ w.mo`, the **entry ⊕ a ledger**. `Δ : List Entry` is a list literal, with `Entry := ⟨addr : Term, width : Nat, val : Term⟩` and addresses as abstraction-2 charts. Four facts are proved once:
1. **The bridge.** `writeMap8 … (writeMap8 m₀ a₁ v₁) … = apply Δ m₀`, by induction on the chain, generic.
2. **Reads.** `rd (apply Δ m₀) a = (Δ.lookup a).getD (rd m₀ a)`, and the lookup is evaluated by `decide` on chart keys.
3. **Normalisation.** `normalize_sound : apply (normalize Δ) = apply Δ`. It sorts by key, lets later writes shadow earlier ones, and splits widths.
4. **The close.** `close_of_ledger : (∀ e ∈ Δ, e.chart ∈ allowed) → … → Core p c' s' w`. `allowed` is a `Finset Chart` parameter: `slot`/`savedpc`/`ltop`/`cstack` for `bleach`, plus `cframe` for `bleachF` (FORPREP's `sp+40`), so the two closes become one rule. The new register file is read off the `slot` entries of `normalize Δ`.

### Core rules

| law | rule |
|---|---|
| L4-split′ (whnf part) | `rd_apply` + `normalize_sound`. A boundary memory is a short list literal, so a split's second half never unfolds a `writeMap8` tower. |
| L4-str′ | `ledger_frame`: `(∀ e ∈ Δ, e.chart ≠ str _) → TStringRepr (apply Δ m) x s ↔ TStringRepr m x s`. One `decide` on the chart list. |
| L4-call′ (memory) | A callee summary contributes `Δ_callee`, whose entries are havoc terms in `cstack` (plus named out-parameters). Calling is ledger concatenation, `Δ ++ Δ_callee`. The memory part of a call frame is never stated. |
| multi-slot close | `close_of_ledger` covers LOADNIL's `k` nil stores (`foldWrites` from abstraction 4 *is* a ledger) and FORPREP's two slots + spill. |

### What it makes free

- `bleach_store`, `bleach_same`, `bleachF`, `kit_frame`, `Core.stack_of`: one rule with a chart-set parameter.
- The insert read-through lemmas in `Kit/Multi.lean`, and `SegSt.mem_eq`.
- The 557k segment: a fallback unification against a store chain becomes a list comparison.
- FORPREP's `FpMem` memory part.
- The 24k close (est.: to < 5k).

### What it costs

- **Setup:**
  - `Entry`, `apply`, the bridge, `rd_apply`, `normalize` + soundness, `close_of_ledger`: about 150 lines (est.);
  - the generator's segment posts must be rewritten to ledger form once, at the bridge, not per segment.
- **What gets harder:**
  - Overlapping widths (a byte store inside a word another entry wrote: `sb 3,8(s6)` next to `sd a5,0(s6)` is disjoint, but a future `sh` into a word is not). `normalize` must split to bytes or prove the overlaps away. Byte splitting is simplest and keeps `decide` finite.
  - Values are `Term`s, so their denotation is evaluated only at the close.
- **Relation to existing work.** This is the arm-level counterpart of `FrameMeta.memFrame_of_chain` ("one `decide`", CLAUDE.md), which works on runs. The ledger should *reuse* its write-chain reflection, not duplicate it.

### Theories

1. **Patch theory.** A repository state = the base ⊕ a sequence of patches, with commutation of independent patches. Mimram & Di Giusto, "A categorical theory of patches", ENTCS 298, 2013; Darcs (Roundy 2005) **(recall; check)**. Known, from a distant field (version control).
2. **Double-entry bookkeeping.** Transactions are journaled, and a balance is computed on demand, never carried. Pacioli, *Summa de arithmetica*, 1494 **(recall; check)**. Known, from a distant field (accounting). The "close" is the trial balance: every entry in the ledger must post to an allowed account.
3. **Delta relations in incremental view maintenance.** Gupta & Mumick, "Maintenance of materialized views: problems, techniques, and applications", IEEE Data Eng. Bull. 18(2), 1995 **(recall; check)**. Known.
4. **Proof by reflection.** Boutin, "Using reflection to build efficient and certified decision procedures", TACS 1997 **(recall; check)**. Known.

### Pilot

- **FORPREP.** This is **the smallest decisive test.** Build `Entry`, `apply`, the `writeMap8` bridge, `rd_apply`, and `close_of_ledger` with a chart-set parameter (needs abstraction 2's `Chart`, or a fallback with `Nat` keys and `omega` once per entry). Close FORPREP's two exits (run/skip) with `allowed = {slot, savedpc, ltop, cstack, cframe}`.
- **MODK refactor.** Replace the post half's `bleach_store` + `kit_frame` (24k measured) and measure.
- **LOADNIL refactor.** The `k`-slot nil fill closes by `close_of_ledger` on `foldWrites`.
- **IDIV.** Two helpers' `cstack` havoc ledgers concatenate.
- **EQ/LT on strings.** `ledger_frame` makes `Core.strTape` (abstraction 1) hold *along* the path, not just at heads.

### Seed

The digit clusters `C596`, `83`, `24`, `91`, `7E6` read as ledger entries. The bracket `Zk2 … Hq2d` read as "start, then entries, then the balance at the end".
