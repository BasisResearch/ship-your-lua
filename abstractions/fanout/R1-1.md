## 1. Intrinsically-footprinted micro-op trees (a typed effect language for opcodes)

**The idea.** Stop writing an opcode's meaning as a `Step` constructor. Write it
as a term in a small first-order effect language whose *type* carries its
footprint:

```lean
-- R: registers it may read, W: registers written so far, E: the edges it may take
inductive μ : (R : Mask) → (W : Mask) → (E : List Edge) → Type
  | rd    (r : Nat) (h : r ∈ R)          (k : Value → μ R W E)   : μ R W E
  | kst   (i : Nat)                       (k : Const → μ R W E)   : μ R W E
  | peek  (k : Word → μ R W E)            -- fetch pc+1 (donextjump)
  | stuck                                                          : μ R W E
  | wr    (r : Nat) (v : Value)           (k : μ R (W ∪ {r}) E)   : μ R W E
  | emit  (s : String)                    (k : μ R W E)           : μ R W E
  | go    (e : Edge) (he : e ∈ E) (hw : W = e.wr)                  : μ R W E
```

Each opcode is one function `sem : Word → Σ R E, μ R ∅ E` whose indices are the
footprint. `reads w`, `edgesOf pc w` and `regTop w` are *projections of that
term's type*. They are no longer tables kept next to the relation. `Step`
becomes the graph of a single generic runner:

```lean
def run : μ R W E → State → Option State      -- one definition, ~15 lines
def Step s s' := ∃ w, p.fetch s.pc = some w ∧ run (sem w).2.2 s = some s'
```

The current constructors (`Step.arith`, `Step.testsetJump`, …) turn into
*derived* lemmas with the same statements, one line each (`⟨w, hf, by simp [sem, run, *]⟩`).
The reader still sees `lvm.c`-shaped rules, but none of them is an axiom of the
development.

The design choice that matters is the continuation style (`k : Value → μ …`).
Branching on a value (`match v with | .int x => … | _ => stuck`) is ordinary
Lean. Register *indices*, however, come only from word fields, never from
values. That is exactly why a type index can state the footprint.

**Core rules.**

- **L-B2 becomes `Iff.rfl`.** `Step H p s s' ↔ step? H p s = some s'`, where
  `step? s := (p.fetch s.pc).bind fun w => run (sem w) s`. The "stepper" is not a
  separate artifact, so there is no soundness theorem left to prove.
- **L-B1 becomes one non-interference theorem, by induction on `μ`:**
  ```lean
  theorem μ.footprint (t : μ R W E) (s₁ s₂ : State)
      (hpc : s₁.pc = s₂.pc) (hout : s₁.out = s₂.out) (hR : ∀ r ∈ R, s₁.regs r = s₂.regs r) :
      (run t s₁ = none ↔ run t s₂ = none) ∧
      ∀ s₁' s₂', run t s₁ = some s₁' → run t s₂ = some s₂' →
        ∃ e ∈ E, s₁'.pc = e.1 ∧ s₂'.pc = e.1 ∧ s₁'.out = s₂'.out ∧
          (∀ r ∈ e.wr, s₁'.regs r = s₂'.regs r) ∧
          (∀ r ∉ e.wr, s₁'.regs r = s₁.regs r ∧ s₂'.regs r = s₂.regs r)
  ```
  The `hw : W = e.wr` index on `go` produces the census's *some edge* refinement
  (the `TESTSET`, `sJ = 0` case) for free. The two `TESTSET` edges are two
  distinct `go` leaves, each carrying its own write set.

**What it makes free.** All of `bc-rule-fanout`:
- the 27 `Step.sim` arms, which become `μ.footprint` applied to `sem w`;
- all `step?_sound` and `step?_complete` arms, which become definitional;
- the `edgesOf`/`reads`/`regTop` entries, which become projections.

What remains per opcode is the `sem` term with its membership side conditions
(`r ∈ rmask w.b 1 ||| rmask w.c 1`). A `decide`-able `Mask` membership
discharges those uniformly. Adding the 11 F1b bitwise opcodes would have cost 11
`intArith` lines and nothing else.

**What it costs.**
- Setup: `μ`, `run` and `footprint`, roughly 120 lines; the indexed `Mask`
  algebra (∪, ∈, decidable), roughly 40.
- A one-time R1 refactor proves the old inductive `Step` equal to the new one.
  That is the only per-rule pass left, and it is mechanical.
- Harder:
  - `edges` must stay *computable* for the `Supported` fixpoint. `E` has to be
    computed from the word (a function `edgesOfμ`), not merely proved about.
    So `sem : (w : Word) → μ (readsμ w) ∅ (edgesOfμ pc w)` needs `readsμ` and
    `edgesOfμ` as functions after all. They are small and live *in the type of*
    `sem`, so they cannot drift. This is the main honest caveat.
  - Dependent-type friction: `W ∪ {r}` has to reduce by `decide`/`simp` at
    concrete masks. Use `Nat` bitmasks, not `Finset`.

**Theories.**
- *Known.* Intrinsically-typed definitional interpreters: Poulsen, Rouvoet,
  Tolmach, Krebbers, Visser, "Intrinsically-typed definitional interpreters for
  imperative languages", POPL 2018. The construction used here: type soundness
  by construction, with the index carrying the invariant.
- *Known.* Read/write-set scheduling in database concurrency control: Bernstein,
  Hadzilacos, Goodman, *Concurrency Control and Recovery in Database Systems*
  (1987). Two operations conflict iff one writes what the other reads or
  writes. `footprint` is the "a transaction's result depends only on its read
  set" axiom those proofs assume.
- *Known.* Algebraic effects: Plotkin & Power, "Algebraic operations and generic
  effects" (Applied Categorical Structures, 2003). `μ` is a free model of the
  signature {rd, wr, emit, go}, and `run` is its handler.
- *Novel:* using the *effect-signature index* as the fragment-check table.

**Pilot.**
- **H1** (`LOADK` of `Const.str`): drop the `.str` exclusion in `edgesOfμ`, and
  `sem` is unchanged. Near 0 lines.
- **H2** (`CONCAT A B`): `sem = rdRange A B fun vs => match concatAll vs with |
  some v => wr A v (clobber (A+1) (B-1) (go …)) | none => stuck`. Here `rdRange`
  is a 5-line recursive μ-builder (reads `rmask A B`), and `concatAll` is a
  right fold with `tostring` of integers.
  - *Check against `lvm.c`:* whether `luaV_concat` leaves intermediate values
    in `R[A+1..A+B-1]`. From memory it concatenates in place at the stack top.
    If so, the edge must write `rmask A B`, not `rmask A 1`.
- **H3** (`LEN`): one `sem` arm.
- **H4** (`LT`/`LE`): the `cmpRR` arm's `match` gains `| .str a, .str b => lexLt a b`.
- **R1:** replace `Step.sim` + `step?_sound`/`complete` with `μ.footprint` +
  `Iff.rfl`.
- Smallest thing to build: `μ`, `run` and `footprint` for 3 opcodes (`MOVE`,
  `TESTSET`, `FORLOOP`, which cover multi-edge and multi-write). Then check that
  `TESTSET`'s `sJ = 0` double edge comes out right.

**Seed.** The palindromes `tft`, `rfr`, `9k9`. One term read in two directions
gives the relation (read backwards: "which `s` step to `s'`") and the function
(read forwards). L-B2 stops being a theorem because both are readings of the
same word.

## 2. Discriminant skeletons: rules selected by a computed key, not guarded alternatives (LL(1) for big-step)

**The idea.** The source semantics' quadratic determinism cost comes from
*guarded alternatives*. `whileT`/`whileF`/`whileX` are three rules for one
construct, told apart by premises (`v.isFalse = true/false`, `sg = normal / ≠`).
Every pair then has to be inverted to show the guards are exclusive.

Replace guarded rule families with **skeletons** built from four combinators:
- `ev e` (evaluate a subterm);
- `filter f` (apply a *partial function*);
- `case d [branches]` (compute a *discriminant* `d : … → Tag` into a finite
  type, then take the one branch it names);
- `loop` (see below).

Each construct is one skeleton, and `ExecS` is its generic big-step
interpretation. Selection is by *computing a key*, like an LL(1) parser choosing
a production by one token of lookahead, so exclusivity holds by construction:
`case` on a function value has one branch.

The loop is the same shape three times. `while`, `repeat` and `fornum`/`ForIter`
all instantiate one skeleton:

```
loop (pre : ctx → Skel Tag) (body : Skel Sig) (post : Sig → Tag) (step : ctx → ctx)
  where Tag ∈ {exit, again, abrupt}, and abrupt returns sg.exitLoop
```

- `while`: `pre = ev c ≫ case isFalse`, `post = id`.
- `repeat`: `pre = skip`, `post = ev c in the body's env ≫ case isFalse`.
- `fornum`: `pre = case (n = 0)`, `step = (i+st, n-1)`.

The `goto` resumption in `ExecBF` (`sg.target all`) is also a `case` on a
computed `Option`.

**Core rules.**
- **L-A1 as a single theorem about the generic interpretation.** For every
  skeleton program `K`, let `⟦K⟧ᴿ` be its big-step relational interpretation
  and `⟦K⟧ᶠ n` its fuel-indexed functional interpretation. Both are derived
  from the *same* `K` by one generic definition each:
  ```lean
  theorem Skel.graph (K : Skel) : ⟦K⟧ᴿ σ r ↔ ∃ n, ⟦K⟧ᶠ n σ = some r
  ```
  Proved once by induction on the skeleton language, which has about 6
  combinators. Determinism, `(⟦K⟧ᴿ σ r₁ → ⟦K⟧ᴿ σ r₂ → r₁ = r₂)`, is a corollary:
  fuel-monotonicity plus the function being a function.
- `LuaSem := ⟦chunkSkel c⟧ᴿ`. The existing rules `whileT` etc. are derived
  lemmas, one line each.

**What it makes free.**
- `ExecS.det` (53 arms), `Eval.det` (50) and `execSound` (all arms) collapse into
  `Skel.graph`.
- Per construct, what remains is its skeleton, about as long as the current
  rules' premises, with no proof.
- The ×2 cost trend stops. It came from the number of alternatives per construct
  and their pairwise inversion. With `case`, alternatives no longer multiply
  obligations.

**What it costs.**
- Setup: the skeleton syntax (mutual, because blocks, statement lists and
  `ForIter` recurse into each other), two interpretations, and `Skel.graph`.
  Estimated 250 to 350 lines.
- Harder:
  - Skeletons must be *first-order data* for the generic induction, but
    constructs recurse into sub-blocks. The skeleton language needs a
    "call the semantics of sub-phrase `b`" hook (`Skel.sub b`), and the
    interpretation is defined by well-founded recursion over syntax plus fuel.
    This is the Bodin et al. "hook" construction.
  - Readability: a reviewer checking faithfulness to the Lua manual reads a
    skeleton rather than an inference rule. The derived-lemma presentation
    mitigates that.

**Theories.**
- *Known.* Bodin, Gardner, Jensen, Schmitt, "Skeletal semantics and their
  interpretations", POPL 2019: one semantic description with several generic
  interpretations (concrete, abstract, big-step), and consistency proved once.
  The same group built a Coq tool for it ("Necro"; tool name from memory, check).
- *Known.* Pretty-big-step semantics: Charguéraud, ESOP 2013. It factorises rules
  so that each evaluates one subterm, which removes premise duplication in
  `whileT`/`whileX`-style families.
- *Known, linguistics/parsing.* The LL(1) condition: Lewis & Stearns, "Syntax-directed
  transduction", JACM 1968; Knuth, "Top-down syntax analysis", Acta Informatica
  1971. Alternatives of a nonterminal are selected deterministically iff their
  lookahead sets are disjoint. Here the "lookahead" is the discriminant, and it
  is a function, so disjointness is automatic.
- *Novel:* a single `loop` skeleton, parameterised by where the test sits
  (pre/post/counter), that makes `while`/`repeat`/`fornum` one proof.

**Pilot.**
- **H1:** one skeleton leaf (`ret (.str s)`).
- **H2:** `ev a ≫ ev b ≫ filter concatV`, where `concatV : Value → Value → Option Value`
  converts integers with `%d`.
- **H3:** `ev a ≫ filter lenV`.
- **H4:** `ev a ≫ ev b ≫ filter ltV`, extended to strings.
- Zero determinism or soundness lines for all four. The only cost is the
  `supE` admission.
- **R2:** re-express `ExecS`/`ExecL`/`ExecBF`/`ForIter` as skeletons, and delete
  `Eval.det`, `ExecS.det` and `execSound`.
- Smallest thing to build: the `loop` skeleton alone, with `Skel.graph`
  restricted to {`ev`, `case`, `loop`}. Then show that the three `while` rules
  and both `ForIter` rules are its derived lemmas, and that determinism of
  `while` is one line.

**Seed.** The repeated bigrams `jX`, `Nq`, `pk`. The same fragment appears at
different sites of the string, as the one loop shape appears under three
constructs. The `LL(1)` angle came from `K5`/`5K59`: one key token decides.

## 3. X-propagating registers: definite initialisation as 4-state logic, footprint as monotonicity

**The idea.** Make "stale" a real value. Registers hold `Value⊥ := Option Value`.
`none` is an **X**: whatever garbage the C stack left there, as in 4-state
hardware simulation. Every primitive is *strict*: a rule's premise
`s.regs r = some (.int x)` cannot match X, so reading X leaves the rule stuck.
Where the machine leaves garbage, the semantics writes X:
- entry registers above `top`;
- what `CALL` clobbers above its results;
- the temporaries `CONCAT` may leave.

`BcSem` is the ⊥-free image.

There is an information order `sx ⊑ sy` (sy agrees wherever sx is defined).
L-B1 then becomes **monotonicity of the lifted step**: define more registers
and you get the same pc, output and written values. "Agree on `reads w`" is the
special case `s₁ ⊒ (s₁|reads) ⊑ s₂`. The fragment check's mask fixpoint is
literally the abstraction of an `Option`-state to its definedness pattern
`{r | regs r ≠ none}`. Its soundness is the textbook abstract-interpretation
theorem, proved once, rather than `bcSemFrom_iff` and `cbcSem_iff` argued
through per-rule simulations.

**Core rules.**
- **L-B1 ⇒ `StepX.mono`:**
  ```lean
  theorem StepX.mono : sx ⊑ sy → StepX sx sx' → ∃ sy', StepX sy sy' ∧ sx' ⊑ sy' ∧ sx'.pc = sy'.pc ∧ sx'.out = sy'.out
  theorem StepX.edge : StepX sx sx' → ∃ e ∈ edges pc, sx'.pc = e.1 ∧ agreeOutside e.wr sx sx'
  ```
  Together with "`sx|reads` still steps whenever `sx` does" (reads-sufficiency),
  these give L-B1 by instantiating `sx := s₁|reads`.
- **Definite-init soundness ⇒ one Galois-connection theorem.** Let
  `α(sx) = defined-mask`, `γ(m) = {sx | m ⊆ α sx}`. `sweep` is a sound
  abstraction of `StepX`'s definedness transformer (`keepMask`/`wr` are exactly
  α of `CALL`'s X-writes and of the edge writes). Then:
  ```lean
  theorem supported_certain : Supported p → (BcSemX p (initX) out ↔ ∀ garbage, BcSem p (init garbage) out)
  ```
  This is the database "certain answer": the output is the same under every
  completion of the nulls.

**What it makes free.**
- The per-rule `Step.sim` arms. `mono` is proved by one uniform tactic over the
  constructors, because every premise is a positive `= some _` match (preserved
  by ⊑), and every conclusion is `set`/`goto`/`emit` (monotone). The per-rule
  content goes from about 8 lines to 0.
- The `bcSemFrom_iff`/`cbcSem_iff` machinery, which becomes the certain-answer
  theorem.
- The A1 representation relation becomes simpler: a machine register slot with
  garbage is related to X, with no case split on whether it was initialised.

**What it costs.**
- `Value⊥` threads through `State.set`/`args`/`printLine`. `print` of X must be
  stuck: a strict `args`.
- Honest caveat: `mono` is proved "by one tactic across constructors", not by a
  structural theorem. It stays cheap only while every rule keeps positive
  premises. A negative premise (`s.regs r ≠ .nil`) breaks monotonicity; such a
  premise must be written as a positive disjunction. Combined with #1, `mono`
  becomes structural (induction on `μ`, with `rd` strict).
- The existing `Supported`-based statements have to be re-proved against the
  X-semantics: this is the R1 refactor.

**Theories.**
- *Known, hardware.* 4-state logic simulation (0/1/X/Z) in IEEE Std 1364
  (Verilog), and "X-propagation" analysis in RTL verification, where X
  pessimism/optimism is exactly the question of whether the lifted semantics is
  monotone and sound.
- *Known, databases.* Imieliński & Lipski, "Incomplete information in relational
  databases", JACM 31(4), 1984. Certain answers over completions of nulls, and
  when a representation system is closed under the query language. Here the
  "query language" is `Step`, and `supported_certain` is a certain-answer
  theorem.
- *Known.* Kleene's strong three-valued logic (Kleene 1952, *Introduction to
  Metamathematics*), and Scott's information order. Monotone = continuous here,
  since the state is finite per step.
- *Known.* Cousot & Cousot, POPL 1977: `sweep`'s soundness as an abstract
  interpretation via a Galois connection.
- *Novel:* treating the C stack's stale slots as X in the *source-level
  specification*, so the definite-initialisation analysis is the abstraction of
  that specification rather than a side condition.

**Pilot.**
- **H2 is the showcase.** If `luaV_concat` leaves intermediates in `R[A+1..]`,
  the rule writes X there, and the fragment check learns that for free from
  `α`. There is nothing to argue about "which garbage".
- **H1, H3, H4:** strict premises on `.str`, so `mono` is automatic.
- **R1:** delete the `Step.sim` arms and replace the `bcSemFrom_iff` proof with
  `supported_certain`.
- Smallest thing to build: `StepX` for `MOVE`/`CALL`/`FORLOOP` with the uniform
  `mono` tactic, plus the Galois-connection lemma for `sweep` on one edge.

**Seed.** `VxzzV`: an `x` and a double `z`, the unknown and high-impedance
values of Verilog, sitting between two `V`s like a value boxed on both sides.

## 4. Factored opcodes: Prim × Addressing × Continuation (an item-and-arrangement ISA)

**The idea.** Both layers restate the same *operator meanings* in many rules:
- Source: `Eval.arith`, `cmp`, `eq`, `ne`, `neg`, `bnot`, `not`.
- Bytecode: `arith` (three shapes), `unm`, `bnot`, `not`, `eq`, `eqk`, `eqi`,
  `cmpRR`, `cmpRI`.

Factor every such opcode into three orthogonal parts. Only the smaller factors
carry laws:

- `Prim`: the *value-level* operation, one total table
  `Prim.apply : Prim → List Value → Option Value`. It covers `+`, `//`, `<`,
  `==`, `not`, `#`, `..`, etc. The source and the bytecode share this, so
  `BinOp.arith`/`intArith`/`intCmp` merge into one.
- `Addr`: where operands come from and where the result goes: `rr`, `rk`, `ri`,
  `r`, `range A B` (for `CONCAT`/`CALL`), `aTest` (compare `R[A]` with the
  operand). There are about 7 of them.
- `Cont`: what happens after:
  - `store+skipMMBIN` (`pc+2`);
  - `store` (`pc+1`);
  - `condjump k` (`docondjump`).

  There are 3.

The opcode table becomes `decodeF : OpCode → Prim × Addr × Cont`, and `Step`
has *one* rule for all of them:

```lean
| op {s w o pr ad ct args v s'} : p.fetch s.pc = some w → w.op? = some o → decodeF o = some (pr, ad, ct) →
    ad.fetch p s w = some args → pr.apply args = some v → ct.finish p s w ad v = some s' → Step s s'
```

On the source side, `Eval.op : EvalList ρ es vs → pr.apply vs = some v → Eval ρ (opExp pr es) v`
replaces seven rules. `and`/`or` stay separate because they are not strict.

**Core rules.**
- **L-B1 per `Addr` and per `Cont`, not per opcode.** `Addr.footprint`
  (7 cases): `fetch` depends only on `Addr.reads w`. `Cont.footprint`
  (3 cases): `finish` writes only `Cont.writes`, and lands on `Cont.edges`. The
  per-opcode law is their composition, proved once:
  ```lean
  theorem op_footprint : Addr.footprint ad → Cont.footprint ct → Footprint (Step.op via decodeF o)
  ```
- **L-B2 / L-A1 for the whole family.** `pr.apply` is a function, so the one
  `op` rule is deterministic and executable by construction. One stepper arm
  and one soundness/completeness arm cover the entire operator family, about
  40 of the 54 opcodes.

**What it makes free.** Laws cost `|Addr| + |Cont| = 10` cases instead of
`|opcodes| ≈ 54`. Every new *operator* (`Prim` case) costs zero proof lines: it
is a data point in a function.

The held-out suite is almost entirely new *operators on existing addressing*:
- H2 `..`, H3 `#`, H4 string `<`/`<=` are `Prim` cases.
- Only `CONCAT` needs one new `Addr` (`range`), and even that is shared with
  `CALL`'s argument window.

Source and bytecode sharing `Prim.apply` also makes the later Layer-B
compiler-correctness proof relate `Eval.op` to `Step.op` *once*, rather than per
operator.

**What it costs.**
- Setup: `Prim`, `Addr`, `Cont`, `decodeF`, and the two footprint families.
  About 150 lines. The R1 refactor rewrites the constructor set.
- Harder:
  - Irregular opcodes do not factor: `FORPREP`/`FORLOOP` (multi-write, count
    arithmetic), `TESTSET` (conditional write), `LOADNIL`, `CALL print`. They
    stay as ordinary rules, about 10 of them, and keep incumbent per-rule cost.
  - `SHLI`'s swapped operands (`sC << R[B]`) and `GTI`/`GEI` must be encoded as
    `Prim` variants (`flip`), not in `Addr`. Otherwise `Addr` loses
    orthogonality.

**Theories.**
- *Known, linguistics.* Hockett, "Two models of grammatical description", *Word*
  10 (1954). Item-and-arrangement vs. item-and-process: a paradigm of surface
  forms (opcodes) analysed as a product of independent morphemes (operation ×
  operand pattern × continuation). The lesson carried over: stating rules on the
  morphemes, not on the words, is what makes the paradigm cheap to extend.
- *Known, algebraic automata theory.* Krohn & Rhodes, "Algebraic theory of
  machines I", Trans. AMS 116 (1965). Machines decompose into cascades of
  simpler components. Here the decomposition is a product rather than a
  cascade, and laws are proved on components (*analogy; the product version is
  the elementary case*).
- *Known, compilers.* CompCert's `Cop.sem_binary_operation`, one operator
  semantics consumed by several intermediate languages' evaluation rules
  (file name from memory; check).
- *Novel:* `Cont` as an explicit factor that absorbs `lvm.c`'s
  `MMBIN`-skip / `docondjump` idioms, so that L-B1's edge component is proved
  on 3 continuations.

**Pilot.**
- **H1:** extend `Const.toValue?`'s admission in the `rk`/`Bx` addressing. No
  rule changes.
- **H2:** `Prim.concat` + `Addr.range`.
- **H3:** `Prim.len` with `Addr.r`.
- **H4:** extend `Prim.lt`/`Prim.le` with `| [.str a, .str b] => lexLt a b`. Zero
  proof lines.
- **R1/R2:** collapse the operator constructors on both sides and delete their
  arms.
- Smallest thing to build: `Step.op` for `ADD`/`ADDK`/`ADDI`/`EQ`/`LTI`
  (3 `Addr`, 2 `Cont`) plus `op_footprint`, then add `BNOT` and measure the
  marginal cost. The census says it cost 10 lines by hand; here it should be 1.

**Seed.** The case pairs `Yy`, `Gg`, `aA`: the same letter in two cases, as the
same operator appears in two syntaxes (source `a + b`, bytecode `ADD`/`ADDK`/`ADDI`).
Mining for "one letter, several forms" led to the morpheme factorisation.

## 5. Arms as lifted micro-op traces, compared modulo independence (Mazurkiewicz-trace equivalence for L-C1)

**The idea.** For L-C1, take the compiled arm between two visits to the
dispatch head and **lift** it, with one verified function, into the *same*
micro-op language as the opcode's specification. That language is #1's `μ`, or
any first-order effect trace language. Then compare the two terms as
**Mazurkiewicz traces**: equal up to commuting *independent* effects.

The compiler reorders things freely:
- it writes a `TValue`'s tag byte before or after its 8-byte payload;
- it hoists the `pc` increment;
- it interleaves `savedpc` stores.

None of this matters, because independent writes commute, and independence is
decided by footprint (disjoint addresses/registers). This is the same read/write
footprint as L-B1, reused a level down.

The lifter is symbolic evaluation over a *representation-aware* term algebra,
defined once against the Lua VM's data layout:
- a load from `base + 16·i` (TValue payload) together with `base + 16·i + 8`
  (tag) is recognised as `rd i`;
- the matching stores are recognised as `wr i v`;
- the `vmfetch` sequence at the arm's end is recognised as `go (pc+k)`.

Anything unrecognised makes `lift` return `none`: fail closed.

**Core rules.**
- **L-C1 ⇒ `lift_sound`**, proved once for the lifter, by induction on the
  lifted instruction list, against the Sail RISC-V step:
  ```lean
  theorem lift_sound : lift Lay code head = some t →
    ∀ m s, Rep Lay m s → AtHead m → ∃ m', MachSteps m m' ∧ AtHead m' ∧ Rep Lay m' (runSpec t s)
  ```
- **Arm obligation ⇒ a decidable equation.** `traceEq (lift armᵣ) (sem r) = true`,
  where `traceEq` is computed via Foata normal form (a canonical representative
  of a trace class). Its soundness is proved once:
  `traceEq t u = true → run t = run u`, which needs only commutation of
  independent `μ` operations.
- Composition to `VmSim` (`Refine.Sim` in `Lua/Theorems.lean`) is one induction
  on `Steps`, with `AtHead` as the coinductive cut predicate.

**What it makes free.** The whole forecast `a1-arm-sim` cluster. Its per-arm
cost falls from "months of per-location proofs" to one `decide`/`rfl` on a
normal form. A new fragment's opcode then costs its `sem` term (#1) and nothing
on the machine side, as long as its arm uses only instruction and memory idioms
the lifter already knows.

**What it costs.**
- Large setup:
  - the lifter for the RV64 subset `luaV_execute` uses (loads/stores/ALU/
    branches/`jalr` through the jump table);
  - the `Rep` separation-logic predicate (register window, `ci->u.l.savedpc`,
    `L->top`, constants array);
  - the Foata normaliser and its soundness.

  Likely 800 to 1500 lines.
- Harder, and specific:
  1. **Calls out of arms.** `OP_CONCAT` calls `luaV_concat` and then a GC check
     (`checkGC`; recalled from `lvm.c` 5.4.7, check). `OP_LEN` calls
     `luaV_objlen`. The lifter must stop at a `jal` to a known callee and emit
     an opaque effect `call f` justified by a *callee contract*, a Hoare triple
     proved separately. GC is the hard part: `Rep` must be stable under
     collection, meaning it cannot mention addresses of collectable objects
     except through a heap abstraction.
  2. **Strings in `Rep` (H1, H4, and EQ on strings).** Short strings (≤ 40
     bytes, `LUAI_MAXSHORTLEN`, from memory) are interned, so the machine's
     `EQ` on them is pointer equality (`eqshrstr`). `Rep` must carry the
     invariant "equal short strings ⇒ same object", or `traceEq` will not match
     `EQ`'s spec. Long strings go through `luaS_eqlngstr` (memcmp), which is
     another callee contract.
  3. `decide` on long arms may be slow in the kernel, and `native_decide` is
     disallowed (axioms standard). The normaliser must be structurally
     recursive and small.

**Theories.**
- *Known, concurrency.* Mazurkiewicz trace theory (Mazurkiewicz 1977, "Concurrent
  program schemes and their interpretations", DAIMI PB-78). Equivalence of
  words under an independence relation. Cartier & Foata (1969, Lecture Notes in
  Math. 85) give the Foata normal form, a canonical form that makes that
  equivalence decidable by comparing normal forms.
- *Known, verification.* Myreen, Gordon, Slind, "Machine-code verification for
  multiple architectures: an application of decompilation into logic", FMCAD
  2008. Decompiling machine code into a functional spec with a proof. Here the
  decompiler is a *verified function* (reflection) rather than a proof-producing
  tactic, so there are no per-arm generated lemmas.
- *Known, category theory.* Rutten, "Universal coalgebra: a theory of systems",
  TCS 249 (2000). The machine observed only at `AtHead` states is a coalgebra.
  `lift_sound` says the representation map is a (lax) coalgebra morphism into
  `Step`, and simulation for `Steps` follows by the standard morphism-to-bisimulation
  argument.
- *Novel:* using the *spec language's own footprint* (L-B1) as the independence
  relation for comparing compiled code against specification. The same law then
  pays for itself in both layers.

**Pilot.**
- **A1 arms**, only if A0.6 lands:
  - `ADD`: straight-line, tag checks for both operands, store and skip `MMBIN`;
  - `EQI`: condjump, including the `donextjump` fetch of `pc+1`;
  - `FORLOOP`: three reads and three writes, where reordering is guaranteed.

  `FORLOOP` is the discriminating test of trace equivalence.
- **H cases** on the machine side: `LEN` on a string needs one callee contract
  (`luaV_objlen` string branch, or inlined `tsslen`); `CONCAT` needs the GC
  contract. Report them separately; they are what this idea does *not* make
  cheap.
- Smallest thing to build: lift the `ADD` arm only, with a `Rep` restricted to
  the register window, and `traceEq` against `sem ADD` by `decide`.

**Seed.** The bracketed run `3Op498U9k9QHPNq3`. `Op` and its digits sit between
two `3`s, as an arm runs between two dispatch heads. The interleaved letters and
digits suggested two sorts of action shuffled together whose relative order does
not matter, which is Mazurkiewicz traces.
