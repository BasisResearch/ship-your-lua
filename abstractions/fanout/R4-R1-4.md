## 1. The closed lid: support-indexed facts (`Sealed`)

### The idea

The relation's eye does not close over strings. `Core.frame` ties `c.σ.mem` to `w.mo` outside `Win`, and `ValRepr.str` states `TStringRepr w.mo x s`. Nothing joins the two, because nothing says where the string *is*. KIT.md's obstruction 1 is that gap.

Do not add a string field. Change the *kind* of fact the complement holds: every complement fact carries its **support**, the set of addresses its truth depends on. One generic theorem then moves any fact whose support misses the window from `w.mo` to the machine memory, at every point of every F1 run. The lid closes once, for every kind of heap object (strings now; tables, closures, `Udata` later), not per resource.

### Core rules

```lean
/-- `P` depends only on the total reads of the addresses in `S`. -/
structure Sealed (P : Mem → Prop) (S : Nat → Prop) : Prop where
  local_ : ∀ m m', (∀ a, S a → bytesT1 m a = bytesT1 m' a) → P m → P m'

/-- (L4-str′ as ONE rule) A sealed fact of the complement holds of the
machine memory when its support misses the window. -/
theorem Core.unseal (hc : Core p c s w) (hP : Sealed P S)
    (hS : ∀ a, S a → ¬ Win p w a) (h : P w.mo) : P c.σ.mem

/-- …and along any run whose write log lands in the window
(every F1 arm: `Core.frame_of`'s hypothesis, or `kit_frame`'s chain). -/
theorem Sealed.along (hP : Sealed P S) (hS : ∀ a, S a → ¬ Win p w a)
    (hrun : ∀ a, ¬ Win p w a → bytesT1 m' a = bytesT1 m a) : P m → P m'
```

- `TStringRepr` reads with presence (`BytesAt` is `m[a]? = some _`, as `TStringRepr.inj`'s `Option.some.injEq` shows), so it is not `Sealed` against `bytesT1` equality. Add its total-read shadow once: `TStringReprT m ts s` (tag at +8, length at +11 or +16..23, `BytesAtT m (ts+24) (s ++ [0])`), with `TStringRepr.toT` and `Sealed (TStringReprT · ts s) (tsFoot ts s)`. The footprint `tsFoot` is exactly L4-str′'s: +8, +11, +16..23, the contents and the terminator. It is *not* +0, +9 or +12, which GC and hashing write.
- The relation change is one index, not a field per resource: `ValRepr mo ι W` with `W := Win p w`, and the `str` constructor carries `∀ a, tsFoot x.toNat s a → ¬ W a`. `W` is constant along every F1 arm (`w` is kept), so the extra conjunct is threaded by the existing `Core.write`/`Core.jump` for free. `Complement.kconst` inherits it for `K[i]`.
- Derived, once: `Core.str_bytes : Core p c s w → s.regs j = some (.str t) → BytesAtT c.σ.mem (x + 24) (t ++ [0])`, where `x` is the slot payload.

### What it makes free

- The four named premises `sim_EQ_of_long`, `sim_EQK_of_long`, `sim_LT_of_str`, `sim_LE_of_str` become ordinary paths, given a `memcmp`/`strcmp` summary (#2).
- UNM's numeric-string path, CONCAT and LEN read strings through the same `Core.str_bytes`.
- Later heap objects (a table's array part for GETTABLE/SETTABLE) use the same `Sealed` with their own footprint. Each needs one `Sealed` instance, not a relation edit.

### What it costs

- `TStringReprT` + `Sealed` instance + `unseal`/`along`: about 60 lines, once.
- A boot-witness obligation: each boot-reachable string's `tsFoot` misses `Win`. `gen_lua_boot_witness.py` already reads every string (`check_tstring`). The trace check (§2b: 0 overlaps on 6,275 strings) says it holds.
- What gets harder: CONCAT and CALL must *establish* the lid for new strings (`luaS_newlstr`'s chunk is fresh, so it is disjoint from the Lua stack chunk by `DlHeap.HeapAt`). That is real work, but it belongs to those arms anyway.
- Check: whether `ι`-interned short strings at boot all lie in the heap rather than `.rodata`. If some lie in `.rodata`, they are still outside `Win` (`Win.above` plus the image bounds).

### Theories

- **Dynamic frames** (Kassios, FM 2006, "Dynamic frames: support for framing, dependencies and sharing without restrictions"). A function's *reads* clause is its support, and framing is "modifies ∩ reads = ∅". *Known; recalled, check citation.*
- **Optimistic concurrency control** (Kung & Robinson, TODS 1981). A transaction commits iff its read set is disjoint from concurrent write sets. Here the "transaction" is the string predicate and the concurrent writer is the arm. *Known; recalled.*
- **Measurability with respect to a sub-σ-algebra** (probability theory). A random variable that is σ(S)-measurable is unchanged by any modification outside S. `Sealed P S` is that statement for a predicate on memory. *Known (standard).*
- **Noninterference** (Goguen & Meseguer, 1982). The "low view" of memory (the string footprint) is unaffected by "high" writes (the window). *Known; recalled.*

### Pilot

- **EQ on two long strings.** `Core.str_bytes` twice gives both byte lists on the machine memory at the head. `Sealed.along` over `savestate`'s two stores (both `Scratch`, so in `Win`) carries them to `luaV_equalobj`'s entry and then into `luaS_eqlngstr` → `memcmp` (#2's summary). The `luaV_equalobj` frame (below `sp`) is `Scratch` too, so the same `along` covers it.
- **LT on two strings.** The same two facts, fed to `l_strcmp`'s summary (#2).
- **FORPREP, IDIV.** Not affected.
- **Smallest build.** `TStringReprT`, its `Sealed` instance, `Core.unseal`, `Core.str_bytes`, and the `ValRepr` index. Then re-prove `eq_short` unchanged: the index is threaded by `Core.write`.

### Seed

*Lagophthalmos* and *oculopalpebral* (an eye whose lid does not close), and *inward*: the relation sees `w.mo` but cannot close over the machine memory where strings sit. The lid is "the support misses the window".

## 2. First-passage scans (the itinerary)

### The idea

Every string loop in the census is read-only. The loops are `memcmp`'s two, `strlen`'s two, `strcmp`'s two and `l_strcmp`'s chunk loop. Each one walks a cursor `i` over one or two byte streams and stops at the **first index where a byte predicate holds**: a mismatch for `memcmp`, a zero for `strlen`, a mismatch or zero for `strcmp`.

So in the abstraction a read-only loop is a *first-passage time* over a fixed memory, not an invariant-and-measure induction. The memory is not in the loop's state family, because nothing writes. That removes L4-loop′'s `mem : α → Mem` and the pack/unpack of `∃ a0 a1 a2` (§1b.1 item 2). The state is the cursor `i` alone. Pins are an affine function of `i` (`a0 = p + i`, `a1 = q + i`), so the measure is `n − i`, a ghost, never read off a register.

Rotated loops, mid-body exits and word-to-byte relays are three uses of one composition law for first-passage times. They are not three shapes.

### Core rules

```lean
/-- the least j ∈ [i, n) with `stop j`, else n -/
def firstStop (stop : Nat → Bool) (i n : Nat) : Nat

/-- (L4-loop′ for read-only loops, ONE rule) -/
theorem scan_loop {h : BitVec 64} (pins : Nat → List Pin) (m : Mem) (stride : Nat)
    (stop : Nat → Bool) (n : Nat) (X : Nat → Config → Prop)
    (body : ∀ i, i < n → (∀ j, j < i → stop j = false) →
      Triple (SegSt h (pins i) (P m))
        (fun c => ((∀ j, i ≤ j → j < i + stride → stop j = false) ∧ i + stride ≤ n
                     ∧ SegSt h (pins (i + stride)) (P m) c)
                  ∨ X (firstStop stop i n) c)) :
    ∀ i, (∀ j < i, stop j = false) → Triple (SegSt h (pins i) (P m)) (fun c => X (firstStop stop 0 n) c)

/-- the relay (strong Markov): a scan resumed at i after a clean prefix -/
theorem firstStop_relay : (∀ j < i, stop j = false) → firstStop stop i n = firstStop stop 0 n
```

Two bit lemmas, each proved once (no `bv_decide`; byte extraction and `omega` per byte):

- `ld_eq_iff`: `bytesT8 m a = bytesT8 m b ↔ ∀ t < 8, bytesT1 m (a+t) = bytesT1 m (b+t)`. This is `memcmp`'s and `strcmp`'s word compare.
- `haszero_iff`: with `M = 0x7f7f7f7f7f7f7f7f`, `((x &&& M) + M ||| x ||| M) ≠ -1 ↔ ∃ t < 8, (x.extractLsb' (8t) 8) = 0`. This is `strcmp`'s and `strlen`'s mask test (`strcmp` loads `mask` from `0x8005c620`; check that `.rodata` holds `0x7f…7f` there). No carry crosses a byte because `0x7f + 0x7f < 0x100`.

Two semantic lemmas, once:

- `stop_prefix`: a result read off a word that includes bytes past the first stop does not depend on them. `strcmp`'s aligned 8-byte loads read up to 7 bytes past the terminator. The model's `readByte` is total, so the bytes exist; they agree in the "equal" case and are never consulted in the "unequal" case.
- `l_strcmp_lexLt`: for strings with embedded zeros, `lexLt (a ++ 0 :: a') (b ++ 0 :: b')` with `a = b` reduces to `lexLt a' b'`, plus the length cases at lines 390–393 of `lvm.c`. `l_strcmp`'s outer loop is then `scan_loop` with stride "to the next zero", a non-constant stride. The rule takes `stride : Nat → Nat` in general.

### What it makes free

- `memcmp`: word loop (`0x800361dc`, stride 8, stop = mismatch in the word) relays into the byte loop (`0x800361ac`, stride 1). The byte loop is entered by `j 0x800361c0` into its middle. With `h` at the DFS head `0x800361c0` that rotation is just the entry.
- `strlen` and `strcmp` (6 exits for the word loop, 2 for the byte loop): every exit is a disjunct of `X`.
- `l_strcmp`: one outer `scan_loop` whose body is two summary calls.
- The kit's `udiv_norm` mid-exit is *not* read-only, so it stays on #3's general rule.

### What it costs

- `firstStop` + `scan_loop` + `relay`: about 80 lines. `ld_eq_iff` and `haszero_iff`: about 60. `l_strcmp_lexLt`: about 50.
- Each scan supplies `pins`, `stop` and its exit post. That is about 5 lines per loop.
- Harder: the `memcmp` summary's result is a *sign* (`subw a5,a4`). δ only needs `= 0`, but `strcmp`'s sign matters for LT. The exit post must state the sign as the byte difference at `firstStop`, under the C locale's unsigned bytes.

### Theories

- **First-passage / stopping times** (probability; e.g. Durrett, *Probability: Theory and Examples*, the strong Markov property). The relay is "τ after a clean prefix equals τ". *Known; recalled.*
- **SWAR has-zero-byte** (Mycroft's 1987 newsgroup post; Warren, *Hacker's Delight*, §6-1). This is `haszero_iff`. *Known; recalled, check attribution.*
- **Homomorphisms on lists** (Bird, "An introduction to the theory of lists", 1987). `firstStop` over `xs ++ ys` splits as a list homomorphism, which is the word/byte relay. *Known; recalled.*
- **Dead reckoning in navigation.** The position is an affine function of elapsed legs (`pins i`), and only the leg count is tracked. That is why the measure is a ghost. *Novel as an analogy; no citation.*

### Pilot

- **EQ long.** `luaS_eqlngstr` (straight-line: length compare at +16, then `jal memcmp`) as a call node over `memcmp_sum`. `memcmp_sum` is `scan_loop` (word) ; `relay` ; `scan_loop` (byte). Its pre is #1's `BytesAtT` facts.
- **LT strings.** `strcmp_sum` and `strlen_sum` by `scan_loop`; `l_strcmp_sum` by an outer `scan_loop`; `l_strcmp_lexLt` turns its result into `lexLt`.
- **Smallest build.** `scan_loop` + `firstStop_relay` + `ld_eq_iff`, then `memcmp_sum`, with the helper segments regenerated for `memcmp`.

### Seed

*Itineration* (a circuit travelled leg by leg), *sinus* (a channel walked through) and *towery* (a landmark that ends the walk): a scan is a journey that stops at the first landmark.

## 3. Paronymic loop schemata (root + affix)

### The idea

The slot nil fill occurs five times: LOADNIL, RETURN0, RETURN1, `luaD_precall`, `luaD_poscall`. The slot copy occurs twice. These are **paronyms**: one root (fill the 16-byte slots from `X` to `E` with tag 0), different affixes:

- the pointer and end registers (`a5/a4`, `a3/…`);
- the store offset (`-8` or `0`, the "subfix");
- whether the store comes before or after the bump.

Morphology proves the root once and treats the affixes as parameters. Do the same here:

- A **schema** is a closed-form summary over a *segment signature*.
- An **instance** is the generated segment lemma itself. The schema's body hypothesis is stated in exactly the shape the generator already emits (`SegSt` to `SegSt`). So an instance is the schema applied to the segment's name. There is no per-loop invariant, measure or induction.

The general L4-loop′ rule (over a `SegSt` family with a disjunctive exit post) is the root theorem that every schema, and `udiv_*`/`muldi3_loop`, is proved from.

### Core rules

```lean
/-- L4-loop′ (ROUND-4 §2b), once: Triple.loop with I := ∃ a, I a ∧ SegSt h (pins a) (P (mem a)). -/
theorem segLoop … -- as stated in §2b

/-- The nil-fill root, over affixes `(ptr endR : Reg) (off : Int) (order : Pre | Post)`. -/
theorem nilFill (body : ∀ X M, X + 16 ≠ E →
      Triple (SegSt h (pin ptr X :: F) (P M))
             (SegSt h (pin ptr (X+16) :: F) (P (bump order (M.insert (X + off) 0)))))
    (last : ∀ M, Triple (SegSt h (pin ptr (E-16) :: F) (P M)) (SegSt ex (pin ptr E :: F) (P (…))))
    (hk : X + 16 * k = E) :
    Triple (SegSt h (pin ptr X :: F) (P M)) (SegSt ex (pin ptr E :: F) (P (nilMem M X k off)))

theorem slotCopy … -- the same, over (src dst cnt) with `ld/sd` payload and `lbu/sb` tag

/-- and the multi-slot close, once: `nilMem` is an `upd` fold over `Core.write`. -/
theorem Core.writeNils : Core p c s w → … → Core p c' ⟨pc', writeDefs (range a n) nils s.regs, s.out⟩ w
```

- `F` is the frame of pins, polymorphic and untouched by the body (see #5's call rule).
- `bump order` is the only affix with semantic weight: with `Post`, the store is at `X + 16 + off`. Normalise both orders to `nilMem M X k off'` with `off' := off + (order = Post ? 16 : 0)`. Then 2 × 2 affixes collapse to one closed form.

### What it makes free

- `loadnil_loop` (25 lines) becomes one application: `nilFill (seg_8001d2a8 …) (seg_exit …) hk`.
- RETURN0, RETURN1, `luaD_precall`, `luaD_poscall` and `luaT_adjustvarargs` (slot copy) are each one application.
- `muldi3_loop`, `udiv_norm` and `udiv_div` move onto `segLoop` with their arithmetic only. This deletes the `| 0 => absurd | n+1 => …` scaffolding (5–6 lines each, §2b).
- Future loops in the print chain: of the 93, 33 are bottom-tested with one exit. Each recurring idiom (`memcpy`, `memset`) is one more root.

### What it costs

- `segLoop`: about 40 lines. `nilFill` + `slotCopy`: about 120. `Core.writeNils`: about 30. All once.
- Harder: matching the generated segment's statement to the schema's `body` up to `rfl`. The generator's pin order and payload shape must agree. If they do not, a one-time adapter per *generator shape* is needed, not per loop. Check how the segments state `m.insert` chains for `sb` (presumably `writeMap1`/`insert`).
- A schema covers only exact idioms. A loop with one extra instruction falls back to `segLoop`, which is still cheap.

### Theories

- **Root-and-pattern morphology** (McCarthy, "A prosodic theory of nonconcatenative morphology", *Linguistic Inquiry* 1981). One root, templatic affixes. *Known; recalled, check venue.*
- **Loop idiom recognition** (LLVM's `LoopIdiomRecognize`: a loop is replaced by `memset`/`memcpy` when it matches). Here the recognition runs the other way: a matched idiom gets its closed-form proof. *Known (LLVM source); recalled.*
- **The polyhedral model** (Feautrier, "Dataflow analysis of array and scalar references", IJPP 1991/92). An affine loop's effect has a closed form over its iteration domain, and `nilMem M X k` is that closed form. *Known; recalled, check year.*

### Pilot

- **LOADNIL (refactor).** `nilFill` + `Core.writeNils`. Target: `sim_LOADNIL` ≤ 8 lines, from 47.
- **FORPREP, IDIV, EQ, LT.** No store loops, so no effect. `segLoop` is the fallback root of #2 for the case where `scan_loop` does not apply.
- **Smallest build.** `segLoop` (L4-loop′), then `nilFill`, re-proving `loadnil_loop` as one line.

### Seed

*Paronym* (words from one root), *subfix* (the `-8`/`0` store offset), *bromidic* (the same commonplace loop, five times).

## 4. Chart memory: region-addressed reads

### The idea

The census measured the cause of C-budget: loads through `savestate`'s stores. They cost 15–20k heartbeats each, with 341 `omega` calls of 5 ms or more for 27 instructions, the same separation facts re-proved per read and per pin. Disjunctive `Ranges` facts multiply that by about 4.

The address terms are not arbitrary `Nat`s. Every one of them is a **chart coordinate**: a region base plus a literal or slot-affine offset (`w.ci + 32`, `w.L + 16`, `w.base + 16j + 8`, `w.sp + 40`, `w.k + 16i`). So reason about them in chart coordinates:

- read over a write to another *region* is decided by comparing two region tags (`decide`, constant cost);
- read over a write in the *same* region is decided on offsets alone, which are literals (`decide`) or slot-affine (`16a + 8` vs `16b`: one small `omega` with no region facts in context).

The disjunctions (`ci_sep`, `L_sep`, `k_sep`, `L_sep_ci`) are saturated **once, in the library**, into one pairwise-disjointness table. No arm's `omega` ever sees a disjunction.

### Core rules

```lean
inductive Region | slots | frame | cstack | ci | L | k | code | heapObj (i : Nat) …
  deriving DecidableEq

/-- a chart: where each region starts and how long it is, for pointers `w` -/
def chart (p : Proto) (w : RelPtrs) : Region → Nat × Nat

/-- L4-split's cost driver as ONE rule: the atlas, proved ONCE from `Ranges`
(all disjunctions are consumed here and nowhere else). -/
theorem Ranges.atlas (hr : Ranges p w) :
    ∀ r r', r ≠ r' → Disjoint (ival (chart p w r)) (ival (chart p w r'))

/-- reads through stores, by chart -/
theorem rd8_wr8_other (hA : atlas p w) (hne : r ≠ r' := by decide)
    (ho : o + 8 ≤ len r) (ho' : o' + 8 ≤ len r') :
    bytesT8 (writeMap8 m (at r o) v) (at r' o') = bytesT8 m (at r' o')
theorem rd8_wr8_same_far (h : o + 8 ≤ o' ∨ o' + 8 ≤ o := by decide) : …
```

- `at r o := (chart p w r).1 + o`. The generated segments' address terms are rewritten to `at r o` form once per arm entry by a `simp only` set keyed on `RelPtrs.slot`, `ciSavedpcOff` and similar. These terms already have that shape; this is folding, not search.
- The runner's `kit_disch` tries `rd*_wr*_other` and `rd*_wr*_same_far` before `omega`. A side condition is then a `decide` on `Region` or an `Int` literal comparison.
- `Ranges.k_*_wm8` (KIT-1's fix) become instances of `rd8_wr8_other` with `r = k`. The pattern KIT-1 found by hand is the general rule.

### What it makes free

- **The `omega` share of C-budget.** That is 4.7 of 7.8 s of tactic time in MODK's pre half, and per §1b.3 the bulk of each 15–20k guarded load. Predicted: a guarded load through two stores falls toward the cost of a `j` (6k). Then about 25 guarded loads fit the budget, instead of about 10. **FORPREP's integer path (six reads after `savestate`) and IDIV's (two helpers) fit in one declaration**, and MODK's split is unnecessary. This is a prediction for the bake-off to measure.
- The 557k unification fallback: store chains compare by region, so `kit_guard`'s fallback never unifies a chain with the entry memory.
- New disjointness facts (FORPREP's `sp+40` out-parameter, `luaV_equalobj`'s callee frame, strings from #1 as `heapObj` regions) are new `Region` constructors plus one atlas row. They are not new disjunctions in every `omega`.

### What it costs

- `Region`, `chart`, `Ranges.atlas` (the one place with all the disjunctions; about 80 lines of `omega`, run once): about 150 lines.
- `kit_disch` reorder plus the folding `simp` set: about 30 lines.
- Harder: slot-affine offsets with *symbolic* indices (`R[A]` vs `R[B]` with `A ≠ B` unknown) still need arithmetic. Those are same-region, small and disjunction-free.
- Harder: `Scratch`'s C-stack interval `[spEntry − cStackBudget, sp)` is a region of *variable* length. Its length is a fixed literal given `sp_eq`, so it stays literal.
- Risk: whnf/type-checking of large concrete memory terms is the *other* third of the budget, and charts do not touch it. #5 covers that.

### Theories

- **CompCert's block-based memory model** (Leroy & Blazy, "Formal verification of a C-like memory model…", JAR 2008). Pointers are (block, offset), and loads from other blocks are unaffected by construction. *Known; recalled.*
- **Burstall's component-as-array model** (Burstall 1972; Bornat, "Proving pointer programs in Hoare logic", MPC 2000). Distinct fields never alias, so their separation is syntactic. *Known; recalled.*
- **Atlases of manifolds** (differential geometry). Coordinates are local to a chart, and transition maps matter only where charts overlap. Here the charts do not overlap, so there are no transitions. *Known (standard); the analogy is novel.*
- **Saturation in chemistry** (*perhydrogenize*: add hydrogen until no double bond is left). Resolve every disjunction once so that none remains to react downstream. *Novel as an analogy.*

### Pilot

- **FORPREP and IDIV.** Measure the per-load heartbeats with charts on, against §1b.3's table. The prediction to falsify: one declaration per path, under 200k, with no split.
- **MODK (refactor).** Re-prove MODK as one declaration (≈ 198k now). If charts cut 40%+ of the pre half, it fits without `armBody_split`.
- **Smallest build.** `Region` with five constructors (`slots`, `frame`, `cstack`, `ci`, `L`, `k`), `Ranges.atlas`, two read-over-write rules, and the `kit_disch` reorder. Then re-time MODK seg2 and seg4 (38k and 42k now).

### Seed

*Quercetum* (a grove of separate oaks), *stockishness* and *statue* (regions that do not move), *perhydrogenize* (saturate the disjunctions once).

## 5. Reflagged checkpoints: boundary states named by their path

### The idea

L4-split′ and L4-call′ both say the boundary state is a *function of the path* (`lcall_frames.py` already composes it in Python). It is written by hand today only because Lean has no name for it.

Give it a name that does not unfold, as a re-flagged ship sails under a new registry. A **checkpoint** is the composite transfer function of a path's generated segments, applied to the arm's entry: `Ckpt π k`, the state after the first `k` segments of path `π`. It is opaque to whnf, because a `@[irreducible]` def is the boundary. Its pin values and memory are pure terms (`τₖ ∘ … ∘ τ₁`), and the kit's normalisers rewrite them by `simp` without touching the machine.

Calls are **frame-polymorphic**. A summarised helper's rule quantifies over any pin list `F` disjoint from its clobber set, so at a call site `F` is the caller's pins minus the clobbered ones. That is a `List.filter` evaluated by `rfl`, not a statement, which is the mimicry: the callee copies the caller's frame back unchanged without being told what it is (*nonparental*).

### Core rules

```lean
/-- each generated segment's pure transfer: post pins and memory as terms of pre -/
structure SegSig where
  pre  : PinVals → Mem → Prop     -- the side conditions as named hypotheses
  post : PinVals → Mem → PinVals × Mem

/-- the boundary after k segments of a path (generator emits `π : List SegName`, data only) -/
@[irreducible] def Ckpt (π : List SegSig) (k : Nat) (e : PinVals × Mem) : Config → Prop :=
  fun c => SegSt (pcOf π k) (pinsOf (fold π k e).1) (ArmPay (fold π k e).2 _) c

/-- L4-split′ as ONE rule: cutting at any k costs one `Triple.seq` and no statement -/
theorem split_at (hA : Triple E (Ckpt π k e)) (hB : ∀ c, Ckpt π k e c → …) : Triple E Q

/-- the values at a checkpoint, by pure rewriting (no machine whnf) -/
theorem Ckpt.vals : Ckpt π k e c → c.σ.regs.get? r = some ((fold π k e).1 r)

/-- L4-call′ as ONE rule: frame-polymorphic call node -/
theorem call_poly (sum : ∀ F, Disj F clob →
      Triple (SegSt f (args ++ F) P) (SegSt ret (res ++ F) P')) :
    Triple (SegSt jalPc L P) (SegSt ret (res ++ L.filter (· ∉ clob)) P')
```

- Where the cut goes is not chosen by hand. A cut is placed where the running sum of the per-segment cost model (6k + about 16k per guarded load through stores, §1b.3) would pass 150k. The generator emits `π` and the cut indices as *data* (a list of segment names per path); it emits no proof. Hand text per arm: `split_at (k := cut₁)` and nothing about the state.
- Half B's facts come from `Ckpt.vals` plus the kit's read normaliser (`slotVal_wm8`, `Ranges.k_*_wm8`, or #4's chart rules) applied to `(fold π k e).2`. That is a closed term, so `simp` works on syntax, not on a whnf'd configuration.

### What it makes free

- **C-call, all of it.** `modk_call`'s 4-line `divFrame` disappears. `divFrame`'s MOD-shaped doc problem (IDIV reuses `s3`/`s4`) disappears, because the frame is whatever the path made. FORPREP's two calls and IDIV's two helpers are two `call_poly` applications each. EQK's `EqCtx` is untouched (it is a precondition, not a frame).
- **C-budget's structure.** `ArmPre`/`ArmPost`/`AtRet` and FORPREP's undrafted `fp_pre`/`FpInts`/`fpFrame`/`FpMem` are each replaced by `Ckpt π k e`. The arm's shape follows the kernel's paths again. The budget only moves the generator's cut index, at about 5k heartbeats per cut (§1b.3: one setup).

### What it costs

- `SegSig` view of the generated segments: a generator change emitting each segment's `post` as a pure function next to the `SegSt` Triple. It is data the liveness pass already has. Plus `Ckpt`, `split_at`, `Ckpt.vals` and `call_poly`: about 120 lines of Lean, once.
- Harder: a path with a *branch* before the cut. `π` is per path, so a two-polarity guard before a cut gives two `Ckpt`s. That is fine (the kit already has one lemma per path), but `split_at` must allow the guard's polarity in `E`.
- Risk: if the folded memory term `(fold π k e).2` is itself huge (two `writeMap8`s are not), elaborating `Ckpt.vals`'s rewrite costs what whnf did. #4 keeps those terms short.

### Theories

- **Defunctionalised continuations** (Reynolds, "Definitional interpreters for higher-order programming languages", 1972). A boundary state named by the code point plus its captured values is a defunctionalised continuation, and `π`, `k` and `e` are its record. *Known; recalled.*
- **Consistent cuts / distributed snapshots** (Chandy & Lamport, TOCS 1985). A checkpoint is valid by construction when it is a cut of the recorded execution, not a hand-stated state. *Known; recalled.*
- **The frame problem** (McCarthy & Hayes, 1969). The state of what an action does not affect should not need stating. `call_poly`'s `F` is the solution by quantification. *Known.*
- **Ship registries / flags of convenience.** The same hull under a new name, with the obligations of the new registry only. *Novel as an analogy.*

### Pilot

- **FORPREP.** Integer path: `π` from the arm target through `luaV_tointeger`'s call (`call_poly` with `toint_sum`, out-parameter at `sp+40` in the `frame` region per #4) and `__udivdi3` (`call_poly` with `udivdi3_sum`). Cut at the generator's index; the hand text is the kernel's 4 exits (up/down × run/skip) plus `split_at`. Close with `Core.bleachF` (KIT-2's frame-write close).

- **MODK (refactor).** `modk_call` becomes `split_at (k := 5)`; `divFrame` is deleted. Target: `modk_call` 1 line, from 6.
- **Smallest build.** `call_poly`, then `Ckpt`/`split_at` over hand-listed `π` for MODK only. Generator support for `SegSig` comes second, once the MODK refactor shows that the statement cost is 0.

### Seed

*Reflag* (the same state under a new registry), *koggelmannetje* (a mimic: the callee hands back a frame it never inspected), *nonparental* (the callee's rule does not depend on its caller), and *autoschediasm* (the boundary is improvised at the generator's cut, not designed per arm).
