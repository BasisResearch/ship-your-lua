These are the facts I checked in the ELF. The proposals depend on them.

- **F-a. The soft-int helpers use no memory at all.** `__muldi3`
  (`0x8002f6c8`, 9 instructions) is a shift-and-add loop over
  `a0..a3`: no `sp` adjustment, no load, no store. `__hidden___udivdi3`
  (`0x8002f734`, 18 instructions) is a restoring-division loop, also in
  registers only. `__divdi3`, `__moddi3` and `__umoddi3` are straight-line
  sign wrappers around `__udivdi3`. They save their return address in `t0`,
  not on the stack. So the "pure" callee shape is stronger than L-C3′ states
  it: for the soft-int helpers, *memory is unchanged, full stop*.
- **F-b. MUL is ADD with a call leaf.** At `0x8001effc`:
  `ld a1,0(s10); ld a0,0(a4); addi s11,s11,8; jal __muldi3; sd a0,0(s6); sb s2,8(s6); j head`.
  ADD's leaf at `0x8001f018` has the same shape with `add` in place of the
  `jal`, but stores the tag before the payload.
- **F-c. MOD's `Protect` stores come first and are unconditional.** The MOD arm
  at `0x8001dc58` begins `ld a4,8(s7); …; sd s3,32(s7); …; sd a4,16(s0)`
  (`savedpc := pc+1`, `L->top := ci->top`) before any tag test. That is why
  the census measured 230/230. The integer path then tests `n+1 ≤u 1`, that
  is n ∈ {0, −1}:
  - n = −1 gives `li a5,0` and the store;
  - n = 0 goes to `luaG_runerror` at `0x8001fde0`;
  - otherwise `__moddi3` runs, then the floor fix-up `r ≠ 0 ∧ (r xor n) < 0 → r += n`.
- **F-d. The EQ arm.** At `0x8001c690` it does the same `Protect` prefix, then
  `jal luaV_equalobj(L, &R[A], &R[B])`. It then *reloads trap*
  (`lw t6,40(s7)` → `s5`) and compares `a0` with the `k` bit. After that it
  either advances pc by 8 or runs `donextjump` at `0x8001e9cc`.
- **F-e. `ValRepr` does not reflect equality.** `ValRepr.nil` accepts any tag
  with `t % 16 = 0`, and `ValRepr.str` accepts either TValue string tag
  whatever the header says. But `luaV_equalobj` compares `ttypetag` first, so
  `VNIL` (0) against `VEMPTY` (16) returns 0 even though both decode to
  `.nil`. Short strings compare by pointer (`eqshrstr`), which is only
  content equality if strings are interned. **So `sim_EQ` is false for
  `VmRel` as stated.** Either the relation needs a canonicity invariant (stack
  nils are `VNIL`; the TValue string tag agrees with the header; short strings
  are unique per content in the heap), or the kernel must see
  representations. The L-C3 oracle agreed on its 7 activations because real
  runs satisfy the invariant, and the relation does not state it. I call this
  **the anomaly**. Proposals 1 and 3 turn it into a rule.
- **F-f. Error paths are vacuous for `sim_X`.** For MOD with n = 0,
  `BinOp.int .mod` is `none`. So `opArith`'s body is `none`, and there is no
  `Step p s s'`. The `sim_X` premise `Step p s s'` makes every path that
  reaches `luaG_runerror` infeasible. The noreturn shape is needed only for
  the stuck side, never inside a `sim_X`.
- **F-g. The kernel inversions (a5) can be avoided.** `kstep_iff` is already
  proved. Rewriting `Step s s'` to `s' = kstep s` turns every `step_opArith`,
  `step_setR`, `step_forloop` and so on into evaluation of a total function.

## 1. The Camera Square (decode-and-compute simulation)

**Seed:** *cameraman*, *enhance*, *unwavered*, *anomaly*. The camera takes
one picture of the machine at each head, and the picture must be the frame
the kernel predicts (L-C4 is literally a camera check). *Enhance* is the
forensic cliché: you do not reason about the pixels, you run the decoder
again on the final image.

### The idea

State `VmRel` as a **computable picture** plus a **picture-independent
invariant**:

```
decode (p : Proto) (w : RelPtrs) (σ : MState) : Option State   -- the L-C4 decoder, in Lean
Inv p w σ : Prop       -- pins minus pc, RegsOk, frame, complement, ranges: nothing that mentions s
VmRelAt p c s w  :=  pcAt c = head ∧ Inv p w c.σ ∧ Agree (M s.pc) (decode p w c.σ) s
```

Here `M` is the must-initialised mask of `Cert`. Agreement is only needed on
defined registers, and the ⊥ registers are the `Cert.star` machinery,
already proved.

The obligation for an arm is then a **commuting square of two functions**:

```
decode (run_arm σ)  ≈  kstep (decode σ)        (on the pruned paths the Step premise allows)
```

The left side is a symbolic run of the arm, giving a final memory term plus
a path condition π over bytes. The right side is `kstep`, computed. `decode`
is a Lean function over the final memory term, so on each path the goal
closes by normalisation. The kernel case split and the machine branches meet
through `decode`: a machine branch on tag byte `t = 3` is, after one rewrite,
`decode … = some (.int _)`, and `kstep`'s `match Opnd.fill os vs with
| [.int x, .int y]` reduces by the same fact.

### Core rules

- **L-C4 becomes `square` (one theorem).** Suppose, for every path of the
  arm's run from `Inv ∧ head`, `decode(final) ≈ kstep(decode(initial))` and
  `Inv(final)` hold. Then `sim_X` holds. It is proved once, generically over
  the arm, from `kstep_iff` and `Cert.step`.
- **`kstep_iff` replaces the inversions (a5).** It exists already. No
  `step_<combinator>` lemma is written again.
- **Guard reflection (a4) becomes one lemma, `decode_tag`.** The tag byte at
  `slot j` equals constant c exactly when `decode` gives the variant that c
  names. One lemma per tag *constant* (nil/false/true/int/shrstr/lngstr/lcf:
  seven), not per branch shape. The `slt` guards on payloads come from
  `BitVec.slt_iff`, since `decode` of an int is its payload.
- **The noncurantist rule (F-f), `vacuous_path`.** If π implies
  `kstep(decode σ) = none`, the path is discharged without being followed.
  This covers every `luaG_*error` exit inside a `sim_X`.
- **The anomaly (F-e) becomes a stated section law, `decode_canon`.**
  - `Inv` carries the canonicity invariant: nil slots have tag exactly 0, the
    string tag agrees with the header, and short strings are unique per
    content.
  - Under it, `decode` is injective on (tag, payload) except for long strings.
  - That one lemma is what EQ, EQK and every future equality test need.

### What it makes free

- (a5) kernel inversions: all 19 existing declarations and every future one.
  Mean cost 18.5 lines and rising.
- (a4) guard pairs: from one `_t`/`_f` pair per branch shape down to 7 fixed
  lemmas.
- The "close" part of (c) that re-proves `stack` per write pattern. `decode`
  of the final memory *is* the new register file. `Core.write`,
  `Core.jump`, `Core.forloop` and the `slotStore_*` variants become instances
  of "decode commutes with a store outside the other slots", one lemma over
  `bytesT1`.
- The store-order issue (tag first or payload first). `decode` reads the
  final memory, so the order does not matter.

### What it costs

- **Setup.**
  - `decode` in Lean (about 60 lines; the Python in `lc4_trace.py` is the
    spec).
  - `decode_tag`, `decode_store_other`, `decode_canon` (about 80 lines).
  - Moving `Core.stack` to the agreement form (about 60 lines, plus touching
    the 25 proved arms mechanically through one adapter lemma
    `Core.stack ↔ Agree … (decode …)`).
- **What gets harder.**
  - `decode` of a string must follow the TString pointer, so it is partial.
    `decode_store_other` then needs "the store is not into the heap object",
    which `Ranges` gives for the slot window.
  - The canonicity invariant must be established at entry (`vmRel_entry`)
    and preserved by CALL. CALL interns strings, and uniqueness is a heap
    invariant: honest new work, but work EQ needs under any abstraction.
- **SymExec's three failures, fixed.**
  1. *Hand lines.* SymExec's per-arm cost was the guard and close reasoning
     at the end of each path. Here that reasoning is `decode` normalisation
     plus seven fixed lemmas.
  2. *Call nodes.* The run stops at `jal` and applies the effect-class rule
     of proposal 3, then continues.
  3. *The weaker theorem.* `Core.frame` is now total-read and `RegsOk` is in
     `Core` (round 2's two changes are merged), so `VmRelZ` = `VmRel`. The
     square's conclusion is `VmRel`, with no extra premise.

### Theories

- **Known.** Abstraction functions and refinement mappings:
  - Hoare, "Proof of correctness of data representations", Acta Informatica
    1972;
  - Abadi & Lamport, "The existence of refinement mappings", TCS 1991.

  `decode` is the abstraction function, and the square is the standard
  commuting diagram, here with a *computable* abstraction function.
- **Known, distant field (machine learning).** Equivariance:
  f(g·x) = g·f(x) (Cohen & Welling, "Group Equivariant Convolutional
  Networks", ICML 2016). The arm and `kstep` are the two actions, and
  `decode` is the intertwiner. Cohen & Welling check equivariance by
  *computing* both sides on a basis, not by case analysis. (Recalled from
  memory: check the venue and year.)
- **Known, distant field (vision).** Analysis-by-synthesis or inverse
  graphics: a hypothesis is accepted when re-rendering matches the image. The
  decoder is the inverse renderer; L-C4 is its acceptance test. (Recalled:
  Yuille & Kersten, TiCS 2006.)
- **Novel.** Using the must-initialised mask of `Cert` as the *agreement
  mask* of a decode-based relation. This makes the kill-port ⊥ and the
  machine's stale slots the same thing, so CALL's clobbered frame costs
  nothing in the relation.

### Pilot

- **Build.**
  - `decode`, `decode_tag`, `decode_store_other`, `square`, `vacuous_path`.
  - `decode_canon`, with only the nil and int cases for the pilot. For
    strings, state it and leave it as the one open lemma.
- **`sim_ADD` refactor.** Replace the template's `step_opArith`, guard pairs
  and `Core.write` with `square` plus `simp [kstep, decide?, opArith, δ, decode_tag]`.
  - Target: under 25 hand lines. Today it is 61 template lines.
- **MUL.** The ADD proof with the leaf `add` replaced by the call rule of
  proposal 3 for `__muldi3`. Expect a table row plus nothing (F-b).
- **MOD.**
  - The `Protect` stores go to dead cells (proposal 2).
  - The n = 0 path goes through `vacuous_path` (F-f).
  - The n = −1 path is `imod x (−1) = 0`, one BitVec fact.
  - The main path is `__moddi3` (proposal 3) plus the floor fix-up lemma
    `fmod_of_tmod`. This is *per BinOp*, shared with MODK and with IDIV's
    `fdiv_of_tdiv`.
- **EQ.** `luaV_equalobj` through proposal 3's "read-only" class, with its
  value given by the camera square applied to the helper itself (below).
  - `decode_canon` closes `a0 = decide (v1 = v2)`.
  - The trap reload (F-d) reads `ci+40`, which the complement fixes.
- **Measure.** Hand lines for MUL/MOD/EQ, and the `sim_ADD` delta.

## 2. Subfusc cells: dead-at-head memory, with one close rule over final memory

**Seed:** *contaminant*, *bleachery*, *autocytolytic*, *subfusc*. Some cells
are contaminated on every arm and nobody cares. `luaV_execute` digests its
own frame (*autocytolytic*). The cells are dim (*subfusc*): the relation
does not look at them. The bleachery is the one rule that washes an arm's
stores back into a clean relation.

### The idea

The census treats `ci->savedpc`/`L->top` (written by `Protect`) as a
**resource to add** to `VmRel` (d1, 100–250 lines each). Invert that. They
are **dead at the head**: in every arm, each read of them is preceded by a
write in the same arm.
- `Protect` writes them before any call.
- `luaD_precall` reads `L->top` only after CALL has set it.

A dead cell does not belong in the relation at all. So *shrink* what the
relation constrains:

```
Dead p w  :=  {ci+savedpcOff .. +8} ∪ {L+topOff .. +8} ∪ [sp − Kc, sp)     -- callee frames below sp
Win' p w  :=  Win p w ∪ Dead p w
Core.frame : ∀ a, ¬ Win' p w a → bytesT1 c.σ.mem a = bytesT1 w.mo a
```

`Complement` must then not mention `Dead`. `LuaStateAt` has to be stated with
`L->top` and `ci->savedpc` as "any value" (a points-to `↦ –`). That is a
one-time weakening, and it is sound because the facts are dead.

**The close rule** takes the *final* memory, not the store list:

```
bleach : Core p c s w →
         (∀ a, ¬ Win' p w a → ¬ Slots_of (e.defs) a → c'.σ.mem a = c.σ.mem a) →   -- one frame premise
         (∀ j ∈ e.defs, ValRepr w.mo (slotTag c'.σ.mem (w.slot j)) (slotVal …) (vals j)) →
         pins, RegsOk, out … →
         Core p c' (s.apply e o) w
```

The frame premise is discharged by one generic fact about the symbolic run:
"every store address was in the window, a dead cell, or a def slot". That is
L-C6′ as a rule. The store *shapes* (tag+payload in either order, tag-only,
payload-only) never appear, because the premise reads the final bytes.

### Core rules

- **L-C6′ becomes the rule `bleach` (above).** It is one theorem and replaces
  `Core.write`, `Core.jump`, `Core.forloop`, every `slotStore_*` and every
  `*_of` transport.
- **Liveness at the head (the law behind `Dead`)** is a **check, not a
  proof**. A proof never needs "dead" as a theorem: if an arm read a dead
  cell before writing it, the symbolic run would find the read unconstrained
  and the proof would be stuck. So the law is enforced by the proofs going
  through; a trace or objdump check (tools may check laws) confirms it
  in advance for the choice of `Dead`.
- **`Dead` is stable under Complement.** One lemma: `Complement p w` depends
  on `w.mo` only outside `Dead`. It is proved once, by rewriting each field
  through `bytesT1_congr`.

### What it makes free

- (c) all 28 declarations and 245 lines of close and store-shape
  maintenance, and every future close shape (9–39 lines each, 19 trees to
  go).
- (d1) at least one of the four forecast widenings (`savedpc`/`L->top`, 100–250
  lines). MOD, MODK, IDIV, IDIVK, EQ, EQK, LT, LE, FORPREP and MMBIN* store
  there on every execution.
- The callee-frame part of L-C6′: helper frames below `sp` are dead by
  definition, so pure helpers that *do* use the stack (`luaV_equalobj`,
  `l_strcmp`) need no frame lemma.

### What it costs

- **Setup.**
  - Restate `LuaStateAt` with two "any value" fields (unknown size: it is in
    a file I may not read in full; my guess is about 30 lines).
  - `bleach` (about 50 lines).
  - `Complement.dead_congr` (about 40).
  - The re-proof of the 25 arms through `bleach` (mechanical, and it shrinks
    them).
- **What gets harder.**
  - The runtime-callee rule (proposal 4) must *re-establish* anything about
    `L->top` that the callee relies on. That comes for free: the arm wrote it
    just before, and the symbolic state knows the value.
  - `vmRel_final` (RETURN reads `L->top` when B = 0) must set it first.
    RETURN in F1 has fixed B, but this needs checking.
  - `Dead` must be sized: `Kc` is the deepest callee frame below `sp` on a
    normal path.

### Theories

- **Known.**
  - Liveness analysis and dead-store reasoning (Appel, *Modern Compiler
    Implementation*, ch. 10).
  - Separation logic's `x ↦ –` (Reynolds, LICS 2002).
- **Known, distant field (logic synthesis).** Observability don't-care sets.
  An output that no observer reads may take any value, and the minimiser
  exploits it (Damiani & De Micheli, "Observability don't care sets and
  Boolean relations", ICCAD 1990). Here the observer is the next head's
  decoder: `savedpc` is in the ODC set. (Recalled: check the venue.)
- **Known, distant field (cell biology).** Autolysis confined to a
  compartment. The lysosome digests inside a membrane and the cell outside
  is unchanged. The rule `bleach` is exactly "digest inside `Win′`, leave the
  outside intact".
- **Novel.** Obtaining dead-at-head as a *by-product of the proofs going
  through* rather than a stated invariant, with the trace check only choosing
  `Dead`.

### Pilot

- **Build.** `Dead`, `Win′`, `bleach`, `Complement.dead_congr`, the
  `LuaStateAt` weakening.
- **`sim_ADD` refactor.** Swap `Core.write` for `bleach`. It should delete the
  `slotStore` shape used.
- **MUL.** Uses `bleach` with no dead cell touched (F-a: `__muldi3` touches no
  memory).
- **MOD.** The `Protect` pair lands in `Dead`, the frame premise closes, and
  no relation field is added. This is the pilot that decides the proposal:
  **MOD must not add a `VmRel` field.**
- **EQ.** Same `Protect` pair, plus `luaV_equalobj`'s frame below `sp` is in
  `Dead`. The trap reload is from `ci+40`, which is *not* dead, and
  `Complement.trap_word` still holds because the callee is read-only
  (proposal 3).

## 3. Effect-class waivers for callees (the biopharmaceutic classification)

**Seed:** *pharmaceutic*, *procurement*, *phylacteried*, *Savitar* (the
impeller: the call). A drug comes phylacteried, with its classification
strapped to it. In pharmacology, some classes are **waived** from in-vivo
bioequivalence studies because class membership alone implies the result.

### The idea

Do not write a contract per helper. Give every direct callee an **effect
class**, *computed from the text image by one verified scanner*, and prove
one call rule per class. The scanner walks the helper's static call closure
(for leaves that is just its own code) and classifies it by the instructions
it contains:

| class | syntactic criterion (checked on `.text`) | proved call rule gives |
|---|---|---|
| **R (register-only)** | no load, store, `ecall` or `csr` in the closure, and no `sp` write; returns by `jr ra` or `jr t0` | memory, `sp`, `gp` and `s0–s11` unchanged; only `a0–a7`, `t0–t6`, `ra` change |
| **RO (read-only)** | stores only at `sp`-relative addresses below entry `sp`; `sp` restored; `s*` saved and restored | memory ≥ entry `sp` unchanged (so `Dead` of proposal 2 absorbs the rest) |
| **N (noreturn)** | every exit reaches `luaG_runerror`, `luaD_throw` or `abort` | the path is either vacuous (F-f), or ends in `Halts _ _ (≠0)` via one exit lemma |
| **U (runtime)** | anything else | proposal 4 |

These are the only frame facts. The **value** a class-R or class-RO callee
returns is the second half. It is *not* a hand contract either, because it
comes from one of two generic sources.

1. **Loop schemas for the bit-serial helpers.** `__muldi3` is the shift-and-add
   schema: `while b ≠ 0: if b&1 then acc += a; a <<= 1; b >>= 1`.
   `__udivdi3` is the restoring-division schema. Each schema has *one* proved
   rule, with its invariant, over any register assignment:
   - shift-and-add: `acc + a·b = x·y mod 2⁶⁴`;
   - restoring division: `q·d + r = n ∧ r < d·2ᵏ`.
   The helpers are then *rows* (entry pc, register map). `__divdi3`,
   `__moddi3` and `__umoddi3` are straight-line wrappers; the call rule
   composes them (a call inside a class-R callee is allowed if the callee is
   class R).
2. **The camera square, applied to the helper** (proposal 1) for the
   tree-shaped C helpers (`luaV_equalobj`, `l_strcmp`, `luaH_getshortstr`).
   Their "kernel" is a Lean function on decoded arguments: `decide (v1 = v2)`,
   `lexLt`, lookup. The helper's arm is proved exactly like a bytecode arm,
   with a *different head* (entry, `ret`) and the pointer arguments decoded
   through the same `decode`. The δ cases (`.eq`, `.lt`, `.le`) are already the
   specification. Nothing new is written per helper except a
   `(entry, δ-case, arg decode)` row.

### Core rules

- **L-C3′ pure becomes `call_R` and `call_RO`.** These are two theorems over
  the scanner's verdict: `scan img f = .R → Frame_R` and
  `scan img f = .RO → Frame_RO`. The scanner is proved once, by induction
  over the instructions of the closure and the Sail semantics of each
  instruction *class* (store/non-store). This is one fact per opcode class,
  not per instruction, and it is not a step lemma per pc.
- **L-C3′ noreturn becomes `call_N` + `vacuous_path`.** Inside `sim_X`, F-f
  makes these free. Only `vmRel_stuck` uses the halting half.
- **L-C2′ for helpers.** MUL and MULK share `__muldi3`. MOD, MODK, IDIV and
  IDIVK share `__udivdi3` through the wrappers. EQ and EQK share
  `luaV_equalobj`; LT and LE share `l_strcmp`.

### What it makes free

- (b) all 10 of the 11 normal-path arm helpers that L-C3 found pure, except
  `luaV_tointeger`'s out-pointer. The out-pointer writes at `sp+40`, inside
  `luaV_execute`'s own frame: that is the window, so it is class RO relative
  to *caller* `sp + 176`. The scanner parameter is "stores below the caller's
  frame top".
- The "sites only, no spec" batteries (`__divdi3`, `__moddi3`, `__umoddi3`)
  and the WHILE-address specs (`Muldi3Spec`, `udivdi3_spec`) get replaced.
- 18 of the 26 open arms need a helper. Of those, the ones whose helper is in
  R or RO (MUL, MULK, MOD, MODK, IDIV, IDIVK, EQ, EQK, LT, LE, GETTABUP's
  `luaH_getshortstr`, FORPREP's conversions) become trees with a call node
  and no hand contract.

### What it costs

- **Setup.**
  - The scanner (about 80 lines of Lean) and its soundness (about 150).
  - Two schema rules (about 60 lines each; the invariants are textbook).
  - The class-RO frame rule needs callee-saved register discipline. That is a
    scanner check too: every `s*` written is saved at entry and restored before
    `ret`. It is syntactic for GCC's prologue/epilogue, but it must be *proved*
    sound, not assumed.
- **What gets harder.**
  - A class-RO helper with internal loops (`l_strcmp` → `strcoll`/`strlen`)
    needs loop invariants inside the camera square. These are new per loop,
    though in F1 only `strlen`/`strcmp`/`memcmp` loops appear, and they are
    three more schemas.
  - The scanner is sound only for *direct* calls; `jalr` inside a closure
    (21 unresolved sites) forces class U.

### Theories

- **Known.**
  - Effect systems (Lucassen & Gifford, "Polymorphic effect systems", POPL
    1988).
  - Program schemas (Paterson & Hewitt, "Comparative schematology", 1970;
    recalled).
  - Bit-serial arithmetic invariants (Hennessy & Patterson, appendix on
    computer arithmetic).
- **Known, distant field (pharmacology).** The Biopharmaceutics
  Classification System (Amidon, Lennernäs, Shah & Crison, Pharm. Res. 1995).
  Drugs in a class are waived from in-vivo bioequivalence studies on the
  strength of class membership alone ("biowaiver"). Here: a helper in class R
  is waived from any frame proof. (Recalled from memory: check the citation.)
- **Novel.** Discharging a helper's *value* by running the same camera square
  as the arms, with the δ case as its kernel. Helpers and arms then share one
  proof method and one specification table.

### Pilot

- **Build.** The scanner restricted to class R (no loads or stores: the
  smallest useful fragment, roughly 40 + 80 lines), the shift-and-add schema,
  and the restoring-division schema.
- **MUL.** A call node on the ADD tree (F-b), plus `call_R __muldi3` and the
  shift-and-add row. Target: under 15 hand lines beyond the setup.
- **MOD.** `call_R __moddi3` (the wrapper, then `__udivdi3` via the schema),
  plus `fmod_of_tmod`.
- **EQ.** Needs class RO (a second stage of the scanner) and
  `luaV_equalobj`'s camera square. If that is too large for the pilot, run EQ
  with RO only and state the value premise explicitly, to measure the frame
  half alone.
- **`sim_ADD` refactor.** No callee, so no change: the control.

## 4. Plate-fixed frames: runtime callees as a rely with a moving origin

**Seed:** *intercontinental*, *untie*, *barrelful*, *blobbed*,
*affluentness*. The Lua stack is a continent that may drift: `func` moves, the
stack reallocates. The heap grows (*affluentness*). Geodesists state positions
relative to the plate they sit on, not to the planet.

### The idea

The four forecast widenings (`savedpc`/`L->top`, `func` moving, heap/strings/`G`
changing, console growth) are the same thing: a **rely** that the callee may
perform. Stop adding a field per resource. Instead:

1. **Partition memory once into owned regions** (the *barrels*): `Win`
   (slots plus own frame), `Dead` (proposal 2), `Img` (text, rodata,
   constants, proto), `CI` (the ci and L fields that the arms read), and
   `Heap` (everything the allocator owns, as `∃ heap state`). `Complement`
   becomes a separating conjunction of one predicate per region.
2. **State the runtime shape as one rely R_rt** over this partition:
   - `Img` unchanged;
   - `CI` fields that the arms read (`ci->func`, `ci->u.l.trap`, `k`, `code`)
     changed only by the moves in the relocation map;
   - `Heap` predicate stable;
   - `Win` slots below `A` preserved *up to relocation τ*;
   - slots at or above `A` killed;
   - console extended by some string.
3. **Relocation is a change of origin.** `VmRel` already quantifies `∃ w`.
   The rule produces a new `w'` with `w'.func = new func` and the slot map
   `τ j = w'.slot j`. It proves `decode(w', σ') = decode(w, σ)` on `R[<A]`.
   Nothing about the *old* location is kept (*untie*).

Then **one theorem, `rt_stable`**: every field of `Complement` is stable
under R_rt. When the relation gains a resource later, the cost is one
stability case, not a new field threaded through every close lemma.

### Core rules

- **L-C3′ runtime becomes `call_U`.** If a callee satisfies R_rt (its
  guarantee), the call node continues with `∃ w'` related to `w` by τ. The
  callee's *guarantee* is what CALL/VARARGPREP/stack growth must prove. It is
  not per helper, but per *entry into the runtime*: `luaD_precall`,
  `luaT_adjustvarargs`, `luaD_poscall`. There are three.
- **L-C4's relocation clause becomes `decode_reloc`.** `decode` is relative to
  `w.func`, so moving all slots by the same offset commutes with `decode`.
  This is one lemma. The trace saw it at pc 145 of f1_src.
- **Console growth** is `out' = out ++ x` in R_rt, and the kernel's print
  edge supplies `x`.

### What it makes free

- (d1) all four forecast widenings. The only new region facts are the
  stability cases, which are about 10–20 lines each rather than 100–250.
- VARARGPREP's 9 out-of-port slot stores: under R_rt they are allowed, and
  `decode_reloc` restates the frame at the new `func`.
- The reallocating CALL's `free` bookkeeping in the old block: the old block
  belongs to `Heap` after the move and is no longer `Win`. This is exactly
  the "measure the ports against the post-step frame" refinement of L-C6′.

### What it costs

- **Setup.** The partition rewrite of `Complement` (large: about 200 lines),
  R_rt, `rt_stable`, `decode_reloc`.
- **What gets harder.**
  - The three runtime entries must be shown to *guarantee* R_rt. For
    `luaD_precall` → `print` (81 functions), that is the real cost of CALL
    under any abstraction. This proposal only makes sure it is paid once,
    against one rely, and never leaks into `VmRel`.
  - Separation-style region predicates in a total-read, `Std.ExtHashMap`
    memory model need a small region algebra (disjointness by `Ranges`).

### Theories

- **Known.**
  - Rely-guarantee (Jones, "Tentative steps toward a development method for
    interfering programs", TOPLAS 1983).
  - Stability of assertions under a rely (as in RGSep: Vafeiadis & Parkinson,
    CONCUR 2007).
  - Moving collectors and forwarding (Cheney, CACM 1970): references
    re-expressed after a move.
- **Known, distant field (geodesy).** Plate-fixed reference frames. Station
  positions are given relative to a tectonic plate, and an explicit
  plate-motion transformation relates epochs (the ITRF, e.g. Altamimi et al.,
  "ITRF2014", JGR Solid Earth 2016; recalled: check it). `w.func` is the
  plate origin and τ is the plate motion.
- **Known, distant field (physics).** Gauge invariance. `∃ w` is a gauge
  choice, and `decode` is gauge-invariant under the relocation group.
- **Novel.** Deriving the complement's region list *from* the kill-port and
  heap-ownership footprint of L-C3′, so the relation's shape is determined by
  the laws, not by the history of which arm first needed which field.

### Pilot

- MUL, MOD and EQ do not call runtime helpers (their helpers are R or RO), so
  this proposal's pilot is **negative on them by design**. Adopting it must
  not raise their cost: measure that they are unchanged.
- The smallest thing to build is the `decode_reloc` lemma plus `rt_stable` for
  just the `Img` and `CI` regions. Then refactor `sim_ADD` to use the region
  form of `Complement` and check that ADD's hand lines do not rise.
- The real held-out test is VARARGPREP (outside this pilot). It is the
  smallest runtime arm: one callee, `luaT_adjustvarargs`, 64 instructions,
  class U.

## 5. Thin-section idioms: the kernel's own constructors, recognised in the machine text

**Seed:** *petrological*, *Asterales*, *Sagittaria*, *choreatic*,
*parallelotropic*. A petrologist identifies a rock by naming the minerals in a
thin section. Point counting classifies every grain as one of about ten
minerals. An Asterales head is many florets on one receptacle, like 82 arms on
one dispatch head. *Sagittaria* has arrow leaves: the jump-table arrows.
*Choreatic*: scheduling is a dance that must not matter. *Parallelotropic*:
the machine tree grows parallel to the kernel term.

### The idea

L-C2′ says the proof key is **lvm.c macro × operand access × helper leaves**.
Those three axes are *already constructors in `Semantics.lean`*:

- the operand access is `Opnd.reg` or `Opnd.imm` (and `imm` splits into the
  K-constant, `sB`/`sC`, and `sBx` idioms);
- the macro is the combinator (`opArith`, `docondjump`, `setR`, `forloopK`,
  …);
- the leaf is `BinOp` or a `Prim`.

So make each **mineral** (idiom) a proved Hoare-style rule over machine
*runs* whose postcondition is phrased in the kernel's vocabulary. A
**verified recogniser** then parses an arm's instruction DAG (modulo
scheduling: the round-2 canonicaliser's DAG form) into a term of minerals.
Its soundness is one theorem: the composed postcondition is the kernel's
`decide?`. About 15 minerals, all visible in the arms I read:

| mineral | machine idiom (from the ELF) | kernel postcondition |
|---|---|---|
| `vRA`/`vRB`/`vRC` | `srliw rX,s4,{7,16,24}; zext.b; slli 4; add rY,s9,rX` | `rY = slot(ins.a/b/c)` |
| `vK` | `ld a4,0(sp)` + `k + 16·i` | `rY = kslot(i)`, with ValRepr of `kval` |
| `vsC`/`vsB` | `srliw …; addiw −127` (bias) | `rY = BitVec.ofInt sC` |
| `tagTest c` | `lbu t,8(rY); beq/bne t, c` | case of the operand's `Value` |
| `intLeaf op` | `ld`, `ld`, ALU op | `BinOp.int op` |
| `callLeaf f` | `mv a0,…; jal f` | δ-case via proposal 3 |
| `slotWrite` | any order of `sb`/`sd` on `slot(a)` | ValRepr of def-port value |
| `protect` | `sd s3,32(s7); sd ci->top,16(s0)` | nothing (dead, proposal 2) |
| `nextPc k` | `addi s11,s11,4k` | edge target `pc+k` |
| `donextjump` | the `0x8001e9cc` block | edge target `nextJump p pc` |
| `trapReload` | `lw t6,40(s7); sext.w s5,t6` | `s5 = 0` by `Complement.trap_word` |
| `toHead` | `j 0x8001bfe4` / `beqz s5,…` | the head |

A new tree is then a **new sentence over known minerals**. Its proof is the
recogniser's output, checked by `decide`, and costs zero hand lines unless it
contains a new mineral. Of the 19 remaining trees, most need none.
- The shifts need one new `intLeaf` (the amount branches as a `tagTest`-like
  `sltiu` mineral).
- LOADNIL needs a loop mineral.

### Core rules

- **L-C2′ becomes `recognise_sound`.** If the recogniser maps an arm to a
  mineral term t, and `kernelOf t = opKernel … op`, then `sim_op` holds.
  This is one theorem. The equality `kernelOf t = opKernel …` is by `rfl`
  when the grammar mirrors the combinators.
- **L-C4 per mineral.** Each mineral rule is L-C4 restricted to the mineral's
  footprint. There are about 15, each proved once (5–30 lines).
- **Guards (a4)** are the single `tagTest c` mineral, parametric in c.
- **Store order** is absorbed by `slotWrite`'s "any order" (it quantifies
  over the final bytes, as proposal 2 does).

### What it makes free

- (a1) new trees: 846 lines so far, 1,070 forecast, 48% of recent cost in
  kind templates.
- (a2) and (a3) layouts and rows. The recogniser is polarity- and
  layout-invariant, like the round-2 canonicaliser, but *verified*.
- Operand-access templates (10% of recent cost): `vRB`/`vK`/`vsC` are proved
  once.

### What it costs

- **Setup.** The recogniser and its soundness. This is the risky part: the
  round-1 idiom-grammar decompiler (R1-4 #4) was not built. Maybe 300–500
  lines, and it must work modulo scheduling, which means proving the DAG
  canonicalisation sound (commuting independent instructions preserves the
  final state: one lemma over register and memory disjointness).
- **What gets harder.**
  - Idioms that GCC fused across minerals. For example, MOD's `Protect` store
    is interleaved with operand decoding at `0x8001dc58`. The recogniser must
    reorder before matching; that is the DAG canonicalisation's job.
  - A wrong mineral boundary makes the recogniser fail loudly, not
    unsoundly.
- **How this differs from forbidden per-kind templates:** there is no text
  per kind or per arm. The only per-arm artefact is the recogniser's *output*,
  computed in Lean, not generated by a script.

### Theories

- **Known.**
  - Idiom recognition (Pinter & Pinter, "Program optimization and
    parallelization using idioms", POPL 1991; recalled).
  - Decompilation into logic (Myreen, FMCAD 2008).
  - Tree-pattern instruction selection run backwards (Aho, Ganapathi & Tjiang,
    "Code generation using tree matching and dynamic programming", TOPLAS
    1989): the minerals are the tiles.
- **Known, distant field (petrology).** Modal analysis by point counting
  (Chayes, *Petrographic Modal Analysis*, 1956; recalled). A rock is
  identified by a small, fixed mineral vocabulary. Its classification (QAPF,
  Streckeisen 1976) is a function of mineral proportions only, as L-C2′'s key
  is a function of idioms only.
- **Novel.**
  - Using the *semantic combinators of `Kernel.lean`* as the tiling grammar,
    so that the recogniser's output equals `opKernel` by `rfl`.
  - A mineral for `protect` whose postcondition is *nothing*: dead cells from
    proposal 2 make it trivial.

### Pilot

- **Build.** Only the minerals the pilot needs: `vRA`, `vRB`, `vRC`,
  `tagTest`, `intLeaf`, `callLeaf`, `slotWrite`, `protect`, `nextPc`,
  `donextjump`, `trapReload`, `toHead`. Add a recogniser for *straight-line
  plus tag branches*, without scheduling canonicalisation (hand-order the
  minerals for the pilot and record how often that was needed).
- **`sim_ADD` refactor.** Recognise and apply `recognise_sound`. Target: 0 hand
  lines beyond the minerals.
- **MUL.** The same sentence with `callLeaf __muldi3`. Target: 0 beyond
  proposal 3's `call_R`.
- **MOD.** Needs `protect`, an `nOneZero` mineral (`add a3,n,1; bgeu 1,a3`)
  and `callLeaf __moddi3`, plus the `fmod_of_tmod` fix-up mineral. This counts
  as one new mineral, shared with IDIV.
- **EQ.** `protect`, `callLeaf luaV_equalobj`, `trapReload`, `donextjump`.
  - All four are shared with LT/LE/EQK.
  - The value half needs `decode_canon` (F-e).

## How the five compose (and what I would bake off first)

- **1 (camera square) and 2 (subfusc cells)** are independent of each other
  and of helpers. Together they remove (a4), (a5) and (c), the rising
  clusters apart from callees. That is the cheapest pilot, and it produces
  the refactored `sim_ADD`.
- **3 (effect-class waivers)** is the callee half for 10 of the 11
  normal-path helpers. MUL is the minimal test: one class-R leaf.
- **4 (plate-fixed frames)** is the answer to (d1) and CALL. It is not
  exercised by MUL/MOD/EQ, so its pilot is "no regression" plus VARARGPREP
  later.
- **5 (thin-section idioms)** is the most ambitious. It pays off only if the
  recogniser's soundness stays under about 500 lines.

**Findings that need action whichever proposal wins:**

- **F-e:** `ValRepr`/`TValueRepr` must be made equality-reflecting before any
  `sim_EQ`/`sim_EQK` can be proved, by stating that nil tags are 0, that the
  TValue string tag agrees with the header, and that short strings are
  interned. As stated, `sim_EQ` is not provable: with a `VEMPTY`-tagged slot,
  the machine returns "not equal" where the kernel says equal.
- **F-c:** MOD's `Protect` stores are at the arm head, before any tag test.
  So *every* path of MOD, MODK, IDIV, IDIVK and EQ writes `ci`/`L`. Any
  per-path treatment pays for them on every path.
- **F-f:** error exits inside `sim_X` are vacuous by the `Step` premise, so
  no noreturn contract is needed for the held-out arms.
