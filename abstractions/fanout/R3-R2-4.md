I read all five round-1 answers in full, the brief, `Rel.lean` (`ValRepr`,

These are new facts, checked in the files. The ideas below rest on them.

- **N1. `Core.frame` compares memory outside the window with `w.mo`, at
  *every* address.** Its type is `∀ a, ¬ Win p w a → bytesT1 c.σ.mem a =
  bytesT1 w.mo a`, and `Win` is the slots plus `[sp, sp+176)`. So it is
  broken by three kinds of store, not one: `Protect`'s two stores, *and*
  any helper frame below `sp`. `luaV_equalobj` opens with `addi sp,sp,-48;
  sd ra,40(sp)` (`0x8001b780`), which is a store at `sp−8` that `Core.frame`
  forbids today. MUL's `__muldi3` and MOD's `__moddi3` touch no memory
  (`__moddi3` saves `ra` in `t0`), so only EQ trips this.
- **N2. `Ranges.ci_out` says no byte of the `CallInfo` is in `Win`.** Any
  merge that *enlarges* `Win` to include `ci->savedpc` makes `ci_out`
  false as stated. So the enlargement has to be a separate exemption, not a
  bigger `Win` (idea 1).
- **N3. CONCAT is in F1** (`Semantics.lean:472`, `concatK`). So a short
  string in a register is not always a K constant. Interning cannot be
  replaced by a "K-provenance" fact; it has to cover strings made at run
  time (idea 2).
- **N4. `luaV_equalobj` is not position-independent, and it has an internal
  indirect jump.** For `ttypetag ≤ 22` it runs `auipc a4; addi a4,-1220`
  (the table at `0x80053310` in `.rodata`), then `lw; add; jr a5`
  (`0x8001b7d4`–`0x8001b7f0`). Two round-1 ideas assumed otherwise:
  - R3-R1-5 #3's scanner rule "`jalr` in the closure forces class U" would
    misfile it as a runtime callee;
  - relocation (R3-R1-1 #3, R3-R1-2 #4) does not apply to it, because it
    reads absolute `.rodata`.

  It needs no relocation anyway: it exists only in the Lua ELF.
- **N5. `__moddi3`'s result is `__udivdi3`'s *second* output.** The code is
  `mv t0,ra; …; jal __hidden___udivdi3; mv a0,a1; jr t0`
  (`0x8002f7b0`–`0x8002f7c4`). So `__moddi3` returns `a1`, the remainder
  that `__udivdi3` leaves behind. The negative path is `neg a0,a1`, so the
  sign follows the dividend, i.e. C's truncated `%`. A `udivdi3_spec` that
  states only `a0 = quotient` does not transport to MOD, however it is
  relocated. I did not read the spec (not on the allowed list); **check
  it.**
- **N6. `luaV_execute` writes nil only as `sb zero,8(…)`** (`0x8001c318`,
  `0x8001ed90`). No `li` of 16, 32, … feeds a slot tag. So "nil slots have
  tag 0" is consistent with the arms. The other producers to check are
  `moveresults` under CALL and the entry stack image.
- **N7. `luaV_equalobj` on F1 values computes representation equality.**
  - Different `ttypetag` (`xor`, `andi 63`, `beqz`) returns 0, unless both
    are numbers.
  - The table then gives:
    - 1 for nil, false and true (tag only);
    - `ld; ld; sub; seqz` for the lcf and default cases (payload);
    - pointer compare for short strings;
    - `luaS_eqlngstr` for long strings.
  - ints take the `beq a4,3` branch to a payload compare.

  So `a0 = 1` iff the two TValues are equal modulo payload irrelevance,
  *except* for long strings.
- **N8. `cstack_room : symHeapEnd + cStackBudget ≤ RuntimeData.spEntry`** is
  proved by `decide` (`Runtime.lean:340`). This is the one fact needed to
  put helper frames below `sp` out of reach of the slots (idea 1).
- **N9. ADD and MUL share one tree, but not one layout.** Side by side, the
  arm prefixes (`0x8001d9c8`, `0x8001dcc8`) differ in:
  - register choice (`a5` vs `a4` for R[B]);
  - load scheduling (MUL hoists `lbu a2,8(a4)`);
  - the polarity of the tag-19 test (`bne` vs `beq`).

  This confirms L-C2′: a leaf-parametric `sim_ADD` does not give `sim_MUL`
  by instantiation. Any saving from MUL has to come from generic *closers*,
  not a shared proof text.

## 1. Sclerotium complement: one exemption set, and the complement left stale

**Acts on:** (b) merges R3-R1-1 #2 (gauge), R3-R1-2 #1 (the Δ-generators
`protect` and `scratch`), R3-R1-3 #2 (owners and `frame_all`), R3-R1-4 #1 R3
(`supp Inv`), R3-R1-4 #5 (rings) and R3-R1-5 #2 (Dead/`bleach`). It also
(c) objects to their proposed *fix* for `L->top`, with a hidden cost.

### The idea

**These six are one mechanism.** Each shrinks the set of addresses on which
`Core.frame` demands `mem = w.mo`, and then argues that the complement does
not look there:

| round-1 idea | what it calls the set | how it re-establishes the complement |
|---|---|---|
| R3-R1-1 #2 | gauge set Γ(pc) | re-prove `Complement` under `regauge` (80–150 lines) |
| R3-R1-2 #1 | Δ = `protect ; scratch` | `Inv` stable under each generator |
| R3-R1-3 #2 | owners `ciF savedpc`, `LF top`, `calleeStack` | phase invariant `L->top ∈ {func+16, ci->top}` plus `protect_ok` |
| R3-R1-4 #1 R3 | outside `supp Inv` | `Inv.frame` |
| R3-R1-4 #5 | ring 2 | `close_2` |
| R3-R1-5 #2 | `Dead`, `Win′ = Win ∪ Dead` | `Complement.dead_congr` |

**The objection: all of them re-prove `Complement` for a new `w.mo`, and
none needs to.** `VmRel` quantifies `∃ w`, and the complement lives in
`w.mo`, not in the machine's memory. Keep `w` **unchanged** across
`Protect`. The complement then goes *stale* at the two `Protect` addresses:
`LuaStateAt.top` still says `L->top = func+16`, but about `w.mo`, not about
the real memory. Nothing re-proves it, and nothing is false, because
`Core.frame` no longer claims that `w.mo` and the machine agree there. The
complement is a dormant body (a sclerotium). It is woken, and paid for, only
at the one consumer that needs the real values: the runtime shape (CALL),
which must rebuild `RuntimeMem` over real memory anyway (R3-R1-4 #3's
regrowth).

So the cheapest build is **one exemption term in one field**:

```lean
def Scratch (w : RelPtrs) (pc : Nat) (a : Nat) : Prop :=
  (w.ci + ciSavedpcOff ≤ a ∧ a < w.ci + ciSavedpcOff + 8)
  ∨ (pc ≠ 0 ∧ w.L + stateTopOff ≤ a ∧ a < w.L + stateTopOff + 8)
  ∨ (w.sp - calleeBudget ≤ a ∧ a < w.sp)

-- Core.frame, edited:
frame : ∀ a, ¬ Win p w a → ¬ Scratch w s.pc a → bytesT1 c.σ.mem a = bytesT1 w.mo a
```

- `pc ≠ 0` keeps `L->top` observable at pc 0. VARARGPREP reads it there
  (`luaT_adjustvarargs` counts `L->top − func − 1`), and at pc 0 the pin
  still holds, because no `Protect` has run.
- `ci->savedpc` is exempt at every pc: its only reader is the prologue
  (`ld s11,32(s7)`), which runs before the first head.
- It is a *separate* exemption, not a bigger `Win`, because `Ranges.ci_out`
  (N2) says the `CallInfo` is outside `Win`. Growing `Win` would make
  `ci_out` false and ripple into every read of `ci->trap` and `ci->func`.

### Core rules

- **L-C6′ (the non-def part) → `frame_scratch`**: stores in `Scratch` leave
  `Core.frame` intact, with the same `w`. The proof is one line: the premise
  excludes those addresses.
- **L-C6′ (the def part)** is idea 4's final-memory close. That is R3-R1-5
  #2's `bleach`, keeping its "read the final bytes" premise and dropping its
  `Win′` and `dead_congr`.
- **Waking (L-C3′ runtime) → `wake`**, which is needed first at CALL, not in
  this pilot:

  > `Complement p w → Core.frame c w → RuntimeMem' c.mem …`

  Here `RuntimeMem'` is `RuntimeMem` with `top` and `savedpc` taken from
  real memory. The `LuaStateAt.top` edit is paid here once, and only for
  the arm that consumes it.

### What it makes free

- **For MOD, EQ and every future `Protect` arm** (MODK, IDIV, IDIVK, EQK,
  LT, LE, FORPREP, MMBIN*): the `Protect` stores cost **0 lines per arm and
  0 re-proof of `Complement`**. The `regauge` (80–150), `protect_ok` or
  `dead_congr` (40) lemmas are not written.
- **For EQ:** `luaV_equalobj`'s `sd ra,40(sp)` (N1), which no round-1 pilot
  accounted for as a `Core.frame` breach.
- **The census's (d1) widening for `savedpc`/`L->top`** is gone entirely;
  there is no new field.

### What it costs

- **Setup, about 40–60 lines:**
  - `Scratch` and the one-field edit;
  - one lemma, `not_scratch_of_const_off`, which discharges `¬ Scratch` at
    every read the proved arms make outside `Win`: `ci+40` (trap), the code
    words, `k`, `0(sp)`. All of these are fixed offsets from pins, so
    `omega` settles them;
  - one `Ranges` conjunct, `slots_lo : w.base + 16·maxstack ≤ w.sp −
    calleeBudget`, proved at entry from `cstack_room` (N8), provided
    `cStackBudget ≥ 176 + 48`. Check this.
- **The 25 proved arms.** `frame` gets *weaker* for the arm to establish,
  so their establishing side is unchanged. Their consuming side gains a
  `¬ Scratch` side-goal at each non-window read. If those reads go through
  shared `*_of` lemmas, the fix is once per lemma, not per arm.
- **What gets harder.** A stale complement is a trap for a later arm that
  *reads* `L->top` through `LuaStateAt` without waking it. That is exactly
  the class of arm that must call `wake`, so the type makes the dependency
  visible.

### Theories

- **Known, distant (databases): snapshot isolation and stale reads.** A
  transaction reads a snapshot. Writes to rows it never reads do not
  invalidate it; a later reader must refresh. Berenson et al., "A critique
  of ANSI SQL isolation levels", SIGMOD 1995 (recalled; check).
- **Known, distant (mycology): sclerotia.** Dormant, hardened fungal bodies
  that stay viable until conditions wake them. The structural pattern is
  "carry an unrefreshed description until a consumer needs it".
- **Known: ghost state.** In separation logic and Iris, `w.mo` is ghost
  memory, and a frame condition may exempt addresses the ghost no longer
  tracks. Jung et al., "Iris from the ground up", JFP 2018 (recalled;
  check).
- **Novel:** doing nothing to the complement for writes it does not need
  to see, where round 1 proposed six ways of re-proving it. The only cost
  moves to the first consumer that reads real memory.

### Pilot

- **Build:** `Scratch`, the field edit, `not_scratch_of_const_off`, and
  `slots_lo`.
- **MOD and EQ:** the `Protect` stores (and EQ's callee frame) close with
  the unchanged `w`. Success means 0 hand lines in either arm mention
  `Protect`.
- **MUL:** a control (no `Scratch` store).
- **`sim_ADD`:** a control. It must not grow, and at most it gains one
  `¬ Scratch` discharge inside a shared lemma.
- **Cheap falsifiers, before the bake-off:**
  - **(i)** In the 1,424-step trace, for every non-CALL arm, the set of
    addresses written outside `Win` is contained in `Scratch`, and no
    address in `Scratch` is read before it is written within an arm.
    (This is L-C6′ restated; tools may check laws.)
  - **(ii)** No F1 edge targets pc 0. If one did, `pc ≠ 0` would need to
    become "no `Protect` since entry".

### Seed

*sclerotia* (the dormant body kept viable unrefreshed), *unexercise* (the
`L->top` clause goes unexercised until CALL) and *benightment* (the
complement is benighted about two addresses, and that is fine).
*togetheriness* and *oxytocin* drove the six-way merge.

## 2. Enshrinement: the intern map in the witness, and a canonical encoder

**Acts on:**
- (a) extends R3-R1-5 #1's `decode_canon` (from its F-e) and R3-R1-2 #1's
  aside that "a string's view stores the TString pointer plus the heap's
  interning map";
- (c) objects to R3-R1-1 #3 R3.3, R3-R1-2 #2 (`Factors_I`), R3-R1-3 #4 and
  R3-R1-4 #2. All four make interning a *heap invariant*, and that is a
  hidden cost in the wrong place;
- (c) also rules out the cheaper-looking K-provenance fix, because CONCAT
  is in F1 (N3).

### The idea

The coordinator's two EQ gaps, canonical nil tags and interned short
strings, are both cases of one fact: **`ValRepr` is not the graph of a
function**. Make it one:

- **Tighten nil and string tags.** Change `ValRepr.nil`'s side condition
  from `t % 16 = 0` to `t = 0` (N6: the arms write tag 0). Make `.str`'s tag
  a function of the length: `0x44` if `s.length ≤ 40`, else `0x54`.
- **Put the intern map in the witness.** Add a partial map
  `ι : ByteString ⇀ Nat` to `RelPtrs`, next to `func`. Then
  `ValRepr.str` for a short string requires `x = ι s` (and `TStringRepr mo
  (ι s) s`).

Two registers holding the same short content now hold **the same pointer
by definition**, because `ι` is a function. No heap-level uniqueness
invariant over `StrtAt` chains is stated, and none is proved for EQ.
Pointer inequality implies content inequality because `TStringRepr` is
functional in its pointer.

With these two changes, one lemma finishes EQ's value side:

```lean
theorem repr_eq_iff (h₁ : ValRepr w t₁ x₁ v₁) (h₂ : ValRepr w t₂ x₂ v₂)
    (hs : ¬ isLongStr v₁) :
    v₁ = v₂ ↔ (t₁ &&& 63 = t₂ &&& 63 ∧ (payloadMatters t₁ → x₁ = x₂))
```

The right-hand side is **exactly what `luaV_equalobj` computes on F1
values** (N7). EQ's call-node residual (idea 3) is then stated on bytes
(`a0 = reprEq slotA slotB`), and `repr_eq_iff` turns it into δ `.eq`.

**Where the interning cost goes.** It goes to the runtime shape that
*creates* strings: CONCAT's `luaS_newlstr`. That shape must return `ι' s`
for some `ι' ⊇ ι`, because `internshrstr` looks the content up before
allocating. At entry, `ι` is the map of the K strings the loader lays out.
Growing `ι` is the same "`∃ w`, re-chosen" move as `func` relocation
(R3-R1-5 #4, R3-R1-3 #2), so it costs no new mechanism.

### Core rules

- **L-C4 on equality tests → `repr_eq_iff`.** It is one lemma for EQ, EQK,
  EQI and every future equality inside a helper (`luaH_getshortstr`'s key
  compare is the same pointer test).
- **L-C3′ runtime, for string creators → `ι`-monotone results.** CONCAT's
  contract says it returns `ι' s` with `ι ⊆ ι'`. That is part of the
  runtime shape, not a relation field.

### What it makes free

- **For EQ, EQK and EQI:** the interning invariant costs 0 lines in the
  arm. R3-R1-1, R3-R1-2, R3-R1-3 and R3-R1-4 all budget it as "real work"
  before EQ can be proved.
- **The nil-tag gap:** it disappears by tightening, and tightening only
  helps consumers. A guard `andi tag,15; beqz` still decides nil.
- **The L-C3′ oracle's blind spot.** `lc3` compared the bytes behind the
  pointers, not the pointers. It could not have seen the gap. Under `ι`, the
  oracle and the machine agree by construction.

### What it costs

- **Setup, about 50–70 lines:**
  - the `ValRepr` edits;
  - `ι` in `RelPtrs`;
  - `repr_eq_iff`;
  - re-checking the arms that *produce* values. LOADNIL writes `sb zero`
    (N6). MOVE and LOADK copy 16 bytes, which preserves canonical form.
    CALL's `moveresults` nil fill is outside the pilot.
- **Long strings stay per-helper.** `luaS_eqlngstr` is `a == b ||
  (len equal && memcmp == 0)`, a memcmp loop. Either the pilot scopes EQ to
  the non-long-string leaves (and reports it), or it adds one memcmp loop
  schema (idea 3).
- **Entry has to build `ι`.** The loader interns K strings. If `p.k` has
  duplicate string constants, both entries must be the same pointer. `luac`
  deduplicates K, but check the loader.

### Theories

- **Known: hash-consing.** Filliâtre and Conchon, "Type-safe modular
  hash-consing", ML Workshop 2006 (recalled; check). With maximal sharing,
  structural equality is pointer equality. Here the sharing map is part of
  the *witness*.
- **Known, distant (chemistry and registries): canonical registry
  numbers.** The CAS Registry gives one number per substance, so identity
  checks are number comparisons (recalled; check). `ι` is the registry.
- **Known, distant (epistemology and the Faerie Queene): Archimago's false
  Una**, a double that passes inspection by appearance. A decoder that
  compares contents (as `lc3` did) is fooled; a canonical map is not.
- **Novel:** interning as a *function in the existential witness*, rather
  than as a uniqueness invariant over the heap. EQ then pays nothing, and
  the one runtime shape that allocates strings pays once.

### Pilot

- **Build:** the tightened `ValRepr`, `ι`, and `repr_eq_iff` restricted to
  nil, bool, int, lcf and short string.
- **EQ:** the residual `a0 = reprEq`, then `repr_eq_iff`, then δ `.eq`.
  Target: 3 lines of the arm are about equality.
- **MUL, MOD, ADD:** controls. The tightened `ValRepr` must not add lines;
  the `tag = 3` guards are unaffected.
- **Cheap falsifier:** extend the L-C4 decoder to be *strict* and rerun it
  on the 1,424 heads (idea 5). It checks that every nil slot has tag 0,
  every string tag agrees with the length, and no two distinct live
  short-string pointers in registers have equal content. One failure kills
  this form.

### Seed

*enshrinement* (one shrine per content: `ι`), *Archimago* (the false double
that the content check cannot see) and *idiocratic* (each value's own
peculiar encoding, made canonical).

## 3. Amplidyne call node: the residual row, corrected on four points the disassembly contradicts

**Acts on:**
- (b) combines R3-R1-4 #2 (the helper's obligation is the *residual* of the
  kernel at the leaf) with R3-R1-5 #3 (class R/RO by syntax) and R3-R1-1 #3
  / R3-R1-2 #4 (reuse of existing specs by relocation);
- (c) corrects four claims with counterexamples: N4, N5, the `t0` linkage,
  and the relocation cost.

### The idea

A small control signal (the table row) drives a large machine (the helper's
proof), which is the amplidyne. The **call node** is the one of R3-R1-4 #2:
abstract `f`, with the residual read off the leaf. That idea is right. Four
details from the disassembly change what the node and the rows must say:

1. **Frame class is per path, not per function.** On F1 paths,
   `luaV_equalobj` writes only `sd ra,40(sp)` in its own frame. Its
   metamethod paths call `luaT_gettm` and `luaT_callTMres` (runtime).
   R3-R1-5 #3's scanner classifies whole closures, so it would file
   `luaV_equalobj` as class U, both through the metamethod calls and through
   its internal `jr a5` (N4). Classify the **ValRepr-feasible slice**: the
   scanner walks only the jump-table entries whose tag some F1 value can
   have (0, 1, 17, 3, 22, 0x44 and 0x54 after `&63`). The walk is decided
   from the tag set and the table bytes in `.rodata`, which
   `Complement.rodata` already fixes.
2. **Two-output helpers.** `__udivdi3` returns the quotient in `a0` *and*
   the remainder in `a1`, and `__moddi3` returns `a1` (N5). The row for
   `__udivdi3` must be `(a0, a1) := (udiv, urem)`. One spec then serves
   `__divdi3`, `__moddi3` and `__umoddi3` by composition, each about 10–15
   lines of sign cases.
3. **Non-`ra` linkage.** `__moddi3` saves `ra` in `t0` and returns by
   `jr t0`, and its inner call clobbers `ra`. So the node's post-state must
   havoc `ra` and `t0`, and the node's *entry* rule must allow a nested
   class-R call whose return register is `t0`. That is still ABI-conformant
   for the caller (both are caller-saved), but R3-R1-1 R3.1's `ra = ret`
   phrasing needs to say "returns to the `jal`'s link", not "`ra` preserved".
4. **Relocation is optional, and the cheaper route is a loop schema.** The
   coordinator confirmed that the soft-int bytes are identical to the WHILE
   build's. But a Sail translation-equivariance theorem is budgeted at
   150–400 lines (R3-R1-1, R3-R1-2), with the `auipc` risk. The alternative
   is R3-R1-5 #3's two loop schemas (shift-add and restoring division),
   about 60 lines each, proved at the Lua addresses. They cover all five
   soft-int helpers, because the wrappers are straight-line. Relocation
   pays off only if more WHILE specs are reused later (`MemcpySpec` for
   CALL). **Decide by what `udivdi3_spec` says about `a1`.** If it says
   nothing, relocation transports an insufficient spec (N5), and the
   schema route wins outright.

### Core rules

- **L-C3′ pure → `call_pure`**, stated as `(link, clobber set, outputs :=
  row f args)`. It is proved once from the ABI and the class verdict.
- **L-C3′ noreturn → nothing inside `sim_X`.** The Step premise (δ `none`)
  makes those paths vacuous, as R3-R1-3 #4, R3-R1-4 #2 and R3-R1-5 F-f say.
  I checked this for MOD: `n = 0` gives `imod = none`, so there is no
  `Step`. It holds.
- **L-C2′ for helpers → the row table.** `__muldi3 ↦ (·*·)`,
  `__udivdi3 ↦ (udiv, urem)`, `__moddi3 ↦ srem`, and
  `luaV_equalobj ↦ reprEq` (idea 2).

### What it makes free

- **(b) for MUL, MULK, MOD, MODK, IDIV, IDIVK, EQ, EQK and EQI:** one row
  each, plus two loop schemas and one F1-slice proof of `luaV_equalobj`.
  That slice is about 25 instructions on the paths for tags 0, 1, 17, 3, 22
  and 0x44.
- **Spills across the call:** none on these paths. MOD keeps the divisor in
  `s10` across `__moddi3`, and EQ keeps `k` in `s4`. So the pilot needs no
  "memory ≥ `sp` unchanged" reasoning beyond `Scratch`.

### What it costs

- The class-RO rule is proved once (callee-saved discipline plus below-`sp`
  stores), about 80 lines.
- The feasible-slice scanner adds about 40 lines on top of R3-R1-5 #3's
  scanner.
- The loop schemas are about 60 lines each.
- **What gets harder:** long strings (memcmp) need a third schema, and that
  is the honest per-helper residue.

### Theories

- **Known: the ABI as a contract.** CompCertO's C-calling-convention
  interface, Koenig and Shao, PLDI 2021 (recalled; check).
- **Known, distant (electrical machines): the amplidyne.** A small control
  field sets a large output (Alexanderson, 1940s; recalled). The row is the
  control field, and the helper's proof is the armature.
- **Known, distant (pharmacology): the "biowaiver"** (R3-R1-5 #3). Here the
  waiver is per *path class*, not per drug. That is closer to "per
  indication" labelling.
- **Novel:** classifying a helper's frame and effect over the
  **representation-feasible slice** of its control flow, with the slice cut
  by the same tag facts that prune the arm.

### Pilot

## 4. Eutaxite δ: the kernel restated once in `lvm.c`'s own branch structure, closed by forward evaluation

**Acts on:**
- (b) combines R3-R1-3 #5 (forward `kstep` evaluation, no inversions) with
  R3-R1-5 #1's `decode_tag` (seven tag lemmas);
- (c) objects to R3-R1-1 #4 (`knf` + `refines`), R3-R1-4 #4 (`KTree` +
  reconciliation), R3-R1-2 #2's `canon`-evaluation of the tree, R3-R1-3 #1
  (occurrence typing) and R3-R1-5 #5 (minerals). The objection is a hidden
  cost: each builds a *second encoding of the kernel's case structure* and
  pays to prove it equal to the first;
- (d) adds the one piece none of round 1 had: a per-BinOp restatement of δ
  **in the machine's branch order**.

### The idea

**The same mechanism under five names.** `knf` (R3-R1-1 #4), `KTree` +
`ktree_eq` (R3-R1-4 #4), `factor_guard` + `canon` (R3-R1-2 #2), occurrence
atoms (R3-R1-3 #1) and minerals (R3-R1-5 #5) all make the kernel's
`match Opnd.fill os vs with | [.int x, .int y] => …` into a data structure,
so that machine branches can be matched against it. But `kstep` **already
is** that data. Once a path condition fixes the tag bytes, `simp` reduces
`Opnd.fill` and the `match`. So the cheapest member of the family is:

- R3-R1-3 #5's `kstep_iff` rewrite;
- R3-R1-5 #1's `decode_tag`: one lemma per tag constant, plus `tag ≠ 3 →
  ∀ x, v ≠ .int x`, plus tag 19 impossible;
- *no* tree datatype, no reconciliation map and no per-combinator `ktree_eq`.

**Where that simple plan breaks is the "duplications".** R3-R1-4 #4 names
them: machine splits with no kernel counterpart. MOD has three:

- `n+1 ≤u 1`;
- the sign fix-up `r ≠ 0 ∧ (r ^ n) < 0`;
- the `n = −1` shortcut.

`simp` on `Int.fmod` will not produce those splits. So state, **once per
BinOp and test**, the `lvm.c` algorithm as a Lean function in the same
branch order as the C, and prove it equal to δ:

```lean
-- luaV_mod (lvm.c), branch-for-branch
def imodC (m n : BitVec 64) : Option (BitVec 64) :=
  if (n + 1).ult 2 then (if n = 0 then none else some 0)
  else let r := m.srem n; some (if r ≠ 0 ∧ (r ^^^ n).msb then r + n else r)
theorem imodC_eq : imodC = imod

-- luaV_equalobj on F1 values (N7), stated on representations
def eqC (t₁ x₁ t₂ x₂) : Bool := (t₁ &&& 63 == t₂ &&& 63) && (!payloadMatters t₁ || x₁ == x₂)
-- equal to δ .eq through idea 2's repr_eq_iff
```

The layers are banded, as in eutaxite: δ, then `δC`, then the machine. The
arm's path conditions then match `δC`'s `if`s one to one, and each leaf
closes by `simp [imodC_eq.symm, imodC, <path condition>]` with no leaf
lemma. The machine-shaped δ is the *only* place `Int.fmod` meets
`BitVec.srem`, and MODK, IDIV (`idivC`) and IDIVK reuse it.

### Core rules

- **L-C4 on a leaf → `leaf_close`**, one theorem. Its premises are:
  - the path's `(edge, vals)`, where `vals` is read from the final memory by
    `slotVal`;
  - that `kstep (s) = some (s.apply e o)`, discharged by `simp [kstep_iff,
    opKernel, δC_eq]` under the path condition.

  Its conclusion is `VmRel p c' s'`, with the frame handled by idea 1.
- **The per-branch guard law → `decode_tag`** (seven lemmas, fixed).
- **L-C2′ → `δC_eq` lemmas, one per BinOp or test** (not per tree). The
  C code is one algorithm per operator, whatever the operand kinds.

### What it makes free

- **(a5) inversions:** 0 new, now and later. This is the same as R3-R1-3 #5,
  and it needs *nothing* built (`kstep_iff` exists).
- **(a4) guards:** 0 new beyond the seven tag lemmas and one lemma per
  numeric test shape (`ult2_iff : (n+1).ult 2 ↔ n = 0 ∨ n = −1`).
- **(a1) duplications:** paid once per operator, as a `δC_eq`, which is
  cluster (a6), already falling.
- **Build cost avoided:** the round-1 structures (`knf` about 150 lines,
  `KTree` about 120, `refines` about 120, the recogniser 300–500, and the
  occurrence rules 450–600) are not built.

### What it costs

- **`δC` proofs:**
  - `imodC_eq` is the one real BitVec proof, about 30–50 lines. The
    `Int.fmod` versus truncation-plus-fix-up identity has to be proved
    carefully at `minint`;
  - `idivC_eq` is similar;
  - the others (`add`, `mul`, `band`, …) are `rfl`.
- **CPU:** `simp` reducing `opKernel` on a symbolic word must not unfold
  `Proto.fetch`. `docondjump`'s `nextJump p pc` must enter as a hypothesis,
  through one shared `donextjump_target` lemma for every conditional jump
  (it reads `code_word` at pc+1).
- **What gets harder:** a leaf that fails leaves a `simp` residue, not a
  named mismatch. R3-R1-3 #5's "double-entry" point still applies: keep
  leaves as separate goals.

### Theories

- **Known: refinement calculus, data refinement by algorithmic
  restatement.** Morgan, *Programming from Specifications*, 1990
  (recalled). `δC` is an intermediate refinement between the spec and the
  code.
- **Known, distant (geology): eutaxitic texture.** Banded layers welded in
  place. Each band is a faithful record of the one below, and each boundary
  is crossed once.
- **Known, distant (compiler testing): "reference implementations in the
  target's idiom".** CompCert's `Int.mods`/`divs` lemmas state C's
  truncating semantics once for all passes (recalled; check).
- **Novel:** the observation that five round-1 proposals rebuild the
  kernel's case data, and that the only missing piece is a
  *machine-branch-ordered* δ, per operator.

### Pilot

- **`sim_ADD`:** three leaves (int × int; B not int; C not int). Float
  leaves die by `decode_tag` 19. Each leaf is `leaf_close` plus `simp`.
  Target: at most 10 lines, against 61.
- **MUL:** the same three leaves, plus idea 3's call row. Target: at most 10.
- **MOD:** five live leaves:
  - `n = −1`;
  - the main path, with and without the fix-up (one leaf via `imodC`);
  - B not int;
  - C not int.

  One vacuous leaf (`n = 0`) comes from `imodC … = none`. Target: about 10,
  plus `imodC_eq` counted separately, since it is shared with MODK.
- **EQ:** two leaves (`a0 = k`, `a0 ≠ k`), plus `eqC`/`repr_eq_iff`, plus
  `donextjump_target`. Target: at most 8.
- **Cheap falsifier:** a 10-line Lean `example`. On a symbolic
  `s : VState Value` with `s.regs b = some (.int x)` and `s.regs c = some
  (.int y)`, check that `simp [kstep, decide?, opKernel, arithRR, opArith,
  δ, imodC_eq.symm, imodC]` reduces `kstep` to the three-way `if` in under
  about 2 s. If it does not, forward evaluation needs a reflective evaluator
  (R3-R1-1 #4's `refines`) after all.

### Seed

*eutaxite* (banded layers: δ, then `δC`, then the machine), *milfoil*
("thousand leaves": the proof is per leaf, not per tree) and *Copepoda*
(many small per-operator lemmas instead of one big structure).
*laparocolectomy* suggested cutting the data structures out.

## 5. Bathycentesis: the relation's decoder as executable Lean, with the law checks run on it

**Acts on:**
- (a) extends R3-R1-5 #1 (`decode` in Lean, with `lc4_trace.py` as its
  spec), R3-R1-4 #1 (`dec`) and R3-R1-1 #1 (`decSlot`);
- (d) goes where none of round 1 went. **The law checks validated a
  different relation from `VmRel`.** Make them validate `VmRel` itself.

### The idea

**The evidence that something is wrong.** L-C4 "holds on 1,424 real
steps", and L-C3 agreed on 7 `luaV_equalobj` activations. Yet as stated,
`sim_EQ` is **false** for `VmRel` (R3-R1-5 F-e: a `VEMPTY`-tagged nil), and
`sim_MOD` is false too (`LuaStateAt.top`). The Python decoder and oracle
checked contents and a relaxed frame; `VmRel` states tags, pointers and a
strict frame. **The checker and the relation have drifted apart**, so a
passing law check says nothing about whether the relation is provable.

The fix is to have one artifact. Write the decoder that R3-R1-5 #1 already
proposes as a computable Lean function:

```lean
def decodeHead (p : Proto) (w : RelPtrs) (σ : MState) : Except Violation State
```

It is *strict*: it fails with a named `Violation` on:

- a nil tag ≠ 0;
- a string tag that disagrees with the length;
- a short-string pointer ≠ `ι s`;
- any byte outside `Win ∪ Scratch` that differs from `w.mo`.

Then prove **one** lemma, `decodeHead_ok ↔ VmRelAt`, restricted to the
must-initialised mask of `Cert` (R3-R1-5 #1's novelty). Now:

- **the relation is the checker**: `lake env lean --run` over the dumped
  1,424 head snapshots (the trace already exists) *is* the L-C4 law check,
  run against `VmRel`'s own definition;
- **every proposed relation change** (idea 1's `Scratch`, idea 2's `ι`,
  canonical nil, a future `RtOwned`) is falsified or confirmed on real
  states *before* any proof is attempted. The run costs minutes, not a
  bake-off.

This is sampling the deep fluid before operating: bathycentesis.

### Core rules

- **L-C4 → `decodeHead_ok ↔ VmRelAt`.** It is one theorem, and it makes
  the empirical law and the proved relation the same predicate.
- **L-C6′ (Scratch form) → a second executable check,
  `armFootprint_ok`.** It runs over each pair of consecutive head
  snapshots and reports addresses outside `Win ∪ Scratch ∪ defs(e)` that
  changed. It is a check only; the proof never uses it.

### What it makes free

- The three soundness gaps of round 1 were found by reading. With this
  artifact, gaps of that kind are found by running. That matters most
  before the four forecast widenings (heap, `G`, `func` moving, console),
  each of which is 100–250 lines if the relation turns out wrong.
- The adapter that R3-R1-5 #1 budgets (about 60 lines) is the same lemma
  as `decodeHead_ok`, so it is not extra.

### What it costs

- **Setup:**
  - `decodeHead`, about 80 lines. It must decode strings through
    `TStringRepr`'s layout on a concrete `Mem`;
  - the `↔` lemma, about 60;
  - a snapshot dumper from the existing trace tool into a Lean-readable
    form. This is a tool, not a proof.
- **What gets harder:**
  - `ValRepr` is inductive, so the `↔` needs `decodeHead` to pick the
    canonical witness. That is only possible *after* idea 2 makes
    `ValRepr` functional, so ideas 5 and 2 go together;
  - existential parts of `Complement` (`∃ rt`) are checked by computing a
    candidate `rt` from memory. This is fine for the pilot fields, but
    `DlHeap.HeapAt` needs a chunk-walker.

### Theories

- **Known: proof-producing checkers and "one definition for spec and
  test".** QuickChick's `Checkable` from executable specifications
  (Lampropoulos and Pierce, *Software Foundations* vol. 4, recalled).
  Also CakeML's use of the executable semantics for testing (recalled;
  check).
- **Known, distant (clinical medicine): diagnostic paracentesis before
  surgery.** Sample the fluid to rule out a diagnosis cheaply before the
  operation.
- **Known, distant (metrology): calibrating the instrument against the
  standard it claims to measure.** A law check whose checker is not the
  relation is an uncalibrated instrument.
- **Novel:** diagnosing that the project's law checks and its relation have
  drifted (L-C4 passes while `sim_EQ` is false), and removing the drift by
  making the relation's decoder the checker.

### Pilot

- This idea does not reduce MUL, EQ or MOD lines. It is the **gate** that
  decides whether ideas 1 and 2 are worth building.
- **Build:** `decodeHead` for int, nil, bool, lcf and short string, and
  `armFootprint_ok`.
- **Run on the 1,424 snapshots:**
  - (a) strict canonicity (idea 2);
  - (b) the `Scratch` footprint (idea 1), with no read before write inside
    an arm;
  - (c) that EQ's `luaV_equalobj` result equals `reprEq` on every
    activation.
- **`sim_ADD`:** unchanged. It is the control for the `↔` adapter.

### Seed

*bathycentesis* and *pneumotomy* (sample before cutting) and
*unpredictably* (the checks passed, but predicted the wrong relation).
*Vu* is the déjà vu of the Python and Lean decoders, which look the same
and are not.
