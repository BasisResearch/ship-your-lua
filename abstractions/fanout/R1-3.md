## 1. Static-footprint rule bodies (Step as a factorised kernel)

**The idea.** Each bytecode rule is a triple. First, a static read vector `reads : List Nat`, computed from `(p, pc, w)` only. Second, a static edge list `edges : List (Nat × List Nat)` of targets and write indices, also computed only from `(p, pc, w)`. Third, a body function:

```lean
structure Kernel where
  reads : List Nat
  edges : List (Nat × List Nat)            -- target pc, registers written on that edge
  body  : List Value → Option (Σ e : Fin edges.length, Vector Value (edges[e].2.length) × String)
```

The body takes the values of the read registers and returns an edge index, the values to write and the output to emit, or `none` (stuck). A single table `kernel : Proto → Nat → Word → Option Kernel` holds all the per-opcode content. `Step` gets ONE constructor:

```lean
| run : p.fetch s.pc = some w → kernel p s.pc w = some K →
        K.body (K.reads.map s.regs) = some ⟨e, vals, str⟩ →
        Step s (((s.writeMany (K.edges[e]).2 vals).emit str).goto (K.edges[e]).1)
```

The central point is statistical. The next state factorises as `g(T(s)) ⊕ frame(s)`, where `T(s) = reads.map s.regs` is a sufficient statistic for the step. In the Fisher–Neyman sense, L-B1 *is* that factorisation. It is currently re-proved per rule only because `Step`'s constructors hide the factorisation inside ad-hoc premises like `s.regs w.b = .int x`.

The applicative shape carries the "static" requirement: the register *addresses* are fixed before any value is seen, as in the static dependencies of an applicative build task. Control dependence, i.e. which edge, goes through the edge index. This is the selective-functor move. `edges` is the static over-approximation, and `body` picks the one taken branch.

**Core rules.**

- **L-B1 becomes `Kernel.footprint`, one theorem of about 25 lines, with no case split on opcodes.** Take `s ≈_{K.reads} t` with the same pc and output. Then `Step s s' → ∃ t', Step t t' ∧ s'.pc = t'.pc ∧ s'.out = t'.out ∧ s' ≈_{(K.edges e).2} t'`, and `∀ j ∉ (K.edges e).2, s'.regs j = s.regs j`. The proof: `K.reads.map s.regs = K.reads.map t.regs` by `List.map_congr`, so both calls to `body` return the same thing, and `writeMany_frame` does the rest. The census's "some edge with that target" refinement is automatic: the edge *index* is chosen, not the target.
- **L-B2 becomes `step?` as `Option.bind` of the same three pieces, and `Step ↔ step? = some` is one lemma** (`constructor <;> rintro …; simp_all`). No stepper arm is written.
- **L-C1 (partial).** The arm's contract is generated from the kernel: read slots `reads`, write slots of edge `e`, land on the head with savedpc equal to the target. Idea 5 builds on this.

**What it makes free.**

- The `step?_sound`, `step?_complete` and `Step.sim` arms: all 75 cases of `bc-rule-fanout`, 8.5 lines per rule.
- The separate `reads`, `regTop` and `edgesOf` tables. `reads w`, `regTop w` and the edge list all become projections of `kernel`: `regTop = max (reads ++ edges.flatMap (·.2)) + 1`.
- The "5 places per rule" become 1.

**What it costs.**

- **Setup.** `writeMany` and its frame lemmas, `Kernel`, the generic `footprint` and `L-B2` proofs, and rewiring `Supported`'s `edges` onto `kernel`. About 200 lines.
- **Faithfulness gets harder to audit.** The 26 readable `Step` constructors become one kernel table of `fun | [.int x, .int y] => …` bodies. Mitigation: keep the constructor docstrings as comments on the kernel arms, and keep each arm next to its `lvm.c` citation.
- **Positional read vectors** are less readable than named premises.
- **`Supported`'s F1 side conditions** (for example "`LOADK` only of non-string constants") must move to a separate `admits` predicate. The kernel now describes behaviour whether or not the fragment admits it, which removes the census's first refinement ("edges exist") by design.
- **The TV-program facts** that invert particular `Step` constructors need rewriting.

**Theories.**

- **Statistics.** The Fisher–Neyman factorisation theorem: `T` is sufficient iff the density factors as `g(T(x), θ)·h(x)`. *Known*: R. A. Fisher 1922, "On the mathematical foundations of theoretical statistics", Phil. Trans. R. Soc. A; J. Neyman 1935 (Giorn. Ist. Ital. Attuari; venue from memory, check). The footprint law is the deterministic, relational analogue: `reads` is sufficient for the step.
- **Build systems.** Applicative tasks have statically known dependencies; monadic ones do not. *Known*: Mokhov, Mitchell, Peyton Jones, "Build Systems à la Carte", ICFP 2018.
- **Selective functors.** `select`, whose static analysis gives over- and under-approximations of effects; here `edges` is the over-approximation. *Known*: Mokhov, Lukyanov, Marlow, Dimino, "Selective Applicative Functors", ICFP 2019 (PACMPL 3).
- **Applicative functors.** *Known*: McBride and Paterson, "Applicative programming with effects", JFP 2008.

**Pilot.**

- **Smallest build.** `Kernel` plus `footprint` plus L-B2 over just `MOVE`, `arith` and `testset*`. These are the three shapes: one read; two reads with a skip; two edges with the same target. Show `Step.sim`'s `forloopAgain` and `TESTSET` arms become one generic lemma.
- **H1** (`LOADK` string): delete the `| _ => none` guard in the kernel's const case. 0 proof lines. `admits` gains `.str`.
- **H2** (`CONCAT A B`): `reads = [A, …, A+B-1]`, one edge `(pc+1, [A, …, A+B-1])`. The body folds right-to-left, integers via `%d`.
  - Faithfulness trap to check against `lvm.c`: `luaV_concat` works in place on `top-n…top-1`. It concatenates "as many string values as possible" per pass, so slots `A+1…` end up holding *intermediate* results, not their old values.
  - The static write set must therefore be the whole range, and the body must produce those intermediate values, or the edge must declare them overwritten. `luac` never reads them, but L-B1's "every register outside `wr` is unchanged" would be *false* if the write set were only `{A}`. This is from memory of `lvm.c`/`luaV_concat`: check it.
  - Proof cost: 0 lines for L-B1 and L-B2.
- **H3** (`LEN` on a string): `reads = [B]`, body `| [.str s] => ⟨0, #[.int s.length], ""⟩`. 0 proof lines.
- **H4** (strings in `LT`/`LE`): add one arm `| [.str a, .str b] => condJump … (lexLt a b)` to the existing `cmpRR` body. `lexLt` needs its own spec lemma (`l_strcmp` in the C locale is byte-lexicographic on unsigned bytes, prefix smaller). That lemma is value-level, not per-rule.
- **R1:** replace `Step.sim` (27 arms), `step?_sound` and `step?_complete` by `footprint` plus L-B2. Expected: 857 lines become about 200 of setup plus about 110 lines of kernel table. Most of the table replaces the `Step`/`edgesOf`/`reads`/`regTop` definitions, which don't count as proof.

**Seed.** The `6OR…6OR` exact repeat, a choice made twice, led to the selective functor's `select` and the edge index as the "OR". The `wo` / `Wo` pair (two states agreeing) framed L-B1 as a factorisation that needs no two-run proof.

## 2. Microcode dictionary: Lempel–Ziv factoring of rules and arms along `lvm.c`'s macros

**The idea.** `lvm.c` is already a compressed text. Its 54 F1 arms are instances of about 9 macros:

| macro | stands for |
|---|---|
| `op_arith` | register-register arithmetic |
| `op_arithK` | arithmetic with a constant |
| `op_arithI` | arithmetic with an immediate |
| `op_bitwise` | register-register bitwise |
| `op_bitwiseK` | bitwise with a constant |
| `op_order` | order comparisons |
| `op_orderI` | order comparisons with an immediate |
| `docondjump` | conditional jump |
| `setobj2s` / `setivalue` | stores |

The macros come with `vRB`, `vRC` and `KC` as operand fetchers. `gcc -O2` emits each macro instance as structurally the same RISC-V sequence, differing only in the ALU instruction and the operand fetch.

The abstraction is a *grammar* over rule phrases. A **phrase** is a small semantic unit that carries its three facts once:

- its relational meaning;
- its footprint (reads and writes, as in idea 1);
- its **machine template**: a RISC-V instruction pattern with holes `⟨fetchB⟩`, `⟨fetchC⟩`, `⟨alu⟩`, obtained by anti-unifying the arms that use it.

An opcode is a *word* in the phrase grammar. For example, `ADDK = fetchR B ; fetchK C ; intOp (+) ; storeInt A ; skipMMBIN`. Composition `P ; Q` (and `select` for branches) preserves all three facts, proved once per combinator.

**Core rules.**

- **L-B1 and L-B2 become `Phrase.seq_foot`, `Phrase.seq_exec` and `Phrase.select_*`.** Footprints union, the executable reading of `P ; Q` is Kleisli composition, and the relation of `P ; Q` is relational composition. Per-phrase facts are proved once per phrase, about 12 phrases.
- **L-C1 becomes `Template.sim`**, one theorem per template (about 9). It is parameterised by the hole instantiations. For example: "for any R-type RISC-V op `f` with `⟦f⟧ = g` on 64-bit values, the `op_arith` template with `⟨alu⟩ := f`, run from the dispatch head on a state representing `s` with `R[B] = .int x` and `R[C] = .int y`, reaches the dispatch head representing `s.set A (.int (g x y)) |>.goto (pc+2)`."

  Each opcode's arm is then a *decidable match* of its bytes against a template plus an instance of the hole lemma (`⟦add⟧ = (·+·)`). `idiv`/`imod` call `luaV_idiv`/`luaV_mod`, so their `⟨alu⟩` hole is a call with its own spec. The match is a decidable check of a law (the arm is an instance of the template), not the abstraction.

**What it makes free.**

- In A1 (`a1-arm-sim`), 54 arms become about 9 template proofs plus 54 one-line matches plus about 15 ALU-hole lemmas, most of which are the ISA's own `add`/`sub`/`and`/`or`/`xor`/`sll`/`srl` semantics.
- The predecessor project's per-site families (706 rows in 40 tables) were exactly this repetition uncompressed.
- Semantically, the existing `Step.arith` already does this factoring for 21 opcodes, via `intArith` and `arithShape`. The idea completes that factoring: `cmpRR`/`cmpRI`/`eq*`/`test` share `docondjump`, and `forprep*`/`forloop*` share `forCount`.

**What it costs.**

- **Setup.** The phrase algebra (about 150 lines) and the template language: instruction patterns with holes and register-renaming invariance. The template language is the risky part.
- **Scheduling differences.** `gcc` may schedule instances differently: register allocation, fusing the `pc++` of `MMBIN` skipping with the next dispatch, sharing tails between arms via cross-jumping. Anti-unification then gives a template with more holes, or splits a family. Worst case, a family degenerates to one template per arm, i.e. the incumbent.
- **Measure first.** Before building anything, compute the least general generalisation of the 21 arith arms' disassembly. That number decides the idea.

**Theories.**

- **Data compression.** LZ77 factorisation, and grammar-based compression (the smallest-grammar problem, which gives the proof bound: proofs over the grammar are O(grammar), not O(text)). *Known*: Ziv and Lempel, "A universal algorithm for sequential data compression", IEEE Trans. IT 23(3), 1977; Charikar et al., "The smallest grammar problem", IEEE Trans. IT 51(7), 2005.
- **Logic and ML.** Anti-unification (least general generalisation) to *compute* the templates from the arms. *Known*: G. Plotkin, "A note on inductive generalization", Machine Intelligence 5, 1970; J. Reynolds, "Transformational systems and the algebraic structure of atomic formulas", same volume.
- **Linguistics.** Paradigm-based morphology: a lexeme's cells are realised by one rule block applied to a stem, so irregularity is local. Here an opcode family is a paradigm, the template is the rule block, the ALU op is the stem, and irregular forms (`SHLI`'s swapped operands, `IDIV` by −1) are listed exceptions. *Known*: G. Stump, *Inflectional Morphology: A Theory of Paradigm Structure*, CUP 2001 (recalled, check). Mapping it to ISA templates is *novel*.
- **ISA DSLs** (not distant; context only). *Known*: Armstrong et al., "ISA semantics for ARMv8-A, RISC-V, and CHERI-MIPS", POPL 2019.

**Pilot.**

- **Smallest build.** Anti-unify the disassembled `ADD`, `SUB`, `BAND` and `ADDK` arms of `luaV_execute`, a text exercise on the ELF. If `ADD`/`SUB`/`BAND` share a template up to the ALU slot, prove the `op_arith` template once and instantiate it for the **A1 arm `ADD`**. Then do `docondjump` for the **`EQI`** arm; `EQI`'s template is shared with `LTI`/`LEI`/`GTI`/`GEI`/`EQK`/`TEST`. `FORLOOP` is its own paradigm (a singleton), so it measures the overhead.
- **H1–H4, semantics side.** CONCAT and LEN are new phrases (`concatFold`, `strLen`). H4 adds a `strCmp` value-level hole to the existing `order` phrase: the `op_order` macro already dispatches on `ttisinteger`/`ttisnumber`/`lessthanothers`. Machine-side H arms aren't in the suite, but `LT` gaining a string path shows up as a template branch, `lessthanothers → l_strcmp`, a call with a spec.
- **R1:** as idea 1, plus grouping the kernel by phrase.

**Seed.** `LZ` at offset 1 and again in `LZHZ` near offset 170: Lempel–Ziv, a factor that refers back to an earlier occurrence. The five scattered `7`s, one symbol recurring in different contexts, suggested one template recurring across opcodes with different surroundings.

## 3. The source semantics as the graph of a reified recursion (free call monad, Bove–Capretta graph)

**The idea.** Stop writing `Eval`/`ExecS`/`ExecL`/`ExecBF`/`ExecB`/`ForIter` as a mutual inductive with several rules per construct. Write ONE total Lean function, the **rulebook**:

```lean
inductive Call | eval (ρ) (e) | stat (ρ o st) | list (ρ o ss) | blockF (base all ρ o ss) | forIter (ρ o x i st n b)
def Ret : Call → Type               -- Value, or Env × String × Sig
inductive Prog (α : Type) | ret (a : α) | call (c : Call) (k : Ret c → Prog α) | stuck
def rule : (c : Call) → Prog (Ret c) -- one arm per construct; branching is Lean `match`/`if`
```

`rule` never recurses. Every recursive premise is a `call` node, so `rule` is structurally trivial and total. The semantics is the least relation closed under running `rule`:

```lean
inductive Graph : (c : Call) → Ret c → Prop
  | mk : Runs (rule c) r → Graph c r
inductive Runs : Prog α → α → Prop
  | ret  : Runs (.ret a) a
  | call : Graph c v → Runs (k v) r → Runs (.call c k) r
```

`LuaSem H c out := ∃ ρ', Graph (.blockF [] c.stats [] "" c.stats) (ρ', out, .normal)`. The `whileT`/`whileF`/`whileX` trio becomes one arm:

```lean
| .stat ρ o (.while_ c b) => do
    let v ← call (.eval ρ c)
    if v.isFalse then ret (ρ, o, .normal)
    else let (ρ₁, o₁, sg) ← call (.block ρ o b)
         if sg = .normal then call (.stat (scope ρ ρ₁) o₁ (.while_ c b))
         else ret (scope ρ ρ₁, o₁, sg.exitLoop)
```

The two readings of the same text:

- read as a relation (`Graph`), it is `LuaSem`;
- read as a function with fuel (`handle fuel : Prog α → Option α`, which interprets `call` by recursion on fuel), it is `luaRun`.

Determinism isn't proved per construct because the guards are Lean `if`s: exclusive by construction.

**Core rules.**

- **L-A1 becomes `Graph_iff_run`**, one generic theorem over *any* `rule : (c : Call) → Prog (Ret c)`: `Graph c r ↔ ∃ fuel, handle rule fuel c = some r`. The `←` direction is induction on fuel, the `→` direction induction on `Graph` with fuel monotonicity. About 60 lines, once.
- **Determinism becomes `Graph.det`**, `Graph c r → Graph c r' → r = r'`, a generic 15-line mutual induction on `Graph`/`Runs`. It holds because `rule c` is a *term*, not a set of terms.
- In allegory terms, `Graph` is *simple* (`R∘R° ⊆ id`) because it is the graph of a partial map.

**What it makes free.**

- All 187 cases of `ast-construct-fanout`: `execSound` (19/19/16/15-line arms), `Eval.det` (50 arms), `ExecS.det` (53 arms), and every future construct's soundness and determinism. The quadratic `whileT × whileF × whileX` inversions don't exist, because there is one arm per construct.
- Adding a construct costs its `rule` arm plus its `supE`/`supStat` line.

**What it costs.**

- **Retiring `LuaSem` as an inductive.** The rulebook reads like a definitional interpreter, which some reviewers trust less than inference rules, and it can't express non-determinism later (unspecified evaluation order, `next` order in F2). Mitigation: `Prog` can grow a `choose` node. Then `Graph.det` is lost only for arms that use it, and a decidable "`choose`-free" check restores it per arm.
- **The dependent `Ret c`** is awkward in Lean. Use a plain sum type and a `stuck` on shape mismatch.
- **`tv-program` rework.** Its per-program facts are proved against `ExecS` constructors and must be re-proved against `Graph`, or through derived "rule lemmas" (`Graph (.stat ρ o (.while_ c b)) r ↔ …`). Those are one-line `simp [rule]` unfoldings, but there are about 25 of them.
- **The ELF-side refinement statements** mention `LuaSem`; they stay, with the definition swapped.

**Theories.**

- **Type theory.** The Bove–Capretta method: general recursion via an inductive domain or graph predicate. *Known*: Bove and Capretta, "Modelling general recursion in type theory", MSCS 15(4), 2005. Interaction trees with `mrec` give the same reification of recursive calls. *Known*: Xia et al., "Interaction Trees", POPL 2020.
- **Databases.** Functional dependencies and Armstrong's axioms. `Graph` satisfies the FD `Call → Ret` because each clause body is a conjunctive query whose head is determined by its body atoms, and FDs propagate through such joins. *Known*: W. W. Armstrong, "Dependency structures of data base relationships", IFIP Congress 1974. Using the chase to certify determinism of a *semantics* is *novel* here.
- **Logic programming.** Mercury's determinism analysis (`det`/`semidet`/`multi`/`nondet` by mode and switch detection) is the checker version of the same idea. *Known*: Henderson, Somogyi, Conway, "Determinism analysis in the Mercury compiler", ACSC 1996 (recalled, check).
- **Category theory.** Maps in an allegory are the simple, entire relations. *Known*: Freyd and Scedrov, *Categories, Allegories*, North-Holland 1990.

**Pilot.**

- **Smallest build.** `Prog`, `Graph`, `handle`, `Graph_iff_run`, `Graph.det` for a toy two-construct rulebook (`Exp` with `binop` plus `while`). Then port `Eval` in full: 18 rules, and `Eval.det`'s 50 arms deleted.
- **H1:** the arm `| .eval _ (.string s) => ret (.str s)`. **H2:** `a ← call; b ← call; match a, b` over str/int with `tostring`. **H3:** `#`. **H4:** add a `(.str a, .str b)` case to the `cmp` arm.
  - Each is 1–4 definition lines and **0 proof lines** for soundness and determinism. `AstSupported` gains the matching `supE` entries (1 line each).
- **R2:** delete `Determinism.lean` (216) and `execSound` (294). Add about 120 lines of generic setup and about 25 one-line derived rule lemmas for `tv-program`.

**Seed.** The three palindromes `ZHZ`, `McM` and `FtF` (a text that reads the same both ways) became one rulebook read forwards as an interpreter and backwards as a relation.

## 4. Pretty-big-step with a single abort rule (keep the inductive, make determinism linear)

**The idea.** A conservative alternative to idea 3 that keeps `LuaSem` an inductive of inference rules. The quadratic determinism cost comes from two sources. First, several rules per construct that differ in a guard (`whileT`/`whileF`/`whileX`, `ifT`/`ifElseif`/`ifElse`/`ifNone`, `andF`/`andT`, `repeatDone`/`repeatAgain`/`repeatX`, `cons`/`stop`). Second, the propagation of an abrupt `Sig` being re-stated in each of them.

Pretty-big-step semantics fixes both:

- Each construct gets ONE entry rule, which evaluates the first subterm and passes its *outcome* to an **intermediate term** (`while₁ v c b`, `while₂ sg ρ₁ o₁ c b`, `if₁ v …`, `and₁ v b`, `seq₁ sg ss`).
- Each intermediate term's rules are indexed by a *constructor* of the outcome, not by a propositional guard.
- Abrupt completion is propagated by ONE generic rule: `abort : sg ≠ .normal → isPropagating K → Ext ρ o (K (abrupt sg)) ρ o sg`.

Loops *catch* `brk`, and blocks catch their own `goto`s. That is expressed by the intermediate terms for loops and blocks being excluded from `isPropagating` (they have their own `caught` rule).

The Boolean guard `v.isFalse` becomes a constructor split. `while₁` takes `Truthy := falsy | truthy`, produced by an `Eval`-level classifier (`truthiness v : Truthy`). Inverting the second derivation therefore yields exactly one rule, by the head constructor.

**Core rules.**

- **L-A1, determinism half, becomes `Ext.det`.** Its arms are linear in the number of rules, not quadratic. Each arm is `cases h₂ <;> simp_all` because the outcome constructor fixes the rule.
- **`abort_det`**, proved once, covers all propagation.
- The soundness half of L-A1 (the interpreter) stays per construct, but each arm is now a single `match` on an outcome constructor (about 3 lines, down from 15–19).

**What it makes free.**

- The quadratic cross-inversions in `Eval.det` (50 arms) and `ExecS.det` (53 arms): expected to become about 30 arms of 1–2 lines each.
- All `…X` rules (`whileX`, `repeatX`, `stop`, the abrupt `ForIter.last` branch) disappear into `abort`.

**What it costs.**

- **Rewriting all rules into pretty-big-step form**, which roughly doubles the number of term forms (intermediate terms).
- The relation is less directly comparable with the manual's prose.
- **`ExecBF`'s goto-catch needs care.** A block catches `goto l` only if `l` is its own label, so `isPropagating` is *value-dependent* (`sg.target all = none`). The abort rule needs a side condition, not just a syntactic class. Check this doesn't reintroduce a guard pair (`done`/`jump`); it does, as one pair, handled by the `Option` constructor of `sg.target all`.
- **Doesn't touch the bytecode clusters.**

**Theories.**

- **PL semantics.** *Known*: A. Charguéraud, "Pretty-Big-Step Semantics", ESOP 2013: one abort rule, intermediate terms, a linear number of rules. Also used in JSCert (Bodin et al., POPL 2014).
- **Category theory.** Abrupt completion as the exception monad's bind, where one `>>=` law replaces per-construct propagation. *Known*: E. Moggi, "Notions of computation and monads", Information and Computation 93(1), 1991.
- **Linguistics.** Continuation-based natural-language semantics. One type-shifting (lift) rule handles scope-taking uniformly, instead of a scoping rule per construction. That is structurally the single `abort` rule. *Known*: C. Barker, "Continuations and the nature of quantification", Natural Language Semantics 10, 2002. The mapping is *novel* and suggestive, not load-bearing.

**Pilot.**

- **Smallest build.** Port `Eval` only: `and`/`or` become `and₁`/`or₁` intermediates with `Truthy`. Measure `Eval.det` before and after, then port `while` and `if` in `ExecS`.
- **H1–H4** are all expressions without new abrupt behaviour, so each adds one entry rule (for binary operators, an `op₂` intermediate on a `ValPair` classifier: `strstr`/`strint`/`intstr`/`intint`/`other`). Determinism is +1 linear arm each.
- **R2:** determinism shrinks strongly, `execSound` moderately.
- A useful *control* in the bake-off against idea 3: it separates the gain from "one arm per construct" from the gain from "semantics as a function".

**Seed.** The doubled letters `JJ`, `rr` and `CC` (a symbol stuttering into an intermediate copy) became the intermediate terms of pretty-big-step: a construct passing through a half-evaluated form of itself.

## 5. Machine arms as view updates with a constant complement (a lens from `Config` to `State`)

**The idea.** For L-C1, the representation of a VM `State` inside the machine configuration is a **lens**:

- `view : Config → Option State`. It decodes `savedpc`/`pc`, the `TValue` slots `base[0 … maxstack)` into `regs`, and the HTIF console buffer into `out`.
- The **constant complement** `comp : Config → Rest` is everything else: the C stack frame, the heap and GC state, the `Proto` in memory, callee-saved registers, and `L`'s other fields.

The lens laws are GetPut, PutGet and PutPut, plus the complement decomposition `Config ≅ State-image × Rest` on well-formed configurations. From them comes one generic theorem, the **update-translation rule**:

> An arm correctly implements a kernel step (idea 1's `Kernel`, or plain `Step`) iff:
>
> 1. it preserves `comp`, up to scratch registers and `Rest`'s allowed churn (GC accounting, `L->top`);
> 2. it changes the `State` image only in the slots of edge `e`'s write set, and there it stores `encode vals`;
> 3. it arrives at the dispatch head with the pc image equal to edge `e`'s target and the output image extended by `str`.

The frame of every arm, "every other register slot unchanged", is *not* proved per arm. It follows from (1) and (2) through the lens laws, together with L-B1 on the semantic side (unchanged registers). In Bancilhon–Spyratos terms, the machine arm is the unique translation of the view update `Step` under constant complement `Rest`. What remains per arm is exactly the *delta*: the written slots' values and the target. For EQI that is just the target.

**Core rules.**

- **L-C1 becomes `arm_sim_of_delta`**, proved once: `ArmDelta K arm → ∀ c s, view c = some s → atHead c → ∃ c', arm c c' ∧ atHead c' ∧ view c' = some s' ∧ comp c' ≈ comp c` where `Step s s'`.
- **`ArmDelta`** is the per-arm obligation, generated from the kernel's `(reads, edges, body)`: a Hoare triple over only `reads ∪ writes(e)` slots plus `savedpc`.
- **L-B1 is used as a lemma here, not re-proved**: `Kernel.footprint` gives `s'.regs j = s.regs j` for `j ∉ writes(e)`, and GetPut gives the machine slots unchanged.

**What it makes free.** In A1, the frame half of every arm simulation: "all other TValue slots, the heap and the C stack untouched". In the predecessor project that half dominated the per-site rows. Per arm, only the delta remains, and with idea 2's templates the delta itself is shared per paradigm.

**What it costs.**

- **Defining `comp` precisely is the hard setup**, for four reasons:
  - `L->top` is reset by `CONCAT` and `CALL`.
  - The GC debt changes on allocation (strings, F4).
  - `Protect(...)` saves `savedpc` into `ci->u.l.savedpc`.
  - `luaV_execute` caches `base`, `pc` and `k` in machine registers, so the view must read caches *or* memory depending on the program point. That means one `view` at the dispatch head, not a general one.
- **Complement decomposition** must be shown for the concrete memory layout: `TValue` = 16 bytes, value then tag byte. That is a `VmLayout` fact.
- **The churn relation `≈` on `Rest`** must be weak enough for allocation, yet strong enough that `view` still decodes.
- **The `STR` case (F4)** needs `view` to decode a `TString*` into `List UInt8`, i.e. heap reachability: a separation-logic predicate inside `view`.

**Theories.**

- **Databases.** The view-update problem and translation under constant complement: an update is translatable iff it preserves a complementary view, and the translation is then unique. *Known*: Bancilhon and Spyratos, "Update semantics of relational views", ACM TODS 6(4), 1981.
- **Bidirectional programming.** Lenses and their laws. *Known*: Foster, Greenwald, Moore, Pierce, Schmitt, "Combinators for bidirectional tree transformations", TOPLAS 29(3), 2007.
- **Separation logic.** The frame rule. *Known*: J. Reynolds, "Separation logic: A logic for shared mutable data structures", LICS 2002. `comp` preservation is the frame, stated once for the whole dispatch loop instead of per arm.
- Combining a kernel's write set with the lens delta, so the semantic footprint law discharges the machine frame, is *novel*.

**Pilot.**

- **Smallest build.** `view` and `comp` at the dispatch head only, over the register window and `savedpc`. Leave `out` and the heap out at first: ADD, EQI and FORLOOP don't print. Then prove `arm_sim_of_delta`.
- **A1 arms:**
  - `ADD`: delta = slot A gets `(value x+y, tag LUA_VNUMINT)`, target `pc+2`.
  - `EQI`: delta = nothing, target = `condJump`.
  - `FORLOOP`: delta = slots A, A+1 and A+3, two edges.

  Measure per-arm lines against the incumbent's A1 pilot, which was stopped at a clean point (ROUND-1 §0).
- **H cases** aren't machine-side in the suite, but H2 is the stress test for `comp`'s churn relation (allocation) and should be tried on paper.

**Seed.** The mirror `63` (in `Jk63Hkb`) against `3j6` (in `m3j6vCC`), the same digits read in both directions, became a bidirectional transformation: get the `State` out of the `Config`, put the updated one back, and keep the rest constant.
