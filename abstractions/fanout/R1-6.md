## 1. Avatar microcode: each opcode is a selective-applicative term, and `Step` is its single interpretation

**Idea.** Today there is one god (lvm.c's semantics) and 27 hand-written
incarnations of it: the `Step` constructors, the `step?` arms, `edgesOf`,
`reads` and `regTop`. That makes five places per rule, all maintained by hand.
The proposal is a small first-order language `Micro` of *selective applicative*
effects: every register read is declared up front, branches are selections
between statically known alternatives, and the leaves are writes plus a target.
Each opcode is written **once**, as `micro p w : Option Micro`. `Step` has one
constructor that interprets the term relationally, and `step?` interprets it in
`Option`. `reads`, `edgesOf` and `regTop` are the term's static analyses.

```lean
inductive RegRef | at (r : Nat) | range (r n : Nat)           -- R[A], R[A..A+B-1]
inductive Tgt    | next (k : Nat) | rel (base : Nat) (off : Int) | nextJmp  -- pc+k, jumpTo, donextjump
inductive Micro where
  | leaf   (wr : List (Nat × (List Value → Option Value)))   -- writes, a function of the read VALUES only
           (tgt : Tgt) (emit : List Value → String)
  | select (test : List Value → Option Bool) (t f : Micro)   -- guard; `none` = stuck (runtime error)
-- a program: reads declared once, statically, from w's fields alone
structure Op where
  rd  : List RegRef
  body : Micro

inductive Step : State → State → Prop
  | exec : p.fetch s.pc = some w → micro p w = some op →
           op.body.run (op.rd.flatMap (·.vals s)) s = some s' → Step s s'
```

Because the body receives `op.rd.flatMap (·.vals s)`, a *list of values*, and
never `s`, it cannot read outside the footprint. This is a property of its type,
so nothing has to be proved to get it. The same holds for the edges: all leaves
are enumerable, so `edges op := op.body.leaves.map (fun l => (l.tgt.eval pc, l.wrMask))`
is a syntactic traversal. TESTSET's two leaves with the same target (the
refinement in ROUND-1 §2) appear as two list entries, so "*some* edge with that
target" is literally the case.

**Core rules.**
- **L-B2 becomes definitional.** `step? p s := do let w ← p.fetch s.pc; let op ← micro p w; op.body.run (op.rd.vals s) s`,
  and `Step s s' ↔ step? s = some s'` is `⟨fun ⟨_,_,h⟩ => by simp [*], …⟩`,
  about 6 lines once, independent of the opcode count.
- **L-B1 becomes one structural induction on `Micro`.**
  `theorem Micro.footprint (m : Micro) (vs : List Value) (s t : State) (h : s.pc = t.pc ∧ s.out = t.out) : (m.run vs s).isNone ↔ (m.run vs t).isNone ∧ ∀ s', m.run vs s = some s' → ∃ e ∈ m.leaves.map (·.edge s.pc), (m.run vs t).map State.pc = some e.1 ∧ agreeOn e.2 s' t'' ∧ unchangedOutside e.2 …`
  Together with `agree op.rd s t → op.rd.vals s = op.rd.vals t` (one lemma about
  `RegRef.vals`), this gives L-B1 for every opcode. `reads w := mask op.rd` is
  derived, not maintained.
- **L-C1 (partial).** The combinators `select`, `leaf.write` and `leaf.tgt`
  correspond to a small fixed set of lvm.c macros: `ttisinteger`/`tvtype`
  tests, `setivalue`/`setobj2s` stores, `pc++`, `donextjump`,
  `dojump`. Prove one machine Hoare triple per macro instance shape. An arm's
  simulation is then the composition that follows the term's tree. The
  per-arm work becomes aligning a CFG against a tree, not reasoning about
  semantics.

**What it makes free.** The whole `bc-rule-fanout` cluster: every `step?_sound`
arm, every `step?_complete` arm and every `Step.sim` arm (75 cases, 8.5 lines
per rule on average). The `edgesOf`, `reads` and `regTop` entries also stop
being written by hand; `regTop` is the maximum over `rd` and `wr`. Adding the 11
bitwise opcodes would have been 11 `micro` lines (they are already one
`intArith` entry each), with 0 proof lines.

**What it costs.**
- About 150 to 250 lines of setup: `Micro`, `run`, `leaves`, the footprint
  induction, and `vals`/`mask`.
- The TCB changes shape. The trusted transcription of lvm.c becomes a table of
  `micro` terms instead of an inductive family. That is arguably easier to
  review (one screen per opcode family), but it has to be re-reviewed once.
- Keeping the current `Step` would need a one-time equivalence proof of 27
  arms. That is a one-off cost, but it counts against R1 compression. The
  recommendation is to redefine `Step` instead.
- What gets harder: rules whose register footprint depends on a *value* rather
  than on the instruction word. `CALL` with `B = 0` (multiple results) and
  later `VARARG` are like this. They need a `Micro` constructor for
  value-dependent ranges, and the footprint theorem weakens there (the
  "applicative" part breaks and "monadic" appears; see Mokhov et al.). F1 and
  H1–H4 are not affected.
- `Supported`'s `edgesOf` currently also encodes *admission* side conditions
  (`LOADK` only of int/bool/nil). Those move into `micro p w = none`.

**Theories.**
- *Known*: selective applicative functors. Their static analysis gives an
  under- and over-approximation of the effects of a computation with
  conditional branches, which is exactly "read set, and the edges with their
  write sets". A. Mokhov, G. Lukyanov, S. Marlow, J. Dimino, "Selective
  Applicative Functors", ICFP 2019 (PACMPL 3). Also: McBride and Paterson,
  "Applicative programming with effects", JFP 18(1), 2008. Applicatives have
  a static effect structure; monads do not.
- *Known*: ISA specifications as a single monadic term with several
  interpretations (a concrete executor, a footprint analysis, symbolic
  execution). This is Sail's own design: Armstrong et al., "ISA semantics for
  ARMv8-A, RISC-V, and CHERI-MIPS", POPL 2019 **[check the exact title]**.
  The "one term, many interpreters" pattern is also Carette, Kiselyov and
  Shan, "Finally tagless, partially evaluated", JFP 19(5), 2009.
- *Known, distant*: data provenance in databases. The read set is the
  *where-provenance* of the successor state (Buneman, Khanna, Tan, "Why and
  Where: A Characterization of Data Provenance", ICDT 2001). Provenance
  computed by construction, instead of verified afterwards, is the move here.

**Pilot.**
- **H1.** Change `micro`'s `LOADK` guard to admit `Const.str`: 1 line, 0 proof
  lines. `Supported` is admitted automatically, because edges are derived.
- **H2.** `CONCAT A B`: `rd := [range A B]`, then a leaf writing
  `A ↦ concatVals` (a right fold over the values, `none` if any is neither a
  string nor an int, with ints rendered by `%d`) to `next 1`. That is about 4
  spec lines and 0 proof lines. `RegRef.range` has to be in the setup already;
  it is also needed for `LOADNIL` and `CALL`.
- **H3.** `LEN` on a string: 3 spec lines.
- **H4.** Extend `cmpRR`'s `test` with the string case (a `strLt`/`strLe`
  byte-lexicographic comparison): 2 lines.
- **R1.** Rewrite 27 constructors as `micro` entries and delete `Exec.lean`'s
  arms and `Step.sim`'s arms. Expected: 596 + 261 lines become about 200 setup
  lines plus about 60 table lines.
- **Smallest build.** `Micro` with `leaf`/`select`, `run`, `leaves`, and the
  footprint theorem, instantiated for `MOVE`, `arith` and `TESTSET` (the
  duplicate-target case). Then check that the generic L-B1 statement from
  ROUND-1 follows for those three with no opcode-specific lines.

**Seed.** *Vishnuite* and *deify* (one deity, many avatars: one semantics,
27 incarnations), plus *abridge* and *undiluted* (one undiluted source
instead of five diluted copies).

## 2. Dialysis-membrane frames: rules typed over their own footprint, globalised by one frame rule

**Idea.** Keep hand-written inductive rules, but change the *state they are
written over*. A rule does not see a `State`. It sees a **cloister**: a
dependent record over exactly the registers the instruction may touch. The
membrane has three kinds of cell:

- `rd` cells, which carry a value in and out;
- `wo` (write-only) cells, which carry no value in, only a hole, and a value out;
- everything else, which is absent: it is not in the type at all.

The global `Step` is obtained by one *frame* construction: cut the cloister
out of the state (dialyse), run the local rule, and splice the result back. So
the rules stay readable inductives in the lvm.c-transcription style, and the
footprint becomes a typing fact.

```lean
structure Cloister (R W : List Nat) where      -- R: read regs, W: write-only regs
  inp  : Fin R.length → Value                  -- no field exists for anything else
  outW : Fin (R ++ W).length → Option Value    -- written cells (by position)

def fp (p : Proto) (w : Word) : Option (List Nat × List Nat)   -- a function of w and K only
inductive LStep (p) (w) : (R W) → Cloister R W → Nat → Cloister R W → Nat → Prop  -- pc-relative
  | move : fp p w = some ([w.b],[w.a]) → LStep … ⟨![v]⟩ pc ⟨writes [a ↦ v]⟩ (pc+1)
  …
def Step s s' := ∃ w R W c c' pc', p.fetch s.pc = some w ∧ fp p w = some (R,W) ∧
  LStep p w R W (s.dialyse R) s.pc c' pc' ∧ s' = (s.splice c').goto pc'
```

**Core rules.**
- **L-B1 becomes the frame theorem**, proved once:
  `agree R s t → s.pc = t.pc → (Step s s' ↔ ∃ t', Step t t' ∧ s'.pc = t'.pc ∧ agree (W ∪ R) s' t' ∧ ∀ r ∉ written, s'.regs r = s.regs r)`.
  The proof is "`s.dialyse R = t.dialyse R`, because the dialysed record only
  contains `R`". That is `funext` over `Fin R.length`, followed by rewriting.
  "Both stuck or both step" follows because the local premise is literally
  the same proposition for `s` and for `t`. This is O'Hearn's *safety
  monotonicity + frame property* for local actions, obtained by definition
  instead of by proof.
- **L-B2** does not follow for free here. Pair it with idea 1 (take
  `LStep := Micro.run`) or with idea 3's schema for the stepper. On its own,
  this idea attacks `Step.sim` only.
- **Definite-initialisation soundness.** Write-only cells are the *reason* a
  register can be undefined before an instruction and defined after it. The
  must-analysis `sweep` is `st[t] ⊇ (st[pc] ∩ keep) ∪ W`, where `W` is read off
  the cloister type. The analysis consumes `fp` and never contradicts it: one
  table, which *is* the rule's index, so it is not kept beside the relation.

**What it makes free.** All 27 `Step.sim` arms (the largest part of R1's 261
lines), and the `reads`/`edgesOf` write masks, which become projections of
`fp`. Adding CONCAT, whose footprint is the range `A..A+B-1`, costs no
simulation proof.

**What it costs.**
- The dependent-type setup: about 120 lines for `Cloister`, `dialyse`,
  `splice`, the splice/dialyse lens laws, and the frame theorem.
- Rules become a little noisier to read (`inp 0` instead of `s.regs w.b`).
  Notation (`R[b]` elaborating to a `Fin` index proved by `decide`) keeps it
  close to lvm.c.
- The one real difficulty: registers that are both read and written (FORLOOP
  reads `A..A+2` and writes `A`, `A+1`, `A+3`) need `rd` cells that are also
  in `W`. The type allows that, because `outW` spans `R ++ W`.
- `fp` must be a function of `w` and `K` only. That holds for F1 and H1–H4 but
  fails for multi-result `CALL` (see idea 1).

**Theories.**
- *Known*: C. Calcagno, P. O'Hearn, H. Yang, "Local Action and Abstract
  Separation Logic", LICS 2007. Local actions are exactly the functions that
  satisfy safety monotonicity and the frame property. Here the actions are
  *built* local, so both properties hold by construction.
- *Known, distant (databases)*: the view-update problem with a *constant
  complement*. An update through a view is well defined iff it leaves the
  complement fixed (F. Bancilhon, N. Spyratos, "Update Semantics of Relational
  Views", ACM TODS 6(4), 1981). `dialyse` and `splice` are a lens with a
  constant complement (the registers outside `R ∪ W`). The very well-behaved
  lens laws (Foster, Greenwald, Moore, Pierce, Schmitt, "Combinators for
  bidirectional tree transformations", TOPLAS 29(3), 2007: GetPut, PutGet,
  PutPut) are what the frame theorem uses, and they are proved once.
- *Novel, from biology*: a dialysis membrane is permeable by *class* (small
  solutes pass, proteins do not), not by instance. The analogue here is that
  permeability is set per instruction word and never per value. That is the
  side condition "`fp` depends on `w` only", which marks where the abstraction
  breaks (value-dependent footprints = active transport).

**Pilot.**
- **H1–H4.** Each rule is written over its cloister: `concat : fp = (range A B, [A])`,
  `len : ([B],[A])`, `ltStr`/`leStr : ([A,B],[])`. Simulation lines per case: 0.
- **R1.** Refactor `Step` to `LStep` plus the frame definition, then delete the
  27 `Step.sim` arms. The stepper arms remain unless this is combined with
  idea 1.
- **Smallest build.** `Cloister`, `dialyse`/`splice`, and their three lens laws,
  plus the frame theorem, instantiated for `MOVE`, `TESTSET` and
  `forloopAgain` (the 13-line exemplar from the census). Check the L-B1
  statement for them with 0 per-rule lines.

**Seed.** *Histodialytic* (dialysis, a membrane), *monastic* (the cloister:
the rule lives in a closed cell and sees nothing outside it), *permittee*
(permissions per cell: read, or write-only).

## 3. LL(1) rule grammars: `LuaSem` as an L-attributed grammar whose determinism is a decidable table check

**Idea.** The determinism cost is quadratic because rules that share a
construct (`whileT`/`whileF`/`whileX`, `ifT`/`ifElseif`/`ifElse`/`ifNone`,
`cons`/`stop`) are told apart only after inverting both derivations. In a
*grammar*, that problem has a 1968 name: LL(1). Rules are productions, a
rule's head is the construct, and rules that share a construct must be told
apart by a *lookahead*: a decidable tag on the outcome of the premise already
evaluated. For `while` that is "`v.isFalse`, then `sg = normal`". Put in
pretty-big-step form, every rule of `LuaSem` has the form "evaluate premises
left to right, threading inherited attributes (`ρ`, `o`); after each premise,
branch on a tag of its synthesised attribute (`v.isFalse`, `sg`, the value's
constructor)". This is an **L-attributed grammar**. The proposal is to
represent the rule system as data, `G : RuleSys`, with `LuaSem := Derives G`,
and to prove two generic theorems once for *every* LL(1) rule system.

```lean
structure Rule (Sort : Type) where
  head   : Sort → Option Key                 -- construct constructor (Exp.binop .concat, Stat.while_, …)
  prems  : List Premise                      -- sub-judgement on a subterm, with an attribute transformer
  look   : List (Tag × Nat)                   -- after premise i, its outcome must have tag t
  concl  : Attrs → Option Attrs               -- output attributes, a function of all premise outputs
def RuleSys.ll1 (G) : Bool :=   -- no two rules with the same head agree on all lookaheads at their first difference
  G.rules.pairs.all fun (r, r') => r.head ≠ r'.head ∨ r.distinguishedFrom r'
theorem Derives.functional (G) (h : G.ll1 = true) : Derives G j a b → Derives G j a c → b = c
theorem Derives.graph (G) : Derives G j a b ↔ ∃ n, G.run n j a = some b   -- G.run: the generic fuelled evaluator
```

**Core rules.**
- **L-A1 becomes `Derives.graph` plus `Derives.functional`**, each proved
  once, by induction over the *generic* derivation (not over Lua's
  constructs). Two things make them free:
  - *Determinism* for Lua becomes `Derives.functional luaG (by decide)`. The
    pairwise inversion becomes a Boolean check over pairs of rules with the
    same head, which the kernel evaluates.
  - The "*executable interpreter*" is not written for Lua at all: it is
    `luaG.run`. Its soundness and completeness are instances of
    `Derives.graph`.

  This is not "an interpreter with a separately proved soundness theorem":
  there is one generic evaluator for all rule systems, and no Lua-specific
  proof.
- **Loops without guessed intermediate states.** `whileT` recurses on the same
  construct with the updated attributes. The grammar allows a premise on the
  *same* syntax with new inherited attributes (the pretty-big-step "`while`
  continuation" rule). `Derives.graph` handles that with fuel, and
  `functional` with ordinary induction on the derivation height.

**What it makes free.** The whole `ast-construct-fanout` cluster: the
`execSound` arms (`while_` 19 lines, `if_` 16, `fornum` 15), the 50 arms of
`Eval.det`, the 53 arms of `ExecS.det`, and the future `ForIter`/`ExecBF`
arms. Each new construct costs one grammar entry, and the LL(1) check reruns
in the kernel. Abrupt completion (`whileX`, `repeatX`, `stop`) collapses into
one generic *abort propagation* production. With Charguéraud's
`abort`-rule design, the `X` variants do not need to be separate rules.

**What it costs.**
- The biggest setup of the five: `RuleSys`, `Derives`, `run`, the two generic
  theorems, and an attribute type that covers `Eval`, `EvalList`, `ExecS`,
  `ExecL`, `ExecBF`, `ExecB` and `ForIter`. That means a sum type of sorts and
  of attribute tuples. Estimate 400 to 600 lines. Mutual inductives become one
  indexed family `Derives G (j : Sort)`, which Lean handles better than
  mutual blocks.
- Readability of the trusted semantics: a rule table is less legible than
  inductive constructors. Mitigation: a `rule` macro that elaborates
  constructor-like syntax to `Rule` values, plus a generated "pretty"
  inductive that is proved equal to the table once, by `Iff.rfl` if the
  encoding is shallow enough.
- The dependence of `ExecBF`'s `jump` on `findLabel`/`jumpEnv`: `concl` and
  the attribute transformers are arbitrary functions, which the grammar
  permits.
- R2 compression needs either redefining `LuaSem` (a TCB change) or a
  one-time equivalence proof. Redefinition is recommended.

**Theories.**
- *Known (linguistics and compilers)*: D. Knuth, "Semantics of context-free
  languages", Math. Systems Theory 2(2), 1968: attribute grammars, with
  L-attributed grammars evaluable in one left-to-right pass. P. M. Lewis and
  R. E. Stearns, "Syntax-directed transduction", JACM 15(3), 1968, and Knuth,
  "Top-down syntax analysis", Acta Informatica 1, 1971 **[check]**: the LL(k)
  condition, a decidable disjointness of lookahead sets that makes a grammar
  unambiguous. Here unambiguity *is* determinism.
- *Known (PL)*: A. Charguéraud, "Pretty-Big-Step Semantics", ESOP 2013:
  intermediate outcome forms and a generic abort rule remove the duplication
  of premise prefixes across `T`/`F`/`X` rules. M. Bodin, P. Gardner, T.
  Jensen, A. Schmitt, "Skeletal Semantics and their Interpretations", POPL
  2019: a semantics as data (skeletons), with the relational and the
  executable semantics as two generic interpretations proved consistent once.
- *Novel*: using the LL(1) check as the determinism certificate of a big-step
  relation. The lookahead is on the synthesised attributes of earlier
  premises, not on input tokens. As far as I know **[check]**, skeletal
  semantics gives the interpretations but does not state determinism as a
  decidable grammar condition.

**Pilot.**
- **H1.** Add `Rule string : Exp.string s ⟶ .str s`: one entry, no lookahead.
- **H2.** `concat`: two premises, then lookahead on the *pair of value tags*
  (`str`/`int` × `str`/`int`), which gives one entry with a total `concl`
  that fails (`none`) on other tags. `ll1` is unaffected, because it is the
  only rule with head `binop .concat`.
- **H3.** `len`: one entry.
- **H4.** String `lt`/`le` is a *second* rule with head `binop .lt`. It is
  distinguished from the integer `cmp` rule by the value-tag lookahead
  (`int,int` vs `str,str`). `ll1` checks this, and that check is the H4
  determinism proof: 0 lines.
- Per H case, the expected cost is 2 to 5 table lines and 0 proof lines,
  instead of an interpreter arm plus a soundness arm plus determinism arms.
- **Smallest build.** `RuleSys`, `Derives`, and the two generic theorems for
  **expressions only** (`Eval`, 17 rules, pure, no mutual recursion). Show that
  `Eval.det` (part of R2) is `Derives.functional evalG (by decide)`, then
  extend to statements.

**Seed.** *Singsong* and *troubadourish* (metre, prosody, grammar), *Swabian*,
*Aguacateca* and *Goyana* (languages and dialects, hence grammars and
parsing), *philosophist* and *doli* (deciding intent unambiguously:
determinism as unambiguity).

## 4. Sand-dollar symmetry: machine arms as orbits under code relabelling, simulated once per orbit

**Idea.** L-C1 prices each of about 54 arms of `luaV_execute` separately. In
lvm.c the arms are *macro instantiations*: `op_arith(L, l_addi, luai_numadd)`,
`op_arithK`, `op_bitwise(L, l_band)`, `op_order(L, l_lti, …)`. So the compiled
arms of `ADD`, `SUB`, `MUL`, `BAND`, `BOR` and `BXOR` should be translated
copies of one another, up to (a) the address they sit at and (b) one ALU
instruction (`add` ↔ `sub` ↔ `mul` ↔ `and`). The Lean semantics already
quotients this symmetry (`Step.arith` plus `intArith`); the binary does not.
The proposal is a *group action* on arms, with the proof obligation per
*orbit*, not per opcode.

Like a sand dollar (Clypeastroida), which is a five-fold radial body around a
mouth, the dispatch loop is a ring. The dispatch head is the centre, each arm
is a petal from head to head, and petals of one family are rotations of each
other.

```lean
structure Relabel where
  shift : Int                                    -- arm translated in the text section
  subst : List (Instr × Instr)                   -- positional instruction substitutions (the ALU op)
def Relabel.apply (σ) (arm : List (Addr × Word)) : List (Addr × Word)
theorem ArmSim.transport
  (h : ArmSim r arm)                             -- head→head simulation of rule-instance r
  (hpic : arm.pcRelativeClosed)                  -- all control transfers PC-relative or to `head` (absolute)
  (hσ  : ∀ (i, i') ∈ σ.subst, Implements i f ∧ Implements i' f')   -- one-instruction lemma
  (hr  : r' = r.withOp f')                       -- the Lean rule instance with f' for f
  : ArmSim r' (σ.apply arm)
```

**Core rules.**
- **L-C1** becomes: *one simulation per orbit*, plus `ArmSim.transport`, which
  is proved once. The transport has two parts:
  - *relocation invariance* of the Sail RISC-V step: a PC-relative
    instruction at `a + Δ` behaves as at `a`, shifted. This is proved once
    over the decoder, because it is a property of the ISA and not of
    `luaV_execute`.
  - *substitution*: a straight-line block that differs in one ALU
    instruction, where the new instruction's result register is dead except
    for the `setivalue` store, simulates the rule with the substituted
    operation. That is a product-program argument: run both copies in
    lockstep, and they diverge only on the one register, which the store
    carries into `R[A]`.
- On the bytecode side the same quotient exists, via `intArith`/`intCmp`, so
  orbit members line up with one Lean constructor and one lookup-table entry
  each.

**What it makes free.**
- The forecast `a1-arm-sim` cluster, which shrinks from about 54 arm proofs to
  one per orbit. My guess **[check by the orbit classifier below]**:
  - `op_arith` rr for `ADD`/`SUB`/`MUL`: one orbit;
  - `op_arithK`: one;
  - `op_arithI` (`ADDI`): one;
  - bitwise rr, K and `SHRI`/`SHLI`: two to four;
  - the `MOD`/`IDIV` pair (which call `luaV_mod`/`luaV_idiv`): one or two;
  - order rr, order immediate (`LTI`, `LEI`, `GTI`, `GEI` via `op_orderI`),
    `EQK`/`EQI`: three or four;
  - `LOADTRUE`/`LOADFALSE`: one.

  That is about 15 to 20 orbits for 54 opcodes.
- The predecessor's per-site tables existed because nothing named the
  symmetry; this names it.

**What it costs.**
- Relocation invariance over the whole Sail decoder is a real theorem. Maybe
  150 lines if the decoder is uniform, much more if it is not.
- GCC may break the symmetry: tail merging (arms sharing a common epilogue,
  which is *good*, because then there is one petal root), different register
  allocation per arm (then `σ` must also rename registers, a larger but still
  finite group), or instruction scheduling that interleaves the ALU op
  differently (then transport fails for that arm, and it becomes its own
  orbit). The abstraction degrades gracefully: the cost is the number of
  orbits, which is never more than the number of arms.
- It does nothing for the metatheory clusters.

**Theories.**
- *Known (algebra)*: orbit counting under a group action (the
  Burnside/Cauchy–Frobenius lemma). The obligations are the orbits, and the
  stabiliser tells what one proof covers. Standard; for example Rotman,
  *An Introduction to the Theory of Groups*.
- *Known (physics, as a design principle)*: Noether's theorem (1918).
  Continuous symmetries give conserved quantities, so one computes in the
  quotient. The discrete analogue in verification is symmetry reduction in
  model checking (Emerson and Sistla, "Symmetry and model checking", FMSD
  9, 1996; Ip and Dill, "Better verification through symmetry", FMSD 9,
  1996). Here it is used as a *proof* quotient, not a state-space reduction.
- *Known (verification)*: product programs and relational verification
  (G. Barthe, J. M. Crespo, C. Kunz, "Relational verification using product
  programs", FM 2011), and translation validation (Pnueli, Siegel,
  Singerman, "Translation validation", TACAS 1998). The substitution half of
  the transport is a two-copy product.
- *Novel*: pricing a binary-level proof campaign by *orbits of a C
  macro-expansion group*.

**Pilot.**
- The A1 held-out arms are `ADD`, `EQI` and `FORLOOP`: three different
  families, so on the held-out cases the idea shows no saving. Say so
  honestly. The demonstration is instead: prove `ADD` normally, then obtain
  `SUB`, `MUL`, `BAND`, `BOR` and `BXOR` by `ArmSim.transport` and report
  the lines for those five (target: under 10 each, only the `Implements`
  instances).
- **Smallest build**, which is also the cheap check of the law:
  - a script that extracts each arm from the ELF between the jump-table
    targets, normalises PC-relative displacements, and computes the orbits
    under `add/sub/mul/and/or/xor` substitution;
  - the relocation lemma for the RV64 instructions that actually occur in
    one orbit.

  If the orbit count is above about 35, abandon the idea.

**Seed.** *Clypeastroida* (sand dollars: radial symmetry about a centre),
*cylindroidal*, *Tuamotu* (atolls, rings) and *moonset* (a cycle that
returns), for the dispatch loop as a ring of petals. *Dimension* and
*supermedial* (a quotient that cuts the dimension of the obligation space).
*Jibstay* (a single stay that holds the whole rig) for the one transport
theorem.

## 5. Exorcising ghosts: definite initialisation as flow-sensitive noninterference, proved by one unwinding theorem at both layers

**Idea.** `Fragment.lean` explains why definite initialisation is needed:
the frame holds whatever the stack held (stale values from
`luaL_requiref`/`VARARGPREP`), and `CALL` clobbers everything above its
results. These are *ghosts*: values the semantics pretends are `nil` but the
machine holds as garbage. The proof obligation "the ghosts are unobservable"
(`bcSemFrom_iff`, `cbcSem_iff`, plus every `Step.sim` arm) is a
**noninterference** statement. Label a register *High* where the
must-analysis says it is not definitely initialised, and *Low* otherwise. The
must-analysis `fixpoint` is then a *flow-sensitive security type system*, and
the program is secure iff no instruction reads High (`msub (reads w) st[pc]`).
Security folklore says NI for whole runs follows from per-step conditions by
one **unwinding theorem**. So the proof becomes the unwinding theorem, proved
once, and the per-step condition is exactly L-B1.

A second payoff is at the machine layer. At A1, `CALL` really clobbers the
stack above its results, and the Lean `Step` does not. Instead of making
every arm's simulation track what `print` leaves in the stack slots, let the
**representation relation be low-equivalence**: a machine state represents
`s` if it agrees with `s` on the Low registers, and High slots may hold
anything. The ghosts are exorcised: they are neither tracked nor proved about.

```lean
def LowEq (L : Nat) (s t : State) : Prop := s.pc = t.pc ∧ s.out = t.out ∧ ∀ r, testBit L r → s.regs r = t.regs r
-- the typing: Γ : Nat → Nat (pc ↦ Low mask) is the must-analysis post-fixpoint
structure Unwinding (Step : State → State → Prop) (Γ : Nat → Nat) : Prop where
  consistency : LowEq (Γ s.pc) s t → (Step s s' ↔ …) ∧ (Step s s' → Step t t' → LowEq (Γ s'.pc) s' t')   -- L-B1 with reads ⊆ Γ pc
  progressEq  : LowEq (Γ s.pc) s t → ((∃ s', Step s s') ↔ ∃ t', Step t t')                             -- stuck-sensitive
theorem unwinding_ni (U : Unwinding Step Γ) : LowEq (Γ 0) s₀ t₀ → (BcSemFrom s₀ out ↔ BcSemFrom t₀ out)
theorem havoc_ni     (U) : …  -- a step that also havocs High regs (the real CALL) is NI-equivalent to one that does not
```

**Core rules.**
- **L-B1** is the single hypothesis `Unwinding.consistency`, stated once over
  all opcodes. Discharge it by idea 1 or idea 2 (then 0 per rule), or, in the
  incumbent style, by the existing `Step.sim` arms (then this idea only
  removes the lifting proofs).
- `bcSemFrom_iff` and `cbcSem_iff` become corollaries: `unwinding_ni` for the
  entry state, and `havoc_ni` for what a call leaves.
- **Kildall correctness.** "The post-fixpoint of `sweep` is a well-typing" is
  proved once for any transfer function of the form
  `(st ∩ keep) ∪ written`, by the standard dataflow argument. It is
  independent of opcodes as long as `written` comes from the rule's edges.
- **L-C1 is weakened.** The machine arm must reach a state that is
  *LowEq-related* to `s'`, not *equal* on all 256 registers. For arms that
  touch the stack (`CALL`, and later `CONCAT`, which uses the stack top as
  scratch in `luaV_concat`) this removes all reasoning about slots above the
  results. Note: `luaV_concat` really does use `L->top` scratch space
  **[check against lvm.c]**, which makes this directly relevant to H2 at A1.

**What it makes free.**
- The definite-initialisation lifting in `FragmentSound.lean`: the
  `bcSemFrom_iff`/`cbcSem_iff` proofs, whose size I have not seen, and any
  induction over `Steps` that re-proves NI.
- At A1: the per-arm clauses about stale or clobbered stack cells.

Honestly: on its own this idea does *not* remove the per-rule `Step.sim` arms.
It turns them into the one named hypothesis that ideas 1 and 2 discharge
generically. Its value is as the glue that makes the footprint pay off twice,
once at the bytecode layer and once at the machine layer.

**What it costs.**
- About 150 lines: `LowEq`, `Unwinding`, `unwinding_ni` (an induction on
  `Steps` with the progress clause, which is needed because stuckness is
  observable: no rule means no behaviour), `havoc_ni`, and the Kildall lemma.
- It must be the *termination- and progress-sensitive* variant, which is
  stronger than the textbook termination-insensitive NI. That is what makes
  the "both stuck or both step" clause of L-B1 essential rather than
  incidental.
- What gets harder: if a later fragment *declassifies* (reads a stale
  register on purpose, as `VARARG` might), the typing needs a declassification
  rule.

**Theories.**
- *Known (security)*: J. Goguen and J. Meseguer, "Security Policies and
  Security Models", IEEE S&P 1982 (noninterference), and "Unwinding and
  Inference Control", IEEE S&P 1984. J. Rushby, "Noninterference, Transitivity,
  and Channel-Control Security Policies", SRI tech report CSL-92-2, 1992: the
  unwinding theorem from *output consistency*, *step consistency* and *local
  respect*.
- *Known (type systems)*: S. Hunt and D. Sands, "On Flow-Sensitive Security
  Types", POPL 2006. Flow-sensitive typings are the fixpoints of a dataflow
  analysis, so the must-init analysis is one.
- *Known (compilers)*: G. Kildall, "A Unified Approach to Global Program
  Optimization", POPL 1973: soundness of monotone-framework post-fixpoints.
- *Known (concurrency and security)*: possibilistic NI for nondeterministic
  systems (D. McCullough, "Specifications for Multi-Level Security and a
  Hook-Up Property", IEEE S&P 1987 **[check]**). The havocking `CALL` is a
  nondeterministic step, so `havoc_ni` is an instance of that.
- *Novel*: using low-equivalence *as the representation relation* of a
  machine-level simulation, so that the definite-initialisation typing is
  also what licenses the binary to keep garbage.

**Pilot.**
- **H1–H4.** Every H rule's `reads` must be inside `Γ pc`:
  - CONCAT reads `A..A+B-1`, which luac always defines just before, so it is
    admitted by the existing analysis;
  - LEN and the string `LT`/`LE` read one or two registers.

  With idea 1 or 2 underneath, the consistency hypothesis is free, and so are
  NI and the lifting: 0 lines per case.
- **R1.** Replace the lifting part of `FragmentSound.lean` with
  `unwinding_ni` and `havoc_ni` instantiated at `Γ := fixpoint …`.
- **Smallest build.** `LowEq`, `Unwinding`, and `unwinding_ni` over an
  *abstract* `Step`, instantiated with the current `Step` and its existing
  `Step.sim` as `consistency`. Show that `bcSemFrom_iff` drops out as a
  one-line corollary. Then, if A0.6's decoders land, state the LowEq
  representation for the `CALL` arm.

**Seed.** *Exorcism* (ghost values in stale registers), *pseudochina* (a
counterfeit that looks like the real thing: garbage that looks like a
value), *suspectful* (a High label is suspicion), *broke*, *terribleness* and
*unsufficience* (the stuck, the error, what is not enough to be observed).

## How they compose

The five ideas stack rather than compete:

- **Idea 1**, or idea 2 plus idea 1's stepper, removes `bc-rule-fanout`.
- **Idea 3** removes `ast-construct-fanout`.
- **Idea 5** reuses the footprint from idea 1 or 2 as the unwinding hypothesis,
  at the bytecode layer and again as the machine representation relation.
- **Idea 4** cuts the remaining A1 arms to one per orbit, and idea 1's
  combinator structure gives each orbit representative a tree to align
  against.

If only one can be built for the bake-off, build **idea 1**. It has the
smallest setup that zeroes all three per-rule bytecode theorems, and H1–H4
become table lines. **Idea 3** is the highest-payoff bet for the source side,
but also the largest setup.
