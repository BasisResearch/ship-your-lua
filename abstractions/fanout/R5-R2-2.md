## Idea 1. JoinCut: cut the proof where the machine joins, so the suffix after a φ runs once on a symbolic Boolean

**Acts on:**
- **R5-R1-3 #A** (`at_run_fork`, answer-atom trees): **(a) extend** it from trees to DAGs with joins.
- **R5-R1-5 #2** (`relOf`): **(b) combine**, as the guard evaluator.
- **R5-R1-1 #3**: **(c) object** to its FORPREP coupling forecast (fact 2).
- **R5-R1-5 #1** (`OTree`, `mtree_run`): **(c) object**. A deep embedding is not needed for the φ, which R5-R1-5 #1 handles inside `OB.ite` at the price of `mtree_run`'s ≈200 lines.

### The idea

All five round-1 variants of M-tree split at forks. None of them **merges** at joins.

Both step-signed loop arms compile the kernel's `if lt 0 st then R x y else R y x` to the same machine shape:
1. fork on the step answer;
2. on each side, one compare call and one idiom that leaves a 0/1 value in a register;
3. a **join pc**;
4. one branch on that register;
5. the shared store/dispatch suffix.

A proof that forks at step 1 and never merges runs steps 3–5 **twice**. That is 4 leaves, half of them re-running the same stores.

JoinCut makes the join a **Floyd cut point**:
- The proof states, once, a named pre-structure at the join pc:

  ```
  structure JoinPre (b : Bool) (c : Config) : Prop where
    pc   : c.pc = joinPc            -- literal, from the CFG
    flag : c.reg rJ = b.toNat        -- the joined register (a5 / a4)
    kept : Kept c                    -- the suffix's footprint facts (s5/a5 base, s6 payload, …)
  ```

- It proves the suffix **once**, from any `JoinPre b c` and **with `b` symbolic**. The suffix's own fork (`bnez a5` / `beqz a4`) then splits on `b`, which gives 2 cases, not on the atoms.
- Each side before the join discharges `JoinPre (ιᵢ (code Rᵢ o₂)) c`. This is a short run whose only content is the idiom value.
- The kernel agreement is ONE closed table over the two atoms.

### Core rules

| law | rule (proved once) | decided at a use site by |
|---|---|---|
| L5-fork + merge | **`join_cut`**: `(∀ b c, JoinPre b c → wp suffix (Φ b) c)` + each side's run ending in `JoinPre (gᵢ o) c` ⇒ `wp (pre ; fork o₁ ; sideᵢ ; suffix) (Φ (g o₁ o₂))`. Stated once over `Wp : MachWP M` (`wp_segW`, `VsaIris/MachWP.lean`), so it serves total and partial WP | **syntactic**: join pcs are closed CFG data (a pc inside the float region with ≥ 2 predecessors in it). `Kept` is the suffix segment's footprint, read off its generated `SegSt` statement |
| L5-idiom | the side's value is `relOf Rᵢ ιᵢ o₂ : Bool` (R5-R1-5 #2): `ι.eval (R.S x y) = relOf R ι (F64.compare x y)` holds by `rfl` after unfolding `Ledf2.S`/`Gedf2.S` (which **are** `match F64.compare a b`, `Spec.lean`). `Eqdf2.S` needs `F64.eq`'s one-line unfolding | **computation** on 4 closed points |
| atoms | **`atom_of_pair`**: one atom per *ordered pair of argument terms*; two calls on syntactically equal pairs share it. A reversed pair is folded by `F64.compare_swap` before `generalize` | **syntactic** term equality of the call-node arguments; no search. Facts 1–2 show FORLOOP and FORPREP never need the swap on the machine side, only on the kernel side |
| kernel side | the kernel's float clause, rewritten by a fixed simp set (`lt_eq_model`, `le_eq_model`, `compare_swap`), is a closed `K : Option Ordering → Option Ordering → Bool` | rewriting with a fixed lemma list |
| agreement | **`phi_table`**: `∀ o₁ o₂, mJoin o₁ o₂ = K o₁ o₂` | **`decide`**, 16 points. Checked in Python for both arms (0 mismatches) |

**Symbolic data.** Payloads (`st`, `idx′ = Adddf3.S st idx`, `limit`, `init`) stay opaque. They appear only in the generalised atoms and in the stored words of the shared suffix, which runs once.

**Search.** None. Polarity is never tried: each side's fork is decided by `relOf` on the atom's case, and the post-join fork by `cases b`.

### What it makes free

- **FORLOOP.**
  - The 4 leaves become 2. The stores `0x8001e1b0–e1b8` and the tail `c240` run once, not once per step-sign side.
  - The 8.3k replay and 10.3k polarity heartbeats go, as in round 1.
  - It also removes **the duplicate suffix replay that round 1's trees keep**. FORLOOP's tail is measured at ≈11k for 4 tails (R5-R1-4 #B's forecast). Half of that goes.
- **FORPREP** (held out).
  - The same table, plus a second kind of join: the three coercion joins of idea 2.
  - The 2-atom table replaces R5-R1-2 #A2's 3-atom, 64-point forecast. `__eqdf2(step, 0)` and `__gedf2(step, 0)` are ONE atom.
- **Any arm whose kernel has `if c then bool₁ else bool₂`**, which GCC compiles to a value join. A CFG census over the 33 fields should count them; this round checked only the two FOR arms.

### What it costs

- **Setup.**
  - `JoinPre` (named, as CLAUDE.md requires for new predicates) and `join_cut`: ≈40 lines over `MachWP`.
  - `phi_table` per arm is one line of `decide`, plus the kernel rewrite list.
- **Harder.**
  - `Kept` must hold on **both** sides. It is the suffix footprint minus the joined register.
  - On FORLOOP, side 2 (`0x8001edf0`) leaves `a0`, `a1` different from side 1. That is harmless only if the suffix does not read them. The generated segment's statement says what it reads, so this is checkable, but it must be checked per join.
  - A join where the sides also differ in a *live* register needs `JoinPre` to carry that register as a second Bool or word. That is still one structure, but with more fields.

### Theories

- **SSA φ-functions** (known; Cytron, Ferrante, Rosen, Wegman, Zadeck, "Efficiently computing static single assignment form and the control dependence graph", TOPLAS 13(4), 1991). The join register *is* a φ of two idiom values. The proof works on the φ, not on the paths.
- **Floyd's cut points** (known; Floyd, "Assigning meanings to programs", 1967). A cut point at every join keeps proofs linear in blocks.
- **Stream confluences in hydrology** (Strahler stream order, Strahler, *Trans. AGU* 38, 1957; known). Downstream of a confluence, flow is measured once, whatever the tributary. Using this to pick proof cut points is **novel**.

### Pilot

- **Refactor FORLOOP.**
  - The prefix runs to `__gedf2(st, 0)`.
  - `cases o₁` decides side 1 or side 2 by `relOf`.
  - Each side runs to `JoinPre` at `0x8001e194`.
  - `join_cut` with the suffix once, then `phi_table` by `decide`.
  - Target: ≤ 8 lines with views (idea 2), and ≤ 30k heartbeats against 59.1k. The measured gain is 18.6k (round 1) plus half the tail.
- **FORPREP** (held out): two φ-tables (step sign, then bound), and the coercion joins of idea 2.
- **LT** (held out): measure whether LT's float paths contain value joins. If LT has none, JoinCut reduces to R5-R1-3 #A there. That is the control.
- **SUB** (held out): no compare atoms, so JoinCut is idle. Also a control.
- **Level (b):** none.
- **Smallest thing to build:** `JoinPre`, `join_cut` over `MachWP`, and the 16-point `phi_table` for FORLOOP as a closed `decide` file (it needs no machine at all), then the FORLOOP refactor.

### Seed

`CC` inside `n71CCG67V`: two equal letters (two compare calls) entering one `G` (a gate, the join), with `7…7` on either side (the two sides mirror each other around the join, as `R x y` mirrors `R y x`).

## Idea 2. Join-census views: per-port coercion views where the machine re-joins, pair classes where it tail-duplicates

**Acts on:** M-view, i.e. R5-R1-2 #A4 (`readPorts`, `forprepK_class`), R5-R1-4 #C (shape tables), R5-R1-3 #A (A0 `kernel_skel`, 216 rows for FORLOOP) and R5-R1-5 #5 (`class_cover`).
- **(c) object:** for FORPREP, a class table over shape *tuples* is the wrong object (facts 3, 5).
- **(a) extend:** R5-R1-2 #A4's generic `readPorts` becomes a generic `coercePorts`.

### The idea

All four round-1 M-view variants enumerate **joint** classes: tuples of head constructors per combinator.

That is right where GCC tail-duplicated per tag pair. SUB (fact 4) has one machine block per pair: `(flt, flt)`, `(flt, int)` and `(int, flt)` each run their own `__floatdidf`/`__subdf3` and reach dispatch separately. There, one class is one machine path. Round 1 is right for SUB.

It is wrong where the machine **re-joins after each register**. FORPREP's float path (fact 3) coerces limit, step and init in three sequential blocks. Each block is either:
- tag 19, so load the payload into a stack slot; or
- call `luaV_tonumber_` with that slot, check `a0 = 1`, and jump back.

The kernel is `match l.tonumber?, st.tonumber?, i.tonumber?`, which is a product as well.

A tuple table has:
- 27 − 3 = 24 shape tuples in the float branch (`{flt, int, str}³`, minus the `(int, ·, int)` integer branch);
- each `str` further split by `str2number`'s int/float outcome;
- error tuples.

The machine has 2³ = 8 paths and **one** callee summary used 3 times.

So the view should be **per port**, composed through the joins (idea 1's cut points). Which shape to use is not a design choice per arm. It is **read off the CFG**: does the float region have a join pc after each port's coercion block?

### Core rules

| law | rule (proved once) | decided at a use site by |
|---|---|---|
| L5-read′ (per port) | **`PortNum`**, a named structure: `slot : bytes c (sp + off) = x`, `num : (s.regs r).bind Value.tonumber? = some (.flt (F64.toModel x) n)`. **`portNum_inline`**: tag 19 ⇒ `PortNum` with `x` = the payload. **`portNum_callee`**: the `luaV_tonumber_` summary with `a0 = 1` ⇒ `PortNum` | **syntactic**: which of the two segments ran is the side of the port's own tag fork. The callee summary is keyed by entry pc `0x8001ab58` (existing summary mechanism) |
| L5-read′ (composition) | **`coercePorts`**: for a list of ports `[(r₁, off₁), …]` and a run through their blocks with joins between them, the post-state has `PortNum` for each, and the kernel's `match tonumber?…` reduces to its `some (.flt …)` branch | **syntactic**, by induction over the literal port list. **Symbolic data.** `x` is opaque. The callee summary relates it to `tonumber?` without inspecting it. String parsing sits behind the existing `Str2dFrom` premise inside `luaV_tonumber_`'s summary.

**Search.** None.

### Theories

- **Lossless-join decomposition in relational databases** (known; Heath, "Unacceptable file operations in a relational database", SIGFIDET 1971; Rissanen, 1977). A relation that is the join of its projections should be stored, and reasoned about, as the projections. FORPREP's class relation is the join of three per-port projections.

## Idea 3. Width-observed margin: read round-to-odd's side condition off the machine's normalised width, not off `log2` of the exact value

**Acts on:** M-odd, i.e. R5-R1-5 #3 (R3d), R5-R1-1 #1 (`round_odd`, `cancel_le_one`), R5-R1-3 #C (C1 `round_congr`), R5-R1-4 #D (`stamp_shl`, `rne_of_stamp`) and R5-R1-2 #A1 (`shr_ro`).
- **(a) extend:** replace the side condition.
- **(c) object** to where they put the hard work, at the use sites.

### The idea

Every round-1 M-odd variant states the hand-off with a side condition on the **exact** value's magnitude:
- R1-1: `e + k + 2 ≤ target n e`;
- R1-3: `k + 1 ≤ (target n e − e).toNat`;
- R1-5: `2 ≤ j` with `j = T − e`;
- R1-2: `2 ≤ s`.

At a use site, `n` is the symbolic exact aligned sum `A·2^k ± B`. Discharging the condition needs `Nat.log2` bounds on a symbolic sum. R5-R1-1 #1 calls these "the hard ones".

My checks (fact 8) show a sharper rule. Its hypothesis is about the **rto'd** value, the one the machine holds:

> **`round_rto_wide`**: `2^54 ≤ rto n k → F64.round s (rto n k) (e + k) false false = F64.round s n e false false`, for every `e : Int` (subnormal targets included). Checked 0/100k bad; just below `2^54` it fails 48,670/100k.

The proof is short. `2^54 ≤ m` gives `log2 m ≥ 54`, so `target m (e+k) − (e+k) ≥ 2`. That is margin 2, the Boldo–Melquiond bound. `target` is invariant because `log2 (rto n k) = log2 n − k` once `n ≥ 2^(k+1)`.

`2^54 ≤ m` is not a fact about the exact value. It is a fact the **machine tests**. soft-fp's pre-round mantissa sits in `[2^55, 2^56)` after normalisation, and at worst `[2^54, 2^55)` after a one-bit cancellation. The path's own guard (the bit-55/56 test, or the clz result) supplies it.

`log2` then appears only inside the proof of `round_rto_wide`, never at a use site.

### Core rules

Each is one proved lemma over `Nat`, with `2^k` symbolic.

| # | rule | checked | decided at a use site by |
|---|---|---|---|
| W1 | `round_rto_wide` (above) | 0 / 100k | rewrite. Side condition `2^54 ≤ m`, where `m` is the machine's pre-round mantissa: the **path guard** hypothesis, closed by `omega` with literal powers **[check: `omega` on `2^54` literals versus numerals; state the constants as numerals if needed]** |
| W2 | `round_scale`: `round s (m <<< j) (e − j) ff = round s m e ff` | 0 bad by value | rewrite. This undoes soft-fp's normalising left shift. Needs `finish = packFin` below `2^53` (one line) |
| W3 | `rto_add_even`, `rto_sub_even` (R5-R1-2 #A1, R5-R1-5 R3c) | 0 bad; odd `A` breaks | rewrite; `2 ∣ A` from `A = f <<< 3` |
| W4 | `rto_lt`: `B < 2^w → 1 ≤ k < w → rto B k < 2^(w−k)`. Corollary **`cancel_wide`**: `2^55 ≤ A < 2^56`, `B < 2^56`, `2 ≤ k` ⇒ `2^54 ≤ A − rto B k` | 0 / 200k | `omega` on literal powers after W4. This **supplies W1's side condition** on the effective-subtract path with `k ≥ 2`, which the machine does not test |
| W5 | `rto_exact`: `2^k ∣ B → rto B k = B / 2^k` | — | `B = f <<< 3`, `k ≤ 3`: divisibility from literals |
| W6 | `rto_rto` (carry SRS by 1) | 0 / 100k | rewrite |

So the regimes are:
- **`k ≤ 3`:** exact by W5. Then W2 and the existing `roundExact` apply, with no margin needed.
- **`k ≥ 2`, effective subtract:** W4 gives `≥ 2^54`, then W1.
- **Effective add:** `≥ 2^55` already, then W1 (and W6 on carry).
- **`k ≥ 57`:** R5-R1-4 #D's `rto_big`.

Every use-site side condition is a literal-power linear fact. **No `Nat.log2` on a symbolic value at any use site. No search.**

### What it makes free

- R5-R1-1 #1's `cancel_le_one` and `log2_odd` at use sites, and R5-R1-3 #C's `target − e ≥ d + 2` derivations: replaced by W4's literal bound.
- **The 6 inlined round sites of `__adddf3` and the 5 of `__subdf3`.** Each reaches W1 with the guard that the machine branched on there, so the per-site work is matching, not arithmetic.
- **`__floatdidf`** (1 sticky): `|i| < 2^64` normalised by clz to bit 55 gives `≥ 2^55`, then W1.

### What it costs

- **Setup.** W1 is the deep one: ≈60 lines (`target` invariance plus the margin-2 `shr` agreement). W2–W6: ≈60 lines.
- **Harder.**
  - The rule is stated at precision 53 with "54". `__muldf3`/`__divdf3` reach W1 only after idea 4's stages.
  - Which machine guard proves `2^54 ≤ m` on each path must be **named per path**. If the lifted `F` does not expose the pre-round mantissa as a node, the guard has no syntactic handle. This is the same generator-cut prerequisite as all of M-odd. W1 does not remove it.

### Theories

- **Round-to-odd** (known; Boldo & Melquiond, *IEEE Trans. Computers* 57(4), 2008). W1 is their theorem with the margin moved onto the observed value.
- **State observers in control theory** (known; Luenberger, "Observing the state of a linear system", *IEEE Trans. Mil. Electron.* 8, 1964). Estimate a hidden state (here `log2` of the exact sum) from the measured output (the machine's normalisation test), instead of computing it. Using this to place proof side conditions is **novel**.
- **Sterbenz's lemma and cancellation bounds** (known; Sterbenz, *Floating-Point Computation*, 1974). W4 is the one-bit-loss bound in a linear form.

### Pilot

- **`__adddf3` (held out):** the finite × finite region. Count use-site side goals not closed by guard + `omega`; the target is 0.
- **`__subdf3` (held out):** the same rules. Its two `__clzdi2` sites (fact 6) each need the clz summary `63 − log2` (idea 4's E3) to state the guard.
- **Arms:** none.
- **Smallest thing to build:** W1 in `Nat`/`F64` alone, stated as above. Go/no-go: W1 under 100 lines at the default budget.
- **Cheap falsifier first:** a `decide` over a 5-bit `F64.round` analogue (parametrise `target` by `p`). `∀ n < 2^10, k < 4, e ∈ [−8, 8], 2^(p+1) ≤ rto n k → …`, closed. I checked the same in Python at p = 5 (0 bad).

### Seed

`00` in `vb00rp` is two zero bits: the margin of 2 that must sit between the jam and the rounding position. `56` in `Dz56v6i` is the semiraw width, the place the margin is read from.

## Idea 4. Soft-int certificates: `__muldf3`/`__divdf3` are not free riders of round-to-odd

**Acts on:**
- R5-R1-1 #1 §4: "`__muldf3`/`__divdf3` … the same `round_odd` applies once the product's low half is collapsed".
- R5-R1-3 #C: "`__muldf3`: one derivation; `__divdf3`: C0".
- R5-R1-5 #3: "That is the 58 stage sites … under 6 laws".
- R5-R1-2 #A1: "the same `shr_ro`".

All are **(c) objected to** with a hidden cost (fact 7), then **(d)** a stage kind none of round 1 named.

### The idea

On rv64i there is no `mul` or `div` instruction.
- `__muldf3` builds the 106-bit product from **4 `__muldi3` calls** on 32-bit halves.
- `__divdf3` runs `udiv_qrnnd`'s C fallback: per half-word digit, a `__udivdi3` estimate, a `__umoddi3` remainder, a `__muldi3` correction product, and up to two corrections. It adds two class jump tables.

So before any rounding law applies, there are two **exact-arithmetic** stages, each at least as large as `round_odd`:
- **mul:** "the 4-partial-product assembly with carries is `u·v` as a (hi, lo) pair";
- **div:** "the two-digit `udiv_qrnnd` returns `q, r` with `n = q·d + r`, `r < d`". This is Knuth's Algorithm D theorem; it needs the divisor normalised (top bit set).

M-odd is silent on both. This changes the cost forecast for MUL, MULK, DIV, DIVK, IDIV, IDIVK, MOD, MODK and POW, the largest group of the 33 fields. It does not change the held-out pilot, which uses add/sub only.

The new abstraction is a **certificate stage**. Do not re-derive the algorithm's correctness from the code path. State its output relation (the certificate) and prove one generic lemma that the relation determines the answer:

```
euclid_cert : q * d + r = n → r < d → q = n / d ∧ r = n % d       -- [recall: core `Nat.div_mod_unique`; check name]
ppmm_cert   : hi * 2^64 + lo = u * v → lo < 2^64 → hi = u * v / 2^64 ∧ lo = u * v % 2^64
```

Then the per-routine obligation is the certificate, i.e. the algorithm's invariant at its exit. That is proved once per *algorithm*: `umul_ppmm`'s C fallback, and `udiv_qrnnd`'s.

The sticky of division is `r ≠ 0`. With `euclid_cert` it becomes `n % d ≠ 0`, so `F64.divCore`'s `st` and W1 (idea 3) apply.

### Core rules

| rule | statement | decided at a use site by |
|---|---|---|
| E1 `ppmm_assemble` | the 4 `Muldi3.S` products of halves (each `< 2^64`, so no wrap), summed with the two carry tests, give `(u·v / 2^64, u·v % 2^64)` | once, over `Nat`, by distributivity with the four products as atoms. At sites: syntactic match of the 4-call sequence (closed) |
| E2 `qrnnd_cert` | the C-fallback `udiv_qrnnd` on `n1 < d`, `2^63 ≤ d` returns `q, r` with `n1·2^64 + n0 = q·d + r ∧ r < d` | once (Knuth Theorem B: `q̂ − 2 ≤ q ≤ q̂`). Side conditions `n1 < d`, `2^63 ≤ d` come from soft-fp's normalisation guard: literal `omega` |
| E3 `clzdi2_spec` | `x ≠ 0 → Clzdi2.S x = 63 − log2 x` | once; shared by add (1 site), sub (2), mul (2), div (2) and floatdidf. Fact 6 shows `clz` is a callee in all of them, so this is one more `SoftFloatSpec`-style field, not an inlined stage |
| E4 `euclid_cert`, `ppmm_cert` | as above | rewrite |

**Symbolic data.** All operands symbolic. The certificates are equations between `Nat` atoms. The product `u·v` is the only nonlinear term, and it is never handed to `omega`.

**Search.** None.

### What it makes free

- The `__muldf3`/`__divdf3` cores, *after* their level (a), which does not exist yet (`SoftFloatSpec` has no `muldf3`/`divdf3` field).
- The soft-int calls reuse the `Muldi3Spec`/`DivSpec` batteries. CLAUDE.md lists them "here (WHILE addresses)", so they must be regenerated at the Lua ELF's addresses `0x8002f6c8`, `0x8002f734`, `0x8002f77c`.

### What it costs

- E2 is real work: ≈100–150 lines, the two-correction bound.
- E1 is ≈40 lines.
- The jump tables (`jr a4`/`jr a5`) need level (a) support for indirect jumps over a closed table. **[check: whether `gen_lua_fn.py` handles `jr` into a table]**
- **What gets harder:** the forecast. MUL-like and DIV-like arms are blocked on two more premises (`Muldf3`, `Divdf3`) and on E1–E2, not on M-odd alone.

### Theories

- **Knuth's Algorithm D** (known; Knuth, *TAOCP* Vol. 2, §4.3.1, Theorem B).
- **Certifying algorithms** (known; McConnell, Mehlhorn, Näher & Schweitzer, "Certifying algorithms", *Computer Science Review* 5(2), 2011). Check a witness relation, not the algorithm.
- **Casting out nines** (known; Fibonacci, *Liber Abaci*, 1202, from earlier Indian and Arabic practice). A product is checked by a cheap invariant of its digits, not recomputed. Here the "nines" are the Euclid relation.

### Pilot

- **Held-out (LT, SUB, FORPREP, add, sub):** not touched. This idea corrects the forecast for the non-held-out third.
- **Smallest thing to build:**
  - `euclid_cert` (or the core lemma it names);
  - `qrnnd_cert` stated as a `def …_Statement : Prop`;
  - a Python check of the statement on `__divdf3`'s vectors from `c/tests/float/`.
  - Then count `__divdf3`'s level (a) nodes, to price it against `__adddf3`'s 133.

### Seed

The digit clusters `46 56 62 71 67 89` are all two-digit limbs, and none is a power of two: a number cut into fixed-width limbs, i.e. 64-bit arithmetic done in 32-bit halves.

## Idea 5. Region lift: lift an arm's float region to a pure Lean function with the existing level-(a) machinery, and prove the arm as a pure equation

**Acts on:**
- **R5-R1-5 #1** (Pidgin: `mtree_run` ≈200 lines, an `MTree` generator ≈150 Python lines, a deep embedding): **(b) combine** it with the level-(a) lifter that already exists. **(c)** It does not need its own machine-to-tree theorem.
- **R5-R1-4 #E** (Biplane control/data planes over a *lifted* routine): **(a) extend** from soft-float routines to arm regions.
- **(d):** none of round 1 used the lifter on `luaV_execute` itself.

### The idea

The project already turns machine code into **pure Lean functions with a proof**: `gen_lua_fn.py` lifts `__adddf3` (418 instructions, 133 nodes) to `Adddf3.F` and proves the machine returns it. Level (b) is then a pure equation, with no Sail state.

The arms' heartbeat problem comes from doing the float reasoning *on Sail states*: the replay, the polarity trials, and the forecast 200k breach on LT/SHL.

So lift the arm's float **region** the same way:
- the region runs from the float tag test to the exits;
- the exits are the dispatch tail (`j 8001bfe4`/`c240`), the error calls (`luaG_forerror`, `luaG_runerror`) and the MMBIN edge.

The lift yields `Rg_o.F : (payloads, tags, base) → Exit`, where `Exit` is a closed sum `dispatch (pcOff) (writes : List (Nat × BitVec 64)) | error | mmbin`. The write list is first-order, as CLAUDE.md law 1 asks.

The arm proof then splits into:
1. **`arm_of_region`** (generic, once): VmRel at entry ⇒ the region's inputs. `Rg_o.F` = `dispatch off ws` ⇒ VmRel at exit, if `ws` and `off` match the kernel's `edge`/`vals`. This is the existing `dispatch` and `memFrame_of_chain` wiring, stated once over `Exit`.
2. **A pure equation per arm:** `Rg_o.F env = exitOf (κ.body …)`. This is a Lean-function equality, proved with idea 1's atom table, round 1's views and the `R.spec` rewrites, and with no machine state in the context.

The forks, φ joins and call nodes are all *inside* `Rg_o.F`, as `if`s and `let`s, the way they are inside `Adddf3.F`. Run-level reconciliation becomes `cases` on 2–5 `Option Ordering` atoms of a pure function.

### Core rules

| law | rule | decided at a use site by |
|---|---|---|
| L5-fork, L5-read′ (machine side) | **`region_lift`** (generated, level (a)): `Rg_o.F` is the region's semantics. This is the same kind of fact as the incumbent's generated `Lua.Vm.Arms.seg_*` segments, i.e. a machine fact, not a refinement proof | generated by the existing lifter. **[check: `gen_lua_fn.py` must accept an entry pc inside `luaV_execute`, exits that are not `ret`, and caller-memory writes as an output log]** |
| the wiring | **`arm_of_region`**: once, for all arms | syntactic instantiation |
| L5-idiom, L5-fork (semantic side) | `Rg_o.F` unfolds to `match`/`if` on `R.S x y`, then `relOf` (R5-R1-5 #2), then `generalize` the atoms (idea 1), then `decide` on the atoms | computation on closed atom products. **No Sail state, no polarity trials, no replay**: `Rg_o.F` is a term, and the cost is `cases o` |
| L5-read′ (registers) | the payload/tag inputs of `Rg_o.F` are the view fields (round-1 M-view, or idea 2's ports) | syntactic |

**Symbolic data.** Payloads are function arguments. Atoms are generalised.

**Search.** None. The lifter is deterministic.

**Forbidden vocabulary check.** The generated object is a *lift* (machine = function), the same category as `Adddf3.F`'s level (a) and the per-arm `seg_*` lemmas already in the tree. The per-arm *semantic* proof is one pure equation, not generated. The bake-off should rule on this explicitly.

### What it makes free

- **The 200k forecast breach.** The heartbeats move into the generated lift, which is budget-checked per declaration like `Adddf3`'s, and into a pure equation whose size is the region's `if`-depth, not paths × prefix.
- **R5-R1-5 #1's `mtree_run` and its generator:** the lifter *is* the machine-to-tree map, already proved generically.
- **R5-R1-4 #E's plane split:** it applies to `Rg_o.F` unchanged, so arm and level (b) share one decision core, as R5-R1-4 wanted.
- **The 7 spilled/moved `a0` sites:** the lifter forwards register moves. Spills to the arm's own frame are R5-R1-3 #D4's `reload_forward`.

### What it costs

- **Lifter support for regions.** The live-in set of `luaV_execute` (base `s9`, `pc` `s3`, the instruction word `s4`, …) becomes `F`'s arguments. The memory inputs (stack slots) become `bytesT8 m …` reads. Exits are tail jumps (`FnSummary.tailJump` exists for this shape in the mandated `gen_fn.py` route).
- **`arm_of_region`:** ≈80 lines.
- **Risk.** If the lifter cannot handle the region (indirect dispatch, `luaV_execute`'s 30 live registers), this idea reduces to idea 1 on the at-route. That is the falsifier.

### Theories

- **Decompilation** (known; Cifuentes, *Reverse Compilation Techniques*, PhD thesis, QUT, 1994). Recover a structured function from a region, then reason at source level.
- **Translation validation** (known; Pnueli, Siegel & Singerman, TACAS 1998). Validate the lifted function against the specification, not the binary against the specification.
- **Explant culture in biology** (known; Harrison, "Observations on the living developing nerve fiber", *Proc. Soc. Exp. Biol. Med.* 4, 1907). Excise a tissue, study it in a controlled medium, and carry the result back through a fixed interface. Using this to scope the arm proof is **novel**.

### Pilot

- **Refactor FORLOOP:**
  - lift `0x8001e158–e1bc` ∪ `0x8001edf0–ee00` (≈28 instructions, 3 calls, one φ);
  - `arm_of_region`;
  - the pure equation by the 16-point table.
  - Target ≤ 6 lines, with the heartbeats measured on the lift and the equation separately.
- **LT (held out):** the real test, 24 paths. Measure the pure equation's heartbeats against the 200k forecast.
- **SUB (held out):** small region (2 calls per class), the control.
- **FORPREP (held out):** callee-heavy (`luaV_tonumber_` ×3, `luaV_tointeger`), so the lift has call nodes with summaries, as `Adddf3.F` has `__clzdi2`.
- **Level (b):** none.
- **Smallest thing to build:** run the lifter on the FORLOOP region alone and see whether it lifts. That is a yes/no answer before any proof.

### Seed

`IdI` at the end (`RIdIG`), with `s6s` and `6v6`: an identity flanked by the same letter. The lifted region has the same interface going in and coming out (VmRel at entry, VmRel at dispatch), and the lift itself is an identity: machine = function.
