## A1. Odd-rounding congruence (`RO`): a sticky shift is round-to-odd, and round-to-odd is invisible to a later RNE

### The idea

The machine's `_FP_FRAC_SRS` idiom (`srl`, `sll` by `64−k`, `snez`, `or`) is exactly **round-to-odd** at unit `2^k`, written `ro n k`:
- `ro n k = n / 2^k` if `2^k ∣ n`;
- otherwise it is the odd one of `⌊n/2^k⌋` and `⌊n/2^k⌋ + 1`, which is `n / 2^k ||| 1`.

In other words, the sticky bit is OR'd into the LSB, von Neumann's "jamming".

Round-to-odd has the two properties that make "rounding after the sticky collapse equals rounding the exact value" a single theorem rather than a per-routine argument:

1. **Equivariance.** `ro` commutes with `x ↦ 2j ± x`, that is, with translation by an even integer and with negation.
   - Translation by an odd integer would flip the parity, but the machine never translates by one.
   - It only adds the *other* operand's mantissa `frac<<3 | 1<<55`, a multiple of 8. I checked this on the ELF: `slli t5,t1,0x3` at `0x8002d7d8` and `add a3,a4,t5` right after the SRS at `0x8002dce4`.
   - So the machine's aligned sum or difference is `ro` of the exact aligned sum or difference.
2. **Transparency.** Rounding to nearest-even (in fact any `shr`-then-`rne`) at a unit at least `2^2` coarser than `ro`'s unit sees the same quotient, round bit and sticky bit as rounding the exact value. Bit 0 of `ro`'s result carries "something nonzero below", which is all that sticky needs. Bit 1 and above are the exact value's bits.

The hand-off then needs no reasoning about paths, about `d`, or about cancellation beyond one linear fact on exponents.

### Core rules

All are stated over `Nat`/`Int` in `Lua/Num/F64` vocabulary. Each is proved once.

| law | rule | how it is decided at a use site |
|---|---|---|
| L5-stage (SRS, `1 ≤ k ≤ 63`) | `srsMachine x k = BitVec.ofNat 64 (ro x.toNat k)` given `1 ≤ k ≤ 63` (checked on 18,900 inputs) | rewriting by syntactic match on the node's idiom; the side condition comes from the guard that branched there (`bge 56,a6`), so it is linear and closed by `omega` over the exponent atoms |
| L5-stage (SRS, `k ≥ 64`, pure sticky) | `ro x k = [x ≠ 0]` when `x < 2^k` | rewriting; side condition `x < 2^56 ≤ 2^k`, closed by `omega` with literal powers |
| hand-off, part 1 | **`ro_add_even`**: `2 ∣ A → A + ro B k = ro (A * 2^k + B) k`, and **`ro_sub_even`**: `2 ∣ A → ro B k ≤ A → A − ro B k = ro (A * 2^k − B) k` | rewriting; `2 ∣ A` is closed by `decide`/`omega`, because `A` is `f <<< 3 ||| 2^55` |
| hand-off, part 2 | **`shr_ro`**: `2 ≤ s → F64.shr (ro n k) false false s = F64.shr n false false (s + k)` | rewriting; `2 ≤ s` is linear in the exponents (`s = T − e − k`, with `T` from `target`), closed by `omega` |
| `F64.shr` as an action | **`shr_shr`**: `shr (shr n rb st a).1 … b = shr n rb st (a + b)` (the triple threaded through) | rewriting. This turns the machine's `rne3` (round at bit 2, sticky from bits 0–1) into `round … false false` at the exact exponent |
| `target` invariance | `target (ro n k) (e + k) = target n e` when `2^(k+1) ≤ n` | rewriting; the side condition is the normalisation fact the clz stage already provides |

Under `A + ro B k`, the symbolic mantissas `A`, `B` and the shift `k` stay symbolic. No case analysis on `d = e_a − e_b` is needed except the region split that already exists (A5):
- for `d ≤ 3` the low 3 bits are zero, so `ro` is exact (`ro (B<<3) d = (B<<3) >>> d`);
- for `d ≥ 4` the cancellation loses at most 1 bit, so `s ≥ 2` holds.

Both facts are linear in `d` once `ro` names the operation. **No rule is decided by search.**

  - That route needs `Subdf3.F a b = Adddf3.F a (b ^^^ 2^63)`, an equality between two *different* lifted functions (509 and 497 paths).
  - That is a per-routine hand equality of a lifted function: forbidden vocabulary, and as hard as either spec.
  - I flag ROUND-5's "`__subdf3` is free" as **wrong as a cost claim**. The spec-side identity is free, but the machine side is not.
  - With `RO`, sub's core is add's core with `ro_sub_even` in place of `ro_add_even`.

### Theories

- **Jamming.** Burks, Goldstine & von Neumann, *Preliminary discussion of the logical design of an electronic computing instrument*, 1946. Known. [CHECK that the term is attributed there.]
- **Sufficient statistics** (Fisher, *On the mathematical foundations of theoretical statistics*, 1922). `ro n k` is a sufficient statistic of `n` for every RNE decision at a unit at least `2^(k+2)`: the "parameter" (the rounding outcome) depends on `n` only through it. `shr_ro` is the factorisation theorem in this instance. **Novel** as an organising principle for sticky-bit proofs.
- **Equivariance under a group action** (Klein's Erlangen programme, 1872). `ro` is equivariant for the group generated by `x ↦ x + 2` and `x ↦ −x`. The machine's operations stay inside that group, which is why the hand-off is one theorem. **Novel** application.

## A2. Reconciled fork trees: run the shared prefix once, and match machine leaves to kernel classes by one closed `decide`

### The idea

Today an arm splits on the kernel's outcomes *first* and then runs the machine once per outcome. That replays the prefix (8.3k heartbeats in FORLOOP) and picks each fork's polarity by trying closers (10.3k).

Invert it:
1. **Run the machine forward once,** symbolically, keeping each soft-float answer as an **atom**: `o₁ := F64.compare st 0`, `o₂ := F64.compare l idx`, of type `Option Ordering`.
2. **At each fork, do not choose.** Apply one generic `fork` rule that continues on both sides under the guard as a hypothesis.
   - The guard is a closed function of the atoms, by A3: `g (o₁, o₂) : Bool`.
3. **At the leaves,** the proof owes `leafExit (path) = κ.edge` and the stored values.
   - Both sides are functions of the *same finite atoms*: the machine side by the guards, the kernel side because each float test in `forloopK`/`opArith`/`δ` rewrites (bridges `lt_eq_model` and so on, plus `compare_swap`) into a function of `F64.compare` on the same payloads.
   - The whole edge agreement is therefore **one closed proposition** `∀ o₁ o₂ : Option Ordering, …`, decided by `decide` over at most `4^k` cases.

This is "gene-tree / species-tree reconciliation":
- the machine's fork tree is the gene tree;
- the kernel's outcome tree is the species tree;
- the map from machine leaves to kernel classes is the reconciliation map;
- duplications (several machine leaves on one class) are the f2i chain's many-to-one leaves that ROUND-5 left untested.

### Core rules

| law | rule | decided by |
|---|---|---|
| L5-fork (prefix once) | **`run_fork`**: `wp (pre ; if g then t₁ else t₂) Φ ⇐ wp pre (fun c => (g c → wp t₁ Φ c) ∧ (¬g c → wp t₂ Φ c))`. This is a structural rule of the existing at-route, stated once over `MachWP`'s `Wp.run` | syntactic: `at_go` applies it at a conditional branch whose guard is not closed, **instead of** trying the two closers |
| L5-fork (polarity by evaluation) | **`atomize`**: generalize every `F64.compare a b` occurring in a guard or a kernel answer into a variable `o : Option Ordering`. The guard and the kernel edge become closed functions of the `o`s | computation; generalization is syntactic (the call-node equations `f<k>_eq` already put answers in `F64.compare` form after A3) |
| L5-read′ + L5-fork | **`reconcile`**: if `∀ ō, exitOf (tree ō) = κEdge ō` is closed and true, then the leaves close against the kernel's outcomes. One `decide` per arm | `decide` over `4^k` atom assignments: 16 for FORLOOP (k = 2); LT has at most 6 compare calls, of which at most 3 lie on one path, [CHECK] the dependency count on the ELF |
| data agreement at leaves | the stored payloads are equal: `Adddf3.S st idx = F64.add idx st` (`add_comm`) | syntactic rewrite, one per leaf family, by A4's normal form |

**Search:** the segment lookups inside `at_run` still pick an at-lemma by candidate trial. That search remains, but it is now only over *which segment*, never over *polarity*, and it happens once per tree node rather than once per kernel outcome. The `fork` rule removes the polarity search entirely.

**Symbolic data:** payloads stay symbolic throughout. Only the `Option Ordering` atoms are enumerated, and only after generalization, so `decide` never meets a `BitVec 64`.

### What it makes free

- **FORLOOP's per-outcome replay** (8.3k) **and wrong-polarity closers** (10.3k), 31% of its heartbeats.
- **The heartbeat budget forecast** for SHL/SHR (22 float paths) and LT/LE (24). The prefix and the call nodes are run once, and the leaves cost a `decide` over `4^k` closed cases plus their tails. Heartbeats grow with the number of *tree nodes*, not with `fp × prefix`.
- **The 16 FORLOOP-like fields' kernel-outcome case split** (`rcases … <;> split <;> rename_i`, 4 of FORLOOP's 29 lines). It is replaced by `reconcile; decide`.
- **The f2i many-to-one leaves:**
  - reconciliation allows several machine leaves per kernel class by construction;
  - the order of machine forks and kernel tests need not agree (ROUND-5's refinement of L5-fork).

### What it costs

- **`run_fork` on the at-route:** about 30 lines. `at_go` must stop splitting at a non-closed guard, a kit change of about 20 lines.
- **`atomize`** needs each guard to be a function of compare answers. That is A3's normal form, so A2 depends on A3, and it is weaker without it.
- **Harder:** an arm whose fork depends on a non-compare soft-float answer (MOD's `fmod` sign fix tests `m > 0`, which is a compare of `fmod`'s *result*, so still an atom; `__fixdfdi`'s value feeding a branch) needs that value as a further atom. If the branch inspects bits rather than a compare, the atom is a `BitVec` and `decide` fails. [CHECK on SHL/SHR, whose shift amount comes from `__fixdfdi`.]

### Theories

- **Reconciliation of gene and species trees.** Goodman et al., *Fitting the gene lineage into its species lineage*, Systematic Zoology 28, 1979; Page, *Maps between trees and cladistic analysis of historical associations among genes, organisms, and areas*, Systematic Biology 43, 1994. Known in phylogenetics; **novel** as a refinement-proof structure.
- **Compiling pattern matching to decision trees.** Maranget, *Compiling pattern matching to good decision trees*, ML Workshop 2008. The machine's tree is a compiled decision tree for the kernel's `match`; `reconcile` is its correctness theorem specialised to finite atoms. Known.
- **Shannon expansion / BDDs.** Bryant, *Graph-based algorithms for Boolean function manipulation*, IEEE Trans. Computers C-35, 1986. Running the prefix once and splitting late is cofactoring on the atoms in fork order. Known.
- **Veritesting** (Avgerinos et al., ICSE 2014): merge paths instead of forking early. Known.

  - The four leaves: `c240` with stores (`e1b0–e1b8`) or without.

  - Target: ≤ 8 lines and ≤ 35k heartbeats, against 29 lines and 59.1k.

## A3. Sign-class semantics of compare answers: 3 routine lemmas + 10 instruction-kind lemmas instead of 17 idiom lemmas, and the f2i chain as one canonical decision function

### The idea

L5-idiom proposes emitting one lemma per (routine, idiom) pair. Factor through the point where the two meet, the **sign class** of `a0`:

```
inductive SgnCls | neg | zero | pos
def sc (x : BitVec 64) : SgnCls        -- by x.toInt
```

- **Every** idiom instruction in `idioms.out` depends on `a0` only through `sc a0`: `beqz`, `bnez`, `bgez`, `bltz`, `blez`, `slti 0`, `slti 1`, `sgtz`, `seqz`, `srli 63`, `not; srli 63`.
  - `slti a0,1` is `a0 ≤ 0`, and `not; srli 63` is `a0 ≥ 0`.
  - So each is `f_ι (sc a0)` for a closed `f_ι`.
- **Every** compare routine's spec composes to a closed function of `F64.compare`:
  - `sc (Ledf2.S a b) = scLe (F64.compare a b)`, with `none ↦ pos` (2);
  - `sc (Gedf2.S a b) = scGe (F64.compare a b)`, with `none ↦ neg` (−2);
  - `sc (Eqdf2.S a b) = scEq (F64.compare a b)`.
- The use site is therefore `f_ι (scR o)`: a closed function of the atom `o`, which reduces by `decide`/`rfl` after generalization (A2's `atomize`). No site lemma and no idiom lemma.

**Chain.** The inlined `luaV_flttointeger` is a decision function over three compare atoms:
- `o_eq := compare x (floor x)`, from `__eqdf2`;
- `o_lo := compare f (−2^63)` and `o_hi := compare f (2^63)`, the range tests (`__gedf2`/`__ledf2`);
- with symbolic data leaves `floor x`, `__fixdfdi (floor x)` and, for ceil, `__adddf3 (floor x) 1`.

All 6 layouts compute **the same** decision function on `(o_eq, o_lo, o_hi)`. They differ only in polarity and fall-through. That is one closed `decide` over 64 cases, which is A2's `reconcile` with the kernel side replaced by one canonical function `f2iCanon mode`.

### Core rules

| law | rule | decided by |
|---|---|---|
| L5-idiom | `idiom_sc` (one lemma per *instruction kind*, about 10, over `BitVec 64`): e.g. `(slti x 1 = 1) ↔ sc x ≠ .pos`, `(x.msb) ↔ sc x = .neg` | proved once each by `BitVec.toInt` facts; at use sites by **syntactic** rewrite (`simp only [idiom_sc]`) |
| L5-idiom | `sc_ledf2`, `sc_gedf2`, `sc_eqdf2`: `sc (R.S a b) = scR (F64.compare a b)` | proved once each by 4-case `decide`; used by rewrite |

| L5-chain (layout) | the site's machine decision function equals `f2iCanon mode` on the atoms | `decide` over `4³ = 64` closed cases; the layout's polarity is visible only to `decide` |

**No search.** The symbolic data (`floor64 x`, the fixdfdi result) passes through the decision function as opaque arguments. It is never inspected.

### What it makes free

## A4. Correlation of parts: kernel-class views give every read register's tag, payload and model as one named record, by a generic read and one inversion per combinator

### The idea

FORLOOP spends 48% of its lines reading three registers and bundling their tag, payload and model. The machine tests one tag; the other two registers' types are kernel facts.

Make that a *representation*: a **register view** as a named-field structure, produced by one generic lemma for any list of read ports:

```
structure FltView (c : Config) (w : …) (r : Nat) (x : BitVec 64) : Prop where
  tag   : slotTag c.σ.mem (w.slot r) = BitVec.ofNat 8 vNumFlt
  pay   : slotVal c.σ.mem (w.slot r) = x
  model : s.regs r = some (.flt (Float.Model.ofBits (UInt64.ofBitVec x)) x.msb)
```

- `VmRel.readPorts` gives, for `κ.reads = ports` and `s.regs <$> ports = vs`, a `ValRepr` for each entry. It is stated once over `List`, for any length.
- A per-**combinator** class lemma (not per arm) turns `κ.body vs = some o ∧ Q` into a disjunction over a closed list of **shapes** (constructor lists), each carrying the edge.

Lemmas needed:
- `forloopK_class`: `[flt, flt, flt]` with edge ∈ {0, 2}, or the int shapes (excluded by `FltStep`, with `none` refuted).
- `opArith_class`: `[flt, flt]`, `[flt, int]` or `[int, flt]` → edge 0; a non-number partner → edge 1.
- `δorder_class`: `[flt, flt]`, `[flt, int]` or `[int, flt]` → `bool`; `none` (error) otherwise.
- `forprepK_class`.

`shape_views` then turns each shape into the views of its float registers in one step.

**The machine-side companion: tag-preserving store.**
- `floatforloop` writes R[A]'s payload (`sd s6,0(s5)`, `0x8001e1b0`) but **not** its tag. It writes only R[A+3]'s tag (`sb a5,56(s5)`).
- **`FltView.store_pay`**: overwriting the payload of a slot whose view is `FltView` gives the `FltView` of the new payload.
- This is one frame lemma. Without it, each FORLOOP-like arm re-derives that R[A] still holds a float after a payload-only store.

### Core rules

| law | rule | decided by |
|---|---|---|
| L5-read′ (generic read) | `VmRel.readPorts : VmRel p c s → s.regs <$> ports = some vs → Forall₂ (ValReprAt c) ports vs` | syntactic: applied once per arm with `ports := κ.reads`, which is literal per opcode after `simp [κ]` |
| L5-read′ (classes) | `κ_class` per combinator, about 6 total: answer + `Q` → `shapeOf vs ∈ κ.shapes` | the membership in a **closed** list is split by `simp [List.mem_cons]`/`rcases`. This is computation, not search; payloads stay symbolic |
| O-pay | `shape_views : shapeOf vs = sh → Forall₂ ValReprAt ports vs → Views sh ports` (`Views` is a named record per float position) | syntactic |
| tag preservation | `FltView.store_pay` | rewriting over the existing first-order write log (`memFrame_of_chain`) |
| O-inv | subsumed: the class lemma *is* the kernel inversion | — |

### What it makes free

- **FORLOOP:** 14 of 29 lines (`kit_reg` ×3, `cases v0 <;> cases v1`, `flt_parts` ×3, `hta`/`hxm`/`hnj`). The refute-non-float step's 2.9k heartbeats become one `κ_class` application.
- **O-pay** (9/10 of the sample) and **O-inv** (4/10). These are the 12 of 33 fields with a register or K partner, plus every FltB/FltA field's single register.
- **C5-handoff partially:** `at_fcond` and `at_farith` (37 lines) become instances of "read views + class". What is left per combinator is the call-node wiring, which is L5-share′'s parametric hand-off. That hand-off becomes thin, because the read/bundle half of it is gone.

### What it costs

- **`readPorts`:** about 30 lines, induction on `ports`.
- **The class lemmas:** about 15 lines each × 6 combinators = 90.
  - `forprepK_class` is the largest. It goes through `Value.tonumber?` (string coercion), so its shapes include `str` positions, whose views are `StrView` (the `ValRepr.str` fields).
- **Harder:** `Q` is a disjunction (`FltBC = FltReg b ∨ FltReg c`), so `κ_class` must be proved under each disjunct. This is fine, but `shapeOf`'s list must be stated per combinator by hand, and checked against `LawChecks.out`'s classes table.

### Theories

- **Views.** Wadler, *Views: a way for pattern matching to cohabit with data abstraction*, POPL 1987. `Views sh` is a view of the register file at a shape. Known.
- **Occurrence typing.** Tobin-Hochstadt & Felleisen, *The design and implementation of Typed Scheme*, POPL 2008. A test on one value refines the types of others. Here the kernel's answer refines the untested registers. Known.
- **Cuvier's principle of the correlation of parts.** Cuvier, *Recherches sur les ossemens fossiles*, 1812: from one bone, infer the animal. The machine tests one tag, and the kernel class infers the whole frame's types. **Novel** application; it names exactly why `tags = 1` suffices on FORLOOP's machine path.

  - Target: 4 one-line class arms + 2 lines of setup.

### Seed

## A5. Chamber partition of the exponent plane: prove level (b) by the spec's regions, not the code's 497 paths

### The idea

`Adddf3.F` has 497 paths because the compiler duplicated tails. Its 76 guards are almost all **linear tests on the two 11-bit exponent fields** and their difference `d`:
- `beq a7,a1` (same sign);
- `blez a6`, which is `d ≤ 0`;
- `beqz t3`, which is `e_b = 0`;
- `beq a5,2047`;
- `bge 56,a6`, which is `d ≤ 56`.

The other guards are on **mantissa magnitudes** (the carry into bit 56, the clz result).

The exponent guards are hyperplanes in the `(e_a, e_b)` plane. Their arrangement has a small number of **chambers**, which align with `F64.add`'s 9 classes × same/opposite sign × `d` range (`d ≤ 0`, `1–3`, `4–56`, `≥ 57`).

So the proof is:
1. **Unpack the operands to the stage triple once,** by a bit-field *lens* for `(sign, bexp, frac)` on `BitVec 64`, with get/put laws. This is ROUND-5's step 2, proved once and used for all routines.
2. **Enumerate the chambers** from `F64.add`'s clauses (syntactic, about 30), not from the code.
3. **In each chamber,** the hypotheses fix every exponent guard. One `simp only [chamber hyps, guard lemmas]` reduces `F` to a single straight-line composition: `pack ∘ rne3 ∘ (A ± ro B k)` (A1) or a special value.
4. **Close each chamber** by A1's rules or `rfl`.

Mantissa guards (the carry, the clz) are not split. They are absorbed into the stage lemmas (`roundPack = F64.round` covers the carry; `clz64 = 63 − log2` covers normalise).

### Core rules

| law | rule | decided by |
|---|---|---|
| L5-stage (unpack) | **`F64Lens`**: `x = bits (sign x) (bexp x) (frac x)` and the machine field extractions `(x >>> 52) &&& 0x7ff = bexp x`, `x <<< 12 >>> 12 = frac x`, `x >>> 63 = sign x`, with constant shifts only | proved once by `BitVec` lemmas with literal shift amounts; at use sites by rewriting |
| frame reloads (outside the stage law) | **`F` without `m`**: the generator forwards each reload of its own frame through the `writeMap8` chain when it emits `F`, the read-over-write done at generation time. Level (a)'s existing proof covers the new `F` (it is still the machine's function) | generator change; **not** a per-routine proof. Flag: this edits `gen_lua_fn.py`'s output form, and the level-(a) proof must still go through generically |
| chamber split | **`chambers_cover`**: the ~30 chamber predicates on `(e_a, e_b, sign_a, sign_b, frac_a = 0, frac_b = 0)` cover all inputs. A Presburger fact on 11-bit naturals | `omega` (linear; all exponents are `Nat` atoms < 2048 after the lens), or one `decide` per chamber pair on the closed guard skeleton |
| guard evaluation inside a chamber | each guard is `decide`-free: its `BitVec` comparison of exponent fields rewrites to the `Nat` comparison (`BitVec.toNat` lemmas), which the chamber hypothesis closes | `omega` on linear exponent facts. The **variable** shifts are by `d`, so they become `ro _ d` (A1) or `<<< d` with `d` bounded, and are never handed to `omega` |
| per-chamber close | `pack ∘ rne3 ∘ …` = the `F64.add` clause | A1's rules (finite × finite), or `rfl`/`decide` on special values |

**Search:** none. Chambers are enumerated from the spec's syntax, and each guard is evaluated by linear arithmetic.

### What it makes free

- **The 497 paths.** The proof follows the spec's case structure, and the code's tail duplication becomes invisible: the six inlined round sites are all the *same* function after the chamber `simp`, so each chamber closes by the one `roundPack` lemma whichever copy it reaches.
- **The 14 frame reloads,** once `F` is emitted without `m`.
- **The unpack step** for every routine: `__floatdidf`, `__fixdfdi`, the compares, `__muldf3` and `__divdf3` all use the lens.
- **`__subdf3`:** the same chambers with `sign_b` flipped (the `F64.sub` clauses mirror `F64.add`'s), with the per-chamber close by `ro_sub_even` (A1).

### What it costs

- The lens: about 40 lines. The chamber list: about 30 one-line predicates. `chambers_cover`: one `omega`.
- **The generator change for frame forwarding.** It may change level (a)'s proofs; if those are generic over the frame, it is cheap. [CHECK: I may not read `Lua/Vm/Fn/*`.]
- **Harder:**
  - The per-chamber `simp` must reduce a 133-node DAG under hypotheses. If the generator's `F` is a deep `let`/`if` term, `simp` may need `F` unfolded node by node, risking the heartbeat budget per chamber.
  - Mitigation: a `decide`-free `Nat` normal form per node, which keeps one chamber's `simp` to the nodes it reaches (about 10–20 of 133).
  - The risk is measurable by the pilot.

### Theories

- **Hyperplane arrangements and chamber counting.** Zaslavsky, *Facing up to arrangements: face-count formulas for partitions of space by hyperplanes*, Memoirs AMS 154, 1975. The guards are hyperplanes, and the proof cost is the number of chambers, not of paths. Known.
- **Phase diagrams in thermodynamics** (Gibbs' phase rule). The routine's behaviour is qualitatively constant on regions of the `(e_a, e_b)` "state space", and the boundaries are where a guard flips. **Novel** analogy: it suggests proving at chamber *boundaries* (`d = 0`, `d = 56`, `e = 0`, `e = 2047`) first, where the census's counterexample (SRS at `k = 0`) lives.
- **Path merging in symbolic execution** (Kuznetsov et al., *Efficient state merging in symbolic execution*, PLDI 2012). Known.
- **Lenses** (Foster et al., *Combinators for bidirectional tree transformations*, TOPLAS 2007) for the bit-field unpack. Known.

### Pilot

- **`SoftFloatSpec.adddf3` (held out).**
  - Build the lens and the chamber list.
  - Prove the special-value chambers (NaN, ∞, zero; about 12, each `simp` + `rfl`) **and** the finite same-sign `d ≤ 3` chamber (exact, no sticky).
  - Success metric: the closed chambers take ≤ 3 lines each, and no `simp` call exceeds 50k heartbeats.
  - With A1, the `4 ≤ d ≤ 56` chambers follow.
- **`SoftFloatSpec.subdf3` (held out):** the marginal cost over add should be the sign-flipped chamber list alone (≤ 15 lines).
- **Arms:** not affected.
- **Smallest thing to build:** `F64Lens` with its constant-shift lemmas. Then try one special-value chamber (`a` NaN) on `Adddf3.F` with `m` held abstract, to measure the per-chamber `simp` cost before changing the generator.

### Seed

Digit clusters sit beside long letter runs: a few discrete exponent facts amid long symbolic mantissa data. Partition by the discrete part, and carry the long part symbolically. The absence of any long palindrome is why sub is not reduced *to* add here: sub gets its own mirrored chamber list, which shares the closing rules.
