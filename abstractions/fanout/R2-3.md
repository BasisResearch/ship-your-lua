## 1. Def/kill edges: garbage is a named write of ⊥, not a value the kernel must compute

**Acts on.**

- **(b)** Combines R1-1 #3 (X-propagating registers) with the kernel family: R1-4 #1 RCW, R1-3 #1 Kernel, R1-5 #1 port-typed kernels.
- **(c)** Objects to their H2 write sets:
  - R1-5 #1 and R1-2 #1 give `CONCAT` the write set `[A]` only. H2 now says that is false.
  - R1-3 #1 notes the problem but proposes that "the body must produce those intermediate values". That transcribes `luaV_concat`'s in-place algorithm into the trusted text. The algorithm concatenates as many consecutive strings per pass as it can, and it rewrites number operands in their slots through `tostring`. The kernel would then have to predict *exactly which* partial string lands in `R[A+1]` after how many passes. That is a faithfulness liability paid for no observable behaviour, since `luac` never reads those slots.

**The problem.** A deterministic `Step` must produce one successor state, so it must say what `R[A+1..A+B-1]` hold after `CONCAT`. There are three options, and two of them are bad:

| option | what `Step` says about the garbage | cost |
|---|---|---|
| (i) exact | `luaV_concat`'s intermediates, computed | trusted text grows; δ becomes a simulation of C's buffer management |
| (ii) havoc | `∀ junk`, i.e. a non-deterministic step | L-B2 (`Step ↔ step? = some`) dies: `step?` is no longer a function |
| (iii) **kill** | the slots become ⊥ | deterministic; the machine may hold anything there |

**The idea.** Registers hold `Option Value`, and an edge carries two masks instead of one:

```lean
structure Edge where
  tgt  : Nat
  def_ : List Nat      -- written with a value
  kill : List Nat      -- written ⊥ ("don't care")
```

The kernel's `δ` returns values for `def_` only; `kill` slots are set to `none` by `apply`.

- **H2** `CONCAT A B`: `def_ = [A]`, `kill = [A+1, …, A+B-1]`.
- **`CALL` of `print`** today says "registers above the results are unchanged". `Fragment.lean` admits this is false of the machine, and pays for it with `keepMask` plus `cbcSem_iff`. `CALL` instead gets `kill = [A + C - 1, frameTop)`.
- **F3 Lua calls** get the same `kill`, because the callee's frame overwrites everything above.

**Core rules.**

- **L-B1 becomes `kernel_footprint_dk`.** It is round 1's single footprint theorem with the frame clause weakened from "every register outside `wr` is unchanged" to "every register outside `def_ ∪ kill` is unchanged". The clause "the `kill` slots are ⊥" follows by definition of `apply`. It is still one theorem, proved once.
- **The dataflow `sweep` becomes the α-image of `apply`.** The update is `st[t] ∩= (st[pc] \ kill) ∪ def_`. `keepMask` disappears as a special case: `CALL` stops being the only opcode with a "keep" rule, because its clobbering is now just its `kill`.
- **Definite-initialisation soundness becomes R1-1 #3's certain-answer theorem, proved once.** The statement is `Supported p → (BcSemX p initX out ↔ ∀ g, BcSemHavoc p (init g) out)`.
  - `bcSemFrom_iff` (entry garbage) and `cbcSem_iff` (call garbage) become two instantiations of it.
  - Monotonicity is structural, not "one tactic over constructors" as R1-1 feared, because on the kernel side every read is `rd` of a static port and strict on ⊥.
- **L-C1 representation.** The machine-side relation is `Rep m s := ∀ r v, s.regs r = some v → slot m r ≅ v`. It has **no clause for ⊥**. Every arm with a `kill` (`CONCAT`, `CALL`, and later `CLOSE` and calls to Lua functions) proves nothing about the killed slots.

**What it makes free.**

- H2's garbage specification: nothing about intermediates is transcribed.
- `keepMask`, and `cbcSem_iff` as a separate proof.
- At A1, the "what does `luaV_concat` / `luaD_precall` leave in the stack above" half of the `CONCAT` and `CALL` arm proofs. In the predecessor project that half was the tail of every call-site row.

**What it costs.**

- `Value⊥` threads through `State.set`, `args` and `printLine`. `print` of ⊥ is stuck: `args` is strict.
- The trusted semantics now says "⊥" where `lvm.c` says "whatever is there". A reviewer must accept that ⊥ is sound only because `Supported` forbids reading it. That argument is exactly the certain-answer theorem, which is proved, not trusted.
- **What gets harder, and where it breaks: aliasing at F3.** An *open upvalue* is a heap pointer into the register window. If a killed slot is captured by an open upvalue, then ⊥ in the register view and a live value in the upvalue view disagree.
  - The fix is that `kill` must never cover a captured slot. `luac` closes upvalues (`CLOSE`, or `k` on `RETURN`) before a slot's lifetime ends, so this is a `Supported`-checkable side condition.
  - This must be decided at F3, not assumed.
- It keeps the readable inductive if wanted. `s.kill a n` is just another state operation, so this idea is orthogonal to the "redefine `Step`" question.

**Theories.**

- *Known, logic synthesis.* Don't-care sets in two-level minimisation. The implementation may realise any value on the don't-care set, and correctness is stated on the care set only. Brayton, Hachtel, McMullen, Sangiovanni-Vincentelli, *Logic Minimization Algorithms for VLSI Synthesis*, Kluwer 1984 (ESPRESSO). The `kill` mask is the step's don't-care set, and `Rep` without a ⊥ clause is "correct on the care set".
- *Known, physics of computation.* Landauer, "Irreversibility and heat generation in the computing process", IBM J. Res. Dev. 5(3), 1961. Erasure is the logically irreversible operation and must be accounted for explicitly. Here, the specification names its erasures (`kill`) because a frame law ("unchanged outside W") cannot be stated honestly without knowing them.
- *Known, refinement calculus.* Morgan, *Programming from Specifications*, Prentice Hall 1990: the specification statement `x : [true, true]` (havoc). ⊥ plus the certain-answer theorem is the deterministic *representation* of that demonic havoc. It keeps the step a function, which option (ii) loses.
- *Novel.* The edge carries `(def, kill)`, and the must-analysis is the α-image of `apply` for both, which retires `keepMask` as a special case.

**Pilot.**

- **H2 (bytecode).**
  - `CONCAT`'s kernel: `def_ = [A]`, `kill = range (A+1) (B-1)`, and `δ` is a right fold with `%d` for integers.
  - Proof lines for L-B1, L-B2 and the dataflow case: **0**.
  - Measure against an "exact intermediates" version (option i) of the same kernel. That is the comparison that tests this idea.
- **H1, H3, H4:** `kill = []`. Nothing changes.
- **R1:** replace `keepMask` + `cbcSem_iff` + `bcSemFrom_iff` with the certain-answer theorem, instantiated twice.
- **Smallest falsifier.** State `CALL print`'s new `kill` and rerun the existing kernel check of `Supported whileProto` and `print_print`.
  - If some `luac` output reads a slot in a `kill` set, `Supported` rejects a program it used to accept. That means the machine really does rely on the slot surviving, and the idea is wrong for `CALL`.
  - Cost: one definition change and one `decide`.

**Seed.** `X3X`: an unknown on both sides of one fixed value. That is `CONCAT`'s result at `A` with don't-cares around it.

## 2. The error sink: stuckness is an A1 obligation, and it exposes a hole in the H suite

**Acts on.**

- **(c)** Objects to R1-4 #4, whose slow-path idiom has "semantic action `stuck` … exactly the F1 convention". It also objects to every round-1 lifter (R1-1 #5, R1-2 #5), which treat stuck as free.
- **(a)** Extends R1-2 #4 and R1-4 #5, whose δ returns `none` as "the runtime error".

**Why stuck is not free.**

- `vm_refinement_Statement` is an **iff**: `BcSem p out ↔ Halts c out 0`. When `Step` is stuck, `BcSem` has no output, so the machine must provably **not** exit 0 on that path.
- L-C1 as stated in ROUND-1 ("the arm reaches the dispatch head representing `s'`") says nothing about stuck states.
- Worse, the stuck path does not stay inside one arm. `lvm.c`'s `op_arith` on a non-integer operand does *not* skip the following `MMBIN`. It falls through to the dispatch head at `pc+1`, and then runs the **`MMBIN` arm**, whose Lean rule does not exist (`edgesOf MMBIN = some []`). That arm calls `luaT_trybinTM`, which either finds a metamethod or calls `luaG_opinterror`. So the stuck case of `ADD` is a **two-arm** path through an opcode with no rule, and "head to head, one arm per rule" does not cover it.

**The hole this exposes in the H suite (check first).**

- Lua 5.4 moved string→number arithmetic coercion into the string library's metatable: `lstrlib.c`'s `stringmetamethods` has `__add`, `__sub`, `__mul`, `__mod`, `__pow`, `__div`, `__idiv` and `__unm`. *Recalled: check the exact list, and whether bitwise operations are in it.*
- If the image opens the string library, then `print("10"+1)` prints `11` and exits 0. The recent `io`/`os` commits suggest libraries are being opened; *check `string`*.
- Under H1, strings reach registers. F1's `arith` and `unm` rules have no string case, so `LuaSem` and `BcSem` are stuck on that program while the machine halts with 0, and **`vm_refinement` is false**.
- `Supported` cannot exclude this, because the operand types are dynamic.
- Worse still, `"1.5"+1` yields a *float*, so the H slice leaks F-Float.
- Either the H suite adds a coercion rule (`"10"+1`) and an exclusion argument (floats), or the image must not install the string metatable. This must be decided before the bake-off, or every contender proves H1–H4 against a false headline.

**The idea.** Make failure *typed* and route it to one absorbing state.

- `δ : … → Except Err Out`, with `Err := arithType | orderType | lenType | concatType | divZero | callNonFn | …`. Each constructor names the `luaG_*` function `lvm.c` reaches (`luaG_opinterror`, `luaG_ordererror`, `luaG_typeerror`, `luaG_concaterror`, `luaG_opinterror` via `luaV_idiv`'s `"attempt to perform 'n//0'"`, …).
- The source side's rulebook (R1-3 #3 / R1-4 #2 trees) replaces `fail` with `raise e`.
- **Stuck = `raise e`, for some named `e`.** `LuaSem` and `BcSem` stay exactly as they are about outputs: `raise` has no behaviour. The *reason* for having no behaviour is now data.

**Core rules.**

- **L-C1 splits into L-C1⁺ and L-C1⁻.**
  - L-C1⁺ is the head-to-head simulation for `Except.ok`.
  - L-C1⁻: from a head state where the kernel returns `.error e`, the machine reaches `Sink e`, a call to the `luaG_*` function that `e` names, possibly through the next instruction's `MMBIN` arm.
- **`sink_absorbing` is proved once.**
  - `Sink e → ¬ Halts c out 0`, or more precisely: `luaD_throw` unwinds to the `lua_pcall` in `main`, and `main` then exits with a nonzero status.
  - Every `luaG_*error` is `l_noret`. It ends in `luaG_errormsg` → `luaD_throw`, so one callgraph fact covers all error kinds.
- **L-B1/L-B2 are unchanged.** `Except` is still a function of the read values, so the round-1 kernel proofs go through.
- **The faithfulness check becomes executable.** On native Lua, each `Err` constructor is paired with its error-message class ("attempt to perform arithmetic on a boolean value", "attempt to compare number with string", …). A difftest under `pcall` checks that every `Err` the kernel raises is the error the C raises. This also catches the string-coercion hole above: the kernel raises `arithType` and native Lua returns `11`.

**What it makes free.**

- **The negative half of every A1 arm**, reduced to "the failing branch jumps to handler `h_e`". That is typically one conditional branch into a call of a known `l_noret` function, plus the shared `sink_absorbing`.
- **`MMBIN` stops being an unaccounted arm.** It is proved once as "reaches `Sink arithType` when no metamethod exists". That holds for all 21 `arith` opcodes, since they all fall through to one of the three `MMBIN*` arms.
- **Differential validation of error behaviour**, which round 1's checks skipped: "programs that raise a runtime error … are skipped".

**What it costs.**

- Every `δ` arm that fails must say why. That is about one constructor per failure site. It is data, not proof.
- `sink_absorbing` needs the `lua_pcall` → exit-code path of `main` modelled at A0. It is one fact, and a large one if `luaD_throw`'s `longjmp` is not yet modelled.
- **Metamethods at F4 turn some `raise`s into calls.** Then `Sink` is no longer absorbing for those `e`, and the error type records exactly which ones, which is the useful part.

**Theories.**

- *Known, probability.* Absorbing Markov chains: absorption is characterised once for the absorbing class, independently of the transient path taken. Kemeny and Snell, *Finite Markov Chains*, Van Nostrand 1960. `Sink` is the absorbing class, and the per-arm obligation is only "reaches the class".
- *Known, algebraic effects.* Plotkin and Pretnar, "Handlers of algebraic effects", ESOP 2009. `raise` is an operation with an empty continuation, so its meaning is fixed by one handler clause. Here that clause is the `pcall` in `main`, proved once.
- *Known, linguistics.* Presupposition failure: an utterance whose presupposition fails has no truth value. Strawson, "On referring", Mind 59, 1950. A stuck step has "no behaviour", but *which* presupposition failed is still meaningful and checkable. `Err` is the typed presupposition.
- *Novel.* Using the error-*kind* as the unit of the negative A1 obligation, which makes the stuck case of an arm a computable match between an `Err` constructor and a callee name.

**Pilot.**

- **Before anything else:** run `print("10"+1)`, `print(-"2")` and `print("3" & 1)` on the ELF under Sail, or on the native build with the same `linit`.
  - If any of them prints, the H suite's semantics is incomplete. Fix the suite (add coercion, or exclude arithmetic on strings in the test's fragment argument) before measuring anyone.
  - This costs three runs and it can falsify the suite, not just this idea.
- **A1 `ADD`, error half.** `ADD` with a boolean operand goes through the `ADD` arm's fail branch, then the head at `pc+1`, then the `MMBIN` arm, `luaT_trybinTM`, `luaG_opinterror` and `Sink`. Measure the lines with and without the typed `Err`.
- **A1 `EQI` and `FORLOOP`** have no error path in F1, so they cost 0 here. That is a useful control.
- **H2** `CONCAT` of a boolean goes to `luaG_concaterror` inside `luaV_concat`. **H3** `#` of an integer goes to `luaG_typeerror`. **H4** `<` on `int, str` goes to `luaG_ordererror`. On the semantic side each is one `Err` constructor with 0 proof lines. At A1, each is one branch-to-sink.

**Seed.** The bookends `cv9 … Ff9`: every path ends on the same `9`. A single absorbing end state, proved once.

## 3. Oracle cells: F2's non-determinism as a read of exogenous state, so the rulebook and the kernel stay functions

**Acts on.**

- **(c)** Objects to R1-3 #3's mitigation for F2 ("`Prog` can grow a `choose` node. Then `Graph.det` is lost only for arms that use it"). The same objection applies to R1-6 #1 and R1-4 #1, which are silent on non-determinism.
  - A `choose` node breaks L-A1 exactly at `next`, the first F2 feature. It also breaks L-B2, because `step?` stops being a function.
  - Layer B then needs *backward* simulation between two non-deterministic semantics, and Layer A needs the machine to be one resolution of the choice.
  - Every generic theorem round 1 built would need a relational (`multi`) twin.
- **(a)** Extends the existing `Host` parameter. `Value.show H` already takes the unknowable rendering of function addresses as a parameter rather than a choice. This idea makes that move the rule for *all* underspecification.

**The observation that makes this cheap.** Lua 5.4's `next` order is not non-deterministic. It is a deterministic function of three things:

1. the table's insertion and resize history;
2. the key hashes;
3. for table, function and userdata keys, their addresses, which enter the hash via `pointer2uint`.

String hashes depend on `G(L)->seed`, which `luai_makeseed` builds from `time(NULL)` and the addresses of a local and of the heap. *Recalled from `lstate.c`: check it, and check what `time` returns on this bare-metal image.*

So what the semantics does not know is small and nameable:

- `seed : Word`;
- `addr : ObjId → Word`, where `ObjId` is the allocation serial number of a collectable object;
- the `%p` rendering, which is the same `addr`.

**The idea.** Both semantics take an **oracle** `O : Oracle := { seed : Word, addr : ObjId → Word }`, as they take `Host` today.

- `next`'s order is `luaH_next` transcribed, i.e. a *function* of `(table contents and history, O)`.
- The rulebook, the kernel and `Step` are functions of `(state, O)`.
- Nothing is non-deterministic, so every round-1 generic theorem (`Graph_iff_run`, `holds_det`, `kernel_footprint`, `Step ↔ step?`) holds *for each fixed `O`* with no change.

**Core rules.**

- **L-A1 at F2** is `∀ O, LuaSem O c out ↔ ∃ n, luaRun O n c = some out`. This is the round-1 theorem, parametric in `O`.
- **Layer B needs one new law, L-B3 (naming).** Compiling preserves the allocation sequence: the k-th collectable object allocated by the source run is the k-th allocated by the bytecode run. Then the same `O` serves both sides, and `LuaSem O s out ↔ BcSem O (compile s) out` is stated at a fixed `O`, which is forward simulation only, as now.
  - L-B3 is checkable cheaply by differential logging of allocation sites.
  - It fails if `luac` allocates something the source semantics does not, such as a closure for a constant function, or a constant string. *Check which of these are interned constants in the `Proto`, allocated before the run starts, versus runtime allocations.*
- **Layer A** is `BcSem (O_of c) p out ↔ Halts c out 0`, where `O_of c` reads the seed and the allocator's address sequence off the machine run. It is an existential witness pinned by the machine, not a universal quantifier.

**What it makes free.**

- Determinism and function-ness at F2 and F3 for the whole round-1 stack, instead of a `multi` twin of every generic theorem.
- The `tostring(t)` address and `Host.showBuiltin` unify: `Host` becomes the `addr` part of `O`.
- `os-trace` (per trace, facts about `next`) becomes per-trace *evaluation* of a function of `O`. Its facts stop being inversions of a choice.

**What it costs.**

- Transcribing `luaH_next`'s traversal order faithfully: array part, then hash nodes in node order. That is the price of determinism. The trusted text must include the hash table's layout, not just "some order". That is a real faithfulness burden, about 150 lines of `ltable.c` model.
- **L-B3 is new, and can fail.** GC timing does not affect allocation *order*, but it affects addresses. The addresses are in `O`, so that is fine. The order depends on the program, and on both sides it follows the same evaluation order, since Layer B already fixes evaluation order to `luac`'s.
- **Where it breaks.** If `luaH_resize` is triggered by GC (it is not in 5.4: tables are not shrunk by the collector; *check `lgc.c`, which does not call `luaH_resize`*), or if weak tables clear entries at GC time. With weak tables, GC timing becomes observable in `next`, and then `O` must include a GC schedule. Weak tables are an F2+ corner, and `Supported` could exclude `__mode`.

**Theories.**

- *Known, economics.* Contingent commodities: Debreu, *Theory of Value*, Wiley 1959, ch. 7 ("Uncertainty"), and Arrow, "The role of securities in the optimal allocation of risk-bearing", Rev. Econ. Stud. 31, 1964. Uncertainty is modelled by indexing everything by an exogenous *state of nature*, and the equilibrium theory for certainty then carries over verbatim. Here the round-1 theorems for a deterministic semantics carry over verbatim at each `O`.
- *Known, probability.* Kolmogorov's sample space (*Grundbegriffe der Wahrscheinlichkeitsrechnung*, 1933): a random variable is a *deterministic function* of `ω`. `O` is `ω`.
- *Known, verification.* Prophecy variables: Abadi and Lamport, "The existence of refinement mappings", TCS 82(2), 1991. Future choices are made up front so that refinement mappings exist, and `O_of c` is the machine's prophecy. It is not a distant field, but it names the Layer A move.
- *Novel.* Keying the oracle by *allocation serial*, and making Layer B's extra law (L-B3) a naming invariant rather than a choice-matching simulation.

**Pilot.**

- **Honestly: no H case exercises this.** Strings are values here, and nothing in H1–H4 depends on `seed` or `addr`. `LEN` on a string does not hash, and interning is an A1 representation issue only.
- **The cheap falsifier**, with no Lean:
  - Build a fixed-seed native Lua (patch `luai_makeseed` to a constant). Run a program that fills a table with 50 string keys and 5 table keys, twice, the second time after one extra dummy allocation.
  - Prediction: string-key order is identical in both runs; table-key order may differ.
  - Then run with `collectgarbage()` inserted at 10 random points. Prediction: the order is unchanged.
  - If the order changes with GC and no weak tables are involved, the oracle must include the GC schedule, and the idea is much weaker.
- **Smallest Lean build:** `Oracle`, and `luaH_next` for the hash part only, over string keys. Then the round-1 rulebook's `Graph_iff_run` is re-used unchanged at a fixed `O`, and the pilot measures 0 new lines of generic proof.

**Seed.** `jYj` and `KUK`: a fixed frame with one free letter in the middle. The free letter is *named* and supplied from outside (the oracle), not chosen inside the rule.

## 4. Two-tier footprints: static register ports, plus an adaptive heap certificate, plus one GC-invisibility theorem

**Acts on.**

- **(c)** Objects to the static-port kernels R1-4 #1, R1-3 #1, R1-5 #1 and R1-6 #1. The shared premise is that `rd : Word → List Nat` is a function of the instruction word alone. R1-6 #1 noted one break (CALL with `B = 0`) and called F1 and H "not affected". The break is wider and arrives with F2/F3:
  - **`top`-dependent ranges.** `CALL B=0` reads `[A+1, top)`, `RETURN B=0` reads `[A, top)`, `SETLIST B=0` reads `[A+1, top)`, and `VARARG C=0` writes `[A, A+nvarargs)`. `top` is set by the previous multi-result instruction.
  - **Heap reads through a value.** `GETTABLE`, `GETFIELD`, `GETUPVAL`, `SELF`, and `LEN` on a table (`luaH_getn`) read cells whose *addresses* are register *values*.
  - **GC.** Every allocating opcode (`NEWTABLE`, `CONCAT`, `CLOSURE`) may run `luaC_step` through `checkGC`.
- **(a)** Extends R1-5 #2 (the query monad). Its certificate lemma does not need static labels. It holds for *adaptive* decision trees, where the next query depends on earlier answers. That is exactly a heap read through a pointer.

**The idea.** A kernel has two tiers.

1. **Register ports.** These are static in `(p, pc, w)` as in round 1, plus one **pseudo-register `top`**. Ranges `[x, top)` are allowed, and the port list is a function of `w` and the value of `top`, which is itself a port. Registers stay in the dataflow analysis. `Supported` tracks `top` as a symbolic "open range from `x`", which `luac` produces in adjacent pairs (`CALL C=0` followed by a consumer with `B=0`).
2. **A heap query program.** This is a free monad over `load : Loc → Value` and `store : Loc → Value → _`, whose locations are computed from port values and earlier loads. It is *not* in the dataflow: the heap has no definite-initialisation problem, because every reachable object is initialised when it is allocated.

**Core rules.**

- **L-B1, register tier.** This is the round-1 theorem unchanged, plus the `top` port.
- **L-B1, heap tier (`cert_footprint`), proved once for all query programs:**
  - If `run q h₁ = (r, log)` and `h₂` agrees with `h₁` on `log`, then `run q h₂ = (r, log)`.
  - Stores go only to locations in the log.
  - This is R1-5 #2's certificate lemma, lifted from registers to the heap and made adaptive.
- **`gc_invisible`, proved once.** Let `Reach s` be the heap cells reachable from roots (registers below `top`, upvalues, `_ENV`, the registry). A collector step `gc : Heap → Heap` changes only cells outside `Reach s`, plus GC metadata (mark bits, gray lists, `GCdebt`), which no query reads.
  - Every query program's log lies inside `Reach s`: it starts from ports and follows pointers.
  - So `run q (gc h) = run q h`, and the heap part of the simulation stutters across GC.
  - This relies on Lua 5.4's collector being **non-moving**, in both incremental and generational mode. *Check this, and check that `luaC_fix`ed strings are covered.*

**What it makes free.**

- **Footprint for every F2 heap opcode.** The register half is round 1's theorem. The heap half is `cert_footprint`. Per opcode this is 0 lines.
- **Every GC-point obligation at A1.** In the machine simulation, `checkGC` in an arm is a call whose effect, viewed through `Rep`, is the identity on the VM-visible state, by `gc_invisible` plus `Rep` mentioning only reachable cells.
  - This is the "GC is the hard part" that R1-1 #5 and R1-3 #5 flagged and left open. It is stated once, not per allocating arm.
  - It also meets H2 at A1: `OP_CONCAT` calls `luaV_concat` and then `checkGC`. *Recalled: check that `checkGC` is in `OP_CONCAT` in 5.4.7.*
- **The `B = 0` / `C = 0` forms of `CALL`, `RETURN`, `SETLIST` and `VARARG`.** They stop being the place where "applicative breaks and monadic appears" (R1-6 #1). Only `top` is dynamic, and it is a port.

**What it costs.**

- **`Reach` must be defined over the machine's actual root set.** Missing a root (the C stack's `TValue` temporaries during `luaV_concat`, or the `L->top` scratch) makes `gc_invisible` false. It is a precise, one-time, large definition.
- **The heap tier leaves the dataflow, so `Supported` knows nothing about it.** That is correct for initialisation, but it means L-B1's use in *Layer B* (compiler TV) needs a heap correspondence, i.e. a separate simulation relation for objects.
- **Open upvalues alias registers.** This is the same point as idea 1: a register-tier write can change a heap-tier read. The `top`/register tier and the heap tier must be declared disjoint *except* through a named `UpVal` indirection, whose aliasing is resolved when the upvalue is closed. That is the F3 risk.

**Theories.**

- *Known, databases.* Queries under access patterns (binding patterns): a source can be read only by supplying bound inputs, and a plan is executable iff each lookup's inputs are bound by earlier results. Rajaraman, Sagiv, Ullman, "Answering queries using templates with binding patterns", PODS 1995 (*check*). The register ports are the statically bound inputs, and heap loads are dependent lookups whose keys are bound by earlier answers.
- *Known, physics.* Gauge invariance: physical observables are invariant under transformations of unobservable degrees of freedom, and it suffices to prove invariance once for the class of observables. Jackson and Okun, "Historical roots of gauge invariance", Rev. Mod. Phys. 73, 2001. Here GC is a gauge transformation of unreachable cells and metadata, and every query log is gauge-invariant.
- *Known, concurrency.* The collector as a process invisible to the mutator: Dijkstra, Lamport, Martin, Scholten, Steffens, "On-the-fly garbage collection: an exercise in cooperation", CACM 21(11), 1978.
- *Novel.* Splitting the footprint law by tier. The static tier feeds the definite-initialisation dataflow, and the adaptive tier feeds a certificate lemma. `top` is a port rather than a break of the applicative discipline.

**Pilot.**

- **On H1–H4: nothing on the semantic side**, honestly: strings are values. At A1, H2's `CONCAT` arm is the first place `gc_invisible` is needed, and `LEN` on a string reads `tsslen` from the `TString` header, a one-query heap program.
- **The cheap falsifier**, a text exercise on `lopcodes.h` and `lvm.c` with no Lean:
  - Classify all 83 opcodes. Does each one's *register* footprint depend only on `w`, `K` and `top`?
  - If any opcode reads a register at an index computed from a register *value* other than `top`, the two-tier split fails. My prediction is none, and `VARARG` is the one to check.
  - Separately, check that 5.4.7's `lgc.c` never moves an object.
- **Smallest Lean build:**
  - the query monad over a toy heap;
  - `cert_footprint`;
  - `gc_invisible` for a mark-sweep toy;
  - `GETFIELD` and `SETFIELD` as two-tier kernels.

  Measure 0 per-opcode footprint lines.

**Seed.** `p0` twice (`fp0Bb`, `qp0qP`): a pointer, dereferenced. `p0` inside the near-palindrome `qp0q` suggested a read that goes out through a pointer and comes back, i.e. an adaptive query.

## 5. Proof-directed compilation: rebuild the ELF so that the orbits are exact, then prove one arm per trie node

**Acts on.**

- **(d)** No round-1 idea proposed changing the *artefact* rather than the proof. The ELF is this project's own build, so its compiler flags are a design parameter.
- **(c)** The coordinator's ELF check refutes R1-6 #4's transport group `Relabel = shift + ALU substitution`:
  - ADD/SUB differ in *one branch sense*. That is a block-layout choice, not an ALU substitution.
  - MUL-family arms differ by *register allocation and scheduling*. `mul`'s latency makes gcc's scheduler move it, so the group needs trace equivalence (R1-1 #5) or renaming. Both are expensive.
- **(a)** Extends R1-5 #4 (orbits) and R1-3 #2 (templates by anti-unification).
  - The observed *identical openings* (BAND/BOR/BXOR, LTI/LEI/GTI/GEI, ADDK/SUBK, LT/LE) say the right quotient is a **prefix trie** of arms, not an orbit.
  - Arms share a prologue exactly, and diverge at the first differing instruction.
  - A proof per trie *node* covers every arm under it.

**The idea.** Two moves, and the second depends on the first.

1. **Canonicalising build.** Build `lvm.c` alone with flags that forbid the transformations that broke the orbits: `-fno-schedule-insns -fno-schedule-insns2` (scheduling), `-fno-reorder-blocks` (branch sense and layout), `-fno-crossjumping -fno-tree-tail-merge` (shared tails), and `-fno-ipa-ra`. *Recalled flag names: check them against the project's gcc version.*
   - The flags do not change semantics.
   - The proof is about whatever ELF is built, so no trust changes. The build recipe is part of the artefact, as it is now.
2. **Arm trie.**
   - Take the arms' instruction sequences from their jump-table entries to their first control transfer, and build a trie.
   - Each internal node carries a **symbolic summary**: the effect of its instruction sequence on the representation, as a μ/RCW prefix.
   - Each summary is proved once, and the arm's simulation starts from its divergence node.
   - Under canonical flags, the trie's branching is expected to be exactly the ALU instruction or the comparison, which is R1-3 #2's single hole. The trie is the fallback that still works where flags do not fully canonicalise.

**Core rules.**

- **L-C1 becomes `trie_sim`.** It composes node summaries along a root-to-leaf path, and it is proved once by induction on the path. Each node's summary is proved against Sail once.
- **The per-arm obligation** is the leaf's suffix plus the `Implements alu f` fact. These are the ISA's own `add`/`sub`/`and`, stated once each.
- **Orbit transport (R1-5 #4) becomes a special case.** It is a trie whose internal nodes all have one child except at the ALU position.

**What it makes free.**

- A1 cost becomes proportional to **trie nodes of distinct content**, not to arms. The coordinator's partial orbits already give roughly 4 + 4 + 2 + 2 members sharing openings. Under canonical flags the rr-arith family (ADD, SUB, MUL, BAND, BOR, BXOR) should collapse to one path plus six leaves.
- The **measure-first check that R1-3 #2 asked for** (the least general generalisation of the arith arms) becomes a reproducible build output, not a property of whatever gcc happened to do.

**What it costs.**

- **A rebuild of the ELF, and regeneration of everything that depends on it.** The last merge did exactly that ("ELF and all dependents regenerated"), so the cost is known and not small.
- **Performance of the interpreter falls**, probably a few percent without scheduling. That is irrelevant to the theorem, but visible to anyone benchmarking.
- **The flags may not canonicalise everything.** Register allocation still differs if the ALU op needs a different register class, as `mul` might through its multi-cycle scheduling. Then the trie absorbs the rest: the divergence moves earlier, and the cost is more nodes, never more than the incumbent.
- **It does nothing for `bc-rule-fanout` or `ast-construct-fanout`.**

**Theories.**

- *Known, hardware testing.* Design for testability: modify the artefact's structure (scan chains, level-sensitive scan design) so that verification becomes tractable, at a small cost in area and speed. Eichelberger and Williams, "A logic design structure for LSI testability", DAC 1977.
- *Known, manufacturing.* Design for assembly: Boothroyd and Dewhurst, *Design for Assembly: A Designer's Handbook*, 1983 (*check the edition*). One of its principles is to make parts symmetric, so that orientation does not matter and handling cost falls. The canonicalising flags make the arms symmetric in the same sense, so one proof "handles" every orientation.
- *Known, phylogenetics.* Felsenstein's pruning algorithm: "Evolutionary trees from DNA sequences: a maximum likelihood approach", J. Mol. Evol. 17, 1981. Likelihood is computed once per internal node of the shared ancestry tree, not per leaf. Here the obligations are computed once per trie node.
- *Novel.* Treating compiler flags as a proof-cost parameter chosen *by the verification*, with the trie as the degradation path.

**Pilot.**

- **The smallest falsifier is one build and no Lean.** Rebuild `lvm.o` with the flag set, objdump the jump-table targets, and recompute the coordinator's comparison.
  - Keep the idea if:
    - ADD/SUB/MUL/BAND/BOR/BXOR are ALU-substitution-identical;
    - LTI/LEI/GTI/GEI differ only in the branch opcode;
    - the orbit count under substitution-only is at most about 20 for 54 arms.
  - Falsified if the flags change nothing, or if the orbit count stays above about 35.
- **A1 arms.** Prove `ADD` from the trie root, then report the *marginal* lines for SUB, MUL and BAND. The target is the `Implements` fact plus about 5 lines. `EQI` and `FORLOOP` are singletons and measure setup only, as R1-5 #4 and R1-6 #4 already conceded.
- **H.** The `LT` string path (`lessthanothers` → `l_strcmp`) becomes one extra trie branch under the `LT/LE` node, not a new arm.

**Seed.** `fff` near the end, and `fFf` at the very end: the same run twice, differing in exactly one position. That is a shared prefix with one divergence, i.e. a trie with a single branching point.

## The hard questions, answered

**Should `Step`/`LuaSem` be redefined as data, or should the readable inductive stay?**

- **Keeping the inductive** costs one equivalence arm per rule, about 2–4 lines. That cost recurs for every new opcode and construct.
- It also grows with the rule's premises. At F2, heap premises (idea 4) make each arm larger. At F3, closures and aliasing make it larger again. The equivalence cost therefore *rises* with exactly the fragments that are coming.
- **Redefining** has a one-time TCB review, and it scales flat.
- My position is to redefine, and to make the review mechanical rather than trusted:
  - the kernel/rulebook is the `step?`/`luaRun` that the difftests already exercise against native Lua;
  - idea 2's typed errors extend those difftests to error behaviour;
  - the named constructors survive as derived one-line lemmas (R1-5 #1's "pedomorphism") for downstream `cases`-style proofs.
- **At F2**, non-determinism does not force a relation, provided it is an oracle (idea 3). With a `choose` node, every generic theorem needs a relational twin, and *that* would favour keeping inductives. Idea 3 removes the reason.

**Which idea actually reduces A1?** A1's per-arm cost has four parts. Round 1 attacked two of them.

| part of an arm's proof | ideas that attack it | cheapest falsifier |
|---|---|---|
| the positive straight line | lifters (R1-1 #5, R1-2 #5, R1-4 #4); templates and orbits (R1-3 #2, R1-5 #4, R1-6 #4); **idea 5** | one canonicalising build plus objdump (idea 5); a *Python* prototype of R1-4 #4's idiom parser on ADD/EQI/FORLOOP, counting new idioms per arm, before any Lean |
| the frame (every other slot, the heap, the C stack) | lens / tether / LowEq (R1-3 #5, R1-5 #5, R1-6 #5); **idea 1** for killed slots; **idea 4** for GC | state `Rep` with no ⊥ clause, and check that `CALL`'s `kill` keeps `Supported whileProto` true |
| the negative (stuck) half | **idea 2** only; round 1 treated it as free | three native runs: `"10"+1`, `-"2"`, `"3"&1` |
| callees (`luaV_concat`, `l_strcmp`, `luaV_objlen`, GC) | callee contracts (R1-2 #4, R1-4 #5); **idea 4** for GC | check `checkGC` in `OP_CONCAT` and non-moving `lgc.c` |

**Ranking.**

- The biggest A1 lever is still a **verified lifter or parser**. It is the only way per-arm cost becomes a computation.
- It is also the most expensive setup, so the right order is:
  - **idea 5's build first.** It costs one build, and it makes the lifter's idiom set and the templates smaller.
  - **R1-4 #4's idiom parser in Python next.** If new idioms per arm do not fall to about 0 by the third arm, stop before writing Lean.
  - **ideas 1, 2 and 4 in parallel.** They remove the frame, stuck and GC halves that no lifter makes free.

**Before any bake-off.** Idea 2's `"10"+1` check should run first. If the image installs the string metatable, then H1 plus F1's arith rules make `vm_refinement` false, and every contender would be measured against a wrong semantics.
