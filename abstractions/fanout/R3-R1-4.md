## 1. Holdover decoding: the relation as the graph of a decoder, closed by image

*Seed:* **holdover** (the state held over from one head crossing to the
next) and **shadowily** (the L-C4 checker rebuilds a shadow memory and
decodes it; make that decoder the relation).

### The idea

L-C4 is stated operationally: *decode* memory at the head and compare the
result with `step?`. The Lean relation instead says it relationally, field
by field (`Core.stack`, `Core.frame`, `kptr`, …), and each arm has to
re-establish each field (the closes, `slotStore_*`, `*_of`). Make the
checker's decoder the relation:

```
dec    : Proto → MState → RelPtrs → VState (Option Value)   -- total; reads bytesT*, never presence
VmRel p c s := ∃ w, Inv p c w ∧ s ⊑ dec p c w                 -- ⊑ : s.regs j = some v → dec.regs j = some v,
                                                             --     pc and out equal
```

- `dec` reads the pc from s11, `out` from the console, and each `R[j]` by
  decoding the 9-byte *image* of `[w.slot j, w.slot j + 9)`. That image is a
  `Fin 9 → BitVec 8`, not a store history.
- `Inv` is everything else (pins, ranges, complement), stated as a predicate
  with a **declared support** `supp Inv w : Set Addr` (a dynamic frame).
- Relocation is free because `dec` recomputes `base` from the `ci->func`
  word each time. `VmRel` already decodes relative to `func`; the change is
  that `dec` is a function, not an existential that must be transported.
- `⊑` is exactly the `Agree`/`Cert` direction that `Kernel.lean` already
  proves (`certain_answers`). Kill ports cost nothing: `⊥ ⊑ anything`.

`ValRepr` is a relation and is not functional: nil is any tag with
`t % 16 = 0`, and a string is decoded through `TStringRepr`. So define
`dec` as the canonical choice, and prove the one lemma
`ValRepr mo t x v ↔ decTV mo t x = some v` for the F1 values. Strings need
`TStringRepr` to be functional: bytes are read from the header's length and
contents. This must be checked, but I believe it holds, since
`TStringRepr mo a s` pins the length.

### Core rules

- **R1 (L-C4 → `dec_step`).** `sim_X` becomes an equation about images:
  `Inv c ∧ Inv c' ∧ dec c' ⊒ (dec c).apply e o`. Here `(e, o) = decide? (dec c)`
  is the edge taken. By the `footprint` theorem already in `Kernel.lean`,
  `s ⊑ dec c` together with `Step s s'` gives `s' ⊑ (dec c).apply e o`.
  So an arm proves `dec c' = (dec c).apply e o` on the def ports and the
  surviving registers, and never talks about `s`.
- **R2 (L-C6′ store half → `dec_image`).** `dec p c' w` depends on
  `c'.mem` only through the image of the slots. Hence:

  > If `c'.mem` and `c.mem` have the same image outside the def slots, and
  > the def slot `j`'s image is `encTV v`, then
  > `dec c' = (dec c)[j ↦ v]`.

  Tag-first, payload-first, tag-only, payload-only and FORLOOP's four
  payload stores all normalise to "final image of the slot". The four store
  shapes and every `slotStore_*` lemma collapse into two lemmas:
  `image_of_stores`, which is list induction over byte stores, and the
  rule above.
- **R3 (L-C6′ frame half → `Inv.frame`).** Stated once:

  > If `∀ a ∈ supp Inv w, c'.mem a = c.mem a`, the pins hold, and
  > `Inv c w`, then `Inv c' w`.

  `{ci->savedpc, L->top}`, the own C frame and everything below `sp` are
  outside `supp Inv`. So `Protect`'s stores and a pure callee's frame are
  framed with no lemma at all.

### What it makes free

- **(c) frame/relation maintenance** (28 decls, 245 lines). The closes
  `Core.write`/`jump`/`update`/`forloop`, the `slotStore_*` variants,
  `ForStore` and the `*_of` transports are replaced by R2 and R3. A new close
  shape costs 0, where it now costs 9–39 lines.
- **(d1) relation widening, for the "scratch" resources.** `savedpc` and
  `L->top` never become fields: they are outside `supp Inv`, and a
  resource that no head-state fact depends on is simply not in the support.
  Widening turns into *shrinking the support*, and the default is empty.
- **Relocation (VARARGPREP, realloc).** `dec` reads `func` fresh, so the
  "`R[<A]` preserved up to relocation" part of L-C3′ runtime becomes
  "`dec` restricted to `j < A` unchanged". That is a statement about decoded
  values, which is invariant under the move. The byte-level transport is
  gone.

### What it costs

- **Setup.** `decTV` and the `ValRepr ↔ decTV` lemma (≈ 60 lines, an
  estimate). `dec`, `⊑`, and `image_of_stores` (≈ 50). `Inv` with `supp`,
  and `Inv.frame`: this is a restatement of `Complement`/`Ranges`/`Pins`,
  and each field needs a support clause, ≈ 80. `VmRel ↔ ∃ w, Inv ∧ ⊑`, to
  keep the public theorem shape, ≈ 40.
- **What gets harder.**
  - `supp Inv` has to be correct for the heap parts (`DlHeap.HeapAt`,
    `LuaStateAt`), whose supports are data-dependent: chunk lists, string
    lengths. It is a dynamic frame, so its support moves as the heap
    changes.
  - Every string value makes the decoder read the heap, so `dec`'s support
    includes live string bodies.

### Theories

- **Well-behaved lenses (known).** Get-put and put-get laws: R2 is put-get
  for the "slot j" lens on memory. Foster, Greenwald, Moore, Pierce,
  Schmitt, *Combinators for bidirectional tree transformations*, TOPLAS 29(3),
  2007.
- **State observers in control theory (known).** A Luenberger observer
  reconstructs internal state from outputs; L-C4 says the observer error is
  exactly zero at every sampling instant (head crossing). D. G. Luenberger,
  *Observing the state of a linear system*, IEEE Trans. Military Electronics
  8(2), 1964 (recalled; check the venue).
- **Dynamic frames (known).** Kassios, *Dynamic frames: support for framing,
  dependencies and sharing without restrictions*, FM 2006. This is R3.
- **Novel here:** the combination of `⊑` (the certain-answers direction of
  `Cert`) with the image-based decoder. The kill ports then need no machine
  fact, and the kernel's `footprint` does the transport.

### Pilot

- **Build:** `decTV`, `dec`, `⊑`, `image_of_stores`, `dec_image`, `Inv` and
  `Inv.frame`, but only the fields ADD needs. Then refactor `sim_ADD`:
  - its close becomes "the image of slot A is `encTV (int (x+y))`" plus
    `Inv.frame`;
  - its pc+1 exit is "no store in the slots", so `dec c' = (dec c)` with a
    new pc.
- **MUL:** the same tree as ADD, with the store payload first; R2 does not
  care about the order. The `__muldi3` call needs idea 2's call node. After
  the call, the only facts needed are "memory ≥ sp unchanged" (R3 frames it)
  and "a0 = x*y".
- **EQ:** no slot stores. The `Protect` stores are outside `supp Inv`, and
  `luaV_equalobj`'s frame is below `sp`. `dec c' = dec c` with the pc set
  to pc+2 or to the `donextjump` target. The trap reload `lw t6,40(s7)`
  reads `ci->u.l.trap`, which *is* in `supp Inv` (`trap_word`) and is
  unchanged.
- **MOD:** the `Protect` stores are framed by R3; the sign fix-up is a value
  lemma, `r + d = imod` (see idea 4).
- **Measure:** the hand lines of the close part of each proof. The
  prediction is 0 new close or store lemmas for all four arms.

## 2. Cuckoo call nodes: helper obligations as residuals of the kernel, not contracts

*Seed:* **cuculiform** (the cuckoo lays its egg in another bird's nest: the
callee builds its frame in our stack, below `sp`, and the host raises
whatever hatches) and **keelhale** (dragged under the hull: the call goes
below `sp` and comes back up).

### The idea

Do not write "a contract per helper". Give the arm executor **one call node
per callee shape**: pure, runtime and noreturn. Each node is parameterised by
an *uninterpreted* denotation `f`. The arm is proved once against the node,
with `f` abstract. What the arm proof needs from `f` is then *computed*: it
is the **residual** (weakest prespecification) of the kernel obligation by
the arm's inline context. For the soft-int arms that residual is a value
equation which δ already names, for example `f(x, y) = BinOp.int .mul x y`.
The shape and the residual together are a table row
`(symbol, shape, residual as a δ-term, argument decoding)`. The helper
layer, a separate proof about the helper's own code, discharges the row;
`Muldi3Spec` and `udivdi3_spec` already exist at WHILE addresses.

The node, for **pure** (this is L-C3′ pure):

```
jal_pure h f :  pc = jal→h, shape h = pure, args = (a0..a7, and memory reads through arg pointers)
   ⟹  one abstract step to ra, with a0 := f(args, memory image of the arg-pointed slots),
       s0–s11, sp, gp unchanged, memory ≥ sp unchanged except declared out-pointers,
       memory < sp and t*/a1–a7 havocked.
```

The **noreturn** node is `jal_noreturn h : ⊥`. The arm's path through it
contributes nothing to `sim_X`, **because of the `Step p s s'` premise.**
The noreturn paths are exactly the paths where the kernel is stuck:

- MOD/IDIV with d = 0, where `imod` is `none`;
- the `luaG_opinterror` family, where δ has no rule.

In each case the path condition contradicts `decide? s = some _`, so the
noreturn node closes by `absurd`. This takes the 81-function error chains out
of `sim_X` entirely; they stay only for `stuck_sim`.

**Runtime** is idea 3's node.

### Core rules

- **L-C3′ pure → `jal_pure`.** One theorem, proved once from the RISC-V ABI
  facts: callee-saved registers and `sp` are restored, the stack below `sp`
  is scratch. It is parameterised by `f`.
- **L-C3′ noreturn → `jal_noreturn` + `stuck_infeasible`.** The second rule:
  if the path condition implies `kstep (dec c) = none`, the path is vacuous
  for `sim_X`.
- **L-C4 on a path with a call → `residual`.** The arm is proved with `f`
  abstract. The unproved leaf obligation is `f(args) ⊨ δ-term`, and
  `residual` is the rule that lifts that leaf back to a table row. No
  helper name appears in any arm proof.

### How it fixes SymExec's three losses (if built into SymExec)

1. **No call nodes.** The three nodes *are* the call nodes, and their
   soundness is proved once.
2. **Weaker theorem.** `jal_pure` is stated on total reads and `RegsOk`,
   both of which are already in `VmRel` since `2332c06`. So the result is
   `VmRel → VmRel`, not `VmRelZ`.
3. **2–4× hand lines.** Most of SymExec's per-arm hand lines were guards and
   kernel matching, and ideas 4 and 1 remove those. The call node adds 0
   lines per arm, because the residual is read off the stuck leaf. This is
   an estimate; the bake-off must measure it.

### What it makes free

- **(b) callee contracts, for the 10 of 11 helpers that are pure on normal
  paths.** Each of `__muldi3`, `__moddi3`, `__divdi3`, `__udivdi3`,
  `luaV_equalobj`, `l_strcmp`, `luaH_getshortstr` and `luaV_tointeger`
  (with its `sp+40` out-pointer declared) needs a *row*, not a contract. The
  row's residual is generated by the arm proof.
- **The error chains** (81 functions, 11,608 instructions) vanish from
  `sim_X`.
- **Arms sharing a tree with a callee leaf.** MUL/MULK join the ADD tree
  with `f` at the leaf, which is L-C2′ extended to call leaves.

### What it costs

- **Setup.** The abstract step for `jal`: the executor must accept a
  "summary step". Also the ABI lemma, and `stuck_infeasible` (≈ 20 lines,
  from `kstep_iff`).
- **Discharging the rows is still work, but it moves to the helper layer**,
  where it is reusable. The WHILE batteries must be restated at the Lua
  ELF's addresses. That is address-relative work, since the helper code is
  the same libgcc.
- **`luaV_equalobj`'s residual is subtle.** It is
  `a0 = (decTV slotA = decTV slotB)`. For long strings this is content
  equality (`luaS_eqlngstr`), which matches δ `.eq` on `Value.str` bytes.
  For short strings it is pointer equality, which is sound only if
  interning holds: a heap invariant, and so part of `supp Inv`. Check this.

### Theories

- **Weakest prespecification / residuation (known).** Hoare and He, *The
  weakest prespecification*, Fundamenta Informaticae 9, 1986/87 (recalled;
  check). Residuated lattices: Ward and Dilworth, Trans. AMS 1939.
- **The unknown-component problem in logic synthesis (known, distant
  field).** Given a circuit with a hole and a spec, compute the largest
  Boolean relation the hole may realise. Watanabe and Brayton, ICCAD 1993;
  Villa et al., *The Unknown Component Problem*, Springer 2012 (recalled).
  The helper is the hole.
- **Assume/guarantee contract quotient (known).** Benveniste et al.,
  *Contracts for System Design*, Found. Trends EDA 12(2–3), 2018: the
  quotient operator.
- **Novel here:** using the Step premise to make noreturn callees vacuous,
  which moves every error chain from the simulation side to the stuck side.

### Pilot

- **Build:** the `jal_pure` node for register arguments only, and
  `stuck_infeasible`.
- **MUL:** the ADD tree with a `jal_pure __muldi3 f` leaf. The residual is
  `f(x, y) = x*y`, and the row cites `Muldi3Spec` re-addressed. Note that
  `addi s11,s11,8` comes *before* the `jal`, so the pc pin must survive the
  call; s11 is callee-saved, which the node gives.
- **MOD:** `bgeu 1, d+1` splits d ∈ {0, −1}:
  - d = 0 is `stuck_infeasible`, since `imod _ 0 = none`;
  - d = −1 is an inline path (`0 − m`, or `0` for mod);
  - otherwise the path is `jal_pure __moddi3 f` followed by the sign
    fix-up. The residual is `f = C's truncated %`, and the fix-up is idea 4's
    value lemma.
- **EQ:** `jal_pure luaV_equalobj f` with pointer arguments. This needs the
  "reads through argument pointers" extension of the node, which this pilot
  measures.
- **ADD refactor:** unchanged by this idea, since it makes no call; this is
  the control.

## 3. Auxospore regrowth: re-grow the relation at the head instead of transporting it

*Seed:* **auxospore** and **division**. A diatom shrinks with each division
until an auxospore restores full size. Each runtime call shrinks what the
relation knows, and the head restores it from a canonical invariant. Also
**insuperableness**: the runtime footprint cannot be carried field by field.

### The idea

L-C3′'s *runtime* shape (CALL, VARARGPREP, RETURN, stack growth) is where
`VmRel` would widen four more times: savedpc/`L->top`, `func` moving, heap
and `G` evolving, the console. Do not transport the head relation across a
runtime callee. Instead, prove ONE **regrowth theorem**, a generalisation of
`vmRel_entry` from "boot" to "any runtime-consistent state at the head":

```
regrow : RtOk m L ci  →  pins reloaded (s0 = L, s7 = ci, s9 = rd ci->func + 16, s11 = rd savedpc′,
                         s5 = rd ci->trap)
       → s ⊑ dec m      →  VmRel p c s
```

- `RtOk` is the *runtime's own* invariant: `luaRuntimeReady`'s
  `LuaStateAt`, `DlHeap.HeapAt`, `ErrorJmpAt`, stdio state, and "`ci` is the
  main activation of `p`". It is maintained by the runtime helpers' shape
  proofs, not by `VmRel`.
- The runtime node then promises only:
  - (i) `RtOk` holds after the call;
  - (ii) `dec` restricted to `j < A` is unchanged. This is decoded, so it is
    relocation-invariant.
  - (iii) the result slots decode to the kernel's def values or the kill
    range, and the console grows by `printLine`.
- The arm's tail (`updatebase`, `updatetrap`, the `trap` → `luaG_traceexec`
  path after a realloc) re-reads everything the pins need *from memory*. So
  the pins are re-derived, not transported. The disassembly confirms this:
  EQ and MOD reload `trap` from `40(s7)` after the call.

Entry is the first sporulation: `vmRel_entry` is `regrow` applied to the
boot state.

### Core rules

- **L-C3′ runtime → the runtime node** (footprint = `RtOk`-preserving, plus
  slots from `R[A]` up) **plus `regrow`.**
- **L-C4 → `regrow`'s `s ⊑ dec` premise.** The "runtime" arm needs no
  relation transport at all, only the decoded-value facts (ii) and (iii).
- **(d1) → "add the resource to `RtOk`".** Each new resource is proved by
  the runtime layer, and is proved *once* for all arms.

### What it makes free

- **(d1) relation widening.** The four forecast widenings (Protect's
  savedpc/`L->top`, `func` moves, heap/strings/`G`, console) become
  `RtOk` conjuncts. These are facts the runtime layer must prove anyway for
  `luaD_precall`. `VmRel` stays fixed.
- **`vmRel_entry`** (+80 lines each time `VmRel` widened) becomes one
  instance of `regrow`, so widening no longer costs twice.
- **Stack relocation** (F3: realloc at 15–30 locals). This is free, because
  the relation is never carried across the move.

### What it costs

- **Setup.**
  - `regrow` is about the size of `vmRel_entry` plus the pin reloads: a few
    hundred lines, estimated from `vmRel_entry` +80 per widening.
  - `RtOk` must be *self-sufficient*: stated with `L->top`, `savedpc`,
    `ci->func` and `nci` existentially quantified, not pinned.
- **What gets harder.**
  - The runtime shape's soundness for `luaD_precall` → print is still the
    hard helper proof: 81 functions. This idea puts it where it belongs, in
    one shape proof, but does not make it smaller.
  - `regrow` needs `s11` to equal `code + 4·pc′`. After CALL, `s11` is
    callee-saved and restored. After a `luaG_traceexec` trap path it is
    reloaded from savedpc, so savedpc *is* observed on that path. Check
    which arms take the trap path under F1 (F3 says: only after realloc).

### Theories

- **Crash Hoare Logic (known).** A recovery procedure re-establishes the
  invariant from any crash state satisfying a weaker "crash condition".
  Chen et al., *Using Crash Hoare Logic for certifying the FSCQ file
  system*, SOSP 2015. Here the runtime callee is the "crash" and the head
  reload is the "recovery".
- **GC safepoints and stack maps (known).** The mutator may break
  invariants between safepoints, and the collector re-derives roots from
  maps at safepoints. Diwan, Moss, Hudson, *Compiler support for garbage
  collection in a statically typed language*, PLDI 1992 (recalled).
- **Diatom size restoration (known, biology).** The MacDonald–Pfitzer rule,
  1869–71 (recalled): progressive shrinkage over divisions, with an
  auxospore resetting size. Used here only as the structural pattern
  "degrade per step, restore at a checkpoint from a canonical form".

### Pilot

The held-out arms exercise only the Protect part of this idea; CALL is the
real test.

- **MOD, EQ:** their `Protect` stores (`sd s3,32(s7)`, `sd a4,16(s0)`) are
  inside `RtOk`'s existentially quantified fields, so no `VmRel` field is
  added. Measure: 0 lines of relation widening, against the census forecast
  of 100–250.
- **MUL:** unaffected, as a control.
- **ADD refactor:** state `vmRel_entry` via `regrow`, and check that
  `sim_ADD` does not change. That shows the relation is unchanged in shape.
- **Smallest build:** `RtOk`, restated from `RuntimeMem` with
  savedpc/`L->top` quantified, and `regrow` for the case "no relocation".
  Relocation is a follow-up measured on CALL with 20 locals (F3's probe).

## 4. Kelly reconciliation: a new tree is a reconciliation map, not guards plus an inversion

*Seed:* **kelly** (the square rod that transmits the rotary table's turn to
the whole drill string: one drive, one dispatch), **cymoscope** (an
instrument that *detects* oscillations: a machine branch detects an
observation of a value), **division** (MOD's extra splits), and
**Cirrostomi** (the lancelets: a bare skeleton, the P5 tree).

### The idea

The rising cluster is (a1) new trees, with their (a4) guards and (a5) kernel
inversions. Both are proved per tree today. Replace them with two
finite-language facts and one generic theorem.

1. **A tiny observation algebra `Obs`.** Its constructors are
   `tagIs k | tagMod16Zero | intLt | intLe | intEq | isFalse | kIsInt i | valEq`.
   It comes with *one* soundness theorem,
   `ValRepr mo t x v → machObs φ t x = obs φ v`. The theorem is proved by
   cases, once per constructor: about 8 cases where there are now 40 guard
   declarations. A machine branch (`beq a2,s2`, `bgeu`, `slt`) is labelled
   with the `Obs` it detects; that is the cymoscope.
2. **A kernel tree `KTree`.** Every kernel body in normal form is a decision
   tree over `Obs`, with leaves `(edge index, def values as δ-terms)`.
   `body = evalKTree (ktree K)` is proved **once per combinator**: `setR`,
   `opArith`, `docondjump`, `testsetK`, `forloopK`, `forprepK`, `mmbin`,
   about 7 of them. This replaces the per-tree kernel inversions: there are
   19 now, with the mean rising from 8.5 to 18.5 lines.
3. **Reconciliation.** Borrowed from phylogenetics: a gene tree is mapped
   into a species tree, with *duplication* and *loss* events. The machine
   arm's pruned tree (the gene tree) is mapped into the kernel tree (the
   species tree):
   - **Speciation:** a machine branch that detects the same `Obs` as a
     kernel split.
   - **Duplication:** a machine split with no kernel counterpart. Examples
     are MOD's `d ∈ {0, −1}` test and its sign fix-up, and ADD's float
     paths. Both children map to the *same* kernel leaf. Each duplication
     needs either a *value lemma* (both children compute the same δ-term,
     e.g. `r ≠ 0 ∧ (r ⊕ d) < 0 → r + d = imod m d`), or pruning by `Supported`
     or `stuck_infeasible` (idea 2).
   - **Loss:** one kernel split that the machine realises without a test.
     For example, EQ realises `valEq` inside `luaV_equalobj`, and the leaf's
     residual absorbs it.

   The generic theorem `reconcile_sound` states:

   > Given a valid map (every machine path condition entails the image
   > kernel path condition, and every machine leaf's effect, via `dec_image`
   > from idea 1, realises its kernel leaf's δ-term), the arm simulates the
   > kernel.

   The map is *data*, a list of `(machine leaf, kernel leaf, event)`.
   Validity is checked by `decide` on the finite trees, with `omega` or the
   value lemmas at duplication leaves.

The straight-line code between branches still has to run on the machine.
That uses whatever executor exists: the incumbent's generated runs, or
SymExec with idea 2's call nodes. This idea removes the per-tree
*reasoning*, not the execution.

### Core rules

- **L-C4 at the arm level → `reconcile_sound`.** Generic over trees.
- **The per-branch guard law** (ROUND-3 law map: "this branch decides the
  kernel's case predicate on the represented value") **→ `Obs.sound`.** One
  theorem, with a finite number of cases.
- **L-C2′ → the map is invariant under the P3p parameters.** Rows vary only
  the ALU op and constants, so one map serves each multi-arm tree.

### What it makes free

- **(a4) guard lemmas.** 40 declarations and 191 lines become about 8 cases
  of `Obs.sound`. No new tree adds a guard pair.
- **(a5) kernel inversions.** 19 declarations and 209 lines, with a rising
  mean, become about 7 `ktree_eq` lemmas, one per combinator. A new *tree*
  of an existing combinator costs 0 inversion lines.
- **(a1) new tree.** The cost drops from 30–273 lines to "a map plus the
  duplication value lemmas". MOD's sign fix-up is exactly an ALU value lemma
  (cluster a6), which is already falling (17 → 5).

### What it costs

- **Setup.** `Obs` and `Obs.sound` (≈ 60 lines). `KTree`, `evalKTree`, and
  the 7 `ktree_eq` (≈ 120). `reconcile_sound` (≈ 100). All are estimates.
- **What gets harder.**
  - Extracting the machine tree with labelled branches is a disassembly-side
    artifact that must be trusted or checked. Checking it is cheap: each
    label is an `Obs.sound` instance at that branch.
  - Duplications that need non-trivial value lemmas (the shift arms' amount
    branches, FORPREP) remain real work, but that work is per-ALU-op, not
    per-arm.

### Theories

- **Gene-tree/species-tree reconciliation (known, distant field).**
  Goodman et al., Syst. Zool. 1979; R. D. M. Page, *Maps between trees and
  cladistic analysis of historical associations among genes, organisms, and
  areas*, Syst. Biol. 43, 1994 (both recalled).
- **Translation validation (known).** Pnueli, Siegel, Singerman, TACAS 1998;
  Necula, PLDI 2000. A per-compilation check against a generic soundness
  theorem.
- **Decision-diagram refinement (known).** Bryant, IEEE TC 1986 (ROBDDs):
  containment between two decision structures over the same predicates.
- **Novel here:** using the kernel's finite `Obs` language as the shared
  species set, so that a guard is one instance of `Obs.sound`, and
  classifying compiler-introduced splits as duplications with a value lemma.

### Pilot

- **Refactor `sim_ADD`.** Speciation on `tagIs 3`, twice. Duplication on the
  float paths, pruned by `ValRepr` (F1 has no floats). The pc+1 leaf maps to
  `opArith`'s edge 1.
- **MUL.** Same map as ADD, with a changed row, plus idea 2's leaf.
- **EQ.** One kernel split `valEq`, realised by *loss* inside
  `luaV_equalobj`. Speciation on the `k` bit (`srliw a5,s4,15; andi 1; bne a5,a0`).
- **MOD.** Speciation `tagIs 3` ×2. Duplication d ∈ {0, −1}: d = 0 is pruned
  by `stuck_infeasible`, and d = −1 gets a value lemma. Duplication on the
  sign fix-up gets a value lemma.
- **Smallest build:** `Obs` with the 4 constructors these arms need
  (`tagIs`, `intEq` against a constant, `valEq`, the `k` bit), the
  `ktree_eq` lemmas for `opArith` and `docondjump`, and `reconcile_sound`.
- **Measure:** guard and inversion lines for MOD and EQ, both new trees.
  The prediction is 0 for both.

## 5. Ringworm grades: an effect-graded arm judgement over nested footprint rings

*Seed:* **ringworm** (a lesion in concentric rings), **tinted** (memory
coloured by role), and **baronage** (a graded hierarchy of tenure: who may
touch what).

### The idea

L-C6′ and L-C3′ list footprints that are *nested*, and each shape only adds
a ring:

| ring | what may change | who reaches it |
|---|---|---|
| 0 | the edge's def slots (images) | inline arms |
| 1 | + `luaV_execute`'s C frame `[sp, sp+176)` | every arm that spills |
| 2 | + `{ci->savedpc, L->top}` + memory below `sp` | `Protect` + pure callee: MOD, EQ, FORPREP, MMBIN* |
| 3 | + the named `L`/`ci`/`G` fields, slots from `R[A]` up, and owned heap | runtime callee: CALL, VARARGPREP, RETURN |
| ⊤ | never returns | noreturn |

Give the arm a **graded judgement** `c ⊢ₖ c'` ("the run from `c` to `c'`
changes at most ring k"), with the usual graded-effect rules:

- **seq:** `c ⊢ₖ c'` and `c' ⊢ₗ c''` give `c ⊢_{k ⊔ l} c''`;
- **weaken:** `k ≤ l`;
- **store:** a byte store to an address coloured ≤ k is at grade k;
- **call:** a `jal` to a helper of shape σ has grade `ring σ`. The shapes
  come from the row table of idea 2.

**One close per grade, not per store shape or combinator.**
`close_k : c ⊢ₖ c' ∧ (def slots decode to the kernel's values) → VmRel c' s'`.
There are four closes in total, grades 0–3; grade ⊤ closes by vacuity.

A new resource is a *colour assignment*, one line in the ring partition,
and never a `VmRel` field. That is the reading of the census's (d1) law:
"the complement is the kill-port and heap-ownership footprint, not a list
of fields".

This composes with idea 1: `close_k` is `dec_image` + `Inv.frame`, where
`supp Inv` is disjoint from rings 0–2. Kept separate, it is still useful
without the decoder, because the grade discipline alone replaces the
per-close lemmas.

### Core rules

- **L-C6′ → `graded_sound`.** A run built by the rules changes only its ring.
- **L-C3′ (all three shapes) → the `call` rule.** Each shape is a grade.
- **L-C4 → `close_k`.** One close per grade.

### What it makes free

- **(c) closes and store shapes.** Every store is one instance of the
  `store` rule, whatever its order or width. The closes shrink to 4, one per
  grade.
- **(d1) relation widening.** A widening becomes a colour. For `Protect`'s
  savedpc and `L->top` the colour is ring 2: one line, not 100–250.
- **Arm composition.** Arms that share a prefix, like the `Protect` preamble
  in MOD/MODK/IDIV/IDIVK/EQ, take it at grade 2 through `seq`, with no
  lemma about the preamble.

### What it costs

- **Setup.**
  - The ring colouring is data-dependent. Ring 3's "owned heap" follows
    `HeapAt`'s chunk list, so the colouring is a function of the complement,
    not a constant set. The rule `store` needs the colour of an address
    decided from `Ranges` (`omega`) for rings 0–2. Ring 3 needs heap-ownership
    reasoning, deferred to CALL.
  - `graded_sound` (≈ 60 lines) and the 4 closes (≈ 30 each), both
    estimates.
- **What gets harder.** Grades are coarse. An arm at grade 2 that should
  *not* touch `L->top` cannot say so. That is fine for `sim_X`, which only
  needs head facts, but a finer spec would need colours, not grades.

### Theories

- **Protection rings (known).** Schroeder and Saltzer, *A hardware
  architecture for implementing protection rings*, CACM 15(3), 1972. These
  are nested privilege domains, and here the privilege is "may write".
- **Graded monads and effect systems (known).** Katsumata, *Parametric
  effect monads and semantics of effect systems*, POPL 2014; Gifford and
  Lucassen, LFP 1986.
- **Novel here:** grades are indexed by *callee shape* and by the kernel
  edge's def ports, so the grade of an arm is computed from its `opKernel`
  entry and its call rows. No per-arm footprint is ever written.

### Pilot

- **Refactor `sim_ADD`:** grade 0 on the int path (the tag-first `sb`/`sd`
  are two `store`s), grade 0 with no stores on the pc+1 path. The close is
  `close_0`.
- **MUL:** grade 2 (`jal_pure`), and the stores are at grade 0. `close_2`
  does not care that `__muldi3` wrote below `sp`.
- **EQ:** grade 2 from the `Protect` stores and the `luaV_equalobj` call,
  with no slot stores. `close_2`.
- **MOD:** grade 2. The error path is ⊤ and vacuous.
- **Smallest build:** the ring colouring for rings 0–2 as a function of
  `RelPtrs`, the judgement with `seq`/`weaken`/`store`/`call(pure)`,
  `graded_sound`, and `close_0` and `close_2`.
- **Measure:** close and store-lemma lines across the 4 arms. The prediction
  is 0 new for MUL, EQ and MOD after the build.

## How the five fit together (for the variation step)

1. **Decoder (1)** is the base representation.
2. **Grades (5)** are the bookkeeping for what may change.
3. **Reconciliation (4)** removes guards and inversions.
4. **Call nodes (2)** give calls a single step and prune the error chains
   by the Step premise.
5. **Regrowth (3)** takes the runtime shape out of `VmRel`.

Only 2 and 4 need an executor change; 1, 3 and 5 are changes to the
statement of the relation plus a few generic lemmas.
