## 1. Location lists: one relation `At` indexed by arm pc

**Seed:** *Joseph* (reading the machine state as a bytecode state, at every
point, not only at the head) and *quadratojugal* (a joint bone: the call
return is a joint where two halves of an arm meet; the joint is *named*,
not re-described).

### Idea

`VmRel` only interprets the machine at one pc, the fetch head. Everywhere
else the kit lives in raw `SegSt` pins and a raw `writeMap8` memory, and the
moment a proof must *stop* (a split, a call return) someone must write the
interpretation by hand (`ArmPre`, `AtRet`, `divFrame`, the FORPREP draft's
`FpMem`). Compilers solved the same problem for debuggers: DWARF *location
lists* say, for each pc range, where each source variable lives (a register,
a frame offset, a constant, an expression over registers). Do the same:

- A tiny location language
  ```
  inductive Loc
    | const (n : BitVec 64)
    | ptr (b : Base) (off : Int)          -- Base ∈ {L, ci, base, sp, k, code, jt}
    | slotTag (j : RIdx) | slotVal (j : RIdx)   -- RIdx := a | b | c | a+1 | … (field of ins)
    | kTag (i : RIdx) | kVal (i : RIdx)
    | ins | pcNext (d : Nat)               -- s4, s3/s11 forms
    | res (n : Nat)                        -- the n-th helper result on this path (ghost)
    | dead
  ```
  with a denotation `⟦ℓ⟧ (w : RelPtrs) (s : State) (ins : Word) (g : Ghost) : BitVec 64`
  that is already the kit's *normalised* form (`slotVal w.mo (w.slot j)`,
  not `bytesT8 (writeMap8 …)`).
- A pc-indexed relation
  ```
  structure At (p s w ins g) (loc : Reg → Loc) (wr : WrSet) (c : Config) : Prop where
    core  : CoreNoPins p c s w            -- Core minus Pins
    regs  : ∀ r, loc r ≠ .dead → c.σ.regs.get? r = some (⟦loc r⟧ w s ins g)
    mem   : MemAt p w s wr c.σ.mem        -- exact outside Slots∪Scratch∪wr; slots in wr hold g's values
  ```
  `VmRelAt` is `At` at `headPc` with the head's `loc` table. `ArmAt` is `At`
  at `armTarget`.
- The generator already computes the live set and the composed post-pins at
  every segment boundary (L4-call′, `lcall_frames.py`). Have it emit the
  composition **in `Loc`**, not as raw terms: a table `locs : Pc → (Reg → Loc)`
  per arm boundary (`Lua/Vm/Arms/locs.tsv` → one generated `def`). This is
  data, not a proof.

### Core rules

- **L4-split′ → `At.split`.** For any boundary `pc` in the table:
  `Run(head → pc) ending in At … (locs pc)` and `∀ c, At … (locs pc) c → Run(pc → head) ∧ VmRel …`
  give the arm. The boundary is written `At p s w ins g (locs 0x8001f7bc) wr`:
  a name, zero lines. This is `armBody_split` with its `ArmPre` generated
  from the table.
- **L4-call′ → `At.call`.** At `jal f` with summary `Sum f pre post`:
  `At (locs site) c → (∀ args, pre (argsOf (locs site))) → At (locs ret) c'`
  where `locs ret = (locs site).restrict (live ret) ⊔ [a0 ↦ res n]`. The
  frame is `restrict`, a list function; nothing is stated.
- **Segment transfer (proved once): `At.seg`.** For a generated segment
  `seg_lo_hi` and the two table rows, a Bool check
  `locXfer seg (locs lo) (locs hi) = true` (a symbolic evaluator over `Loc`:
  `addi a5, s9, 16·b` maps `ptr base 0` to `ptr base (16·b)`; `lbu a3,8(a5)`
  maps it to `slotTag b`) implies `At lo c → ∃ c', StepsN … ∧ At hi c'`.
  `locXfer_sound` is proved once; each segment's check is one `decide`. Loads
  through `savestate`'s stores are resolved by abstraction 4's forwarder.

### What it makes free

- `modk_call`'s 4-line `divFrame`; every `ArmPre`/`AtRet`; the
  `armBody_split` call sites become `At.split (pc := …)`.
- FORPREP's uncommitted `fp_pre`/`FpInts`/`fpFrame`/`FpMem`: the
  `luaV_tointeger` return and the `__udivdi3` return are two rows of the
  table.
- IDIV/IDIVK reusing `s3`/`s4` as operand temporaries: the table says
  `s3 ↦ slotVal b`, `s4 ↦ slotVal c` at that pc; the MOD-shaped doc comment
  of `divFrame` no longer matters.
- The normaliser pass of L4-call′ (`slotVal_wm8`, `Ranges.k_*_wm8`) is
  folded into `⟦·⟧`: values are stated normalised by construction.

### What it costs

- `Loc`, `⟦·⟧`, `At`, `MemAt`: about 150 lines. `locXfer` and its soundness:
  about 200–300 lines (one case per RV64I opcode that the arms use: `addi`,
  `add`, `slli`, `srli`, `andi`, `ld`, `lbu`, `lw`, `sd`, `sb`, `mv`, `li`).
- The generator gains a symbolic evaluator over `Loc` (Python, data
  emission). A value that is not expressible (a helper result combined
  arithmetically, e.g. MOD's `r + n` correction) needs a `res`-indexed ghost
  plus a side equation; the post halves still do their arithmetic by hand.
- The kit runner (`pins_of`) must read pins as `⟦loc r⟧`: a second runner
  mode.

### Theories

- DWARF location lists and location expressions (DWARF 5, §2.6 and §2.5)
  *(recalled, check section numbers)*: known.
- Translation validation with per-program-point simulation relations
  (Pnueli, Siegel, Singerman 1998; Necula, PLDI 2000) *(recalled)*: known.
- Control theory: an observer (Luenberger 1964) *(recalled)*. The machine
  state is "observed" through a fixed output map, and the location table is
  that map made explicit per pc: known as an analogy; using it as a proof
  boundary is novel.

### Pilot

- **Refactor MODK:** replace `ArmPre` and `modk_call` with
  `At.split (pc := ret of __moddi3)`. Prediction: `modk_call` 6 → 2 lines;
  `armBody_split`'s argument disappears.
- **IDIV:** two helpers, so two table rows; the budget is no longer a design
  input, because each half is cut at a row.
- **FORPREP:** cut at the `luaV_tointeger` return; `sp+40` appears in `wr`
  (see abstraction 5).
- **Smallest thing to build:** `Loc` with only `const`, `ptr`, `slotVal`,
  `kVal`, `res`, `dead`; `At`; `At.split`. Use the generator's existing
  composed post-pins, normalised, for the one MODK row. Skip `locXfer` at
  first: the pre half still ends in raw `SegSt`, closed into `At` by one
  `At.of_seg` lemma that runs the normaliser once.

## 2. Bastion cells: values own a footprint outside the window

**Seed:** *bastionary* (a fortified object that no tenant may enter) and
*bilocellate* (two-celled: memory is partitioned into cells, and separation
is cell inequality, not arithmetic).

### Idea

C-str is a relation gap, not a proof gap: `ValRepr.str` speaks of `w.mo`,
and nothing says the string's bytes are outside `Win`, so `c.σ.mem` may
differ there. The L4-str′ check found that no F1 store ever touches a
reachable string's footprint. Make that a *type* of the memory, not a field
per resource:

- One generic footprint function on values: `fp : Value → RelPtrs → Set Nat`,
  with `fp (.str s) = [x, x + 24 + s.length]` (header bytes `tt`, `shrlen`/`lnglen`,
  contents, terminator), `fp _ = ∅` for immediates. Tables, closures and
  userdata get their own clause later. This is ONE function, not a field per
  resource.
- ONE relation field, the *bastion* law:
  `Core.bastion : ∀ j v, s.regs j = some v → ∀ a ∈ fp v w, ¬ Win p w a`
  (and the same in `Complement` for `kval`). The boot witness checks it, as
  `lstr_trace.py` already does on every trace.
- A cell classifier `cellOf w : Nat → Cell`, where
  `Cell := slots | cframe | savedpc | top | callee | kArr | code | ci | L | bastion | other`,
  is defined from `Ranges` by an `if` cascade. `cellOf_spec` is proved once,
  and each `Ranges` disjunction is consumed once there.

### Core rules

- **L4-str′ → `Core.str_live`.**
  `Core p c s w → s.regs j = some (.str t) → TStringRepr c.σ.mem x t ∧ bytesT1 c.σ.mem (x+24+|t|) = 0`.
  It follows from `Core.frame` and `Core.bastion`, by one `congr` over the
  footprint.
- **Run invariance: `bastion_run`.** If a run's writes are all in cells
  `≠ bastion` (which every F1 arm's close already proves: `bleach` is
  exactness outside slots ∪ Scratch), then every intermediate config reads
  the bastion as `w.mo` does. So inside `memcmp`, called from
  `luaS_eqlngstr` from `luaV_equalobj` from OP_EQ, the bytes the loop reads
  are `t`'s bytes, a fixed `List UInt8`.
- **Separation by tag: `sep_of_cell`.** `cellOf a ≠ cellOf b → a ≠ b`. A
  read of `K[C]` through `savestate`'s two stores becomes three `decide`s
  on `Cell` (`kArr ≠ savedpc`, `kArr ≠ top`), with no `omega` on
  `k_sep ∨ …`.

### What it makes free

- `sim_EQ_of_long`, `sim_EQK_of_long`, `sim_LT_of_str`, `sim_LE_of_str`
  stop being premises. They are proved, given the scan summaries of
  abstraction 3.
- UNM's numeric-string path: the bytes are fixed. It still needs
  `luaO_str2num` (4 loops), but no longer a relation premise.
- `Ranges.k_getElem_wm8`, `k_bytesT1_wm8`, `k_bytesT8_wm8`, and the next
  such family for every new region: one `sep_of_cell` instead.
- The ×4 `omega` penalty of disjunctive separation facts: the disjunctions
  are consumed once inside `cellOf_spec`, never in `kit_setup`.

### What it costs

- Preservation obligation: every arm that *writes* a register must show the
  new value's footprint is outside `Win`. On F1 this is trivial except
  LOADK/MOVE (copy a pointer: the footprint comes from `kconst`/the source
  register) and later CONCAT/CALL (which create strings: their allocator
  summary must return a fresh chunk in the heap cell).
- `cellOf` must be total and decidable. Overlapping ranges are an error, so
  `Ranges` must already make the cells disjoint. It does (`ci_sep`, `L_sep`,
  `k_sep`, `frame_sep`, `*_top`), except `L_sep_ci`, which becomes one more
  cell boundary.
- GC header writes (`marked` +9, `next` +0, `hnext` +16) under CALL/CONCAT:
  `fp` must exclude those offsets. L4-str′ already gives the exact footprint.

### Theories

- Bell–LaPadula (1973): subjects with clearance cannot write into
  higher-classified objects; F1 arms are "low" tenants *(recalled)*: known.
- Region-based memory (Tofte–Talpin 1994/1997) and ownership types (Clarke,
  Potter, Noble, OOPSLA 1998) *(recalled)*: known.
- CHERI capabilities / W^X page permissions: hardware write-permission
  partitions: known.
- Burstall's component-as-array model (1972; Bornat 2000) *(recalled)*:
  separation by type of field instead of by address arithmetic: known.
  Using a per-relation *cell enumeration* as a decision procedure for Sail
  memory reads is novel here.

### Pilot

- **EQ on two long strings:** `Core.str_live` for both registers, then
  `bastion_run` across `luaV_equalobj → luaS_eqlngstr → memcmp`. With the
  `memcmp` scan summary (abstraction 3) giving
  `a0 = 0 ↔ bytes equal`, this closes against `δ .eq` (content equality)
  through `luaS_eqlngstr`'s length check (`ld 16(a0)` = `lnglen`, in `fp`).
- **LT on two strings:** the same, with `strcoll = strcmp` and `strlen` over
  bastion bytes. `l_strcmp`'s chunk loop exits on its first pass when the
  string has no embedded `'\0'`. That is a *premise-free* fact only if
  `lexLt` is proved equal to the chunked comparison, so state one list
  lemma `lexLt_chunks` (pure math, once).
- **MODK refactor:** `kitk_rd`'s `Ranges.k_*_wm8` → `sep_of_cell`.
- **Smallest thing to build:** `fp` (strings only), `Core.bastion`, the boot
  witness check, `Core.str_live`. Then delete the premise of
  `sim_EQ_of_long` modulo a stated `memcmp` summary statement.

## 3. Affine cursor loops

**Seed:** *seismometry* (a needle reading a tape at a steady rate: the
loop's registers are affine in one counter), *Omagua* (flattened heads:
the loop state flattens to one `Nat`), *metagastrula* (a sheet folding into
a tube: rotated loops, entered mid-body), *branchi* (branches: multiple
exits).

### Idea

L4-loop′ fixes the rule but leaves `I` and `μ` to each loop. Every loop of
§1b.2 that F1 meets has the same *shape*:

- a set of **induction registers** affine in one counter `i`
  (`r = r₀ + stride·i`): `memcmp` (`a0`, `a1` stride 8 in the word loop,
  then 1; `a2` = `n − 8i`), `strcmp` (`a0`, `a1`, stride 24 aligned, 1
  bytewise), `strlen`, the nil fill (`a5` stride 16), the slot copy;
- **fixed pins** (`ra`, `sp`, callee-saved);
- **loop-carried values that are functions of `i` and fixed bytes**
  (`a5`/`a4` = the bytes at `i`, read from the bastion);
- a **memory effect** that is identity (scans) or a prefix fill
  (`nilMem m X i`, `copy m src dst i`);
- an **exit oracle** `σ : Nat → Option ExitIx`: at cursor `i`, which exit
  (if any) the body takes. For the scans it is a pure function of the fixed
  byte lists.

`__muldi3` and `__udivdi3` are *not* affine (shift-and-add on values). They
use the general L4-loop′ rule, but with the same packaging: a measure on a
`Nat` counter and the pins as a function of the counter.

So a loop is given by a **`CursorShape`** (data):

```
structure CursorShape where
  head    : BitVec 64
  ivars   : List (Reg × Loc × Int)    -- register, base (abstraction 1's Loc), stride
  fixed   : List Pin
  carried : List (Reg × (Nat → BitVec 64))
  eff     : Nat → Mem → Mem
  bound   : Nat                        -- i ≤ bound
  σ       : Nat → Option ExitIx
```

The invariant and measure are **derived**:
`I i := SegSt head (pinsAt shape i) (P (eff i m))`, `μ i := bound − i`.

### Core rules

- **L4-loop′ → `cursor_loop`.** Given the body obligation
  `∀ i < bound, σ i = none → Triple (I i) (I (i+1))` and
  `∀ i, σ i = some e → Triple (I i) (Exit e i)`, conclude
  `Triple (I i₀) (fun c => ∃ i e, firstExit σ i₀ bound = (i, e) ∧ Exit e i c)`.
  It is proved once from `Triple.loop` (`DeriveLoop.loopFromBody` with
  `I := ∃ i, I i ∧ …`, which removes all three §1b.1 mismatches: the exit is
  carried by `σ`, the state is a family, the measure is a ghost).
- **Rotation: `cursor_loop_rot`.** The entry is a mid-body pc. It is the
  same rule applied after one entry segment, with `i₀` at phase 1/2.
- **Loop to loop: `cursor_chain`.** `memcmp`'s word loop exits on a
  mismatch at word `i` into the byte loop at byte `8i`. The rule
  re-indexes: `Exit_mismatch i ⇒ I_byte (8·i)`, then `Triple.seq`.
- **The body obligations are straight-line.** Each is a kit run of the
  body's generated segments from `pinsAt i`, with no induction. `σ`'s value
  is a guard the runner's `kit_guard` already decides.
- **Scan library (pure, once):** `firstDiff a b n`, `firstZero a`,
  `firstDiffOrZero a b`, with `firstExit` lemmas relating them to `List`
  equality, `lexLt`, and `length`. Plus the word lemma
  `bytesT8_eq_iff : bytesT8 m x = bytesT8 m y ↔ ∀ k < 8, bytesT1 … = …`
  for the stride-8 loops, and `strcmp`'s has-zero-byte mask
  `((x & m) + m) | x | m = -1 ↔ no zero byte` (one `bv_omega`-free lemma
  over 8 bytes, proved once).

### What it makes free

- `loadnil_loop` (25 lines) and its `| 0 => absurd | n+1 => …` recursion; the
  RETURN0/RETURN1 fills and `luaD_precall`/`luaD_poscall`'s fills (5
  instances of the nil-fill shape: one `CursorShape` each, generated from
  the segment names, with the store offset as data); the slot copy ×2.
- `muldi3_loop`, `udiv_norm`, `udiv_div`: refactor to the general rule with
  a counter-indexed pin family (saves the recursion skeleton, about 5–6
  lines each, as §2b predicts).
- `memcmp` (2 loops, rotated, 2 exits), `strlen` (2), `strcmp` (2, with 6
  and 2 exits): no invariant is written; the invariant is "pins are affine
  in `i`, memory unchanged".

### What it costs

- The generator must detect the induction variables and strides
  (scalar-evolution on the loop's segments: a register `r` with
  `r' = r + c` on every back edge). This is a few dozen lines of Python and
  emits *data* (`CursorShape`), checked by one `decide` against the
  segments' pin updates.
- Not every loop is affine. `l_strcmp`'s chunk loop advances by
  `strlen + 1`. It needs the general L4-loop′ with measure `s3` (bytes
  left). Under F1 (no embedded `'\0'`) it runs at most one iteration, but
  the proof still needs the rule.
- Partial words at the end of a string. `memcmp` reads whole words only
  while `n > 7`, so this is fine. `strcmp`'s aligned loop reads 8 bytes past
  a terminator inside the same word. The bastion `fp` must cover the
  rounded-up word, or the read must be shown harmless: `readByte` is
  `getD 0`, so the bytes are *some* value, and only the zero-byte test
  decides. The scan lemma must quantify over the extra bytes.

### Theories

- Scalar evolution / chains of recurrences (Bachmann, Wang, Zima 1994;
  LLVM's SCEV) *(recalled)*: known, for detecting `ivars`.
- Two-tape finite automata reading in lockstep (Rabin–Scott 1959)
  *(recalled)*: `memcmp`/`strcmp` are two-head scanners, and `σ` is the
  automaton's accepting/rejecting state: known.
- Seismograph / sampled-signal processing: a fixed-rate sampler over a
  tape is fully characterised by its sampling index. The analogy is known;
  using it as an invariant generator is novel.
- AutoCorres-style lifting of C loops to `whileLoop` over a pure state
  (Greenaway et al., PLDI 2014) *(recalled)*: known. It is the
  closest prior art for "the loop's meaning is a pure function".

### Pilot

- **Refactor LOADNIL:** `CursorShape` with `ivars = [(a5, slotAddr (a+1), 16)]`,
  `eff i = nilMem m X i`, `σ i = if i = b+1 then some done else none`.
  Prediction: `loadnil_loop` 25 → 3 lines (the shape instance plus one body
  run).
- **EQ on long strings:** `memcmp` = word cursor (stride 8, exits `mismatch`
  / `n ≤ 7`) ⟶`cursor_chain`⟶ byte cursor (stride 1, exits `mismatch` /
  `count`). `a0 = 0 ↔ firstDiff = none`.
- **LT on strings:** `strcmp` = aligned cursor (stride 24, unrolled ×3:
  `σ` has 6 exits) + byte cursor; `strlen` the same. `l_strcmp`'s chunk loop
  uses general L4-loop′.
- **Smallest thing to build:** `CursorShape` with identity `eff`,
  `cursor_loop`, and the `firstDiff` lemma. Prove the `memcmp` byte loop
  alone. Then add `eff` for LOADNIL.

## 4. Store-forwarding by reflection on a region-tagged write log

**Seed:** *dischargeable* (each separation fact is discharged once, not
341 times), *sharecropper*/*averagely* (each segment pays rent to a fixed
budget; make the rent constant and small), *sterve* (the budget starves:
`timeout at whnf`).

### Idea

§1b.3 measured where the budget goes. It goes to loads through
`savestate`'s stores (15–20k each), to 341 `omega` calls in `kit_disch`
re-proving the same address separations, and to whnf of concrete
`writeMap8` memories. All three come from one representation choice: the
segment's post-memory is a *term*, and every read is a *proof* about that
term.

Make the memory a reflected first-order **write log** (law 1: "reflect on
the first-order write log; never whnf the Sail state"):

```
structure SymAddr where base : Base; off : Int      -- Base from abstraction 1/2
inductive Ent | w8 (a : SymAddr) (v : SymVal) | w1 (a : SymAddr) (v : SymVal)
def Log := List Ent
def applyLog (m₀ : Mem) (ρ : Base → Nat) : Log → Mem
```

- Bases are tagged with the cells of abstraction 2. Two addresses with
  different cells never alias; two with the same base alias iff offsets
  overlap.
- `fwd : Log → SymAddr → Width → Fwd`, with `Fwd := hit v | miss | stuck`,
  is a Bool-level forwarder that compares cells and constant offsets.
- `fwd_sound` (proved once):
  `fwd log a wd = miss → bytesT wd (applyLog m₀ ρ log) ⟦a⟧ = bytesT wd m₀ ⟦a⟧`,
  and `hit v → … = ⟦v⟧`.

The generator emits the segment posts as `applyLog m₀ ρ [...]` (a boundary
format option, like `"boundary": "segst"` today). The runner's normaliser
`kitk_rd` becomes `rw [fwd_sound (by decide)]`.

### Core rules

- **C-budget → `seg_log`.** A segment's post memory is a log extension; a
  read in the next segment is resolved by one `decide` on `fwd` (log length
  ≤ 4 on F1 arms, enum compare + `Int` compare of literals). It never runs
  `omega` on a disjunction, and never whnfs a `Mem`.
- **L4-split′ (by-product) → `log_cut`.** A boundary state is
  `SegSt pc pins (ArmPay (applyLog m₀ ρ log) o)`: it is small, stated by its
  log, and printable by the generator. If a cut is ever needed, its
  statement is data.
- **Close → `bleach_log`.** If every entry in the log has cell ∈
  `{slots, savedpc, top, callee}`, then `Core.frame` holds of
  `applyLog m₀ ρ log`. One `decide` on the cells replaces the `kit_frame`
  tactic's per-store work (which was 24k of MODK's post half).

### What it makes free

- The ≈15–20k heartbeats per guarded load. Estimate: 1–3k for a `decide` on
  a 2-entry log *(estimate, to be measured)*. MODK whole path ≈ 60–80k, so
  `armBody_split` is not needed. FORPREP's integer path (3 slot reads ×
  tag+payload after `savestate`, two calls) fits one declaration.
- `kit_disch`'s repeated `omega` for read separations: the side conditions
  left are pin equalities and range facts about the *base* (alignment, top),
  and those are proved once per arm by `Ranges`.
- The 557k fallback unification: the log is compared syntactically, so
  unification over store chains never happens.
- The `Ranges.k_*_wm8` family and its `kit_side_pre` hook.

### What it costs

- A second segment boundary format in `gen_segment.py`. Segments must keep
  the raw form available for the `SegSt` pin values (abstraction 1's `Loc`
  takes that role).
- `SymVal` must reflect the stored values: registers (pins), `savestate`'s
  `ci->top` load, constants. Values that are not reflected are opaque atoms,
  which is fine because `fwd` never inspects values.
- Symbolic offsets (`16·C + 8` for `K[C]`) are not literals. `fwd` needs
  `off : Int ⊕ (cell-interval)`: an offset known only to lie in the cell's
  interval is enough when the other access is in a different cell. Within
  the slots cell, two symbolic slots `16a`, `16b` with `a ≠ b` need one
  hypothesis atom (`a ≠ b`) in the log's context: the one remaining `omega`.

### Theories

- Proof by reflection (Boutin, TACS 1997; Gonthier's small-scale reflection)
  *(recalled)*: known.
- CPU store-to-load forwarding and memory disambiguation (load/store queues;
  Moshovos & Sohi, MICRO 1997, on memory dependence prediction)
  *(recalled)*: known. The arm's 2–4 stores *are* a store queue, and
  `savestate` is a store buffer that the following loads snoop.
- Base+offset alias analysis in compilers (e.g. Diwan, McKinley, Moss,
  PLDI 1998, type-based alias analysis) *(recalled)*: known.
- Using a cell-tagged log as the Sail memory's *proof representation*, so
  the heartbeat cost per load is constant: novel here.

### Pilot

- **Refactor MODK:** regenerate its 5 segments with `"boundary": "log"`.
  Measure per-segment heartbeats against §1b.3 (32/38/6/42/10k). The
  prediction to falsify is that seg2 and seg4 drop below 10k, and that the
  whole path fits one declaration under 120k.
- **IDIV:** one declaration, two calls.
- **FORPREP:** one declaration; this is the decisive test.
- **Smallest thing to build:** `SymAddr` over 4 bases (`base`, `ci`, `L`,
  `k`), `Log` with `w8`/`w1`, `fwd`, `fwd_sound`. Hand-translate MODK seg2's
  post (`savestate`'s two `sd`s) into a `Log` and measure the `K[C]` tag read
  alone. If that read does not fall from 38k to under 10k, stop.

## 5. Summary dynasty: helper footprints derived along the call tree

**Seed:** *dynastidan* (a lineage: a helper's effects are inherited from
its callees: `luaV_equalobj → luaS_eqlngstr → memcmp`,
`__moddi3 → __udivdi3`, `l_strcmp → strcoll → strcmp`, `strlen`) and
*Hopkinsianism* (disinterested benevolence: a callee that leaves its
caller's world untouched, and *says so once*).

### Idea

The census found that after the kit, what remains at a call is not the
frame registers. It is two things:

1. the callee's **precondition** (`EqCtx`: 9 address facts);
2. the callee's **write effect** (FORPREP's `luaV_tointeger` writes `sp+40`
   in the caller's frame, which forced `bleachF`; CALL writes the heap).

Both are properties of the callee's *code*, and both compose along the call
tree. So derive them instead of writing them per helper:

- **`Fp f`** (register mod set, memory write cells, stack depth) is
  computed by the generator from `f`'s segments: registers assigned, stores
  with `sp`-relative or argument-relative bases. It is closed under calls:
  `Fp f = local f ∪ ⋃_{g callee of f} Fp g`. It is emitted as data and
  checked per segment by `decide` (each segment's store addresses and
  written registers ⊆ the claimed `Fp`).
- **`Rd f`** is the set of cells `f` *reads* through its argument registers
  (`a0 ↦ bastion` for `memcmp`, `a0 ↦ slots ∪ bastion` for
  `luaV_equalobj`). The caller discharges `Rd f` by one cell-membership
  `decide` (abstraction 2's `cellOf`), not 9 address facts.
- The value part of a summary (`a0 = …`) still comes from running `f`'s
  segments. With abstraction 3 for loops, and nested call nodes for callees,
  it is a composition, not a contract.

### Core rules

- **L4-call → `call_frame_free`.**
  `SegSt site (args ++ F) P c → Disjoint (regs F) (Fp f).regs → Sum f → SegSt ret (res ++ F) P' c'`.
  `F` is the caller's pin list filtered by `Fp f` (a list function); it is
  never stated (`hframe?` today, now with a reason).
- **Dynasty composition → `fp_call`.** If `f`'s segments write within
  `local f` and its call nodes call `g` with `Fp g`, then `f` writes within
  `Fp f`. It is proved once over the segment/call-node graph, as an
  induction on the *call tree*, which is acyclic on F1 (checked).
- **Close with effects → `bleach_fp`.** An arm's close requires its log
  (abstraction 4) ∪ ⋃ `Fp` of its calls ⊆ `Win ∪ {cframe words above 0(sp)}`.
  This is `bleachF` stated once for every footprint. FORPREP's `sp+40` is
  the cell `cframe`, and `0(sp)` (the `kptr`) is excluded by cell.
- **Precondition → `rd_ok`.** `∀ arg cell ∈ Rd f, cellOf ⟦arg⟧ ∈ allowed`:
  one `decide`.

### What it makes free

- `EqCtx`'s 9 address facts (EQK's 16 lines): `Rd luaV_equalobj` is
  discharged by cells.
- The per-arm `bleachF`/`bleach` choice and the "variant that allows frame
  writes except `0(sp)`" that KIT.md forecasts for FORPREP (≈15 lines).
- The hand footprint clauses of `muldi3_sum`, `udivdi3_sum`, `moddi3_sum`,
  `equalobj_sum`, `toint_sum` (the "leaves `s0, s1, …` unchanged and writes
  only below `sp`" half of each summary).
- For later: CALL's runtime-shape callees get a *derived* footprint (heap
  cells, `L`, `ci`), which is exactly the L-C3′ "footprint post-condition"
  KIT.md says CALL print needs.

### What it costs

- The generator's footprint analysis must be sound for computed addresses.
  A store through a pointer that is not `sp`- or argument-based (for
  example, `luaV_tointeger`'s `*p = …` through `a1`) needs the argument's
  cell from the call site. So `Fp` is *parametric* in argument cells:
  `Fp f (cellsOf args)`.
- The per-segment `decide` check must read store addresses as `Loc`/`SymAddr`
  (abstractions 1/4); with raw `BitVec` terms it would be the cost it
  removes.
- Recursive callees (none in F1; `luaD_call` later) need a fixpoint, not an
  induction on the call tree.

### Theories

- Interprocedural MOD/REF analysis (Banning, POPL 1979; Cooper & Kennedy,
  PLDI 1988) *(recalled)*: known.
- Effect systems (Lucassen & Gifford, POPL 1988) and the frame rule of
  separation logic (O'Hearn, Reynolds, Yang, CSL 2001) *(recalled)*: known.
- Inheritance in genealogy and heraldry: arms (coats of arms) are composed
  from ancestors' charges by fixed rules of marshalling. The analogy of
  effects inherited and composed by rule along a lineage is novel as a
  proof device.

### Pilot

- **IDIV:** `__divdi3 → __udivdi3`. `Fp` is derived (`t0`–`t2`, `a0`–`a5`,
  `ra` saved below `sp`). The caller's `s3`/`s4` temporaries are outside
  `Fp`, so `call_frame_free` carries them.
- **FORPREP:** `Fp luaV_tointeger (a1 ↦ cframe)` = `{sp+40}`; the close is
  `bleach_fp`. With abstraction 4 it is one declaration.
- **EQ long:** `Rd luaV_equalobj = {slots, bastion}`, derived through
  `luaS_eqlngstr` and `memcmp`.
- **Refactor MODK:** `moddi3_sum`'s footprint half is replaced by `fp_call`.
- **Smallest thing to build:** `Fp` for registers only, `call_frame_free`,
  and the per-segment `decide` check on `__muldi3`, `__udivdi3`,
  `__moddi3`. Then add memory cells once abstraction 2's `cellOf` exists.
