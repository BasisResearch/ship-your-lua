## 1. Pidgin: a contact language of soft-float observations, compared by reflection

**Seed:** *beachlamar* (a pidgin, the contact language two communities
trade in, which neither speaks natively), *tachygraphist* (shorthand),
*sphygmochronograph* (record the pulses, not the whole body).

### The idea

The kernel and the machine never speak each other's language. The kernel's
float clause is Lean `match`/`if` over `Float.Model`. The machine path is
`at_run` over Sail states with call nodes. Today every arm translates
between them by hand (`cases v0 <;> cases v1`, `rcases … <;> split`,
`model_add_comm`, `e` for the closers).

Introduce a small **deep-embedded contact language** in which both sides are
written down as closed data: an **observation tree** `OTree` over **atom
indices**, not values. Then the arm's obligation becomes:
1. one soundness theorem per *kernel combinator*, mapping kernel to tree;
2. one generic theorem mapping machine to tree, by structural recursion over
   a generated fork tree whose nodes point at already-generated segments
   and call summaries;
3. **one `decide`** that the two closed trees are equal after a verified
   normaliser.

The tree is the shorthand (*tachygraphist*). It records only the pulses
(*sphygmochronograph*): which soft-float calls on which atoms, which forks
on which answer, which values reach which registers.

```lean
/-- Atoms: the payloads the arm reads (registers/constants by position in
`κ.reads`/`Opnd.fill`), as F64 bits, plus integer operands. Indices only. -/
inductive OAtom | flt (i : Fin 4) | int (i : Fin 4)

/-- Float-valued observation terms. -/
inductive OTm
  | atom (a : OAtom) | ofI (i : Fin 4)            -- `__floatdidf`/`__floatsidf` of an int atom
  | lit (b : BitVec 64)                          -- 0.0, 1.0, an immediate's image
  | add (x y : OTm) | sub (x y : OTm) | mul (x y : OTm) | div (x y : OTm)
  | neg (x : OTm) | floor (x : OTm) | fmod (x y : OTm) | pow (x y : OTm)
  | str2d (i : Fin 4)                            -- `luaV_tonumber_` → `strtod`: `Str2dFrom`'s value

/-- Boolean observations: what a fork can test. -/
inductive OB
  | cmp (r : Rel) (x y : OTm)    -- r ∈ {lt, le, eq, unord}, read through `F64.compare`
  | fits (i : Fin 4)             -- `intfitsf` of an int atom (integer ALU on the machine)
  | f2i (m : F2Imod) (x : OTm)   -- `tointegerns` succeeded (the inlined chain, L5-chain)
  | icmp (r : Rel) (i : Fin 4) (x : OTm)  -- `i < fi`, `fi ≤ i` after a successful f2i
  | ite (c a b : OB) | not (c : OB) | lit (b : Bool)

/-- The kernel's answer, or the machine's leaf. -/
inductive OTree
  | stuck                                   -- `none`: no `Step`
  | leaf (edge : Nat) (vals : List OVal)    -- edge index, values stored (OVal = flt OTm | int … | bool b)
  | br (c : OB) (t f : OTree)
```

`OTree.eval (env : Env) : OTree → Option (Nat × List Value)` is the one
semantics. `Env` maps atom indices to the arm's actual payloads (F64 bits
for floats, `BitVec 64` for ints). Inside `eval`, `OTm.add` is `F64.add`,
`cmp` is `F64.compare`, and so on. The bridges `F64.add_eq_model`,
`compare_eq_model`, … are applied **once**, inside the per-combinator
soundness theorem, never at an arm.

### Core rules (law → one proved rule; how it is decided)

| law | rule | decided at a use site by |
|---|---|---|

Proved once by structural recursion on the generated fork DAG `t`. Prefix nodes are run once, because the recursion is on the tree and the prefix is above the fork. Joins (FORLOOP's `0x8001e194`) are φ nodes whose Boolean is an `OB.ite`. | syntactic: the tree is generator data (pcs, segment ids, call ids, idiom ids); `NodeFact` is a table of references to the existing generated at-lemmas/segment triples and `<R>.spec` call summaries |

`≈` is equality of the two trees' *Boolean-function semantics over
comparison atoms*. The check evaluates both trees on every assignment of the
(few) distinct `OB` atoms: up to 4 values per `cmp` atom, 2 per `fits`, and
`some/none` per `f2i`. If both trees give the same leaf on every assignment,
they agree on every env. **Soundness does not need feasibility.**
Completeness can fail on infeasible assignments where the trees differ. That
failure is a decidable `false`, and a `#eval` diff prints the witness
assignment. The check is **not search**: it is a bounded enumeration of
closed data.

What happens with symbolic data: none enters the `decide`. The payloads
live in `env`, and `env` appears only in `mtree_run` and `kernelTree_sound`,
which are proved once.

## 2. Endolymph: answers carry only orientation (a 4-point code), and the order is the sign-magnitude integer order

**Seed:** *endolymph* (the inner ear senses orientation, not position),
*Themistian* and *predominancy* (law and dominance: an order), *Senusism*
(one order, many lodges: one comparison, many routines).

### The idea

Every use of `__ledf2`/`__gedf2`/`__eqdf2` in `luaV_execute` reads only the
answer's **orientation**: one of 4 points, `lt | eq | gt | unord`. The 93
sites differ only in how an instruction idiom maps a 64-bit code back to a
Boolean or a 0/1 value.

So, in two parts:
- **Arm side.** Make "idiom" a closed mini-language with one interpreter.
  Then every idiom fact is one theorem instantiated by computation on 4
  points. That gives no per-idiom lemma, and **no generated per-idiom lemma
  either**. This is cheaper than round 5's "generator rule" verdict for
  L5-idiom.
- **Level-(b) side.** Orientation is decided by one fact: on non-NaN
  doubles, `F64.compare` is the integer order of a **sign-magnitude key**.
  The three comparison routines' 19 + 67 + 67 paths then become `omega`
  over literal shifts and masks, with no variable shifts. These routines
  feed every f2i chain and every comparison arm.

```lean
inductive IOp | slti (k : Int) | sgtz | sltz | seqz | snez | not | srli (k : Fin 64) | srai (k : Fin 64)
inductive IEnd | beqz | bnez | bltz | bgez | blez | bgtz | val      -- branch, or a 0/1 value kept
structure Idiom where ops : List IOp; fin : IEnd

def Idiom.eval (ι : Idiom) (a0 : BitVec 64) : Bool := …          -- one interpreter
def code (R : Cmp) : Option Ordering → BitVec 64                  -- = Ledf2.S/Gedf2.S/Eqdf2.S's match, definitionally
def relOf (R : Cmp) (ι : Idiom) : Option Ordering → Bool := fun o => ι.eval (code R o)

theorem idiom_fork (R ι) (a b) : ι.eval (R.S a b) = relOf R ι (F64.compare a b)   -- by `R.S`'s definition: `rfl` after unfolding the match

/-- level (b), comparisons -/
def key (x : F64) : Int := if x.sign then -((x.toNat % 2^63 : Nat) : Int) else (x.toNat % 2^63 : Nat)
theorem compare_key (x y : F64) (hx : x.isNaN = false) (hy : y.isNaN = false) :
    F64.compare x y = some (Ord.compare (key x) (key y))
theorem isNaN_iff (x : F64) : x.isNaN ↔ 0x7ff0000000000000 < x.toNat % 2^63
```

| L5-idiom | `idiom_fork`, proved once. At a fork, the side taken under the class fact `F64.compare a b ∈ P` (P a closed subset of the 4 points, given by the kernel class) is `decide (∀ o ∈ P, relOf R ι o = true)`. | **computation on 4 closed points**. ## 3. Homeopathic sticky: `_FP_FRAC_SRS` is round-to-odd, and round-to-odd is innocuous before nearest-even

**Seed:** *homoeopathically* (a dilution so thin that one trace remembers
the whole substance: the sticky bit is one bit that remembers the whole
discarded tail), *urobilinogenuria* (a metabolic chain whose pigment is
conserved through every conversion: an invariant carried stage to stage),
*bowshot* (a bounded range: the shift `1 ≤ k ≤ 63`), *nondropsical* (not
swollen: the error does not grow through the chain).

### The idea

This is the open hand-off, "rounding after the sticky collapse equals
rounding the exact value", and it is a **known theorem with a name**.

The machine's SRS idiom is `x / 2^k ||| [x mod 2^k ≠ 0]`, checked for
`1 ≤ k ≤ 63` (ROUND-5 §2). That is exactly **round-to-odd** at `k` bits:
truncate, then force the last bit to 1 if anything was lost. Boldo and
Melquiond's theorem: rounding to odd with at least 2 extra bits, then
rounding to nearest-even, equals rounding to nearest-even directly.
soft-fp keeps 3 work bits.

So the whole of `__adddf3`'s precision story is one conserved invariant:
*every intermediate mantissa is the round-to-odd image of the exact value at
the current scale*. Five algebraic laws carry it through every stage:
align, add or subtract, carry, normalise, and the subnormal shift.

```lean
/-- Round to odd: drop `k` bits, keeping a trace of the tail in bit 0. -/
def rto (n k : Nat) : Nat := n / 2 ^ k ||| (if n % 2 ^ k = 0 then 0 else 1)

/-- Round to nearest-even dropping `j` bits, in `F64.shr`/`F64.rne` form. -/
def rneDrop (n j : Nat) : Nat := let (q, rb, st) := F64.shr n false false j; F64.rne q rb st
```

### Core rules (each proved once, in `Nat`, with no `BitVec`)

| # | rule | statement | why it matters |
|---|---|---|---|
| R3a | **SRS = rto** | `srsMachine x k = BitVec.ofNat 64 (rto x.toNat k)` for `1 ≤ k ≤ 63` (the guard that branched there discharges it); `k ≥ 64` branch: `[x ≠ 0] = rto x k` when `x < 2^k` | the only lemma with a variable `BitVec` shift; proved once by `toNat_ushiftRight`/`toNat_shiftLeft` and `Nat.div`/`mod` lemmas, not `omega`. After it, **no variable shift is left** in the core |
| R3b | **composition** | `rto (rto n a) b = rto n (a + b)` | carry-out renormalisation (shift by 1 more) and the subnormal shift compose into one `rto` |
| R3c | **even anchor** | `E % 2 = 0 → rto (E * 2^k + B) k = E + rto B k`, and `E % 2 = 0 → B ≤ E * 2^k → rto (E * 2^k − B) k = E − rto B k` | the aligned add/sub (`0x8002dce8: add a3,a4,t5`): the large operand is semiraw (`m·8`, even), so adding the sticky-collapsed small operand equals collapsing the exact sum. Checked by hand on both signs: with `B/2^k = q + f`, the four cases `q` even/odd × `f` = 0/> 0 agree |
| R3d | **innocuous double rounding** (Boldo–Melquiond) | `2 ≤ j → rneDrop (rto n k) j = rneDrop n (k + j)` | the hand-off itself: rounding the collapsed value = rounding the exact value |
| R3e | **exactness** | `n % 2^k = 0 → rto n k = n / 2^k`, and left shifts are exact | cancellation (`clz` left shift) only happens when the alignment shift was `≤ 1`, so nothing was lost |
| R3f | **round-pack** | `roundPack s E f = F64.round s (f / 8) (E − 1075) rb st` (L5-stage, checked on 7,280 instances) together with R3d, so `roundPack s E (rto N k) = F64.round s N (e…) false false` | joins the machine's `rne3`/pack join node to `F64.round`/`normalize` |

**Use-site decision.** Each machine node in `__adddf3`'s DAG is matched by
*one rewrite* to its stage: SRS → `rto` by R3a, the add by R3c. The
remaining arithmetic is linear in `rto`-atoms and literal-scaled mantissas,
so `omega` can treat `rto n k` as an atom with the linear facts `rto n k ≤
n / 2^k + 1` and `rto n k % 2 = 1 ∨ n % 2^k = 0` (these feed it the round
bits). The exponent difference `k` stays linear (`e₁ − e₂`). The factor
`2^k` appears only inside R3c's hypothesis, which matches syntactically.
Nothing is decided by search.

**How 497 paths collapse.** One invariant is stated *per DAG node*, not per
path (133 nodes). It is "the node's `(s, E, f)` satisfies `f = rto
(exactScaled a b) k` for the `k` this node's scale implies". It is a
Floyd-style annotation: the generator emits the invariant *statement* per
node from the stage it recognised (data). Each node's verification condition
is one of R3a–R3f plus `omega`, and each path's correctness follows by
composing node invariants along the DAG.
- This is a node-indexed proof, linear in the DAG, like `FnSummary`'s fold.
- Is it a "per-routine hand equality proof"? It is not hand-written. The
  VCs are discharged by one tactic, `stage_vc := rw [R3*]; omega`, and the
  invariants are generated from stage recognition. I flag this as the place
  the bake-off must measure.

**Prerequisite, the vessels** (*kelchin*, *mugg*: things briefly held). The
14 frame reloads (blocker ii) are removed first by **spill promotion**.
- The generator forwards each `bytesT8 m (sp+o)` reload to the value its
  own frame store wrote. One generic lemma does it,
  `frame_forward : readMap8 (writeMap8 m a v) a = v` and disjointness for
  other offsets (literal, so `decide`).
- Then `F m s r a b = F' a b`, which does not depend on `m`. This is
  `mem2reg`, and it belongs in `gen_lua_fn.py`'s emission of `F`. It is
  *not* a proof per routine.

**Sub from add.** L5-comm's sign-flip identity is a spec fact, and it does
not by itself give `Subdf3.F = Adddf3.F ∘ flip`: the two are different
machine codes. Under this abstraction, `__subdf3` runs **the same node
invariants**, with the second operand's sign flipped at the unpack node,
and the same VCs re-discharged by `stage_vc`. Its cost is the generator
mapping stages, not new lemmas. Held-out evidence: whether `stage_vc`
closes `__subdf3`'s 142 nodes with no new rule.

### What it makes free

- C5-spec for `__adddf3`, `__subdf3`, `__floatdidf` (1 round, 1 sticky), and
  `__muldf3` (its 128-bit product is collapsed by an `rto`-like
  `_FP_FRAC_SRS`/`|=`, which is R3a at another width [CHECK]).
- `__divdf3`'s remainder-sticky is `rto` by another name: the sticky is
  `rem ≠ 0`.
- `__floatdidf`'s `clz` + sticky.

That is the 58 stage sites of ROUND-5's table under 6 laws.

### What it costs

- **Setup.**
  - R3a about 60 lines (the one hard `BitVec` proof). R3b–R3e about 120 in
    `Nat`. R3d is the deep one, about 80, following Boldo–Melquiond's
    radix-2 argument: case on the 2 low bits of `rto n k` against the
    rounding boundary.
  - Spill promotion in the generator, about 100 Python and about 30 Lean.
  - Node-invariant emission, about 200 Python.
- **Harder.**
  - The generator must recognise stages semantically (ROUND-5: the add
    and sub join nodes are different terms). The recogniser can be
    unsound-but-checked: it proposes, and `stage_vc` proves or fails.
  - Subnormal results and overflow-to-∞ are separate leaves of `F64.round`;
    R3f covers them only via L5-stage's checked instances, so they are still
    theorems to prove.
  - Exact zero sum gets sign `+` in RNE (`normalize … false`). The machine's
    path for `x + (−x)` must hit that leaf. That is a per-path fact, but a
    `decide`-closed one.

### Theories

- **Round-to-odd** (Boldo & Melquiond, "Emulation of FMA and correctly
  rounded sums: proved algorithms using rounding to odd", *IEEE Trans.
  Computers* 57(4), 2008; Flocq's `Round_odd`). Known. Also von Neumann's
  "jamming" of the last bit (EDVAC report, 1945 [recalled, CHECK]).
- **Guard, round and sticky bits** (Goldberg, *ACM Computing Surveys* 1991).
  Known.
- **Tracer conservation in metabolic pathways** (isotope tracer studies,
  e.g. the bilirubin → urobilinogen cycle): a labelled quantity is conserved
  through every conversion, so a stage proof is a conservation check per
  reaction, not per route through the network. That is the per-node, not
  per-path, invariant. As a proof architecture this is novel (an analogy).
- **Floyd–Hoare annotations on a DAG** (Floyd 1967). Known.

### Pilot

- **`__adddf3` (held out).**
  1. Prove R3a–R3f.
  2. Add spill promotion.
  3. Generate node invariants.
  4. Run `stage_vc` on all 133 nodes.

  Measure hand lines outside the generic lemmas (target: 0 per node) and the
  generated-file CPU.
- **`__subdf3` (held out):** the same with no new rule.
- **Smallest thing to build:** R3c + R3d in `Nat` (about 150 lines), plus a
  `#eval` law check on the artefact. Instrument `SpecTest`'s 2,900 pairs to
  assert that `__adddf3`'s pre-round node value equals `rto (exact aligned
  sum) k`. That checks the invariant on the lifted DAG before any proof is
  attempted.

## 4. The patcher's tracer: arm proofs parametric in the number domain (the float arm is the int arm with its leaf patched)

**Seed:** *patcher* (one who patches: replace the leaf, keep the garment),
*feathermonger* (light goods carried, not inspected), *urobilinogenuria*
again (a labelled tracer moving through a pathway without reacting),
*approachability*.

### The idea

L5-share′ says that for `opArith` and `docondjump`, the float path is the
int path with three patches:
- the value leaf (inline ALU → soft-float call node);
- the stored tag (3 → 19);
- conversion calls per int partner.

The machine shares 61–85% of instructions with the int path. Make that
literal. **Abstract the number domain** out of the existing int-arm
hand-offs into a structure, and prove each combinator's hand-off **once
over the abstract domain**. Then instantiate it twice.

The payload word is a *tracer*. The machine moves it and passes it to call
nodes, and never inspects it. By relational parametricity, a path that
treats `w` opaquely commutes with any interpretation of `w`.

```lean
/-- A number domain as the arm sees it: how a value is stored, and how the
leaf is computed on the machine. -/
structure NumDom where
  Pay : Type                         -- BitVec 64 for both, but read differently
  tag : BitVec 8                     -- 3 (int) | 19 (flt)
  repr : Pay → Value → Prop          -- ValRepr.int / ValRepr.flt
  /-- the leaf: inline ALU segment, or a call node with its summary -/
  leaf : BinOp → LeafSpec            -- LeafSpec = segment id or (callee pc, `R.spec`) with result in a0
  leaf_sound : ∀ o x y vx vy, repr x vx → repr y vy → fastArith o vx vy = .val n →
               repr (leafVal o x y) (.ofNum n)

/-- One hand-off per combinator, over any domain (and over a mixed pair of
domains for an int partner, via the conversion leaf). -/
theorem opArith_handoff (D₁ D₂ : NumDom) (conv : Conv D₁ D₂) … : ArmPathOn (opArith …) (Cls D₁ D₂)
theorem docondjump_handoff (D₁ D₂ : NumDom) (conv : Conv D₁ D₂) … : ArmPathOn (docondjump …) (Cls D₁ D₂)
```

### Core rules

| law | rule | decided by |
|---|---|---|
| L5-share′ | `opArith_handoff`, `docondjump_handoff`, `unary_handoff`, `bitwiseRK_handoff`: 4 theorems over `NumDom`. They replace `at_fcond`, `at_farith` and the ≈10 forecast macros. | syntactic instantiation: `D := fltDom`, `D := intDom`, `conv := floatdidfConv` |
| L5-read′ classes | the domain pair `(D₁, D₂)` **is** the class: `(flt, flt)`, `(flt, int)`, `(int, flt)` | computation on the class (as in 5) |
| the tracer law | `opaque_path : PathTreats w opaquely → run (σ[w := x]) = (run σ)[w := x]`. Proved once over the at-route's location-list rows: a row that only moves `Loc.reg/Loc.mem` content commutes with substitution. Instantiating the int arm's path at a float payload is then free. | syntactic (the generator marks opaque rows; the check is a closed `decide` on the row list) |
| L5-comm | part of `leaf_sound` for the float domain: `fltDom.leafVal .add x y := Adddf3.S y x`, normalised by `F64.add_comm` inside `leaf_sound`, once | — |

### What it makes free

- The ADDI-like 8 fields (ADD, SUB, MUL, ADDK, SUBK, MULK, plus IDIV/IDIVK
  with a `floor` leaf).
- The GEI-like 3 and DIV/DIVK (all-float = `(flt, flt)` after two
  conversions).
- The bitwise 11, **if** `tointegerns` is a "leaf" of the domain. Bitwise
  float operands are converted *before* the integer op, so the f2i chain is a
  conversion `Conv flt int` whose spec is `flttointeger .eq` (L5-chain).
- In total, about 24 of 33 fields become `exact opArith_handoff fltDom intDom
  … (by decide)`.

**Not covered: FORLOOP, FORPREP, MOD and LT/LE's mixed `intfitsf` branch.**
For FORLOOP and FORPREP, L5-share is false (22% shared code). For MOD, the
`fmod` sign fix is an extra fork after the leaf. LT/LE's mixed branch makes
the domain pair choose between two algorithms. Those need 1 or 3. This
abstraction is honest about its reach: it is cheap for the regular
two-thirds and useless for the irregular third.

### What it costs

- **Setup.**
  - Refactor the int hand-offs into `NumDom` form: about 4 × 40 lines, plus
    `intDom` and `fltDom` at about 40 each.
  - `opaque_path` over the row language: about 80. This is the deep one;
    it needs the rows' semantics to be substitution-stable, which a
    location-list row language should be [CHECK against B-SEGLOCAL's row
    definition, not read here].
- **Harder.**
  - The int arms must be re-proved through the abstract hand-off
    (regression risk; the refactor is measurable).
  - A float path that differs in *code*, not just leaf (the MMBIN edge from
    a float-but-non-integral bitwise operand, which goes to MMBIN where an
    int does not), needs a domain-specific `fail` predicate in `NumDom`.

### Theories

- **Relational parametricity / free theorems** (Reynolds 1983; Wadler,
  FPCA 1989). Known.
- **Isotopic tracer methodology** (Schoenheimer & Rittenberg, 1930s: a
  labelled atom traced through a pathway without changing its chemistry):
  the payload is the label. Known in biochemistry; novel as a proof device.
- **Functorial / modular semantics with a pluggable value domain** (Liang,
  Hudak & Jones, POPL 1995, monad transformers; abstract interpreters
  parameterised by a value lattice). Known.

### Pilot

- **SUB (FltBC):** `opArith_handoff fltDom fltDom` + `(fltDom, intDom)` +
  `(intDom, fltDom)` + the MMBIN class (the int arm's own). Expected about 3
  lines.
- **LT (FltAB):** the `(flt, flt)` class is `docondjump_handoff`. The mixed
  classes are not covered (`intfitsf` + f2i) and fall back to 1. That is the
  falsifier for this abstraction's reach.
- **FORPREP:** not covered; report it as the obstruction.
- **FORLOOP:** not covered (L5-share false).
- **Smallest thing:** `NumDom` + `opArith_handoff` re-proving the int ADD arm
  and proving the float ADD arm from the same theorem.

## 5. Antirent: the kernel pays the rent of every untested register (an occurrence-typed payer ledger)

**Seed:** *antirentism* (refuse per-use rent: no register should pay for a
fact twice), *nooked* (cornered: the kernel's match corners the register's
type), *sanctification* and *glorifiable* (a fact consecrated once and
then used freely), *Buteo* (the hawk sees the whole field: the class is seen
from above, before any machine step).

### The idea

FORLOOP's 48% (14 of 29 lines) is rent paid per register:
- read the register;
- refute the non-float constructors by `cases`;
- bundle tag and model.

The machine tests only one tag (R[A+2], `lbu a5,40(s5)`). The other two
registers' types are guaranteed by the **kernel** (its float clause), and
behind that by `Supported`'s `loopsOk`.

So split every operand fact by **who pays**:
- **machine-paid:** a tag the machine loads and branches on;
- **kernel-paid:** a constructor the kernel's clause demands, else `none`.

Then let one *occurrence-typing* theorem per combinator hand the arm a
named view that has every register's tag and model as fields, already paid.

```lean
/-- The answer classes of a combinator under an operand predicate Q:
computed from the clause list (L5-read′). -/
def classes (κ : KComb) (Q : OpPred) : List KClass          -- e.g. forloopK, FltStep ↦ [exit, back]

/-- A class's view: one named field per read register (constructor, tag,
payload model), and the kernel's answer for that class. -/
structure ClassView (c : KClass) (p s ins) : Prop where
  regs : ∀ i ∈ c.flts, ∃ x n, s.reg (c.port i) = .flt x n ∧ TagIs i 19 ∧ ModelIs i x   -- ValRepr.flt_parts
  ints : …
  answer : κ.body (s.reads) = c.answer (payloads)

/-- Occurrence typing, once per combinator. -/
theorem class_cover (κ) (Q) : Q p s ins → Step … s s' → ∃ c ∈ classes κ Q, ClassView c p s ins
/-- Who paid: the machine's tag tests on the path are a subset of the
class's constructors; the rest are kernel-paid and need no machine read. -/
def payer (c : KClass) (tagsTested : List Port) : Port → Payer
```

### Core rules

| law | rule | decided by |
|---|---|---|
| L5-read′ | `class_cover`, one per combinator, from `kstep_iff` and the clause list | computation: `classes κ Q` evaluates on constructor skeletons (the census's `LawChecks` table *is* this function's output) |
| per-register payload | `ClassView.regs`, by `ValRepr.flt_parts` inside `class_cover`, once | — |
| machine tag tests | `tag_paid : payer c tested i = .machine → at_hyp …`: the at-runner discharges a tag-test fork by the view's `TagIs` field, by `decide` on the closed tag literal | computation |
| kernel-paid registers | no machine obligation at all. The view supplies the model for the call node's argument. | — |
| `loopsOk` | the FORLOOP/FORPREP view's `regs` for A and A+1 come from the kernel clause `[.flt i _, .flt l _, .flt st _]`. Behind it, `Supported`'s loop check guarantees nothing else wrote them, so `class_cover` for `forloopK` needs no machine read of A and A+1. | — |

### What it makes free

- FORLOOP's 8 + 6 lines (register reading and payload bundling): **14 of
  29**.
- In every member with a register or K partner (12 of 33, O-inv), and in
  9/10 sampled (O-pay), the payload bundle.
- C5-handoff's register part, i.e. the part of `at_fcond`/`at_farith` that
  reads one register.

It does **not** remove the prefix replay or the polarity trials (pair it
with 2 or 1), or the per-shape macros (pair it with 4 or 1). It is the
smallest independent step, and it is a prerequisite that 1 and 4 both
consume: `kernelTree_sound` and `NumDom.repr` take a `ClassView`.

### What it costs

- **Setup.**
  - `KClass`, `classes`, `ClassView`: about 80 lines.
  - `class_cover` for 7 combinators: about 30 each. Each is a
    `kstep_iff` unfolding plus the clause match. Proved once per combinator,
    so this is not a per-arm float case analysis.
- **Harder.** `classes` must be a function of the *combinator*, not of the
  opcode. Opcodes with the same combinator but different operand shapes
  (register vs K vs immediate) need `Opnd.fill` in the class computation,
  which is closed data, so this is fine.

### Theories

- **Occurrence typing** (Tobin-Hochstadt & Felleisen, ICFP 2010, "Logical
  types for untyped languages"): a test narrows the type of what it tested.
  Here the narrowing comes from the *kernel's* match, the "test" the
  machine never ran. Known.
- **Double-entry bookkeeping** (Pacioli, *Summa*, 1494): every fact is
  debited to exactly one payer, and the books balance when every read
  register is paid by the machine or the kernel. Known (accounting); novel as
  a proof ledger.
- **Rely/guarantee** (Jones 1983): `loopsOk` is the guarantee that pays for
  the untested reads. Known.

### Pilot

- **FORLOOP refactor:** `class_cover forloopK` + `ClassView`. Target 29 →
  about 15 alone, or about 3 with 1.
- **LT:** `class_cover (docondjump∘δ .lt)` gives classes `(flt, flt)`,
  `(int, flt)`, `(flt, int)` and `err`.
- **SUB:** `class_cover opArith` gives three value classes plus MMBIN.
- **FORPREP:** `class_cover forprepK` on `ForCoerce`, with `tonumber?`'s
  string class as `Str2dFrom`-paid.
- **Smallest thing:** `classes forloopK FltStep` + `class_cover` +
  `ClassView` (about 110 lines), then delete FORLOOP's `kit_reg` ×3, the
  `cases v0 <;> cases v1` and `flt_parts` ×3.
