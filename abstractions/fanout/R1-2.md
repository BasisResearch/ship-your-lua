## 1. Register micro-code: `Step` as the meaning of a first-order lvm.c macro language

**Idea.** `lvm.c` is already written in a small vocabulary of macros: `vRA`/`vRB`/`KC` (read), `setobj2s`/`setivalue` (write), `dojump`/`donextjump` (control), `luai_*` (operators), plus falling through to `vmfetch`. Make that vocabulary a deep-embedded, *first-order* Lean language `μ`, and give every opcode as a μ-term `code p w : μ`. `Step` is no longer 25 hand-written constructors. It has one rule:

```
Step p s s' :↔ ∃ w, p.fetch s.pc = some w ∧ Run (code p w) s s'
```

μ has about 8 constructors. Values are built from a small expression language, so every register read is visible in the syntax:

```
inductive VE   | reg (r : Nat) | kst (i : Nat) | imm (v : Value) | prim (f : Prim) (args : List VE)
inductive μ    | wr (r : Nat) (e : VE) (k : μ)        -- setobj2s R[r] := e
               | emit (args : List VE) (k : μ)        -- luaB_print's line
               | test (e : VE) (t f : μ)              -- branch on l_isfalse / a Bool prim
               | nextJ (k : Int → μ)                  -- donextjump reads the next word's sJ (static in p)
               | go (off : Int)                       -- pc := pc + off (jumpTo)
               | fail                                 -- no rule: stuck
```

`reads`, `edgesOf` and `regTop` stop being tables. They become three folds over the term: `fv (code p w)`, `gotos (code p w)` paired with the `wr` targets on each path, and `max fv ∪ wr-targets`. The fold runs on the concrete `p`, so constant-dependent side conditions (LOADK of a string, EQK of a float) are decided by partial evaluation of `kst`.

**Core rules.**
- **L-B1 → `Run.footprint`** (one induction over μ, about 40 lines):
  `s ≈[fv m] t → s.pc = t.pc → s.out = t.out → (Run m s s₁ ↔ ∃ t₁, Run m t t₁ ∧ …)`, where there is `(pc', W) ∈ edgesμ m` with `s₁ ≈[W] t₁` and `s₁ ≈[Wᶜ] s`. The "*some* edge, not *the* edge" refinement from ROUND-1 holds automatically, because each μ path is its own edge (TESTSET's two paths to the same target are distinct paths).
- **L-B2 → `Run_iff_exec`** (one induction over μ): `Run m s s' ↔ exec m s = some s'`. `step? := exec (code p w)`. There is no per-opcode stepper to relate to anything.

**What it makes free.**
- All 75 `bc-rule-fanout` arms (`step?_sound`, `step?_complete`, `Step.sim`) become the two theorems above.
- 3 of the 5 definition sites per rule (`reads`, `edgesOf`, `regTop`) are now derived.
- The `step?` arm disappears. A new opcode costs one μ-term.
- H1 (LOADK of a string) is zero lines: `kst` already produces `.str`, and `edgesμ` stops rejecting it once `Supported`'s side condition is dropped.
- H2 CONCAT is `wr A (prim .concat ((List.range B).map (reg ∘ (A+·)))) (go 1)`.
- H3 LEN is `wr A (prim .len [reg B]) (go 1)`. H4 is the existing comparison term with `prim .lt` extended to strings.

**What it costs.**
- About 250 lines of setup: μ, VE, Run, exec, the folds, and the two theorems.
- The faithfulness reviewer now compares μ-terms against lvm.c. I claim that is *easier*, because the terms read like the macros.
- The existing inductive `Step` must either be retired, or kept as a readable view and proved equal once. That is a one-time, per-rule cost paid in R1, and it is what R1 measures.
- Harder: `FORPREP`'s `forCount` and `FORLOOP`'s three writes are awkward in μ unless `prim` covers them (`prim .forcount`). CALL's clobbering is modelled only by `emit` and nil-writes, as today.

**Theories.**
- *Known*, databases: read/write sets of transactions. Two operations with disjoint footprints commute, and a conflict is defined by footprint overlap (Bernstein, Hadzilacos and Goodman, *Concurrency Control and Recovery in Database Systems*, 1987). Here the footprint is syntactic, `fv`, exactly as in a transaction's declared read and write set.
- *Known*, algebra and PL: algebraic operations and generic effects (Plotkin and Power, "Algebraic operations and generic effects", Applied Categorical Structures 2003). μ is the free model of the signature {read, write, emit, branch, jump}, and `Run`/`exec` are its two handlers. L-B2 is the statement that the two handlers agree, proved once on the free model.
- *Known*, computer architecture: microprogramming (Wilkes, "The best way to design an automatic calculating machine", 1951). Opcodes are defined by microcode over a small datapath vocabulary.
- *Novel*: deriving the dataflow table (`edgesOf`) as an abstract interpretation of the microcode, which makes the definite-initialisation analysis's input a theorem rather than a parallel table.

**Pilot.**
- The smallest build: μ with `wr`/`test`/`nextJ`/`go`/`fail`, VE with `reg`/`kst`/`imm`/`prim`, and the two theorems.
- Port MOVE, LOADK, arith, EQ, TEST and TESTSET first (TESTSET is the edge-quantifier trap) and measure R1 on those arms.
- Then add H1–H4 as μ-terms plus `Prim` cases, and count the metatheory lines. Prediction: 0.

**Seed.** The doubled `wr` next to `R`/`r` (`NwrRf`, `Ddwrk`). An instruction is its writes and reads, so write down only those.

## 2. Section-typed transfer functions: footprints in the type, L-B1 by `congrArg`

**Idea.** Don't prove that two states agreeing on the reads step alike. Make it impossible to say anything else, by quotienting away the second copy. Each rule is a function from a *view* (a section of the register file over the read mask) to an outcome carrying a *patch* (a section over the edge's write mask):

```
def View (R : Nat) := (r : Nat) → R.testBit r = true → Value
def restrict (R) (s : State) : View R := fun r _ => s.regs r
structure Xfer (R : Nat) where
  run : View R → Option (Σ e : Edge, (r : Nat) → e.2.testBit r = true → Value) × Option String
Step p s s' :↔ ∃ w x, p.fetch s.pc = some w ∧ xfer p w = x ∧ x.run (restrict (reads w) s) = some o ∧ s' = patch s o
```

`xfer p w : Xfer (reads w)` is ordinary Lean pattern matching, close to lvm.c's C code. The type itself stops it from touching a register outside `reads w`, and `patch` can only write the edge's mask.

**Core rules.**
- **L-B1 → `Xfer.local`**: `s ≈[R] t → restrict R s = restrict R t` (funext), so both states get the same outcome by `congrArg`, and `patch` gives `s' ≈[Wᶜ] s` by definition of `patch`. Proved once, about 15 lines, with no induction at all.
- **Naturality (the definite-initialisation corollary).** For `R ⊆ M`, `restrict R` factors through `restrict M`. Every state pair agreeing on the must-initialised mask `M ⊇ reads w` is covered by the same theorem. `Step.sim` becomes a two-line corollary instead of 27 arms.
- **L-B2 → definitional.** `step? p s := (xfer p w).run (restrict …) |>.map (patch s)`, and `Step ↔ step? = some` is `Iff.rfl` up to unfolding the existential. There is no second artefact to reconcile.

**What it makes free.**
- Every `Step.sim` arm and every `step?_sound`/`_complete` arm.
- The `reads` table stays, but it is now checked by the elaborator: `xfer` does not typecheck if it reads outside `reads w`.
- `edgesOf` is still a table, but its contents are pinned by the type of the patch.
- H2–H4 cost only their `xfer` arm and their `reads` entry. CONCAT's view is over `rmask A B`.

**What it costs.**
- Dependent types over masks. Each `View` access needs a `testBit` proof, discharged by `decide`, which is fine when `w`'s fields are symbolic but only after `simp [reads, rmask]`. This is the known Lean pain point.
- The inductive `Step` loses its one-constructor-per-case readability. Mitigation: keep the docstrings per `xfer` arm.
- Cheaper setup than idea 1 (about 80 lines). It derives nothing, though, and does not help L-C1.

**Theories.**
- *Known*, databases: view update under constant complement (Bancilhon and Spyratos, "Update semantics of relational views", ACM TODS 1981). The patch is an update of the view over `W` that keeps the complement `Wᶜ` constant, which is exactly the "writes only W" half of L-B1.
- *Known*, physics: domain of dependence in causal structure (Hawking and Ellis, *The Large Scale Structure of Space-Time*, 1973). The state in a region is determined by data on its past domain, and nothing outside the light cone can matter. The reads mask is the instruction's past light cone.
- *Known, recall to check*: sheaf semantics of objects (Goguen, "Sheaf semantics for concurrent interacting objects", MSCS 1992). Views are sections, `restrict` is the restriction map, and the transfer is a natural transformation. Naturality *is* the definite-initialisation lemma.

**Pilot.**
- Define `View`/`Xfer`/`patch` and port the 27 `Step.sim` arms' rules. R1's `Step.sim` should collapse to about 20 lines.
- H1–H4: one `xfer` arm each, plus `reads` entries. Count the `decide` friction separately.

**Seed.** `Y0Y0`, a period-2 repeat: two copies of the same thing. The law is a 2-safety property about two copies of the state, so quotient them into one.

## 3. Derivations as parses: LuaSem as an LL(1)-unambiguous rule grammar

**Idea.** `ExecS.det` has 53 arms because it inverts every pair of rules that share a construct. That is an *ambiguity check on a grammar of derivations*, done by hand.

Reify `LuaSem`'s rules as a description (an indexed rule schema). Each rule is:
- a construct pattern (the input);
- a sequential chain of premises, where premise *i*'s inputs are functions of the construct and earlier outputs;
- a *discriminator*: a decidable predicate on the earlier outputs (`v.isFalse`, `sg = normal`, `n = 0`, `sg.target all`);
- a conclusion computed from all the outputs.

`ExecS`/`ExecB`/`ExecL`/`ExecBF`/`ForIter`/`Eval` are the least fixpoint `Sem D` of the description `D`.

**Core rules.**
- **L-A1, determinism half → `Sem.functional`**: `LL1 D → Functional (Sem D)`. `LL1 D` says: for two rules with the same construct pattern, the longest shared premise prefix is followed by discriminators that are disjoint on every output of that prefix. The proof is one induction: the shared prefix gives equal outputs by the induction hypothesis, disjoint discriminators give the same rule, and the rest follows by the induction hypothesis again. `LL1 D` is decided by `decide` per construct, because discriminators are drawn from a finite vocabulary (`isFalse` true/false, `sg = normal`/`≠`, `n = 0`/`≠`, `target = none`/`some`).
- **L-A1, graph half → `Sem.graph`**: `Sem D x y ↔ ∃ fuel, run D fuel x = some y`, where `run` is the *generic* fuelled evaluator of any description. It is proved once, over descriptions and not over constructs. The per-construct interpreter and `execSound` go away.

**What it makes free.**
- `Eval.det` (50 arms), `ExecS.det` (53 arms) and every `execSound` arm: 187 case obligations become two generic theorems plus one `decide` per construct.
- It kills the quadratic growth outright: adding a fourth `while` rule costs one `decide`, not four new pairs.
- H1: one rule, no discriminator.
- H2 (concat on str/int): with idea 4's δ it is one rule. Without it, it is up to four rules with disjoint discriminators on the value tags, and `decide` checks them.
- H3, H4: one rule each.

**What it costs.**
- A description language rich enough for `ExecBF`'s `jump` (the continuation's input `jumpEnv base k ρ₁` is a function of the outputs, which is allowed), for mutual families (index the description by a sort), and for `ForIter`'s changing index (`i + st`, `n - 1`). About 300–400 lines.
- The readable inductive disappears unless it is kept and proved equal once. That is a per-rule, one-time proof, and it is where R2 shrinks or doesn't.
- Harder: a proof about one construct now goes through the description. Program-level proofs by `cases h` need a derived inversion principle, obtained generically from `Sem.unfold`.

**Theories.**
- *Known*, linguistics and parsing: LL(1) grammars are unambiguous when the alternatives of a nonterminal have disjoint FIRST/FOLLOW sets (Lewis and Stearns, "Syntax-directed transduction", JACM 1968; Knuth, "Top-down syntax analysis", Acta Informatica 1971; recall, to check). *Novel*: applying this to derivation trees of a big-step semantics, where the "lookahead" is the output of the shared premise prefix and not the next token.
- *Known*, category theory: in an allegory, univalent relations (maps and partial maps) are closed under composition, and a union of univalent relations with disjoint domains is univalent (Freyd and Scedrov, *Categories, Allegories*, 1990). `Sem.functional` is this, closed under least fixpoints.
- *Known, recall to check*: determinism inference in Mercury (Henderson, Somogyi and Conway, "Determinism analysis in the Mercury compiler", ACSC 1996). Switch detection on a bound variable is the discriminator.
- *Known*: descriptions of inductive families (Chapman, Dagand, McBride and Morris, "The gentle art of levitation", ICFP 2010).

**Pilot.**
- Build the description language for the `while`/`repeat`/`if` fragment of `ExecS` plus `Eval` (skip `goto` at first). Prove `Sem.functional` and `Sem.graph`, and check `LL1` for those constructs by `decide`.
- Measure R2 on those arms.
- Then add H1–H4 as rules and count.

**Seed.** `33813`: a doubled 3 read as the 3×3 square of pairwise inversions between `whileT`/`whileF`/`whileX`. Replace the square with a linear, decidable check.

## 4. One δ: a shared primitive-operator algebra with a single strict-operator rule per layer

**Idea.** Most rule cases in both clusters are the *same shape*: evaluate operands, apply a partial primitive, store or branch. That covers arith, bitwise, unm, bnot, not, eq, eqk, eqi, the order comparisons, and in H: concat, len and string order.

Define one function over values, shared by both layers:

```
inductive Prim | arith (o) | cmp (o) | eq | not | unm | bnot | concat | len | tostr
def δ : Prim → List Value → Option Value
```

δ is total on its domain. `none` is the runtime error: no rule. It covers integer and string `lt`/`le` via `l_strcmp` as lexicographic order on `List UInt8`, `concat` over `str ∪ int` via `%d`, and `len` of `str`. Then:
- **Source** gets one rule, `Eval.strict : EvalList ρ args vs → δ (primOf op) vs = some v → Eval ρ (opExp op args) v`. It replaces `arith`, `eq`, `ne`, `cmp`, `neg`, `bnot` and `not`. `and`/`or` stay separate because they are lazy.
- **Bytecode** gets one rule per *addressing mode × continuation*, not per opcode:
  - `Step.strictSet`: `operands mode w s p = some vs → δ (primOf o) vs = some v → Step s ((s.set w.a v).goto (s.pc + skip o))`;
  - `Step.strictJump`: the same, but feeding `condJump` with `v = .bool b`.
  - The modes are `rr | rk | ri | r | range(A, B)`. `range` is CONCAT's `R[A..A+B-1]`, folded right-to-left inside δ to match `luaV_concat`.

**Core rules.**
- **L-B1 for all strict opcodes → `operands_local`**: `s ≈[modeReads mode w] t → operands mode w s p = operands mode w t p`. One lemma per addressing mode (5 modes, about 3 lines each) and *zero per primitive*, because δ never sees the state.
- **L-B2 for all strict opcodes**: one `step?` arm, `(operands …).bind (δ …)`, with one soundness and one completeness case for each of the two rules.
- **L-A1**: `Eval.strict` is functional given functional `EvalList`, whatever δ is. Its interpreter case is `evalList.bind δ`. Both are one case.
- **L-C1 (factoring)**: an arm = fetch-operands(mode) ; call-primitive ; store/branch. Prove one contract per C primitive (the `luai_numadd` expansion, `luaV_concat`, `l_strcmp`, `luaV_objlen`) and one simulation per addressing mode. The cost is |modes| + |prims| instead of |modes| × |prims|.

**What it makes free.**
- H2, H3 and H4 in *both* clusters become δ cases only: pure functions checked by `rfl`/`decide` on examples, with no metatheory lines.
- Layer B translation validation for operators becomes `rfl`, because source and bytecode call the same δ. CompCert gets a similar saving from its shared `eval_operation`.
- About 11 of 25 `Step` constructors and 7 of the ~16 `Eval` constructors collapse into 2 and 1.

**What it costs.**
- δ's argument order and conventions must match both layers. SHLI's swapped operands (`shiftl y x`) and GTI/GEI's immediate-on-the-right both become per-opcode `primOf`/`operands` entries. That is a small table, but it is inside the relation, not beside it.
- The skip-MMBIN rule (`pc + 2` for binary, `pc + 1` for unary) becomes `skip o`.
- Harder: an error must be `none` in δ, so a rule that errs after a partial write (none in F1–F4 strings) wouldn't fit.

**Theories.**
- *Known*, compilers: CompCert's `Op.eval_operation`, shared across RTL, LTL, Linear and Mach, so each pass proves operator preservation once (Leroy, "Formal verification of a realistic compiler", CACM 2009).
- *Known*, algebra: initial-algebra semantics (Goguen, Thatcher, Wagner and Wright, "Initial algebra semantics and continuous algebras", JACM 1977). δ is the Σ-algebra on `Value`, and both semantics are homomorphisms parameterised by it.
- *Known*, linguistics: Montague's compositionality as a homomorphism from syntactic to semantic algebra ("Universal Grammar", Theoria 1970).
- *Known, recall to check*: δ-rules in λδ-calculi (Barendregt, *The Lambda Calculus*, 1984, the δ-reduction section). Primitive operators are one reduction rule over an external function table.

**Pilot.**
- Implement δ for F1 operators plus the H strings.
- Rewrite `Eval`'s strict rules and `Step`'s arith/cmp rules onto `Eval.strict`, `strictSet` and `strictJump`. Measure R1 and R2.
- H1–H4 are then δ cases plus two `operands` modes (`range` and `r`). Report metatheory lines, predicted 0, separately from δ definition lines.
- This is the cheapest idea to pilot, and it composes with ideas 1–3 (it is the `prim` of idea 1).

**Seed.** `QcQ` and `BxPB`: palindromes of shape X·op·X, a binary operator between like operands. Every operator case is the same shape, so there should be one rule for it.

## 5. Dispatch head as a Poincaré section: L-C1 as a conjugacy, discharged by reflective arm summaries

**Idea.** Observe the Sail machine only when it crosses the dispatch head (the `vmfetch` / jump-table `jr` point). That gives a first-return map `ret : M ⇀ M` on the section, and L-C1 says that the decode `D : M → State` conjugates it to `Step`: `D ∘ ret = step ∘ D`. Two concepts make this one theorem instead of one proof per arm:
1. **Partition of the section by opcode.** A generic lemma about the dispatch sequence (`i & 0x7f`, table load, `jr`) says `ret` restricted to states with opcode `o` equals `runFrom (table[o])` up to the next head. This is proved once, not per opcode.
2. **Arm summaries in the micro-code of idea 1.** A *verified symbolic evaluator* `sym : Code → Addr → Option μ` covers the ~20 RV64 instructions gcc emits in the arms (ld, sd, lw, add/sub/and/or/xor, sll/srl/sra, slli, beq/bne/blt/bge, jal, jalr, lui, auipc, mv). It runs over the representation abstraction: `R[i]` is the TValue at `base + 16i` with tag at +8, `K[i]` is at `k + 16i`, and `pc` is `savedpc`. It is proved sound *once*: `sym c a = some m → ∀ σ ~ s, runFrom c a σ reaches head σ' with D σ' = run m s`. `sym` reads the fixed machine code as data; nothing about individual words is lemma'd.

**Core rules.**
- **L-C1 → `arm_sim_of_summary`**: `sym code (table[o]) = some m → m ≡ code_μ o → ArmSim o`. `≡` is μ-term equivalence under a normaliser, also proved once. Per opcode, the obligation is a closed computation (`by decide` or `by native`-free `rfl`), with proof by reflection.
- **Conjugacy composition**: from `∀ o, ArmSim o` and the partition lemma, `VmSim` follows by one induction on `Steps`, which `vm_refinement_of_sim` already consumes.

**What it makes free.**
- The forecast `a1-arm-sim` cluster (one hand simulation per rule, which the predecessor project spent months on) becomes one `rfl` per opcode.
- New H opcodes (CONCAT, LEN) cost only when their arm calls a C function (`luaV_concat`, `luaV_objlen`, `l_strcmp`). Those get a *function contract* (idea 4's per-primitive contract) that `sym` uses as an opaque `prim` node.

**What it costs.**
- `sym` and its soundness proof is the big setup, and it depends on A0.6's representation decoders.
- gcc's scheduling interleaves the operand loads of one arm, so `sym` must evaluate over a symbolic store and not recognise idioms. That is why it targets the μ semantics and not μ syntax, and it needs the normaliser `≡`.
- Arms that fall into shared tails (`checkGC`, `Protect`, `luaD_call` for `print`) need summaries of those tails as opaque μ primitives with separately proved contracts.
- Harder: anything whose effect is not register-local, such as the CALL arm's stack growth and CallInfo updates, exceeds μ, and `D` has to hide it.

**Theories.**
- *Known*, dynamical systems: the Poincaré section and first-return map, which reduces a flow to a discrete map on a transversal section (standard; e.g. Guckenheimer and Holmes, *Nonlinear Oscillations, Dynamical Systems, and Bifurcations of Vector Fields*, 1983). L-C1 is a *conjugacy* of return maps. *Novel*: using the section's partition (by opcode) to split the conjugacy proof into independent, finitely many computable checks.
- *Known*: coalgebra and bisimulation (Rutten, "Universal coalgebra: a theory of systems", TCS 2000). `D` is a coalgebra homomorphism from the section coalgebra to `step`.
- *Known*: proof by reflection (Boutin, "Using reflection to build efficient and certified decision procedures", TACS 1997). One verified evaluator replaces per-instance proofs.
- *Known, recall to check*, biology: the genetic code as a lookup table read by one universal machine, the ribosome. Correctness of translation is per-codon table correctness plus one mechanism. This is an analogy only.

**Pilot.**
- Measured only if A0.6 lands. The smallest thing to build is `sym` for the ~10 instructions of the ADD arm (loads of `R[B]`/`R[C]` tags and payloads, tag compare, add, stores, `pc++`, the jump to the head), proved sound, then `rfl` for ADD.
- EQI then adds branches, and FORLOOP adds three writes and a backward jump.
- If `sym` handles all three without new cases, the per-arm cost is the `rfl`.
- For H, CONCAT and LEN each need one C-function contract and nothing per arm.

**Seed.** `CFF0UHSBeue`: the hex-like `FF0` suggested machine words and a jump table, and the palindrome `eue` suggested a return to the same place: dispatch head → arm → dispatch head, a first-return map.

## How the five fit together

- Idea 4 (δ) is the cheapest, and it cuts across both clusters and L-C1. It should be piloted first, since it composes with everything.
- Ideas 1 and 2 are rival answers for `bc-rule-fanout`: 1 derives the tables and costs more, 2 is cheaper and derives nothing.
- Idea 3 is the answer for `ast-construct-fanout`.
- Idea 5 needs idea 1's μ as its target language.
