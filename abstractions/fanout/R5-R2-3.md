## Idea 1. Pair atoms: one comparison atom per *unordered pair of model values*, never per call

**Acts on:**
- (c) **R5-R1-4 #B**, which chooses "one atom per call";
- (c) **R5-R1-1 #A3**, which predicts FORPREP is "the search case's first instance" (coupling);
- (c) **R5-R1-3 #E** (Galois + order closure) and the feasibility filters of **R5-R1-3 #A** and **R5-R1-4 #B/#E**;
- (a) **R5-R1-3 #A** / **R5-R1-2 #A2**: it fixes their atom.

### The idea

Every M-tree variant generalises answers into atoms. The round-1 variants disagree on *what the atom is keyed by*, and that choice decides whether a feasibility filter, a coupling search or an order-closure checker is needed at all.

**Key the atom by the unordered pair of `Float.Model` values compared, with a fixed orientation.** Neither the call nor the routine nor the bit payload is part of the key.

- `atom {x, y} := Float.Model.compare x y`, with `x` the operand that appears first in the kernel clause.
- A machine call `R.S wa wb` with `toModel wa = y`, `toModel wb = x` becomes `(atom {x,y}).map swap` by one rewrite with `compare_swap`.

This is enough because two calls on the same pair can never disagree. Feasibility problems came only from treating them as independent variables. The artefact shows this directly:

| site | calls | per-call atoms | pair atoms |
|---|---|---|---|
| FORPREP float | `__eqdf2(st,0)` `c17c`, `__gedf2(st,0)` `c198`, `__ledf2(l,i)` `c1ac` / `__gedf2(l,i)` `ecf8` | 4 (256 valuations, of which 12 of 16 combinations of the first two are infeasible) | **2**: `{st,0}`, `{l,i}` (16 valuations, all feasible) |
| FORLOOP float | `__gedf2(st,0)` `e178`, `__gedf2(l,idx′)` `e188` / `__ledf2(l,idx′)` `edf8` | 3 | **2** |
| `nummod` (MOD, MODK) | kernel: `lt 0 m`, `lt b 0`, `lt m 0`, `lt 0 b` | 4 kernel tests | **2**: `{0,m}`, `{0,b}` |
| f2i chain | `__eqdf2(n,f)`, `__gedf2(f,K₁)`, `__ledf2(f,K₂)` | 3 | 3, and the kernel's `flttointeger` tests **the same three pairs in the same order** |

So R5-R1-1 #A3's FORPREP coupling case does not exist. `compare st 0` and `compare 0 st` are one atom.

The f2i chain needs **no** feasibility filter, order closure or Galois lemma. The kernel was written in C shape (`Arith.lean:89`), so after pair atomisation the machine's decision function and the kernel's are the *same Boolean function* of three atoms. They agree on every valuation, the infeasible ones included. R5-R1-3 #E's ≈180 lines (E1's 80 + E4's 100) answer a question this key never raises.

### Core rules

| law | rule (proved once) | decided at a use site by |
|---|---|---|
| L5-comm (orientation) | `Float.Model.compare_swap : Float.Model.compare y x = (Float.Model.compare x y).map Ordering.swap`, from `F64.compare_swap` through `compare_eq_model` (or directly on `UnpackedFloat.compare`; ≈10 lines) | **syntactic**: the atomiser orients each call by comparing its two model terms against the kernel's operand order. Both are closed *syntax*. |
| kernel side | none needed. `Float.Model.lt/le/beq x y` unfold **by `rfl`** to `(Float.Model.compare x y == some .lt)`, `.any isLE` and `== some .eq` (core's definitions, checked) | `simp only [Float.Model.lt, …]` or `show`; the result is a closed function of the atom |
| machine side | `R.S wa wb = code R (F64.compare wa wb)` (the routine's spec, `rfl` after unfolding) then `compare_eq_model` | rewrite |
| L5-chain | none: the chain is three atoms. The literals `K₁`, `K₂` meet `minIntF`, `minIntF.neg` by one closed fact each, `toModel (image bytes at 0x8005c478) = minIntF`, by `decide +kernel` on a ground term | computation, closed |
| `generalize` | `generalize Float.Model.compare x y = o` across machine goal and kernel goal at once | syntactic; it works only because both sides now contain the *identical* term |

**Symbolic data.**
- Payloads never enter a decision.
- Atoms over *computed* values need the value equation first, and then the atom: MOD's `m = fmod a b`, the ceil chain's `f + 1`, FORLOOP's `idx′ = st + i`. Examples:
  - `Adddf3.S wf one = ofModel (Float.Model.add f 1)` via `SoftFloatSpec` + `add_eq_model`;
  - then `toModel` of it is the kernel's `Float.Model.add f (.ofNat 1)`.
- "Value before atom" is a fixed ordering of the normaliser, not a search.

**Hidden cost every M-tree variant skipped.**
- Core Lean has no `Fintype`. So `decide` on `∀ o : Option Ordering, …` (let alone a product) has no instance.
- One small `Enum α` class (`all : List α`, `complete : ∀ a, a ∈ all`) with instances for `Option Ordering`, `Bool` and pairs, plus `decide` through `List.all`, is about 25 lines. Only R5-R1-4 #A mentions this.

### What it makes free

- The feasibility filter (R5-R1-3 #A `Φ`, R5-R1-4 #B `feas`/`FeasSound`, R5-R1-4 #E `feasible`) for every arm whose kernel is in C shape. That is all of them: `forprepK`, `forloopK`, `nummod`, `flttointeger`, `forLimit` and `ltNum` mirror `lvm.c`.
- The coupling search of R5-R1-1 #A3, the only rule round 1 flagged as "decided by search".
- C5-f2i: 20 sites, 6 layouts and 3 modes, with no summary, certificate or Galois lemma. Layout polarity is `relOf`'s; the modes are the kernel's own `match`.
- O-ord: GTI's `__gedf2(x, imm)` against `lt imm x` is one oriented atom.

### What it costs

- The 25-line `Enum`, the 10-line model-level `compare_swap`, one literal fact per rodata constant (`0.0`, `1.0`, `±2^63`: 4 facts), and the atomiser: a `generalize` driver that orients by syntax, about 40 lines of `Lean.Meta`.
  - If a tactic is unwelcome, a named lemma `atomise₂ : P (Float.Model.compare x y) (Float.Model.compare y x) ↔ ∀ o, P o (o.map swap)` does it by `rw`.
- **What gets harder:** a kernel written *not* in C shape would reintroduce feasibility.
  - That makes "the kernel mirrors lvm.c's test order" a discipline rule.
  - Proposed `discipline_rules.tsv` line: forbid `Float.Model.compare` matched by hand in `Lua/Bytecode/Semantics.lean`, and require the `lt/le/beq` combinators.

### Theories

- **Atom canonicalisation in SMT solvers** (known): Z3 and others normalise `b > a` and `a < b` to one atom before DPLL, so the Boolean skeleton never sees two variables for one fact (de Moura & Bjørner, "Z3: an efficient SMT solver", TACAS 2008 **[recall]**). Here it is a proof normal form, not a solver step.
- **Converse relations in lexical semantics** (known): *buy/sell*, *above/below* and *before/after* name one relation from two ends (Lyons, *Semantics*, 1977, ch. 9 **[recall]**). A comparison call is a converse lexicalisation of the pair's one ordering; the atom is the relation, and the call picks a word for it. Novel as a proof device.
- **The chemical bond as an unordered pair** (known): valence counts bonds, not bond ends. Two calls on the same pair are two ends of one bond.

### Pilot

  - two pair atoms `{st,0}` and `{l,i}`;
  - the step-zero error is `o₁ = some .eq` (kernel `none`, no obligation);

  - the `tonumber` prefix is the class view's (M-view), with `luaV_tonumber_` as the callee summary under `Str2dFrom`.
- **LT (held out):**
  - float/float: one atom;
  - int/float with `intfitsf`: one atom on `{ofI i, f}` (`__floatdidf` value first);
  - otherwise the ceil/floor chain: 3 atoms + the final `{i, fi}` integer compare, which is an integer ALU guard, cased by the kernel's own `if`.
  - No filter at any leaf.
- **SUB (held out):** no atoms (control).
- **FORLOOP refactor:** 2 atoms; `model_add_comm` is the value equation, not a line.
- **Smallest thing to build:** `Enum` + model `compare_swap` + `atomise₂`. Then a `decide` that FORPREP's machine decision function (`relOf` of its 4 idioms on 2 atoms) equals `forprepK`'s float clause. The falsifier is that one `decide`.

### Seed

- The string has **no repeated 3-gram**: nothing should exist twice, so two calls on one pair must be one atom.
- The doubled letters (`oo`, `QQ`, …): the same thing asked twice, as FORPREP asks about `(step, 0)` twice.

## Idea 2. Split on the bit the machine reads, decide the kernel under the path condition

**Acts on:**
- (c) **R5-R1-3 #A** ("split ONCE on `oᵢ`: `cases oᵢ`, 4 children") and **R5-R1-4 #B** ("at a fork the proof cases on the atom, 4 cases");
- (c) **R5-R1-5 #1**'s deep embedding as the vehicle;
- (b) combines **R5-R1-3 #A**'s `at_run_fork` with **R5-R1-5 #2**'s `relOf`.

### The idea

A machine fork reads one bit, `relOf R ι o`. Casing the 4-valued `o` gives 4 children, but the machine has 2 successors. So 2 of the 4 children (often 3) re-run the *same* machine suffix.

- **FORLOOP, first fork** (`blez` on `__gedf2(st,0)`): the children `{lt, eq, none}` all take the negative side. That side contains a `__ledf2` call and a second fork, so `cases o₁` runs it 3 times.
- This is the 8.3k "prefix replay" again, moved one fork down.
- The variant that splits on the kernel first (today) and the variant that splits on the atom (round 1) both replay. Only a split on the **bit** matches the machine one-to-one.

So:
1. **At a fork:** rewrite the guard to `relOf R ι o` (closed function of the atom). `cases h : relOf R ι o` gives **2 goals**. The branch lemma is selected by `h`, a closed `Bool`, so no closer is tried.
2. **At a leaf:** the path condition is the list `Π = [relOf Rⱼ ιⱼ oⱼ = bⱼ]`. The obligation "the kernel's outcome is this leaf's class" is the closed statement `∀ o⃗ ∈ Enum.all, Π o⃗ → K o⃗ = c`. It is decided by `decide` over ≤ 4^k points (16 for FORLOOP/FORPREP).
   - The kernel is never split.
   - `K` is the kernel's float clause after idea 1's atomisation, a closed function.

Heartbeats are then prefix + Σ over *machine* leaves (suffix + one ≤16-point `decide`). There is no factor of answer values and no factor of kernel outcomes.

### Core rules

| law | rule | decided at a use site by |
|---|---|---|
| L5-fork | **`fork_bit`**: `(b = true → wp t Φ) → (b = false → wp f Φ) → wp (branch-on b; t | f) Φ`. This is the existing branch run lemma with its guard abstracted to a `Bool` term. | syntactic: the at-runner stops at a branch whose guard is not a literal, rewrites it by `idiom_fork`, and emits `cases h : relOf …` |
| L5-idiom | `idiom_fork R ι a b : ι.eval (R.S a b) = relOf R ι (F64.compare a b)` (R5-R1-5 #2) | `rfl` after unfolding `R.S`; `relOf` on a literal `ι` reduces by `decide` |
| L5-read′ + L5-fork | **`leaf_by_pc`**: `(∀ o⃗, Π o⃗ → K o⃗ = c) → Π (atoms) → K (atoms) = c` | `decide` on the closed statement, which is closed after `generalize` (idea 1) |
| many-to-one leaves | nothing new: several machine leaves can name the same `c` | — |

**Symbolic data:** none in any `decide`. Payloads stay in the atoms, and the atoms are generalised before the leaf's `decide`.

**Search:** none. The fork's polarity is `h`. The one remaining search is today's candidate trial over *which segment lemma*, unchanged.

### What it makes free

- FORLOOP's replay (8.3k) and polarity trial (10.3k) **without** the 4× child duplication that `cases o` reintroduces. It also does this without a tree datatype, a `Mesh`, an `OTree` or a 200-line `mtree_run`.
- The forecast budget breach for LT/LE (24 paths) and SHL/SHR (22). The cost is linear in machine leaves, as in Pidgin, at a fraction of the setup.
- The "kernel outcomes" `rcases … <;> split <;> rename_i` lines in every FORLOOP-like arm.

### What it costs

- `fork_bit` as an at-route entry point (≈20 lines, a variant of the branch lemma that takes a `Bool` term), and `leaf_by_pc` (≈10 lines).
- The at-runner's change: stop at a non-literal guard instead of trying closers. I cannot read the kit, so this is unverified. R5-R1-2 #A2 estimates 20 lines.
- **What gets harder:**
  - A leaf's `decide` failure says only "false". An `#eval` that prints the failing `o⃗` is needed, as R5-R1-1 #A3 says.
  - Seven spilled `a0` sites need the bit carried as a value until its branch. With pair atoms the carried value is `code R o`, a closed function of `o`, so `relOf` still applies where it is finally read.

### Theories

- **Reduced decision diagrams** (known; Bryant, IEEE TC 1986): the reduction rule merges children with the same sub-diagram. `cases o` builds the unreduced 4-ary node; `cases relOf` is the reduced binary one.
- **Value of information in decision analysis** (known; Raiffa & Schlaifer, *Applied Statistical Decision Theory*, 1961): split only on what changes the action. The machine's action depends on the bit, and the 4-point answer is information it never acts on. Novel as a proof-search rule.
- **Path conditions in symbolic execution** (known; King, CACM 1976): the leaf's `Π` is the path condition. Here it is closed and finite, so it is discharged by enumeration, not by a solver.

### Pilot

- **FORLOOP refactor:** prefix once, then `fork_bit` at `e17c` (2 goals). With idea 3, the second fork is after the join and runs once. Then two `leaf_by_pc` decides. Target: ≤ 6 lines, ≤ 30k heartbeats (against 29 lines and 59.1k).
- **LT:** the longest path has ≤ 4 forks, so ≤ 2^4 machine leaves per class. Each leaf is a `decide` over ≤ 4^3·2 points. Measure the heartbeats against the 24 × 15k forecast.
- **FORPREP:** 3 forks (`bnez` at `c180`, `bgtz` at `c1a0`, the φ branch at `c1b8`), so 4 leaves: error, skip, enter, plus the second side.
- **SUB:** idle (control).
- **Smallest thing to build:** `fork_bit` + `leaf_by_pc` on FORLOOP. The metric is that heartbeats fall by more than the 18.6k that `cases o` would only partly remove.

### Seed

- `441`: two 4-valued things, `44`, followed by one `1`. The machine reads one bit from a 4-point answer.
- `QQ`: the same query asked twice. Ask once, and only for the bit.

## Idea 3. Signed bound: FORLOOP and FORPREP are one float skeleton with a φ join

**Acts on:**
- (d) somewhere round 1 did not go;
- (c) **R5-R1-5 #4**'s verdict that FORPREP is "not covered; report it as the obstruction", and **R5-R1-1 #A5**'s "FORLOOP and FORPREP … get their own `classify` but no domain parametricity";
- (a) **R5-R1-5**'s disassembly fact about FORLOOP's join at `0x8001e194`, which I found repeated in FORPREP at `0x8001c1b8`.

### The idea

L5-share is false *between int and float*. Round 1 concluded that FORLOOP and FORPREP are each on their own. But they share a skeleton **with each other**. Both kernels' float clauses contain the C idiom `luai_numlt(0, step) ? R(a, b) : R(b, a)`:
- `forloopK`: `if lt 0 st then le idx l else le l idx`;
- `forprepK`: `if lt 0 fs then lt fl fi else lt fi fl`.

Both machine paths compile it the same way (checked above):
1. one `__gedf2(st, 0)` with a sign idiom;
2. on each side, one call on the **same ordered pair** with a different idiom:
   - FORLOOP: `__gedf2(l,idx′)` with `not;srli 63`, and `__ledf2(l,idx′)` with `slti 1`;
   - FORPREP: `__ledf2(l,i)` with `srli 63`, and `__gedf2(l,i)` with `sgtz`;
3. a φ join that turns both into one 0/1 register (`a5` at `e194`, `a4` at `c1b8`);
4. **one** branch on it.

Name the kernel idiom once:

```
def sgnBound (R : Float.Model → Float.Model → Bool) (st a b : Float.Model) : Bool :=
  if Float.Model.lt Lua.Num.zero st then R a b else R b a
```

The two kernel clauses become `sgnBound le st idx l` and `sgnBound lt fs fl fi`. Both rewrites are `rfl`: the definitions are those expressions.

On the machine side, the φ join is **run once as a join summary**, not once per side. Both sides of `fork_bit` (idea 2) end at the join pc with the frame equal except one register. So:

> **`phi_join`** (once, at-route): if `wp` from the left side reaches `pcⱼ` with `r := vₜ` and from the right side reaches `pcⱼ` with `r := v_f`, then the fork reaches `pcⱼ` with `r := if b then vₜ else v_f`.

After the join, the suffix (the bound branch and the stores or skip) runs **once** with a symbolic bit. Then one `fork_bit` and two leaves.

With pair atoms `o_s = compare st 0` and `o_b = compare l x`, the join value is a closed function `J (ι₁, ι₂, ι₃) o_s o_b`. Agreement with `sgnBound R` is one `decide` over 16 points per idiom triple. There are two triples (FORLOOP's and FORPREP's), so this is checked once each, in one table.

### Core rules

| law | rule | decided at a use site by |
|---|---|---|
| (new) shared kernel idiom | `forloopK_float = … sgnBound Float.Model.le st idx l …`, `forprepK_float = … sgnBound Float.Model.lt fs fl fi …` | `rfl` |
| L5-fork at a join | **`phi_join`** over `MachWP` (≈30 lines): the two sides as hypotheses, one continuation | syntactic: the join pc is generator data (the target of the side's `j`, e.g. `ee00 → e194`, `ed04 → c1b8`) |
| L5-idiom, L5-comm | **`sgnBound_tab`**: `∀ o_s o_b, (relOf Ge blez o_s = false → …)`, i.e. `J τ o_s o_b = sgnBound' R o_s o_b` for the 2 idiom triples τ | **one `decide`** over `2 × 16` closed points |
| step-zero (FORPREP only) | `__eqdf2(st,0)` + `bnez` is `o_s ≠ some .eq`, the same atom (idea 1), and the error side is kernel `none` | `relOf`, closed |

**Symbolic data:** `st`, `l`, `i`/`idx` stay symbolic. Only `o_s` and `o_b` are enumerated.

### What it makes free

- **FORPREP's float clause as FORLOOP's**, plus one zero test and the coercing prefix. That is 10 float paths reduced to 3 leaves (error, skip, enter), with the second side folded by `phi_join`.
- **FORLOOP's second fork** runs once, not once per side. Each side is only `call + idiom`, so the suffix (`e1a0–e1b8` stores, tail `c240`) is the only thing run twice (back and exit).
- **`forLimit`'s sign split** (`if 0 < step` / `lt zero n.toFloat`) is the integer-step cousin of the same idiom. It reads an int sign, so it is a kernel `if`, not a float atom. It does not need `phi_join`.

### What it costs

- `sgnBound` (3 lines), two `rfl` rewrites, `phi_join` (≈30 lines over `MachWP`), and the 2-row `sgnBound_tab` (`decide`).
- **What gets harder:** `phi_join` needs both sides to leave the *same* frame except the joined register.
  - At `e194` they do: each side is `mv a0; mv a1; jal; idiom → a5`, and every other register is callee-saved across the call.
  - At `c1b8` the negative side reloads `a5` from `16(sp)` (`ecfc`), as the positive side does (`c1b0`). That is the same value, so the frames agree.
  - The frame equality is `FrameMeta.abiFrame_of_wrChain`'s business, one `decide`.
  - **If a future compile breaks the frame symmetry, `phi_join` fails by name.**

### Theories

- **Direction bits in sorting networks** (known; Batcher, "Sorting networks and their applications", AFIPS SJCC 1968): a bitonic merger's comparator is `dir ? cmpx(a, b) : cmpx(b, a)`. One comparator design, with the direction selecting the orientation.
- **Signed-increment DO loops** (known; ISO/IEC 1539 Fortran, the iteration count `MAX(INT((m2 − m1 + m3)/m3), 0)` **[recall]**): the loop test's orientation is a function of the step's sign, defined once for both directions.
- **Melodic inversion in counterpoint** (known, e.g. Fux, *Gradus ad Parnassum*, 1725): one motif played upright or upside down. `sgnBound` is the motif, and the step sign is the inversion. Novel as a proof device.

### Pilot

- **FORLOOP refactor:** `class_cover` (M-view) → prefix → `fork_bit` at `e17c` → `phi_join` at `e194` → `fork_bit` → 2 × `leaf_by_pc`, with `sgnBound_tab` closing the bound. Target ≤ 6 lines.
- **FORPREP (held out):** the same script with the coercing prefix, plus one `fork_bit` for step zero. The measure is the lines *beyond* FORLOOP's (target ≤ 3 + the `tonumber` prefix).
- **LT, SUB:** idle. LT's `ltNum` has no step sign; it is ideas 1 and 2 only.
- **Smallest thing to build:** `sgnBound`, the two `rfl` rewrites and `sgnBound_tab` by `decide`. That checks the machine's 2 idiom triples against the kernel *before* any at-route work, and is a pure falsifier: if it is false, the skeleton is not shared.

### Seed

- `62` and `82`: two heads, one tail, which is a φ join.
- `89` and `82`: one head, two tails, which is the shared `__gedf2(st,0)` prefix with two loops after it.
- `441`: two 4-valued atoms into one bit, which is the joined register.

## Idea 4. One jam, any divisor: `shr_jam` is the whole rounding hand-off, for add, sub, mul, div and floatdidf

**Acts on:**
- (a) **R5-R1-2 #A1**'s `shr_ro`, the cheapest M-odd member, generalised from `2^k` to any divisor;
- (c) **R5-R1-1 #A1** and **R5-R1-5 #3**'s claim that `__divdf3` is "the same `round_odd`" / "`rto` by another name". It is not literally: its sticky source is a remainder, not a shift, and the spec encodes its round bit differently.
- (c) **R5-R1-3 #C**'s C0 `round_rbst`, which is flagged "[to check] … a corner at `n` small".

### The idea

Every sticky source in soft-fp is a **division with the remainder folded into the last bit**:
- the SRS shift is division by `2^k`;
- the 106-bit product's collapse is division by `2^53` or so **[recall: `_FP_MUL_MEAT_D` then `_FP_FRAC_SRS`]**;
- `__divdf3`'s quotient sets `q |= (r ≠ 0)` **[recall: `_FP_DIV_MEAT_1_udiv_norm`]**, which is division by `m₂`.

Define one jam, over a divisor:

```
def jam (a b : Nat) : Nat := a / b ||| (if a % b = 0 then 0 else 1)
```

`rto n k = jam n (2^k)`. Then **one** lemma, `shr_jam`, is the hand-off:

```
theorem shr_jam (a b s : Nat) (hb : 0 < b) (hs : 2 ≤ s) :
  F64.shr (jam a b) false false s
    = (a / (b * 2^s), decide (a / (b * 2^(s-1)) % 2 = 1), decide (a % (b * 2^(s-1)) ≠ 0))
```

The right side is the *exact* triple of the rational `a/b` at `s` bits. Law check: 0 failures in 66,924 cases over `b < 40`, and the `s = 1` boundary fails (14,054 cases).

Since there is no CSR read in the ELF, RNE is the only rounding to match. And since `F64.round` reads only `(q, rb, st)` and `target`, agreement of the triple is agreement of the rounding. **No round-to-odd theorem is needed**, only this triple equality. That is why it is cheaper than R5-R1-1 #A1's `round_odd`, R5-R1-4 #D's `rne_of_stamp` and R5-R1-5 #3's R3d: each of those passes through `rne`.

`target` needs one more fact, `log2 (jam a b) = log2 (a / b)` when `a / b ≥ 2`. It holds because OR-ing bit 0 never moves the top bit once the value is ≥ 2.

**The two spec encodings.**
- `F64.add`/`sub`/`mul` and `ofInt` call `round … false false` on an exact integer. There `shr_jam` with `b = 2^k` meets them directly: the exact triple at `s + k` is `shr n false false (s + k)`.
- `F64.div` calls `round q t rb st` with `divCore`'s encoding: `rb = (m₂ ≤ 2r)`, `st = (r ≠ 0 ∧ 2r ≠ m₂)`. That is a *different* `(rb, st)` convention from the exact triple at one more bit.
- So `__divdf3` needs one bridge, **`round_divCore`**: `round neg q t rb_d st_d = round neg (jam a' m₂) (t − 2) false false` for the soft-fp scaled dividend `a'`. Its premise is "`a'/m₂ ≥ 2^54`", i.e. at least two extra quotient bits.
- This is R5-R1-3 #C's C0 with its corner named: when the quotient has fewer than 2 extra bits, the two encodings can disagree. soft-fp's dividend scaling keeps ≥ 3 **[recall: `_FP_WFRACBITS`]**, so the premise is the routine's scaling constant, a literal fact.

### Core rules

| law | rule | decided at a use site by |
|---|---|---|
| L5-stage (SRS) | `srs_jam`: the machine's `srl/sll 64−k/snez/or` = `BitVec.ofNat 64 (jam x.toNat (2^k))`, `1 ≤ k ≤ 63` (R5-R1-2 #A1's `srsMachine`, renamed) | syntactic match on the node; `1 ≤ k` from the dominating guard, `omega` on literals |
| hand-off | **`shr_jam`** (above) | rewrite; `2 ≤ s` is linear in the exponent atoms, `omega` with `2^k` opaque |
| exact anchor | `jam_add_even`: `2 ∣ X → X + jam Y (2^k) = jam (X·2^k + Y) (2^k)`, and `jam_sub_even` (law-checked; the odd anchor fails 25,088 times, so `2 ∣ X` is load-bearing) | rewrite; `2 ∣ X` from `X = f <<< 3` |
| composition | `jam_jam`: `jam (jam a b) c = jam a (b·c)` | rewrite (the carry renormalise `jam _ 2` after an SRS) |
| cancellation | `cancel_le_one`: `d ≥ 2`, `A ∈ [2^55, 2^56)`, `B < 2^56` → `log2 (A − jam B 2^d) ≥ 54`. Law-checked: the normalising shift is ≤ 1 for `d ≥ 2` on 299,882 pairs | `omega` after `generalize log2` |
| div | `round_divCore` (above) | rewrite; premise by `decide` on soft-fp's literal scaling |

**Symbolic data:** `a`, `b`, `k` and `s` stay symbolic. `2^k` is an opaque atom outside the five lemma proofs.

### What it makes free

- The rounding half of every arithmetic `SoftFloatSpec` field: add, sub, mul, div and `floatdidf`, from one triple lemma plus one div bridge. Round 1 had a separate story for div (C0) or a `[CHECK]`.
- `__muldf3`'s level (b) once its level (a) lands. Its product collapse is `jam p (2^53)` or so, then `shr_jam`.
- Every margin argument becomes the single side condition `2 ≤ s`. The subnormal case only raises `s`, because `target`'s `max … (−1074)` is coarser.

### What it costs

- ≈ 120 lines of `Nat`.
  - `shr_jam` is the core, ≈ 40 lines via `Nat.div_div_eq_div_mul` and a parity case on `a / (b·2^(s−1))`.
  - `log2_jam` and `cancel_le_one` (≈ 15 lines each) need `Nat.log2` bounds, which core has only partly: `Nat.lt_pow_succ_log_self`, `Nat.log2_lt` **[recall: names]**.
- `round_divCore`: ≈ 30 lines.
- **What gets harder:** nothing new; this removes the `rne`-level proofs.
- **The risk** is not the math (law-checked) but matching the 497-path DAG to stages. That is idea 5's subject.

### Theories

- **Round to odd** (known; Boldo & Melquiond, IEEE TC 57(4), 2008): `jam` is round-to-odd. `shr_jam` is the observational core of their theorem, before any rounding mode is applied.
- **Censored observations in survival analysis** (known; Kaplan & Meier, JASA 1958): an observation records "the event happened beyond this point" without its value. The jam bit is a censoring indicator. Kaplan–Meier is exact for any statistic that reads only through censoring, as `round` reads only through `(q, rb, st)`. Novel as a framing.
- **Euclidean division as the universal remainder** (known, elementary): shift, product collapse and quotient are one operation `(a / b, a % b ≠ 0)`. That is why one lemma covers all three.

### Pilot

- **`SoftFloatSpec.adddf3`/`subdf3` (held out):** `shr_jam`, `jam_add_even`/`jam_sub_even`, `jam_jam`, `cancel_le_one` close the finite × finite clause, given idea 5's stage cut.
- **Arms:** idle.
- **Smallest thing to build:** `Lua/Num/Jam.lean` with `jam`, `shr_jam`, `jam_add_even`, `jam_sub_even`, `jam_jam`, about 80 lines.
  - Go/no-go: `shr_jam` under 200k with no `BitVec`.
  - The Python law check is already done (above). A Lean `decide` on `a < 256`, `b < 8`, `s < 5` is a second, kernel-checked sanity check.

### Seed

- `oo` (o for odd, doubled: double rounding).
- The lone `1` after `44`: one bit that remembers the whole tail.
- The absence of repeats: the three sticky sources are not three things.

## Idea 5. A soft-fp-shaped reference (`SfRef`): split level (b) at the C macros, so `__subdf3`'s *spec* half is definitional and its *machine* half is the same chamber script

**Acts on:**
- (b) combines **R5-R1-2 #A5** (chambers) with **R5-R1-1 #A1** / idea 4 (the jam algebra);
- (c) **R5-R1-3 #D**'s requirement that the generated `F` become data plus an interpreter, with level (a) re-proved;
- (c) **R5-R1-5 #3**'s per-node invariants "generated from stage recognition", whose recogniser is the search point it flags itself;
- (c) **R5-R1-1 #A2**'s `conj_of_core`, which needs an `F = core ∘ unpack` factorisation of the binary that its own text says does not exist.

### The idea

Kernel arms got cheap where the kernel was written in **C shape**: idea 1's f2i chain needs no filter because `flttointeger` follows `lvm.c`. Do the same at level (b). Insert one reference program between the lifted `F` and `F64.add`:

```
SfRef.add : F64 → F64 → F64
```

It is written **as soft-fp's `_FP_ADD_INTERNAL` reads** **[recall: `op-common.h`, semiraw form]**:
- unpack;
- the class switch;
- `<< 3`;
- swap so that `ea ≥ eb`;
- `d ≥ 56` → sticky-only, else `jam B (2^d)`;
- same sign: add, carry → `jam _ 2`; else: subtract, `clz` normalise;
- RNE at 3 bits;
- pack.

All in `Nat` with `jam`. It is about 40 lines and *one* function, not 497 paths. Its branches are the C macro's branches, about 10.

`SfRef.sub a b := SfRef.add a (flipUnlessNaN b)` is soft-fp's own `_FP_SUB` definition **[recall: it flips `Y`'s sign unless `Y` is NaN, then runs the same macro]**. Here the seed's one-mismatch mirror (`qALVoAQ`) is exact: sub and add are the same text with one letter changed, *in the source*. The binary does not keep the symmetry. R5-R1-2 #A1 and R5-R1-4 #A showed that `__subdf3` is a separately compiled 142-node DAG.

Level (b) then splits into two parts.

- **(b2) `SfRef.add = F64.add`**, pure `Nat`/`Int`, proved once by idea 4's lemmas. `SfRef.sub = F64.sub` follows from (b2) and the 9-clause spec identity `F64.sub a b = F64.add a (neg b)` (NaN clause: both `qnan`). **No second proof.**
  - Python evidence: the soft-fp-shaped add equals IEEE on 299,882 pairs. That is (b2) checked as a law, including subnormals and cancellation.
- **(b1) `Adddf3.F = SfRef.add` and `Subdf3.F = SfRef.sub`**: the binary against a C-shaped program.
  - By chambers (R5-R1-2 #A5): the chambers are `SfRef`'s ≈ 10 branches, read off its definition, not the code's 497 paths.
  - In each chamber, the chamber's hypotheses fix every exponent and class guard of `F`. `simp only [F, guards]` reduces `F` to the straight-line node chain, which meets `SfRef`'s branch by:
    - `srs_jam` at the SRS node;
    - literal-shift field lemmas elsewhere (`F64Lens`, R5-R1-2 #A5);
    - one `roundPack` stage equation at the join.
  - `__subdf3`'s chambers are add's with `sign_b` negated, so the chamber *list* is shared data.

### Core rules

| law | rule | decided at a use site by |
|---|---|---|
| L5-comm (spec, sub) | `SfRef.sub = SfRef.add ∘ (id, flipUnlessNaN)`: **by definition** | `rfl` |
| L5-comm (spec) | `F64.sub_eq_add_neg` (9 clauses, `cases` on `cls`, `cls_neg`) | `cases` + `rfl` |
| L5-stage + hand-off | (b2) `SfRef.add_eq : SfRef.add = F64.add`: the 8 special clauses by `rfl`, the finite clause by idea 4 | proved once; rewrite |
| L5-stage (matching) | (b1) **`chambers_cover`** (one `omega` over the 11-bit exponent atoms and the class Booleans), and per chamber `F = SfRef` by `simp only` under the chamber's hypotheses | the cover by `omega`; per chamber by **rewriting with literal shifts only**. The one variable shift per chamber is the SRS node, consumed by `srs_jam`. |
| frame | `reload_forward` (R5-R1-3 #D) applied in `gen_lua_fn.py`'s emission, so `F` has no `m`; level (a)'s proof is unchanged in form | `decide` on the closed offset list |

**Search:** none at use sites. The chamber list is `SfRef`'s branch list (data), and the per-chamber tactic is fixed.

**Flag (vocabulary).** The per-chamber script is one tactic block over a closed list, `∀ c ∈ chambers, …`, per routine. It is not a hand equality per path, and the generator emits only the chamber list (data). The bake-off must check that this does not count as "a per-routine hand equality proof of a lifted function".

### What it makes free

- `__subdf3`'s (b2) entirely. Its (b1) is a rerun of add's chamber list with one sign flipped. That is the most of the "sub is free" claim that survives the correction.
- The DAG-as-data rewrite of R5-R1-3 #D, and the re-proof of level (a): `F` stays a nest of `def`s.
- R5-R1-5 #3's stage recogniser: there is nothing to recognise. `SfRef` *is* the stage structure, written down once.
- `__muldf3`/`__divdf3` later: `SfRef.mul`/`div` from `_FP_MUL`/`_FP_DIV`, with (b2) by idea 4's `jam_jam`/`round_divCore`.

### What it costs

- `SfRef.add` (≈ 40 lines), (b2) (≈ 60 lines over idea 4's lemmas), `F64.sub_eq_add_neg` (≈ 20), `chambers_cover` (≈ 30 one-line predicates + one `omega`), and `reload_forward` in the generator.
- **The real risk is (b1)'s per-chamber `simp` on a 133-node `F`**: whether unfolding stays within the default budget per chamber. R5-R1-2 #A5 named this; it is still the go/no-go.
- **What gets harder:** `SfRef` must follow soft-fp's control flow closely enough that each chamber of `SfRef` fixes *every* guard of `F`.
  - `F`'s data-dependent guards (`(x & 7) ≠ 0`, the carry test, R5-R1-4 #E's point) are inside the round and carry stages.
  - They must sit inside `SfRef`'s round and carry stages too, as sub-branches of the chamber, or the chamber `simp` meets an unresolved `if`.

### Theories

- **Two-step floating-point verification against an algorithmic model** (known): Russinoff proved AMD's RTL against a C-like algorithm and the algorithm against IEEE (e.g. "A mechanically checked proof of IEEE compliance of the floating point multiplication, division and square root algorithms of the AMD-K7 processor", LMS JCM 1, 1998 **[recall]**). `SfRef` is that middle layer, written from soft-fp's macros.
- **Interlinear glossing** (known; the Leipzig Glossing Rules, 2008): between a source line and its free translation sits a morpheme-by-morpheme gloss that matches the source's structure and the translation's meaning. `SfRef` is the gloss: (b1) is the gloss's fidelity to the source, (b2) its meaning. Novel as a proof architecture.
- **Translation validation** (known; Pnueli, Siegel & Singerman, TACAS 1998): (b1) validates one compilation of a known program, not an arbitrary DAG.

### Pilot

- **`SoftFloatSpec.adddf3` (held out):**
  1. (b2) first: `SfRef.add_eq` with idea 4. This is pure `Nat`, independent of the DAG, so it is the cheap half.
  2. Then (b1) on three chambers: `a` NaN, same-sign `4 ≤ d ≤ 56`, and opposite-sign `d ≥ 2`.
  3. Measure heartbeats per chamber.
- **`SoftFloatSpec.subdf3` (held out):** (b2) by `rfl` + `sub_eq_add_neg`. (b1) on the same three chambers with `sign_b` flipped. Report the *new* hand lines (target: 0 beyond the chamber list).
- **Arms:** idle.
- **Smallest thing to build:** `SfRef.add` in Lean, plus `#eval` agreement with `Adddf3.F` *and* `F64.add` on `SpecTest`'s 2,900 pairs. That is one falsifier for both halves, before any proof.

### Seed

- The single near-palindrome `qALVoAQ` with exactly one mismatch, at the centre: sub is add with one letter changed. That is true in soft-fp's source, which is the layer `SfRef` writes down, and false in the compiled binary.
