## 1. Slot lens: `VmRel` as the graph of a decoder, and closes as lens laws

**Idea.** L-C4's checker already has a total decoder: from a head state it reads `pc` from `s11`, `R[j]` from the 9 bytes at `s9+16j`, and `out` from the console. Make that decoder the relation's core instead of a list of per-slot `ValRepr` facts. It is a *lens* on memory: `get` decodes a slot, and `put` is "some store sequence that leaves the slot's 9 bytes representing `v`". The census's cluster (c) (closes, `slotStore_*`, `Core.write/jump/forloop`, the `*_of` transports) is re-proving the lens laws once per store shape and once per close. Prove the lens laws once, over an *abstract store trace*, and every close follows as a corollary.

**Core rules.**

- **R1.1 `Dec` (L-C4 as a definition, not a check).**

  ```
  decSlot (mo m : Mem) (a : Nat) : Option Value
  ```

  `decSlot` is partial but computable, and `ValRepr mo t x v ↔ decSlot mo m a = some v` whenever `t, x` are read at `a`. `Core.stack` becomes `∀ j v, s.regs j = some v → decSlot w.mo c.σ.mem (w.slot j) = some v`. One equivalence lemma, proved once, replaces reasoning about the `ValRepr` constructors in guards.

- **R1.2 PutGet / GetPut on a 9-byte focus (L-C6′, def part).** Let the store trace `τ` (a list of `(addr, width, bytes)`) be "focused on `F`" if every store lies in `F`, and let `F = ⋃_{d ∈ e.defs} [slot d, slot d + 9) ∪ ownFrame ∪ ghost` (`ghost` is §2's gauge set). Then:

  ```
  lens_close :
    Core p c s w → τ focused on F(e) →
    (∀ d ∈ e.defs, decSlot w.mo (apply τ c.σ.mem) (w.slot d) = some (vals d)) →
    Pins c'.σ w e.tgt → RegsOk c'.σ → output unchanged-or-appended →
    Core p c' (s.apply line e o) w
  ```

  This is ONE theorem. `Core.write`, `Core.jump` and `Core.forloop` become instances with `e.defs = [a]`, `[]` and `[a, a+1, a+3]`.

- **R1.3 PutPut on disjoint foci (why store order does not matter).** The final bytes of a store trace at an address depend only on the *last* store covering it. The lemma `apply_final` says: `(apply τ m)[x]? = last-writer τ x <|> m[x]?`. This one lemma makes tag-first versus payload-first (L-C6′'s "compiler order, not kernel order") irrelevant. The four store shapes stop being four lemmas; they become four *traces*, whose final-byte map is computed by `simp` with `apply_final`.

**What it makes free.**
- All of cluster (c): 28 declarations, 245 lines, plus 9–39 lines per new close shape and 4–10 lines per new store shape.
- The `*_of` transports (`text_of`, `frame_of`, `kptr_of`) become one lemma: "exact outside `F`".
- For the pilot: MUL's payload-first `sd`/`sb`, MOD's `sd`/`sb 3` and ADD's tag-first order all close by one call of `lens_close`, with no new store-shape lemma.

**What it costs.**
- About 60–90 Lean lines: `decSlot`, its equivalence with `ValRepr`, `apply_final`, `lens_close`.
- Re-stating `Core.stack` via `decSlot` touches every existing close call. `lens_close` absorbs them, so this is a deletion, but the 25 proved arms need re-plumbing.
- **Harder:** `decSlot` for strings must read `TStringRepr` through `mo`. Its computability matters only for the L-C4 checker, not for proofs, so declare it noncomputable in proofs if needed.

**Theories.**
- *Known:* bidirectional transformations. Foster, Greenwald, Moore, Pierce and Schmitt, "Combinators for bidirectional tree transformations", POPL 2005 / TOPLAS 2007 (recalled; check). The laws PutGet, GetPut and PutPut are exactly R1.2 and R1.3.
- *Known, distant (databases):* the view-update problem. Bancilhon and Spyratos, "Update semantics of relational views", TODS 1981 (recalled; check). `VmRel` is a view of memory, an arm is a view update, and "constant complement" is literally `Core.frame`'s `w.mo`.
- *Known, distant (algebraic topology):* sheaf gluing. Per-slot sections that agree on overlaps (none here: slots are disjoint) glue into a unique global section. Goguen, "Sheaf semantics for concurrent interacting objects", MSCS 1992 (recalled; check). PutPut on disjoint foci is the gluing axiom.
- *Novel:* using the constant-complement view-update criterion as the machine–VM simulation relation, with the complement pinned existentially (`∃ w`).

**Pilot.**
- **Build first:** `apply_final`, `decSlot`, `lens_close` (about 80 lines). The trace `τ` of an arm is read off the arm's final memory (`SegSt` already yields `c'.σ.mem`) as `writeMap8`/`insert` compositions. No new executor is needed.
- **Refactor `sim_ADD`:** replace its `Core.write`/`slotStore_*` use with `lens_close`. Success means fewer lines than the current ADD close path.
- **MUL:** the same tree as ADD, with `lens_close` for the payload-first order. Only the callee is new (§3).
- **MOD:** the close is identical to MUL's. Its `Protect` stores (`L->top`, `savedpc`) fall in `ghost` (§2).
- **EQ:** there is no def store, so `lens_close` with `defs = []`. Only `ghost` stores appear (Protect, `s5` reload).
- **Measure:** lines in the close parts of the four arms versus the incumbent's close plus store-shape lemmas.

**Seed.**
- `9x` (twice): the 9-byte focus, a payload at +0..7 and a tag at +8.
- `561` (5, 6, then back to 1: not monotone): order-independence (PutPut). Stores arrive in an order that is not the kernel's.

## 2. Gauge quotient: relation invariance under writes to dead-at-head state

**Idea.** Some memory locations the arms write carry no information the VM state depends on:

- `ci->savedpc`;
- `L->top` (after pc 0);
- the callee C frames below `sp`;
- the spills in `luaV_execute`'s own frame;
- for the runtime shape, the allocator and interned-string internals.

Such a location is either:
- (a) always written before it is next read, on every path from any head; or
- (b) read only through an invariant that tolerates any value.

In physics terms, this is *gauge freedom*: the observable (the decoded VM state) is invariant under a group of transformations. So:

- declare the gauge set `Γ(pc)` (phase-dependent: at `pc = 0`, `L->top` is not gauge, because VARARGPREP reads it);
- state every component of `Complement`/`RuntimeMem` as **gauge-invariant**;
- prove it once per component, not once per arm or per resource.

Then the census's (d1) widening stops being "one relation field per resource". A new resource is either inside the gauge (costing nothing per arm) or observable (already in the decoder).

**Core rules.**

- **R2.1 Gauge set.**

  ```
  Gauge p w pc : Nat → Prop :=
    [ci+savedpcOff, +8) ∪ (pc ≠ 0 ? [L+topOff, +8) : ∅) ∪ [stackLo, sp)   -- callee frames
    ∪ spillArea ⊆ ownFrame ∪ RtOwned w                                        -- runtime-owned (below)
  ```

- **R2.2 Gauge invariance (L-C6′ non-def part, one rule).**

  ```
  Complement.regauge :
    Complement p w → (∀ a, ¬ Gauge p w pc a → mo'[a]? = w.mo[a]?) →
    GaugeOk mo' → Complement p { w with mo := mo' }
  ```

  Here `GaugeOk` is the *invariant* part of the gauge (for example "`L->top ≤ stack_last`", "the heap is well-formed"). It is proved once, by one pass over `Complement`'s fields, each of which reads only non-gauge addresses, or reads gauge ones through `GaugeOk`. This forces one edit to `LuaStateAt`: `top` becomes `pc = 0 → L->top = func+16`, plus the gauge invariant `func+16 ≤ L->top ≤ stack_last`. The change is justified by L-C3 counterexample 3: Protect writes `L->top := ci->top` on 230/230 MODK runs.

- **R2.3 Gauge-fixing at use sites (L-C3′ runtime).** A consumer that *does* read a gauge location (VARARGPREP reads `L->top`; `luaD_precall` reads `L->top` after CALL sets it) is exactly a place where the kernel's read ports or a runtime callee's pre-state fix the gauge. The rule `gauge_fix` says: if the arm writes `x ∈ Γ` with a value `f(s)` before calling a runtime callee, the callee's precondition may assume `x = f(s)`. This covers Protect-then-call (MOD's error path, EQ's `luaV_equalobj`, and CALL's `L->top = ra+b`) with one statement.
- **R2.4 Runtime-owned region as an abstract type.** `RtOwned w` is heap blocks owned by the runtime (strings table, CallInfo list, stdio buffers, malloc state, `G` counters such as `GCdebt`/`totalbytes`/`strcache`). The relation says nothing about their contents except `RtInv` (for example `HeapAt`, `StrtAt`). The runtime callee shape is then `RtInv → RtInv' ∧ ports`. The eight `G` and heap fields from counterexample 2 are not eight new relation fields; they are one region under one invariant.

**What it makes free.**
- (d1) relation widening for `savedpc`/`L->top`: this was 100–250 lines per the census and becomes 0 per arm. Around 30 lines go into the one-time `LuaStateAt` edit and `regauge` for `top`.
- For heap/strings/`G` evolving under CALL: the widening becomes a single `RtOwned`/`RtInv` definition, not a field per `G` member.
- The callee's C frame below `sp` for every helper-calling arm.
- In the pilots: MOD's and EQ's two Protect stores, and `luaV_equalobj`'s 48-byte frame.

**What it costs.**
- `regauge`: about 80–150 lines. There is one case per `Complement`/`RuntimeMem`/`LuaStateAt` field, most of them "reads a non-gauge address" by `omega` on offsets.
- The `LuaStateAt.top` edit ripples into `vmRel_entry` (at `pc = 0` the pin still holds, so entry is unchanged) and into VARARGPREP (which must use the pc = 0 clause).
- **Harder:** stating `Gauge` below `sp` requires a lower stack bound (`stackLo`). Choosing `RtOwned` for CALL is real work, but it is work the runtime shape needs anyway.
- **Risk:** a field that looks dead but is read on some path, for example `savedpc` by `luaG_traceexec` when `trap ≠ 0`. Mitigation: `trap = 0` is already a pin, and the trace pass of L-C6′ can check `Γ` as a law (0 reads before a write, per head interval). That is a check, not the abstraction.

**Theories.**
- *Known, distant (physics):* gauge invariance and gauge fixing. Yang and Mills, Phys. Rev. 1954; the Faddeev–Popov gauge-fixing idea (recalled; check). Observables are gauge-invariant functions, and fixing the gauge at the interaction point is R2.3.
- *Known, distant (digital logic synthesis):* don't-care conditions in Boolean minimisation (Karnaugh 1953; Quine–McCluskey). A gauge location is an observability don't-care, and phase-dependence is a sequential don't-care (recalled; check).
- *Known (verification):* `havoc`/`modifies` clauses in Boogie (Leino et al.) and stability under rely conditions in rely–guarantee (Jones 1983) (recalled; check). `regauge` is a stability proof whose rely is "anything in Γ".
- *Novel:* the phase-dependent gauge (`L->top` is observable at pc 0 only), and deriving the relation's complement as the co-gauge rather than as a list of fields.

**Pilot.**
- **Build first:** `Gauge` for `{savedpc, L->top (pc≠0), [stackLo, sp)}` and `regauge` for the current `Complement` (about 120 lines). `RtOwned` waits for CALL.
- **MOD:** Protect's two stores are gauge. The `__moddi3` frame is below `sp`, so gauge. The error exit (`n = 0`) is excluded by `Step` (δ is `none`), so it is not in `sim_MOD`.
- **EQ:** Protect is gauge, and `luaV_equalobj`'s frame is gauge. The `s5` reload of `trap` reads `ci->trap`, a non-gauge `Complement` field (`trap_word`), so it stays `0`.
- **MUL:** only the (empty) `__muldi3` frame, so trivially gauge.
- **Refactor `sim_ADD`:** ADD writes no gauge location on the int path, so there is no line change. It is the control arm.
- **Measure:** lines to handle Protect in MOD and EQ, against the forecast widening of 100–250.

**Seed.**
- `G0` (twice): "gauge 0", a fixed reference gauge, and also "`G` at time 0". The `G` fields drift under CALL, which is why they become owned-and-invariant instead of pinned.
- `fTf`: frame · Transition · frame. Only what the frames bound matters, not what happens inside the transition.

## 3. Content-addressed, δ-indexed callee oracles (call nodes without per-helper contracts)

**Idea.** A helper call from an arm is an *oracle query*. Make `jal` a node in the arm's reasoning whose semantics is one of three shapes (L-C3′), each proved once. The per-helper content of a pure call is not a hand-written contract. It is two table entries:

- **(i)** which δ entry (or δ-adjacent BitVec function) the helper implements, given by `decode ∘ δ`;
- **(ii)** a *code hash* pointing at an existing proof of that fact for the same instruction bytes, possibly at another address.

The key observation is that the repository already has `Muldi3Spec` and `udivdi3_spec` at *WHILE* addresses (census cluster (b)). `__muldi3` is a pc-relative-free leaf of 9 instructions. A **relocation theorem**, proved once, says that code whose bytes are equal and which has no absolute or pc-relative references outside itself has the same behaviour at any base. That turns every existing battery into a contract here for free.

**Core rules.**

- **R3.1 Pure call node (L-C3′ pure).**

  ```
  call_pure :
    CodeAt m a bytes → PureSpec bytes f →              -- f : args → a0, frame-bounded
    regs a0..a7 = args, ra = ret, sp = s →
    ∃ c', StepsN n c c' ∧ c'.pc = ret ∧ a0' = f args ∧
          callee-saved regs, sp, gp preserved ∧ mem =_{≥ s} mem ∧ RegsOk c'
  ```

  `PureSpec` is stated about the *bytes*, not the address.
- **R3.2 Relocation (content addressing).** If `bytes` is closed (no `auipc`, and no `jal` outside `[0, |bytes|)`), then `PureSpec_at a bytes f → PureSpec_at a' bytes f`. It is proved once by a simulation between Sail runs at `a` and `a'` where `pc' = pc − a + a'`. Closedness is decidable by scanning bytes.
- **R3.3 Memory-read pure call (L-C3′ pure, `luaV_equalobj`/`l_strcmp`).** Arguments are pointers to decoded values. `PureSpecDec bytes g` states `a0 = g (decSlot a1, decSlot a2)` (§1's decoder), with memory `≥ sp` unchanged. For EQ, `g := fun x y => δ .eq [x, y] |>.map isTrue`. The table row *is* the δ entry, and the proof obligation is the helper's correctness restricted to `ValRepr`-representable values.
- **R3.4 Noreturn node (L-C3′ noreturn).** `call_noreturn : NoRet bytes → ¬ ∃ n c', StepsN n c c' ∧ AtHead c'`. It belongs to `stuck_sim` only. For MOD, the `n = 0` path reaches `luaG_runerror` and is excluded from `sim_MOD` because `Step` has no successor.

**What it makes free.**
- For cluster (b), the soft-int helpers. `__muldi3` costs 0 new lines of spec, only a relocation check. `__moddi3`/`__divdi3` currently have call sites but no spec; each needs a spec *once*, which relocation then carries everywhere. MUL and MULK, and later MOD, MODK, IDIV and IDIVK, share the pure node.
- The "SymExec has no call nodes" gap (§4 uses this).
- The helper frames (with §2).

**What it costs.**
- R3.2 (relocation): about 150–250 Lean lines. It needs a lemma that Sail `execute` of a decoded instruction is translation-equivariant for non-pc-relative instructions, and `jal`/`branch` offsets are relative, so they are equivariant too. `auipc` is the only non-equivariant RV64I instruction; `ret`/`jalr` are equivariant because they go through `ra`.
- R3.1: about 60 lines.
- **Harder:**
  - `__moddi3` has no spec; it is a long-division loop. Its spec is the one genuinely new functional proof (probably 100+ lines). It is not per-arm, but it is per-helper.
  - `luaV_equalobj` for F1 values: it has short-string pointer equality (interning) and `luaS_eqlngstr` for long strings. The F1-restricted spec needs the interning invariant (`StrtAt`) to justify pointer equality. This is real.
- **Honest limit:** a functional fact per *distinct pure helper* remains. There are 10 such helpers, not 131. The rule structure is shape-level, and the fact is a table row plus a proof reused by content hash.

**Theories.**
- *Known, distant (molecular biology):* annotation transfer by sequence homology. Identical sequence implies identical function, wherever it sits in the genome (BLAST, Altschul et al., JMB 1990; recalled, check). R3.2 is annotation transfer with the identity threshold at 100%.
- *Known, distant (software distribution):* content-addressed stores. Dolstra's Nix thesis (2006) and Git's object model (recalled; check). A proof is keyed by the hash of what it is about, not by where it lives.
- *Known (computability):* oracle machines, relative computability (Turing 1939). A call node is an oracle query whose answer is a function of the query.
- *Known (compilers):* CompCert's external-call axioms (Leroy). Here they are *proved* and keyed by bytes, not assumed (recalled; check).
- *Novel:* using δ entries themselves as the table rows of callee contracts, so the helper's spec and the kernel share a term, and the arm proof needs no value lemma (a6) at all.

**Pilot.**
- **Build first:**
  - R3.1;
  - R3.2 for the RV64I subset that `__muldi3` uses (`mv/li/andi/beqz/add/srli/slli/bnez/ret`);
  - a port of `Muldi3Spec` via R3.2.
- **MUL:** ADD's tree, with the `add` leaf replaced by a pure call node with `f = (· * ·)`. That matches δ's `.arith .mul` by `rfl`.
- **MOD:** a new tree:
  - the `n+1 ≤u 1` branch splits into `n = −1`, which is the inline `0` path, and `n = 0`, which is noreturn;
  - `__moddi3` is a pure node (spec needed: truncating remainder);
  - the fix-up branch is followed by a lemma, `imod_fixup : Int.fmod = (tmod fixed by sign)`, which is BitVec arithmetic proved once.
- **EQ:** a memory-read pure node with `g = δ .eq`. Needs `luaV_equalobj`'s F1 spec (budget separately).
- **Refactor `sim_ADD`:** its value leaf becomes the degenerate call node `f = (· + ·)` (no call). This shows the node form costs nothing inline.
- **Measure:** hand lines per arm excluding helper specs, and helper-spec lines separately. Success means MUL is under 15 lines above its table row.

**Seed.**
- `cau` at 178 and `Cau` at 243: the same content at two positions, differing only in surface case. This drove relocation (same bytes, different address, same meaning) and the "no exact repeats, only normalised ones" reading.
- `Cau` followed by `TM` (tag method: the metamethod and error paths that never return to the head) drove R3.4.

## 4. SymExec v2: α-guards, δ-leaves, call nodes, stated on the exact theorem

**Idea.** Keep the verified symbolic executor's strength: zero generated volume, and the best refactor (59 against 107). Fix its three losses by changing *what the executor computes*. Its leaves should not be raw machine terms that a human then matches against the kernel. They should be **kernel outcomes**:
- tag tests become a single abstraction `α : Value → Tag`;
- δ is applied symbolically at leaves;
- `jal` becomes a call node (§3).

The per-arm proof becomes "the executor's tree, abstracted by α, refines the kernel's decision". It is checked by a proved-sound *reflective* comparison of two finite trees, not searched for.

**Core rules.**

- **R4.1 α-guard (a4 as one rule, L-C4's per-branch guard).** For any `K : BitVec 8`:

  ```
  guard_tag : ValRepr mo t x v → (t = K ↔ tagClass v = classOf K)
  ```

  This is one lemma over all tags, stated with `classOf : BitVec 8 → TagClass`, a finite table (3 ↦ int, 19 ↦ float (unreachable under F1), 1/17 ↦ false/true, and so on). The executor's branch on `beq t, s2` or `beq t, 19` produces the α-predicate automatically. The census's 40 guard declarations (191 lines) collapse into this lemma plus `classOf`. The `slt`/constant guards (cmpI, `n+1 ≤u 1`) get `guard_cmp`, one lemma over `BitVec.slt/ult` with δ's `toInt` comparisons.
- **R4.2 Kernel normal form (a5 as one rule).** A total function `knf : Kernel Value → DTree (α-predicates on read ports) (edge × δ-term)` is defined by structural recursion over the combinators (`opArith`, `docondjump`, `setR`, `forloopK`, …). One theorem, `knf_sound : KStep s s' ↔ path of knf K selected by α(reads s) yields s'`, replaces the 19 kernel inversions (209 lines, rising). For MOD, `knf (opArith .mod)` yields:
  - `int,int ∧ y≠0 → edge0, imod x y`;
  - `int,int ∧ y=0 → stuck`;
  - `else → edge1`.
- **R4.3 Tree refinement (L-C4 at arm level, the one per-arm check).** `refines (exec arm) (knf K)`, where `exec` is the SymExec v2 output tree, *pruned* by the F1 `Supported`/α-facts (the float paths die because `classOf 19 = float` is not in F1's reachable tags). It is decided by a small reflective checker on finite trees, and `refines_sound` is proved once. This is a verified decision on data the executor produced, not proof search. The per-arm hand content is at most the table row (ALU op, helper, layout) plus any leaf arithmetic lemma (for MOD, `imod_fixup`).

**How it fixes the three losses.**
1. **Costs 2–4× more hand lines per arm.** The hand lines went into matching path conditions to kernel cases, which is R4.1 and R4.2 done by hand per path. With α-guards and `knf`, the per-path matching is `refines` by evaluation. The expected hand content per arm is the table row, plus a leaf lemma only when the machine computes δ by a different algorithm (MOD's sign fix-up, MUL's call).
2. **No call nodes.** Add a node `Call (target) (shape)` whose semantics is §3's R3.1/R3.3/R3.4. The executor stops at `jal` into a known helper, emits the node, and continues at `ra` with the shape's post-state: `a0` is a fresh symbol constrained by `f args`, memory `≥ sp` is unchanged, and memory below `sp` is havocked (§2's gauge).
3. **Proves a weaker theorem.** `VmRelZ`/`SymOk` were the gap. Since `2332c06`, `Core.frame` uses total reads and `Core.ok` carries `RegsOk`, so `VmRelZ = VmRel` and `SymOk` is a projection of `Core`. The v2 top theorem is stated directly as `sim_X`'s signature. Confirm this at the pilot's first build (it is claimed from the commit log, not from reading proofs).

**What it makes free.**
- (a4) guards and (a5) inversions.
- Most of (a1): a new tree costs a row, not 30–273 lines.
- (d4) generated volume goes to 0.
- (d3) segment-interface extensions go away (there are no segments).
- With §1, (c) as well.

**What it costs.**
- `knf` and `knf_sound`: about 150 lines. `guard_tag`/`guard_cmp` with `classOf`: about 50. `refines` and `refines_sound`: about 120. The call node in the executor: about 100, plus §3.
- **Harder:** SymExec's CPU and memory (2.96 GB peak) may rise with call nodes. Executor terms must stay small enough for `refines` to evaluate by `decide` (the kernel may choke; do not use `native_decide` if the project forbids it; check CLAUDE.md).
- **Risk:** the executor's term language may not expose δ-shaped leaves. `__muldi3`'s `a0` is fine; MOD's `r+n` fix-up needs `imod_fixup` as a rewrite.

**Theories.**
- *Known:* abstract interpretation with Galois connections (Cousot and Cousot, POPL 1977). α is the tag abstraction, and `guard_tag` is its best-transformer property on `beq` (recalled; check).
- *Known:* proof by reflection (Boutin, TACS 1997; the `ring` tactic lineage) (recalled; check).
- *Known, distant (clinical medicine):* differential diagnosis by decision trees. The kernel's `knf` is the diagnosis table, the machine's branches are tests, and `refines` requires each test to be perfectly sensitive and specific for the diagnosis it separates (sensitivity/specificity 1). The float paths are "ruled-out diagnoses" (pruned by prior F1 facts, Bayesian zero prior).
- *Novel:* comparing a machine-derived tree against a *kernel-derived* normal form, rather than against hand-written path specifications.

**Pilot.**

- **Refactor `sim_ADD`:** the table row `(opArith, .add, rr)`, plus `refines` by evaluation. Target: under 20 lines, against 61 as a template.

## 5. Canonical arm DAGs: prove on the normal form, transport by a verified normaliser

**Idea.** Round 1's `canon.py` found that arms collapse to 46 classes modulo ALU op, and to 37 at P3p. Its self-test showed invariance under 376 branch flips, 3,000 adjacent swaps and register renamings. That canonicaliser is currently only a *measurement*. Promote it to a **verified normaliser in Lean**:

```
canon : Code → DAG
canon_sound : ⟦code⟧ ⊑ ⟦canon code⟧
```

Here ⟦DAG⟧ is a tiny *denotational* semantics:
- pure operation nodes;
- memory epochs with loads and stores;
- branches normalised to EQ/LT/LTU;
- call nodes as barriers (§3's shapes);
- head exits.

The per-tree proof is then done **once on the DAG**, which is small, pure and layout-free, against `knf` (§4). Every arm whose `canon` equals that DAG modulo leaf parameters inherits it. Layout (2%) and scheduling vanish by construction. MUL ≡ ADD modulo the leaf "add" ↦ "call `__muldi3`".

**Core rules.**
- **R5.1 `canon_sound` (L-C2′ as one theorem).** For any closed arm fragment (head to head), the Sail run refines the DAG's denotation. It is proved once, by induction over the instruction sequence, with three commuting-square lemmas: renaming, adjacent independent swap, and branch polarity.
- **R5.2 DAG-level simulation (L-C4 at arm level).** `dag_sim : ⟦D⟧ refines knf K under ValRepr` is proved per *DAG class*, not per arm. The DAG proof uses §4's α-guard and §1's lens close in the DAG's own vocabulary. There are no machine registers there, so the proofs are shorter.
- **R5.3 Parametric leaves.** A DAG class is a DAG with holes for (ALU op | pure call | constant). `dag_sim` is stated for all hole fillers that satisfy "the leaf computes `δ o`". This is L-C2′'s "one proof plus a table row", but keyed by *canonical structure* rather than by `opKernel` combinator, which L-C2 found to be the wrong key.

**What it makes free.**
- (a2) layouts and (a3) rows.
- Per-arm (d5) failed builds from layout-specific templates.
- The (a1) cost of *new layouts of old trees*.
- It does not by itself make new *trees* cheap. §4 does that, so §5 composes with §4.

**What it costs.**
- `canon` and `canon_sound`: the biggest setup here, likely 400–700 Lean lines. The DAG semantics with memory epochs and an alias discipline (same base, same width, as in `canon.py`) must be *proved*, where `canon.py`'s alias model is heuristic (REPORT caveat). The alias proof needs the `Win`/`Ranges` separation facts.
- **Harder:** anything the Python canonicaliser treated heuristically. That includes call arities, which come from prototypes; the Lean side takes them from §3's shapes instead.
- **Risk:** the saving tops out at L-C2′'s 7% if trees dominate. So §5 is only worth building together with §4, as the layer that makes §4's per-tree result apply across arms without re-executing.

**Theories.**
- *Known:* translation validation. Pnueli, Siegel and Singerman, TACAS 1998; Necula, PLDI 2000 (recalled; check). Here the "compiler" is the canonicaliser and it is verified once.
- *Known, distant (chemistry):* canonical SMILES and InChI. Weininger, JCICS 1988/1989 (recalled; check). Molecules drawn differently get one canonical string, and properties are indexed by it. The arm's register allocation and scheduling are its "drawing".
- *Known, distant (graph theory):* canonical labelling. McKay's nauty (1981) (recalled; check).
- *Novel:* a *proved* canonical form used as the index for simulation proofs, so that identity of proofs follows from equality of normal forms.

**Pilot.**
- **Build first:** `canon` restricted to straight-line code plus EQ/LT/LTU branches plus pure call barriers, with no memory-epoch reordering: the arms here schedule loads before stores anyway. That is the smallest proved slice (about 250 lines). Then the ADD DAG class with an `op` hole.
- **Refactor `sim_ADD`:** `canon ADD = D_arith[add]`, with `dag_sim D_arith` proved once.
- **MUL:** `canon MUL = D_arith[call __muldi3]` is a table row. MUL has a different tag-test order and register choice than ADD (`beq a2,s2` then `li 19`; `s6`/`s10`), and `canon` must erase that.
- **MOD:** a new class `D_mod` with the special-case branch, a call and a fix-up. It is proved once, and MODK, IDIV and IDIVK are expected to be rows of it (L-C2′ predicts `{MOD, IDIV}` share a P3p tree modulo helper; verify).
- **EQ:** a new class `D_eqcall` (Protect, then call, then k-compare, then jump); EQK should be its row.
- **Measure:** hand lines for the two new classes against 4 arms' worth of templates, and whether `canon` erases MUL's layout differences from ADD without hand help.

**Seed.**
- The mining result itself: **zero exact repeated trigrams, two repeats after case-folding**. Structure that appears only modulo a normalisation is the whole thesis of §5.
- `pp` (the one doubled letter): the pair of equal-up-to-renaming programs whose proofs should be one.
