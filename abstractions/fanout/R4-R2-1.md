## 1. Discriminated footprints: a representation is a list of reads, and its footprint is computed from it

**Acts on:**
- **(c)** R4-R1-4 #1 (`Sealed`/`tsFoot`), R4-R1-5 #2 (bastion `fp`), R4-R1-1 #5 (`Core.owned`/`fp`) and R4-R1-3 #5 (holed complement);
- **(a)** R4-R1-4 #1's `Sealed`, generalised.

### The objection: no M-str variant can discharge LT on a long string as stated

All five M-str proposals transfer `TStringRepr` from `w.mo` to the machine memory. A transfer only carries facts that the representation already states. `TStringRepr.long` (`Lua/Vm/Repr.lean`) states `tt` at +8, `lnglen` at +16, the contents and the terminator. It says nothing about `shrlen` at +11.

`l_strcmp` branches on exactly that byte, for every operand:

```
8001a720: lbu  s2,11(a0)     ; shrlen
8001a724: li   a5,255
8001a72c: bne  s2,a5,…       ; short: length = shrlen
8001a730: ld   s2,16(a0)     ; long (shrlen = 0xFF): length = lnglen
```

The same test runs for the second operand at `0x8001a734..0x8001a744`. This is `tsslen` in Lua 5.4.7 (`lobject.h:410`: `shrlen != 0xFF ? shrlen : u.lnglen`).

So **LT/LE on any long operand cannot be proved premise-free** by any transfer of today's `TStringRepr`: the path through `0x8001a730` needs `rd8 (ts+11) = 0xFF`, and no relation fact supplies it. EQ on long strings is not affected, because `luaS_eqlngstr` reads `lnglen` at +16 directly (`0x80017188`).

The census's own L4-str′ footprint, "`shrlen` at +11 *or* `lnglen` at +16..23", is wrong in the same way. A long string's footprint is +11 *and* +16..23.

### Second objection: each fixed footprint is falsified by a measured store

- **R4-R1-5 #2** takes `fp (.str s) = [x, x+24+len]`, which includes `next` (+0) and `marked` (+9). `bastion_run` then needs runs that do not write into the bastion. CALL's GC writes there 41 times in `l4str_fullgc` (§2b).
- **R4-R1-4 #1** takes `tsFoot` = +8, +11, +16..23 for every string. For a *short* string, +16 is `u.hnext`. CONCAT's `tablerehash` writes it 35 times in `l4str_gc` (§2b), so `Sealed.along` fails at CONCAT.

The footprint depends on a byte inside the footprint: +11 decides whether +16..23 belongs to it. The seed's `UuU` is exactly this: one object in two variants, with a discriminator in the middle.

### The idea

Stop writing `Repr` predicates as inductives over `Option` reads with hand-chosen footprints. Write each variant as a **read list**:

`rs : List (off × width × val)`, generated from `Layout.lean` (the offsets) together with the variant's values.

One predicate and one theorem cover every read list:

```lean
def ReadsHold (m : Mem) (base : Nat) (rs : List Read) : Prop :=
  ∀ r ∈ rs, bytesT r.width m (base + r.off) = r.val          -- total reads

def fpOf (base : Nat) (rs : List Read) : Nat → Prop :=
  fun a => ∃ r ∈ rs, base + r.off ≤ a ∧ a < base + r.off + r.width

theorem readsHold_sealed : Sealed (ReadsHold · base rs) (fpOf base rs)   -- once, for every rs
```

`TStringRepr` becomes a disjunction of two *generated* read lists, `shortReads s` and `longReads s`. The long list includes `(11, 1, 0xFF)`. A string's footprint is `fpOf ts (variantReads s)`. The variant is a function of `s.length` (`strTag`), so the footprint is a function of the value: a dependent footprint with no case split at use sites.

### Core rules

| law | rule (proved once) |
|---|---|
| L4-str′ (with the corrected footprint) | `readsHold_sealed` together with R4-R1-4 #1's `Core.unseal`/`Sealed.along`. The footprint is never written by hand, so the +11/+16 slip cannot recur. |
| L4-str′ at CALL/CONCAT | `fpOf_avoids`: the GC header writes (+0, +9) and `hnext` (+16, short strings only) are outside `fpOf ts (variantReads s)`. One `decide` per variant on literal offsets. |
| later heap objects | `Table`, `LClosure` and `Udata` reprs are read lists too. Each gets `Sealed` from the same theorem, with no new instance. |

### What it makes free

- **LT/LE on long strings.** `l_strcmp`'s `bne` at `0x8001a72c` resolves by `ReadsHold`. Without this, LT stays premised even after M-str and M-scan land.
- **The footprint bookkeeping that R4-R1-4 #1 asked for by hand** (`TStringReprT`, its `Sealed` instance, `tsFoot`). It is now one generic instance.
- **The relation's string facts stated with total reads.** CLAUDE.md asks for total reads (`RamRead*`: "never demand presence"). `BytesAt`'s `m[a]? = some` presence becomes `bytesT`, so the `Sealed` congruence holds by `rfl` on `bytesT1`.

### What it costs

- **A relation edit.** `TStringRepr.long` gains `(11, 1, 0xFF)`. That is a boot-witness check (`check_tstring` reads the object already) and a `luaS_createlngstrobj` fact for CONCAT later. Rewriting `TStringRepr` as read lists touches every `TStringRepr.inj` use. About 80 lines (est.).
- **What gets harder.** Read lists are flat. A repr that follows a pointer (a table's `array` → its elements) is a read list *per object* plus a link. `ReadsHold` composes by conjunction over objects, but the footprint of a linked structure is then a union over the link. Strings do not need this; F2 tables do.

### Theories

- **Tag-length-value encodings** (ITU-T X.690, BER) **(recalled; check)**. Known, from networking. A field's presence and extent are decided by an earlier field of the same record. `shrlen = 0xFF` is a tag that selects the length field.
- **Implicit dynamic frames and self-framing assertions.** Smans, Jacobs and Piessens, TOPLAS 2012 **(recalled; check)**. Known. An assertion frames its own footprint. Here the footprint is computed from the assertion's *syntax*, a read list.
- **Sufficient statistics** (Fisher; the Fisher–Neyman factorisation) **(recalled; check)**. Known, from statistics. `fpOf rs` is the statistic of the memory that the predicate depends on. Computing it from the predicate's form, rather than declaring it, is the factorisation theorem's direction.
- **Novel here:** footprints derived from a generated read list, with one `Sealed` theorem for every repr.

### Pilot

- **The smallest build:**
  - `Read`, `ReadsHold`, `fpOf`, `readsHold_sealed`;
  - `longReads` with `(11,1,0xFF)`, and the boot-witness check;
  - `Core.str_bytes` as R4-R1-4 #1 states it, now generic.
- **The falsifier.** Run `lstr_trace.py`'s heads with one extra column, "+11 of each long string". If any long string has `shrlen ≠ 0xFF`, the variant model is wrong. If all do, LT on a long string has exactly one missing fact, and this is it.
- **LT on two strings** then needs only M-scan (idea 5 of this file does not; R4-R1-4 #2 does).
- **No effect** on FORPREP, IDIV, LOADNIL or MODK.

### Seed

The case pairs `Uu`, `gG`, `Xx`, and above all `UuU`: one letter in two variants, with the variant decided in the middle. That is a `TString`, short or long, with the choice made by the byte at +11.

## 2. Chunk-sourced regions: the allocator's chunk list is the region table

**Acts on:**
- **(b)** R4-R1-1 #3 (`Rgn`/`sep_sound` from `Ranges`) with R4-R1-5 #2 (`cellOf`/bastion) and R4-R1-3 #5 (holed complement);
- **(c)** all M-log variants' source of soundness, on VARARGPREP's relocation and on CONCAT creating strings.

### The objection

Every M-log variant (R4-R1-1 #3, R4-R1-2 #2, R4-R1-3 #3, R4-R1-4 #4, R4-R1-5 #4) proves its label table sound **from `Ranges`**. That gives a closed table: R4-R1-1 #3 itself says "a new object kind is a new constructor, so `sep_sound` grows by a row". Every M-str variant then adds a *second* disjointness source, "string footprint ∉ `Win`", which must be:
- checked at boot;
- re-proved at CONCAT, where new strings appear;
- re-proved at VARARGPREP and CALL, where `Win` moves.

R4-R1-1 #5 and R4-R1-5 #2 list these re-proofs as costs.

VARARGPREP is worse than "`Win` moves":
- `luaT_adjustvarargs` (`ltm.c`) calls `luaD_checkstack(L, p->maxstacksize + 1)` *before* the copy loop at `0x80019874`.
- That can `luaD_reallocstack`: a `realloc` of the whole Lua stack into a fresh chunk.
- Every `slot j` label is relative to `w.base`, and after the realloc it denotes a different block.
- A table proved from one `Ranges` snapshot does not survive this.

### The idea

The relation already holds the heap. `Complement.runtime` gives `RuntimeMem w.mo …`, whose `heap : DlHeap.HeapAt m top brkv chunks bins` walks every chunk in order (`Lua/Vm/DlHeap.lean`'s `ChunkWalk`). Each object `Ranges` separates is in its own in-use chunk:
- the Lua stack;
- the Lua function's `CallInfo` (`luaE_extendCI`);
- the `LG` block holding `L`;
- the Proto's `k` array.

Every `TString` is too: `luaC_newobj` calls `luaM_malloc`.

So **a region is a chunk index**, and an address is CompCert's (block, offset). The ghost `RelPtrs` gains a `Nodup` list of the chunk indices of `base`, `ci`, `L` and `k`. Each value's repr carries its chunk index (`ValRepr.str` with `ts ∈ chunk i`).

One theorem, proved once from `ChunkWalk`, replaces the four disjunctions:

```lean
theorem ChunkWalk.disjoint (hw : ChunkWalk m a b cs) (hi : i < cs.length) (hj : j < cs.length)
    (hne : i ≠ j) : Disjoint (cs[i].span) (cs[j].span)     -- the only place `i < j ∨ j < i` is split
```

- `k_sep`, `ci_sep`, `L_sep` and `L_sep_ci` become theorems: `Nodup [iBase, iCi, iL, iK]` together with `ChunkWalk.disjoint`.
- "A string is outside `Win`" becomes `iTs ∉ [iBase, iCi, iL]` together with "Scratch ⊆ C stack ∪ ci ∪ L". It is no longer a boot fact per string.

### Core rules

| law | rule |
|---|---|
| L4-split′ (the cost part: separation without disjunctions) | `ChunkWalk.disjoint` once. An arm's separation goal is `iX ≠ iY` from a `Nodup` hypothesis (`simp` on a 4-element list), or a literal offset comparison inside one chunk. |
| L4-str′ (preservation) | `fresh_chunk`: the allocator's step-table summary (`SWP` over `VsaIris.Vsa.AllocSteps`, CLAUDE.md) returns a chunk index absent from the old in-use list. So CONCAT's new string is outside `Win` by `Nodup`, and VARARGPREP's realloc'd stack is a new index that no live string can share. |
| L4-str′ at VARARGPREP | `realloc_preserves_others`: in-use chunks other than the realloc'd one keep their spans and bytes. Every string's `ReadsHold` (idea 1) survives the relocation unchanged. |

### What it makes free

- **The ×4 disjunction penalty, at its source.** The disjunctions do not just move into a library table (R4-R1-1 #3, R4-R1-2 #2): they stop being relation fields at all.
- **Every M-str preservation obligation at CONCAT, CALL and VARARGPREP.** They follow from the allocator summary that CALL print and CONCAT need anyway.
- **The boot witness's per-string footprint check** (R4-R1-1 #5, R4-R1-3 #5, R4-R1-4 #1). `HeapAt` at boot already places every string in a chunk.
- **F2's tables.** Every `Table` is a chunk, so `Table` versus slot separation is the same `Nodup`.

### What it costs

- **Ghost indices.** `RelPtrs` gains chunk indices, and every value repr gains one. `vmRel_entry` must find them from the boot heap walk, which `Boot/Heap.lean` already performs.
- **Not everything is a chunk.** The C stack, `.rodata` and `tohost` are static regions. The region type is `chunk i | cstack | rodata | io`: a 4-row static table plus `ChunkWalk.disjoint`.
- **Inside one chunk, offsets still need comparing.** `ci->savedpc` against the other `ci` fields, `L->top` against the rest of `L`. These are literal offsets, so `decide`.
- **Risk.** Is the main function's `CallInfo` a separate chunk, or `L->base_ci` inside `LG`? `L_sep_ci`'s existence suggests the relation already allows either. **(check in `Boot/Heap.lean`)** If it is `base_ci`, then `ci` and `L` share a chunk, and their separation is an offset comparison inside it, which is still `decide`.

### Theories

- **CompCert's block/offset memory.** Leroy and Blazy, JAR 2008 **(recalled; check)**. Known; R4-R1-2 #2 cites it. What is new here is the *source*: blocks are the allocator's chunks, read off a verified heap walk, not posited.
- **Separation logic's `malloc` axiom.** `malloc` returns a fresh block `∗` the old heap. Reynolds, LICS 2002 **(recalled; check)**. Known. `fresh_chunk` is that axiom, discharged by the allocator's step tables.
- **Cadastral registries** (land surveying). Known practice; the analogy is novel. Parcels are surveyed once at registration, and a boundary dispute is settled by the parcel ID, never by re-measuring. A new parcel never overlaps a registered one.
- **Heap parsability in garbage collectors.** A linear walk over object headers recovers every object's extent. Jones, Hosking and Moss, *The Garbage Collection Handbook*, 2011 **(recalled; check)**. Known, from GC. `ChunkWalk` is exactly a parsable heap.

### Pilot

- **The smallest build.** `ChunkWalk.disjoint`, then derive `k_sep` and `ci_sep` as theorems from a `Nodup` of chunk indices at boot. Measure MODK's seg2 (the `K[C]` tag through `savestate`) with the disjunction hypotheses *removed from context* and replaced by `Nodup`.
  - This is the cheapest test of the "×4" claim alone, independent of any log.
- **EQ/LT on strings.** `iTs ∉ window chunks` instead of a boot check per string.
- **The held-out stress for later:** VARARGPREP with a forced `luaD_reallocstack` (`progs` with `maxstacksize` near the stack size).

### Seed

The three zeros `lc0y`, `XS0u`, `wR0m` as fences between blocks (chunk headers). `AX` recurring in two distant places (`AXS0`, `KAXrT`): the same kind of object in two blocks, so identity comes from the block.

## 3. Spill-and-read-through call frames: the frame includes the caller's stack cells, and the callee reads through the caller's log

**Acts on:**
- **(c)** R4-R1-5 #1 (location lists `loc : Reg → Loc`) and R4-R1-1 #2 (∀ρ over callee-saved registers), each with a counterexample;
- **(b)** R4-R1-5 #5 (`Rd f`, the read set) with R4-R1-2 #5 (ledger, "calling is ledger concatenation").

### The objection, from FORPREP's machine code

FORPREP carries a live pointer across *both* of its calls **in memory, not in a register**:

```
8001e1e0: sd   a5,16(sp)        ; spill a5 = &R[A]
8001e1fc: jal  luaV_tointeger   ; writes 40(sp) through a1
8001e200: ld   a5,16(sp)        ; reload
8001e20c: ld   a0,40(sp)        ; the out-parameter
  …
8001f868: sd   a5,16(sp)        ; spill again
8001f86c: jal  __udivdi3
8001f870: ld   a5,16(sp)        ; reload
8001f878: sd   a4,16(a5)        ; R[A+1] := count, through the reloaded pointer
```

The descending path repeats this at `0x8001fa88..0x8001fa90`.

- **R4-R1-5 #1's `At`** names registers only (`loc : Reg → Loc`). Its `MemAt` is "exact outside `Slots ∪ Scratch ∪ wr`", and `16(sp)` is in `Scratch` (the C frame). So after the call, `a5`'s reloaded value is unconstrained, and the store at `0x8001f878` goes to an unknown address. The arm cannot be closed.
- **R4-R1-1 #2's ∀ρ** covers `s0..s11`. `a5` is caller-saved, so it lives on only through `16(sp)`, a memory cell. The memory half of ∀ρ, "∀ M outside the callee's footprint", is the right shape. But then the frame is not "never written": the spill cell's *value* must be named at the boundary.

A second gap concerns **reads**, which none of round 1 addressed. `luaV_tointeger` reads `R[A+1]` through `a0 = s11` *after* the arm has already written:
- `R[A+3]`'s tag (`sb s2,56(a5)` at `0x8001e1dc`) and payload (`sd s10,48(a5)` at `0x8001e1e4`);
- the spill;
- `savestate`'s two words (`0x8001c104`, `0x8001c110`).

So `toint_sum`'s precondition, `TValueRepr m (a0) v`, must hold of a memory that is `w.mo` *plus a 5-entry log*. R4-R1-2 #5's "calling is ledger concatenation" composes the callee's *writes*. It says nothing about the callee's *reads* through the caller's ledger.

### The idea

A call frame is a pair:
- the live registers (the generator's liveness set, R4-R1-1 #2 / R4-R1-4 #5);
- **the live caller-frame cells**: the `sp`-relative cells that are stored before the `jal` and loaded after it. The generator finds them the same way, as a store/load pair across the call node.

A summary is stated **read-set-polymorphically**: `∀ Δ, Δ.addrs ∩ Rd f = ∅ → Pre (applyLog Δ m) ↔ Pre m`. Its read set `Rd f` comes from R4-R1-5 #5, as region tags.

At a call site:
1. The caller's log `Δ` is checked disjoint from `Rd f` by one `decide` on regions (idea 2's chunks, or any M-log variant).
2. The callee's precondition is discharged on the *entry* memory, where `Complement`/`Core` already state it.
3. The callee's write effect is appended.
4. Spilled cells come back by the log's read-over-write hit: `rd (applyLog (Δ ++ Δ_f) m) (sp+16) = a5` because `sp+16 ∉ Wr f` (the ABI: the callee writes below its entry `sp` and through its out-parameters).

### Core rules

| law | rule (proved once) |
|---|---|
| L4-call′ (registers and spills) | `call_frame : SegSt jal (args ++ F) (applyLog Δ m) → Disj F.regs clob → Disj Δ.addrs (Rd f) → Disj (spills Δ) (Wr f) → SegSt ret (res ++ F) (applyLog (Δ ++ Δ_f) m)`. Here `spills Δ` is the sub-log at `sp`-relative cells. |
| L4-call (preconditions) | `pre_through_log : Disj Δ.addrs (Rd f) → (Pre f m ↔ Pre f (applyLog Δ m))`. This holds for any `Pre` that is `Sealed` on `Rd f` (idea 1's `readsHold_sealed`). |
| out-parameters | `Wr f` is parametric in argument regions: `Wr luaV_tointeger (a1 ↦ cframe 40) = {cframe 40..47} ∪ cstack`. This is R4-R1-5 #5's `Fp f (cellsOf args)`. |

### What it makes free

- **FORPREP's 4 call sites** (§1b.4: `FORPREP ×4`). There is no `fpFrame` and no `FpMem`, and the spill pointer survives by `hit`.
- **`EqCtx`'s 9 address facts** (EQK). They are a `Pre` on `luaV_equalobj`'s read set, so `pre_through_log` together with a region `decide` replaces them. This is where R4-R1-5 #5 meets the ledger.
- **IDIV's two calls in sequence** (`__divdi3` at `0x8001f73c`, then `__moddi3` at `0x8001f964` on the sign-mismatch path). Both read only registers (`Rd = ∅`), so `pre_through_log` is trivial. `s3`/`s4` ride in `F`.
- **Future:** CALL print's `luaD_precall` reads the stack through the arm's log, and the same rule covers it.

### What it costs

- **A generator analysis:** store/load pairs at `sp`-relative offsets across call nodes. This is data, about 30 lines of Python (est.).
- **Each summary's read set.** `Rd f` is derived (R4-R1-5 #5's dynasty) for `luaV_tointeger`, `luaV_equalobj`, `luaS_eqlngstr`, `memcmp`, `l_strcmp`, `strcmp` and `strlen`. For the soft-int helpers it is empty.
- **What gets harder.** A callee that reads through a pointer argument whose region is not syntactic (`luaV_tointeger`'s `a0 = &R[A+1]` is; a table walk's node is not) needs the argument's region from the caller's value repr. Idea 2 gives it a chunk index.

### Theories

- **CompCert's Stacking pass.** Spill slots are part of the frame, and the proof of Linear→Mach shows they are preserved across calls by the callee's frame discipline. Leroy, "A formally verified compiler back-end", JAR 2009 **(recalled; check)**. Known.
- **GC stack maps.** At each call safepoint, the compiler records which stack slots hold live roots. Diwan, Moss and Hudson, PLDI 1992 **(recalled; check)**. Known, from garbage collection. The live caller-frame cells are a stack map, emitted the same way.
- **Read/write-set validation in optimistic concurrency.** Kung and Robinson, TODS 1981 **(recalled; check)**. Known; R4-R1-4 #1 cites it for strings. Here it is applied to a *callee's read set* against the *caller's uncommitted writes*: the callee commits iff `Rd f ∩ Δ = ∅`.
- **Novel here:** stating helper summaries read-set-polymorphically over the caller's log, so a callee precondition is never re-proved on the logged memory.

### Pilot

- **FORPREP.** This is the decisive case: two calls, a memory-carried pointer and an out-parameter. The smallest build:
  - `call_frame` and `pre_through_log` over any `applyLog`;
  - `toint_sum` restated with `Rd = {slot (A+1)}` and `Wr = {cframe 40, cstack}`;
  - `udivdi3_sum` with `Rd = ∅` and `Wr = {cstack}`.
- **MODK refactor.** `modk_call`'s 4 frame lines go. `Rd __moddi3 = ∅`, and the frame is the liveness set.
- **The falsifier.** If `toint_sum`'s precondition cannot be stated `Sealed` on `Rd` (because `luaV_tointeger` reads something outside `R[A+1]`, such as a string's bytes through `l_strton` on a string limit), then FORPREP's string-limit path needs idea 1's footprints in `Rd`. On F1's integer limits it should not.

### Seed

The mirrored digit pair `39`…`93`: a value written before a call and read back, mirror-imaged, after it. The repeated `9K` (`f9Kh`, `X9KX`): the same cell on both sides of something.

## 4. Cuts carried by the log: M-cut's boundary is (pc, live registers, log), and M-log's *representation* is mandatory even if its *speed* claim fails

**Acts on:**
- **(b)** R4-R1-3 #4 (retimed cuts, `CutSt`) with R4-R1-2 #5 (ledger) and R4-R1-4 #5 (`Ckpt`, `@[irreducible]`);
- **(c)** R4-R1-2 #3 and R4-R1-4 #5's raw composed terms;
- an answer to "if M-log's heartbeat claim is false, what carries the budget?"

### The argument

**What carries the budget if M-log's speed claim is false.** The declaration count does. §1b.3 measured cost as additive per segment, with about 5k per extra cut. My estimate of FORPREP's integer path (ascending, `step ≠ 0`) from that table:

| piece | contents | k heartbeats (est.) |
|---|---|---|
| setup | | 5 |
| `0x8001c0f8..0x8001c120` | `savestate`'s 2 `sd`, `R[A]` tag `lbu` + `bne` through them | ~32 |
| `0x8001e1c0..0x8001e1d0` | `R[A+2]` tag + `beq`; step payload + `bnez` | ~38 + ~20 |
| `0x8001e1d8..0x8001e1fc` | init payload, 3 stores, `jal luaV_tointeger` | ~20 + call 18 |
| **cut here** | | |
| `0x8001e200..0x8001e214` | 2 reloads (`16(sp)`, `40(sp)`) + `blt` | ~20 + ~18 |

So FORPREP needs **one** cut, and IDIV's sign-mismatch path (two calls) needs one too, *without* M-log's speed-up. M-cut carries the budget. The cut is safe at any index (R4-R1-3 #4's `cut_compose`), so a generator's greedy placement is untrusted data.

**Why M-cut still needs M-log's representation.** FORPREP's boundary at the `luaV_tointeger` return is not "registers". Its memory differs from `w.mo` in 6 places:
- `savestate` ×2;
- `R[A+3]` tag and payload;
- the `16(sp)` spill;
- `40(sp)`, written by the callee.

A cut must state this memory. Raw composition, as in R4-R1-2 #3's `post` or R4-R1-4 #5's `fold π k e`, gives a `writeMap8` tower of depth 6. §1b.3 found that whnf of exactly such towers is where the budget *breaks* ("every failure seen is a `timeout at whnf`"). R4-R1-4 #5 notes the risk ("if the folded memory term is itself huge"), and R4-R1-2 #3 says it "wants abstraction 5's ledger as `MemTerm`". I make that a requirement: **the boundary memory is a log literal over `w.mo`, `applyLog [e₁…e₆] w.mo`, and the cut predicate is `@[irreducible]`** (R4-R1-4 #5's device). The second piece then sees a 6-element list, never a tower.

### Core rules

```lean
structure Cut where               -- generated DATA per path and cut index; no proof
  pc   : Nat
  regs : List (Reg × Ex)          -- R4-R1-3 #4's `Ex` (normalised: `slotPay j`, `kPay i`, `res n`, …)
  log  : List (Rgn × Nat × Width × Ex)

@[irreducible] def CutSt (k : Cut) (p w s) : Config → Prop :=
  SegSt k.pc (k.regs.map (·.2.eval p w s)) (ArmPay (applyLog (k.log.map (eval …)) w.mo) _)

theorem cut_compose : Triple A (CutSt k) → Triple (CutSt k) B → Triple A B   -- trivial; correctness independent of k
theorem cut_entry  : Triple (CutSt k) Q ← (∀ c, CutSt k c → …)              -- unfold once per piece
```

- **L4-split′** becomes `cut_compose`, with the statement generated (`Cut` is data).
- **L4-call′** is idea 3's `call_frame`, with the log carried through.
- **The normaliser** that L4-call′ demands is `Ex.eval`'s defining equations together with `rd_log` (any M-log variant's read rule).

### Which round-1 variants are the same mechanism

The five M-cut proposals differ on only two axes:

| | value language | memory at the cut | checked by |
|---|---|---|---|
| R4-R1-1 #4 path certificates | `Expr` (normalised) | log | kernel `decide` (verified evaluator, 600–900 lines) |
| R4-R1-2 #3 residuals | raw `Term` + `view` lens | `MemTerm` (wants a ledger) | elaboration |
| R4-R1-3 #4 retimed cuts | `Ex` (normalised) | `WLog` | elaboration, plus a `WellFormed` decide |
| R4-R1-4 #5 `Ckpt` | raw `fold` | raw `fold` | elaboration, `@[irreducible]` |
| R4-R1-5 #1 location lists | `Loc` (normalised), **registers only** | `MemAt` (loses spills: idea 3) | `locXfer` decide (200–300 lines) |

- R4-R1-3 #4 and R4-R1-5 #1 are the same thing under different names, except that #1 drops spill cells.
- R4-R1-2 #3 and R4-R1-4 #5 are the same thing, and both need a ledger to avoid the tower.
- **The cheapest that works on FORPREP** is R4-R1-3 #4's `Ex` with a log boundary, plus R4-R1-4 #5's `@[irreducible]` wrapper. No verified evaluator (R4-R1-1 #4) and no `locXfer` (R4-R1-5 #1) are needed, because the generated segment lemmas are already the transfer proofs.

### What it makes free

- `ArmPre`, `AtRet`, `divFrame`, `armBody_split`'s hand index, and FORPREP's `fp_pre`/`FpInts`/`fpFrame`/`FpMem`.
- **The heartbeat risk of M-log being false.** Its failure costs one cut per long path, not a blocked arm.

### What it costs

- **Generator:** a `Cut` row per (path, cut index); `Ex` printing; the greedy cut placement. About 100 lines of Python (est.).
- **Lean:** `Ex`/`eval` (one `ret` equation per helper result in use), `CutSt`, `cut_entry`, and `rd_log` from any M-log variant. About 150 lines (est.).
- **What gets harder.** `Ex.ret` needs every helper result as a *function* of its arguments. `luaV_tointeger` returns *two* things, a flag in `a0` and the value at `40(sp)`, so `res` needs a projection index.

### Theories

- **ARIES checkpointing.** A checkpoint is the dirty-page table plus the log tail, and restart reads only that, never the full database image. Mohan et al., TODS 1992 **(recalled; check)**. Known, from databases. The cut is exactly (live registers, log tail).
- **Lambda lifting / closure conversion.** The continuation's free variables become an explicit environment record. Johnsson, FPCA 1985 **(recalled; check)**. Known. A cut is a closure-converted continuation, and spill cells are free variables that happen to live in memory.
- **Retiming.** Leiserson and Saxe, Algorithmica 1991 **(recalled; check)**. Known; R4-R1-3 #4 cites it. Kept because cut placement is untrusted.

### Pilot

- **The smallest decisive build.** `Cut`, `CutSt`, `cut_compose`, a hand-written `Cut` row for FORPREP at `0x8001e200` (6 log entries), and `rd_log` from R4-R1-4 #4's two rewrite rules, which are the cheapest M-log variant: no generator change.

  - If it exceeds about 30k, cuts are not "about 5k", and FORPREP's two pieces do not fit. Then the budget really does require M-log's speed claim.
  - If it is about 5–10k, M-cut carries the budget alone.
- **MODK refactor.** One generated `Cut` at `0x8001f7bc` (`__moddi3`'s return) with a 2-entry log (`savestate`). Target: `modk_call` 6 → 1 line, with no `ArmPre`.
- **IDIV.** One cut after `__divdi3` on the `bltz` path.

## 5. Comprehension log entries: a store loop's closed form *is* a log entry

**Acts on:**
- **(b)** R4-R1-3 #2 (lattice `tile`/`accel`) and R4-R1-2 #4 (`iterate_affine` and `foldWrites`) with R4-R1-2 #5 (ledger and `close_of_ledger`);
- **(c)** R4-R1-3 #2's single-pointer cell and R4-R1-4 #3's `slotCopy` schema, with a counterexample at VARARGPREP.

### The objection

R4-R1-3 #2 and R4-R1-4 #3 claim that the two slot copies are "the same" (`luaD_poscall` `0x8000a464`, and `luaT_adjustvarargs` `0x80019874`). They are not. The VARARGPREP body has **four** stores against two moving pointers and one fixed cell:

```
80019874: ld   a2,-8(a4)       ; src payload            (a4: source, stride 16)
80019878: sd   a5,16(a6)       ; L->top := a5           FIXED address, written every pass
8001987c: addi a5,a5,16        ;                        (a5: destination, stride 16)
80019880: sd   a2,-32(a5)      ; dst payload
80019884: lbu  a2,0(a4)        ; src tag
80019888: addi a4,a4,16
8001988c: sb   a2,-24(a5)      ; dst tag
80019890: sb   zero,-16(a4)    ; setnilvalue(src)       (ltm.c: "erase original parameter")
80019894: bne  a5,a3,…
```

`luaD_poscall`'s copy (`0x8000a464..0x8000a47c`) has 2 stores and no fixed cell.

- R4-R1-3 #2's `Cell` is `writes : List (Int × Src)`, offsets relative to *one* pointer. It cannot express the source-nil store, which is relative to `a4`, nor `L->top`, which has stride 0, last write wins.
- `tile_rd`'s "which cell does a point fall in" is false for a stride-0 write, because every pass hits the same address.

### The idea

Do not give store loops a separate closed-form object (`tile`, `nilMem`, `foldWrites`) plus a separate multi-slot close (`bleach_tile`, `Core.writeNils`). Add **one log entry kind** to the M-log ledger:

```lean
inductive Entry
  | w   (r : Rgn) (off : Ex) (wd : Width) (v : Ex)
  | all (k : Ex) (r : Rgn) (off₀ stride : Ex) (wd : Width) (v : Ex → Ex)   -- ∀ i < k, write at off₀ + stride·i the value v i
```

- A loop's post memory is `applyLog (Δ ++ [all k …, all k …, …]) m`: one comprehension entry per store in the body, each with its own stride.
- A stride-0 entry collapses to `w r off₀ wd (v (k-1))` when `k > 0`. That is one lemma, `all_stride0`.
- The source-nil and the destination-copy entries are in different regions of one chunk: the old frame versus above `L->top`. `fwd` separates them by offset ranges, given `actual + 1 ≥ nfix`.

The loop rule (any L4-loop′ variant; R4-R1-4 #3's `segLoop` is the cheapest) is instantiated **once, generically**:

```lean
theorem compr_loop (body : ∀ i < k, Triple (SegSt h (pins i) (applyLog (Δ ++ prefix i) m))
                                            (SegSt h (pins (i+1)) (applyLog (Δ ++ prefix (i+1)) m)))
    : Triple (SegSt h (pins 0) (applyLog Δ m)) (SegSt ex (pins k) (applyLog (Δ ++ compr k) m))
```

Here `prefix i` is the comprehension entries truncated at `i`. The body obligation is the generated segment, read through `rd_log` with a symbolic `i`.

### Core rules

| law | rule (once) |
|---|---|
| L4-loop′ (store loops) | `compr_loop` (from `segLoop`) + `all_snoc : applyLog (all (k+1) …) = applyLog (all k … ++ [w … (v k)])`. That is the whole induction, and no loop writes it. |
| reads through a loop's effect | `rd_all`: a read at `off` hits iff `∃ i < k, off = off₀ + stride·i`. For slots this is `a ≤ j < a + k`: one linear, disjunction-free fact, not `decide`. |
| the close | R4-R1-2 #5's `close_of_ledger`, unchanged. A comprehension entry in region `slot` with nil tags is an allowed entry, so LOADNIL's close is MOVE's close. |

### What it makes free

- **`loadnil_loop` and the separate multi-slot close.** LOADNIL's whole proof becomes a kit run with one `compr_loop` node and the ordinary close.
- **RETURN0's and RETURN1's fills** (store-first, offset 0, versus bump-first, offset −8: `0x8001c2f4` vs `0x8001ed74`). These are one entry with a different `off₀`. That is the affix normalisation R4-R1-4 #3 asked for, now done by the entry's arithmetic.
- **VARARGPREP's copy:** four entries, one of them stride 0. This is the case R4-R1-3 #2 sends to "conditional cells … fall back". It is not conditional; it is multi-pointer.
- **Callee effects.** `luaT_adjustvarargs` is a *helper* called from the VARARGPREP arm, so its summary's write effect `Δ_f` is these four entries. That is precise, not R4-R1-2 #5's havoc in `cstack`, and idea 3's `call_frame` appends it.

### What it costs

- **`Entry.all`, `rd_all`, `all_snoc`, `all_stride0`, `compr_loop`:** about 120 lines (est.). `rd_all` is where `omega` remains: one linear goal per read through a loop effect.
- **The generator** must emit the body's stores as `(region, off₀, stride, width, value)`. Stride and region come from R4-R1-5 #3's scalar-evolution pass, which is data.
- **What gets harder.**
  - `fwd`'s `decide` is no longer total: a read against an `all` entry with symbolic `k` returns `stuck`, and `rd_all` takes over.
  - VARARGPREP's `luaD_checkstack` realloc precedes the loop. The loop's region is then the *new* stack chunk (idea 2), and the old one is freed.

### Theories

- **Run-length encoding.** A run of k repeated symbols is stored as (symbol, k) and decoded on demand. Golomb, IEEE Trans. Inf. Theory 1966 **(recalled; check)**. Known, from data compression. A comprehension entry is an RLE of k writes with an affine address.
- **The polyhedral model and Presburger arithmetic with divisibility.** Feautrier 1991; Cooper's quantifier elimination, 1972 **(recalled; check)**. Known. `rd_all`'s hit test is `∃ i < k, a = off₀ + stride·i`, a Presburger formula with a divisibility atom.
- **Array comprehensions in SMT array theories.** `λ i. ite (i ∈ range) v (old i)`, as in the combinatory array logic of de Moura and Bjørner, FMCAD 2009 **(recalled; check)**. Known. Here as a *log entry*, not a theory solver.
- **Novel here:** store loops and the M-log ledger sharing one representation, so loops add no close and no closed-form object.

### Pilot

- **LOADNIL refactor.** This is the smallest build.
  - Build `Entry.all`, `rd_all`, `all_snoc`, `compr_loop` (on R4-R1-4 #3's `segLoop`) and `close_of_ledger` with `all` entries.
  - Target: `sim_LOADNIL` at 5 hand lines or fewer, from 47, with no `loadnil_loop` and no `Core.writeNils`.
- **The cross-check.** RETURN1's fill at `0x8001ed74` with zero new lemmas.
- **The stress test.** `luaT_adjustvarargs`'s 4-entry body, the one R4-R1-3 #2 cannot express.
- **No effect** on FORPREP, IDIV, EQ or LT.

### Seed

`jj`, the only doubled letter: one unit repeated. It sits right after `12`, the only digit run starting with 1, read as "one entry, k copies".

### If M-log's heartbeat claim is false

The declaration count carries the budget: M-cut with generated cut indices, at about 5k per cut (idea 4). FORPREP (≈ 223k est.) and IDIV's mismatch path need one cut each.

The condition is that a cut's boundary memory is a short log literal under an `@[irreducible]` predicate, so M-log's *representation* is still required. The decisive measurement is the setup cost of `cut_entry` on FORPREP's 6-entry boundary.

### What would falsify the leading combination cheaply

1. **The +11 byte.** One extra column in `lstr_trace.py`: every long string's `shrlen` at every head. A value other than `0xFF` kills idea 1's model. Seeing `0xFF` everywhere confirms that LT has exactly this one missing fact. Seconds of work.
2. **The cut setup.** One hand `Cut` row for FORPREP at `0x8001e200`, then measure `cut_entry`. Above about 30k means M-cut cannot carry the budget, and M-log's speed becomes necessary.
3. **Spills.** One generator pass listing `sp`-relative store/load pairs across call nodes in the 9 call-bearing arms.
   - Any pair other than FORPREP's `16(sp)` and `40(sp)` is more of idea 3's case.
   - A pair whose cell the callee *does* write would break the ABI assumption behind `call_frame`.
4. **The has-zero lemma.** Prove `haszero_iff` first, by the lane digit argument with no `bv_decide`. If it does not fit the budget as one declaration, every aligned `strlen`/`strcmp` path is blocked. Both functions take the word path on 8-aligned `ts+24`, so no scan rule helps until this lemma exists.
