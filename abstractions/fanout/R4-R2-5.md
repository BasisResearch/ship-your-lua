## 1. Wrap-free charts: the omega is modular, not separating

**Acts on:**
- **(c)** M-log's heartbeat claim as R4-R1-5 #4, R4-R1-1 #3 and R4-R1-3 #3 state it;
- **(a)** R4-R1-2 #2 and R4-R1-4 #4 (charts).

### The idea

All five round-1 budget proposals assume that `kit_disch`'s `omega` time goes to proving that two addresses *differ*. The FORPREP ledger (`ledger/kit-arms-2.md`, "FORPREP: the obstruction") says something more specific: "**2–4 `omega` runs per side condition through `Nat.mod_eq_of_lt`**". Those are **no-wrap** goals, `(x + o) % 2^64 = x + o`, not separation goals.

The machine addresses are `BitVec 64`, such as `addi a5,s9,16·b` and `ld 16(s0)`. The relation's ranges and `slotVal` are stated on `Nat`. Every read pays twice:
1. lift the address from ℤ/2⁶⁴ to ℕ;
2. then compare.

A region-tag table removes step 2 only. The lift is still needed:
- inside `addrOf`'s soundness (R4-R1-1 #3);
- inside `⟦a⟧` of a `SymAddr` (R4-R1-5 #4);
- inside `rd_wr_chart`'s `w.at ρ + o` (R4-R1-2 #2).

So the falsifier being run now can measure "labels by `decide`", see the guarded load fall only part of the way (say to 12k rather than under 10k), and report M-log as FALSE. The mechanism would not be wrong; the residue would be the lift.

**Proposal.** A chart pointer is a `BitVec` term of a fixed shape, `ptr ρ o := w.atBV ρ + BitVec.ofNat 64 o`. It comes with one theorem per *region kind*, proved once from `Ranges`:

```
Ranges.lift (hr : Ranges p w) (ho : o < size p ρ) :
    (ptr ρ o).toNat = w.at ρ + o
```

The premise is `w.at ρ + size p ρ ≤ 2^64`. That is the covering-space fact: each region sits in one sheet of ℕ over ℤ/2⁶⁴, so the lift exists and is unique there.

`o < size ρ` is a literal comparison (`decide`), except for slots: `16·j + 8 < 16·maxstack`. That follows from the operand bound the arm already has (`Supported`'s "register operands `< maxstacksize`"). So it is one hypothesis lookup per operand per arm, not one per read.

### Core rules

**L4-split's cost precondition → `Ranges.lift` plus `chart_sep`.**
- `chart_sep` is any round-1 table (`Rgn.sep_sound` of R4-R1-1 #3, `Ranges.atlas` of R4-R1-4 #4). It is now stated on *lifted* addresses.
- `simp only [Ranges.lift hr (by decide)]` replaces every `% 2^64` before the separation table runs.

### What it makes free

- **The `Nat.mod_eq_of_lt` `omega` runs.** The ledger says these are 2–4 per side condition, which is a large share of the 341 runs if it holds for MODK too.
- **The residue that would otherwise make the M-log measurement inconclusive.**
- **The scan bodies of M-scan.** `lbu a5,0(a0)` with `a0 = x + 24 + i` is one `Ranges.lift`, with the string's chunk as the region and `i < len + 1`, instead of a wrap proof per iteration.

### What it costs

- One `size` per region, read from `Layout.lean` (no hand offsets), plus one `lift` lemma per region kind. That is about 40 lines on top of whatever chart table is chosen.
- What gets harder: generated address terms must keep the `base + ofNat o` shape. If the segment generator constant-folds `s9 + 16·b + 8` into a single `ofNat` of a sum, a normaliser must re-associate it once.

### Theories

- **Covering spaces and path lifting** (algebraic topology; Hatcher, *Algebraic Topology*, §1.3 **[check]**). ℕ → ℤ/2⁶⁴ is a covering map. A region that does not contain the wrap point is evenly covered, so the lift is unique on it. Known mathematics; novel as a proof device for machine addresses.
- **Wrapped-interval analysis** (Navas, Schachte, Søndergaard, Stuckey, "Signedness-agnostic program analysis", APLAS 2012 **[check]**). Known. Intervals on the circle are lifted when they do not straddle the wrap.
- **CompCert's `Ptrofs` and `Mem.valid_access`** (Leroy). Known. A valid access is in bounds, so its offset arithmetic does not overflow.

### Pilot and cheap falsifier

- **Falsifier (an hour, no build of new rules).** In MODK's seg2 and seg4 (38k and 42k), log every goal `kit_disch` sends to `omega` and classify it as either:
  - **wrap:** it contains `%` or `2^64`, or comes through `Nat.mod_eq_of_lt`;
  - **sep:** `≠` or a disjunction.
- **Reading the result.** If the wrap goals are under 30% of `omega` time, this idea is dead and M-log carries everything. If they are over 50%, M-log's measurement must be run *with* `Ranges.lift`, or it will under-report.
- **Control arm, for the same run.** Count how many distinct goals there are, against the 341 runs. If the ratio is about 12:1, as ROUND-4 suggests ("the same facts are re-proved for each read and each pin"), then memoising each goal once per declaration is the null hypothesis that any log or chart must beat.
- **Smallest build.** `ptr`, `size`, `Ranges.lift` for `slot`, `kslot`, `ciF`, `LF`. Re-time seg2 and seg4.

### Seed

*Overmultiply*: multiplication that overflows, i.e. the wrap. *Swither* (to hesitate) and *irrelate* (unrelated): the measurement may be judging the wrong cause.

## 2. Summaries keyed by entry and continuation, not by symbol

**Acts on:**
- **(c)** R4-R1-5 #5 (the summary dynasty over the call tree);
- **(c)** R4-R1-1 #2's per-helper `of_wrChain`;
- **(b)** with R4-R1-4 #5's `call_poly`.

### The idea

The libgcc soft-division code that IDIV and FORPREP call is not a set of functions. It is one region with several entries (disassembly at `0x8002f72c..0x8002f7dc`):
- `__divdi3` is two instructions (`bltz a0`, `bltz a1`). Then it **falls through** into `__hidden___udivdi3` at `0x8002f734`, with no call and with `ra` still the caller's.
- Its negative paths branch into the middle of the *`__umoddi3`* symbol:
  - `0x8002f78c`, `0x8002f79c`, then `j __hidden___udivdi3` (`0x8002f798`), a tail jump that returns through the caller's `ra`;
  - or `mv t0,ra; jal …; neg; jr t0` (`0x8002f7a0..7ac`).
- `__moddi3` (`0x8002f7b0`) keeps the caller's return address in **`t0`**. It returns by `jr t0`, and its inner `jal` has clobbered `ra`.

So:
- R4-R1-5 #5's `Fp f = local f ∪ ⋃_{g callee of f} Fp g` is wrong for `__divdi3`. Its symbol has no callee, but it executes all of `udiv` and part of `__umoddi3`.
- "Acyclic call tree" holds, but over the wrong graph.
- Any summary or footprint derivation keyed by symbol, or that recognises a return as `ret` (`jalr x0,0(ra)`), either misses `jr t0` or attributes `udiv`'s writes to the wrong owner.

**Proposal.** The unit of summary is a **peninsula**: an entry pc `e` together with a *continuation value* `k`, the symbolic return address held in whatever register.
- Its region is the DFS closure from `e`, cut at any `jalr` whose *target value* is `k`. A return is recognised by value, not by register.
- Nested `jal`s with a fresh link become call nodes.
- The summary is `∀ k`.

`__hidden___udivdi3`'s summary is `∀ k, ra = k → … reaches k`. The same theorem then serves all three ways in:
- the fall-through from `__divdi3` (`k` = the arm's return);
- the tail jump from `0x8002f798`;
- the `jal` from `__moddi3` (`k = 0x8002f7c0`).

### Core rules

**L4-call → `peninsula_call`, proved once.**

```
peninsula_call (S : ∀ k, PenSum e k) (hjal : link register r := k at pc) :
  SegSt pc pins M → SegSt k (S.results ++ pins.filter (· ∉ S.clobber)) M'
```

- `S.clobber` is computed from the region's write chain (`FrameMeta.abiFrame_of_wrChain`, one `decide`). For `__moddi3` it includes `ra` and `t0`.
- The filter is R4-R1-4 #5's `call_poly` frame; R4-R1-1 #2's `∀ρ` is the same thing.

**Footprint composition → `pen_fp`.** The footprint of `(e, k)` is the write set of its region plus the footprints of its call nodes. The induction is over the *peninsula graph*: `jal` edges with fresh links only. Tail jumps and fall-through are region membership, not edges.

### What it makes free

- **IDIV's two helpers.** `__divdi3` and `__moddi3` (`0x8001f73c`, `0x8001f964`) are two `peninsula_call`s.
- **FORPREP's `__hidden___udivdi3` (`0x8001f86c`).** No `t0` pin is needed. KIT-2 pinned `t0` by `SegSt.pin5`; `t0` is just in or out of the clobber set.
- **The "one `decide` per helper" claim** of R4-R1-1 #2 becomes true per peninsula rather than false per symbol.
- **Later stdio helpers.** The print chain has the same shape: newlib shares tails and uses tail jumps.

### What it costs

- **Generator.** The region DFS must stop on *value*. That is a symbolic-equality check on the jump target, which the generator's segment emitter already evaluates for `jalr`.
- **Proof side.** One `PenSum` structure and `peninsula_call`, about 60 lines.
- **Harder.** A region reachable from two entries is summarised once per entry, unless the shared part is its own peninsula. Here `udiv` is its own, so it is summarised once.

### Theories

- **Continuation-passing style.** A return is a jump to a continuation value (Appel, *Compiling with Continuations*, 1992 **[check]**). Known. `jr t0` is just invoking the continuation held in `t0`.
- **Function-boundary recovery in binaries**: ByteWeight (Bao et al., USENIX Security 2014 **[check]**); Andriesse et al., "Compiler-agnostic function detection in binaries" (EuroS&P 2017 **[check]**). Known. Symbols do not delimit code that compilers share.
- **Watershed delineation in hydrology** (Jenson and Domingue, 1988 **[check]**). A basin is defined by its pour point and the flow into it, not by political borders, which here are the symbols. Known; the analogy is novel.

### Pilot

- **IDIV mixed-sign path.** `jal __divdi3`, then `bltz` at `0x8001f748`, then `jal __moddi3` at `0x8001f964`, then `snez`/`sub`, then the shared epode at `0x8001f74c`. Use one `udiv` peninsula, applied from both callers.
- **Smallest build.** `PenSum` for `udiv` only, then check that `__divdi3`'s fall-through and `__moddi3`'s `jal` both instantiate it.
- **Falsifier.** If the existing `udivdi3_sum` is already `∀ ra` and is already reused from `__moddi3`, this idea reduces to a correction of R4-R1-5 #5's derivation. The caller can check that in the proof file.

### Seed

*Peninsularism* (code joined to its neighbour by a fall-through neck), *endgate* (the exit is a gate defined by where it leads), *recussion* (beaten back: the return goes to whatever value was handed in).

## 3. Two footprints per string: a coarse one for disjointness, an exact one by variant for stability

**Acts on:**
- **(c)** R4-R1-3 #5 (the holed complement);
- **(c)** R4-R1-4 #1's `tsFoot`;
- **(c)** R4-R1-5 #2's `fp`;
- **(a)** R4-R1-2 #1(a) (the footprint conjunct in `ValRepr.str`).

### The idea

Round 1 used one set for two jobs:
- **(i)** "the string is not in `Win`", which transfers its bytes to the machine memory;
- **(ii)** "no run writes a byte this predicate reads", which keeps the predicate true along CALL and CONCAT's GC.

The two need different sets, and every round-1 choice is wrong for one of them.

`TString` (`lobject.h`) has `next` at +0, `tt` at +8, `marked` at +9, `extra` at +10, `shrlen` at +11, `hash` at +12, and a **union** at +16: `lnglen` for long strings, `hnext` for short ones. Contents start at +24.
- **R4-R1-3 #5** makes "`hnext` +16 of every object" a hole. But `luaS_eqlngstr` reads `ld a4,16(a0)` / `ld a2,16(a1)` at `0x80017188`, which is `lnglen`. It is the very first thing EQ-long needs. `l_strcmp` reads it too (`ld s2,16(a0)` at `0x8001a730` when `shrlen = 0xFF`). The holed complement deletes the length of every long string.
- **R4-R1-4 #1** fixes `tsFoot` = +8, +11, +16..23, contents, terminator. For a *short* string, +16..23 is `hnext`, which `luaS_resize` (rehash) and `luaS_remove` (sweep) rewrite. So `Sealed.along` fails at the first CALL or CONCAT that resizes the string table or sweeps a neighbour.
- **R4-R1-5 #2's** `fp = [x, x+24+len]` includes `next`, `marked` and `hash`, which the GC and `luaS_hashlongstr` write (`hash` +12 and `extra` +10 of long strings, the first time one becomes a table key: F2).

**Proposal.** Two sets.
- **Coarse, for disjointness: the string's whole allocation chunk** `[x, x + 24 + len + 1)`. "Chunk ∩ `Win` = ∅" is the one conjunct in `ValRepr.str`, in R4-R1-2 #1(a)'s place. Header bytes being inside it is harmless, because this set is only ever compared with `Win`.
- **Exact, for stability: the variant support** `strSupp v x len`, a function of the variant read from `Layout.lean`:
  - short: `{tt, shrlen}` ∪ contents ∪ terminator;
  - long: `{tt, shrlen, lnglen₀..₇}` ∪ contents ∪ terminator.
  - It is only ever compared with *write logs*: GC writes, `luaS_resize`, `luaS_hashlongstr`.

### Core rules

**L4-str → `Core.str_bytes`.**
- Coarse disjointness plus `Core.frame` gives `TStringReprT c.σ.mem x s`.
- Because the predicate is total-read (R4-R1-4 #1's `T` shadow) and its support ⊆ the chunk, this is `Sealed.unseal` with `S := chunk`.

**L4-str′ for CALL/CONCAT → `str_stable`.**
- Any run whose write log misses `strSupp` preserves `TStringReprT`. The log is checked against a set computed from `shrlen`, by `decide` on offsets.
- GC stores to `next`, `marked` and (short) `hnext`, and hashing stores to (long) `hash`/`extra`, are all outside the support by the variant definition.

### What it makes free

- **EQ-long, with its length.** `lnglen` is supported for long strings.
- **LT on both variants.** `l_strcmp` tests `shrlen` at `0x8001a720` and `0x8001a734`.
- **The CALL and CONCAT stability proofs.** These pass against a write log that touches headers.
- **The F2 table-key case.** `luaS_hashlongstr` breaks no string fact.

### What it costs

- One `Layout.lean`-generated `strSupp`, about 20 lines. The `T` shadow and `Sealed` instance are R4-R1-4 #1's, about 60 lines.
- **Harder.**
  - `ValRepr.str` must know the variant to pick the support. It does: the tag at +8 is `0x04` or `0x14`, and the boot witness reads it.
  - Long strings with `extra = 0` that later get hashed are fine, because `extra` is outside the support.

### Theories

- **Dynamic frames with state-dependent reads clauses** (Kassios, FM 2006; Dafny's `reads` sets, Leino **[check]**). Known. The support is a function of the object's own bytes (the variant).
- **Alternative splicing** (molecular biology). One gene, with different exons expressed per variant. The union at +16 is one locus read as two different fields. Known biology; the analogy is novel.
- **Variant records and tagged unions** (Wirth's Pascal, 1971 **[check]**). Known. Field validity depends on the discriminant.

### Pilot and falsifier

- **EQ-long.**
  1. `Core.str_bytes` twice.
  2. `luaS_eqlngstr`: pointer test, then the `lnglen` loads, then `jal memcmp` at `0x800171b0`.
  3. A `memcmp` scan summary (R4-R1-4 #2), with `n = lnglen`.
- **Falsifier, a law check on traces.** Count stores to:
  - +16..23 of a short string;
  - +16..23 of a long string;
  - +10 and +12 of a long string.

  Run it over the test suite, CALL print's chain, and one table-keyed long-string program. The prediction: the first and third counts are non-zero and the second is 0. If the first is 0 everywhere too, the coarse/exact split is moot until F2.

### Seed

*Morphoplasmic* (the form depends on the substance: the footprint depends on the variant), *unpitted* (whether the stone at +16 is there), *uncravatted* (a union is untied).

## 4. Fork-placed cuts: a proof trie over the arm's path DAG

**Acts on:**
- **(b)** R4-R1-3 #4 (`CutSt`, computed cut states) combined with R4-R1-4 #5 (`Ckpt`, irreducible);
- **(c)** per-path enumeration, as in R4-R1-1 #4's path words and R4-R1-3 #4's `PathTable`.

### The idea

All five M-cut variants place cuts by *budget* (a running sum near 150k) and enumerate *paths*. The disassembly shows that this repeats the expensive part.

**FORPREP.** The integer path does:
- `savestate`;
- the tag test of `R[A+2]` (`lbu a4,40(a5)` at `0x8001e1c0`);
- the step-zero test;
- `ld s10,0(a5)`;
- `sb`/`sd` of `R[A+3]`;
- the spill `sd a5,16(sp)`.

Then it **forks on the sign of the step** (`bgez s6` at `0x8001e1e8`) *before* either call.
- Each side calls `luaV_tointeger` at its own site (`0x8001e1fc` up, `0x8001f9b0` down).
- Each then forks skip/run (`blt a0,s10` at `0x8001e210`).
- The run paths call `__hidden___udivdi3` (`0x8001f86c`; GCC dropped the `step != 1` test).
- The skip paths **rejoin** at `0x8001e218`.

That is four Step-feasible leaves. Per-path lemmas elaborate the shared prefix, which holds all the guarded loads through `savestate`, four times. Each copy carries the cost the ledger measured: "the run to the `luaV_tointeger` entry alone is between 100,000 and 200,000".

**IDIV** forks twice:
- `bgeu` at `0x8001f730` (n ∈ {0, −1});
- `bltz` at `0x8001f748` after `__divdi3`.

The mixed-sign path rejoins the main one at `0x8001f74c`, a Pindaric triad: strophe, antistrophe, shared epode.

**Proposal.** Cut at **forks**, not at heartbeat sums.
- The generator emits the arm's path *trie*: the CFG unrolled from the jump-table target to the head, with infeasible error leaves marked. It emits this as data.
- A fork whose subtree has ≥ 2 Step-feasible leaves is a cut. The cut state is the computed strongest postcondition at that pc (R4-R1-3 #4's `CutSt` or R4-R1-4 #5's `Ckpt`). It is unique, because a fork in a trie has one incoming path.
- Joins are not cuts. A shared tail is duplicated per leaf, which is cheap: 4–6 instructions plus the close.
- The budget only *adds* cuts, inside a long unforked segment. That is where retiming (R4-R1-3 #4) still applies.

### Core rules

**L4-split′ → `fork_split`, proved once.**

```
fork_split (T : Trie) (v : T.fork)
    (hpre : Triple P (Cut T v))
    (hkids : ∀ c ∈ T.children v, Triple (Cut T v ⊓ guard c) Q) :
    Triple P Q
```

- `Cut T v` is a `def` application. The guards are the branch polarities, discharged by `kit_guard` as today.
- Correctness is independent of the placement (as in R4-R1-3 #4). Fork placement makes the *total* elaboration linear in the trie's size instead of in (paths × prefix).

### What it makes free

- **FORPREP with no hand split.** One prefix declaration to `0x8001e1e8`, then two declarations per sign, each with:
  - a call node;
  - one load of `sp+40`;
  - a fork;
  - a second call node or the skip.

  Each suffix is about 80k by §1b.3's rates (2 call nodes about 17k, one guarded load about 18k, the close 24k, setup 5k).
- **IDIV.** The prefix through `__divdi3` is cut at `0x8001f748`.
- **Total heartbeats for FORPREP.** These fall from about 4 × prefix to 1 × prefix.
- **If M-log is FALSE, this carries the budget.** No mechanism here touches the per-load cost. The prefix fits iff the ledger's "100–200k to the call" is under 200k at the fork, which is three instructions earlier.

### What it costs

- Generator: emit the trie with fork ids (it already walks every path). About 40 lines of Python, data only.
- Lean: `Trie`, `Cut` (borrowed from whichever M-cut variant wins), `fork_split`. About 50 lines.
- **Harder.** A fork *inside* a summarised helper (`__moddi3`'s sign tests) is not an arm fork. The helper's summary hides it, which is correct.

### Theories

- **Tries and prefix sharing** (Fredkin 1960 **[check]**). Known. The shared prefix is elaborated once.
- **Dominator trees** (Lengauer and Tarjan, TOPLAS 1979). Known. On a trie, a fork's prefix dominates all its leaves.
- **Phylogenetics**: on a tree, an ancestral state is reconstructed once per internal node and shared by every descendant lineage. That is Felsenstein's pruning, *Journal of Molecular Evolution* 1981 **[check]**. Known; the analogy is novel.
- **The Pindaric triad**: strophe and antistrophe part, the epode is shared. Literary form, used here only as the seed's image.

### Pilot and cheap falsifier

- **Falsifier (with today's kit, no new rule).** Elaborate FORPREP's prefix to `0x8001e1e8` as one `ArmBody` and log heartbeats.
  - Over 185k: fork-cuts alone cannot carry FORPREP, and idea 1 or M-log is required.
  - Under 150k: FORPREP is unblocked by this idea alone.
- **Smallest build.** `fork_split` with a hand-listed trie for FORPREP, and `Cut` as R4-R1-4 #5's `Ckpt`.

### Seed

*Pindarus* beside *Cassia*: the Pindaric triad (two voices part, one epode is shared) is IDIV's diamond and FORPREP's rejoin at `0x8001e218`. *Groenendael* (a herding dog): paths herded into a trie. *Trapezohedron*: faces that share edges.

## 5. Stack-indexed charts: labels that survive a frame move

**Acts on:**
- **(c)** R4-R1-2 #2's atlas ("charts do not overlap, so there are no transitions") and R4-R1-4 #4;
- **(c)** the `slot j` labels relative to `w.base` in R4-R1-1 #3, R4-R1-3 #3 and R4-R1-5 #4;
- **(c)** M-str's "outside `Win`" anchor as R4-R1-1 #5 states it, since it admits re-proof at VARARGPREP and CALL.

### The idea

Every main chunk begins with `VARARGPREP`. `luaT_adjustvarargs` (`ltm.c`) does three things that matter here:
- it copies the function and the fixed parameters to the top;
- it nils the originals;
- then it sets `ci->func += actual + 1` and `ci->top += actual + 1`.

Before any of that, `luaD_checkstack(L, maxstacksize+1)` may **reallocate the whole Lua stack** (`luaD_growstack`), which moves every slot to a fresh block.

CALL moves the window too: the callee's `base` is the caller's `R[A]+1`, so the two frames overlap.

So:
- A label `slot j` relative to `w.base` changes meaning across VARARGPREP and CALL. The atlas *does* need transition maps, at exactly the arms that M-cut and M-log have not yet met.
- "Footprint ∩ `Win` = ∅" must be re-proved whenever `Win` moves (R4-R1-1 #5 lists this as a cost).

**Proposal.** Label stack cells by **absolute stack index** `stk n`, an index into the current stack block (`w.stack`), not an address relative to `base`.
- `slot j := stk (w.baseIdx + j)` is an abbreviation (a view).
- A frame move changes `w.baseIdx` and leaves every log entry and every footprint fact untouched.
- A reallocation changes `w.stack` (the chart origin) and nothing else, because entries are indices.

The M-str anchor becomes "chunk ∩ (stack block ∪ C stack ∪ `ci`/`L` objects) = ∅". That is invariant under `func` moves. It needs re-proof only at `luaD_reallocstack`, whose new block is fresh from the allocator (`_malloc_r`, already an `SWP` run here).

### Core rules

**L4-split's separation → `stk_sep`.** `stk n` and `stk n'` are disjoint iff `n ≠ n'`; `stk` and every non-stack chart are disjoint. This is one table row, as in round 1.

**Frame move → `view_shift`, proved once.**

```
Core p c s w → w' = { w with baseIdx := w.baseIdx + d } →
  (slot_{w'} j = slot_w (j + d)) ∧ logs and footprint facts unchanged
```

The only proof content left at VARARGPREP is the kernel's own register shuffle.

**Reallocation → `realloc_rechart`.** Labels are kept, and the origin moves. Fresh-block disjointness comes from the allocator summary, once.

### What it makes free

- **The relabelling of every log entry and footprint fact.** Without this, VARARGPREP and CALL each need it.
- **`luaT_adjustvarargs`'s slot-copy loop** (`0x80019874`) can be stated as a tile over `stk` indices (R4-R1-3 #2's `accel`), with source and destination disjoint by index inequality.
- **M-str's anchor at CALL and VARARGPREP.**

### What it costs

- `RelPtrs` gains `stack` and `baseIdx` (with `base = stack + 16·baseIdx`), plus one `Ranges` fact: the stack block's extent.
- **Harder.**
  - `Win`'s definition must be re-expressed in indices. That is a refactor of `Rel.lean`, one field.
  - Arms on F1 see no change if `slot j` stays the abbreviation the kit already uses.

### Theories

- **Relative and absolute addressing; segment registers** (machine architecture). Known. Data is named by an offset into a segment, so relocating the segment does not rename it.
- **Moving-frame coordinates in geodesy**: positions recorded against a plate-fixed datum, not a moving vehicle, so the vehicle's motion does not rewrite the map (e.g. ITRF **[check]**). Known; the analogy is novel.
- **de Bruijn indices versus levels** (de Bruijn 1972). Known. Levels, which are absolute, are stable under adding binders at the inside; indices, which are relative, shift. `stk n` is a level, and `slot j` is an index.

### Pilot and falsifier

- **Not a held-out case.** It protects whichever M-log/M-str variant wins from a rewrite at VARARGPREP, the next arm every program meets.
- **Falsifier, a law check on traces.** Over the test suite:
  - does `luaD_checkstack` in VARARGPREP ever reallocate;
  - does any string chunk ever fall inside the *new* `Win`?

  If there are no reallocations and no overlaps, `view_shift` alone suffices and `realloc_rechart` can wait.
