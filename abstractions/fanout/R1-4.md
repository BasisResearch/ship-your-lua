## 1. Read–Choose–Write normal form (RCW): an opcode is a function of its read vector

**Idea.** Stop writing each opcode's meaning as a `Step` constructor whose premises pattern-match on `s.regs`. Write it as a first-order record in which the *type* stops the transfer function from seeing any register it does not declare:

```lean
structure OpSpec where
  -- static: depends on (p, pc, w) only, never on register contents
  admit  : Proto → Nat → Word → Bool                 -- F1 side conditions (LOADK kinds, CALL b≠0…)
  rd     : Word → List Nat                            -- read addresses, in order
  nEdge  : Nat
  tgt    : Proto → Nat → Word → Fin nEdge → Option Nat  -- edge targets (jumpTo, condJump's next sJ)
  wr     : Word → Fin nEdge → List Nat                -- write addresses per edge
  -- dynamic: sees ONLY the read vector (and static data)
  δ      : Proto → Nat → Word → List Value →
             Option ((i : Fin nEdge) × Vector Value (wr w i).length × String)
             -- chosen edge, written values, emitted output; none = stuck
```

`spec : OpCode → OpSpec` is the trusted artefact, written against `lvm.c` just as `Step` is now. Everything else is *derived* from it:

```lean
def specStep (p) (s s' : State) : Prop :=
  ∃ w o S, p.fetch s.pc = some w ∧ w.op? = some o ∧ spec o = S ∧ S.admit p s.pc w ∧
    ∃ i vs e t, S.δ p s.pc w ((S.rd w).map s.regs) = some ⟨i, vs, e⟩ ∧ S.tgt p s.pc w i = some t ∧
      s' = ((s.setList (S.wr w i) vs.toList).emit e).goto t
def reads w  := mask (spec o).rd w          -- replaces Fragment.reads
def edgesOf  := List.finRange nEdge |>.map (fun i => (tgt i, mask (wr w i)))  -- replaces edgesOf
def regTop   := max over rd ∪ ⋃ wr, + 1      -- replaces regTop
def step?    := the same expression, computed
```

In selective-functor terms (seed: `FbF`, read forwards and backwards), the edge choice is a `select` whose branches can be enumerated statically. The *over-approximation* of the effects is `edgesOf`, and the *dynamic* run is `δ`. The existing `Supported` tables become the static analysis of the same term that `Step` runs, so they are no longer a second copy of the facts.

**Core rules.**

- **L-B1 becomes one lemma, `rcw_footprint`.**
  If `s₁.pc = s₂.pc`, `s₁.out = s₂.out` and `∀ r ∈ (spec o).rd w, s₁.regs r = s₂.regs r`, then:
  - `(S.rd w).map s₁.regs = (S.rd w).map s₂.regs`, a `List.map_congr` of one line;
  - so `δ` returns the same `⟨i, vs, e⟩` on both states;
  - so both states are stuck, or both take the edge `(tgt i, mask (wr w i)) ∈ edgesOf` with equal values on `wr w i`;
  - and `setList_frame` gives that every register outside `wr w i` is unchanged.

  The "*some* edge with that target" refinement from the census is automatic: the witness is the chosen `i`. For `TESTSET` with `sJ = 0`, the two `Fin 2` edges share a target but differ in `wr`. The proof is about 25 lines, once, for all opcodes.
- **L-B2 becomes `Iff.rfl` plus `Option` plumbing.** `specStep ↔ step? = some` holds because `step?` is the computational reading of the *same* existential over a function. It is one generic lemma, proved by the `Option.bind` normal form.
- **The Supported side condition "the edges exist" is `admit`.** It is also a single field, so `edges_exist → (step → ∃ edge)` is one lemma.

**What it makes free.**

- **All of `bc-rule-fanout`.** Every `Step.sim` arm is an instance of `rcw_footprint`. Every `step?_sound` and `step?_complete` arm is an instance of the generic `Option` lemma.
- **Three of the five per-rule definition sites.** `reads`, `edgesOf` and `regTop` are computed from the spec, and the `step?` arm stops being written by hand.
- **The held-out cases need no bytecode proof lines.** H1 widens `admit` for LOADK to allow `.str`. H3 (`LEN`) is `rd = [b]`, `nEdge = 1`, `wr = [a]`, and `δ [.str s] = some ⟨0, #[.int s.length], ""⟩`. H2 (`CONCAT`) is `rd = List.range' a b` and `δ = concatCore` (see §5). H4 adds a string branch to `LT`/`LE`'s `δ` (or none at all, via §5).

**What it costs.**

- **Setup.** About 150–250 lines: the `OpSpec` structure, `setList` and its frame lemma, `mask`, the derived `reads`/`edgesOf`/`regTop`, and a proof that they meet `supportedB`'s old contract. The dataflow `sweep` and `fixpoint` stay as they are.
- **Trust.** `Step` is no longer an inductive with one readable constructor per case. The trusted text becomes 39 `OpSpec` entries. Readability can be kept: each `δ` is a `match` on the read list mirroring `lvm.c`, for example `| [.int i, .int l, .int st] => if st = 0 then none else …` for FORPREP.
- **Inversion.** Inversion on "a step by FORLOOP" becomes `simp [specStep, spec]` rather than `cases`, so proofs that relied on constructor inversion (the Layer B TV, if it inverts `Step`) must be adjusted once.
- **A one-time equivalence, if the old `Step` must stay.** Keeping the old `Step` as the headline would need `Step ↔ specStep` once, which is a per-rule proof in disguise. I recommend retiring the old `Step` rather than bridging it.
- **Honest risk.** A reviewer may call `spec` a "per-opcode table". It is not *beside* the relation; it *is* the relation, and nothing is maintained twice. That distinction is the point of the idea.

**Theories.**

- **Selective applicative functors** (*known*). Mokhov, Lukyanov, Marlow, Dimino, "Selective Applicative Functors", ICFP 2019. `select`/`branch` allow static over- and under-approximation of the effects of a program with conditional branches but static addresses. That is exactly `edgesOf` (over) and the per-edge `wr` (exact per branch).
- **Databases: functional dependencies and Heath's theorem** (*known*; check the citation). Heath, "Unacceptable file operations in a relational data base", SIGFIDET 1971. Armstrong, "Dependency structures of data base relationships", IFIP 1974. L-B1 *is* the functional dependency `pc, out, R[rd] → pc', out', R[wr]` on the relation `Step`. Heath's lossless-join decomposition `R = π_{X∪Y} R ⋈ π_{X∪Z} R` under `X → Y` is exactly the decomposition `specStep = project(rd) ; δ ; frame-join`. RCW stores the relation in decomposed form, so the dependency holds by schema, not by checking.
- **Information flow: noninterference by self-composition** (*known*). Barthe, D'Argenio, Rezk, "Secure Information Flow by Self-Composition", CSFW 2004. RCW is the degenerate case where the program's type makes the product program trivial.

**Pilot.**

- **Smallest thing to build.** `OpSpec`, `specStep`, and `rcw_footprint` for three opcodes of increasing shape:
  - `ADD` (rr, one edge);
  - `TESTSET` (two edges, one shared target);
  - `FORPREP` (two edges with different write sets, three reads).

  Then prove that the derived `edgesOf` equals the old `Fragment.edgesOf` on those opcodes, by `decide` on the opcode.
- **H1–H4.** Add the four spec entries. The measured proof lines for `bc-rule-fanout` should be 0 per case.
- **R1.** Delete `step?_sound`, `step?_complete` and `Step.sim`'s 27 arms (596 + 261 lines). Replace them with the generic lemmas, forecast under 100 lines.
- **Measure** whether `f4_strlite`'s `BcSem` kernel validation still reduces: `step?` is now a generic `δ` evaluator, so check that `decide` or `rfl` performance does not regress.

**Seed.** The doubled glyphs `ll 77 cc 44 pp` (one text, two readings: `δ` read as a relation and as a function) and the palindrome `FbF` (forward run against backward static analysis of the same term).

## 2. Construct trees: the source semantics as the least model of a deterministic call-tree per construct

**Idea.** Write `LuaSem` as one *call-tree* per construct: a free-monad term over a "call a sub-judgment" effect. Do not write it as a family of inductive rules per construct (`whileT`/`whileF`/`whileX`), and do not write it as an interpreter plus a soundness proof. Then define the relation as the least set closed under running trees whose calls are answered by the relation itself:

```lean
inductive Judg | exp | expl | stat | list | blockF | block | forIter   -- the 7 mutual judgments
def In  : Judg → Type                     -- e.g. In .stat = Env × String × Stat
def Out : Judg → Type                     -- e.g. Out .stat = Env × String × Sig
inductive Tree (α) | ret : α → Tree α
                   | call : (j : Judg) → In j → (Out j → Tree α) → Tree α
                   | fail : Tree α        -- "no rule": runtime error, outside the fragment
def rules : (j : Judg) → In j → Tree (Out j)   -- ONE tree per construct; the trusted artefact

inductive Holds : (j : Judg) → In j → Out j → Prop
  | mk : Runs (rules j i) o → Holds j i o
-- `Runs t o`: follow `t`, answering each `call j' i'` by some `o'` with `Holds j' i' o'`
```

The whole of `while_` becomes one tree, where `exitLoop` and `scope` are ordinary functions:

```lean
| .stat, (ρ, o, .while_ c b) =>
    call .exp (ρ, c) fun v =>
    if v.isFalse then ret (ρ, o, .normal) else
    call .block (ρ, o, b) fun (ρ₁, o₁, sg) =>
    if sg = .normal then call .stat (scope ρ ρ₁, o₁, .while_ c b) ret
    else ret (scope ρ ρ₁, o₁, sg.exitLoop)
```

The branching lives in ordinary Lean `if`/`match` inside the continuation. The Mercury mode discipline (every premise's inputs are fixed by earlier outputs) holds *by construction*, because a continuation can only use what it has been given.

**Core rules (L-A1 becomes three generic theorems, each proved once by induction on `Holds`/`Runs`).**

- **`holds_det`:** `Holds j i o₁ → Holds j i o₂ → o₁ = o₂`. Two runs of the same tree issue the same first call. The IH makes the answers equal, so the continuations are the same function applied to the same value, and the rest follows by induction. No rule pairs are inverted: `whileT` against `whileX` is an `if`, not two rules.
- **`solve_sound` / `solve_complete`:** `solve : Nat → (j : Judg) → In j → Option (Out j)` is the fuel-bounded generic evaluator of `Tree` (about 10 lines, written *once* for all constructs), with `solve n j i = some o → Holds j i o` and `Holds j i o → ∃ n, solve n j i = some o`.
- **Together** these are L-A1: `LuaSem H c out ↔ ∃ fuel, luaRun H fuel c = some out`, with `luaRun := solve` at `.block`.

**What it makes free.**

- **All of `ast-construct-fanout`: 187 cases.** The per-construct `execSound` arms (`while_` 19 lines, `if_` 16, `fornum` 15) disappear, because the interpreter is not written per construct. `Eval.det`'s 50 arms and `ExecS.det`'s 53 arms disappear, because determinism is one theorem about trees.
- **H1–H4 on the source side cost only the tree branches.** `Exp.string s` is `ret (.str s)`. `#a` is `call .exp (ρ,a) fun v => match v with | .str s => ret (.int s.length) | _ => fail`. `..` and `<` go through §5's core functions. Proof lines: 0.

**What it costs.**

- **Setup.** `Judg`/`In`/`Out` (dependent), `Tree`, `Runs`/`Holds`, the three theorems, and the fuel monotonicity lemma for `solve`. My estimate is 200–300 lines.
- **Readability of the spec.** The rule-per-premise form is replaced by a do-notation tree. Using `do` notation over `Tree` (it is a monad) makes each construct read like the manual's prose.
- **Getting classic rule shapes back.** Downstream proofs that want the classic shape (Layer B TV forward simulation, which likely inducts on `ExecS`) need *derived rule lemmas*. These come from one generic `Holds.unfold` plus `simp [rules]`. Each is a one-liner, but they are per construct if you write them all. Write only those that are used.
- **Dependent types.** `In j`/`Out j` are dependent, and `Holds` over a dependent family can hit Lean's elaborator and structural-recursion limits. Fallback: a single sum type `Inp`/`Outp` with a `fail` on mismatch.
- **The pilot needs an equivalence or a swap.** Either prove `Holds ↔` old `LuaSem` once (per-rule, once: the R2 refactor, forecast well under 510 lines), or retire the old `LuaSem`.

**Theories.**

- **Interaction trees / freer monads** (*known*). Xia, Zakowski, He, Hur, Malecha, Pierce, Zdancewic, "Interaction Trees", POPL 2020. Kiselyov and Ishii, "Freer Monads, More Extensible Effects", Haskell 2015. The `call` node is a visible event, and `Holds` is its interpretation by a *relational* handler, the least fixed point.
- **Logic programming: Mercury determinism and mode analysis** (*known*). Somogyi, Henderson, Conway, "The execution algorithm of Mercury, an efficient purely declarative logic programming language", JLP 1996. Mercury infers `det` for predicates whose clauses are guarded by mutually exclusive switches on bound inputs. The tree form makes every construct's clauses a *switch* syntactically, so the determinism check is trivially satisfied rather than inferred.
- **Attribute grammars** (*known*). Knuth, "Semantics of context-free languages", Math. Systems Theory 1968. The requirement that each attribute be defined by exactly one semantic function per production is what gives unique attribution. A construct tree is exactly "one semantic function per production".
- **Partial recursion as an inductive graph** (*known*). Bove and Capretta, "Modelling general recursion in type theory", MSCS 2005. `Holds` is the Bove–Capretta domain predicate annotated with outputs.

**Pilot.**

- **Smallest thing to build.** `Tree`, `Holds`, and `holds_det` for a mini-language of three constructs: `Exp` with `binop`, `and`, `not`; `Stat.while_`; `ExecL.cons`/`stop`. Show the whole `whileT`/`whileF`/`whileX` determinism triple is zero lines.
- **Then** transcribe all of F1's `rules` (about 120 lines, the same size as the current inductives). Prove `LuaSem`-equivalence, or swap it in.
- **H1–H4.** Add the tree branches and measure proof lines, forecast 0.
- **R2.** `Eval.det`/`ExecS.det` plus `execSound` (216 + 294 lines) are replaced by the three generic theorems (forecast about 120 lines).

**Seed.** `A9roupI8` / `9upm`, read as "group" and "up": each construct's rules are grouped into one tree that *calls up* to sub-judgments. The case-folded `kND`/`Nd` pair fed it too: the same letters in two cases, like one construct under several rule names.

## 3. Head-percolated abort: pretty-big-step with ONE signal-propagation principle

**Idea.** This is a less radical alternative to §2 that keeps the source semantics an ordinary Lean inductive but makes it *syntax-directed per (form, incoming outcome)*. The quadratic pairwise inversion in determinism exists because several rules share a head with overlapping premises. Today, `whileT`, `whileF` and `whileX` all start with `Eval c v`, and `whileT`/`whileX` both then run the body.

Move to Charguéraud's pretty-big-step form:

- **Intermediate forms** carry the outcome of the previous premise: `while₁ c b v`, `while₂ c b (ρ₁, o₁, sg)`, `for₁ …`, `list₁ ss sg`, and so on.
- **One rule per (intermediate form, outcome head)**, with no premise duplicated.
- **A single `abort` rule** stated once over a predicate `abortsFrom : Form → Sig → Bool`. It propagates any non-normal `Sig` (after `exitLoop` for loop forms) out of any intermediate form that declares it propagates.

`whileX`, `repeatX`, `ExecL.stop`, the `sg ≠ .normal` disjunct of `ForIter.last`, and `ExecBF.done` all collapse into that one rule. Each construct then has exactly one rule per `(form head, Sig head, isFalse bit)`. That is a *syntax-directed* system, and a syntax-directed inductive has a single inversion principle per judgment.

**Core rules.**

- **L-A1's determinism half becomes `det_of_syntaxDirected`.** It is proved once: a relation whose rules are indexed by a computable `key : Input → PremiseOutcomes → RuleId` is functional given functional premises. Concretely, the determinism proof is one induction whose every case is closed by `cases h₂ <;> simp_all` with no cross-rule contradictions, because two rules with the same key do not exist.
- **The abort rule's own lemma, `abort_det`, is proved once** for all constructs.
- **L-A1's soundness half** is not free here. The interpreter still has one case per construct, but that case is now one-line-per-rule because rules and interpreter branches are in bijection. It reduces `execSound`'s 15–19 line arms to about 2 each. That is weaker than §2, which is the price of keeping inductive rules.

**What it makes free.**

- **The quadratic term.** The census says `ExecS.det` arms grow with the square of the number of rules per construct. After the rewrite, the arm count equals the number of rules, and the rule count itself drops: every `…X` rule goes into the one `abort`.
- **Future constructs** (`return`, `goto` across functions, `pcall` errors in F3) add a new `Sig` constructor and *zero* new abort rules.

**What it costs.**

- **A one-time rewrite of `LuaSem`** into pretty-big-step form, plus a one-time equivalence with the current big-step (per-rule, once).
- **About 40% more intermediate-form constructors.** The spec is less like the manual's prose.
- **Layer B TV proofs** that invert `ExecS.whileT` now go through two intermediate forms.

**Theories.**

- **Pretty-big-step semantics** (*known*). Charguéraud, "Pretty-Big-Step Semantics", ESOP 2013, which introduced the single `abort` rule and intermediate forms to remove premise duplication.
- **Linguistics: the Head Feature Principle of HPSG** (*known*). Pollard and Sag, *Head-Driven Phrase Structure Grammar*, 1994. Rather than every phrase-structure rule restating how agreement features pass up, one principle says head features percolate from head daughter to mother. `abort` is the head feature principle for `Sig`: every construct is a mother, its current premise is the head daughter, and a non-normal signal percolates unless the mother is a loop (which *binds* `brk`, like a phrase that discharges a feature).
- **Proof theory: focusing** (*known*). Andreoli, "Logic programming with focusing proofs in linear logic", J. Logic and Computation 1992. Focusing removes the don't-care nondeterminism of proof search by committing to a phase. Intermediate forms are "focused" premises, and determinism of focused search is the analogue of `det_of_syntaxDirected`.

**Pilot.**

- **Smallest thing to build.** Rewrite only `while_`, `repeat_` and `ExecL` into pretty-big-step. Prove `det` for those with the generic abort lemma, and count arms against the current `whileT × whileF × whileX` block.
- **H1–H4 are expression-level.** They each add one `Eval` rule (with §5, one rule total for all binary operators on core values), and their determinism arms are one line each. Record this honestly: §3's advantage shows on R2, not on H.
- **Pick this over §2 only if** swapping `LuaSem` for a tree encoding is judged too costly for trust.

**Seed.** `Q999s`, the only triple in the string: three sibling rules (`whileT`/`whileF`/`whileX`) collapsing to one, with the third 9 (the X rule) absorbed into a shared principle.

## 4. Idiom grammar: machine arms parsed into RCW terms by a verified decompiler (L-C1)

**Idea.** GCC compiled the 54 arms of `luaV_execute` from a *small, closed vocabulary of C macros*:

- `vmfetch`;
- `RA(i)`/`vRB(i)`/`KC(i)` (field extraction and scaling);
- `ttisinteger` (tag load and compare);
- `setivalue`/`setobj2s` (payload store and tag store);
- `docondjump`/`dojump` (pc arithmetic);
- `Protect`/`savepc`;
- `luai_numlt` and the like.

The optimizer mixes them, but at `-O2` the result is still overwhelmingly a concatenation of recognisable *idioms*.

The abstraction is a **grammar `G` of RISC-V idioms whose semantic actions build RCW terms** (§1's `rd`/`δ`/`wr`/`tgt`), plus a **verified parser**:

```lean
structure Idiom where                  -- ~20-30 productions, shared by all arms
  pat    : InstrPattern                -- a small dataflow graph over RISC-V instrs with holes
  action : Holes → MicroFragment       -- e.g. "load R[A] as int x, else goto slowpath"
  sound  : ∀ h σ, Repr s σ → matches pat σ h → runs σ … ⊨ ⟦action h⟧ s   -- proved once per idiom

def parseArm : List Instr → Option OpSpecTerm      -- reflective, total, executable
theorem parseArm_sound :                            -- ONE theorem, by induction on the parse
  parseArm arm = some τ → ArmSimulates arm ⟦τ⟧      -- dispatch head to dispatch head
```

L-C1 for an opcode is then a closed, decidable fact: `parseArm (armOf o) = some τ ∧ τ ≡ spec o`. Here `≡` is *syntactic* equality after normalization, because both sides are terms of the same first-order RCW language (§1). Both conjuncts close by `decide` or `rfl`. There is no per-opcode proof, only a per-opcode *computation*.

Two design points keep this from becoming a per-site battery:

- **Patterns are partial orders (dataflow DAGs), not sequences.** The parser matches modulo instruction scheduling and register renaming, like a finite-state morphological analyser that matches morphemes regardless of allophonic variation.
- **Slow paths** (`luaV_arith` fallback, `luaG_opinterror`) are matched by one idiom, "call to a function outside the fragment". Its semantic action is `stuck` (no RCW edge), which is exactly the F1 convention that a non-integer operand has no rule.

**Core rules.**

- **L-C1 becomes `parseArm_sound`**, one theorem by induction over the parse derivation, composing the idioms' `sound` fields sequentially with a frame rule over machine registers and memory.
- **The dispatch-head invariant `Repr`** is stated once: `base` in `s1`/`s2`, `pc` in a callee-saved register, and the `TValue` layout. Every idiom's `sound` is relative to it, so "head to head" is the grammar's start and end symbol.

**What it makes free.**

- **The forecast `a1-arm-sim` cluster** (54 arms, where the predecessor project had 706 site rows in 40 tables). Each arm is a `decide` computation. New opcodes (H2's CONCAT arm, H3's LEN arm) cost 0 proof lines *if* they use existing idioms. Otherwise each costs one new production, which is reused by every later arm that uses it.

**What it costs.**

- **Setup:** `InstrPattern` DAG matching, `Repr`, and the idiom soundness proofs against Sail (each is a small straight-line Sail run, but against Sail's heavy step function). Estimate 20–30 idioms at 20–40 lines each, plus about 300 lines of parser and soundness.
- **The idiom set is empirical.** If GCC fused macros in some arm (for example a shared tail between `LT` and `LE` via cross-jumping), that arm needs a "shared tail" idiom or a fallback manual proof.
- **Kernel cost** of `decide` on 50–200-instruction arms. This may need `Nat`-indexed patterns tuned for the kernel.
- **Callees such as `luaV_concat` are not arms.** They need a *function-contract* idiom ("call f with args in a0–a2 ⊨ contract f"), and each contract is proved once. See §5: the callee contracts are the core-algebra functions.

**Theories.**

- **Decompilation into logic** (*known*). Myreen, Slind, Gordon, "Machine-code verification for multiple architectures: an application of decompilation into logic", FMCAD 2008. The "decompiler" there produces a function plus a certificate theorem. Here the output language is RCW rather than HOL functions, and the equality check is syntactic.
- **Computational linguistics: finite-state morphology** (*known*). Kaplan and Kay, "Regular models of phonological rule systems", Computational Linguistics 1994. Surface forms (instruction sequences) are analysed into morphemes (macros) by composed transducers robust to contextual alternation (scheduling and register choice). The arm is a "word", the idiom a "morpheme", and `parseArm` the analyser.
- **Proof by reflection** (*known*). Boutin, "Using reflection to build efficient and certified decision procedures", TACS 1997. `parseArm_sound` is the reflection lemma, and the per-opcode obligation is evaluation.

**Pilot (A1 arms, if A0.6 lands).**

- **Smallest thing to build.** Extract the `ADD` arm, then write idioms by hand until it parses:
  - `fieldA`/`fieldB`/`fieldC`;
  - `tagIsInt`;
  - `loadPayload`;
  - `addStore`;
  - `skipMMBIN` (`pc += 1`);
  - `dispatch`.

  Prove those 6–8 idioms sound, then `decide` the parse.
- **Then `EQI`.** The measure is how many *new* idioms it needs: forecast `sBfield`, `condjump`, and nothing else.
- **Then `FORLOOP`.** New idioms: `count≠0`, `pc -= Bx`.
- **The bake-off statistic** is new idioms per arm, which should fall to about 0 by the third arm. If it does not fall, the abstraction fails, and that shows cheaply.

**Seed.** `U1Ox … u2Ox`: numbered `0x` stems, hex addresses in sequence, which pointed me at the binary. `kP` recurring three times with a different letter each time: the same idiom in different contexts, like morphemes with allophones.

## 5. Sort-erased core algebra shared by both layers (the Lua "value core")

**Idea.** F1 bakes the *sort* of operands into rules:

- `Step.arith` requires `s.regs w.b = .int x`;
- `cmpRR` requires `.int x`, `.int y`;
- `Eval.arith`/`Eval.cmp` require `Eval ρ a (.int x)`.

Every new sort (strings now, floats later) therefore adds rules, and every rule multiplies across three bytecode theorems and two source theorems. The census growth (1.4 → 8.3) is partly this.

Replace this with a **core algebra on `Value`**, a small set of partial functions shared *verbatim* by both semantics, each mirroring one `lvm.c`/`lobject.c` entry point:

```lean
namespace Lua.Core
def arith?    : ArOp  → Value → Value → Option Value   -- luaO_arith / luaV_arith, int (later float)
def lessThan? : Value → Value → Option Bool            -- luaV_lessthan: int×int, str×str (l_strcmp), else none
def lessEq?   : Value → Value → Option Bool            -- luaV_lessequal
def len?      : Value → Option Value                   -- luaV_objlen on strings (tables: F2)
def concat?   : List Value → Option Value              -- luaV_concat, right to left, tostring "%d" coercion
def unop?     : UnOp → Value → Option Value
end Lua.Core
```

Then:

- `Step.arith` becomes `(s.regs w.b) (operand) → arith? op va vb = some r → …`.
- `cmpRR` becomes `lessThan? va vb = some b → condJump … b …`.
- `Eval.cmp` becomes `Eval a va → Eval b vb → lessThan? va vb = some r → Eval (a < b) (.bool r)`, and `>` is the same with the arguments swapped, as `lparser.c` does.

**No rule mentions a sort.** Sorts live only in the core functions, and each is proved about *once* (for example `lessThan?_str : lessThan? (.str a) (.str b) = some (lexLt a b)`).

With §1, the core functions are exactly `δ`'s building blocks. With §2, they are called from the trees.

**Core rules.**

- **Sort-parametricity of L-B1, L-B2 and L-A1.** The metatheory proofs of a rule never case on the value sort, because the rule sees only `Option` results of core functions. The proved rule is: *each metatheorem is stable under extension of the core functions*. Concretely, `Step.sim`, `step?_sound`/`_complete`, `Eval.det` and `execSound` quantify over any `Core` structure. They are proved once in F1 and never reopened for strings or floats.
- **A new law, L-X1 (core agreement):** the same `Core` instance is used by `LuaSem` and `BcSem`. It gives *per-operator* compile correctness for free: the TV fact "source `<` means bytecode `LT`" is `rfl` on the operator.
- **For L-C1:** each core function has exactly one C counterpart (`luaV_lessthan`, `l_strcmp`, `luaV_concat`, `luaV_objlen`). Its machine contract is proved once and used by every arm and every source operator. With §4 this is the "function-contract idiom".

**What it makes free.**

- **H4 needs no new rule in either layer.** `LT`/`LE` with two strings is the `str×str` branch of `lessThan?`, and the source `<`/`<=`/`>`/`>=` are the existing rule. Held-out proof lines: 0 in both clusters, plus about 10 lines defining `lexLt` and testing it against `l_strcmp` in the C locale.
- **H3:** one bytecode rule (`LEN`: `len? (R[B]) = some v`) and one source rule, each sort-free.
- **H2:** CONCAT's coercion (`tostring` `%d` on integers, error on anything else) lives in `concat?`. Lua's right-to-left pairwise `luaV_concat` order is inside `concat?` too. The source `..` is right-associative and compiled into one CONCAT over consecutive registers. The core function is stated on a *list*, so the source `a .. b .. c` and the bytecode `CONCAT A 3` share one function, and their agreement is a one-line `concat?` associativity lemma rather than a TV theorem.
- **Later: floats.** They enter as new branches of `arith?`, `lessThan?` and `unop?`, and no metatheory is reopened. This is where the pay-off compounds.

**What it costs.**

- **Rewriting 6–8 existing rules** in each layer to go through `Core`. That is one-time, and small.
- **Opcodes with operand shapes** (`arith`'s `rr`/`rk`/`ri`) still need their operand fetch, which is unchanged.
- **Proofs that used the pattern `.int x`** directly (for example `forCount` in FORPREP) keep it. FOR loops genuinely are integer-sorted in F1, and float loops are a separate `forprep` path in `lvm.c`. Keep `forprep` outside `Core` until Float.
- **Risk:** `Value.show` and `tostring` for `concat?` must agree with `%d` (`LUAI_NUMFFORMAT` for ints is `"%" LUA_INTEGER_FRMLEN "d"`). This is recalled from memory; check it in `luaconf.h`.

**Theories.**

- **Order-sorted algebra** (*known*). Goguen and Meseguer, "Order-sorted algebra I", TCS 1992. Operations are declared once at the top sort with subsort-overloaded behaviour; later, int ≤ number ≥ float. Rules are written at the top sort, and the algebra does the dispatch.
- **Linguistics: type coercion in the Generative Lexicon** (*known*). Pustejovsky, *The Generative Lexicon*, MIT Press 1995. A predicate selecting for one type coerces an argument of another type ("begin a book" → "begin reading a book"). `..`'s coercion of integers to strings is lexical coercion *owned by the operator*, not by the grammar rule. That is exactly the move of pushing coercions out of `Eval`/`Step` and into `concat?`.
- **Institutions** (*known*). Goguen and Burstall, "Institutions: abstract model theory for specification and programming", JACM 1992. `LuaSem` and `BcSem` are two "logics" sharing a signature (`Core`), and the satisfaction condition (truth invariant under a signature morphism) is what L-X1 exploits. That the compile map is a signature morphism fixing `Core` is *novel* here.

**Pilot.**

- **Smallest thing to build.** `Core` with `lessThan?` for `int×int` only. Rewrite `cmpRR` and `Eval.cmp` to use it, and confirm that R1's `cmpRR` arms and R2's `cmp` arms shrink.
- **Then add the `str×str` branch.** The measure is that *nothing else changes* (H4 = 0 metatheory lines).
- **Then** `len?` (H3) and `concat?` (H2). H1 is independent of `Core`: it is a `LOADK` admit change plus one `Eval.string` rule.
- **Validation:** differential-test `lessThan?` and `concat?` against native Lua on random byte strings and integers, including embedded `\0`. Note that `l_strcmp` handles embedded zeros by chunked `strcoll`, which in the C locale equals byte order. That is recalled; check it against `lvm.c`.

**Seed.** The case-folded pair `kND`/`Nd` and the mirror `ZAz`: the same letter under two "sorts" (upper and lower case), treated as one symbol once the case is erased, like one operator over int and str. `UqO`/`Oq`, the same pair in both orders, suggested `>` as `<` with its arguments swapped, which needs no new rule.
