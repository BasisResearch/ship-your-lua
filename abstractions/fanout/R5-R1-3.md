## A. Answer-atom trees: an arm is a finite transducer over comparison atoms

### The idea

Today a float arm splits on the kernel's outcomes first and then runs the
machine once per outcome. It picks each fork's polarity by trying closers,
and it reads every float register by hand.

A float path's control flow depends on its data only through a few
**atoms**:
- head-constructor classes of the read registers: `nil | bool | int | flt | str | builtin`;
- `F64.compare` answers, 4 values: `lt | eq | gt | none`.

Every soft-float call answer that reaches a branch is a function of one
`compare` atom (L5-idiom). Every kernel test (`Float.Model.lt/le/beq`) is a
function of one `compare` atom too, by `lt_eq_model`/`le_eq_model`/
`eq_eq_model` + `compare_eq_model`.

So both sides are **finite decision trees over the same atoms**:
- the machine tree `MTree`: forks in ELF order, leaves are end
  configurations;
- the kernel tree `KTree`: the kernel body, leaves are `{edge, vals}`.

The arm obligation becomes:
1. run the shared prefix once, symbolically, producing the atoms as opaque
   terms;
2. `generalize` the atoms to variables `o₁ … oₖ : Option Ordering`;
3. walk `MTree` and evaluate `KTree` along the same partial valuation.

The walk is a closed computation.

### Core rules

| law | rule (proved once) | decided at a use site by |
|---|---|---|
| L5-read′ (classes) | **A0 `kernel_skel`**, once per kernel combinator (`opArith`, `docondjump`, `setR`, `forloopK`, `forprepK`; 5 proofs): `body vs = r → r.edge ∈ classTab κ (heads vs)`, where `classTab κ : Heads → List (Class)` is a *computable* table over head-constructor tuples, and each class carries its register constructors | `decide` on the closed head tuple. FORLOOP: 6³ = 216 rows; the operand predicate `FltStep` pins one head, the class pins the other two. Symbolic payloads never enter, because the table ranges over heads only |

**Symbolic data.** Payloads stay opaque. They appear only:
- inside atoms, as `F64.compare x y`, which is generalised;
- inside stored values, as `F64.add st i`, closed by the value normaliser.

**Infeasible valuations.** The walk is sound under ANY valuation, because
it checks every leaf the machine can reach. A machine leaf that only an
infeasible atom combination reaches still has to agree with the kernel.

This bites only for **dependent atoms**, i.e. the f2i chain: `compare
(floor x) x` and the range compares are not independent. There the walk
needs a feasibility filter `Φ` with a soundness lemma per **atom family**
(the f2i family: E below), never per site.
- **Flag: decided by search** only in the choice of where `Φ` prunes. The
  filter is itself computed.

### What it makes free

- **FORLOOP's 29 lines.**
  - A0/A0′ remove the three-register read and the bundle (14 lines, 48%).
  - A2 removes the `rcases … <;> split` outcome split (4 lines).
  - `add_comm` is absorbed in the value normaliser.
- **Heartbeats.**
  - The replayed prefix (8.3k, 14%) and the wrong-polarity closers (10.3k,
    17%) are removed.
  - Cost now grows with the machine's leaf count, not with leaves ×
    prefix. That is the forecast that put SHL/SHR (22) and LT/LE (24) over
    200k.
- **C5-idiom**: 17 idioms at 93 sites become one `decide` (A1).
- **C5-handoff**: `at_fcond`/`at_farith` and the forecast ≈10 more
  per-shape hand-offs collapse into A2 + A3 plus five `kernel_skel` rows,
  one per combinator.

### What it costs

- **Setup.**
  - `Idiom` + `idiom_tab`: about 60 lines.
  - `kernel_skel` for 5 combinators, about 15 lines each. `forprepK` is the
    hardest: three `tonumber?` calls, strings included.
  - `at_run_fork`: a variant of `at_run` that stops at a fork whose guard
    is a soft-float answer.
  - `sim_of_atree`: about 40 lines, generic over `Kernel`.
- **What gets harder.**
  - The 7 spilled/moved `a0` sites. There the atom has to be carried through
    a register or stack slot before its fork, so `at_run_fork` must keep a
    "pending atom" ghost.
  - Dependent atom families need `Φ`.
  - Merging the trees is clean only when the machine's leaves map
    many-to-one onto kernel leaves (f2i). It is clean then. If a machine
    leaf ever needs **two** kernel leaves (the kernel finer than the
    machine), A3 fails with a named leaf. That is a useful obstruction.

### Theories

- **Ordered decision diagrams** (Bryant 1986, "Graph-based algorithms for
  Boolean function manipulation"), known. Both sides are decision diagrams
  over a shared variable order. Agreement is a product walk.
- **Product programs / relational verification** (Barthe, Crespo, Kunz,
  FM 2011, "Relational verification using product programs"), known. The
  walk is a product of `MTree` and `KTree`, aligned at the leaves.
- **Gene-tree / species-tree reconciliation** in phylogenetics (Goodman et
  al. 1979; Page 1994, "Maps between trees and cladistic analysis of
  historical associations"), known; the use here is novel. The machine
  tree is the gene tree, the kernel tree the species tree, and the f2i
  chain's many-to-one leaves are exactly a reconciliation map.
- **Predicate abstraction** (Graf & Saïdi, CAV 1997), known: the atoms are
  the abstraction predicates.

## B. The site group: comparison sites, layouts and operand orders as one orbit table

### The idea

The 93 comparison sites, the 6 f2i layouts, GTI's `__gedf2(x, imm) > 0` for
`imm < x`, FORLOOP's `__adddf3(step, idx)` for `idx + step`, and `__subdf3`
against `__adddf3` all differ by a few **involutions**:

| generator | acts on | law |
|---|---|---|
| `σ` swap | the arguments of a compare or a commutative op | `F64.compare_swap`, `add_comm`, `mul_comm` |
| `ν` negate the answer encoding | `__ledf2` ↔ `−__gedf2`, unordered `2` ↔ `−2` | L5-comm row 3 |
| `β` branch polarity | `beqz`/`bnez`, `bgez`/`bltz`, which side falls through | flips the `Bool` of the consumer and swaps the successor pair |
| `τ` sign flip of one operand | `sub x y = add x (τ y)`, `τ y = y ^^^ 2^63` | L5-comm row 4 (spec side) |

`G = ⟨σ, ν, β, τ⟩` is a small group (≤ 16 elements; the generators commute
up to the obvious relations **[to check]**).

A **site** is a closed descriptor:
- the routine;
- the argument permutation;
- the idiom;
- the layout polarity bits.

It acts on symbolic arguments `(a, b)`. Every site is `g • canon(site)`.
Only the canonical representatives (one per orbit) carry meaning lemmas,
and the generators carry equivariance lemmas.

### Core rules

| law | rule | decided at a use site by |
|---|---|---|
| L5-comm | **B1 equivariance**, 4 lemmas, one per generator: `sem (g • s) a b = g.out (sem s (g.in (a, b)))` | proved once, from `compare_swap`, the 4-case `decide` for `ν`, `Bool.not` for `β`, and `F64.sub`'s definition for `τ` (the last needs `cls_neg` and is the hardest, about 20 lines) |
| L5-idiom | **B2 `canon_spec`**: `∀ s, s = (canonG s) • (canon s)`, with `canon : Site → Site` and `canonG : Site → G` computable | `decide` on the closed descriptor. The descriptor is read off the ELF words (`beqz` vs `bnez`, argument registers), which are closed |
| L5-chain (layouts) | **B3**: the 6 f2i layouts are one canonical layout up to `β` on each of its 3–4 forks and a mode parameter. The chain's summary (E) is proved for the canonical layout, and `β`-transport gives the rest | computation on the layout's polarity bit vector |
| O-ord | **B4**: lvm.c's operand order is a site whose descriptor has `σ` set. The kernel side needs no lemma: `sem` of the swapped site is literally the kernel's expression after B1 | `decide` on the descriptor |

**Symbolic data.** The arguments are never inspected. Only the descriptor
is closed, so the cost per site is the cost of one `decide` on a
10-constructor term.

### What it makes free

- **C5-idiom.** Here, unlike A1, the idioms are *quotiented*: 17 idioms ×
  3 routines fall to about 5 canonical representatives (sign test,
  zero test, 0/1-from-sign, …). Only those need meaning lemmas. A1's table
  shrinks by the same factor.
- **Operand order** (O-ord): GTI, FORPREP, FORLOOP's `add_comm` line, MOD's
  `fmod` sign fix if its swap is a `τ`.
- **The 6 f2i layouts** become 1 (B3). This is what keeps L5-chain from
  becoming 6 summaries.
- **Level (b), spec side**: `F64.sub = F64.add ∘ (id, τ)`, proved once. The
  `Subdf3.S` field then reads `F64.add a (τ b)`, so any stage proof of the
  add core (C, D) transports to sub's spec.
  - The machine side does **not** come free from B. `Subdf3.F a b =
    Adddf3.F a (τ b)` is an equation between two 500-path DAGs.
  - B only helps if the routine's proof is cut at "after unpack", where sub's
    unpack produces `¬s_b` and the remainder is the same soft-fp macro.
    That makes it D's business.

### What it costs

- **Setup.** The `Site` descriptor, `G`, the action and `canon`: about 80
  lines. `τ`-equivariance on the spec: about 20.
- **Harder.**
  - The descriptor must be *recognised* from ELF words. That is a data
    pattern, the same one `idioms.out` already computes, but it must be
    stated as a Lean function of the instruction words so the `decide` is
    honest.
  - Sites that spill `a0` (7) carry the answer before the consumer, so the
    descriptor must include the carrier.

### Theories

- **Crystallography's asymmetric unit** (International Tables for
  Crystallography, Vol. A, known). A structure is described on one
  asymmetric unit and the space group generates the rest. Here the
  canonical sites are the asymmetric unit.
- **Symmetry reduction in model checking** (Emerson & Sistla, "Symmetry and
  model checking", FMSD 1996; Ip & Dill 1996), known: verify one
  representative per orbit.
- **Gauge fixing** in field theory (novel framing): `canon` picks a gauge,
  and B1's equivariance lemmas are the gauge transformations. Physical
  (semantic) content is invariant.

### Pilot

- **LT**: 24 paths contain about 10 compare sites, including `LTintfloat`'s
  `F2Iceil` chain. B2 reduces them to ≤ 3 canonical sites. Measure the lines
  per site.
- **SUB**: B contributes only the spec-side `τ`: `Subdf3.S = F64.add a (τ b)`.
  This is a negative control: SUB should cost the same as without B.
- **FORPREP**: the step-sign test `__gedf2(st, 0)` against kernel
  `lt 0 st` is a `σ`+`ν` site, and the skip test is a `β` site.
- **Refactor FORLOOP**: the `add_comm` line and the bound idiom's
  `not; srli 63` are a `σ`-site and a `β∘ν`-site.
- **Smallest thing**: `Site`, `G`, B1 for `σ`, `ν`, `β` (not `τ`), `canon`
  with `canon_spec` by `decide`. Then rerun the 5 existing `FltVal` idiom
  bridges as instances and count.

**Seed:** the near-palindromes `QCQ`, `qAq`, `HiH`, `4M4`: mirrors around a
middle, i.e. swap and polarity.

## C. The sticky congruence: rounding factors through `≡ₖ`

This is the open hand-off: "rounding after the sticky collapse equals rounding
the exact value". I propose it as a **congruence** with closure rules, not as a
per-routine lemma.

### The idea

Define, on `Nat`:

```
StEq (k : Nat) (n m : Nat) : Prop :=
  n / 2^k = m / 2^k ∧ (n % 2^k = 0 ↔ m % 2^k = 0)
```

`n ≡ₖ m`: same bits above `k`, and the same zero-ness below. The pair
`(n / 2^k, [n % 2^k ≠ 0])` is a **sufficient statistic** of `n` for rounding,
as long as the round bit sits at or above position `k`.

Every soft-fp operation the routines perform before rounding preserves
`≡ₖ`:
- adding a multiple of `2^k`;
- *reflected* subtraction from a multiple of `2^k`;
- scaling by `2^j`.

Every sticky shift *produces* a `≡` with the exact value. So the core of each
routine is a short **congruence derivation**, not a path enumeration:

> the machine's pre-round mantissa `≡ₖ` the exact aligned result,

and `round` is constant on the classes.

### Core rules (all on `Nat`; the stage functions are L5-stage's)

| rule | statement | proof idea |
|---|---|---|
| **C1 `round_congr`** | `StEq k n m → 0 < n / 2^k → k + 1 ≤ (target n e − e).toNat → round s n e false false = round s m e false false` | `log2 n = log2 m` (same high part, nonzero), so `target` agrees. `shr` by `T − e ≥ k + 1` sees the same quotient, the same round bit (at `T − e − 1 ≥ k`) and the same sticky (low zero-ness). Then `rne`, `finish` agree. Uses the existing `shr`, `target`, `log2_shiftLeft` |
| **C2a `add_mul`** | `StEq k n m → StEq k (n + c·2^k) (m + c·2^k)` | `Nat.add_mul_div_right`, `Nat.add_mul_mod_self_right` |
| **C2b `rsub`** | `StEq k n m → n ≤ c·2^k → m ≤ c·2^k → StEq k (c·2^k − n) (c·2^k − m)` | `(c·2^k − n)/2^k = c − ⌈n/2^k⌉`, and the remainder is zero iff `n`'s is. **This is why reflected subtraction keeps the sticky bit correct**, the classic G/R/S argument |
| **C2c `scale`** | `StEq k n m → StEq (k + j) (n·2^j) (m·2^j)` | divisions by `2^(k+j)` |
| **C2d `coarsen`** | `StEq k n m → k ≤ j → StEq j n m` | |
| **C3 `srs_congr`** | `1 ≤ d → StEq (d + 1) (srs y d · 2^d) y`, where `srs y d = y / 2^d ||| [y % 2^d ≠ 0]` | the low bit of `srs` is the old bit `d` OR'd with sticky. Above bit `d+1` it agrees, and zero-ness below `d+1` is "bit d = 0 and sticky = 0". Also **`srs_full`**: for the `d ≥ 56` branch, the machine's `[y ≠ 0]` satisfies `StEq (d+1) ([y≠0]·2^d) y` whenever `y < 2^d` |
| **C0 `round_rbst`** (for div/sqrt, which round with `rb`/`st`) | `round s n e rb st = round s (4n + 2·rb + st) (e − 2) false false` when `n` is wide enough that the round bit is not exact **[to check: the residual encoding vs `acc`; a corner at `n` small]** | reduces C1's use to exact rounding |

**At a use site** (the `__adddf3` core, effective add, `ea > eb`,
`d = ea − eb`, fractions with hidden bit and 3 work bits, `A = fa·8`,
`B = fb·8`):
- machine: `X = A + srs(B, d)` at exponent `eb + d − 3 − 52`;
- exact: `E = A·2^d + B` at exponent `eb − 3 − 52`.

The derivation is:
1. C3 gives `srs(B, d)·2^d ≡_{d+1} B`.
2. C2a with `c = 4fa`, since `A·2^d = (4fa)·2^(d+1)`, gives `X·2^d ≡_{d+1} E`.
3. C1 needs `d + 2 ≤ target − e`. Since `A ≥ 2^55`, `log2 E ≥ 55 + d`, so
   `target − e ≥ d + 3`. This is linear in `d` and `log2`, so `omega` can
   do it after one `log2_le` fact.

Effective subtract is the same with C2b and `A·2^d ≥ B`:
- for `d ≥ 2`, the cancellation loses at most one bit, so
  `target − e ≥ d + 2` (tight);
- for `d = 1`, `srs(B, 1)` is exact because `B`'s low 3 bits are 0;
- for `d = 0`, there is no shift.

These are the guards the machine branches on (`li 56; bge`, `blez a6`,
`beqz a6`), so each regime is a separate *derivation*, and there are about
4. **[to check against soft-fp's `_FP_ADD_INTERNAL`, recalled: it shifts
by `diff` with `_FP_FRAC_SRS` and `_FP_WFRACBITS` = 56, and the cancellation
case renormalises with `__FP_CLZ`; the `li 56` threshold at `0x8002d800`
matches.]**

**Symbolic data.**
- `2^d` stays an opaque atom; the rules take it as given.
- `omega` sees only linear facts in `d` and `log2`. It never sees a
  variable shift, because C3 consumed it.
- The machine's `BitVec` shift nodes reach `srs` through L5-stage's
  per-site `srsMachine` identity. That is a precondition: `1 ≤ d ≤ 63`,
  discharged by the branch guard.

### What it makes free

- **The core of every arithmetic routine.**
  - `__adddf3`/`__subdf3`: about 4 regimes × about 4 rule applications.
  - `__muldf3`: the 106-bit product is collapsed to 56 bits by one `srs`;
    C3 + C1 with `target − e ≥ 53`, so it is one derivation.
  - `__floatdidf`: one `srs`.
  - `__divdf3`: C0.
- **The 6 inlined round sites, 5 sticky sites and 4 pack sites of
  `__adddf3`.** After the core equation they are one C1 application per
  regime, not per site.
- **The "497 paths" problem.** Paths differ in which regime and which
  special class (zero/inf/NaN) they are in. The finite regimes are ≤ 4
  derivations. The special classes are `F64.add`'s first 8 clauses, which
  are bit-level `decide`-sized facts on the unpack.
- **`__subdf3`.** Its core derivation is `__adddf3`'s with the sign of `b`
  flipped (B's `τ`). The congruence rules never look at signs.

### What it costs

- **Setup.** About 150 lines of `Nat` lemmas (C1 is the hard one, about 60).
- **Harder.**
  - C1's side condition at the subnormal boundary (`target` clamps to
    `−1074`). There the sum is exact, because subnormal + subnormal never
    shifts. That case is `StEq 0`, i.e. equality, but it must be recognised
    and not sent to C1.
  - C does not address the **matching** of `BitVec` nodes to the `Nat`
    stages. That is D, or L5-stage's per-site identities.

### Theories

- **Guard/round/sticky bits** (Goldberg, "What every computer scientist
  should know about floating-point arithmetic", ACM CSUR 1991, Theorem 2 and
  the sticky-bit discussion), known.
- **Flocq's location abstraction** (Boldo & Melquiond, "Flocq: a unified
  library for proving floating-point algorithms in Coq", ARITH 2011;
  `inbetween`, `loc_Exact | loc_Inexact`), known. `StEq` is that, on
  naturals, with closure rules added.
- **Sufficient statistics** (Fisher 1922; the Fisher–Neyman factorisation),
  known; the use here is novel. `round` depends on `n` only through
  `T(n) = (n / 2^k, [n mod 2^k ≠ 0])`, and C1 *is* the factorisation.
- **Myhill–Nerode congruence** (Nerode 1958), known. `≡ₖ` is a right
  congruence for the context operations `+c·2^k`, `c·2^k −`, `·2^j`, and
  the observer `round` is constant on its classes.

### Pilot

- **Held-out level (b).**
  - Build C0–C3.
  - Prove `addCore`: for normal operands of equal sign,
    `round s (A + srs(B, d)) (…) = F64.add x y`, as a pure `Nat`/`Int`
    theorem.
  - Then `__subdf3`'s core is held out: the measure is lines added for sub
    (target ≤ 20).
- **Arms.**
  - C does nothing directly for LT/SUB/FORPREP: they consume
    `SoftFloatSpec`.
  - Its arm effect is that `SoftFloatSpec.adddf3`/`.subdf3` shrink from
    premises to theorems, given D or the stage matches.
- **Refactor FORLOOP**: unchanged lines, but the arm's premise narrows.
- **Smallest thing to build**: `StEq`, C2a, C3, C1, then evaluate
  `round_congr`'s statement on L5-stage's 6,070 + 1,210 vectors with `#eval`
  (a law check, not a proof) before proving C1.

**Seed:** `I0g0`, zeros on both sides of one symbol: what lies below
matters only by whether it is zero. `UU`: two numbers that are "equal" for
the observer.

## D. Stage-typed node assertions over the lifted DAG (linear in nodes, not paths), with frame forwarding

### The idea

Proving `F = S` by following `F`'s branches costs 497 paths. A DAG with 133
nodes admits a **Floyd-style proof**:
- attach an assertion to each node's inputs;
- prove one local verification condition (VC) per node-edge;
- conclude by one generic soundness theorem.

The assertions are not free-form. They come from a **fixed, finite stage
vocabulary** (an inductive `Asn` with an interpreter), the soft-fp
pipeline's intermediate types:

```
inductive Asn
| unpacked  (x : Arg)                          -- (s, e, f) = fields of x, cls x
| aligned   (k : Term) (eExact : Term)         -- semiraw (s, e, X), X·2^k ≡_{k+1} exact sum (C)
| normal    (s e f)                            -- 2^55 ≤ f < 2^56 or the subnormal case
| rounded   (s e f)                            -- f = rne3 of the aligned value (C1 applied)
| packed    (res = S a b)
| special   (c : SpecialCls)                   -- one of F64.add's first 8 clauses
```

`Asn.holds : Asn → NodeEnv → Prop` is the meaning, and
`dag_sound : (∀ n ∈ F.nodes, VC n) → F a b = S a b` is proved once, for any
generated `F` (the lifted functions share one node-function format).

**Frame reloads** are removed before any of this, by one generic theorem
over the first-order write log (CLAUDE.md law 1: reflect on the write log):

```
reload_forward : (ws : List (Nat × BitVec 64)) → lastWrite ws off = some v →
    bytesT8 (writeChain m s ws) (s + off) = v
```

`lastWrite` is a closed computation on the literal offsets (8, 16, 24 for
`__adddf3`'s 48-byte frame). Applying it at each of the 14 reloads
(`simp only [reload_forward]` with `decide` side goals) yields
`F m s r a b = F' a b`. The `m`, `s`, `r` disappear and the premise loses
its `FnSp` argument.

### Core rules

| law | rule | decided at a use site by |
|---|---|---|
| L5-stage (semantic matching) | **D1 `VC` per node kind**: a node whose body matches a stage pattern (SRS, rne3, clz-normalise, pack) gets its VC from the stage lemma, through L5-stage's per-site `BitVec` identity | the match is syntactic, on the node body's alpha-normal form against the 4 stage patterns (L5-stage found 58 sites). The residual `BitVec` identity is a `decide`-free `BitVec` lemma per *pattern*, instantiated |
| L5-stage (bit-identity nodes) | **D2**: a node that only moves or masks bits (spill, `mv`, `andi 2047`) inherits its predecessor's assertion by a `BitVec`→`Nat` field lemma (`toNat_split`, `exp_eq_ones`, …, which exist) | rewriting with the existing field lemmas |
| the open hand-off | **D3**: the `aligned → rounded` edge is C1. The `unpacked → aligned` edges are C2/C3 | C's rules |
| frame | **D4 `reload_forward`** | `decide` on the closed offset list. **This is not search** |
| join points | **D5**: at a join (the 6 round sites jump to one pack join `N_8002d92c`), the join's assertion is the *disjunction-free* `rounded s e f`. Each predecessor proves it, and the join's VC is proved once | per edge |

**Where the assertions come from. Flag: search.** They are inferred by
forward propagation from the matched stage sites (D1 fixes the post-assertion
of each matched node, and D2 propagates through bit-moves). An unmatched,
non-bit-move node is an **inference failure**, reported by name.

The bake-off measures how many nodes fail. If it is more than a handful,
D's premise ("the compiler's nodes are stage-shaped up to bit moves") is
false, and the failing nodes are the obstruction.

**Symbolic data.**
- The VCs mention `d` (the exponent difference) and `2^d` as atoms.
- Variable `BitVec` shifts appear only inside D1-matched SRS nodes, so
  `omega` never sees them.
- The guards on each edge become the hypotheses of that edge's VC: a
  `BitVec` comparison is turned into a `Nat` fact by the existing `toNat`
  lemmas, once per edge, not once per path.

### What it makes free

- **Path explosion.** 497 → 133 nodes × (≈1.5 edges) VCs, of which most are
  D1/D2 instances. The paths are never enumerated.
- **The 14 reloads in add/sub and 8 in `__floatdidf`**: one theorem.
- **`__subdf3`** is a *second instance* of the same assertion vocabulary.
  - Its join node `N_8002ea50` is the same function as add's with permuted
    parameters (L5-stage checked 7,326/7,326), so D1 matches it.
  - Its unpack VC carries `τ` (B).
  - Its hand cost is only the inference failures specific to it.
- **`__muldf3`/`__divdf3`** when level (a) exists: the same vocabulary,
  with C0 at the round edge.

### What it costs

- **Setup.**
  - `Asn` and `dag_sound`: about 120 lines. It needs the node format of
    `gen_lua_fn.py` as a Lean datatype, or a reflection of the generated
    `N_` functions into one. **[to check: whether the lifted functions are
    already a first-order term the theorem can quantify over, or a nest of
    `def`s that must be reflected.]**
  - `reload_forward`: about 30 lines.
- **What gets harder.**
  - The theorem must be generic in the DAG, so the generated `F` must be
    *data* (a node list) plus an interpreter, not a nest of `def`s. That is
    a change to `gen_lua_fn.py`'s output form, and level (a) must be
    re-proved against the interpreter.
  - The level-(a) theorem may become heavier.

### Theories

- **Inductive assertions** (Floyd, "Assigning meanings to programs", 1967),
  known. A DAG needs no loop invariants, only cut-point assertions.
- **Dataflow analysis over a finite lattice** (Kildall, POPL 1973), known:
  assertion inference is forward propagation.
- **Double-entry bookkeeping** (Pacioli 1494), known; the use is a novel
  analogy. Every node must *balance*: the exact value equals the kept value
  plus the sticky account. Auditing is per entry, never per history of
  entries.

### Pilot

- **Held-out level (b).**
  - On `__adddf3`, run assertion inference and count failures.
  - Then on `__subdf3`, count the *additional* hand lines (target: ≤ the
    unmatched nodes specific to sub, about 0–5).
- **Arms**: none directly. Arms gain only through `SoftFloatSpec` fields
  becoming theorems.
- **Smallest thing to build**: `reload_forward` alone, applied to
  `Adddf3.F` to produce the `m`-free `F'` with a single equation. That
  needs no `Asn`, measures whether law 1's write-log reflection is enough,
  and is useful to C and to any other level-(b) route.

**Seed:** `a56`: 56 is the semiraw fraction width (`_FP_WFRACBITS_D` = 56
**[recall]**), the type every assertion speaks about. The run of `V`s in
`VDE`/`VLU`/`VF3`/`Veh` (one letter shared by many different words) is one
vocabulary shared by many different nodes.

## E. Float-to-integer as an adjunction: the f2i chain and every mixed comparison by one Galois rule set, with a reflective order closure

### The idea

The census's new recurring chain (L5-chain, forecast) appears in three
modes:
- `floor > __eqdf2 > __gedf2 > __ledf2 > __fixdfdi` for `F2Ieq`;
- without `__eqdf2` for `F2Ifloor`;
- with an extra `__adddf3` for `F2Iceil`.

It sits in 20 sites in 13 fields, and feeds `ltIntFloat`, `leFloatInt`,
`eqNum`, `forLimit` and the bitwise family. Each mode is a **Galois
connection** between `Float.Model` (exact dyadic values ∪ {±∞, NaN}) and
`Int`:

- `⌊x⌋ ≤ n ↔ x < n + 1`
- `n ≤ ⌊x⌋ ↔ n ≤ x`
- `⌈x⌉ ≤ n ↔ x ≤ n`
- `i < x ↔ i < ⌈x⌉`, the very comment in `LTintfloat`

Instead of a mode-and-layout-quantified *summary* of the chain, state each
machine call's answer as an **order fact on exact values**, and the
kernel's `flttointeger x m` as an order specification:

```
flttointeger x .floor = some n  ↔  exact n ≤ exact x < exact n + 1  ∧  inRange n
flttointeger x .ceil  = some n  ↔  exact n − 1 < exact x ≤ exact n ∧ inRange n
flttointeger x .eq    = some n  ↔  exact x = exact n ∧ inRange n
```

Each machine path along the chain produces a conjunction of atomic order
facts over ≤ 6 terms:
- `x` and `floor x`;
- the constants `±2^63`;
- the integer `i`;
- `ofInt i`.

The kernel's answer is entailed from those facts by **order transitivity
alone**, no arithmetic. That is decided by a reflective order-closure
checker, proved sound once.

### Core rules

| law | rule | decided at a use site by |
|---|---|---|
| L5-chain | **E1 `f2i_galois`** (3 lemmas, one per mode): the order specification above, proved on `F64` from `truncInt?`, `floor`'s definition, and `compare_eq_model` | proved once |
| floor premise | **E2 `floor_spec`** (a named premise beside `SoftFloatSpec`, as L5-chain asks): libm `floor` returns `F64.floor x` with `exact (floor x) ≤ exact x < exact (floor x) + 1` for finite `x` | premise (level (b) of `s_floor.c` later) |
| answers as order facts | **E3**: each `R.S a b` consumed by idiom `ι` (A1/B2) yields one atomic fact `exact a ⋈ exact b` with `⋈ ∈ {<, ≤, =, ≥, >, unordered}`. `__fixdfdi` on an integral in-range float yields `exact (fix y) = exact y` | from the idiom table, computed |
| (new) order closure | **E4 `OrdClosure.sound`**: a reflected checker `closure : List (Fact Nat) → Fact Nat → Bool` over term indices, with `closure Γ φ = true → (∀ γ ∈ Γ, ⟦γ⟧ρ) → ⟦φ⟧ρ` for any valuation `ρ` into a linear order with a NaN-aware `unordered` atom | `decide` on the closed fact graph (terms are indices, values opaque). **Flag: the checker internally searches** (Floyd–Warshall on ≤ 6 nodes), but the search is inside a verified function, so at the use site it is one computation |
| L5-fork refinement (many-to-one leaves) | **E5**: this supplies A's feasibility filter `Φ` for the f2i atom family: a valuation is infeasible iff `closure` derives `⊥` from its facts plus E1/E2's axioms | computation |

**Symbolic data.**
- Floats and ints stay opaque. Only the *shape* of the fact graph is
  closed.
- `ofInt i` is exact when `intfitsf i`: `ofInt_exact`, which exists, after a
  bridge from `intfitsf`'s unsigned test to `|i| ≤ 2^53`.
  - That bridge is one lemma.
  - Off that branch, `ltIntFloat` itself does not convert, so no rounding
    fact is ever needed.

### What it makes free

- **C5-f2i**: 20 sites, 6 layouts, 3 modes become 3 Galois lemmas + E4.
  Each site is a closure call. (Layouts are B's job and vanish there too.)
- **LT/LE** (24 paths each), **EQ/EQK** (`eqNum`'s mixed case through two
  `tointegerns .eq`), **FORPREP**'s `forLimit` (floor/ceil by the step's
  sign, then `lt zero n` for out-of-range): every mixed-type leaf.
- **The bitwise family** (BAND…SHR, BANDK…, BNOT, SHRI/SHLI), with 4–24
  paths each. Its `tointegerns` is the `.eq` mode.

### What it costs

- **Setup.**
  - E1 is the substantive proof: about 80 lines on `F64` with `truncInt?`
    and `Float.Model`'s floor. **[to check: whether `Lua.Num.flttointeger`
    is defined through `F64.floor`/`truncInt?` or through `Float.Model`
    directly; the bridge cost depends on it.]**
  - E4: a verified order-closure checker, about 100 lines.
  - The NaN-aware order: either a separate unordered atom, or each fact
    guarded by `cls ≠ nan`, taken from an `unordered` idiom answer.
- **Harder.**
  - The facts are about `exact`, a function into a *mathematical* order.
    Without Mathlib there is no `ℚ`. Use `(Int × Int)` dyadics with a
    decidable order, or compare through `F64.compare` itself (a total
    preorder on non-NaN, with `trichotomy`, which exists, and
    transitivity, which must be proved: about 40 lines).

### Theories

- **Galois connections / adjunctions for floor and ceiling** (Graham,
  Knuth, Patashnik, *Concrete Mathematics*, §3.1, "x < n ⟺ ⌊x⌋ < n" and
  similar), known. Lua's own comment (`lvm.c:405`) uses one.
- **Reflective decision procedures for orders** (Isabelle's `order`
  tactic; Boutin, "Using reflection to build efficient and certified
  decision procedures", TACS 1997), known.
- **Stratigraphic seriation, the Harris matrix** (Harris, *Principles of
  Archaeological Stratigraphy*, 1979), known; the use is novel. Layers are
  dated only by "above/below" relations and their transitive closure, never
  by absolute dates. Here the machine path's answers are the stratigraphic
  relations, and the kernel's answer is a date entailed by the closure.

### Pilot

- **LT** (FltAB), the main test.
  - The int×flt leaf off `intfitsf`: the machine path facts are the f2i
    chain in `F2Iceil` mode (with `__adddf3`), then `i < fi`. E1(ceil) + E4
    entail `ltIntFloat`'s answer.
  - Target: the 24 paths cost no hand lines beyond A/B's arm skeleton.
- **SUB**: no f2i, so E is idle. This is the control.
- **FORPREP**: `forLimit`'s `tointegerns (floor|ceil)` and the out-of-range
  `lt zero n`.
- **Refactor FORLOOP**: idle (no f2i), except that E4 could replace the bound
  idiom's two cases.
- **Smallest thing**: E1 for the `.floor` mode alone, plus the E4 checker
  restricted to `{<, ≤}`, applied to one bitwise site (BNOT's
  `tointegerns .eq` needs `.eq`, so pick SHRI's `.eq`, or `forLimit`'s
  `.floor`).

**Seed:** the near-repeat with an insertion, `Ca5` / `Ca5p6` / `Ha56`: the
same chain in three modes, one of which (`F2Iceil`) has one extra call
inserted.
