## 1. Top-frame gauge with promotion (the `L->top`/savedpc fix that survives CALL, GC and closures)

**Acts on:**
- R3-R1-3 #2, objection (c): its phase invariant is false after CALL;
- R3-R1-5 #2 and R3-R1-4 #1, objection (c): "dead" is false at GC points and for parent frames;
- R3-R1-1 #2, extension (a): its gauge-fixing rule R2.3 is the right shape, and it can be made much cheaper through N7.

### The objections, concretely

1. **R3-R1-3 #2** restates `LuaStateAt.top` as `L->top = func+16 ∨ L->top = ci->top`. After `CALL print(x)` with A > 0, `moveresults` case 0 sets `L->top = ra = base + 16A` (N4), which is neither. The first CALL arm falsifies the invariant, so the disjunction needs a third case, and every further runtime op adds another.
2. **R3-R1-5 #2** ("`Dead` … sound because the facts are dead") and **R3-R1-4 #1** ("`savedpc`/`L->top` are simply not in the support") are right *at the head of an F1 arm*, but wrong in two later fragments.
   - **GC.** `traversethread` reads `L->top` and nils everything above it (N5). An arm that reaches `luaC_step` with a stale `L->top = func+16` would have its live registers `R[1..]` collected. `savestate` exists precisely to prevent this.
   - **Lua-to-Lua calls.** The `returning:` label of `luaV_execute` does `pc = ci->u.l.savedpc` for the *caller's* ci. Once a Lua frame is pushed, the caller's savedpc is the return continuation, and it is crossed at the dispatch head while live.
3. **R3-R1-1 #2** is phase-dependent by *pc* (`L->top` observable at pc = 0). The real phase variable is *which ci is on top*, and *whether a GC point lies before the next write*.

### The idea

**Gauge set.** It holds only the fields of the **top** frame:

```
Γ(w) := {w.ci + savedpcOff .. +8} ∪ {w.L + stateTopOff .. +8} ∪ [stackLo, w.sp)
```

It says nothing about any ancestor ci. In F1 there is no ancestor Lua ci, so the set is exact.

**Absorption by re-choosing the witness (N7).** `VmRel` is `∃ w`, and `Core.frame` compares memory with `w.mo` outside `Win`. So an arm whose stores outside `Win` all lie in `Γ(w)` closes with `w' := { w with mo := c'.σ.mem on Γ(w) }`. The only obligation is `Complement p w → Complement p w'`, proved **once**, and today only `LuaStateAt.top` (`Runtime.lean` l.221) mentions a Γ address. Weaken it to:

```
top : ∃ t, rd64 m (L + stateTopOff) = some t ∧ w.func + stackValueSize ≤ t ∧ t ≤ w.stackLast
```

`VARARGPREP` is the only reader that needs the exact entry value. `vmRel_entry` already produces it, so move the exact value into `VARARGPREP`'s own premise: the arm at pc 0 reads `Γ` through the kernel's port. This is R3-R1-1's R2.3, restricted to the one F1 consumer.

**Promotion (for later fragments).** A **push** rule, used by CALL of a Lua function, moves the caller's `savedpc` *out of* Γ and into the observable decoder as the return continuation of a frame stack. A **GC point** is a callee precondition `L->top ≥ ci->top`, which the arm fixes by its own `savestate` store just before the call. That is gauge fixing at the interaction point: the fixing obligation belongs to the runtime callee's precondition, never to the relation.

### Core rules

- **L-C6′, the `{savedpc, L->top}` and callee-frame part: `regauge`.** Stores into `Γ(w)` are absorbed by `w' := w[mo := c'.mem on Γ]`, with `Complement.regauge` proved once.
- **L-C3′ runtime, the GC/precall reads: `gauge_fix`.** A runtime callee may assume `L->top = f(s)` when the arm stored `f(s)` there on the same path. Only the arms that call such a callee use this rule.
- **The push rule** is deferred until closures exist. It is stated here so that nobody bakes "savedpc is dead" into the relation.

### What it makes free

- The census's `savedpc`/`L->top` widening (d1, 100–250 lines): about 30–60 lines once, and 0 per arm.
- The callee frames below `sp`, for `luaV_equalobj` and `l_strcmp`: the same `regauge`, if F-B finds no complement field reading below `sp`.
- **The shared tail `0x8001e43c` (N1).** MOD reaches it after its `Protect` stores and ADD without them. With `w` re-chosen at the point of the stores, both reach the tail satisfying `Core p c s w'`, so one tail argument serves both.

### What it costs

- The `LuaStateAt.top` edit, and threading "`top` exact" to `VARARGPREP`'s pc = 0 premise.
- A stack lower bound `stackLo` for `Γ`.
- **Harder:** the push rule, when closures arrive. The relation then needs a decoder for the ci chain. That is real, but it is a new *observable*, not a widening per resource.

### Theories

- **Known (programming languages):** continuations as saved return points. Reynolds, "Definitional interpreters for higher-order programming languages", ACM Annual Conference 1972 (recalled; check). The parent's savedpc *is* a continuation, which is why it cannot be gauge.
- **Known (garbage collection):** stack maps and safepoints. Diwan, Moss and Hudson, PLDI 1992 (recalled). `savestate` publishes the root extent before a safepoint, which is `gauge_fix`.
- **Known, distant (philosophy of language):** Kaplan, "Demonstratives" (1977, published 1989; recalled). Indexicals like "now" and "here" get their content from context. The top frame's savedpc is an indexical whose content is fixed only when a push shifts the context.
- **Novel:** gauge set indexed by *frame depth* rather than by pc, and absorption by re-choosing the relation's existential witness, so that no field and no `Δ` algebra is added.

### Pilot

- **Build:** `Γ` for the top frame, the `LuaStateAt.top` weakening, and `Complement.regauge`.
- **MOD:** both edges re-choose `w`.
- **EQ:** the same, plus `luaV_equalobj`'s `sd ra,40(sp)` below `sp`.
- **MUL:** a control. It makes no out-of-`Win` store (N6).
- **`sim_ADD`:** unchanged.
- **Measure:** lines to take MOD's `Protect` pair from "false" to closed. The forecast is under 60, once.

## 2. The four-lemma kit: the cheapest merge of the round-1 convergence

**Acts on:**
- combination (b) of R3-R1-3 #5 (forward evaluation), R3-R1-5 #2 (`bleach`), R3-R1-1 #4 R4.1 (`guard_tag`) and R3-R1-5 #3 (restricted to class R);
- objection (c) to R3-R1-2 #3 (`WriteLog`) and R3-R1-3 #3 (the patch normaliser), which are redundant;
- objection (c) to R3-R1-1 #4, R3-R1-2 #5 and R3-R1-4 #4, whose finite-tree machinery (`knf`, `KProd`, `KTree`) is not needed for these arms.

### The objections

- **Log and patch data types are redundant.** After a run, `c'.σ.mem` is already a term of nested `insert`s. The last-writer fact (R3-R1-1's `apply_final`) is the map's own `getElem?_insert` simp lemma. A reified `WriteLog` (150–220 lines) or patch normaliser (300–400 lines) re-proves it with an extra encoding layer.

  Their one real benefit, order-independence, comes free from reading final bytes. Their stated hazard, read-after-write inside an arm, never arises when the close reads final memory and the arm's loads were already executed against the pre-state by the run.
- **`KTree`, `knf`, `KProd` and the reconciliation map are not needed for these arms.** `opArith` and `docondjump` bodies are four-line `match`es on `Opnd.fill os vs` (`Semantics.lean` l.326, l.346). `simp [kstep, decide?, opArith, Opnd.fill, δ]` evaluates them once the leaf supplies `[.int x, .int y]`.

  A normal-form tree type with a soundness proof per combinator (120–150 lines) buys nothing until a kernel body is too big for `simp`. None of MUL, MOD or EQ is.

### The idea

Four generic lemmas, used inside whatever produces the machine runs.

1. **`sim_of_leaf`, forward.** From `Step p s s'`, `kstep_iff` gives `s' = (kstep s).get`. On a machine path whose tags give `Opnd.fill os vs = [.int x, .int y]`, `s'` is computed. No `step_opArith` or `step_condjump` is ever written again.
2. **Guards.**
   - `tag3_iff : ValRepr mo t x v → (t = 3 ↔ v = .int x)`;
   - `tag19_absurd : ValRepr mo 19 x v → ¬ F1Value v`.

   Every guard in the three arms is one of these. The fixed-point test `bgeu 1, n+1` in MOD is `BitVec` `omega` on the payload, which is not a guard lemma.
3. **`close_final`.** This is R3-R1-5 #2's `bleach`, with its dead set replaced by idea #1's `Γ(w)` and the witness re-choice. Premises:
   - `c'.σ.mem` agrees with `c.σ.mem` outside `Win ∪ Γ(w) ∪ DefSlots`;
   - each def slot's final bytes are `ValRepr` of the kernel's value;
   - `Pins`, `RegsOk` and `out` hold.
4. **`call_R` (L-C3′ pure, class R only).** For a block that touches no memory, `sp` or `s` register (N6), `jal` continues at `ra` with:
   - `a0 = f(a0, a1)`;
   - all memory and `s0`–`s11`, `sp`, `gp` unchanged;
   - `t*`, `a1`–`a7` and `ra` havocked.

   `f` comes from `Muldi3Spec` and `udivdi3_spec`, relocated **per code block** (N6), not per symbol.

### Core rules

- **L-C4 at the arm → `sim_of_leaf`** (by `kstep_iff`).
- **The branch law → `tag3_iff`**, one lemma.
- **L-C6′ → `close_final`.**
- **L-C3′ pure (class R) → `call_R`.**

### What it makes free

- (a5) inversions and (a4) guards: 0 per new tree.
- (c) closes and store shapes: 0 per new tree.
- (b) for MUL, MULK, MOD, MODK, IDIV and IDIVK: 0 per arm. The block specs exist, or compose.

### What it costs

- About 80–110 lines for lemmas 1–3.
- `call_R` plus block relocation: the 150–250 lines R3-R1-1 estimated for translation-equivariance. It is simpler here, because class-R blocks contain no load, store or `auipc`.
- **Harder:** nothing new for these arms. The cost that is *not* removed is the per-path machine run (F-A).

### Theories

- **Known (programming languages):** abstraction functions, Hoare, "Proof of correctness of data representations", Acta Informatica 1972 (recalled). `sim_of_leaf` + `close_final` is the commuting square with the abstraction applied at the ends only.
- **Known, distant (manufacturing):** design for assembly. Boothroyd and Dewhurst, *Product Design for Assembly*, 1983 (recalled; check). For each part, ask whether it must be separate from its neighbours; if not, merge it. Here, fourteen round-1 rule names collapse to four lemmas.
- **Known (abstract interpretation):** Cousot and Cousot, POPL 1977 (recalled). `tag3_iff` is the complete (best) transformer of `beq t, s2` for the tag abstraction.
- **Novel:** nothing in the lemmas. The novelty is the claim, testable by F-A, that the rest of round 1's machinery is unnecessary for the held-out arms.

### Pilot

- **Build:** the four lemmas, with `call_R` for the `__muldi3` block only.
- **`sim_ADD`:** replace its guard pair, inversion and close with `tag3_iff`, `sim_of_leaf` and `close_final`. Success means lines drop by the census share of (a4) + (a5) + (c) in ADD.
- **MUL:** ADD's text with `call_R __muldi3`.
- **MOD:** add #1 and #5.
- **EQ:** add #1, #3 and #4.
- **Measure:** hand lines per arm, split into "run" lines and "reasoning" lines.

## 3. Transparent callees: a helper path without a loop is arm code

**Acts on:**
- objection (c) to R3-R1-5 #3: its syntactic scanner cannot classify `luaV_equalobj` as RO;
- objection (c) to R3-R1-1 #3 R3.3, R3-R1-2 #4, R3-R1-3 #4 and R3-R1-4 #2: `luaV_equalobj` is not a pure helper beyond F1, so a value row for it is a liability;
- (d): nobody in round 1 proposed *not* making it a call node.

### The objections

- **R3-R1-5 #3's scanner** classifies by the static call closure. `luaV_equalobj`'s closure contains `luaT_callTMres` (`0x8001b8d4`), which reaches `luaD_call` and hence `luaV_execute`. It also dispatches through an `auipc` jump table (`jr a5` at `0x8001b7f0`). A sound syntactic scanner must answer **class U** for it.
- **The "pure" rows** (R3-R1-2 #4's `luaV_equalobj ↦ δ .eq`, R3-R1-3 #4's `Pure (eq on decoded values)`, R3-R1-4 #2's residual). Once tables with metatables exist, `fasttm` → `luaT_gettm` writes `events->flags` in the metatable (`ltm.c:64`). So even *equality of two distinct tables with a metatable lacking `__eq`* writes the heap, and with `__eq` it runs arbitrary Lua.

  A row stated for F1 must be rewritten at the first table fragment. A spec proved against the whole helper must cover paths F1 never takes.

### The idea

`jal` is an ordinary instruction; so is `ret`. The shape of a callee is decided **per path**, by what the caller's path condition already fixes:

- If the helper's path under that condition is **loop-free**, the arm simply runs through it. This holds for `luaV_equalobj` under known tag classes (N3): about 12–16 instructions and one store below `sp`. There is no node and no row. The callee's frame store is absorbed by idea #1's `Γ` (below `sp`).
- If the path contains a **loop**, it becomes a call node with a spec: `__muldi3`'s shift-add, `__hidden___udivdi3`'s restoring division, `luaS_eqlngstr`'s `memcmp`.

For EQ under F1 the arm's tree grows by one leaf per class pair `luaV_equalobj` separates:
- (int, int), where equality is `sub; seqz`;
- (nil, nil);
- (false, true), where the tags differ in bit 4 and the helper returns 0;
- (short string, short string), a pointer compare;
- differing type, which returns 0.

Each leaf is closed by the kernel side, `docondjump … (δ .eq)`, evaluated forward, plus #4's canonicity for the pointer compare and the nil case.

### Core rules

- **L-C3′ pure, loop-free case:** there is no rule at all. The existing run mechanism plus `close_final` handle it, and `sp`-relative stores go to `Γ`.
- **L-C3′ pure, looping case:** `call_R` / `call_RO` (idea #2), with a block spec.
- **The per-path shape criterion:** the helper's CFG restricted to the path condition is acyclic. This is checked by the run terminating in bounded steps. It is not a proof obligation.

### What it makes free

- The `luaV_equalobj` contract and row. EQ, EQK and later `EQI` do not need them.
- The metatable and `__eq` paths. They are never run under F1's path conditions, so their heap writes never enter a proof, and nothing about F1 must be retracted when tables arrive. At that point the table-class leaf alone becomes a runtime node.
- The `auipc` jump table needs no relocation argument. It is executed in place at its real address.

### What it costs

- EQ's leaf count grows, by roughly five class pairs times the two values of `k` (F-F is the falsifier).
- The run mechanism must accept a `jal`/`ret` pair inside an arm path and the callee's `sp` adjustment. With generated runs this is free. With SymExec it needs `sp`-relative stores to be tracked, which it already does for spills.
- **Harder:** a helper path whose loop appears only for some inputs, like `luaS_eqlngstr` on long strings. That leaf needs a node while its siblings do not.

### Theories

- **Known (partial evaluation):** polyvariant specialisation. Jones, Gomard and Sestoft, *Partial Evaluation and Automatic Program Generation*, 1993 (recalled). The helper is specialised to the caller's static tag knowledge.
- **Known (program analysis):** call-string context sensitivity, Shivers, *Control-Flow Analysis of Higher-Order Languages*, PhD thesis 1991 (recalled). The helper is analysed per calling context, not once.
- **Known, distant (company law):** piercing the corporate veil. A subsidiary's separate identity is respected by default (*Salomon v A Salomon & Co*, 1897; recalled) but disregarded when separateness serves no purpose. Here the helper's separate contract is disregarded when its path is a straight line.
- **Novel:** choosing between inlining and a call node **per path**, by a loop criterion on the path-restricted CFG, so that contracts exist only where induction is unavoidable.

### Pilot

- **EQ only:** run `luaV_equalobj` inline under each F1 class pair and close each leaf.
- **Control:** state EQ with a `call_RO` node and an *assumed* `a0 = decide (v₁ = v₂)` premise, and compare hand lines. If inline is not smaller, drop #3.
- **MUL, MOD:** unaffected, since their helpers loop (N6).
- **`sim_ADD`:** unaffected.

## 4. Observational canonicity by constant provenance (interning without a heap invariant, for F1)

**Acts on:**
- extension (a) of R3-R1-5 #1's `decode_canon` and finding F-e;
- objection (c) to the "interning invariant" in R3-R1-2 #1 and #2, R3-R1-3 #4 and R3-R1-4 #2: a string-table invariant is far more than F1 needs;
- the coordinator's two soundness gaps (the canonical nil tag, and short-string interning).

### The objection

Every round-1 fix for EQ on strings is "a heap invariant: equal short-string contents imply equal pointers". Stated over the string table (`strt`), it must be:
- established from the entry image's hash chains;
- preserved by `CALL print`. `luaL_tolstring` → `lua_pushfstring` → `luaS_new` *inserts* into `strt`, and may resize it.

That is heap-structure reasoning with no bound, bought for a fragment that creates no string a register can see. `CONCAT` is the first non-F1 opcode (`ROUND-3.md`, `f4_strlite`).

### The idea

State canonicity about **what `luaV_equalobj` observes** (N3), which is 9 bytes per slot, with a **provenance** set that is finite and fixed at entry:

```
Canon w m j v :=
  match v with
  | .nil        => slotTag m (w.slot j) = 0            -- exactly VNIL (not 16, not 32)
  | .bool b     => slotTag … = (if b then 17 else 1)
  | .int i      => slotTag … = 3 ∧ slotVal … = i
  | .str s      => (slotTag …, slotVal …) ∈ P w ∧ bytesOf P (slotVal …) = s
  | _           => True
P w : Finset (Tag × Ptr)  -- the short-string TValues in K and in the entry heap image's globals
```

It is fixed at entry. `P`'s **injectivity in contents** is a decidable fact about the loaded image, checked once in `vmRel_entry` by `decide`. Arms preserve `Canon` because:

- every F1 store to a register writes one of:
  - a K entry's 9 bytes (`LOADK`);
  - another register's 9 bytes (`MOVE`, `GETUPVAL`/`GETTABUP` values stored earlier from registers);
  - a fresh int, bool or nil with a literal tag;
- `P` itself is outside every arm's write set. `CALL print` may add *new* strings to `strt` but cannot change `P`'s entries: the growth-only clause of R3-R1-2 #1's runtime generator.

Then one lemma serves EQ:

```
equalobj_bytes : Canon a va → Canon b vb → F1Class va → F1Class vb →
                 (machine result of the class-pair leaf) = decide (va = vb)
```

For strings, this lemma is pointer equality ↔ content equality, by `P`'s injectivity. For nil, it is `0 = 0`.

### Core rules

- **The EQ law (the coordinator's gaps) → `equalobj_bytes`**, proved once for all equality arms (EQ, EQK, and the equality half of later `EQI`).
- **The L-C4 value half →** `Core.stack` strengthened by `Canon`. It is preserved by `close_final` because the def value's bytes come from a canonical source.

### What it makes free

- The interning heap invariant, for all of F1.
- The `VNIL`/`VEMPTY` counterexample (R3-R1-5 F-e): nil is tag exactly 0 by construction. The nil writers `setnilvalue` in `LOADNIL`, `luaD_precall`, `moveresults` and `luaV_finishget` all store `LUA_VNIL` (checked in the sources).
- The "string tag agrees with header" condition: provenance copies tag and pointer together.

### What it costs

- Strengthening `ValRepr` use sites to `Canon` in `Core.stack`. The 25 proved arms must preserve it. For inline arms this follows from the literal tags they store, so it should be one `simp` fact per store shape. That estimate needs checking against the templates.
- Computing `P` from the entry image. `_VERSION` and other library strings are interned by `luaL_openlibs`, so `P` must include the globals' short strings, not only K.
- **Harder, and planned:** at `CONCAT` or `tostring` (f4), `P` stops being fixed. The rule then upgrades to the real `strt` interning invariant. The claim is only that F1 does not need to pay for it now.

### Theories

- **Known (programming languages):** hash-consing, where pointer equality coincides with structural equality. Goto, 1974; Filliâtre and Conchon, "Type-safe modular hash-consing", ML Workshop 2006 (recalled). `P` is a hash-consed table frozen at entry.
- **Known (databases):** where-provenance. Buneman, Khanna and Tan, "Why and where: a characterization of data provenance", ICDT 2001 (recalled). Canonicity is carried by where a value was copied from.
- **Known, distant (forensics and law):** chain of custody. An exhibit is admissible because its custody chain from a sealed source is unbroken, not because it is re-tested. Here a string register is admissible to pointer comparison because its bytes were copied from `P` (textbook; no single citation).
- **Novel:** replacing a heap interning invariant with a *finite, entry-fixed provenance set* whose injectivity is decided on the loaded image, for exactly the fragments that create no register-visible strings.

### Pilot

- **EQ:** `equalobj_bytes` on (int, int), (nil, nil), (bool, bool) and (short string, short string).
- **Entry:** the `decide` check of `P`'s injectivity for the F1 corpus images.
- **Falsifier F-D first.** If any live nil has tag 16 or 32, or any live short-string pointer lies outside `P`, the idea is dead before it is built.
- **MUL, MOD, `sim_ADD`:** they must preserve `Canon`. This measures the cost to arms that do not need it.

## 5. Machine-normal-form δ: write the kernel's value function in the compiler's case structure, once per BinOp

**Acts on:**
- extension (a) of R3-R1-4 #4 (reconciliation): it removes its "duplication" events by rewriting the species tree, instead of paying a value lemma at each duplication leaf;
- objection (c) to R3-R1-3 #5 and R3-R1-5 #1: forward evaluation of `opArith … .mod` by `simp` does not close MOD's leaves;
- extension (a) of R3-R1-1 #3's `imod_fixup` and R3-R1-5's `fmod_of_tmod`: one rewrite, stated so that evaluation uses it automatically.

### The objection

**MOD's machine tree has three splits the kernel does not have** (checked at `0x8001f7e0`, `0x8001fd30`, `0x8001fb74`):
- `n+1 ≤u 1`;
- `n = 0`;
- the fix-up test `r ≠ 0 ∧ (r xor n) < 0`.

The kernel's `δ (.arith .mod) [.int x, .int y]` is some `imod`, presumably a single `Int.fmod`-style definition. So on each of MOD's four live leaves, `simp [kstep, opArith, δ]` leaves a residue such as `imod x y = x.srem y + y`, under a hypothesis about signs. "Forward evaluation closes it" is false without the value lemma. The value lemma must then be *applied by hand* at each leaf, once in MOD and again in MODK.

### The idea

For each BinOp whose C implementation branches (`luaV_mod`, `luaV_idiv`, `luaV_shiftl`/`shiftr`), prove **once** an equation that restates δ in the machine's case structure. For MOD:

```
imod_mnf : BinOp.int .mod x y =
  if (y + 1).toNat ≤ 1 then (if y = 0 then none else some 0)     -- bgeu 1, n+1 ; beqz
  else let r := x.srem y                                          -- __moddi3 (truncated)
       some (if r ≠ 0 ∧ (r ^^^ y).msb then r + y else r)          -- bltz (r xor n) → r += n
```

Tag it as the `simp` normal form of δ inside the arm layer. Forward evaluation then produces *the same* `if` tree as the machine run. Each leaf's path condition selects one branch by `if_pos`/`if_neg`, and the leaf closes by `rfl`. The `y = 0` leaf gives `none`, which contradicts `Step`: the vacuous path (R3-R1-3 #4, R3-R1-5 F-f).

This is the "species tree rewritten to the gene tree's shape" move. After `imod_mnf`, reconciliation (R3-R1-4 #4) has no duplication events for MOD. And forward evaluation (R3-R1-3 #5) needs nothing per arm.

### Core rules

- **L-C2′, the rows that differ only by helper plus fix-up → `mnf` equations per BinOp.** MOD/MODK share one, IDIV/IDIVK another, and SHL/SHR/SHLI/SHRI a third (the `n ≥ 64` / negative-amount splits of `luaV_shiftl`). That makes 3–4 equations for all of F1's branching arithmetic.
- **L-C4 at a MOD leaf →** `simp only [imod_mnf, h_path]` then `rfl`.

### What it makes free

- The (a6) value lemmas at MOD, MODK, IDIV and IDIVK leaves: the arm proofs never mention them.
- The R3-R1-4 #4 duplication bookkeeping for these arms.
- **The `n = −1` special case.** It is in the equation, and the machine's `li a5,0` leaf (`0x8001fd34`) matches `some 0` by `rfl`.

### What it costs

- The equation itself, about 30 lines per BinOp, `BitVec`/`Int` reasoning, once. That is the real mathematical content: `fmod` from `srem` with the sign fix-up.
- A discipline: the `mnf` form must be the *only* `simp` form of δ used in the arm layer, or the two forms fight.
- **Harder:** if GCC changes the case structure (a different `-O` level or version), the equation still holds. Only its *shape* stops matching, and the failure is a `simp` residue, not unsoundness.

### Theories

- **Known (compiler verification):** translation validation by symbolic evaluation to a common normal form. Necula, PLDI 2000; Tristan and Leroy, "Formal verification of translation validators", POPL 2008 (recalled). Here the normalisation happens on the *spec* side, by a proved rewrite.
- **Known, distant (computational linguistics):** sentence alignment of parallel corpora. Gale and Church, "A program for aligning sentences in bilingual corpora", ACL 1991 (recalled). Alignment is easy when both texts are segmented alike, so segment the source to match the target first.
- **Known, distant (biology):** gene-tree/species-tree reconciliation (as in R3-R1-4 #4; Page, Syst. Biol. 1994, recalled). Rewriting the species tree to remove duplications is the move here.
- **Novel:** putting the compiler's case splits into δ's *simp normal form* by one proved equation per branching BinOp, so that arm leaves close by `rfl` and duplication events disappear.

### Pilot

- **MOD:** `imod_mnf`, then four live leaves by `simp only [imod_mnf, h]; rfl`, and one vacuous leaf.
- **Measure:** MOD's leaf lines with `imod_mnf` against lines with `imod_fixup` applied by hand.
- **MUL, EQ:** no branching BinOp (`__muldi3` computes `*` exactly, and EQ is a test), so the idea is inert. This confirms it adds no cost where it is not needed.
- **`sim_ADD`:** inert.
